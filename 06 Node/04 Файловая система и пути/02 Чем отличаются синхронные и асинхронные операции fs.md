> [!summary]
> Синхронные операции `fs` блокируют выполнение JavaScript до завершения работы с диском. Асинхронные операции отдают задачу Node.js и позволяют event loop продолжать обрабатывать другие события.

## Короткий ответ

В Node.js один основной поток выполняет JavaScript-код. Если вызвать синхронную операцию, этот поток будет ждать диск.

```js
import { readFileSync } from 'node:fs';

const config = readFileSync('config.json', 'utf8');
console.log(config);
```

Пока файл читается, сервер не сможет обрабатывать новые запросы.

Асинхронная версия не блокирует основной поток:

```js
import { readFile } from 'node:fs/promises';

const config = await readFile('config.json', 'utf8');
console.log(config);
```

`await` приостанавливает текущую async-функцию, но не весь Node.js-процесс.

## Когда sync API допустим?

Синхронные операции нормальны, если код выполняется редко и не обслуживает пользователей прямо сейчас:

- чтение конфига при запуске;
- одноразовый скрипт миграции;
- CLI-утилита;
- генерация файлов в build step.

На HTTP-сервере в обработчике запроса sync API обычно считается плохой практикой.

```js
import { readFileSync } from 'node:fs';
import http from 'node:http';

http.createServer((req, res) => {
  const page = readFileSync('index.html', 'utf8'); // блокирует все запросы
  res.end(page);
});
```

## Собеседовательный нюанс

Асинхронность в `fs` не означает, что файл читается самим JavaScript. Node.js использует возможности ОС и libuv, а часть операций может выполняться через thread pool.

## Мини-шпаргалка

- `Sync` API блокирует event loop.
- Async API лучше для серверов.
- Sync API допустим при старте приложения и в простых скриптах.
- `await` не блокирует весь процесс.
- В обработчиках HTTP-запросов избегай `readFileSync`.
