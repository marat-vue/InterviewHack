# Как типизировать useCallback()?

> [!summary]
> `useCallback` мемоизирует функцию, а TypeScript обычно выводит ее тип из параметров и тела. Явная типизация нужна, когда callback должен соответствовать props-контракту, React event handler, generic-функции или внешнему API.

## Базовый пример

```tsx
const handleSelect = useCallback((id: string) => {
  setSelectedId(id)
}, [])
```

TypeScript понимает тип:

```ts
(id: string) => void
```

## Типизация через alias

```tsx
type OnSelect = (id: string) => void

const handleSelect = useCallback<OnSelect>((id) => {
  setSelectedId(id)
}, [])
```

Так удобно, если функция должна точно соответствовать prop:

```tsx
type UserListProps = {
  onSelect: (userId: string) => void
}
```

## Event handlers

```tsx
const handleClick = useCallback<React.MouseEventHandler<HTMLButtonElement>>(
  (event) => {
    event.currentTarget.disabled = true
  },
  [],
)
```

Или через параметр:

```tsx
const handleChange = useCallback(
  (event: React.ChangeEvent<HTMLInputElement>) => {
    setValue(event.currentTarget.value)
  },
  [],
)
```

Оба варианта нормальные.

## Callback с return value

```tsx
const getUserLabel = useCallback((user: User): string => {
  return `${user.name} (${user.email})`
}, [])
```

Если return type очевиден, его можно не писать. Если это публичный контракт, явный return type повышает читаемость.

## Generic callback в TSX

В TSX generic arrow function пишут с запятой:

```tsx
const identity = useCallback(<T,>(value: T): T => {
  return value
}, [])
```

Запятая помогает TypeScript не спутать `<T>` с JSX-тегом.

## Dependencies важнее типа

Типизация не спасает от stale closure:

```tsx
const handleSubmit = useCallback(() => {
  send(value)
}, [])
```

Если `value` меняется, dependency нужна:

```tsx
const handleSubmit = useCallback(() => {
  send(value)
}, [value])
```

Если callback зависит от setter с functional update, dependency может быть не нужна:

```tsx
const increment = useCallback(() => {
  setCount((count) => count + 1)
}, [])
```

## Когда useCallback не нужен?

Не нужно оборачивать каждую функцию:

```tsx
function Button() {
  function handleClick() {
    console.log('click')
  }

  return <button onClick={handleClick}>Click</button>
}
```

`useCallback` полезен, когда:

- callback передается в memoized child;
- callback входит в dependencies другого hook;
- нужна стабильная ссылка для подписки;
- функция является частью публичного API кастомного хука.

## Что отвечать на собеседовании?

`useCallback` типизирует функцию. Чаще всего TypeScript выводит тип сам. Явно типизируют параметры, return value, event handler или generic callback. При этом правильный dependency array важнее ручного generic, потому что stale closure остается логической ошибкой.

## Частые ошибки

- Оборачивать все функции в `useCallback`.
- Забывать dependencies.
- Использовать `any` в параметрах.
- Путать `useCallback` с `useMemo`.
- Писать generic arrow в TSX без запятой: `<T>`.

## Мини-шпаргалка

- Автовывод работает в большинстве случаев.
- Alias: `useCallback<OnSelect>((id) => {}, deps)`.
- Event: `React.MouseEventHandler<HTMLButtonElement>`.
- Generic в TSX: `<T,>`.
- Следи за dependencies.
