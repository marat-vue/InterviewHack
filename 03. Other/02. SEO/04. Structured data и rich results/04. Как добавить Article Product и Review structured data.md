# Как добавить Article, Product и Review structured data?

> [!summary]
> Article, Product и Review - часто встречающиеся типы structured data. Они полезны для медиа, блогов, магазинов и сервисов, но требуют аккуратности: нельзя размечать то, чего пользователь не видит на странице.

## Article

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Core Web Vitals простыми словами",
  "datePublished": "2026-07-20",
  "dateModified": "2026-07-25",
  "author": {
    "@type": "Person",
    "name": "Анна Петрова"
  },
  "image": "https://example.com/images/web-vitals.png"
}
</script>
```

Подходит для статей, гайдов и новостей.

## Product

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Курс по Frontend",
  "description": "Практический курс по JavaScript, Vue и тестированию.",
  "offers": {
    "@type": "Offer",
    "price": "19900",
    "priceCurrency": "RUB",
    "availability": "https://schema.org/InStock"
  }
}
</script>
```

Для ecommerce важно, чтобы цена и наличие были актуальными.

## Review

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Review",
  "reviewRating": {
    "@type": "Rating",
    "ratingValue": "5",
    "bestRating": "5"
  },
  "author": {
    "@type": "Person",
    "name": "Иван"
  }
}
</script>
```

Отзывы должны быть реальными и видимыми пользователю.

## Частые ошибки

- Разметка отзывов без видимых отзывов.
- Неверная валюта или устаревшая цена.
- Разметка Product на категории вместо товара.
- Дублирование нескольких противоречивых сущностей.
- Отсутствие обязательных полей для rich result.

## Мини-шпаргалка

- Article - для материалов и публикаций.
- Product - для конкретного товара или услуги.
- Review - для реальных отзывов.
- Данные должны быть видимыми и актуальными.
- Перед релизом проверяй валидатором rich results.
