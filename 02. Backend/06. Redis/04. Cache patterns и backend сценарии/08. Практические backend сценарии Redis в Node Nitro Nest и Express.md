# Практические backend сценарии Redis в Node, Nitro, Nest и Express

> [!NOTE]
> Redis обычно подключают не ради “технологии”, а под конкретные backend-сценарии: cache, sessions, rate limit, queues, Pub/Sub и locks. Ниже - минимальные patterns, которые легко перенести между Express, NestJS и Nitro.

## Singleton client

```ts
// redis.ts
import { createClient } from 'redis';

export const redis = createClient({
  url: process.env.REDIS_URL,
});

redis.on('error', (error) => {
  console.error('Redis error', error);
});

await redis.connect();
```

## Express cache middleware

```ts
app.get('/api/products/:id', async (req, res) => {
  const key = `cache:product:${req.params.id}`;
  const cached = await redis.get(key);

  if (cached) {
    return res.json(JSON.parse(cached));
  }

  const product = await productService.findById(req.params.id);

  await redis.set(key, JSON.stringify(product), {
    EX: 300,
  });

  return res.json(product);
});
```

## Nitro handler

```ts
import { defineHandler } from 'nitro';
import { getRouterParam } from 'nitro/h3';
import { redis } from '../server/utils/redis';

export default defineHandler(async (event) => {
  const id = getRouterParam(event, 'id');
  const key = `cache:product:${id}`;
  const cached = await redis.get(key);

  if (cached) {
    return JSON.parse(cached);
  }

  const product = await productService.findById(id);

  await redis.set(key, JSON.stringify(product), {
    EX: 300,
  });

  return product;
});
```

## NestJS service

```ts
@Injectable()
export class RedisService {
  private readonly client = createClient({
    url: process.env.REDIS_URL,
  });

  async onModuleInit() {
    await this.client.connect();
  }

  async getJson<T>(key: string): Promise<T | null> {
    const value = await this.client.get(key);
    return value ? JSON.parse(value) as T : null;
  }

  async setJson(key: string, value: unknown, ttlSeconds: number) {
    await this.client.set(key, JSON.stringify(value), {
      EX: ttlSeconds,
    });
  }
}
```

## WebSocket fan-out

```ts
await publisher.publish('notifications', JSON.stringify({
  type: 'comment.created',
  postId,

```

Each instance subscribes and pushes to local WebSocket clients.

## Common checklist

- connection singleton;
- graceful shutdown;
- error listener;
- timeouts/reconnect strategy;
- env config;
- key prefixes;
- TTL;
- fallback behavior;
- tests with Redis container.

## Мини-шпаргалка

- Redis integration начинается с use case, не с клиента.
- Express/Nitro/Nest отличаются wrapper-ами, но patterns одинаковые.
- Cache и rate limit требуют TTL.
- Pub/Sub требует отдельного subscriber connection.
- Production code должен обрабатывать Redis outage.
