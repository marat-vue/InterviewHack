# Как создать глобальное состояние с useContext?

> [!summary]
> `useContext` позволяет читать значение из React Context без ручной передачи props через каждый уровень. Context подходит для данных, которые нужны многим компонентам: тема, язык, текущий пользователь, настройки. Но он не является полноценной заменой state manager во всех случаях.

## Базовый пример Context

```jsx
import { createContext, useContext, useState } from 'react'

const ThemeContext = createContext(null)

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light')

  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      {children}
    </ThemeContext.Provider>
  )
}
```

Использование:

```jsx
function ThemeButton() {
  const { theme, setTheme } = useContext(ThemeContext)

  return (
    <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>
      {theme}
    </button>
  )
}
```

## Подключение Provider

```jsx
function App() {
  return (
    <ThemeProvider>
      <Layout />
    </ThemeProvider>
  )
}
```

Все компоненты внутри `ThemeProvider` могут читать `ThemeContext`.

## Важный нюанс производительности

Когда значение Context меняется, компоненты, которые читают этот Context, могут перерендериться.

Плохо:

```jsx
<AppContext.Provider value={{ user, theme, cart, setTheme }}>
  {children}
</AppContext.Provider>
```

Один большой context для всего может вызывать лишние обновления.

Лучше разделять:

- `AuthContext`;
- `ThemeContext`;
- `LocaleContext`;
- отдельный state manager для часто меняющихся данных.

## Когда Context подходит?

- Тема.
- Язык.
- Auth user.
- Dependency injection.
- Настройки приложения.
- Данные, которые меняются не слишком часто.

Для больших списков, server state и частых обновлений часто лучше использовать специализированные инструменты.

## Мини-шпаргалка

- Context помогает избежать prop drilling.
- `createContext` создает Context.
- `Provider` передает значение вниз.
- `useContext` читает значение.
- Context нужно разделять по смыслу, чтобы не раздувать обновления.
