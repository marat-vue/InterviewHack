# Что такое декларативный подход?

> [!summary]
> Декларативный подход - это стиль программирования, при котором код описывает желаемый результат, а не детальный список команд для его достижения. В React это проявляется в том, что компонент возвращает UI для текущего состояния.

## Простыми словами

Декларативный подход:

```text
Покажи список задач, а выполненные задачи зачеркни.
```

Императивный подход:

```text
Создай ul, затем для каждой задачи создай li, вставь текст, проверь completed, добавь класс, вставь li в ul.
```

## Пример в React

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id} className={todo.done ? 'done' : ''}>
          {todo.title}
        </li>
      ))}
    </ul>
  )
}
```

Компонент говорит, как должен выглядеть список при текущих `todos`.

## Пример без React

```js
const list = document.createElement('ul')

for (const todo of todos) {
  const item = document.createElement('li')
  item.textContent = todo.title

  if (todo.done) {
    item.classList.add('done')
  }

  list.append(item)
}
```

Этот код вручную создает и изменяет DOM.

## Почему это важно для мышления в React?

В React лучше думать так:

```text
Какие данные есть?
Какой UI должен получиться из этих данных?
Где должно жить состояние?
Как состояние меняется через события?
```

А не так:

```text
Как мне найти элемент и вручную изменить его?
```

## Частые признаки недекларативного React-кода

- ручные `document.querySelector` внутри компонента;
- изменение DOM напрямую;
- попытка синхронизировать интерфейс через глобальные переменные;
- хранение данных вне state без причины;
- дублирование одного и того же состояния в нескольких местах.

## Мини-шпаргалка

- Декларативный подход описывает итоговый UI.
- React-компонент должен быть предсказуемым результатом props и state.
- DOM лучше не менять вручную.
- События меняют state, state меняет UI.
- Чем меньше ручной синхронизации, тем меньше ошибок.
