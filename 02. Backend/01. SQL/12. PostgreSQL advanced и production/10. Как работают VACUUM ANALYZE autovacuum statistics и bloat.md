# Как работают VACUUM, ANALYZE, autovacuum, statistics и bloat?

> [!NOTE]
> PostgreSQL использует MVCC, поэтому UPDATE/DELETE оставляют старые версии строк. `VACUUM` очищает dead tuples, `ANALYZE` обновляет статистику planner-а, а autovacuum делает это автоматически.

## Почему нужен VACUUM?

При UPDATE:

```sql
UPDATE users SET name = 'New' WHERE id = 1;
```

PostgreSQL не перезаписывает строку на месте в простом смысле. Он создает новую версию, а старая становится dead tuple после завершения транзакций, которым она могла быть видна.

`VACUUM` освобождает место для повторного использования.

## Что делает ANALYZE?

`ANALYZE` собирает статистику:

- распределение значений;
- null fraction;
- distinct estimates;
- most common values.

Planner использует это для выбора плана.

```sql
ANALYZE users;
```

## Autovacuum

Autovacuum автоматически запускает vacuum/analyze. Его нельзя просто выключить “чтобы не мешал”: без него будут bloat, плохие планы и риск transaction ID wraparound.

## Что такое bloat?

Bloat - лишнее место из-за dead tuples и устаревших страниц.

Симптомы:

- таблица сильно больше ожидаемого;
- индексы раздуты;
- запросы читают больше страниц;
- storage растет после массовых updates/deletes.

## VACUUM FULL

```sql
VACUUM FULL users;
```

`VACUUM FULL` физически переписывает таблицу и возвращает место ОС, но требует сильную блокировку. В production применяют осторожно.

## Что мониторить?

- dead tuples;
- autovacuum runs;
- table/index size;
- long transactions;
- replication slots;
- `last_autovacuum`;
- `last_analyze`.

## Мини-шпаргалка

- `VACUUM` чистит dead tuples.
- `ANALYZE` обновляет статистику planner-а.
- Autovacuum жизненно важен.
- Long transactions мешают cleanup.
- `VACUUM FULL` блокирующий и тяжелый.
