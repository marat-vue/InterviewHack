# Почему внешние ключи часто нужно индексировать?

> [!summary]
> Foreign key поддерживает целостность данных, но сам по себе не всегда автоматически создает индекс на дочерней колонке. Индекс на FK часто нужен для быстрых join, поиска дочерних строк и проверок при удалении родителя.

## Пример

```sql
CREATE TABLE orders (
  id bigint PRIMARY KEY,
  user_id bigint NOT NULL REFERENCES users(id)
);
```

Частый запрос:

```sql
SELECT *
FROM orders
WHERE user_id = 42;
```

Для него нужен индекс:

```sql
CREATE INDEX idx_orders_user_id
ON orders(user_id);
```

## JOIN

```sql
SELECT u.email, o.total
FROM users u
JOIN orders o ON o.user_id = u.id
WHERE u.id = 42;
```

Индекс на `orders.user_id` помогает быстро найти заказы пользователя.

## Удаление родителя

При удалении пользователя базе нужно проверить, есть ли связанные заказы. Без индекса на FK это может быть дорого.

## Мини-шпаргалка

- FK - про целостность, индекс - про скорость.
- На FK-колонки часто нужен индекс.
- Индекс помогает join и delete/update родителя.
- Некоторые СУБД автоматически индексируют не все FK.
- Проверяй планы запросов, а не верь на глаз.
