# Что такое Arrange Act Assert?

> [!summary]
> Arrange Act Assert - это простая структура теста: подготовить данные, выполнить действие, проверить результат. Она делает тесты читаемыми и помогает не смешивать setup, действие и ожидания в одну кашу.

## Из чего состоит AAA?

1. **Arrange** - подготовка окружения и данных.
2. **Act** - действие, которое тестируем.
3. **Assert** - проверка результата.

## Пример с функцией

```ts
test('adds discount to product price', () => {
  // Arrange
  const price = 1000;
  const discount = 15;

  // Act
  const result = applyDiscount(price, discount);

  // Assert
  expect(result).toBe(850);
});
```

Комментарии `Arrange`, `Act`, `Assert` не обязательно писать всегда. Они полезны в учебных материалах или сложных тестах.

## Пример с компонентом

```ts
test('emits submit with email', async () => {
  const wrapper = mount(LoginForm);

  await wrapper.find('[data-testid="email"]').setValue('ann@example.com');
  await wrapper.find('form').trigger('submit');

  expect(wrapper.emitted('submit')).toEqual([
    [{ email: 'ann@example.com' }],
  ]);
});
```

Здесь:

- Arrange - `mount(LoginForm)`;
- Act - заполнение input и submit;
- Assert - проверка emitted event.

## Почему это важно?

Плохой тест трудно читать:

```ts
test('works', async () => {
  const wrapper = mount(Form);
  expect(wrapper.text()).toContain('Email');
  await wrapper.find('input').setValue('a@b.com');
  expect(wrapper.vm.email).toBe('a@b.com');
  await wrapper.find('button').trigger('click');
  expect(wrapper.emitted()).toHaveProperty('submit');
});
```

Проблема: тест проверяет слишком много вещей сразу. Если он упадет, не сразу понятно почему.

Лучше разделять сценарии:

```ts
test('renders email field', () => {});
test('updates email field', async () => {});
test('submits form data', async () => {});
```

## Мини-шпаргалка

- Arrange - подготовь данные.
- Act - выполни действие.
- Assert - проверь результат.
- Один тест лучше посвящать одному поведению.
- Хорошее имя теста объясняет сценарий.
