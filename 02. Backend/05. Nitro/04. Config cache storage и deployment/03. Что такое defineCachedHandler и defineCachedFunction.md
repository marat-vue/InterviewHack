# Что такое defineCachedHandler и defineCachedFunction?

> [!NOTE]
> `defineCachedHandler` кеширует HTTP handler, а `defineCachedFunction` кеширует обычную async function. Первый подходит для целых endpoints, второй - для дорогих операций внутри handler.

## `defineCachedHandler`

```ts
import { defineCachedHandler } from 'nitro/cache';

export default defineCachedHandler(async () => {
  const posts = await cms.getPosts();

  return posts;
}, {
  maxAge: 60 * 10,
});
```

Используй, когда весь response endpoint можно кешировать.

## `defineCachedFunction`

```ts
import { defineCachedFunction } from 'nitro/cache';

const getGitHubStars = defineCachedFunction(async (event, repo: string) => {
  const data = await fetch(`https://api.github.com/repos/${repo}`).then((r) => r.json());

  return data.stargazers_count;
}, {
  name: 'github-stars',
  maxAge: 60 * 60,
  getKey: (_event, repo) => repo,
});

export default defineHandler(async (event) => {
  const repo = getRouterParam(event, 'repo')!;
  const stars = await getGitHubStars(event, repo);

  return {
    repo,
    stars,
  };
});
```

Для edge workers важно передавать `event` первым аргументом cached function, чтобы runtime мог корректно держать instance alive во время background refresh.

## Общие options

| Option | Что делает |
|---|---|
| `maxAge` | сколько секунд значение считается свежим |
| `swr` | включить/выключить stale-while-revalidate |
| `staleMaxAge` | сколько можно отдавать stale value |
| `base` | storage mount point для cache |
| `name` | имя cached function/handler |
| `group` | группа ключей в cache |
| `getKey` | функция построения cache key |
| `varies` | headers, которые учитываются при cache key/response |
| `shouldBypassCache` | условие, когда cache нужно обойти |
| `shouldInvalidateCache` | условие, когда cache нужно инвалидировать |

Набор options зависит от версии Nitro, но эти названия важно знать как основной mental model.

## Как выбрать между handler и function cache?

| Задача | Что выбрать |
|---|---|
| Закешировать весь `/api/posts` | `defineCachedHandler` |
| Закешировать запрос в CMS внутри нескольких handlers | `defineCachedFunction` |
| Закешировать route pattern | `routeRules.cache` |
| Закешировать user-specific data | лучше не кешировать глобально |
| Закешировать external API result | `defineCachedFunction` |

## Инвалидация

Если данные меняются редко, можно жить с `maxAge`.

Если данные меняются по событию:

- используй небольшой `maxAge`;
- добавь explicit key;
- храни cache в управляемом storage;
- делай invalidation после write operation;
- не кешируй write responses.

## Пример cache в Redis

```ts
export default defineConfig({
  storage: {
    redis: {
      driver: 'redis',
      url: process.env.REDIS_URL,
    },
  },
});
```

```ts
export default defineCachedHandler(handler, {
  base: 'redis',
  maxAge: 600,
});
```

## Мини-шпаргалка

- `defineCachedHandler` кеширует endpoint.
- `defineCachedFunction` кеширует функцию.
- Для edge передавай `event` первым аргументом cached function.
- `maxAge` отвечает за свежесть.
- `swr` позволяет отдавать stale и обновлять фонoм.
- Cache key должен учитывать все факторы, влияющие на ответ.
