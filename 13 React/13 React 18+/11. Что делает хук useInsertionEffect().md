# Что делает хук useInsertionEffect()?

> [!summary]
> `useInsertionEffect` - специальный хук React 18 для CSS-in-JS библиотек. Он нужен, чтобы вставлять CSS-правила до layout effects, чтобы компоненты могли измерять layout уже с примененными стилями. В обычной прикладной разработке почти всегда следует использовать `useEffect` или `useLayoutEffect`.

## Зачем появился useInsertionEffect?

CSS-in-JS библиотеки генерируют стили во время работы приложения:

```jsx
const Button = styled.button`
  background: tomato;
  color: white;
`
```

Внутри такая библиотека должна вставить CSS в DOM:

```html
<style>
  .button_abc123 {
    background: tomato;
    color: white;
  }
</style>
```

Если стиль вставится слишком поздно, возможны проблемы:

- контент на мгновение появится без стилей;
- `useLayoutEffect` другого компонента измерит layout до применения CSS;
- при concurrent rendering порядок вставки стилей станет менее предсказуемым.

`useInsertionEffect` дает CSS-in-JS библиотекам место, где можно синхронно вставить стили перед layout effects.

## Сигнатура

```jsx
useInsertionEffect(setup, dependencies)
```

Пример:

```jsx
import { useInsertionEffect } from 'react'

function useDynamicStyle(className, cssText) {
  useInsertionEffect(() => {
    const style = document.createElement('style')
    style.textContent = `.${className} { ${cssText} }`
    document.head.appendChild(style)

    return () => {
      style.remove()
    }
  }, [className, cssText])
}
```

Использование:

```jsx
function Button({ color }) {
  const className = `button-${color}`

  useDynamicStyle(className, `background: ${color}; color: white;`)

  return <button className={className}>Save</button>
}
```

Это учебный пример. В реальном проекте лучше пользоваться готовой CSS-in-JS библиотекой, а не генерировать стили вручную.

## Порядок эффектов

Упрощенно:

| Хук | Когда нужен |
|---|---|
| `useInsertionEffect` | вставка CSS-правил библиотекой |
| `useLayoutEffect` | измерение DOM и синхронные layout-правки |
| `useEffect` | запросы, подписки, логирование, интеграции |

`useInsertionEffect` не заменяет `useEffect`. Его задача очень узкая.

## Что нельзя делать внутри useInsertionEffect?

Нельзя использовать его как универсальный "самый ранний effect".

Не стоит:

- отправлять HTTP-запросы;
- подписываться на события приложения;
- читать размеры DOM;
- менять state;
- запускать бизнес-логику;
- работать с refs как с уже полностью готовыми DOM-узлами.

Для измерения layout используй `useLayoutEffect`:

```jsx
function Tooltip() {
  const ref = useRef(null)

  useLayoutEffect(() => {
    const rect = ref.current.getBoundingClientRect()
    // расчет позиции tooltip
  }, [])

  return <div ref={ref}>Tooltip</div>
}
```

Для обычных побочных эффектов используй `useEffect`:

```jsx
function Page() {
  useEffect(() => {
    document.title = 'Profile'
  }, [])

  return <h1>Profile</h1>
}
```

## Почему это важно при concurrent rendering?

Concurrent rendering может прерывать и повторять render. CSS-in-JS библиотекам важно не вставлять стили хаотично и не допускать, чтобы layout effects сработали раньше нужных CSS-правил.

`useInsertionEffect` помогает библиотекам встроиться в commit-процесс React более безопасно.

## Нужен ли он в обычном приложении?

Почти никогда.

Обычно выбор такой:

- `useEffect` - по умолчанию;
- `useLayoutEffect` - если нужно измерить DOM до paint;
- `useInsertionEffect` - если ты пишешь CSS-in-JS библиотеку или очень низкоуровневую styling-инфраструктуру.

## Что отвечать на собеседовании?

`useInsertionEffect` - низкоуровневый React 18 hook для вставки стилей CSS-in-JS библиотеками до layout effects. Он не предназначен для запросов, подписок, измерения DOM и обычной бизнес-логики.

## Частые ошибки

- Использовать `useInsertionEffect` вместо `useEffect`, потому что он "раньше".
- Писать туда запросы к API.
- Измерять DOM внутри него.
- Обновлять state.
- Добавлять этот хук в обычные компоненты без реальной причины.

## Мини-шпаргалка

- Хук нужен главным образом авторам CSS-in-JS библиотек.
- Выполняется до layout effects.
- Помогает избежать проблем с поздней вставкой CSS.
- Не предназначен для прикладной логики.
- Для DOM-измерений используй `useLayoutEffect`.
