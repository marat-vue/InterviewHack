# Что такое Root Layout?

> [!summary]
> Root Layout - это главный layout приложения в файле `app/layout.tsx`. Он оборачивает все маршруты App Router и обязан возвращать теги `<html>` и `<body>`.

## Где находится Root Layout?

```text
app/
  layout.tsx
  page.tsx
```

`app/layout.tsx` - это корень дерева маршрутов. Все страницы и вложенные layout находятся внутри него.

## Минимальный пример

```tsx
// app/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  )
}
```

В отличие от обычных вложенных layout, Root Layout должен содержать HTML-оболочку документа.

## Что обычно кладут в Root Layout?

- глобальный CSS;
- базовые шрифты;
- тег `<html lang="ru">`;
- глобальные metadata;
- провайдеры темы, авторизации, query-клиента;
- аналитику;
- общие компоненты, действительно нужные всему приложению.

Пример:

```tsx
// app/layout.tsx
import type { Metadata } from 'next'
import { Inter } from 'next/font/google'
import './globals.css'
import { Providers } from './providers'

const inter = Inter({ subsets: ['latin', 'cyrillic'] })

export const metadata: Metadata = {
  title: {
    template: '%s | Frontend Notes',
    default: 'Frontend Notes',
  },
  description: 'База знаний по frontend-разработке',
}

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="ru">
      <body className={inter.className}>
        <Providers>{children}</Providers>
      </body>
    </html>
  )
}
```

## Почему Root Layout лучше оставлять серверным?

Root Layout оборачивает все приложение. Если поставить в нем `'use client'`, весь этот уровень станет клиентским компонентом.

Плохой сигнал:

```tsx
'use client'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  )
}
```

Лучше вынести интерактивную часть в отдельный `Providers`:

```tsx
// app/providers.tsx
'use client'

export function Providers({ children }: { children: React.ReactNode }) {
  return <ThemeProvider>{children}</ThemeProvider>
}
```

Так Root Layout остается Server Component, а клиентским становится только нужный кусок.

## Можно ли иметь несколько Root Layout?

Да, через route groups можно создать несколько независимых root layouts:

```text
app/
  (shop)/
    layout.tsx
    page.tsx
  (admin)/
    layout.tsx
    page.tsx
```

Это полезно, если у частей приложения полностью разная HTML-оболочка. Но при переходе между разными root layouts может происходить полноценная загрузка страницы, поэтому такой прием используют осознанно.

## Что отвечать на собеседовании?

Root Layout - это главный layout App Router в `app/layout.tsx`. Он обязателен для дерева `app`, оборачивает все маршруты, должен возвращать `<html>` и `<body>`, часто содержит глобальные стили, шрифты, metadata и провайдеры. Его желательно оставлять серверным, а клиентские провайдеры выносить в отдельный компонент.

## Частые ошибки

- Забывать `<html>` и `<body>`.
- Добавлять `<head>` вручную вместо Metadata API.
- Делать Root Layout клиентским из-за одного провайдера.
- Класть в Root Layout логику, нужную только одной странице.
- Не указывать `lang` у `<html>`.
- Дублировать глобальные стили в разных layout.

## Мини-шпаргалка

- Root Layout - `app/layout.tsx`.
- Оборачивает все маршруты.
- Обязан вернуть `<html>` и `<body>`.
- Подходит для global CSS, fonts, providers, metadata.
- Лучше оставлять Server Component.
- Несколько root layouts возможны через route groups.
