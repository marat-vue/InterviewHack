# createRoot() vs render()

> [!summary]
> `createRoot` - новый API для создания React root в React 18+. Старый `ReactDOM.render` относится к legacy API и не включает полноценное поведение нового concurrent renderer для корня приложения.

## Старый способ

```jsx
import ReactDOM from 'react-dom'

ReactDOM.render(<App />, document.getElementById('root'))
```

Этот API использовали в React 17 и раньше.

## Новый способ

```jsx
import { createRoot } from 'react-dom/client'

const rootElement = document.getElementById('root')
const root = createRoot(rootElement)

root.render(<App />)
```

Для SSR используют не `createRoot`, а `hydrateRoot`:

```jsx
import { hydrateRoot } from 'react-dom/client'

hydrateRoot(document.getElementById('root'), <App />)
```

## Что меняется?

`createRoot` включает root, который работает с возможностями React 18:

- automatic batching;
- concurrent rendering;
- transitions;
- новый Strict Mode development behavior;
- современный root lifecycle.

## Automatic batching пример

```jsx
setTimeout(() => {
  setCount((count) => count + 1)
  setText('updated')
  // createRoot + React 18: один render
}, 1000)
```

В legacy behavior такие updates могли приводить к нескольким render.

## unmount

Старый API:

```jsx
ReactDOM.unmountComponentAtNode(container)
```

Новый API:

```jsx
root.unmount()
```

## Миграция

Обычно минимальная миграция выглядит так:

```jsx
import { createRoot } from 'react-dom/client'
import App from './App'

createRoot(document.getElementById('root')).render(<App />)
```

Если приложение использует SSR:

```jsx
hydrateRoot(document.getElementById('root'), <App />)
```

## Мини-шпаргалка

- `ReactDOM.render` - legacy API.
- `createRoot` - клиентский root для React 18+.
- Для SSR нужен `hydrateRoot`.
- `root.unmount()` заменяет старый unmount API.
- Без нового root нельзя нормально перейти на современное поведение React 18+.
