# Что такое Nitro и зачем он нужен?

> [!NOTE]
> Nitro - это full-stack server framework для современного JavaScript/TypeScript. Он умеет запускать server routes, API endpoints, middleware, plugins, cache, storage, tasks, WebSocket и собирать приложение под разные runtime: Node.js, Bun, Deno, serverless и edge.

## Простое определение

Nitro - это серверный слой, который принимает HTTP-запрос, находит подходящий handler, дает тебе удобный `event`-объект и возвращает ответ в формате, который можно запустить на разных платформах.

```txt
HTTP request
  -> Nitro server
    -> route rules
    -> middleware
    -> route handler
    -> H3 response
  -> deployment runtime
```

В Nuxt Nitro отвечает за `server/` директорию и production server output. В standalone-проекте Nitro можно использовать как отдельный backend-фреймворк.

## Зачем нужен Nitro?

Nitro нужен, когда хочется писать backend на TypeScript без тяжелого MVC-фреймворка, но с готовой инфраструктурой:

- file-based routing;
- API routes;
- typed handlers;
- middleware;
- runtime config;
- cache;
- KV storage;
- deployment presets;
- serverless/edge compatibility;
- route rules;
- plugins;
- tasks;
- WebSocket;
- OpenAPI metadata;
- integration with Nuxt.

## Как выглядит минимальный endpoint?

```ts
// server/routes/api/health.get.ts
import { defineHandler } from 'nitro';

export default defineHandler(() => {
  return {
    status: 'ok',
  };
});
```

В Nuxt чаще встретишь такой вариант:

```ts
// server/api/health.get.ts
export default defineEventHandler(() => {
  return {
    status: 'ok',
  };
});
```

Идея одна: handler возвращает значение, а Nitro/H3 превращает его в HTTP response.

## Чем Nitro удобен для backend?

Nitro хорошо подходит для:

- BFF-слоя между frontend и внешними API;
- backend внутри Nuxt-приложения;
- небольшого standalone API;
- serverless functions;
- edge endpoints;
- proxy endpoints;
- webhook handlers;
- auth endpoints;
- cached API;
- server-side интеграций с Prisma, Redis, email, storage.

## Что Nitro не делает сам?

Nitro не заменяет все backend-решения:

- он не является ORM - для БД подключают Prisma, Drizzle, SQL client;
- он не является auth-системой - для auth можно подключить Better Auth;
- он не навязывает DI-контейнер как NestJS;
- он не проектирует доменную архитектуру за тебя;
- он не отменяет HTTP, security, SQL и transaction-мышление.

## Где Nitro особенно силен?

Nitro силен там, где нужна легкая, portable server layer:

```txt
Один код handlers
  -> Node.js server
  -> serverless functions
  -> edge worker
  -> Nuxt server output
```

Для собеседования важно сказать: главная идея Nitro - писать server code один раз, а собирать под разные deployment targets.

## Мини-шпаргалка

- Nitro - server framework и server engine.
- В Nuxt он обслуживает server routes и production output.
- В standalone-проекте Nitro можно использовать как отдельный API framework.
- Handler возвращает объект, строку, `Response`, stream или другой поддерживаемый ответ.
- Для базы данных, auth и тестов подключают внешние инструменты: Prisma, Better Auth, Vitest, `@nuxt/test-utils`.
