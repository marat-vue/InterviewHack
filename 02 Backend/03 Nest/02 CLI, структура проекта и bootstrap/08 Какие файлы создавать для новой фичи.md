# Какие файлы создавать для новой фичи?

> [!NOTE]
> Для новой фичи в NestJS обычно создают feature module, controller, service и DTO. Если фича работает с базой, добавляют repository, entity/schema или Prisma model.

## Минимальный набор

```txt
users/
  users.module.ts
  users.controller.ts
  users.service.ts
  dto/
    create-user.dto.ts
    update-user.dto.ts
```

## Если есть база данных

```txt
users/
  users.module.ts
  users.controller.ts
  users.service.ts
  users.repository.ts
  dto/
    create-user.dto.ts
    update-user.dto.ts
```

Если используется TypeORM, может быть `entities/user.entity.ts`. Если Prisma, модель обычно живет в `prisma/schema.prisma`, а queries могут быть в repository.

## Кто за что отвечает?

| Файл | Ответственность |
|---|---|
| `module` | регистрирует controller/providers |
| `controller` | HTTP routes |
| `service` | use cases |
| `repository` | database access |
| `dto` | input/output contract |

## Мини-шпаргалка

- Новая фича почти всегда начинается с module.
- Controller не должен ходить в БД напрямую.
- DTO держи рядом с feature module.
- Repository нужен, если data access усложняется.
- Не создавай папки заранее без понятной роли.
