# Зачем нужен patch flag

> [!summary]
> **Patch flag** - это подсказка, которую компилятор Vue добавляет к VNode. Она сообщает runtime, какая именно часть узла динамическая и что нужно проверить при обновлении.

## Главное

Без подсказок runtime пришлось бы сравнивать узел целиком: текст, классы, стили, props, children. Patch flags позволяют сузить проверку.

```vue
<template>
  <p>{{ message }}</p>
</template>
```

Для такого узла Vue понимает: динамическим является текст. При обновлении не нужно заново анализировать все свойства элемента.

## Пример с классом и текстом

```vue
<template>
  <button :class="variant">
    {{ label }}
  </button>
</template>
```

У этого узла динамические части:

- `class`, потому что он зависит от `variant`;
- текст, потому что он зависит от `label`.

Именно эти зоны runtime проверяет в первую очередь.

## Как это связано с компилятором

Patch flags появляются после компиляции шаблона. Разработчик обычно не пишет их вручную.

```text
template
  -> compiler analyzes dynamic bindings
  -> compiler adds patch flags
  -> runtime uses flags during patch
```

## Условный пример render-кода

Это не точная копия внутреннего вывода Vue, а пример идеи:

```js
createElementVNode(
  "p",
  null,
  message,
  TEXT
);
```

Флаг `TEXT` говорит: у этого узла нужно обновлять текстовое содержимое.

## Какие динамические части могут помечаться

- текст;
- `class`;
- `style`;
- отдельные props;
- список динамических props;
- события;
- фрагменты и списки.

## Почему это ускоряет обновления

Patch flags уменьшают количество сравнений. Vue не тратит время на проверку того, что компилятор уже признал статическим.

## Мини-шпаргалка

- Patch flag - подсказка для runtime Vue.
- Его добавляет компилятор шаблона.
- Он показывает, что именно может измениться в VNode.
- Благодаря patch flags Vue меньше сравнивает и быстрее обновляет DOM.
- Patch flags работают вместе с block tree.
