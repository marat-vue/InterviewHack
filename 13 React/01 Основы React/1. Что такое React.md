# Что такое React?

> [!summary]
> React - это JavaScript-библиотека для создания пользовательских интерфейсов. Она помогает описывать UI как набор компонентов, автоматически обновлять экран при изменении данных и разделять сложный интерфейс на маленькие независимые части.

## Простое определение

React отвечает на вопрос:

```text
Как по текущим данным приложения получить интерфейс на экране?
```

Вместо ручного изменения DOM ты описываешь, как UI должен выглядеть при конкретном состоянии:

```jsx
function Greeting({ name }) {
  return <h1>Привет, {name}!</h1>
}
```

Если `name` изменится, React заново вычислит результат компонента и обновит нужную часть интерфейса.

## Из каких идей состоит React?

| Идея | Что означает |
|---|---|
| Компоненты | UI делится на переиспользуемые части |
| JSX | разметка описывается внутри JavaScript |
| Props | данные передаются от родителя к ребенку |
| State | компонент хранит изменяемые данные |
| Render | React вызывает компоненты и получает описание UI |
| Reconciliation | React сравнивает старое и новое дерево элементов |

## Пример компонента со state

```jsx
import { useState } from 'react'

function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      Счет: {count}
    </button>
  )
}
```

Здесь `count` - состояние компонента. Когда вызывается `setCount`, React запускает новый render и показывает обновленное значение.

## Что React делает, а что нет?

React делает:

- помогает описывать интерфейс;
- обновляет UI при изменении состояния;
- дает модель компонентов;
- предоставляет хуки;
- работает с DOM через React DOM.

React сам по себе не решает:

- routing;
- работу с серверным API;
- глобальное состояние;
- сборку проекта;
- стилизацию;
- SSR и SSG.

Для этого обычно используют дополнительные библиотеки или фреймворки: React Router, TanStack Query, Redux Toolkit, Vite, Next.js.

## Как объяснить на собеседовании?

Хороший ответ:

```text
React - это библиотека для построения UI на основе компонентов. Мы описываем интерфейс декларативно: как он должен выглядеть при текущих props и state. Когда данные меняются, React заново вызывает нужные компоненты, сравнивает результат с предыдущим деревом и применяет минимальные изменения к DOM.
```

## Частые ошибки понимания

- React - не полноценный фреймворк сам по себе.
- React не обновляет весь DOM при каждом изменении.
- JSX - это не HTML, а синтаксис, который превращается в JavaScript.
- Компонент должен быть чистым во время render.
- State не нужно использовать для всего подряд.

## Мини-шпаргалка

- React = компоненты + декларативный UI + обновление по state.
- Компонент - функция, которая возвращает React-элементы.
- Props приходят извне, state хранится внутри.
- При изменении state React запускает render.
- React описывает UI, а React DOM применяет изменения к браузерному DOM.
