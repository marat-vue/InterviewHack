# React Router в проекте и вопросы на собеседовании

> [!summary]
> В реальном проекте React Router важен не только для страниц, но и для архитектуры URL: layouts, protected routes, query params, redirects, 404, pending UI, loaders/actions и интеграции с server state.

## Как проектировать routes?

Хорошая структура отражает продукт:

```text
/
/login
/dashboard
/dashboard/settings
/users
/users/:userId
/products?category=books&page=2
```

URL должен быть:

- читаемым;
- стабильным;
- bookmark-friendly;
- достаточно выразительным;
- не завязанным на внутренний UI-state без необходимости.

## Protected routes

```tsx
function RequireAuth() {
  const user = useAuthStore((state) => state.user)

  if (!user) {
    return <Navigate to="/login" replace />
  }

  return <Outlet />
}
```

Routes:

```tsx
{
  element: <RequireAuth />,
  children: [
    { path: '/dashboard', element: <Dashboard /> },
  ],
}
```

Важно: клиентская защита route не заменяет серверную авторизацию.

## Query params или state?

В URL стоит хранить:

- search query;
- filters;
- sort;
- page;
- selected tab, если нужна sharable ссылка.

В local state можно хранить:

- открытую модалку;
- временный draft;
- hover state;
- несохраняемый wizard-step.

## Частые вопросы

### Чем `Link` отличается от `<a>`?

`Link` делает client-side navigation без полной перезагрузки. `<a href>` по умолчанию загружает документ заново.

### Когда использовать `useNavigate`?

После действия пользователя или async operation: сохранить форму и перейти дальше. В loaders/actions для redirect лучше использовать `redirect`.

### Что такое nested routes?

Это routes внутри routes, где родительский компонент обычно является layout, а дочерний рендерится через `Outlet`.

### Почему query params лучше, чем state для фильтров?

Потому что URL можно скопировать, обновить, открыть заново и сохранить в истории браузера.

## Частые ошибки

- Хранить важные фильтры только в local state.
- Использовать `useNavigate` вместо обычного `Link`.
- Делать protected route только на клиенте и забывать backend authorization.
- Не добавлять 404 route.
- Неверно располагать `Outlet`.
- Путать path params и search params.

## Что отвечать на собеседовании?

React Router в проекте отвечает за URL как часть состояния приложения. Хороший разработчик умеет выбирать между path params, search params и local state, строить nested layouts, защищать routes, делать redirects, использовать loaders/actions и показывать pending UI.

## Мини-шпаргалка

- Фильтры и page часто должны жить в URL.
- `Link` лучше `useNavigate` для обычных переходов.
- Protected route на клиенте - только UX, не безопасность.
- `Outlet` нужен layout routes.
- 404 route обязателен.
