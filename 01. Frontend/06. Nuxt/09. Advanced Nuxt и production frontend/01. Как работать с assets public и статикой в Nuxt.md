# Как работать с assets, public и статикой в Nuxt?

> [!NOTE]
> В Nuxt есть два основных способа хранить статические файлы: `app/assets` для файлов, которые должен обработать bundler, и `public` для файлов, которые надо отдать как есть по стабильному URL.

## Зачем разделять `assets` и `public`?

Если файл участвует в сборке, оптимизации, CSS imports или компонентных imports, клади его в:

```text
app/assets/
```

Если файл должен быть доступен напрямую по URL без обработки Vite/Nitro, клади его в:

```text
public/
```

Примеры:

| Что хранить | Где хранить | Почему |
| --- | --- | --- |
| SCSS/CSS design tokens | `app/assets/css` | Подключается в bundle. |
| Изображение для компонента | `app/assets/images` | Можно импортировать и хешировать. |
| `favicon.ico` | `public/favicon.ico` | Доступен как `/favicon.ico`. |
| `robots.txt` | `public/robots.txt` или SEO module | Должен быть доступен по `/robots.txt`. |
| `manifest.webmanifest` | `public/manifest.webmanifest` | Стабильный public URL. |
| Большой PDF | `public/files/report.pdf` | Можно скачать напрямую. |

## Пример структуры

```text
app/
  assets/
    css/
      main.css
    images/
      hero.webp
public/
  favicon.ico
  robots.txt
  files/
    terms.pdf
```

## Как подключить global CSS?

`nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  css: ['~/assets/css/main.css']
})
```

`app/assets/css/main.css`:

```css
:root {
  --color-brand: #0f766e;
}

body {
  margin: 0;
  font-family: system-ui, sans-serif;
}
```

## Как импортировать asset в компонент?

```vue
<script setup lang="ts">
import heroUrl from '~/assets/images/hero.webp'
</script>

<template>
  <img :src="heroUrl" alt="Главный экран продукта">
</template>
```

Bundler сможет обработать этот файл: добавить hash, оптимизировать путь и включить в dependency graph.

## Как ссылаться на файл из `public`?

Файл:

```text
public/files/terms.pdf
```

Ссылка:

```vue
<template>
  <a href="/files/terms.pdf">Условия использования</a>
</template>
```

Для `public` не нужен import. Файл отдается как есть.

## Что с изображениями?

Для обычного `<img>` можно использовать оба подхода:

```vue
<template>
  <img src="/logo.svg" alt="Logo">
</template>
```

или:

```vue
<script setup lang="ts">
import logo from '~/assets/images/logo.svg'
</script>

<template>
  <img :src="logo" alt="Logo">
</template>
```

Для production изображений лучше часто использовать `@nuxt/image`:

```vue
<template>
  <NuxtImg
    src="/images/product.jpg"
    width="720"
    height="480"
    alt="Карточка товара"
    format="webp"
  />
</template>
```

## SEO-файлы

Минимальный вариант:

```text
public/robots.txt
public/sitemap.xml
```

Но для живого проекта лучше использовать Nuxt SEO modules:

- sitemap генерировать из маршрутов;
- robots настраивать по окружению;
- canonical и social meta держать рядом со страницами;
- structured data генерировать программно.

## Когда не класть файл в `public`?

Не клади в `public`:

- приватные документы;
- `.env`;
- source maps, если они раскрывают исходники и не должны быть публичными;
- admin-only exports;
- файлы, доступ к которым должен проверяться авторизацией.

`public` означает: браузер может запросить файл напрямую.

## Что отвечать на собеседовании?

В Nuxt `app/assets` используется для файлов, которые должен обработать bundler: CSS, изображения в компонентах, шрифты, импортируемые ресурсы. `public` используется для файлов, которые надо отдать как есть по URL, например `/favicon.ico` или `/files/terms.pdf`. Секреты и приватные файлы в `public` класть нельзя.

## Частые ошибки

- Класть секретные файлы в `public`.
- Пытаться импортировать `/public/...` как обычный module.
- Держать большие пользовательские uploads внутри repo.
- Не задавать `width`/`height` для изображений и получать layout shift.
- Путать `app/assets` и `public` при сборке Docker image.

## Мини-шпаргалка

- `app/assets` - processed by bundler.
- `public` - served as static URL.
- `/favicon.ico` лежит в `public/favicon.ico`.
- Global CSS подключается через `css` в `nuxt.config.ts`.
- Для responsive images используй `@nuxt/image`.
- Все в `public` публично.
