# Что такое streaming rendering?

> [!summary]
> Streaming rendering - постепенная отправка UI с сервера в браузер частями. В Next.js streaming строится на React Server Components и Suspense: shell страницы может прийти сразу, а медленные блоки догружаются позже.

## Зачем нужен streaming?

Без streaming сервер может ждать самый медленный блок:

```text
Header готов быстро
Sidebar готов быстро
RevenueChart ждет медленный API
Вся страница ждет RevenueChart
```

Со streaming можно отправить shell и fallback:

```text
Header + Sidebar + ChartSkeleton -> сразу
RevenueChart -> позже
```

## loading.tsx

Самый простой способ включить loading UI для segment:

```text
app/
  dashboard/
    loading.tsx
    page.tsx
```

```tsx
export default function Loading() {
  return <DashboardSkeleton />
}
```

## Suspense

```tsx
import { Suspense } from 'react'

export default function DashboardPage() {
  return (
    <>
      <Header />

      <Suspense fallback={<RevenueSkeleton />}>
        <RevenueChart />
      </Suspense>
    </>
  )
}
```

`RevenueChart` может ждать данные, не блокируя весь route.

## Когда streaming полезен?

- dashboard;
- страницы с медленными виджетами;
- profile + secondary data;
- комментарии под статьей;
- рекомендации;
- аналитика;
- большие nested sections.

## Что отвечать на собеседовании?

Streaming rendering позволяет Next.js отправлять HTML/RSC результат частями, не ожидая готовности всего route. `loading.tsx` создает Suspense boundary для сегмента, а ручной `<Suspense>` дает более точный контроль над отдельными блоками.

## Частые ошибки

- Делать один огромный Suspense вокруг всей страницы.
- Показывать spinner вместо skeleton для больших блоков.
- Думать, что streaming ускоряет сам backend.
- Не группировать зависимые данные.
- Считать streaming заменой кешированию.

## Мини-шпаргалка

- Streaming = UI частями.
- Основа: Suspense.
- `loading.tsx` - segment-level fallback.
- `<Suspense>` - granular fallback.
- Shell страницы может прийти раньше.
- Не заменяет оптимизацию данных.
