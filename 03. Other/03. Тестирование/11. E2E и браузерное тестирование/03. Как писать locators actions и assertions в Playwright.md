# Как писать locators, actions и assertions в Playwright?

> [!summary]
> В Playwright тест обычно состоит из перехода на страницу, поиска элемента через locator, действия пользователя и web-first assertion. Хорошие locators опираются на роли, labels, текст и стабильные test ids.

## Locator

Locator - это способ найти элемент:

```ts
const submitButton = page.getByRole('button', { name: 'Сохранить' });
```

Playwright рекомендует locators, похожие на пользовательский опыт:

```ts
page.getByRole('button', { name: 'Войти' });
page.getByLabel('Email');
page.getByText('Заказ оформлен');
page.getByTestId('cart-total');
```

## Actions

```ts
await page.getByLabel('Email').fill('ann@example.com');
await page.getByLabel('Password').fill('secret123');
await page.getByRole('button', { name: 'Войти' }).click();
```

Перед действиями Playwright делает actionability checks: элемент должен быть видимым, доступным и готовым к взаимодействию.

## Assertions

```ts
await expect(page.getByText('Добро пожаловать')).toBeVisible();
await expect(page).toHaveURL('/profile');
await expect(page.getByTestId('cart-count')).toHaveText('3');
```

Playwright assertions автоматически ждут выполнения условия до timeout.

## Плохой locator

```ts
await page.locator('.button:nth-child(3)').click();
```

Он ломается от изменения CSS или порядка элементов.

Лучше:

```ts
await page.getByRole('button', { name: 'Удалить товар' }).click();
```

## Мини-шпаргалка

- Locator ищет элемент лениво и стабильно.
- Лучше использовать roles, labels и text.
- CSS selectors оставляй для крайних случаев.
- Assertions в Playwright auto-retry.
- Не добавляй ручные `waitForTimeout`, если можно ждать состояние.
