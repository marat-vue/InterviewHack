# Как оптимизировать большие таблицы

> [!summary]
> Большие таблицы оптимизируют через виртуализацию, пагинацию, серверную фильтрацию, стабильные ключи, мемоизацию вычислений и уменьшение количества реактивных данных, которые Vue должен отслеживать.

## Главная проблема

Таблица на тысячи строк создает много DOM-узлов и компонентов. Даже если Vue эффективно обновляет Virtual DOM, браузеру все равно нужно хранить, раскладывать и перерисовывать реальные элементы.

```text
10 000 rows x 8 columns = 80 000 cells
```

Это много работы для рендера, layout, paint и обработки событий.

## Использовать пагинацию

Если пользователю не нужно видеть все строки сразу, проще показывать данные страницами.

```vue
<template>
  <DataTable :rows="pageRows" />
  <Pagination v-model:page="page" :total="total" />
</template>
```

Пагинация уменьшает количество DOM-узлов и хорошо подходит для бизнес-таблиц.

## Использовать виртуализацию

Виртуализация рендерит только видимые строки и небольшой запас вокруг viewport.

```vue
<template>
  <VirtualList
    :items="rows"
    :item-height="44"
  >
    <template #default="{ item }">
      <TableRow :row="item" />
    </template>
  </VirtualList>
</template>
```

Пользователь может скроллить огромный список, но в DOM находится ограниченное количество строк.

## Переносить тяжелые операции на сервер

Фильтрация, сортировка и поиск по большим объемам данных часто должны выполняться на backend.

```js
const { data } = await api.get("/products", {
  params: {
    page: page.value,
    sort: sort.value,
    query: query.value,
  },
});
```

Frontend получает только нужный фрагмент данных.

## Стабилизировать key и props

```vue
<TableRow
  v-for="row in rows"
  :key="row.id"
  :row="row"
/>
```

Стабильный `key` помогает Vue корректно переиспользовать строки. Не стоит использовать индекс массива, если строки могут сортироваться или удаляться.

## Уменьшать реактивность больших структур

Если данные большие и редко меняются, иногда полезны `shallowRef` или `markRaw`.

```js
import { shallowRef } from "vue";

const rows = shallowRef([]);

rows.value = await loadRows();
```

`shallowRef` отслеживает замену массива, но не делает глубоко реактивным каждый вложенный объект.

## Убирать лишние обработчики

Вместо обработчика на каждой ячейке можно использовать один обработчик на таблице.

```vue
<table @click="handleTableClick">
  <!-- rows -->
</table>
```

Это особенно полезно, когда строк и ячеек много.

## Мини-шпаргалка

- Для больших таблиц главный враг - количество DOM-узлов.
- Пагинация проще, виртуализация мощнее.
- Тяжелую сортировку и поиск лучше переносить на сервер.
- Используй стабильные `key`.
- Для больших неизменяемых данных рассмотри `shallowRef`.
- Оптимизируй после измерений, а не на глаз.
