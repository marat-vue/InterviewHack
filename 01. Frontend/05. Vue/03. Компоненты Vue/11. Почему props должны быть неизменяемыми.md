# Почему props должны быть неизменяемыми?

> [!NOTE]
> Props должны быть неизменяемыми в дочернем компоненте, потому что источник этих данных находится у родителя. Ребенок читает props, но не владеет ими.

## Вопрос

Почему props должны быть неизменяемыми?

## Главная причина

Если ребенок меняет prop напрямую, поток данных становится неясным: родитель думает, что владеет состоянием, а ребенок меняет его изнутри.

```vue
<script setup>
const props = defineProps<{ count: number }>();

// props.count++; // ошибка
</script>
```

Vue предупреждает о такой мутации.

## Правильная схема

Ребенок сообщает о намерении изменить данные через событие.

```vue
<!-- Child.vue -->
<script setup>
defineProps<{ count: number }>();
const emit = defineEmits<{ increment: [] }>();
</script>

<template>
  <button @click="emit('increment')">{{ count }}</button>
</template>
```

```vue
<!-- Parent.vue -->
<template>
  <Child :count="count" @increment="count++" />
</template>
```

## Если нужна локальная правка

Можно создать локальную копию prop.

```typescript
const props = defineProps<{ initialName: string }>();
const name = ref(props.initialName);
```

Так дочерний компонент редактирует свое состояние, а не prop.

## Вложенные объекты

Мутировать вложенные свойства объекта-prop технически возможно, но архитектурно опасно: источник изменения становится скрытым.

## Мини-шпаргалка

- Props принадлежат родителю.
- Дочерний компонент должен считать props readonly.
- Изменения наверх отправляют через emit.
- Для локального редактирования делай копию.
- Вложенные мутации props лучше избегать.
