# Что такое “Layered Architecture” в фронтенде?

> [!summary]
> Layered Architecture делит frontend-приложение на слои с разной ответственностью. Слои помогают контролировать зависимости: UI не должен случайно знать детали API, а shared-код не должен зависеть от конкретной страницы.

## Простая идея

```text
Page -> Feature -> Entity -> Shared
```

Верхний слой собирает сценарий, нижний предоставляет более базовые детали.

## Пример слоев

```text
src/
  app/          # запуск приложения, providers, router
  pages/        # страницы
  widgets/      # крупные блоки страниц
  features/     # пользовательские действия
  entities/     # бизнес-сущности
  shared/       # общий технический код
```

Это похоже на FSD, но сама идея layered architecture шире: можно использовать другие названия слоев, если правила понятны команде.

## Что класть в shared?

```text
shared/
  ui/
    Button/
    Modal/
  api/
    httpClient.ts
  lib/
    formatDate.ts
  config/
    env.ts
```

`shared` не должен знать про `user`, `cart`, `checkout` и другие бизнес-модули.

## Что класть в entities?

```text
entities/product/
  ui/
    ProductPrice.tsx
  model/
    types.ts
    selectors.ts
  api/
    productApi.ts
  index.ts
```

Entity описывает бизнес-сущность, но не конкретное действие пользователя.

## Что класть в features?

```text
features/add-to-cart/
  ui/
    AddToCartButton.tsx
  model/
    useAddToCart.ts
  index.ts
```

Feature - это пользовательское действие: добавить в корзину, войти, применить фильтр, сменить язык.

## Главное правило зависимостей

Плохо:

```ts
// entities/product/model/types.ts
import { CatalogPageFilters } from '@/pages/catalog'
```

Entity не должна знать о странице.

Хорошо:

```ts
// pages/catalog/ui/CatalogPage.tsx
import { ProductList } from '@/widgets/product-list'
import { ProductFilters } from '@/features/filter-products'
```

Страница может знать о нижних слоях и собирать их.

## Почему это важно?

Layered architecture помогает:

- предотвратить хаотичные импорты;
- уменьшить циклические зависимости;
- упростить onboarding;
- ограничить blast radius изменений;
- сделать проект предсказуемым.

## Мини-шпаргалка

- Слой = уровень ответственности.
- Нижние слои более общие.
- Верхние слои собирают сценарии.
- Импорты должны идти в разрешенном направлении.
- FSD - один из популярных способов применить layered architecture во frontend.
