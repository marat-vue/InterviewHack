# Что означает пустой массив зависимостей в useEffect?

> [!summary]
> Пустой массив зависимостей `[]` означает, что effect не зависит от reactive values компонента и должен выполниться после первого commit. В development Strict Mode React может выполнить setup и cleanup дополнительный раз, чтобы найти ошибки очистки.

## Базовый пример

```jsx
useEffect(() => {
  console.log('Компонент появился на экране')
}, [])
```

Такой effect обычно используют для одноразовой подписки или инициализации внешней системы.

## Пример с подпиской

```jsx
useEffect(() => {
  function handleOnline() {
    setIsOnline(true)
  }

  window.addEventListener('online', handleOnline)

  return () => {
    window.removeEventListener('online', handleOnline)
  }
}, [])
```

Такой effect не зависит от props или state, поэтому массив пустой.

## Важная ловушка: stale values

```jsx
useEffect(() => {
  console.log(userId)
}, [])
```

Если `userId` приходит из props, но не указан в dependencies, effect увидит только значение из первого render.

Правильно:

```jsx
useEffect(() => {
  console.log(userId)
}, [userId])
```

## Почему в dev effect может выполниться дважды?

В Strict Mode React в development может выполнить дополнительный цикл setup-cleanup-setup, чтобы проверить, корректно ли ты освобождаешь ресурсы.

Это не значит, что production работает так же. Но если двойной запуск ломает код, значит cleanup или идемпотентность setup нужно поправить.

## Мини-шпаргалка

- `[]` означает "effect не зависит от reactive values".
- Обычно effect с `[]` выполняется после первого commit.
- В Strict Mode dev возможен дополнительный запуск.
- Не прячь зависимости, чтобы effect "сработал один раз".
- Если используешь prop/state внутри effect, они обычно должны быть в dependencies.
