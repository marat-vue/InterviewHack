# Как работает “микротаска промиса”

> [!summary] Коротко
> Обработчики `.then()`, `.catch()` и `.finally()` выполняются как микротаски: после синхронного кода и до таймеров.

## Вопрос

Почему `.then()` выполняется раньше `setTimeout(fn, 0)`?

## Определение

Когда промис завершается, его обработчики не выполняются прямо внутри `resolve`. Они ставятся в Microtask Queue.

Микротаски имеют более высокий приоритет, чем макротаски. Поэтому промисовые обработчики выполняются перед callbacks таймеров.

## Пример

```javascript
console.log('sync 1');

Promise.resolve().then(() => {
  console.log('promise');
});

setTimeout(() => {
  console.log('timeout');
}, 0);

console.log('sync 2');

// sync 1
// sync 2
// promise
// timeout
```

## resolve не вызывает then сразу

```javascript
const promise = new Promise((resolve) => {
  console.log('inside promise');
  resolve('done');
});

promise.then(console.log);

console.log('after');

// inside promise
// after
// done
```

Функция внутри `new Promise()` выполняется синхронно, но `.then()` выполняется позже как микротаска.

## Очередь очищается полностью

```javascript
Promise.resolve()
  .then(() => {
    console.log(1);
    return Promise.resolve();
  })
  .then(() => {
    console.log(2);
  });
```

Каждый следующий `.then()` добавляет новую микротаску.

## Мини-шпаргалка

```text
sync code -> Promise microtasks -> setTimeout tasks
```
