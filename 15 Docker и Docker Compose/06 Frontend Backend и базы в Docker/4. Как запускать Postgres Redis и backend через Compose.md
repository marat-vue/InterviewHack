# Как запускать Postgres Redis и backend через Compose?

> [!summary]
> Docker Compose позволяет поднять backend, PostgreSQL и Redis одной командой. Backend подключается к зависимостям по именам services: `db:5432`, `redis:6379`, а данные базы хранятся в named volume.

## Пример compose.yaml

```yaml
services:
  api:
    build: .
    ports:
      - "3000:3000"
    env_file:
      - .env
    environment:
      DATABASE_URL: postgres://app:secret@db:5432/app
      REDIS_URL: redis://redis:6379
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started

  db:
    image: postgres:18
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      timeout: 3s
      retries: 10

  redis:
    image: redis:8-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:
```

## Почему host `db`, а не localhost?

Backend внутри container должен подключаться к:

```text
db:5432
redis:6379
```

Потому что `localhost` внутри `api` - это сам `api` container.

## Нужно ли публиковать ports базы?

В dev удобно:

```yaml
ports:
  - "5432:5432"
```

Так можно подключиться из TablePlus, DBeaver или DataGrip через `localhost:5432`.

В production database port обычно не публикуют наружу, если он нужен только backend.

## Запуск

```bash
docker compose up -d
docker compose logs -f api
docker compose exec db psql -U app app
```

Остановка:

```bash
docker compose down
```

Удаление вместе с данными:

```bash
docker compose down -v
```

Осторожно: это удалит volume базы.

## Что отвечать на собеседовании?

В Compose backend, Postgres и Redis описываются как services. Compose создает сеть, где services доступны друг другу по именам `db` и `redis`. Backend получает `DATABASE_URL` и `REDIS_URL`, база хранит данные в named volume, а `healthcheck` помогает дождаться готовности Postgres перед запуском API.

## Частые ошибки

- Использовать `localhost` в `DATABASE_URL` внутри контейнера.
- Не добавлять volume для Postgres.
- Публиковать ports базы в production.
- Думать, что `depends_on` без healthcheck ждет готовности.
- Хранить пароль production базы прямо в compose.yaml.
- Делать `down -v` и терять локальные данные.

## Мини-шпаргалка

- Backend -> `db:5432`, не `localhost`.
- Redis -> `redis:6379`.
- Postgres data -> named volume.
- Dev DB port можно открыть наружу.
- Production DB port лучше держать internal.
- `pg_isready` помогает healthcheck.
