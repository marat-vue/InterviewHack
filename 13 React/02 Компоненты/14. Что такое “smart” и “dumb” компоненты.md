# Что такое smart и dumb компоненты?

> [!summary]
> Smart и dumb components - старое название разделения на компоненты с логикой и компоненты отображения. Сейчас чаще говорят container/presentational или data/UI components, потому что "dumb" звучит неточно и устарело.

## Что называли smart component?

Smart component:

- получает данные;
- хранит состояние;
- вызывает API;
- знает бизнес-правила;
- передает props дочерним компонентам;
- связывает UI с инфраструктурой.

Пример:

```jsx
function ProfilePage() {
  const { data: user, isLoading } = useUser()

  return (
    <ProfileView
      user={user}
      isLoading={isLoading}
    />
  )
}
```

## Что называли dumb component?

Dumb component:

- получает готовые данные через props;
- отображает UI;
- вызывает callback при действиях;
- не знает про API;
- легко переиспользуется.

```jsx
function ProfileView({ user, isLoading }) {
  if (isLoading) {
    return <p>Загрузка...</p>
  }

  return <h1>{user.name}</h1>
}
```

## Почему термины устарели?

Компонент отображения не является "глупым". Он может быть сложным с точки зрения UX, accessibility и визуальных состояний.

Лучше говорить:

- container component;
- presentational component;
- data component;
- UI component;
- feature component.

## Всегда ли нужно разделять?

Нет. Если компонент маленький, искусственное разделение может ухудшить читаемость.

Разделение полезно, когда:

- компонент трудно тестировать;
- UI хочется переиспользовать;
- бизнес-логика смешалась с разметкой;
- запросы мешают Storybook;
- один компонент стал слишком большим.

## Мини-шпаргалка

- Smart = логика, данные, состояние.
- Dumb = отображение через props.
- Современные термины: container/presentational или data/UI.
- Разделение полезно, но не обязательно для каждого компонента.
- Custom hooks часто выносят логику лучше, чем отдельный container.
