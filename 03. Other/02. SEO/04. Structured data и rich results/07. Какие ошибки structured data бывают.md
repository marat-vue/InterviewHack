# Какие ошибки structured data бывают?

> [!summary]
> Ошибки structured data бывают техническими и смысловыми. Самая опасная ситуация - валидный JSON, который описывает не то, что реально видно пользователю.

## Технические ошибки

- Невалидный JSON.
- Лишняя запятая.
- Неправильный `@type`.
- Отсутствуют обязательные поля.
- Неверный формат даты.
- Относительные URL там, где нужны абсолютные.
- Несколько противоречивых JSON-LD блоков.

## Смысловые ошибки

- Разметка товара на странице категории.
- Разметка отзывов, которых нет на странице.
- Цена в JSON-LD отличается от цены в интерфейсе.
- Автор указан, но на странице его нет.
- Breadcrumb не совпадает с навигацией.
- FAQ размечен, но вопросы скрыты от пользователя.

## Пример плохой разметки

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Ноутбуки Apple"
}
</script>
```

Если это категория с десятками товаров, а не конкретный продукт, `Product` может быть неверным выбором.

## Как чинить?

Алгоритм:

1. Определить тип страницы.
2. Выбрать подходящий Schema.org тип.
3. Проверить требования поисковой системы.
4. Сравнить JSON-LD с видимым HTML.
5. Проверить валидатором.
6. Проверить в Search Console после индексации.

## Мини-шпаргалка

- Валидный JSON не гарантирует правильную разметку.
- Данные должны совпадать с тем, что видит пользователь.
- Не размечай сущности "на всякий случай".
- Ошибки шаблона масштабируются на тысячи страниц.
- Проверяй structured data после релиза.
