# Что такое Metadata API в Next.js?

> [!summary]
> Metadata API - это механизм App Router для декларативного управления содержимым `<head>`: `title`, `description`, Open Graph, Twitter Cards, robots, canonical URL, icons и другими SEO-метаданными. В App Router вместо ручного `<Head>` обычно используют `metadata` и `generateMetadata`.

## Зачем нужен Metadata API?

Метаданные влияют на:

- заголовок вкладки браузера;
- сниппет в поисковой выдаче;
- превью ссылки в мессенджерах и соцсетях;
- индексацию страниц;
- canonical URL;
- favicon и icons;
- Open Graph и Twitter Cards.

В App Router Next.js предлагает описывать это рядом с маршрутом:

```text
app/
  layout.tsx
  page.tsx
  blog/
    [slug]/
      page.tsx
```

## Статические metadata

Если метаданные известны заранее, экспортируют объект `metadata`:

```tsx
// app/about/page.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'О проекте',
  description: 'Описание проекта и команды',
}

export default function AboutPage() {
  return <main>О проекте</main>
}
```

Это хороший вариант для статичных страниц: about, contacts, pricing, docs.

## Динамические metadata

Если metadata зависят от данных, используют `generateMetadata`:

```tsx
// app/blog/[slug]/page.tsx
import type { Metadata } from 'next'

type Props = {
  params: Promise<{ slug: string }>
}

export async function generateMetadata({
  params,
}: Props): Promise<Metadata> {
  const { slug } = await params
  const post = await getPostBySlug(slug)

  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      description: post.excerpt,
      images: [post.coverUrl],
    },
  }
}

export default async function BlogPostPage({ params }: Props) {
  const { slug } = await params
  const post = await getPostBySlug(slug)

  return <article>{post.title}</article>
}
```

`generateMetadata` выполняется на сервере и может получать данные из базы, CMS или API.

## Наследование metadata

Metadata из layout и page объединяются.

```tsx
// app/layout.tsx
export const metadata = {
  title: {
    template: '%s | Frontend Notes',
    default: 'Frontend Notes',
  },
  description: 'База знаний по frontend',
}
```

```tsx
// app/react/page.tsx
export const metadata = {
  title: 'React',
  description: 'Вопросы и ответы по React',
}
```

Итоговый title будет:

```text
React | Frontend Notes
```

## Какие поля чаще всего используют?

```tsx
export const metadata = {
  title: 'Страница',
  description: 'Короткое описание страницы',
  keywords: ['Next.js', 'React', 'SEO'],
  alternates: {
    canonical: 'https://example.com/page',
  },
  openGraph: {
    title: 'Страница',
    description: 'Описание для соцсетей',
    url: 'https://example.com/page',
    siteName: 'Example',
    images: [
      {
        url: 'https://example.com/og.png',
        width: 1200,
        height: 630,
      },
    ],
    locale: 'ru_RU',
    type: 'website',
  },
  twitter: {
    card: 'summary_large_image',
    title: 'Страница',
    description: 'Описание для Twitter/X',
    images: ['https://example.com/og.png'],
  },
  robots: {
    index: true,
    follow: true,
  },
}
```

## Важные правила

- `metadata` и `generateMetadata` поддерживаются только в Server Components.
- В одном route segment обычно выбирают либо статический `metadata`, либо `generateMetadata`.
- Для App Router не нужно вручную использовать `next/head` в большинстве случаев.
- Metadata наследуются от родительских layout.
- Более глубокие segments могут переопределять поля родителя.
- Для динамических страниц важно генерировать уникальные title и description.

## Что отвечать на собеседовании?

Metadata API в Next.js - это серверный декларативный способ управлять SEO-метаданными в App Router. Для статичных страниц используют экспорт `metadata`, для динамических - `generateMetadata`. Метаданные могут наследоваться от layout, переопределяться на уровне page и автоматически превращаются Next.js в теги внутри `<head>`.

## Частые ошибки

- Использовать `next/head` в App Router вместо Metadata API.
- Делать metadata внутри Client Component.
- Ставить одинаковый title и description на все страницы.
- Не задавать Open Graph для страниц, которыми делятся в соцсетях.
- Забывать canonical URL для страниц с дублями.
- Писать слишком длинный или нерелевантный description.

## Мини-шпаргалка

- `metadata` - статические метаданные.
- `generateMetadata` - динамические метаданные.
- `title.template` - шаблон для дочерних страниц.
- `description` - текст сниппета.
- `openGraph` - превью в соцсетях.
- `robots` - правила индексации.
- `alternates.canonical` - canonical URL.
