# Какие типы роутинга существуют в Next.js?

> [!summary]
> В Next.js есть два основных роутера: современный App Router в папке `app` и legacy Pages Router в папке `pages`. В App Router маршруты бывают статическими, динамическими, catch-all, optional catch-all, сгруппированными через route groups и вложенными через layouts.

## Два роутера

| Роутер | Где находится | Когда встречается |
|---|---|---|
| App Router | `app/` | современный стандарт |
| Pages Router | `pages/` | legacy-проекты и постепенная миграция |

В новых проектах обычно выбирают App Router.

## Статический маршрут

```text
app/
  about/
    page.tsx
```

URL:

```text
/about
```

Это самый простой вариант: папка соответствует сегменту URL.

## Динамический маршрут

```text
app/
  blog/
    [slug]/
      page.tsx
```

URL:

```text
/blog/next-js-routing
```

`slug` можно получить из `params`.

## Catch-all маршрут

```text
app/
  docs/
    [...slug]/
      page.tsx
```

Подходит для:

```text
/docs/getting-started
/docs/react/server-components
/docs/a/b/c
```

`slug` будет массивом:

```ts
['react', 'server-components']
```

## Optional catch-all

```text
app/
  docs/
    optional catch-all slug/
      page.tsx
```

Такой маршрут подойдет и для `/docs`, и для `/docs/a/b`.

## Route Groups

```text
app/
  (marketing)/
    pricing/
      page.tsx
```

URL:

```text
/pricing
```

Папка `(marketing)` не попадает в адрес. Она нужна для организации проекта и layouts.

## Nested routes

```text
app/
  dashboard/
    layout.tsx
    page.tsx
    settings/
      page.tsx
```

`dashboard/layout.tsx` оборачивает `/dashboard` и `/dashboard/settings`.

## Что отвечать на собеседовании?

В Next.js есть App Router и Pages Router. В App Router основные типы маршрутов задаются файловой структурой: static segments, dynamic segments `[id]`, catch-all `[...slug]`, optional catch-all segment, route groups `(group)` и nested routes через `layout.tsx`.

## Частые ошибки

- Путать route group `(admin)` и dynamic segment `[admin]`.
- Думать, что любая папка создает страницу без `page.tsx`.
- Использовать Pages Router API в App Router.
- Создавать одинаковые URL в разных route groups.
- Хранить query params как path segments без причины.

## Мини-шпаргалка

- `about/page.tsx` -> `/about`.
- `[id]` -> один динамический сегмент.
- `[...slug]` -> массив сегментов.
- optional catch-all -> optional массив сегментов.
- `(group)` -> не влияет на URL.
- `layout.tsx` -> nested shell.
