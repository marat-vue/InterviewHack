# SSR и Time to First Paint

> [!summary]
> SSR может ускорить появление осмысленного контента, но не всегда ускоряет первый байт ответа. Важно различать TTFB, FCP, LCP и TTI: SSR улучшает одни метрики, но может ухудшить другие, если сервер медленный или hydration тяжелая.

## Метрики, которые часто путают

| Метрика | Что означает |
|---|---|
| TTFB | Когда браузер получил первый байт ответа |
| FP | Когда появился первый пиксель |
| FCP | Когда появился первый контент |
| LCP | Когда появился главный крупный контент |
| TTI | Когда страница стала интерактивной |
| INP | Насколько быстро страница отвечает на взаимодействия |

SSR чаще всего нужен не ради "первого пикселя", а ради первого осмысленного content.

## CSR-поток

```text
1. Сервер быстро отдает HTML shell
2. Браузер загружает JS
3. JS выполняется
4. React рендерит UI
5. Данные догружаются
6. Появляется content
```

TTFB может быть быстрым, но FCP/LCP с реальным content может быть поздним.

## SSR-поток

```text
1. Сервер получает request
2. Сервер загружает данные
3. Сервер рендерит HTML
4. Браузер получает HTML
5. Браузер показывает content
6. JavaScript загружается
7. Hydration делает UI интерактивным
```

TTFB может быть медленнее, но FCP/LCP часто лучше, потому что content уже в HTML.

## Где SSR может проиграть?

SSR может ухудшить UX, если:

- сервер долго грузит данные;
- нет кеширования;
- HTML слишком большой;
- streaming не используется;
- hydration тяжелая;
- bundle слишком большой;
- сервер находится далеко от пользователя.

## Как улучшать SSR-метрики?

- кешировать HTML и data;
- использовать CDN/edge;
- стримить HTML через `renderToPipeableStream`;
- ставить Suspense boundaries;
- уменьшать client bundle;
- выносить тяжелые виджеты из первого экрана;
- использовать preload для критичных assets;
- избегать лишней hydration.

## Главная формулировка

```text
SSR может увеличить TTFB, потому что сервер делает больше работы,
но улучшить FCP/LCP, потому что пользователь получает готовый content.
```

## Мини-шпаргалка

- TTFB и FCP - разные вещи.
- SSR не гарантирует скорость автоматически.
- Hydration может задерживать интерактивность.
- Streaming помогает отправлять HTML частями.
- Для SSR важны кеширование, data loading и размер JS.
