# Что такое иммутабельность состояния?

> [!summary]
> Иммутабельность состояния означает, что state нельзя менять напрямую. Вместо изменения старого объекта или массива нужно создать новое значение и передать его в setter. Это делает обновления предсказуемыми и помогает React корректно сравнивать данные.

## Mutable vs immutable

Мутация:

```jsx
user.name = 'Мария'
items.push(newItem)
```

Иммутабельное обновление:

```jsx
setUser({ ...user, name: 'Мария' })
setItems([...items, newItem])
```

React state нужно воспринимать как read-only, даже если JavaScript технически позволяет менять объект.

## Почему это важно?

Иммутабельность помогает:

- видеть изменения по новым ссылкам;
- избегать скрытых side effects;
- корректно работать с `memo`;
- проще отлаживать состояние;
- писать чистые reducer;
- безопасно обновлять вложенные структуры.

## Таблица операций для массивов

| Задача | Не стоит | Лучше |
|---|---|---|
| добавить | `push` | `[...items, item]` |
| удалить | `splice` | `filter` |
| заменить | `items[i] = value` | `map` |
| отсортировать | `items.sort()` | `[...items].sort()` |
| перевернуть | `items.reverse()` | `[...items].reverse()` |

## Immer

В некоторых проектах используют Immer:

```jsx
setUser(produce((draft) => {
  draft.name = 'Мария'
}))
```

Код выглядит как мутация, но Immer создает новое иммутабельное значение. Это удобно для сложных вложенных структур, но добавлять библиотеку только ради пары простых обновлений не всегда нужно.

## Мини-шпаргалка

- State нужно считать read-only.
- Не используй мутации вроде `push`, `splice`, прямого присваивания.
- Создавай новый объект или массив.
- Для вложенных структур копируй каждый изменяемый уровень.
- Immer может упростить сложные обновления.
