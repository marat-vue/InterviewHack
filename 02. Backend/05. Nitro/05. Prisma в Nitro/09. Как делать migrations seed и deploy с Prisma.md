# Как делать migrations, seed и deploy с Prisma?

> [!NOTE]
> Prisma Migrate управляет историей изменений схемы. В development обычно используют `prisma migrate dev`, в production - `prisma migrate deploy`. Seed наполняет базу начальными или тестовыми данными.

## Development migration

```bash
npx prisma migrate dev --name init
```

Команда:

- сравнивает `schema.prisma` с database;
- создает migration SQL;
- применяет migration локально;
- обновляет migration history;
- запускает `prisma generate`.

## Production migration

```bash
npx prisma migrate deploy
```

Команда применяет уже созданные migrations из:

```txt
prisma/migrations
```

Production не должен генерировать новые migrations на лету.

## `db push`

```bash
npx prisma db push
```

`db push` синхронизирует schema с database без migration history.

Подходит для:

- prototypes;
- локальных demo;
- quick experiments;
- Better Auth docs examples.

Не лучший вариант для production, потому что история изменений не фиксируется как migrations.

## `prisma generate`

```bash
npx prisma generate
```

Генерирует Prisma Client. Запускай после:

- изменения моделей;
- изменения generator output;
- установки dependencies;
- CI build, если client не закоммичен.

## Seed

В `package.json`:

```json
{
  "prisma": {
    "seed": "tsx prisma/seed.ts"
  }
}
```

Файл:

```ts
// prisma/seed.ts
import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

async function main() {
  await prisma.user.upsert({
    where: {
      email: 'admin@example.com',
    },
    update: {},
    create: {
      email: 'admin@example.com',
      name: 'Admin',
    },
  });
}

main()
  .finally(async () => {
    await prisma.$disconnect();
  });
```

Запуск:

```bash
npx prisma db seed
```

```json
{
  "scripts": {
    "db:dev": "prisma migrate dev",
    "db:deploy": "prisma migrate deploy",
    "db:push": "prisma db push",
    "db:generate": "prisma generate",
    "db:studio": "prisma studio",
    "db:seed": "prisma db seed"
  }
}
```

## Deploy порядок

Типичный production pipeline:

```txt
install dependencies
  -> prisma generate
  -> build Nitro/Nuxt app
  -> prisma migrate deploy
  -> start app
```

Иногда migrations запускаются отдельным release job до старта новых instances.

## Безопасные migrations

Для больших таблиц опасны:

- `DROP COLUMN`;
- добавление `NOT NULL` без default/backfill;
- тяжелые indexes без concurrent mode;
- изменение типа колонки;
- долгие locks;
- data migration внутри transaction на миллионы строк.

Для production:

- делай backup;
- проверяй generated SQL;
- применяй expand/contract pattern;
- разделяй schema migration и data backfill;
- тестируй на staging.

## Мини-шпаргалка

- Dev: `prisma migrate dev`.
- Prod: `prisma migrate deploy`.
- Prototype: `prisma db push`.
- Client: `prisma generate`.
- Seed: `prisma db seed`.
- Migrations должны коммититься.
- Production migrations лучше запускать отдельным controlled step.
