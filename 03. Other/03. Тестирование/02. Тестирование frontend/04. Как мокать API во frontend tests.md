# Как мокать API во frontend tests?

> [!summary]
> API в frontend-тестах обычно мокают, чтобы тест не зависел от сети и backend. Можно мокать модуль клиента, `fetch`, Axios-инстанс или использовать MSW для более реалистичного перехвата HTTP-запросов.

## Зачем мокать API?

Если тест ходит в настоящий API, он становится:

- медленным;
- нестабильным;
- зависимым от окружения;
- сложным для проверки ошибок.

В unit и component tests чаще используют mock.

## Мок модуля API

```ts
import { vi } from 'vitest';
import { getUser } from '@/api/users';

vi.mock('@/api/users', () => ({
  getUser: vi.fn(),
}));

test('shows user name', async () => {
  vi.mocked(getUser).mockResolvedValue({ id: 1, name: 'Ann' });

  const wrapper = mount(UserProfile);
  await flushPromises();

  expect(wrapper.text()).toContain('Ann');
});
```

## Мок `fetch`

```ts
vi.stubGlobal('fetch', vi.fn().mockResolvedValue({
  ok: true,
  json: async () => ({ id: 1, name: 'Ann' }),
}));
```

После теста важно восстановить глобальные моки:

```ts
afterEach(() => {
  vi.unstubAllGlobals();
});
```

## Когда использовать MSW?

MSW полезен, когда хочется тестировать почти реальный HTTP-слой, но без настоящего backend.

Идея:

```ts
http.get('/api/users/:id', () => {
  return HttpResponse.json({ id: 1, name: 'Ann' });
});
```

Так компонент делает обычный HTTP-запрос, а тестовый handler возвращает подготовленный ответ.

## Мини-шпаргалка

- В component tests API обычно мокают.
- Мокай границу, а не половину приложения.
- Для простых случаев хватит `vi.mock`.
- Для реалистичных HTTP-сценариев удобен MSW.
- Проверяй success, loading и error states.
