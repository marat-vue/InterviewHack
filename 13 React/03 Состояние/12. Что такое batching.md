# Что такое batching?

> [!summary]
> Batching - это группировка нескольких обновлений состояния в один render. React делает это, чтобы не перерисовывать компонент после каждого setter отдельно и улучшать производительность.

## Простое объяснение

В обработчике события:

```jsx
function handleSubmit() {
  setIsLoading(true)
  setError(null)
  setStep('sending')
}
```

React может выполнить один render после всех трех обновлений, а не три render подряд.

## Зачем нужен batching?

Batching помогает:

- уменьшить количество render;
- сделать UI быстрее;
- избежать промежуточных состояний на экране;
- согласованно применить несколько изменений.

## Batching и snapshot

Batching не отменяет правило snapshot:

```jsx
setCount(count + 1)
setCount(count + 1)
```

Если `count` был `0`, оба вызова используют `0`.

Если нужно учитывать очередь:

```jsx
setCount((count) => count + 1)
setCount((count) => count + 1)
```

## Automatic batching

В современных версиях React batching работает шире, чем только в обработчиках событий. Обновления могут группироваться также в промисах, таймерах и других async-сценариях.

Пример:

```jsx
setTimeout(() => {
  setCount((count) => count + 1)
  setIsOpen(false)
}, 1000)
```

React может сгруппировать эти обновления.

## Когда batching может мешать?

Иногда нужно принудительно применить обновление синхронно, например при интеграции с DOM API. Для этого существует `flushSync`, но использовать его нужно редко и осознанно.

## Мини-шпаргалка

- Batching группирует несколько state updates в один render.
- Он улучшает производительность и согласованность UI.
- Snapshot state все равно остается важным.
- Для зависимых обновлений используй updater function.
- `flushSync` - редкий escape hatch, не обычный инструмент.
