# Tailwind в проекте и вопросы на собеседовании

> [!summary]
> В production Tailwind требует дисциплины: дизайн-токены, компоненты, контроль длинных className, переиспользуемые variants, доступность focus states и понимание, когда utility-first подход лучше или хуже компонентного UI-kit.

## Как не превратить Tailwind в хаос?

Правила:

- не копировать огромные className по всему проекту;
- повторяющиеся паттерны выносить в компоненты;
- использовать шкалы Tailwind вместо arbitrary values;
- держать consistent spacing;
- не забывать focus-visible;
- не удалять semantic HTML.

## Tailwind и компоненты

Плохой признак:

```tsx
// Одинаковая кнопка скопирована в 20 мест
<button className="inline-flex items-center rounded-md bg-blue-600 px-4 py-2 text-sm font-medium text-white hover:bg-blue-700">
```

Лучше:

```tsx
<Button variant="primary">Save</Button>
```

Tailwind не запрещает компонентный подход. Он просто меняет способ описания стилей.

## Tailwind vs CSS Modules vs MUI

| Инструмент | Когда выбирать |
|---|---|
| Tailwind | custom design, быстрый UI, utility-first команда |
| CSS Modules | локальный CSS без utility-first |
| MUI | нужен готовый компонентный UI-kit |
| plain CSS | маленькие проекты или базовая верстка |

## Частые вопросы

### Tailwind - это inline styles?

Нет. Inline styles пишутся в атрибут `style`, а Tailwind генерирует CSS-классы. Utilities просто применяются прямо в markup.

### Как делать condition classes?

```tsx
const className = isActive
  ? 'bg-blue-600 text-white'
  : 'bg-white text-zinc-900'
```

В реальном проекте удобнее `clsx`:

```tsx
clsx('rounded-md px-4 py-2', isActive && 'bg-blue-600 text-white')
```

### Что делать с конфликтами классов?

Если одновременно пришли `px-2` и `px-4`, помогает `tailwind-merge`.

## Частые ошибки

- Использовать arbitrary values везде: `text-[13px]`, `mt-[7px]`.
- Делать несемантический HTML ради классов.
- Не описывать focus states.
- Смешивать MUI и Tailwind без правил.
- Не выносить повторяющиеся controls в компоненты.

## Что отвечать на собеседовании?

Tailwind в production хорош, если команда строит UI через компоненты и дизайн-токены, а не просто копирует классы. Он не заменяет архитектуру компонентов, accessibility и дизайн-систему. Его плюс - скорость, consistency и маленький production CSS.

## Мини-шпаргалка

- Tailwind - не inline styles.
- Повторы выноси в компоненты.
- Для условий используй `clsx`.
- Для конфликтов - `tailwind-merge`.
- Focus states обязательны.
- Utility-first не отменяет semantic HTML.
