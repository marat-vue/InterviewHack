# Что такое keyspace notifications и когда их использовать?

> [!NOTE]
> Keyspace notifications позволяют Redis публиковать события о ключах: expired, deleted, set и другие. Это удобно для некоторых reactive-сценариев, но требует осторожной настройки и не заменяет надежную очередь.

## Что такое keyspace notifications?

Redis может публиковать события, когда с ключами что-то происходит:

```txt
key expired
key deleted
key set
```

Например, можно узнать, что истек session key или temporary token.

## Как включить?

```redis
CONFIG SET notify-keyspace-events Ex
```

`E` - keyevent notifications.

`x` - expired events.

После этого можно подписаться:

```redis
SUBSCRIBE __keyevent@0__:expired
```

## Node.js пример

```ts
const sub = redis.duplicate();
await sub.connect();

await sub.subscribe('__keyevent@0__:expired', (key) => {
  console.log('expired:', key);
});
```

## Когда использовать?

Подходит для:

- debug;
- soft cleanup;
- cache invalidation signals;
- non-critical expiry reactions;
- локальной автоматизации.

## Когда не использовать?

Не используй keyspace notifications для critical business logic:

- платежи;
- обязательная отправка email;
- надежное завершение workflow;
- audit.

Notifications используют Pub/Sub semantics. Если consumer offline, событие может быть потеряно.

## Мини-шпаргалка

- Keyspace notifications нужно включать явно.
- Expired events: `notify-keyspace-events Ex`.
- Подписка: `__keyevent@0__:expired`.
- Это не reliable queue.
- Для надежной обработки выбирай Streams.
