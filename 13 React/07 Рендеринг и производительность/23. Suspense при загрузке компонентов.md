# Suspense при загрузке компонентов

> [!summary]
> `<Suspense>` показывает запасной UI, пока дочерняя часть дерева не готова к render. Для lazy-компонентов это означает: пока загружается JavaScript chunk, пользователь видит `fallback`.

## Базовый пример

```jsx
import { lazy, Suspense } from 'react'

const Chart = lazy(() => import('./Chart'))

function Dashboard() {
  return (
    <Suspense fallback={<ChartSkeleton />}>
      <Chart />
    </Suspense>
  )
}
```

Если `Chart` еще не загружен, React покажет `ChartSkeleton`. Когда загрузка завершится, React повторит render и покажет настоящий компонент.

## Что такое fallback?

`fallback` - это React node, который временно отображается вместо suspending subtree.

```jsx
<Suspense fallback={<p>Loading comments...</p>}>
  <Comments />
</Suspense>
```

Хороший fallback:

- легкий;
- не вызывает тяжелых запросов;
- не ломает layout;
- похож по размеру на будущий контент;
- не создает резкого скачка интерфейса.

## Ближайшая Suspense-граница

React ищет ближайший `<Suspense>` выше компонента, который suspended.

```jsx
<Suspense fallback={<PageSkeleton />}>
  <Header />

  <Suspense fallback={<CommentsSkeleton />}>
    <Comments />
  </Suspense>
</Suspense>
```

Если suspended `Comments`, сработает внутренний fallback `CommentsSkeleton`, а не вся страница.

## Несколько Suspense-границ

Несколько границ позволяют показывать страницу частями.

```jsx
function ProductPage() {
  return (
    <>
      <ProductInfo />

      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />
      </Suspense>

      <Suspense fallback={<RecommendationsSkeleton />}>
        <Recommendations />
      </Suspense>
    </>
  )
}
```

Отзывы и рекомендации могут грузиться независимо.

## Suspense не ловит любой async код

Важно для собеседования: Suspense не реагирует на обычный `fetch` внутри `useEffect`.

```jsx
function Users() {
  useEffect(() => {
    fetch('/api/users')
  }, [])

  return <div>Users</div>
}
```

Такой компонент сам должен хранить `isLoading`. Suspense срабатывает для Suspense-enabled источников: `lazy`, framework data fetching, cached Promise через `use` и похожие интеграции.

## Suspense и already visible content

Если уже показанный контент снова suspended, React может показать fallback. Но transitions и deferred values помогают избежать нежелательного мигания fallback при несрочных обновлениях.

## Мини-шпаргалка

- Suspense показывает `fallback`, пока subtree не готово.
- Для `lazy` Suspense обязателен.
- Ближайшая граница управляет конкретной зоной загрузки.
- Несколько границ улучшают UX.
- Suspense не заменяет `isLoading` для обычного `fetch` в `useEffect`.
