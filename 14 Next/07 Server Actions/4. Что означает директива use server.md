# Что означает директива use server?

> [!summary]
> Директива `'use server'` помечает функцию или целый модуль как server-only код. В Next.js ее используют для Server Actions/Server Functions: мутаций, работы с БД, секретами, cookies, revalidation и redirect.

## Два способа использования

### На уровне файла

```ts
'use server'

export async function createPost(formData: FormData) {
  await db.post.create({
    data: { title: String(formData.get('title')) },
  })
}

export async function deletePost(id: string) {
  await db.post.delete({ where: { id } })
}
```

Все exports из файла считаются server functions.

### Внутри функции

```tsx
export default function Page() {
  async function createPost(formData: FormData) {
    'use server'

    await db.post.create({
      data: { title: String(formData.get('title')) },
    })
  }

  return <form action={createPost}>...</form>
}
```

Такой inline-вариант удобен в Server Component.

## Что можно делать внутри?

- читать `FormData`;
- валидировать входные данные;
- писать в БД;
- читать cookies/headers;
- использовать server env;
- вызывать `revalidatePath`;
- вызывать `revalidateTag`;
- делать `redirect`.

```ts
'use server'

import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createProduct(formData: FormData) {
  const title = String(formData.get('title'))

  await db.product.create({ data: { title } })
  revalidatePath('/products')
  redirect('/products')
}
```

## use server не делает код "безопасным автоматически"

Server Function выполняется на сервере, но ее все равно нужно защищать.

```ts
'use server'

export async function deleteUser(userId: string) {
  const currentUser = await requireCurrentUser()

  if (!currentUser.isAdmin) {
    throw new Error('Forbidden')
  }

  await db.user.delete({ where: { id: userId } })
}
```

## Что отвечать на собеседовании?

`'use server'` сообщает Next.js, что функция должна выполняться только на сервере. Ее используют для Server Actions/Server Functions, особенно для мутаций. Директива не отменяет авторизацию, валидацию, обработку ошибок и revalidation после изменения данных.

## Частые ошибки

- Думать, что `'use server'` заменяет проверку прав.
- Использовать server function как публичный REST API.
- Забывать `revalidatePath` или `revalidateTag`.
- Возвращать пользователю сырые ошибки БД.
- Импортировать server function не по правилам в client graph.

## Мини-шпаргалка

- `'use server'` в начале файла - все exports server-only.
- `'use server'` внутри функции - inline server action.
- Используют для mutations.
- Можно работать с БД и secrets.
- Auth и validation обязательны.
- После mutation часто нужна revalidation.
