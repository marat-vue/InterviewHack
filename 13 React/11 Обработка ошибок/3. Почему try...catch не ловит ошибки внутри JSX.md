# Почему try...catch не ловит ошибки внутри JSX?

> [!summary]
> `try...catch` вокруг JSX не ловит ошибки, которые происходят позже, когда React сам рендерит дочерние компоненты. Ошибки render распространяются по React tree и ловятся Error Boundary, а не обычным `try...catch` в родителе.

## Плохой пример

```jsx
function Page() {
  try {
    return <UserCard user={null} />
  } catch (error) {
    return <ErrorMessage error={error} />
  }
}
```

Кажется, что ошибка внутри `UserCard` попадет в `catch`, но это не так.

## Почему?

JSX - это описание элемента:

```jsx
<UserCard user={null} />
```

После компиляции это примерно:

```js
React.createElement(UserCard, { user: null })
```

Родитель создал описание, но не вызвал `UserCard` вручную. React вызовет `UserCard` позже в своем render-процессе.

## Где try...catch работает?

В обычном синхронном коде:

```jsx
function Page() {
  try {
    const user = normalizeUser(rawUser)

    return <UserCard user={user} />
  } catch (error) {
    return <ErrorMessage error={error} />
  }
}
```

Здесь `normalizeUser` вызывается прямо внутри `try`.

В event handler:

```jsx
function SaveButton() {
  async function handleClick() {
    try {
      await save()
    } catch (error) {
      showToast('Failed to save')
    }
  }

  return <button onClick={handleClick}>Save</button>
}
```

## Как правильно ловить ошибки render?

Через Error Boundary:

```jsx
<ErrorBoundary fallback={<ErrorFallback />}>
  <UserCard user={null} />
</ErrorBoundary>
```

Если `UserCard` упадет при render, React поднимет ошибку к ближайшей boundary.

## Что сказать на собеседовании?

```text
try...catch ловит ошибки только в текущем стеке выполнения.
JSX дочернего компонента не вызывает этот компонент немедленно;
React вызывает его позже. Поэтому ошибки render ловятся Error Boundary.
```

## Мини-шпаргалка

- JSX - описание UI, а не прямой вызов дочернего компонента.
- `try...catch` не заменяет Error Boundary.
- В handler и обычной функции `try...catch` работает.
- Ошибки render нужно локализовать boundary.
- Ошибки async-кода обрабатывают отдельно.
