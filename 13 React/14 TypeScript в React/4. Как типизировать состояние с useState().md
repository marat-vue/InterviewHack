# Как типизировать состояние с useState()?

> [!summary]
> `useState` чаще всего не требует явной типизации: TypeScript выводит тип из initial value. Generic `<T>` нужен для `null`, пустых массивов, union-состояний, сложных объектов и случаев, где initial value не дает достаточно информации.

## Автовывод типов

```tsx
const [count, setCount] = useState(0)
const [query, setQuery] = useState('')
const [isOpen, setIsOpen] = useState(false)
```

TypeScript выводит:

- `count` как `number`;
- `query` как `string`;
- `isOpen` как `boolean`.

## Когда нужен generic?

### null initial value

```tsx
type User = {
  id: string
  name: string
}

const [user, setUser] = useState<User | null>(null)
```

Без `<User | null>` TypeScript будет знать только `null`.

### Пустой массив

```tsx
type Todo = {
  id: string
  text: string
  completed: boolean
}

const [todos, setTodos] = useState<Todo[]>([])
```

Если написать просто `useState([])`, тип может получиться слишком узким и бесполезным.

### Literal union

```tsx
type Status = 'idle' | 'loading' | 'success' | 'error'

const [status, setStatus] = useState<Status>('idle')
```

Теперь нельзя случайно сделать:

```tsx
setStatus('done')
```

### Сложное состояние

```tsx
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string }

const [state, setState] = useState<RequestState<User[]>>({
  status: 'idle',
})
```

Такой discriminated union удобнее, чем набор отдельных boolean:

```tsx
const [isLoading, setIsLoading] = useState(false)
const [error, setError] = useState<string | null>(null)
const [data, setData] = useState<User[] | null>(null)
```

## Тип setter

Обычно setter типизировать не нужно. Но если передаешь его в props:

```tsx
type CounterControlsProps = {
  setCount: React.Dispatch<React.SetStateAction<number>>
}

function CounterControls({ setCount }: CounterControlsProps) {
  return (
    <button onClick={() => setCount((count) => count + 1)}>
      Increment
    </button>
  )
}
```

Если хочется более строгий API, лучше передать готовый callback:

```tsx
type CounterControlsProps = {
  onIncrement: () => void
}
```

## Обновление объекта

```tsx
type FormState = {
  email: string
  password: string
}

const [form, setForm] = useState<FormState>({
  email: '',
  password: '',
})

setForm((currentForm) => ({
  ...currentForm,
  email: 'ada@example.com',
}))
```

Не мутируй состояние:

```tsx
form.email = 'ada@example.com'
setForm(form)
```

## Что отвечать на собеседовании?

`useState` типизируют явно, когда TypeScript не может вывести правильный тип из initial value: `null`, пустой массив, union, сложный объект. В простых случаях лучше доверять выводу типов. Setter имеет тип `React.Dispatch<React.SetStateAction<T>>`.

## Частые ошибки

- Писать `useState<any>()`.
- Забывать `| null` для данных, которые сначала отсутствуют.
- Использовать несколько boolean вместо union state.
- Мутировать объект или массив состояния.
- Передавать setter глубоко в дерево вместо понятного callback.

## Мини-шпаргалка

- Простые значения типизируются автоматически.
- `useState<User | null>(null)`.
- `useState<Todo[]>([])`.
- Статусы удобно описывать union-типом.
- Setter: `Dispatch<SetStateAction<T>>`.
