# Как описывать модели, поля, связи и индексы Prisma?

> [!NOTE]
> Prisma schema описывает data model: модели, поля, типы, constraints, связи, индексы и mapping к таблицам. Хорошая schema - основа типизированного Prisma Client и безопасных migrations.

## Модель

```prisma
model User {
  id        String   @id @default(cuid())
  email     String   @unique
  name      String?
  posts     Post[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

Модель обычно соответствует таблице, а поле - колонке.

## Базовые типы

| Prisma type | Что хранит |
|---|---|
| `String` | строка |
| `Int` | integer |
| `BigInt` | большой integer |
| `Float` | floating point |
| `Decimal` | decimal для денег/точных значений |
| `Boolean` | true/false |
| `DateTime` | дата и время |
| `Json` | JSON |
| `Bytes` | binary data |
| `Enum` | перечисление |

Реальная поддержка зависит от database provider.

## Optional field

```prisma
name String?
```

`?` означает nullable/optional поле.

## ID и defaults

```prisma
id String @id @default(cuid())
```

Варианты:

```prisma
id Int    @id @default(autoincrement())
id String @id @default(uuid())
id String @id @default(cuid())
```

## Unique constraints

```prisma
email String @unique
```

Compound unique:

```prisma
@@unique([provider, providerAccountId])
```

Compound ID:

```prisma
@@id([userId, postId])
```

## One-to-many relation

```prisma
model User {
  id    String @id @default(cuid())
  posts Post[]
}

model Post {
  id       String @id @default(cuid())
  title    String
  authorId String
  author   User   @relation(fields: [authorId], references: [id])
}
```

`Post.authorId` - foreign key, `Post.author` - relation field.

## One-to-one relation

```prisma
model User {
  id      String   @id @default(cuid())
  profile Profile?
}

model Profile {
  id     String @id @default(cuid())
  bio    String?
  userId String @unique
  user   User   @relation(fields: [userId], references: [id])
}
```

`userId @unique` делает связь one-to-one.

## Many-to-many relation

Implicit many-to-many:

```prisma
model Post {
  id   String @id @default(cuid())
  tags Tag[]
}

model Tag {
  id    String @id @default(cuid())
  posts Post[]
}
```

Explicit join model:

```prisma
model PostTag {
  postId String
  tagId  String
  post   Post @relation(fields: [postId], references: [id])
  tag    Tag  @relation(fields: [tagId], references: [id])

  @@id([postId, tagId])
}
```

Explicit вариант лучше, если у связи есть metadata: `createdAt`, `role`, `order`.

## Indexes

```prisma
@@index([createdAt])
@@index([authorId, createdAt])
```

Индексы нужны для:

- foreign keys;
- частых filters;
- sorting;
- pagination;
- unique lookup;
- join performance.

## Mapping таблиц и колонок

```prisma
model User {
  id        String @id @default(cuid())
  createdAt DateTime @map("created_at")

  @@map("users")
}
```

`@map` и `@@map` полезны, если database naming style отличается от Prisma naming.

## Мини-шпаргалка

- `model` описывает таблицу/коллекцию.
- `@id` - primary key.
- `@unique` - unique constraint.
- `@default` - default value.
- `@updatedAt` - auto-update timestamp.
- `@relation` - связь.
- `@@index` - индекс.
- `@@unique` - compound unique.
- `@map`/`@@map` - mapping имен.
