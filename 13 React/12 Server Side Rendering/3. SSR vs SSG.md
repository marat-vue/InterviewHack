# SSR vs SSG

> [!summary]
> SSR генерирует HTML во время запроса пользователя, а SSG генерирует HTML заранее на этапе build. SSR дает более свежие данные, SSG дает максимальную скорость раздачи и простое кеширование.

## SSR

```text
Request -> server fetches data -> render HTML -> response
```

Подходит, когда данные зависят от:

- пользователя;
- cookies;
- географии;
- прав доступа;
- часто меняющихся данных;
- request headers.

Пример:

```jsx
app.get('/profile', async (req, res) => {
  const user = await getUserFromSession(req.cookies.session)
  const html = renderToString(<ProfilePage user={user} />)

  res.send(createDocument(html))
})
```

## SSG

```text
Build time -> fetch data -> render HTML files -> deploy to CDN
```

Подходит для:

- блогов;
- документации;
- лендингов;
- changelog;
- маркетинговых страниц;
- справочников.

Пример результата:

```text
dist/
  index.html
  blog/react-ssr.html
  docs/routing.html
```

Серверу не нужно рендерить React на каждый запрос: он отдает готовые файлы.

## Таблица

| Критерий | SSR | SSG |
|---|---|---|
| Когда рендерится | На каждый request | На build |
| Актуальность | Высокая | На момент build |
| Скорость ответа | Зависит от сервера | Очень высокая через CDN |
| Персонализация | Хорошая | Ограниченная |
| Стоимость | Выше | Ниже |
| Риск устаревания | Ниже | Выше |

## ISR

ISR, или Incremental Static Regeneration, пытается соединить плюсы SSG и свежесть SSR.

```text
Отдаем статическую страницу -> по расписанию или событию пересобираем ее в фоне
```

Это популярная стратегия для страниц товаров, статей и каталогов, где данные меняются, но не каждую секунду.

## Мини-шпаргалка

- SSR рендерит на request.
- SSG рендерит на build.
- SSR лучше для персонализации и свежих данных.
- SSG лучше для статичного публичного content.
- ISR обновляет статические страницы после build.
