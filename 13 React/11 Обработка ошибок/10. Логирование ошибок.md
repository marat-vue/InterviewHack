# Логирование ошибок

> [!summary]
> Логирование ошибок в production нужно, чтобы команда видела реальные падения у пользователей: stack trace, component stack, URL, browser, release, user impact и частоту. Без мониторинга ошибка существует только в браузере пользователя.

## Что логировать?

Полезные данные:

- error message;
- stack trace;
- React component stack;
- URL;
- route params без чувствительных данных;
- browser/device;
- release version;
- user id или anonymous id;
- feature flag state;
- severity;
- breadcrumbs: последние действия пользователя.

Не логировать:

- пароли;
- access tokens;
- банковские данные;
- приватные сообщения;
- полные cookies;
- персональные данные без необходимости.

## Логирование из Error Boundary

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false }

  static getDerivedStateFromError() {
    return { hasError: true }
  }

  componentDidCatch(error, info) {
    reportError({
      error,
      componentStack: info.componentStack,
      url: window.location.href,
      release: import.meta.env.VITE_APP_VERSION,
    })
  }

  render() {
    if (this.state.hasError) {
      return <ErrorFallback />
    }

    return this.props.children
  }
}
```

## Глобальные ошибки

```js
window.addEventListener('error', (event) => {
  reportError({
    error: event.error,
    message: event.message,
  })
})

window.addEventListener('unhandledrejection', (event) => {
  reportError({
    error: event.reason,
  })
})
```

Это не заменяет локальную обработку ошибок, но помогает ловить неожиданные падения.

## Ошибки API

```ts
export async function httpClient(url: string, options?: RequestInit) {
  const response = await fetch(url, options)

  if (!response.ok) {
    reportApiError({
      url,
      status: response.status,
      requestId: response.headers.get('x-request-id'),
    })

    throw new ApiError(response.status)
  }

  return response.json()
}
```

Для API важно логировать status, endpoint и request id, но не сырые чувствительные payload.

## Инструменты

Часто используют:

- Sentry;
- GlitchTip;
- Rollbar;
- Datadog;
- New Relic;
- OpenTelemetry.

## Мини-шпаргалка

- Error Boundary дает `componentStack`.
- Global handlers ловят неожиданные JS errors и unhandled rejections.
- API errors лучше нормализовать в API-слое.
- Нельзя логировать секреты и чувствительные данные.
- В логах должен быть release, чтобы находить регрессии после deploy.
