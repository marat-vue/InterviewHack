# Что делает startTransition?

> [!summary]
> `startTransition` помечает синхронные state updates внутри переданной функции как transition. Такие обновления становятся менее срочными и могут быть прерваны более важными обновлениями, например вводом пользователя.

## Вариант из useTransition

```jsx
const [isPending, startTransition] = useTransition()

function selectTab(nextTab) {
  startTransition(() => {
    setTab(nextTab)
  })
}
```

Этот вариант дает `isPending`.

## Импортированный startTransition

```jsx
import { startTransition } from 'react'

function selectTab(nextTab) {
  startTransition(() => {
    setTab(nextTab)
  })
}
```

Такой вариант не дает `isPending`, но может использоваться там, где hook недоступен, например в коде библиотеки.

## Важный нюанс про синхронность

Функция внутри `startTransition` выполняется сразу:

```jsx
startTransition(() => {
  setTab(nextTab)
})
```

React помечает state updates, которые произошли синхронно во время вызова.

Если после `await` нужно снова пометить update как transition, может потребоваться дополнительный `startTransition`.

## Что transition дает пользователю?

Если тяжелое обновление идет в transition, React может:

- сначала обработать ввод;
- не блокировать клики;
- прервать устаревшую работу;
- показать старый UI, пока новый готовится;
- сделать интерфейс субъективно быстрее.

## Мини-шпаргалка

- `startTransition` помечает обновления как transition.
- Transition updates менее срочные.
- Они могут быть прерваны срочными обновлениями.
- Версия из `useTransition` дает `isPending`.
- Не используй transition для controlled input value.
