# Что такое flaky tests и как с ними бороться?

> [!summary]
> Flaky test - тест, который иногда проходит, иногда падает без изменения кода. Такие тесты разрушают доверие к CI, поэтому их нужно расследовать: время, сеть, shared state, порядок запуска, случайные данные, timezone и асинхронные ожидания.

## Простое определение

Flaky test:

```text
Сегодня зеленый -> через минуту красный -> после rerun снова зеленый.
```

Если команда начинает игнорировать падения, тестовый набор перестает защищать проект.

## Частые причины

- тест зависит от порядка запуска;
- общая база не очищается;
- реальные timers;
- `waitForTimeout`;
- случайные данные без seed;
- timezone/date;
- внешний API;
- гонки async operations;
- анимации;
- нестабильные selectors.

## Пример плохого ожидания

```ts
await page.waitForTimeout(1000);
await expect(page.getByText('Готово')).toBeVisible();
```

Если CI медленнее, тест упадет.

Лучше:

```ts
await expect(page.getByText('Готово')).toBeVisible();
```

Playwright сам будет ждать состояние до timeout.

## Как расследовать flaky test?

1. Запустить тест много раз локально.
2. Проверить порядок запуска.
3. Включить trace/screenshots/logs.
4. Проверить shared state.
5. Убрать реальные внешние зависимости.
6. Стабилизировать дату и timers.
7. Убедиться, что тест ждет состояние, а не время.

## Что делать с flaky test в команде?

Варианты:

- быстро починить;
- временно quarantined, если он блокирует CI;
- завести issue с причиной;
- не оставлять "известно, иногда падает" навсегда.

## Мини-шпаргалка

- Flaky tests убивают доверие к CI.
- Жди состояние, а не секунды.
- Изолируй данные между тестами.
- Стабилизируй дату, timers и network.
- Retries не заменяют исправление причины.
