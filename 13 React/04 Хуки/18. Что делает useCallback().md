# Что делает useCallback?

> [!summary]
> `useCallback` кеширует саму функцию между render, пока зависимости не изменились. Его используют, когда стабильная ссылка на функцию важна для `memo`-компонентов, dependencies эффектов или custom hooks.

## Базовый синтаксис

```jsx
const handleSubmit = useCallback((order) => {
  sendOrder(productId, order)
}, [productId])
```

React вернет ту же функцию между render, если `productId` не изменился.

## Важное уточнение

`useCallback` не предотвращает создание функции магически во всех смыслах и не ускоряет саму функцию. Он помогает сохранить ссылку на функцию стабильной.

```text
useCallback(fn, deps) примерно похож на useMemo(() => fn, deps)
```

## Пример с memo

```jsx
const ProductCard = memo(function ProductCard({ product, onBuy }) {
  return <button onClick={() => onBuy(product.id)}>Купить</button>
})

function ProductPage({ product }) {
  const handleBuy = useCallback((productId) => {
    addToCart(productId)
  }, [])

  return <ProductCard product={product} onBuy={handleBuy} />
}
```

Если `handleBuy` создается заново на каждом render, `ProductCard` может получать новый prop и рендериться снова.

## Пример с effect

```jsx
const createOptions = useCallback(() => {
  return { roomId, serverUrl }
}, [roomId, serverUrl])

useEffect(() => {
  const connection = createConnection(createOptions())
  connection.connect()
  return () => connection.disconnect()
}, [createOptions])
```

Но часто проще перенести функцию внутрь effect.

## Частые ошибки

- Использовать `useCallback` для каждой функции.
- Забыть dependency и получить stale value.
- Ожидать, что `useCallback` ускорит выполнение функции.
- Мемоизировать callback, который передается обычному DOM-элементу без пользы.

## Мини-шпаргалка

- `useCallback` кеширует ссылку на функцию.
- Он полезен вместе с `memo`, effects и custom hooks.
- Dependencies должны быть полными.
- Не используй его механически.
- Код должен быть корректным без `useCallback`.
