# Запрос при первом рендере

> [!summary]
> В клиентском React запрос "при первом рендере" обычно означает запрос после первого commit, то есть внутри `useEffect` с пустым массивом зависимостей. Сам render остается чистым, сначала показывается loading UI, затем результат запроса кладется в state.

## Базовый пример

```jsx
function UserPage() {
  const [user, setUser] = useState(null)

  useEffect(() => {
    fetch('/api/user')
      .then((response) => response.json())
      .then(setUser)
  }, [])

  if (!user) {
    return <p>Loading...</p>
  }

  return <h1>{user.name}</h1>
}
```

Пустой массив зависимостей означает: эффект не зависит от значений из render scope и запускается после mount.

## Полный шаблон

```jsx
function UserPage() {
  const [user, setUser] = useState(null)
  const [isLoading, setIsLoading] = useState(true)
  const [error, setError] = useState(null)

  useEffect(() => {
    const controller = new AbortController()

    async function loadUser() {
      try {
        setIsLoading(true)
        setError(null)

        const response = await fetch('/api/user', {
          signal: controller.signal,
        })

        if (!response.ok) {
          throw new Error('Failed to load user')
        }

        const data = await response.json()
        setUser(data)
      } catch (error) {
        if (error.name !== 'AbortError') {
          setError(error)
        }
      } finally {
        setIsLoading(false)
      }
    }

    loadUser()

    return () => controller.abort()
  }, [])

  if (isLoading) return <UserSkeleton />
  if (error) return <ErrorMessage error={error} />

  return <UserProfile user={user} />
}
```

## Если запрос зависит от props

```jsx
function UserPage({ userId }) {
  useEffect(() => {
    const controller = new AbortController()

    fetch(`/api/users/${userId}`, { signal: controller.signal })
      .then((response) => response.json())
      .then(setUser)

    return () => controller.abort()
  }, [userId])
}
```

Если `userId` меняется, запрос должен перезапускаться.

## Strict Mode и двойной запрос в development

В development Strict Mode React может выполнить effect по схеме:

```text
setup -> cleanup -> setup
```

Это проверяет, корректно ли написан cleanup. Не стоит лечить это глобальным `useRef`, который запрещает второй запуск эффекта: можно скрыть настоящую проблему.

Лучше:

- писать корректный cleanup;
- использовать AbortController;
- применять query cache, который дедуплицирует запросы;
- помнить, что production-поведение отличается.

## Мини-шпаргалка

- Запрос при mount делают в `useEffect(..., [])`.
- Сначала render показывает loading state.
- Запрос нужно обрабатывать с loading/error.
- Для fetch полезен `AbortController`.
- Если есть зависимость вроде `userId`, она должна быть в массиве зависимостей.
