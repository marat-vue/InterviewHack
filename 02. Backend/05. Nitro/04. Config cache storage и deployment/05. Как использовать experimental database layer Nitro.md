# Как использовать experimental database layer Nitro?

> [!NOTE]
> Nitro имеет экспериментальный lightweight SQL database layer через `useDatabase`, построенный вокруг DB0. По умолчанию он может работать с SQLite в development, но для серьезной доменной БД в full-stack проектах чаще выбирают Prisma или другой ORM/query builder.

## Как включить database layer?

```ts
// nitro.config.ts
export default defineConfig({
  experimental: {
    database: true,
  },
});
```

После включения доступен `useDatabase`.

```ts
import { useDatabase } from 'nitro/database';

export default defineHandler(async () => {
  const db = useDatabase();

  const { rows } = await db.sql`SELECT 1 as value`;

  return {
    rows,
  };
});
```

## Как работает default connection?

По документации Nitro default connection преднастроен на SQLite и хранит данные в:

```txt
.data/db.sqlite
```

Это удобно для:

- локальных demo;
- быстрых prototypes;
- маленьких internal tools;
- experimentation.

## Named connections

```ts
const defaultDb = useDatabase();
const usersDb = useDatabase('users');
```

Named connections нужны, если проект работает с несколькими database connections.

## SQL через tagged template

```ts
const id = 'user-1';

const { rows } = await db.sql`
  SELECT *
  FROM users
  WHERE id = ${id}
`;
```

Tagged template помогает параметризовать значения и не склеивать SQL строками.

## Когда использовать `useDatabase`?

Можно использовать, если:

- нужен легкий SQL слой;
- проект маленький;
- не нужна полноценная ORM;
- удобно писать SQL напрямую;
- экспериментальная природа acceptable.

## Когда лучше Prisma?

Prisma лучше, если нужны:

- schema.prisma;
- migrations;
- generated typed client;
- relation queries;
- nested writes;
- transaction API;
- production-ready workflow;
- интеграция с Better Auth Prisma adapter;
- команда уже знает Prisma.

## Как сочетать с Prisma?

Обычно выбирают что-то одно для доменной БД:

```txt
Nitro route
  -> service
    -> Prisma Client
      -> PostgreSQL
```

`useDatabase` можно оставить для отдельных lightweight internal задач, но смешивание двух database layers требует дисциплины: одна миграционная система, один source of truth схемы, понятные ownership rules.

## Мини-шпаргалка

- `experimental.database: true` включает database layer.
- `useDatabase()` возвращает default connection.
- `useDatabase('name')` возвращает named connection.
- SQL пишется через tagged template.
- Feature experimental, поэтому для production чаще выбирают Prisma/Drizzle/SQL client.
- Не смешивай ORM и experimental layer без понятной причины.
