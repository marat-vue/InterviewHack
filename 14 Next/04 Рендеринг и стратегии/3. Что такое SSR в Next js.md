# Что такое SSR в Next js?

> [!summary]
> SSR в Next.js - рендеринг HTML на сервере во время запроса. В App Router это обычно называется dynamic rendering и включается, когда route зависит от cookies, headers, search params, uncached data или явно помечен как dynamic.

## Как SSR работает?

```text
Request -> Next server -> загрузка данных -> render -> HTML -> browser -> hydration
```

SSR нужен, когда HTML нельзя подготовить заранее.

## Пример dynamic route

```tsx
import { cookies } from 'next/headers'

export default async function AccountPage() {
  const cookieStore = await cookies()
  const session = cookieStore.get('session')?.value
  const user = await getUserBySession(session)

  return <Account user={user} />
}
```

Такой route зависит от request cookies, значит не может быть общей статикой для всех.

## Принудительный dynamic rendering

```tsx
export const dynamic = 'force-dynamic'
```

Использовать стоит только когда есть реальная причина.

## SSR и cache no-store

```tsx
const data = await fetch('https://api.example.com/live', {
  cache: 'no-store',
}).then((res) => res.json())
```

`no-store` говорит, что данные не нужно кешировать между запросами.

## Когда SSR нужен?

- пользовательские страницы;
- данные зависят от cookies;
- permissions зависят от request;
- цены/остатки должны быть свежими;
- A/B testing по headers;
- dashboard с серверной авторизацией.

## Что отвечать на собеседовании?

SSR в Next.js нужен для динамического HTML на каждый request. В App Router dynamic rendering включается через request-specific APIs вроде `cookies()`/`headers()`, uncached fetch или `dynamic = 'force-dynamic'`. SSR полезен для персонализации и свежих данных, но может быть дороже SSG.

## Частые ошибки

- Делать все страницы dynamic.
- Путать SSR и RSC.
- Забывать кеширование backend-запросов.
- Использовать SSR для статичных лендингов.
- Не измерять TTFB.

## Мини-шпаргалка

- SSR = HTML на request.
- В App Router часто говорят dynamic rendering.
- `cookies()` и `headers()` делают route динамичным.
- `cache: 'no-store'` отключает кеш fetch.
- SSR нужен для персонализации.
