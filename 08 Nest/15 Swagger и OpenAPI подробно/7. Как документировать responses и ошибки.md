# Как документировать responses и ошибки?

> [!summary]
> Response decorators описывают успешные и ошибочные HTTP-ответы: `@ApiOkResponse`, `@ApiCreatedResponse`, `@ApiBadRequestResponse`, `@ApiUnauthorizedResponse`, `@ApiNotFoundResponse` и другие.

## Success response

```ts
@ApiOkResponse({ type: UserDto })
@Get(':id')
findOne() {}
```

## Created response

```ts
@ApiCreatedResponse({ type: UserDto })
@Post()
create() {}
```

## Error responses

```ts
@ApiBadRequestResponse({ description: 'Validation failed' })
@ApiNotFoundResponse({ description: 'User not found' })
@ApiConflictResponse({ description: 'Email already exists' })
```

## Error DTO

```ts
export class ErrorResponseDto {
  @ApiProperty({ example: 400 })
  statusCode: number;

  @ApiProperty({ example: 'Validation failed' })
  message: string;
}
```

```ts
@ApiBadRequestResponse({ type: ErrorResponseDto })
```

## Мини-шпаргалка

- Документируй не только 200.
- Для POST часто нужен 201.
- Для validation нужен 400.
- Для auth нужны 401/403.
- Error response DTO должен совпадать с exception filter.
