# Что делает “Higher-Order Component (HOC)”?

> [!summary]
> Higher-Order Component - это функция, которая принимает компонент и возвращает новый компонент с дополнительным поведением. HOC применяли для переиспользования логики до массового перехода на hooks, но паттерн до сих пор встречается в библиотеках и старом коде.

## Базовая форма

```jsx
function withSomething(Component) {
  return function WrappedComponent(props) {
    return <Component {...props} />
  }
}
```

HOC не меняет исходный компонент. Он создает обертку.

## Пример: withAuth

```jsx
function withAuth(Component) {
  return function AuthenticatedComponent(props) {
    const user = useCurrentUser()

    if (!user) {
      return <Navigate to="/login" />
    }

    return <Component {...props} user={user} />
  }
}
```

Использование:

```jsx
const ProtectedSettingsPage = withAuth(SettingsPage)
```

## Пример: withLogger

```jsx
function withLogger(Component) {
  return function LoggedComponent(props) {
    useEffect(() => {
      console.log('mounted', Component.name)
    }, [])

    return <Component {...props} />
  }
}
```

## Зачем HOC нужен?

HOC позволяет добавить:

- авторизацию;
- подписку на данные;
- логирование;
- feature flags;
- обработку ошибок;
- layout-обертку;
- injected props.

## Минусы HOC

- wrapper hell: много вложенных оберток;
- сложнее понять, откуда пришли props;
- возможны конфликты имен props;
- сложнее типизировать;
- сложнее отлаживать дерево компонентов.

```jsx
export default withTheme(withAuth(withTracking(Page)))
```

С hooks часто проще:

```jsx
function Page() {
  const user = useCurrentUser()
  const theme = useTheme()

  return <PageView user={user} theme={theme} />
}
```

## Когда HOC все еще встречается?

- старые React-проекты;
- интеграции библиотек;
- wrappers для route guards;
- подключение providers или analytics;
- codebase до hooks.

## Мини-шпаргалка

- HOC = функция `Component -> EnhancedComponent`.
- Он добавляет поведение через обертку.
- HOC не должен мутировать переданный компонент.
- Hooks часто заменяют HOC для логики.
- Паттерн важно понимать для legacy и библиотечного кода.
