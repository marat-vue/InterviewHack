# Как выполнять CRUD через Prisma Client в Nitro routes?

> [!NOTE]
> CRUD в Nitro обычно выглядит так: route читает params/body/query, валидирует input, вызывает service, service вызывает Prisma Client. Prisma Client предоставляет методы `findMany`, `findUnique`, `create`, `update`, `delete` и другие.

## Create

```ts
// server/routes/api/users.post.ts
import { readValidatedBody } from 'h3';
import { z } from 'zod';

const schema = z.object({
  email: z.string().email(),
  name: z.string().min(1),
});

export default defineHandler(async (event) => {
  const body = await readValidatedBody(event, schema);

  const user = await prisma.user.create({
    data: body,
    select: {
      id: true,
      email: true,
      name: true,
    },
  });

  event.res.status = 201;
  return user;
});
```

## Read list

```ts
// server/routes/api/users.get.ts
export default defineHandler(async () => {
  return prisma.user.findMany({
    orderBy: {
      createdAt: 'desc',
    },
    select: {
      id: true,
      email: true,
      name: true,
      createdAt: true,
    },
  });
});
```

## Read by id

```ts
// server/routes/api/users/[id].get.ts
import { createError, getRouterParam } from 'h3';

export default defineHandler(async (event) => {
  const id = getRouterParam(event, 'id')!;

  const user = await prisma.user.findUnique({
    where: { id },
    select: {
      id: true,
      email: true,
      name: true,
    },
  });

  if (!user) {
    throw createError({
      statusCode: 404,
      statusMessage: 'User not found',
    });
  }

  return user;
});
```

## Update

```ts
// server/routes/api/users/[id].patch.ts
const schema = z.object({
  name: z.string().min(1).optional(),
});

export default defineHandler(async (event) => {
  const id = getRouterParam(event, 'id')!;
  const body = await readValidatedBody(event, schema);

  return prisma.user.update({
    where: { id },
    data: body,
    select: {
      id: true,
      email: true,
      name: true,
    },
  });
});
```

Если записи нет, `update` выбросит Prisma error. Для public API лучше ловить ошибку и превращать в `404`.

## Delete

```ts
// server/routes/api/users/[id].delete.ts
import { noContent } from 'h3';

export default defineHandler(async (event) => {
  const id = getRouterParam(event, 'id')!;

  await prisma.user.delete({
    where: { id },
  });

  return noContent(204);
});
```

## Массовые операции

```ts
await prisma.session.deleteMany({
  where: {
    expiresAt: {
      lt: new Date(),
    },
  },
});
```

`deleteMany`, `updateMany`, `createMany` обычно возвращают count или специальный результат, а не всегда массив сущностей.

## Где обрабатывать Prisma errors?

Для service:

```ts
import { Prisma } from '@prisma/client';

try {
  return await prisma.user.create({ data });
} catch (error) {
  if (
    error instanceof Prisma.PrismaClientKnownRequestError &&
    error.code === 'P2002'
  ) {
    throw createError({
      statusCode: 409,
      statusMessage: 'Email already exists',
    });
  }

  throw error;
}
```

## Мини-шпаргалка

- `create` - создать запись.
- `findMany` - список.
- `findUnique` - найти по unique field.
- `update` - обновить одну запись по unique field.
- `delete` - удалить одну запись по unique field.
- Валидация должна быть до Prisma.
- Prisma errors нужно переводить в понятные HTTP errors.
