# Что делает useMemo?

> [!summary]
> `useMemo` кеширует результат вычисления между render, пока зависимости не изменились. Его используют для дорогих вычислений, стабильных object props и предотвращения лишней работы, но не как универсальное средство оптимизации.

## Базовый синтаксис

```jsx
const cachedValue = useMemo(() => {
  return calculateValue(a, b)
}, [a, b])
```

React выполнит функцию на первом render и повторит вычисление только если изменятся зависимости.

## Пример с фильтрацией

```jsx
function TodoList({ todos, tab }) {
  const visibleTodos = useMemo(() => {
    return todos.filter((todo) => todo.status === tab)
  }, [todos, tab])

  return <List items={visibleTodos} />
}
```

Если `todos` и `tab` не изменились, React может вернуть сохраненный результат.

## Когда useMemo полезен?

- Дорогое вычисление.
- Большой список.
- Подготовка данных для графика.
- Стабильный объект для memo-компонента.
- Значение используется как dependency другого hook.

Пример стабильного объекта:

```jsx
const options = useMemo(() => ({
  pageSize,
  sort,
}), [pageSize, sort])
```

## Когда useMemo не нужен?

Не нужен для простых вычислений:

```jsx
const fullName = `${firstName} ${lastName}`
```

Не нужен "на всякий случай". Сам `useMemo` тоже имеет стоимость: React хранит значение и сравнивает dependencies.

## Важный нюанс

`useMemo` - оптимизация производительности, а не гарантия семантики. Код должен работать корректно и без `useMemo`. Если без него ломается логика, значит проблема в архитектуре.

## React Compiler

Современный React Compiler может автоматически мемоизировать часть значений и функций, уменьшая необходимость ручных `useMemo`. Но в реальных проектах ручной `useMemo` все еще встречается и его нужно понимать.

## Мини-шпаргалка

- `useMemo` кеширует результат вычисления.
- Dependencies должны включать все используемые reactive values.
- Не используй `useMemo` для каждой мелочи.
- Код должен быть корректным без `useMemo`.
- Сначала измерь проблему, потом оптимизируй.
