# Suspense в React 18

> [!summary]
> В React 18 `Suspense` стал важной частью concurrent rendering и SSR. Он по-прежнему используется для `React.lazy`, но также помогает streaming SSR, selective hydration и интеграциям с Suspense-enabled data fetching.

## Что такое Suspense?

`Suspense` позволяет показать запасной UI, пока дочерняя часть дерева еще не готова.

```jsx
import { Suspense, lazy } from 'react'

const ProfileSettings = lazy(() => import('./ProfileSettings'))

function ProfilePage() {
  return (
    <Suspense fallback={<p>Загружаем настройки...</p>}>
      <ProfileSettings />
    </Suspense>
  )
}
```

Если `ProfileSettings` еще не загружен, пользователь увидит `fallback`.

## Что изменилось в React 18?

До React 18 основной стабильный сценарий Suspense - lazy loading компонентов на клиенте.

В React 18 Suspense стал связан с:

- concurrent rendering;
- transitions;
- streaming SSR;
- selective hydration;
- data fetching интеграциями;
- React Server Components в фреймворках.

## Suspense и streaming SSR

Обычный SSR часто работает как "все или ничего": сервер ждет, пока соберется вся HTML-страница.

Streaming SSR позволяет отправлять страницу частями:

```jsx
<AppShell>
  <Suspense fallback={<CommentsSkeleton />}>
    <Comments />
  </Suspense>
</AppShell>
```

Сервер может быстро отправить shell страницы и fallback для комментариев, а HTML комментариев дослать позже.

## Suspense boundary

Каждый `<Suspense>` создает границу ожидания.

```jsx
function Dashboard() {
  return (
    <>
      <Suspense fallback={<ProfileSkeleton />}>
        <Profile />
      </Suspense>

      <Suspense fallback={<StatsSkeleton />}>
        <Stats />
      </Suspense>
    </>
  )
}
```

`Profile` и `Stats` могут загружаться независимо. Если зависнет `Stats`, это не обязательно блокирует `Profile`.

## Suspense и transitions

Без transition React может заменить уже показанный экран на fallback:

```jsx
setPage('settings')
```

С transition React понимает, что переход несрочный:

```jsx
const [isPending, startTransition] = useTransition()

function openSettings() {
  startTransition(() => {
    setPage('settings')
  })
}
```

Это помогает не прятать уже видимый UI слишком резко. Пользователь может видеть старый экран, пока новый готовится.

## Suspense и data fetching

Сам по себе `Suspense` не делает обычный `fetch` Suspense-aware:

```jsx
function User() {
  const user = fetch('/api/user') // так нельзя использовать напрямую

  return <h1>{user.name}</h1>
}
```

Нужен источник данных, который умеет интегрироваться с Suspense:

- Relay;
- TanStack Query в Suspense-режиме;
- framework-level data fetching;
- React Server Components;
- специальные resource abstractions.

Пример с Suspense-enabled query:

```jsx
function UserCard({ userId }) {
  const { data: user } = useSuspenseQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
  })

  return <h2>{user.name}</h2>
}

function UserPage() {
  return (
    <Suspense fallback={<UserSkeleton />}>
      <UserCard userId="42" />
    </Suspense>
  )
}
```

## Suspense не ловит ошибки

`Suspense` ловит ожидание, но не заменяет Error Boundary.

```jsx
<ErrorBoundary fallback={<p>Не удалось загрузить профиль</p>}>
  <Suspense fallback={<p>Загружаем профиль...</p>}>
    <Profile />
  </Suspense>
</ErrorBoundary>
```

Если Promise ожидается - работает `Suspense`. Если произошла ошибка - нужен `ErrorBoundary`.

## Как выбирать размер Suspense boundary?

Слишком большая граница:

```jsx
<Suspense fallback={<FullPageSpinner />}>
  <Header />
  <Main />
  <Sidebar />
  <Footer />
</Suspense>
```

Минус: один медленный блок может спрятать всю страницу.

Более гибкий вариант:

```jsx
<>
  <Header />

  <Suspense fallback={<MainSkeleton />}>
    <Main />
  </Suspense>

  <Suspense fallback={<SidebarSkeleton />}>
    <Sidebar />
  </Suspense>
</>
```

Так важные части интерфейса могут появляться быстрее.

## Что отвечать на собеседовании?

В React 18 Suspense - механизм для декларативного ожидания частей UI. Он используется для `React.lazy`, streaming SSR, selective hydration и Suspense-enabled data fetching. Suspense показывает fallback, но не обрабатывает ошибки; для ошибок нужен Error Boundary.

## Частые ошибки

- Думать, что Suspense автоматически работает с любым `fetch`.
- Оборачивать всю страницу в один большой fallback.
- Использовать spinner там, где лучше skeleton или stale UI.
- Путать Suspense и Error Boundary.
- Забывать про transition при переключении тяжелых экранов.

## Мини-шпаргалка

- `<Suspense fallback={...}>` задает границу ожидания.
- `React.lazy` - базовый клиентский сценарий.
- React 18 добавил сильную интеграцию с SSR и hydration.
- Для data fetching нужен Suspense-enabled источник.
- Ошибки ловит Error Boundary, а не Suspense.
