# Несовпадение HTML

> [!summary]
> Hydration mismatch возникает, когда HTML, созданный сервером, не совпадает с первым render на клиенте. React ожидает одинаковую разметку; если она отличается, появляются warnings, мигание UI или полный client rerender поддерева.

## Пример проблемы

```jsx
function RandomNumber() {
  return <p>{Math.random()}</p>
}
```

Сервер:

```html
<p>0.123</p>
```

Клиент:

```html
<p>0.987</p>
```

React видит несовпадение.

## Частые причины

- `Date.now()`;
- `new Date()` в render;
- `Math.random()`;
- `window.innerWidth`;
- `localStorage`;
- условие `typeof window !== 'undefined'` прямо в JSX;
- разные locale/timezone;
- разные данные на сервере и клиенте;
- невалидная HTML-вложенность;
- browser extension меняет DOM.

## Browser-only код

Плохо:

```jsx
function ThemeLabel() {
  const theme = localStorage.getItem('theme')

  return <p>{theme}</p>
}
```

Лучше:

```jsx
function ThemeLabel() {
  const [theme, setTheme] = useState(null)

  useEffect(() => {
    setTheme(localStorage.getItem('theme'))
  }, [])

  return <p>{theme ?? 'System'}</p>
}
```

Первый render одинаковый на сервере и клиенте.

## Данные должны совпадать

Если сервер загрузил данные, клиент должен получить те же initial data.

```html
<script>
  window.__INITIAL_DATA__ = ...
</script>
```

Иначе клиент может сразу перезапросить данные и отрендерить другое дерево.

## suppressHydrationWarning

Для отдельных неизбежно разных текстов можно использовать:

```jsx
<time suppressHydrationWarning>
  {new Date().toLocaleTimeString()}
</time>
```

Это escape hatch для редких случаев. Он не должен маскировать системные проблемы.

## Мини-шпаргалка

- Серверный HTML и первый клиентский render должны совпасть.
- Нестабильные значения нельзя считать прямо в render.
- Browser API используй после mount.
- Initial data нужно передавать на клиент.
- `suppressHydrationWarning` - редкое исключение.
