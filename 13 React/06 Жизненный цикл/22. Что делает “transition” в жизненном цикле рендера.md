# Что делает transition в жизненном цикле рендера?

> [!summary]
> Transition помечает обновление как менее срочное. React может выполнять такое обновление в фоне, прерывать его более срочными действиями и показывать старый UI, пока новый готовится.

## Простая идея

Есть срочные обновления:

```text
символ появился в input
кнопка нажалась
checkbox изменился
```

Есть менее срочные обновления:

```text
пересчитать тяжелый список
переключить вкладку с большим графиком
обновить результаты поиска
```

Transition помогает сказать React:

```text
Это обновление можно сделать менее срочно, не блокируя ввод.
```

## Пример

```jsx
function SearchPage() {
  const [query, setQuery] = useState('')
  const [resultsQuery, setResultsQuery] = useState('')
  const [isPending, startTransition] = useTransition()

  function handleChange(event) {
    const nextQuery = event.target.value
    setQuery(nextQuery)

    startTransition(() => {
      setResultsQuery(nextQuery)
    })
  }

  return (
    <>
      <input value={query} onChange={handleChange} />
      {isPending && <span>Обновляем результаты...</span>}
      <Results query={resultsQuery} />
    </>
  )
}
```

Input обновляется срочно, результаты - transition.

## Что происходит в lifecycle?

```text
urgent update -> React обрабатывает быстро
transition update -> React может отложить или прервать
commit -> применяет готовый результат
```

Transition не меняет правила commit: пользователь видит согласованный UI.

## Ограничение

Transition не подходит для controlled input value. Значение input должно обновляться срочно, иначе ввод станет неприятным.

## Мини-шпаргалка

- Transition = менее срочное обновление.
- Он помогает сохранить отзывчивость UI.
- React может прервать transition render.
- `isPending` показывает незавершенную transition-работу.
- Controlled input value не должен быть transition.
