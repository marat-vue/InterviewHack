# Как React 18 изменил работу жизненного цикла?

> [!summary]
> React 18 сделал concurrent-возможности частью основной модели React: появились `createRoot`, automatic batching, transitions, streaming SSR и более явная идея interruptible render. Это не отменило mount/update/unmount, но изменило то, как нужно думать о render phase.

## Главное изменение мышления

Раньше многие представляли render как строго синхронный процесс:

```text
setState -> render -> DOM update
```

В современной модели точнее:

```text
update scheduled -> React выбирает приоритет -> render может быть прерван -> commit применяет готовый результат
```

## Automatic batching

React 18 расширил batching:

```jsx
setTimeout(() => {
  setCount((count) => count + 1)
  setFlag(true)
}, 1000)
```

Несколько updates могут быть сгруппированы в один render не только в React event handlers, но и в async-сценариях.

## Transitions

```jsx
const [isPending, startTransition] = useTransition()

startTransition(() => {
  setTab(nextTab)
})
```

Transitions позволяют пометить часть обновлений как менее срочные.

## Strict Mode и эффекты

В development Strict Mode React может дополнительно вызывать render и effects, чтобы найти:

- нечистый render;
- отсутствующий cleanup;
- проблемы с ref cleanup;
- deprecated API.

Это development-only поведение.

## Что важно на собеседовании?

```text
React 18 не означает, что lifecycle исчез. Но render phase стала мыслиться как работа, которую React может планировать, приоритизировать и иногда прерывать. Поэтому side effects в render особенно опасны, а effects должны иметь корректный cleanup.
```

## Мини-шпаргалка

- React 18 принес concurrent root через `createRoot`.
- Automatic batching стал шире.
- Transitions позволяют делать обновления неблокирующими.
- Render может быть interruptible.
- Strict Mode в dev помогает находить нечистый код.
