# Что такое Next.js и какую проблему он решает?

> [!summary]
> Next.js - fullstack React-фреймворк для production-приложений. Он добавляет к React файловый роутинг, серверный рендеринг, Server Components, загрузку данных на сервере, кеширование, оптимизацию изображений, Metadata API и backend-возможности через Route Handlers и Server Actions.

## Почему одного React часто недостаточно?

React сам по себе отвечает за UI. Если собрать обычную SPA на Vite, приложение часто выглядит так:

```tsx
function App() {
  return <RouterProvider router={router} />
}
```

Это удобно для интерактивных интерфейсов, но в production быстро появляются вопросы:

- как отдать поисковику готовый HTML;
- как сделать быстрый первый экран;
- как описывать routes без ручной конфигурации;
- где получать данные до render;
- как не отправлять лишний JavaScript в браузер;
- как генерировать metadata для SEO;
- как сделать backend endpoint рядом с UI.

Next.js решает эти задачи на уровне фреймворка.

## Главная идея Next.js

Next.js берет React и добавляет вокруг него инфраструктуру приложения:

```text
React = компоненты и UI
Next.js = React + роутинг + рендеринг + сервер + кеш + оптимизация
```

В App Router страницы создаются через папки и специальные файлы:

```text
app/
  layout.tsx
  page.tsx
  blog/
    [slug]/
      page.tsx
```

Файл `app/blog/[slug]/page.tsx` автоматически становится страницей `/blog/:slug`.

## Какие проблемы решает Next.js?

| Проблема | Как помогает Next.js |
|---|---|
| SEO в SPA | отдает готовый HTML и metadata |
| медленный первый экран | Server Rendering, SSG, streaming |
| большой JS bundle | Server Components не едут в браузер |
| ручной роутинг | file-system routing |
| дублирование backend/frontend | Route Handlers и Server Actions |
| изображения и шрифты | `next/image`, `next/font` |
| кеширование данных | `fetch` cache, `revalidate`, tags |

## Next.js не заменяет React

Next.js использует React внутри. Все базовые знания React остаются важными:

- компоненты;
- props;
- state;
- hooks;
- Server и Client Components;
- Suspense;
- hydration.

Но в Next.js нужно дополнительно понимать, где код выполняется: на сервере, на клиенте, во время build или во время request.

## Что отвечать на собеседовании?

Next.js - это React-фреймворк для production, который решает задачи, не входящие в ядро React: маршрутизацию, SSR/SSG/ISR, Server Components, загрузку данных, кеширование, SEO, оптимизацию assets и backend endpoints. Его выбирают, когда приложение должно быть быстрым, индексируемым и удобно разворачиваться как полноценный web-продукт.

## Частые ошибки

- Считать Next.js просто роутером для React.
- Думать, что все компоненты в Next.js клиентские.
- Использовать Next.js там, где достаточно простой SPA.
- Путать SSR, SSG, ISR и Server Components.
- Забывать, что server code не должен попадать в Client Components.

## Мини-шпаргалка

- Next.js = React framework.
- App Router основан на папке `app`.
- Server Components включены по умолчанию.
- SEO улучшается за счет HTML и metadata.
- Backend-возможности: Route Handlers и Server Actions.
- Для интерактива нужен Client Component с `'use client'`.
