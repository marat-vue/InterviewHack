# Как тестировать Nuxt pages, components, server routes и composables?

> [!NOTE]
> Nuxt тестируют на нескольких уровнях: unit tests для composables/utils, component tests для Vue/Nuxt components, route/server tests для Nitro endpoints и e2e tests для пользовательских сценариев.

## Что поставить?

```bash
pnpm add -D vitest @nuxt/test-utils playwright happy-dom
```

`vitest.config.ts`:

```ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    globals: true
  }
})
```

## Unit test composable

`app/composables/useMoney.ts`:

```ts
export function useMoney(value: number) {
  return new Intl.NumberFormat('ru-RU', {
    style: 'currency',
    currency: 'RUB'
  }).format(value)
}
```

Test:

```ts
import { describe, expect, it } from 'vitest'

describe('useMoney', () => {
  it('formats RUB value', () => {
    expect(useMoney(1000)).toContain('1')
  })
})
```

## Component test с `mountSuspended`

```ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { describe, expect, it } from 'vitest'
import ProductCard from '~/components/ProductCard.vue'

describe('ProductCard', () => {
  it('renders title', async () => {
    const wrapper = await mountSuspended(ProductCard, {
      props: {
        product: {
          id: '1',
          title: 'Keyboard',
          price: 1000
        }
      }
    })

    expect(wrapper.text()).toContain('Keyboard')
  })
})
```

`mountSuspended` полезен, потому что Nuxt components часто используют async setup, auto imports, routing и app context.

## Test page с router

```ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { describe, expect, it } from 'vitest'
import Page from '~/pages/products/[id].vue'

describe('product page', () => {
  it('renders product route', async () => {
    const wrapper = await mountSuspended(Page, {
      route: '/products/123'
    })

    expect(wrapper.exists()).toBe(true)
  })
})
```

## Mock composable

```ts
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { vi } from 'vitest'

mockNuxtImport('useUserSession', () => {
  return () => ({
    loggedIn: ref(true),
    user: ref({ id: '1', name: 'Marat' })
  })
})
```

## Server route test

```ts
import { $fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('/api/health', async () => {
  await setup({
    server: true
  })

  it('returns health', async () => {
    await expect($fetch('/api/health')).resolves.toEqual({
      ok: true
    })
  })
})
```

## E2E test

```ts
import { createPage, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('login flow', async () => {
  await setup({
    browser: true,
    server: true
  })

  it('opens login page', async () => {
    const page = await createPage('/login')
    await expect(page.getByRole('button', { name: 'Войти' })).toBeVisible()
  })
})
```

## Integration tests с DB/Redis

Для тестов с инфраструктурой лучше поднимать отдельные services:

```yaml
services:
  test-db:
    image: postgres:18
    environment:
      POSTGRES_USER: test
      POSTGRES_PASSWORD: test
      POSTGRES_DB: test
    tmpfs:
      - /var/lib/postgresql/data

  test-redis:
    image: redis:8-alpine
```

Env:

```env
DATABASE_URL=postgresql://test:test@test-db:5432/test
REDIS_URL=redis://test-redis:6379
```

Не запускай integration tests против dev/prod базы.

## Что тестировать?

| Объект | Вид теста |
| --- | --- |
| formatter/utils | Unit. |
| composable с Nuxt context | Unit/component with Nuxt environment. |
| form component | Component test. |
| route middleware | Unit/integration. |
| server route | `$fetch` + Nuxt server setup. |
| login checkout flow | E2E. |
| SEO/meta | SSR/e2e snapshot or assertion. |

## Что отвечать на собеседовании?

Nuxt тестируют через Vitest и `@nuxt/test-utils`. Для компонентов используют `mountSuspended`, для server routes - `setup({ server: true })` и `$fetch`, для browser flows - `setup({ browser: true })` и Playwright APIs. Infrastructure tests должны использовать отдельные test DB/Redis, а не dev/prod окружение.

## Частые ошибки

- Тестировать Nuxt component обычным mount без Nuxt context.
- Не мокать auto-import composables.
- Запускать server tests без `setup({ server: true })`.
- Использовать dev database для tests.
- Смешивать unit и e2e в одном медленном наборе.
- Не проверять SSR-specific ошибки и hydration.

## Мини-шпаргалка

- Config: `defineVitestConfig`.
- Component: `mountSuspended`.
- Mock auto import: `mockNuxtImport`.
- Server route: `$fetch` + `setup`.
- Browser: `createPage`.
- DB/Redis tests: отдельные test services.
