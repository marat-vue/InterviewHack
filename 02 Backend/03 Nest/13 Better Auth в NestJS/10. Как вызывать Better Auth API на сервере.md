# Как вызывать Better Auth API на сервере?

> [!summary]
> Better Auth instance содержит `api` object, через который серверный код может вызывать auth endpoints как функции: получить session, выполнить sign in, обновить пользователя и обработать ошибки.

## getSession

```ts
const session = await auth.api.getSession({
  headers: request.headers,
});
```

Конкретный способ передачи headers зависит от того, в каком runtime и integration ты находишься.

## signInEmail

```ts
await auth.api.signInEmail({
  body: {
    email: 'john@example.com',
    password: 'password',
  },
});
```

## Получить response headers

Иногда нужны cookies или headers.

```ts
const { headers, response } = await auth.api.signUpEmail({
  returnHeaders: true,
  body: {
    email: 'john@example.com',
    password: 'password',
    name: 'John Doe',
  },
});
```

## Обработка ошибок

```ts
try {
  await auth.api.signInEmail({ body: { email, password } });
} catch (error) {
  if (isAPIError(error)) {
    throw new UnauthorizedException(error.message);
  }

  throw error;
}
```

## Мини-шпаргалка

- `auth.api` вызывает Better Auth endpoints на сервере.
- Body передается как `{ body: ... }`.
- Headers передаются как `{ headers: ... }`.
- Для cookies иногда нужны response headers.
- Ошибки Better Auth нужно перевести в Nest exceptions.
