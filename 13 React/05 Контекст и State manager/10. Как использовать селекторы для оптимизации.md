# Как использовать селекторы для оптимизации в Zustand?

> [!summary]
> Selector в Zustand позволяет компоненту подписаться только на нужный slice store. Это главный инструмент оптимизации: чем точнее selector, тем меньше компонент реагирует на чужие изменения.

## Плохой пример: чтение всего store

```jsx
function UserName() {
  const store = useUserStore()

  return <span>{store.user.name}</span>
}
```

Компонент может обновляться при любом изменении store, даже если `user.name` не менялся.

## Хороший пример: точечный selector

```jsx
function UserName() {
  const name = useUserStore((state) => state.user.name)

  return <span>{name}</span>
}
```

Компонент явно зависит от `user.name`.

## Несколько значений

Простой вариант:

```jsx
const name = useUserStore((state) => state.user.name)
const avatar = useUserStore((state) => state.user.avatar)
```

Если хочется вернуть объект, нужна осторожность:

```jsx
const userView = useUserStore((state) => ({
  name: state.user.name,
  avatar: state.user.avatar,
}))
```

Такой selector создает новый объект, что может вызывать лишние render.

## useShallow

```jsx
import { useShallow } from 'zustand/react/shallow'

const { name, avatar } = useUserStore(
  useShallow((state) => ({
    name: state.user.name,
    avatar: state.user.avatar,
  }))
)
```

`useShallow` помогает сравнивать объект поверхностно.

## Практические правила

- Выбирай минимальный slice.
- Не возвращай весь store.
- Для нескольких полей используй несколько selectors или shallow.
- Не создавай новые массивы в selector без необходимости.
- Derived data лучше считать аккуратно и стабилизировать, если она дорогая.

## Мини-шпаргалка

- Selector уменьшает область подписки.
- `useStore((state) => state.field)` - базовый паттерн.
- Чтение всего store часто ведет к лишним render.
- Object selector требует shallow или другой стабилизации.
- Оптимизация начинается с точной зависимости компонента.
