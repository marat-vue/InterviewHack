# Как работают write-through, write-behind и write-around?

> [!NOTE]
> Эти cache patterns описывают, что происходит при записи. В web backend чаще всего начинают с cache-aside, но write-through/write-behind/write-around важно знать для архитектурных вопросов.

## Write-through

При записи приложение обновляет и БД, и cache:

```txt
write request -> DB update -> Redis set -> response
```

Пример:

```ts
const product = await db.product.update({
  where: {
    id,
  },
  data,
});

await redis.set(`cache:product:${id}`, JSON.stringify(product), {
  EX: 300,
});
```

Плюс: после write cache уже свежий.

Минус: запись медленнее и сложнее обработать partial failure.

## Write-behind

Приложение пишет в cache/queue, а запись в БД происходит позже:

```txt
write request -> Redis -> response
worker -> DB
```

Плюс: низкая latency write path.

Минус: сложная durability, retries, consistency, потеря данных при плохой настройке.

Для важных данных write-behind требует очень осторожной архитектуры.

## Write-around

При записи приложение обновляет БД, но не обновляет cache:

```txt
write request -> DB update -> delete cache или ничего
next read -> cache miss -> DB -> cache
```

Это уменьшает cache pollution, если новые данные редко читают.

## Как выбрать?

| Pattern | Когда выбрать |
|---|---|
| Cache-aside | default для web backend |
| Write-through | важно, чтобы cache был свежим после write |
| Write-behind | write latency критична, допустима eventual consistency |
| Write-around | write-heavy данные редко читаются сразу |

## Как объяснить consistency?

Redis cache почти всегда eventual-consistent относительно source of truth. Нужно явно решить:

- сколько допустима stale data;
- где invalidation;
- что делать при Redis outage;
- что делать при DB outage;
- какие операции нельзя кешировать.

## Мини-шпаргалка

- Write-through обновляет cache при записи.
- Write-behind откладывает запись в source of truth.
- Write-around пишет в БД, cache обновится при read.
- Cache-aside проще и чаще всего достаточен.
- Чем ближе cache к source of truth, тем сложнее failure modes.
