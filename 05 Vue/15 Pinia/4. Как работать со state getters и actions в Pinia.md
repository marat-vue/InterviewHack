# Как работать со state, getters и actions в Pinia?

> [!summary]
> В Pinia `state` хранит данные, `getters` вычисляют значения на основе state, а `actions` изменяют state, вызывают API и содержат бизнес-логику client-side слоя.

## State

```typescript
export const useCartStore = defineStore("cart", {
  state: () => ({
    items: [] as CartItem[],
    isLoading: false,
  }),
});
```

State должен объявлять все поля заранее. Нельзя надежно добавить новое поле позже:

```typescript
cart.unknownField = 123;
```

Такой код ломает предсказуемость и типизацию.

## Getters

```typescript
getters: {
  totalPrice: (state) =>
    state.items.reduce((sum, item) => sum + item.price * item.quantity, 0),
  itemsCount: (state) =>
    state.items.reduce((sum, item) => sum + item.quantity, 0),
}
```

Getter похож на `computed`: он не должен делать side effects или API-запросы.

## Actions

```typescript
actions: {
  addItem(product: Product) {
    const item = this.items.find((item) => item.productId === product.id);

    if (item) {
      item.quantity++;
      return;
    }

    this.items.push({
      productId: product.id,
      title: product.title,
      price: product.price,
      quantity: 1,
    });
  },
}
```

Actions могут быть async:

```typescript
async loadCart() {
  this.isLoading = true;

  try {
    this.items = await cartApi.getCart();
  } finally {
    this.isLoading = false;
  }
}
```

## Прямое изменение state

В Pinia можно писать:

```typescript
cart.items = [];
cart.items.push(item);
```

В отличие от Vuex, отдельные mutations не нужны. Для группового изменения можно использовать `$patch`.

## Мини-шпаргалка

- `state` - источник данных store.
- `getters` - computed-значения без side effects.
- `actions` - операции, async-запросы и изменение state.
- В Pinia нет mutations.
- State поля нужно объявлять заранее.
- API-запросы обычно живут в actions или service layer, который вызывают actions.
