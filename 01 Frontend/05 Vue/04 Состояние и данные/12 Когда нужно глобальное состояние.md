# Когда нужно глобальное состояние?

> [!NOTE] Коротко
> Глобальное состояние нужно, когда одни и те же данные используются разными независимыми частями приложения и должны иметь единый источник правды.

## Вопрос

Когда нужно глобальное состояние?

## Хорошие кандидаты

- Текущий пользователь и права доступа.
- Корзина покупок.
- Тема приложения и настройки.
- Данные, общие для нескольких страниц.
- Кэш сущностей, который используют разные экраны.

```typescript
export const useCartStore = defineStore("cart", {
  state: () => ({
    items: [] as CartItem[],
  }),
});
```

## Когда local state уже неудобен

Если состояние нужно компонентам из разных веток дерева, props и emits начинают создавать длинные цепочки.

```text
Page -> Layout -> Sidebar -> CartBadge
Page -> ProductList -> ProductCard
```

Корзина нужна в разных местах, поэтому store может быть оправдан.

## Когда глобальное состояние не нужно

Флаг открытия локальной модалки, значение input-а или временное состояние одной формы обычно лучше хранить локально.

## Риски глобального state

Чем больше данных в store, тем сильнее связаны части приложения. Это усложняет тесты и понимание того, кто меняет данные.

## Мини-шпаргалка

- Global state нужен для общих данных.
- Он должен иметь понятный источник правды.
- Не выноси в store локальные UI-флаги без причины.
- Если данные нужны многим независимым местам, Pinia часто подходит.
