# Как делать international SEO и hreflang?

> [!summary]
> International SEO помогает показывать правильную языковую или региональную версию страницы. Для этого нужны понятная URL-структура, локализованный контент и корректный `hreflang`.

## Когда нужен hreflang?

Если есть несколько версий страницы:

```text
https://example.com/en/pricing
https://example.com/ru/pricing
https://example.com/de/pricing
```

`hreflang` помогает поисковику понять, какую версию показать пользователю.

## Пример hreflang

```html
<link rel="alternate" hreflang="en" href="https://example.com/en/pricing">
<link rel="alternate" hreflang="ru" href="https://example.com/ru/pricing">
<link rel="alternate" hreflang="x-default" href="https://example.com/pricing">
```

## Важное правило взаимности

Если русская страница указывает на английскую, английская должна указывать обратно на русскую.

Иначе сигнал может быть проигнорирован.

## Как выбрать структуру URL?

Варианты:

| Структура | Пример |
|---|---|
| Подпапки | `/ru/`, `/en/` |
| Поддомены | `ru.example.com` |
| Разные домены | `example.ru`, `example.de` |

Подпапки часто проще поддерживать технически.

## Частые ошибки

- hreflang указывает на неканонический URL.
- Нет обратных ссылок между версиями.
- Перевод неполный.
- Автоматический redirect по IP мешает выбрать язык.
- Все языки имеют одинаковый title.
- `html lang` не соответствует языку страницы.

## Мини-шпаргалка

- hreflang нужен для языковых и региональных версий.
- Все альтернативы должны ссылаться друг на друга.
- URL должны быть canonical и индексируемыми.
- `x-default` полезен для страницы выбора языка или дефолтной версии.
- Локализация - это не только перевод слов, но и intent, валюта, региональные ожидания.
