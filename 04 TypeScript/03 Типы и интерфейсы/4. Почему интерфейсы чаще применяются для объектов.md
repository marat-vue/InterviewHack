# Почему интерфейсы чаще применяются для объектов

> [!summary] Коротко
> Интерфейсы специально удобны для описания формы объектов: полей, методов, наследования и реализации классами.

## Вопрос

Почему `interface` часто используют именно для объектов?

## Определение

Интерфейс описывает контракт объекта: какие свойства и методы должны присутствовать. Это совпадает с тем, как в JavaScript обычно передают данные: plain objects, props, конфиги, DTO.

## Пример

```typescript
interface ButtonProps {
  label: string;
  disabled?: boolean;
  onClick(): void;
}
```

Такой интерфейс понятно описывает объект настроек кнопки.

## Наследование

```typescript
interface Entity {
  id: number;
}

interface User extends Entity {
  name: string;
}
```

`extends` читается естественно для объектных контрактов.

## Реализация классом

```typescript
interface Logger {
  log(message: string): void;
}

class ConsoleLogger implements Logger {
  log(message: string): void {
    console.log(message);
  }
}
```

Класс явно обещает соответствовать интерфейсу.

## Где interface особенно уместен

- props компонентов;
- DTO объектов;
- модели данных;
- публичные контракты библиотек;
- классы с `implements`;
- расширяемые типы.

## Когда лучше type

Если нужно описать union, tuple, conditional type или mapped type, `type` обычно удобнее.

## Мини-шпаргалка

```typescript
interface User {
  id: number;
  name: string;
}
```
