# Как работают Streams в Redis?

> [!NOTE]
> Streams - структура данных Redis для append-only событий. Они похожи на легкий event log: сообщения сохраняются, имеют ids, могут читаться несколькими consumers и поддерживают consumer groups.

## Когда использовать Streams?

Streams подходят для:

- event-driven backend;
- background jobs;
- audit events;
- order processing;
- email sending;
- integration events;
- reliable-ish queues;
- replay после падения consumer.

## Как добавить событие?

```redis
XADD orders * type created orderId 42 userId 1
```

`*` значит, что Redis сам создаст id:

```txt
1786000000000-0
```

## Как читать stream?

С начала:

```redis
XREAD COUNT 10 STREAMS orders 0
```

Только новые:

```redis
XREAD BLOCK 5000 STREAMS orders $
```

## Consumer groups

Создать group:

```redis
XGROUP CREATE orders order-workers $ MKSTREAM
```

Читать новые сообщения:

```redis
XREADGROUP GROUP order-workers worker-1 COUNT 10 BLOCK 5000 STREAMS orders >
```

Подтвердить обработку:

```redis
XACK orders order-workers 1786000000000-0
```

## Pending entries

Если consumer прочитал сообщение, но не сделал `XACK`, запись остается pending.

Проверить:

```redis
XPENDING orders order-workers
```

Забрать stuck messages:

```redis
XAUTOCLAIM orders order-workers worker-2 60000 0-0 COUNT 10
```

## Node.js пример worker-а

```ts
while (true) {
  const response = await redis.xReadGroup(
    'order-workers',
    'worker-1',
    {
      key: 'orders',
      id: '>',
    },
    {
      COUNT: 10,
      BLOCK: 5000,
    },
  );

  if (!response) {
    continue;
  }

  for (const stream of response) {
    for (const message of stream.messages) {
      await handleOrderEvent(message.message);
      await redis.xAck('orders', 'order-workers', message.id);
    }
  }
}
```

## Как ограничить размер stream?

```redis
XADD orders MAXLEN ~ 100000 * type created orderId 42
```

Или:

```redis
XTRIM orders MAXLEN ~ 100000
```

Без trimming stream может расти бесконечно.

## Streams или Pub/Sub?

| Требование | Выбор |
|---|---|
| Нужна история сообщений | Streams |
| Нужны consumer groups | Streams |
| Допустима потеря offline сообщений | Pub/Sub |
| Нужен простой realtime broadcast | Pub/Sub |
| Нужен retry | Streams |

## Мини-шпаргалка

- `XADD` - добавить событие.
- `XREAD` - читать stream.
- `XGROUP CREATE` - создать group.
- `XREADGROUP` - читать как consumer.
- `XACK` - подтвердить обработку.
- `XPENDING` - pending messages.
- `XAUTOCLAIM` - забрать зависшие messages.
- Всегда думай про trimming.
