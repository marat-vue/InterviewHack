# Как работают HyperLogLog в Redis?

> [!NOTE]
> HyperLogLog оценивает количество уникальных элементов с маленькой фиксированной памятью. Это probabilistic structure: результат приблизительный, зато очень компактный.

## Когда использовать HyperLogLog?

HyperLogLog подходит для:

- unique visitors;
- approximate daily active users;
- unique search queries;
- unique IPs;
- unique product views;
- приблизительных метрик.

Если нужна точная membership проверка, используй Set.

## Основные команды

```redis
PFADD uv:2026-08-06 user:1 user:2 user:3
PFCOUNT uv:2026-08-06
```

Объединение:

```redis
PFMERGE uv:week uv:2026-08-01 uv:2026-08-02 uv:2026-08-03
PFCOUNT uv:week
```

## Чем HLL отличается от Set?

| Требование | Set | HyperLogLog |
|---|---:|---:|
| Точное количество | Да | Нет, приблизительно |
| Проверить member | Да | Нет |
| Память на миллионы значений | Больше | Очень мало |
| Объединить периоды | Да | Да |

## Пример unique visitors

```ts
export async function trackVisit(userId: string) {
  const day = new Date().toISOString().slice(0, 10);

  await redis.pfAdd(`uv:${day}`, userId);
  await redis.expire(`uv:${day}`, 60 * 60 * 24 * 90);
}

export async function getDailyUniqueVisitors(day: string) {
  return redis.pfCount(`uv:${day}`);
}
```

## Ограничения

HyperLogLog не подходит, если:

- нужен точный ответ;
- нужно перечислить members;
- нужно удалить member;
- нужно проверить, был ли конкретный user.

## Мини-шпаргалка

- `PFADD` - добавить элементы.
- `PFCOUNT` - оценить unique count.
- `PFMERGE` - объединить несколько HLL.
- HLL экономит память.
- HLL не умеет membership и deletion отдельных members.
