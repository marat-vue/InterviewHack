# Как тестировать components, которые вызывают Nitro API?

> [!NOTE]
> Если Nuxt component вызывает `$fetch('/api/...')`, в runtime tests удобно использовать `registerEndpoint`. Он позволяет замокать server response без поднятия реального backend endpoint.

## Component

```vue
<script setup lang="ts">
const { data } = await useFetch('/api/profile');
</script>

<template>
  <div>{{ data?.name }}</div>
</template>
```

## Test с `registerEndpoint`

```ts
import { describe, expect, it } from 'vitest';
import { mountSuspended, registerEndpoint } from '@nuxt/test-utils/runtime';
import ProfileCard from '~/components/ProfileCard.vue';

describe('ProfileCard', () => {
  it('renders profile name', async () => {
    registerEndpoint('/api/profile', () => ({
      name: 'Anna',
    }));

    const wrapper = await mountSuspended(ProfileCard);

    expect(wrapper.text()).toContain('Anna');
  });
});
```

## Mock endpoint with method

```ts
registerEndpoint('/api/profile', {
  method: 'PATCH',
  handler: () => ({
    saved: true,
  }),
});
```

## Mock Nuxt imports

Если component использует `useRoute`:

```ts
import { mockNuxtImport } from '@nuxt/test-utils/runtime';

mockNuxtImport('useRoute', () => {
  return () => ({
    params: {
      id: 'u1',
    },
  });
});
```

## Проверка events/forms

```ts
const wrapper = await mountSuspended(ProfileForm);

await wrapper.find('input[name="name"]').setValue('Anna');
await wrapper.find('form').trigger('submit');

expect(wrapper.text()).toContain('Saved');
```

## Когда лучше e2e?

Runtime component test с mocked endpoint хорош для UI state.

E2E лучше, если нужно проверить:

- реальный Nitro route;
- реальные cookies;
- Better Auth session;
- Prisma write/read;
- navigation после sign in;
- browser behavior.

## Частые ошибки

| Ошибка | Что делать |
|---|---|
| Component зависает | проверь async setup и `mountSuspended` |
| `$fetch` идет в реальный API | зарегистрируй `registerEndpoint` до mount |
| mock не применяется к auto import | используй `mockNuxtImport` |
| child component мешает | используй `mockComponent` |
| DOM API отсутствует | настрой `happy-dom`/`jsdom` |

## Мини-шпаргалка

- Component с Nuxt async setup: `mountSuspended`.
- Mock API: `registerEndpoint`.
- Mock auto import: `mockNuxtImport`.
- Mock child component: `mockComponent`.
- UI тесты не заменяют API integration tests.
- Auth/cookies лучше проверять e2e.
