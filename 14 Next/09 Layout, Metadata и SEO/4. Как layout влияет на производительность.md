# Как layout влияет на производительность?

> [!summary]
> Layout улучшает производительность за счет сохранения общей оболочки при навигации, частичного рендера, меньшего количества повторной работы и возможности держать большую часть интерфейса на сервере. Но неправильный Root Layout может, наоборот, увеличить client bundle и замедлить приложение.

## 1. Layout не перемонтируется при вложенной навигации

Если пользователь находится в разделе `/dashboard`:

```text
/dashboard/users
/dashboard/settings
/dashboard/billing
```

то общий `app/dashboard/layout.tsx` сохраняется. Это значит:

- сайдбар не создается заново;
- состояние меню не сбрасывается;
- общая оболочка не пересобирается без необходимости;
- пользователь ощущает навигацию быстрее.

## 2. Next.js может обновлять только нужный сегмент

App Router строит интерфейс сегментами. При переходе между страницами внутри одного layout Next.js может переиспользовать уже загруженные части дерева и запросить только новый segment payload.

Упрощенно:

```tsx
<RootLayout>
  <DashboardLayout>
    <OnlyThisPageChanges />
  </DashboardLayout>
</RootLayout>
```

Это снижает количество работы на клиенте и сервере.

## 3. Layout помогает уменьшить client-side JavaScript

Layout по умолчанию является Server Component. Если оставить его серверным, код layout не попадает в клиентский bundle как интерактивный JavaScript.

Плохо:

```tsx
// app/layout.tsx
'use client'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html><body>{children}</body></html>
}
```

Так весь Root Layout становится клиентским, а вместе с ним часто утягиваются провайдеры и зависимости.

Лучше:

```tsx
// app/providers.tsx
'use client'

export function Providers({ children }: { children: React.ReactNode }) {
  return <ThemeProvider>{children}</ThemeProvider>
}
```

```tsx
// app/layout.tsx
import { Providers } from './providers'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  )
}
```

## 4. Layout хорошо сочетается со streaming

В App Router можно использовать `loading.tsx`, Suspense и серверный рендеринг по сегментам. Общий layout может показаться сразу, а вложенная страница догрузиться позже.

```text
app/
  dashboard/
    layout.tsx
    loading.tsx
    reports/
      page.tsx
```

Пользователь быстрее видит стабильную оболочку интерфейса, даже если конкретная страница грузит тяжелые данные.

## 5. Layout может навредить, если хранить в нем слишком много

Layout расположен выше страниц. Поэтому все, что ты кладешь в layout, потенциально влияет на много маршрутов.

Плохие идеи:

- тяжелые клиентские библиотеки в Root Layout;
- запросы к данным, нужным только одной странице;
- огромные меню, которые не нужны большинству маршрутов;
- глобальные провайдеры, которые используются только в одном разделе;
- частые request-specific данные в persistent layout.

Если данные нужны только странице, лучше грузить их в `page.tsx` или более низком layout.

## Что отвечать на собеседовании?

Layout влияет на производительность тем, что сохраняется между переходами внутри сегмента и позволяет Next.js переиспользовать общую часть UI. Это уменьшает повторный рендер, сохраняет состояние и помогает App Router обновлять только изменившиеся части маршрута. Но если сделать Root Layout клиентским или положить туда тяжелую логику, можно увеличить bundle и ухудшить performance.

## Частые ошибки

- Делать `app/layout.tsx` клиентским без причины.
- Класть все провайдеры в корень, даже если они нужны одному разделу.
- Загружать в layout данные, нужные только одной странице.
- Не использовать вложенные layout для крупных разделов.
- Ожидать, что layout всегда обновляется как обычная страница.

## Мини-шпаргалка

- Layout сохраняется при вложенной навигации.
- App Router может обновлять только изменившийся сегмент.
- Server Layout уменьшает client JS.
- `loading.tsx` и Suspense улучшают perceived performance.
- Тяжелый Root Layout замедляет все приложение.
- Данные лучше держать как можно ниже в дереве.
