# Как запускать tests, lint и typecheck Nuxt в Docker?

> [!NOTE]
> Docker полезен для тестов Nuxt/Nitro, потому что можно поднять одинаковые Node.js, PostgreSQL и Redis в CI и локально. Unit tests могут идти без инфраструктуры, integration tests - с отдельными test services.

## Test target в Dockerfile

```dockerfile
FROM node:22-bookworm-slim AS base
WORKDIR /app
ENV PNPM_HOME=/pnpm
ENV PATH=$PNPM_HOME:$PATH
RUN corepack enable

FROM base AS deps
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile

FROM base AS build
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN pnpm build

FROM build AS test
ENV NODE_ENV=test
CMD ["pnpm", "test"]
```

## Compose service для unit tests

```yaml
services:
  test:
    build:
      context: .
      target: test
    command: pnpm test
    environment:
      NODE_ENV: test
```

Запуск:

```bash
docker compose run --rm test
```

## Lint и typecheck

```yaml
services:
  lint:
    build:
      context: .
      target: build
    command: pnpm lint

  typecheck:
    build:
      context: .
      target: build
    command: pnpm typecheck
```

Команды:

```bash
docker compose run --rm lint
docker compose run --rm typecheck
```

## Integration tests с PostgreSQL и Redis

```yaml
services:
  test:
    build:
      context: .
      target: build
    command: sh -c "pnpm prisma migrate deploy && pnpm test:integration"
    environment:
      NODE_ENV: test
      DATABASE_URL: postgresql://test:test@test-db:5432/test
      REDIS_URL: redis://test-redis:6379
    depends_on:
      test-db:
        condition: service_healthy
      test-redis:
        condition: service_healthy

  test-db:
    image: postgres:18
    environment:
      POSTGRES_USER: test
      POSTGRES_PASSWORD: test
      POSTGRES_DB: test
    tmpfs:
      - /var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U test -d test"]
      interval: 5s
      timeout: 3s
      retries: 10

  test-redis:
    image: redis:8-alpine
    tmpfs:
      - /data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
```

`tmpfs` делает test database одноразовой и быстрой. После container stop данные исчезают.

## `@nuxt/test-utils`

Типичный Vitest config:

```ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    globals: true
  }
})
```

Пример теста Nitro endpoint:

```ts
import { describe, expect, it } from 'vitest'
import { $fetch, setup } from '@nuxt/test-utils/e2e'

describe('/api/health', async () => {
  await setup({
    server: true
  })

  it('returns ok', async () => {
    await expect($fetch('/api/health')).resolves.toEqual({ ok: true })
  })
})
```

В Docker такой тест получает те же env:

```yaml
environment:
  DATABASE_URL: postgresql://test:test@test-db:5432/test
  REDIS_URL: redis://test-redis:6379
```

## CI pipeline идея

```text
docker build --target build .
docker compose -f compose.yaml -f compose.test.yaml run --rm lint
docker compose -f compose.yaml -f compose.test.yaml run --rm typecheck
docker compose -f compose.yaml -f compose.test.yaml run --rm test
```

Для ускорения используют BuildKit cache и registry cache.

## Что отвечать на собеседовании?

Docker помогает запускать Nuxt tests в одинаковом окружении. Unit tests можно запускать в test target без инфраструктуры, а integration tests поднимают отдельные Postgres и Redis services с healthcheck и tmpfs. Для Nuxt используют Vitest и `@nuxt/test-utils`, а env для тестов передают через Compose.

## Частые ошибки

- Запускать integration tests против dev database.
- Не очищать test state между прогонами.
- Использовать persistent volume для test DB.
- Не ждать готовности Postgres.
- Смешивать lint/typecheck/test в один плохо диагностируемый command.
- Не прокидывать test env внутрь container.

## Мини-шпаргалка

- Unit: no DB.
- Integration: test-db + test-redis.
- Test DB: `tmpfs`.
- Nuxt tests: Vitest + `@nuxt/test-utils`.
- CI: same Compose commands.
- Migrations: перед integration tests.
