# Чем контейнер отличается от виртуальной машины?

> [!NOTE]
> Виртуальная машина запускает полноценную гостевую операционную систему со своим ядром, а контейнер запускает изолированный процесс, который использует ядро host OS. Поэтому контейнеры обычно легче, быстрее стартуют и плотнее используют ресурсы.

## Виртуальная машина

VM выглядит так:

```text
hardware
  host OS
    hypervisor
      guest OS
        app
```

У каждой VM есть:

- свое ядро;
- своя операционная система;
- свои системные службы;
- выделенные ресурсы;
- более тяжелый старт.

## Контейнер

Контейнер выглядит так:

```text
hardware
  host OS kernel
    container runtime
      isolated process
```

Контейнер не запускает отдельное ядро ОС. Он использует механизмы изоляции host OS.

## Сравнение

| Критерий | Container | Virtual Machine |
| --- | --- | --- |
| Ядро ОС | Общее с host | Свое guest kernel |
| Старт | Обычно секунды или меньше | Обычно дольше |
| Размер | Меньше | Больше |
| Изоляция | На уровне процессов и namespaces | Сильнее, на уровне ОС |
| Использование ресурсов | Легче | Тяжелее |
| Типичный кейс | Упаковка сервисов | Полная изоляция ОС |

## Почему это важно frontend/backend-разработчику?

Docker позволяет быстро поднять:

- Node.js API;
- PostgreSQL;
- Redis;
- Nginx;
- worker;
- frontend dev server.

Без установки всех этих сервисов напрямую в систему.

## Когда VM все еще нужна?

VM полезна, когда нужна:

- другая ОС с другим kernel;
- сильная изоляция;
- инфраструктура cloud provider;
- запуск Docker Engine внутри отдельной Linux-среды;
- тестирование системного уровня.

В реальности VM и containers часто используются вместе: cloud дает VM, а внутри нее запускаются containers.

## Что отвечать на собеседовании?

Контейнер отличается от виртуальной машины тем, что контейнер не содержит отдельное ядро операционной системы. Он запускает изолированный процесс и использует ядро хоста. VM тяжелее, но дает более полную изоляцию ОС. Контейнеры быстрее стартуют, занимают меньше ресурсов и удобны для упаковки приложений и сервисов.

## Частые ошибки

- Говорить, что контейнер вообще не содержит ОС. В image могут быть userland-файлы Linux-дистрибутива, но не отдельное ядро.
- Считать контейнеры абсолютно безопасными.
- Думать, что Docker заменяет cloud/infrastructure.
- Сравнивать только размер, забывая про модель изоляции.
- Запускать Docker там, где достаточно обычного процесса.

## Мини-шпаргалка

- VM имеет guest OS и kernel.
- Container разделяет host kernel.
- Container легче и быстрее.
- VM изолирует сильнее.
- Docker часто запускается внутри VM в cloud.
- Image может содержать Linux userland, но не kernel.
