# Чем Nitro отличается от Express, NestJS и Nuxt server?

> [!NOTE]
> Nitro ближе к легкому server framework и deployment engine. Express - минимальный middleware framework, NestJS - архитектурный backend framework с DI и decorators, а Nuxt server - практическое использование Nitro внутри Nuxt-приложения.

## Nitro и Express

Express строится вокруг `req`, `res`, `next` и ручной регистрации маршрутов.

```ts
app.get('/api/users', async (req, res) => {
  res.json(await getUsers());
});
```

Nitro чаще строится вокруг file-based routing:

```ts
// server/routes/api/users.get.ts
export default defineHandler(async () => {
  return await getUsers();
});
```

Главное отличие:

- Express живет в Node.js-мире;
- Nitro проектируется как runtime-agnostic server layer;
- Express требует больше ручной сборки инфраструктуры;
- Nitro из коробки дает routing conventions, deployment presets, cache, storage, route rules.

## Nitro и NestJS

NestJS - большой фреймворк с модулями, controllers, providers и dependency injection.

```ts
@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Get()
  findAll() {
    return this.usersService.findAll();
  }
}
```

Nitro не навязывает такую архитектуру:

```ts
// server/routes/api/users.get.ts
export default defineHandler(async () => {
  return userService.findMany();
});
```

В Nitro ты сам выбираешь, как разложить логику:

```txt
server/
  routes/
  utils/
  services/
  repositories/
```

## Nitro и Nuxt server

Nuxt использует Nitro как server engine. Поэтому в Nuxt:

```txt
server/
  api/
  routes/
  middleware/
  plugins/
  utils/
```

Но Nuxt добавляет поверх Nitro свои соглашения:

- auto imports;
- `useRuntimeConfig`;
- `$fetch`;
- SSR context;
- route rules из `nuxt.config.ts`;
- связь с Vue-приложением;
- prerender и rendering modes.

Standalone Nitro не обязан иметь Vue, pages или components.

## Когда выбрать Nitro?

Nitro хорошо выбрать, если:

- проект на Nuxt и нужен backend рядом с frontend;
- нужно легкое TypeScript API;
- важна сборка под serverless/edge;
- API не требует сложного DI и модульной архитектуры;
- много endpoint-ов являются BFF, proxy, webhooks, cached handlers.

## Когда выбрать NestJS?

NestJS обычно уместнее, если:

- проект большой и enterprise-like;
- нужна строгая модульная архитектура;
- много команд, bounded contexts и сложных dependencies;
- нужны guards/interceptors/pipes/decorators как основной стиль;
- много интеграций, очередей, microservices, Swagger-contracts.

## Когда выбрать Express?

Express уместен, если:

- нужен максимально знакомый Node.js server;
- проект уже на Express;
- нужна большая middleware-экосистема;
- portable deployment не является ключевой задачей.

## Мини-шпаргалка

- Express - простой Node.js middleware framework.
- NestJS - архитектурный framework с DI.
- Nitro - легкий server framework и deployment engine.
- Nuxt server - Nitro внутри Nuxt.
- Nitro не запрещает слои `service/repository`, но не заставляет их использовать.
