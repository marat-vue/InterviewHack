# Что делает useContext?

> [!summary]
> `useContext` позволяет компоненту прочитать значение из ближайшего Provider выше по дереву и подписаться на его изменения. Это удобный способ передавать данные глубоко без prop drilling.

## Базовый пример

```jsx
import { createContext, useContext } from 'react'

const ThemeContext = createContext('light')

function Button() {
  const theme = useContext(ThemeContext)

  return <button className={`button-${theme}`}>Сохранить</button>
}
```

Если Provider выше не найден, используется default value из `createContext`.

## Provider

```jsx
function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Button />
    </ThemeContext.Provider>
  )
}
```

`Button` получит `"dark"`.

## Context со state

```jsx
const AuthContext = createContext(null)

function AuthProvider({ children }) {
  const [user, setUser] = useState(null)

  return (
    <AuthContext.Provider value={{ user, setUser }}>
      {children}
    </AuthContext.Provider>
  )
}
```

Компоненты внутри могут читать пользователя:

```jsx
function UserName() {
  const { user } = useContext(AuthContext)
  return <span>{user?.name}</span>
}
```

## Важные правила

- `useContext` ищет ближайший Provider выше компонента.
- Provider внутри того же компонента не влияет на `useContext`, вызванный в этом же компоненте.
- При изменении `value` компоненты-потребители могут перерендериться.
- Context не заменяет все state managers.

## Когда useContext подходит?

- тема;
- текущий пользователь;
- язык;
- настройки;
- dependency injection;
- данные, нужные глубоко в дереве.

## Мини-шпаргалка

- `useContext(SomeContext)` читает ближайший Provider выше.
- Context помогает избежать prop drilling.
- Изменение context value обновляет потребителей.
- Не делай один огромный context для всего.
- Для частых и больших обновлений может понадобиться state manager.
