# Оптимизация длинных списков

> [!summary]
> Длинные списки тормозят не только из-за React, но и из-за браузера: много DOM-узлов, много layout/paint работы, много обработчиков и тяжелый контент. Главный инструмент - виртуализация, а остальные оптимизации помогают убрать лишние render и тяжелые вычисления.

## В чем проблема длинного списка?

```jsx
function ProductList({ products }) {
  return products.map((product) => (
    <ProductCard key={product.id} product={product} />
  ))
}
```

Если `products` содержит 10 000 элементов, React создаст 10 000 React-элементов, а браузер получит огромный DOM. Даже если каждый элемент простой, страница может тормозить при:

- первом render;
- скролле;
- фильтрации;
- изменении state родителя;
- пересчете layout;
- загрузке изображений.

## Главный прием: virtualization

Виртуализация рендерит только видимое окно списка и небольшой запас.

```jsx
import { FixedSizeList } from 'react-window'

function VirtualProducts({ products }) {
  return (
    <FixedSizeList
      height={500}
      width="100%"
      itemCount={products.length}
      itemSize={64}
    >
      {({ index, style }) => (
        <div style={style}>
          {products[index].title}
        </div>
      )}
    </FixedSizeList>
  )
}
```

В DOM будет не 10 000 строк, а примерно столько, сколько помещается на экране.

## Пагинация и бесконечный скролл

Если пользователь не должен видеть все элементы сразу, можно загружать данные порциями.

```jsx
function ProductsPage() {
  const [page, setPage] = useState(1)
  const products = useProducts({ page })

  return (
    <>
      <ProductList products={products} />
      <button onClick={() => setPage(page + 1)}>Load more</button>
    </>
  )
}
```

Пагинация уменьшает и сетевую нагрузку, и объем данных в памяти.

## Стабильные key

Плохой вариант:

```jsx
items.map((item, index) => <Row key={index} item={item} />)
```

Если список сортируется, фильтруется или элементы вставляются в начало, `index` ломает сопоставление. Лучше:

```jsx
items.map((item) => <Row key={item.id} item={item} />)
```

## Мемоизация строк списка

```jsx
const ProductRow = memo(function ProductRow({ product, onSelect }) {
  return <button onClick={() => onSelect(product.id)}>{product.title}</button>
})

function ProductList({ products }) {
  const selectProduct = useCallback((id) => {
    console.log(id)
  }, [])

  return products.map((product) => (
    <ProductRow key={product.id} product={product} onSelect={selectProduct} />
  ))
}
```

Это полезно, если строки тяжелые и props действительно стабильны.

## Фильтрация и ввод

Для поиска по большому списку можно разделить срочное обновление поля и менее срочное обновление списка.

```jsx
function SearchableList({ items }) {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)

  const filtered = useMemo(() => {
    return items.filter((item) => item.title.includes(deferredQuery))
  }, [items, deferredQuery])

  return (
    <>
      <input value={query} onChange={(event) => setQuery(event.target.value)} />
      <ProductList products={filtered} />
    </>
  )
}
```

`input` остается отзывчивым, а список может догонять значение в фоне.

## Мини-шпаргалка

- Для очень длинных списков сначала думай про virtualization.
- Используй стабильный `key`, обычно `id`.
- Пагинация уменьшает объем работы и данных.
- `memo` помогает только при стабильных props.
- `useDeferredValue` полезен для тяжелого UI, зависящего от ввода.
