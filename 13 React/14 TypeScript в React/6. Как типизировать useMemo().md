# Как типизировать useMemo()?

> [!summary]
> `useMemo` почти всегда типизируется автоматически по возвращаемому значению callback. Явный generic нужен редко: для union, `null`, сложных структур, уточнения типа или когда TypeScript выводит слишком широкий/узкий тип.

## Базовый пример

```tsx
const fullName = useMemo(() => {
  return `${user.firstName} ${user.lastName}`
}, [user.firstName, user.lastName])
```

TypeScript понимает, что `fullName` - `string`.

## Массив объектов

```tsx
type Product = {
  id: string
  title: string
  price: number
}

const expensiveProducts = useMemo(() => {
  return products.filter((product) => product.price > 1000)
}, [products])
```

Если `products` уже имеет тип `Product[]`, то результат тоже будет `Product[]`.

## Когда нужен generic?

### Union с null

```tsx
const selectedUser = useMemo<User | null>(() => {
  return users.find((user) => user.id === selectedId) ?? null
}, [users, selectedId])
```

### Map или Set

```tsx
const usersById = useMemo<Map<string, User>>(() => {
  return new Map(users.map((user) => [user.id, user]))
}, [users])
```

### ReactNode

```tsx
const content = useMemo<React.ReactNode>(() => {
  if (status === 'loading') {
    return <Loader />
  }

  if (status === 'error') {
    return 'Something went wrong'
  }

  return <UserList users={users} />
}, [status, users])
```

## useMemo не нужен только ради типов

Плохой пример:

```tsx
const user = useMemo<User>(() => {
  return { id, name }
}, [id, name])
```

Если вычисление дешевое, можно проще:

```tsx
const user: User = { id, name }
```

`useMemo` нужен для производительности и стабильности ссылок, а не для объявления типа.

## useMemo и зависимости

Типизация не спасает от неправильных dependencies:

```tsx
const filteredUsers = useMemo(() => {
  return users.filter((user) => user.name.includes(query))
}, [users])
```

Здесь забыли `query`. Правильно:

```tsx
const filteredUsers = useMemo(() => {
  return users.filter((user) => user.name.includes(query))
}, [users, query])
```

## useMemo vs useCallback

| Хук | Что мемоизирует |
|---|---|
| `useMemo` | значение |
| `useCallback` | функцию |

```tsx
const value = useMemo(() => calculateValue(input), [input])

const callback = useCallback(() => {
  submit(input)
}, [input])
```

## Что отвечать на собеседовании?

`useMemo` типизируется по return value callback. В простых случаях generic не нужен. Явный тип полезен для `T | null`, `Map`, `Set`, `React.ReactNode` или когда нужно уточнить вывод TypeScript. `useMemo` не используют только ради типов.

## Частые ошибки

- Ставить generic там, где TS сам выводит тип.
- Использовать `useMemo` для дешевых вычислений.
- Забывать зависимости.
- Мутировать данные внутри `useMemo`.
- Путать `useMemo` и `useCallback`.

## Мини-шпаргалка

- По умолчанию доверяй выводу типов.
- `useMemo<User | null>(() => ..., deps)`.
- `useMemo<Map<string, User>>(() => ..., deps)`.
- `useMemo` возвращает значение.
- Dependencies важнее ручного generic.
