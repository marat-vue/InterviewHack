# Что такое Cascade Layers (@layer)

> [!summary]
> **Cascade Layers** через `@layer` позволяют явно управлять порядком приоритета групп CSS-правил внутри каскада, уменьшая зависимость от специфичности селекторов.

## Главное

```css
@layer reset, base, components, utilities;

@layer reset {
  * {
    box-sizing: border-box;
  }
}

@layer components {
  .button {
    padding: 8px 12px;
  }
}

@layer utilities {
  .p-0 {
    padding: 0;
  }
}
```

Слои, объявленные позже в списке, имеют больший приоритет.

## Зачем нужны layers

Без layers приходится управлять конфликтами через порядок файлов, специфичность и иногда `!important`. `@layer` дает архитектурный уровень каскада.

```text
reset < base < components < utilities
```

Утилиты могут переопределять компоненты без повышения специфичности.

## Важный нюанс

Правила вне `@layer` обычно имеют больший приоритет, чем правила внутри layers. Поэтому проекту важно договориться, где живут стили.

## Импорт в слой

```css
@import url("./reset.css") layer(reset);
@import url("./components.css") layer(components);
```

Так можно подключать файлы сразу в нужный слой.

## Мини-шпаргалка

- `@layer` управляет приоритетом групп CSS.
- Порядок слоев задают заранее.
- Поздний слой сильнее раннего.
- Layers помогают уменьшить войны специфичности.
- Правила вне слоев могут перебить layered CSS.
- Хорошая схема: reset, base, components, utilities.
