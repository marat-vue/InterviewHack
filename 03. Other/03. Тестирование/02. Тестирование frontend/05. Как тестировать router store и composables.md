# Как тестировать router, store и composables?

> [!summary]
> Router, store и composables тестируют либо изолированно, либо вместе с компонентом. Важно выбрать уровень: composable можно проверить как функцию, Pinia store - как состояние и actions, router - через реальные переходы или mock.

## Как тестировать composable?

Composable без DOM часто тестируется как обычная функция:

```ts
test('toggles value', () => {
  const { isOpen, toggle } = useDisclosure();

  toggle();

  expect(isOpen.value).toBe(true);
});
```

Если composable использует lifecycle hooks, его удобнее тестировать внутри тестового компонента.

## Как тестировать Pinia store?

Для Pinia обычно создают тестовую Pinia:

```ts
import { createPinia, setActivePinia } from 'pinia';

beforeEach(() => {
  setActivePinia(createPinia());
});

test('adds item to cart', () => {
  const cart = useCartStore();

  cart.addItem({ id: 1, price: 100 });

  expect(cart.total).toBe(100);
});
```

## Как тестировать router?

Есть два подхода.

Первый - mock router, если важно проверить вызов:

```ts
const push = vi.fn();

mount(LoginButton, {
  global: {
    mocks: {
      $router: { push },
    },
  },
});
```

Второй - настоящий router, если важно проверить реальный переход:

```ts
const router = createRouter({
  history: createMemoryHistory(),
  routes: [{ path: '/profile', component: ProfilePage }],
});
```

## Как выбрать подход?

- Для простой кнопки "перейти" можно mock.
- Для guards и route params лучше реальный router.
- Для store actions лучше тестировать store отдельно.
- Для компонента, который сильно зависит от store, подключай тестовую Pinia.

## Мини-шпаргалка

- Composables часто тестируются как функции.
- Pinia store тестируют через state, getters и actions.
- Router можно мокать или подключать реально.
- Guards лучше проверять на настоящем router.
- Не смешивай все уровни в одном тесте без необходимости.
