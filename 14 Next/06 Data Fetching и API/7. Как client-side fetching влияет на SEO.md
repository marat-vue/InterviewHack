# Как client-side fetching влияет на SEO?

> [!summary]
> Client-side fetching может ухудшить SEO, если основной контент появляется только после загрузки JavaScript и запроса из браузера. Для индексируемого контента в Next.js лучше использовать Server Components, SSG, SSR или ISR.

## Проблема

Client-only подход:

```tsx
'use client'

useEffect(() => {
  fetch('/api/article')
    .then((res) => res.json())
    .then(setArticle)
}, [])
```

Первый HTML может содержать только loader:

```html
<p>Loading...</p>
```

Поисковику сложнее быстро увидеть основной контент.

## Чем это плохо?

- контент может позже попасть в индекс;
- crawler тратит больше ресурсов;
- social previews могут быть неполными;
- Core Web Vitals могут ухудшиться;
- пользователь видит loading вместо содержания.

## Лучше для SEO

```tsx
export default async function ArticlePage({ params }: Props) {
  const { slug } = await params
  const article = await getArticle(slug)

  return (
    <article>
      <h1>{article.title}</h1>
      <p>{article.description}</p>
    </article>
  )
}
```

Контент появляется в HTML.

## Когда client fetching нормален?

- dashboard после login;
- данные не нужны поисковикам;
- autocomplete;
- фильтр с быстрым refetch;
- пользовательские уведомления;
- analytics widgets;
- infinite scroll после первого серверного блока.

## Что отвечать на собеседовании?

Client-side fetching не всегда вреден, но для SEO-важного контента он хуже серверного рендеринга, потому что основной текст появляется только после JS. В Next.js лучше отдавать индексируемый контент через Server Components, SSR, SSG или ISR, а client fetching оставлять для интерактивных частей.

## Частые ошибки

- Грузить title/description статьи в `useEffect`.
- Думать, что Google всегда идеально выполнит JS.
- Делать Open Graph данные client-only.
- Показывать пустой HTML для карточек товаров.
- Не различать public content и private dashboard.

## Мини-шпаргалка

- SEO-контент лучше на сервере.
- Client fetching подходит для интерактива.
- Metadata должна быть серверной.
- Loader в HTML хуже реального контента.
- Infinite scroll можно комбинировать с серверным первым экраном.
