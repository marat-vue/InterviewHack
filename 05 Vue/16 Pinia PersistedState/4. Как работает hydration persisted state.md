# Как работает hydration persisted state?

> [!summary]
> Hydration persisted state - это восстановление Pinia store из storage при старте приложения. Важно понимать момент восстановления, конфликт с initial state и отличия client-only storage от SSR.

## Что происходит при загрузке?

```txt
1. createPinia()
2. pinia.use(persistedStatePlugin)
3. app.use(pinia)
4. component вызывает useSettingsStore()
5. plugin читает storage
6. store получает сохраненные значения
```

После этого компонент видит уже восстановленный state.

## Initial state vs saved state

```typescript
state: () => ({
  theme: "light",
});
```

Если в storage лежит:

```json
{
  "theme": "dark"
}
```

то после hydration store будет:

```typescript
settings.theme === "dark";
```

## Что если schema store изменилась?

Например, раньше сохранялось:

```json
{
  "theme": "dark"
}
```

а потом ты добавил `language`.

Хорошая практика:

- держать адекватные defaults в `state`;
- сохранять только стабильные поля;
- при сложных изменениях добавлять versioning/migration;
- уметь сбросить storage при несовместимости.

## SSR-нюанс

`localStorage` и `sessionStorage` существуют только в browser. Если проект с SSR, нельзя читать их на server side. Нужны SSR-friendly storages, cookies или client-only логика.

## Мини-шпаргалка

- Hydration восстанавливает store из storage.
- Saved state перекрывает initial state для сохраненных полей.
- Изменение структуры store может потребовать migration.
- Browser storage не существует на server side.
- Для SSR нужно думать отдельно.
