# Чем отличаются HTTP/1.1, HTTP/2 и HTTP/3?

> [!summary]
> HTTP/1.1, HTTP/2 и HTTP/3 решают одну задачу request-response, но по-разному используют соединения. Для frontend важно понимать connection reuse, multiplexing, head-of-line blocking и почему много мелких assets уже не всегда так плохо, как раньше.

## HTTP/1.1

HTTP/1.1 может переиспользовать соединение через keep-alive, но параллелизм ограничен. Браузеры открывали несколько соединений к одному origin, чтобы загружать ресурсы параллельно.

Проблема: много requests может упираться в лимиты соединений.

## HTTP/2

HTTP/2 добавил multiplexing: много requests могут идти по одному TCP connection параллельно.

Это улучшает загрузку страниц с большим количеством assets.

```txt
One TCP connection
  -> request CSS
  -> request JS
  -> request image
  -> responses interleaved
```

## HTTP/3

HTTP/3 работает поверх QUIC, который использует UDP. Он лучше справляется с некоторыми сетевыми проблемами и уменьшает head-of-line blocking на transport layer.

## Что это значит для frontend?

- Domain sharding стал менее полезен.
- Concatenation всех файлов в один bundle уже не всегда обязательна.
- Но размер JavaScript все еще важен.
- Cache и code splitting остаются важными.
- Нужно смотреть реальные метрики, а не оптимизировать по старым правилам.

## Мини-шпаргалка

- HTTP/1.1 ограничен параллелизмом соединений.
- HTTP/2 дает multiplexing поверх TCP.
- HTTP/3 использует QUIC поверх UDP.
- Много маленьких requests менее страшны на HTTP/2/3, но не бесплатны.
- Размер JS и cache strategy все еще критичны.
