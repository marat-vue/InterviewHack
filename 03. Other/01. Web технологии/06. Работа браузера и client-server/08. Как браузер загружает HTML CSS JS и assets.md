# Как браузер загружает HTML, CSS, JS и assets?

> [!summary]
> Browser начинает с HTML, затем находит CSS, JavaScript, images, fonts и другие assets. CSS может блокировать render, scripts могут блокировать parsing, а preload, defer, async, cache и HTTP/2 влияют на скорость загрузки.

## HTML - стартовая точка

```http
GET / HTTP/1.1
Accept: text/html
```

Server возвращает HTML. Browser парсит его сверху вниз и находит дополнительные resources:

```html
<link rel="stylesheet" href="/styles.css" />
<script src="/app.js" defer></script>
<img src="/hero.jpg" alt="" />
```

## CSS

CSS обычно render-blocking: browser должен получить и разобрать styles, чтобы корректно нарисовать страницу.

Поэтому важно:

- не грузить лишний CSS;
- использовать critical CSS, если нужно;
- кешировать CSS;
- избегать огромных blocking stylesheets.

## JavaScript

Обычный script может блокировать HTML parsing:

```html
<script src="/app.js"></script>
```

`defer` загружает script параллельно и выполняет после parsing HTML:

```html
<script src="/app.js" defer></script>
```

`async` загружает script параллельно и выполняет, когда он готов:

```html
<script src="/analytics.js" async></script>
```

## Images и fonts

Images обычно не блокируют parsing, но влияют на LCP и layout shifts. Fonts могут влиять на текстовую отрисовку.

Для важных ресурсов можно использовать:

```html
<link rel="preload" href="/font.woff2" as="font" type="font/woff2" crossorigin />
```

## Cache

Assets с hash в имени можно кешировать долго:

```http
Cache-Control: public, max-age=31536000, immutable
```

HTML обычно кешируют осторожнее, чтобы пользователь получал ссылки на актуальные assets.

## Мини-шпаргалка

- HTML запускает загрузку остальных resources.
- CSS часто render-blocking.
- Обычный script может блокировать parsing.
- `defer` обычно хорош для app scripts.
- `async` подходит для независимых scripts.
- Hashed assets можно кешировать долго.
