# Чеклист production Nitro приложения

> [!NOTE]
> Production readiness для Nitro - это проверка runtime, config, database, auth, cache, security, observability, tests и deployment. Чеклист полезен перед релизом и перед собеседованием как системная картина backend-подготовки.

## Runtime и deploy

- выбран правильный `NITRO_PRESET`;
- `.output` запускается локально через preview/start;
- `PORT`/`HOST` настроены;
- healthcheck endpoint есть;
- reverse proxy/CDN настроен;
- HTTPS терминируется корректно;
- WebSocket/tasks поддерживаются выбранной платформой;
- env variables заданы в platform secrets.

## Config и secrets

- secrets не лежат в repository;
- `.env` не коммитится;
- `.env.example` обновлен;
- `runtimeConfig.public` не содержит secrets;
- `BETTER_AUTH_SECRET` задан;
- `BETTER_AUTH_URL` production URL;
- OAuth client secrets заданы;
- Redis/database URLs заданы.

## Database и Prisma

- `prisma generate` выполняется в build;
- migrations закоммичены;
- production применяет `prisma migrate deploy`;
- database backup есть;
- connection pooling настроен;
- indexes проверены;
- slow queries мониторятся;
- seed не запускается случайно на production.

## Auth и security

- Better Auth catch-all route работает;
- auth schema применена;
- cookies `HttpOnly`, `Secure`, правильный `SameSite`;
- trusted origins настроены;
- CORS не permissive без причины;
- auth endpoints rate-limited;
- password reset/email verification настроены;
- protected routes используют `requireAuth`;
- admin routes используют `requireRole`/permissions;
- webhook signatures проверяются.

## Nitro API

- request body size ограничен;
- validation есть на body/query/params;
- route errors мапятся в понятные HTTP status;
- private routes не кешируются;
- routeRules review сделан;
- redirects защищены от open redirect;
- proxy защищен от SSRF;
- headers не раскрывают secrets.

## Cache/storage

- cache strategy описана;
- user-specific data не кешируется глобально;
- multi-instance cache вынесен во внешний storage;
- Redis/storage credentials заданы;
- invalidation понятна;
- storage keys имеют prefix;
- TTL настроен.

## Observability

- request id есть;
- structured logs есть;
- error reporting подключен;
- latency/status metrics есть;
- database errors логируются без secrets;
- auth failures логируются безопасно;
- external API failures видны;
- alerts настроены.

## Tests

- unit tests для services/permissions/validation;
- integration tests для Prisma repositories;
- auth guard tests;
- API e2e tests через `@nuxt/test-utils`;
- coverage threshold разумный;
- CI использует test database;
- tests не зависят от порядка;
- mocks/env очищаются после tests.

## Мини-шпаргалка

- Production Nitro начинается с правильного preset и env.
- Prisma требует migrations и pooling.
- Better Auth требует secret, URL, cookies, CORS, rate limit.
- Cache требует external storage для multi-instance.
- Tests должны покрывать не только happy path, но и auth/errors.
- Logs и metrics нужны до первого production incident.
