# Как устроена структура Nitro проекта?

> [!NOTE]
> В Nitro структура строится вокруг server directory. Внутри нее лежат routes, middleware, plugins, utils, tasks и другие server-only файлы. В Nuxt эта же идея выражена через директорию `server/`.

## Базовая структура standalone Nitro

```txt
project/
  nitro.config.ts
  vite.config.ts
  package.json
  server/
    routes/
      api/
        health.get.ts
    middleware/
      01.logger.ts
      02.auth.ts
    plugins/
      db.ts
    utils/
      prisma.ts
      auth.ts
    tasks/
      db/
        seed.ts
```

## Базовая структура Nuxt + Nitro

```txt
nuxt-app/
  nuxt.config.ts
  server/
    api/
      users.get.ts
      users.post.ts
      users/
        [id].get.ts
    routes/
      sitemap.xml.ts
    middleware/
      01.logger.ts
      02.auth.ts
    plugins/
      prisma.ts
    utils/
      prisma.ts
      auth.ts
```

## Что класть в `routes/`?

`routes/` - это обычные server routes. В standalone Nitro `routes/api/test.ts` станет `/api/test`.

```ts
// server/routes/hello.get.ts
export default defineHandler(() => 'Hello');
```

## Что класть в `api/`?

В Nuxt `server/api` - удобная директория для API endpoints. Файл:

```txt
server/api/users.get.ts
```

создает endpoint:

```txt
GET /api/users
```

## Что класть в `middleware/`?

Middleware выполняется до route handler.

```ts
// server/middleware/01.logger.ts
export default defineEventHandler((event) => {
  console.log(event.method, event.path);
});
```

Middleware полезны для:

- request id;
- logging;
- CORS;
- простых auth-checks;
- добавления данных в `event.context`;
- раннего reject запроса.

## Что класть в `plugins/`?

Plugins выполняются при старте Nitro runtime и позволяют расширить server behavior.

```ts
// server/plugins/db.ts
export default definePlugin(() => {
  console.log('Nitro server started');
});
```

В plugins удобно инициализировать:

- database client;
- metrics;
- hooks;
- external SDK;
- background integrations.

## Что класть в `utils/`?

`utils/` - место для server-only helpers.

```ts
// server/utils/prisma.ts
import { PrismaClient } from '@prisma/client';

export const prisma = new PrismaClient();
```

В Nuxt server utils обычно auto-imported в server code. В standalone Nitro чаще используют явные imports.

## Что класть в `tasks/`?

`tasks/` - экспериментальный Nitro API для одноразовых runtime operations:

```ts
// server/tasks/db/seed.ts
export default defineTask({
  meta: {
    name: 'db:seed',
    description: 'Seed database',
  },
  async run() {
    return {
      result: 'ok',
    };
  },
});
```

## Мини-шпаргалка

- `routes/` - server routes.
- `api/` в Nuxt - API routes с префиксом `/api`.
- `middleware/` - код до handler.
- `plugins/` - runtime initialization.
- `utils/` - server helpers.
- `tasks/` - runtime tasks.
- Бизнес-логику лучше выносить из handlers в `services/` или `repositories/`.
