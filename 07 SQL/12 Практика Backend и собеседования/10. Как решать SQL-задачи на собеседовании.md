# Как решать SQL-задачи на собеседовании?

> [!summary]
> SQL-задачи на собеседовании лучше решать по шагам: понять таблицы и связи, определить нужную гранулярность результата, выбрать join или exists, добавить фильтры, агрегации, оконные функции и только потом думать об оптимизации.

## Шаг 1. Понять результат

Сначала спроси себя: одна строка результата означает что?

- один пользователь;
- один заказ;
- один день;
- одна категория;
- одна пара пользователь-товар.

Это называется гранулярность результата.

## Шаг 2. Определить связи

Проверь:

- primary key;
- foreign key;
- one-to-many;
- many-to-many;
- нужны ли строки без совпадений.

## Шаг 3. Выбрать паттерн

| Задача | Частый паттерн |
|---|---|
| есть связанные строки | `EXISTS` |
| нет связанных строк | `NOT EXISTS` |
| посчитать по группам | `GROUP BY` |
| последняя строка в группе | `ROW_NUMBER` |
| накопительная сумма | window `SUM` |
| топ N в группе | `ROW_NUMBER` + CTE |

## Шаг 4. Проверить edge cases

- `NULL`;
- дубли после join;
- пользователи без заказов;
- одинаковые даты;
- пустой результат;
- ties в рейтинге.

## Мини-шпаргалка

- Начинай с гранулярности результата.
- Не ставь `DISTINCT`, пока не понял источник дублей.
- Для existence-задач часто нужен `EXISTS`.
- Для top per group часто нужна оконная функция.
- Всегда проговаривай edge cases.
