# Как считать накопительную сумму?

> [!NOTE]
> Накопительная сумма считается оконной функцией `SUM(...) OVER` с сортировкой и frame от начала окна до текущей строки.

## Пример по всем заказам

```sql
SELECT
  created_at,
  total,
  SUM(total) OVER (
    ORDER BY created_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_total
FROM orders
ORDER BY created_at;
```

## По каждому пользователю

```sql
SELECT
  user_id,
  created_at,
  total,
  SUM(total) OVER (
    PARTITION BY user_id
    ORDER BY created_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS user_running_total
FROM orders;
```

## Зачем явный frame?

В разных СУБД поведение frame по умолчанию может давать неожиданные результаты, особенно при одинаковых значениях `ORDER BY`. Явный `ROWS` делает намерение понятнее.

## Мини-шпаргалка

- Running total считается через оконный `SUM`.
- Нужен `ORDER BY`.
- Для групп добавь `PARTITION BY`.
- Явный frame повышает читаемость.
- При одинаковых датах добавляй второе поле сортировки, например `id`.
