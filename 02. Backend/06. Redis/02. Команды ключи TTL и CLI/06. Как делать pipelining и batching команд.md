# Как делать pipelining и batching команд?

> [!NOTE]
> Pipelining уменьшает количество network round trips. Это один из главных способов ускорить пачку Redis-команд из Node.js, особенно если приложение и Redis находятся на разных машинах.

## Что такое round trip?

Без pipelining:

```txt
client -> SET a -> Redis -> response
client -> SET b -> Redis -> response
client -> SET c -> Redis -> response
```

С pipelining:

```txt
client -> SET a, SET b, SET c -> Redis -> responses
```

Redis все равно выполнит команды по порядку, но клиент меньше ждет сеть.

## Как node-redis делает auto-pipelining?

В `node-redis` команды, выполненные в один tick event loop, могут быть автоматически сгруппированы. Поэтому полезно использовать `Promise.all`:

```ts
await Promise.all([
  redis.set('user:1:name', 'Marat'),
  redis.set('user:1:role', 'admin'),
  redis.set('user:1:theme', 'dark'),
]);
```

## Когда нужен ручной batching?

Ручной batching нужен, когда:

- нужно записать много ключей;
- нужно прогреть cache;
- нужно удалить пачку keys после `SCAN`;
- нужно массово обновить TTL;
- нужно ограничить нагрузку batch size.

Пример с batch size:

```ts
const keys = ['a', 'b', 'c'];

for (let i = 0; i < keys.length; i += 100) {
  const batch = keys.slice(i, i + 100);

  await Promise.all(
    batch.map((key) => redis.expire(key, 60 * 10)),
  );
}
```

## Чем pipeline отличается от transaction?

| Механизм | Что дает |
|---|---|
| Pipeline | меньше network round trips |
| Transaction `MULTI/EXEC` | команды выполняются как очередь без вмешательства других команд |
| Lua script | сложная логика атомарно на сервере |

Pipeline не делает команды атомарной бизнес-операцией. Он только эффективнее отправляет их.

## Чем опасны огромные pipeline?

Если отправить сотни тысяч команд сразу:

- вырастет memory в клиенте;
- вырастет memory в Redis output buffers;
- появятся latency spikes;
- сложнее обработать partial failure.

Лучше делать batch-и.

## Мини-шпаргалка

- Pipelining уменьшает network overhead.
- `Promise.all` в node-redis помогает сгруппировать команды.
- Pipeline не равен transaction.
- Огромные pipeline дроби на batch-и.
- Для атомарной сложной логики выбирай Lua или transactions.
