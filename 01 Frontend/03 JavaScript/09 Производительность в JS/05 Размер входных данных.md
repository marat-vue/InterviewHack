# Размер входных данных

> [!NOTE] Коротко
> Чем больше входных данных, тем важнее сложность алгоритма, объем памяти и способ обработки.

## Вопрос

Как размер входных данных влияет на производительность?

## Определение

Один и тот же код может быть быстрым на 100 элементах и слишком медленным на 100 000. Поэтому производительность нужно оценивать не только по операции, но и по размеру данных.

## Пример

```javascript
const users = getUsers();

const activeUsers = users.filter((user) => user.isActive);
```

Для небольшого массива это мгновенно. Для огромного массива фильтрация может стать заметной задачей в main thread.

## Сложность важнее микроправок

```javascript
const result = users.filter((user) => selectedIds.includes(user.id));
```

Если `users` и `selectedIds` большие, `includes` внутри `filter` дает много лишнего поиска.

Лучше:

```javascript
const selectedIdsSet = new Set(selectedIds);
const result = users.filter((user) => selectedIdsSet.has(user.id));
```

Проверка через `Set.has()` обычно лучше масштабируется.

## Что учитывать

- количество элементов;
- глубину вложенности объектов;
- размер строк и JSON;
- количество DOM-узлов;
- частоту повторения операции;
- память под промежуточные структуры.

## Мини-шпаргалка

```text
small data -> readability first
large data -> algorithm, memory, batching, profiling
```
