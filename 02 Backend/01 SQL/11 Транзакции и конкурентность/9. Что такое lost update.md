# Что такое lost update?

> [!summary]
> Lost update - конкурентная аномалия, когда две транзакции читают одно значение, обе вычисляют новое значение и одна запись перетирает результат другой.

## Пример

Баланс равен `100`.

```txt
T1 читает balance = 100
T2 читает balance = 100
T1 записывает 100 + 10 = 110
T2 записывает 100 + 20 = 120
```

Ожидали `130`, получили `120`. Обновление T1 потерялось.

## Опасный паттерн

```js
const balance = await getBalance(accountId);
await setBalance(accountId, balance + 10);
```

Между чтением и записью другая транзакция может изменить значение.

## Лучше атомарный UPDATE

```sql
UPDATE accounts
SET balance = balance + 10
WHERE id = 1;
```

База выполнит изменение как одну операцию с нужными блокировками.

## Другие решения

- `SELECT ... FOR UPDATE`;
- optimistic locking через `version`;
- более строгий isolation level;
- retry конфликтующих транзакций.

## Мини-шпаргалка

- Lost update теряет одно из параллельных изменений.
- Read-modify-write в приложении опасен.
- Атомарный `UPDATE field = field + value` часто лучше.
- Для сложной логики используй locks или optimistic locking.
- Конфликтующие транзакции должны уметь retry.
