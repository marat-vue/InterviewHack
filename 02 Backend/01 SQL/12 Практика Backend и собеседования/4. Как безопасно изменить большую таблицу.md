# Как безопасно изменить большую таблицу?

> [!summary]
> Большие production-таблицы нельзя менять так же беспечно, как локальную базу. Нужно учитывать блокировки, длительность миграции, совместимость старого и нового кода, backfill и возможность отката.

## Опасный подход

```sql
ALTER TABLE users
ADD COLUMN country text NOT NULL DEFAULT 'US';
```

В зависимости от СУБД и версии такое изменение может надолго заблокировать таблицу или переписать много данных.

## Более безопасный подход

1. Добавить nullable-колонку.
2. Деплоить код, который умеет работать с `NULL`.
3. Заполнить данные батчами.
4. Добавить constraint.
5. Удалить старую логику позже.

## Backfill батчами

```sql
UPDATE users
SET country = 'US'
WHERE country IS NULL
  AND id BETWEEN 1 AND 10000;
```

## Индексы

Создание индекса на большой таблице может блокировать запись. В PostgreSQL для этого часто используют `CREATE INDEX CONCURRENTLY`.

## Мини-шпаргалка

- Большие таблицы меняют поэтапно.
- Избегай долгих блокировок.
- Backfill делай батчами.
- Код и схема должны быть совместимы во время деплоя.
- Проверяй особенности своей СУБД.
