# Как работают ACL users, permissions и command categories?

> [!NOTE]
> ACL в Redis позволяет создать пользователей с разными правами: какие команды разрешены, какие keys доступны, нужен ли password, можно ли Pub/Sub channels. Это лучше, чем один общий admin password.

## Что такое ACL user?

Redis user может иметь:

- username;
- password;
- enabled/disabled state;
- command permissions;
- key patterns;
- channel patterns.

Пример идеи:

```redis
ACL SETUSER api on >strong_password ~prod:api:* +@read +@write -FLUSHALL -CONFIG
```

## Key patterns

```redis
~prod:api:*
```

Так user может работать только с ключами приложения.

Для background worker:

```redis
~prod:api:queue:* ~prod:api:stream:*
```

## Command categories

Redis группирует команды в categories:

```txt
@read
@write
@admin
@dangerous
@pubsub
@stream
```

Пример:

```redis
ACL SETUSER readonly on >password ~prod:api:* +@read -@write
```

## Запрет dangerous commands

```redis
ACL SETUSER api -FLUSHALL -FLUSHDB -CONFIG -SHUTDOWN
```

Даже если у приложения есть write-доступ, ему почти никогда не нужен `CONFIG` или `FLUSHALL`.

## Как посмотреть ACL?

```redis
ACL LIST
ACL GETUSER api
WHOAMI
```

## Как подключиться с user?

```bash
REDIS_URL="redis://api:strong_password@redis.internal:6379"
```

## Практическая модель пользователей

| User | Права |
|---|---|
| `api` | read/write только app keys |
| `worker` | streams/queues + needed writes |
| `readonly` | read-only diagnostics |
| `admin` | admin только для операторов |

## Мини-шпаргалка

- ACL ограничивает users, commands, keys и channels.
- Используй key patterns: `~prod:api:*`.
- Не давай app user dangerous/admin commands.
- Разделяй API, workers и readonly users.
- Проверяй права через `ACL GETUSER`.
