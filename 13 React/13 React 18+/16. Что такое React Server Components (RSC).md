# Что такое React Server Components (RSC)?

> [!summary]
> React Server Components - это модель компонентов, в которой часть React-дерева выполняется в серверной среде и не попадает в клиентский JavaScript bundle. RSC позволяют читать данные ближе к источнику, уменьшать клиентский JS и смешивать серверный контент с интерактивными Client Components.

## Главная идея

Обычный React-компонент часто попадает в браузер:

```jsx
function ProductList() {
  const [products, setProducts] = useState([])

  useEffect(() => {
    fetch('/api/products').then((res) => res.json()).then(setProducts)
  }, [])

  return <Products products={products} />
}
```

Server Component выполняется на сервере:

```jsx
async function ProductList() {
  const products = await db.product.findMany()

  return <Products products={products} />
}
```

Код `ProductList` не нужен в браузере, потому что он не интерактивный. Клиент получает результат серверной работы в специальном RSC payload, а не исходный код компонента.

## Server Component и Client Component

В RSC-совместимых фреймворках компоненты часто являются серверными по умолчанию. Если компоненту нужна интерактивность, ставят директиву:

```jsx
'use client'

import { useState } from 'react'

export function LikeButton() {
  const [liked, setLiked] = useState(false)

  return (
    <button onClick={() => setLiked((value) => !value)}>
      {liked ? 'Liked' : 'Like'}
    </button>
  )
}
```

Server Component может рендерить Client Component:

```jsx
async function ProductPage({ productId }) {
  const product = await db.product.findUnique({ where: { id: productId } })

  return (
    <article>
      <h1>{product.title}</h1>
      <p>{product.description}</p>
      <LikeButton productId={product.id} />
    </article>
  )
}
```

## Чем RSC отличается от SSR?

| Вопрос | SSR | RSC |
|---|---|---|
| Что делает сервер | генерирует HTML | выполняет Server Components и формирует RSC payload |
| Нужна ли hydration | да, для клиентского React-дерева | только для Client Components |
| Едет ли код компонента в браузер | обычно да | Server Component code не едет |
| Можно ли читать БД в компоненте | только через серверный слой/framework | да, в Server Component |
| Цель | быстрее показать HTML | уменьшить клиентский JS и перенести работу на сервер |

SSR и RSC не конкуренты. Во фреймворках они часто работают вместе: RSC готовит серверную часть дерева, SSR превращает результат в HTML, а клиент гидратирует интерактивные части.

## Что можно делать в Server Components?

Можно:

- читать файлы;
- ходить в базу данных;
- использовать server-only SDK;
- читать секреты из env;
- делать `await`;
- импортировать тяжелые библиотеки, которые не должны попадать в browser bundle.

```jsx
async function AdminStats() {
  const stats = await analyticsClient.getDashboardStats()

  return <StatsView stats={stats} />
}
```

Нельзя:

- использовать `useState`;
- использовать `useEffect`;
- вешать `onClick`;
- читать `window`;
- читать `localStorage`;
- использовать browser-only API.

## Что можно передавать в Client Component?

Props через границу server-to-client должны быть сериализуемыми.

Хорошо:

```jsx
<LikeButton productId={product.id} initialLikes={product.likes} />
```

Плохо:

```jsx
<ClientWidget db={db} />
<ClientWidget onSave={() => saveToDatabase()} />
```

Функции через границу можно передавать только в специальных случаях, например как Server Functions/Actions при поддержке фреймворка.

## Нужен ли фреймворк?

Да, почти всегда. RSC - не просто "импорт из React". Нужна интеграция сборщика, сервера, роутера и протокола передачи RSC payload.

На практике RSC используют через:

- Next.js App Router;
- Remix/React Router framework modes с поддержкой server features;
- другие RSC-aware фреймворки и сборочные решения.

В обычном Vite SPA без RSC-интеграции Server Components сами по себе не заработают.

## Что отвечать на собеседовании?

React Server Components - это компоненты, которые выполняются в серверной среде и не отправляют свой код в браузер. Они помогают уменьшить JS bundle, читать данные на сервере и безопасно использовать server-only ресурсы. Для интерактивности используется граница `'use client'`, а SSR и RSC могут работать вместе.

## Частые ошибки

- Называть RSC просто новым видом SSR.
- Использовать `useState` или `useEffect` в Server Component.
- Передавать несериализуемые props в Client Component.
- Думать, что RSC работает в любом React SPA без фреймворка.
- Ставить `'use client'` слишком высоко и случайно переносить много кода в browser bundle.

## Мини-шпаргалка

- Server Components выполняются на сервере.
- Их код не попадает в клиентский bundle.
- Client Components нужны для интерактивности.
- `'use client'` задает границу клиента.
- Props через границу должны быть сериализуемыми.
- RSC обычно требует фреймворк.
