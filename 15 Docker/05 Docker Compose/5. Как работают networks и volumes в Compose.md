# Как работают networks и volumes в Compose?

> [!summary]
> Compose автоматически создает default network для services и позволяет объявлять named volumes на верхнем уровне. Services общаются по DNS-именам, а volumes сохраняют данные независимо от containers.

## Default network

Если networks не указаны:

```yaml
services:
  api:
    build: .
  db:
    image: postgres:18
```

Compose создаст default network проекта. `api` сможет обратиться к базе по имени:

```text
db:5432
```

## Custom networks

```yaml
services:
  nginx:
    image: nginx:alpine
    networks:
      - frontend
      - backend

  api:
    build: .
    networks:
      - backend

  db:
    image: postgres:18
    networks:
      - backend

networks:
  frontend:
  backend:
```

Так можно сделать Nginx видимым снаружи, а базу оставить во внутренней сети.

## Named volumes

```yaml
services:
  db:
    image: postgres:18
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

Top-level `volumes` объявляет named volume, а service монтирует его в нужную папку.

## Bind mounts в Compose

```yaml
services:
  api:
    build: .
    volumes:
      - .:/app
```

Это полезно в dev, чтобы изменения кода на host были видны внутри container.

## External resources

Если network или volume уже создан вне Compose:

```yaml
volumes:
  pgdata:
    external: true
```

Compose не будет создавать этот volume, а попробует использовать существующий.

## Удаление

```bash
docker compose down
```

Обычно удаляет containers и network, но не named volumes.

```bash
docker compose down -v
```

Удаляет и volumes проекта. Осторожно: можно потерять базу.

## Что отвечать на собеседовании?

Compose создает default network, в которой services доступны друг другу по service name. Для более сложной архитектуры можно объявлять custom networks и разделять публичные и внутренние services. Volumes объявляются в top-level `volumes` и монтируются в services; они нужны для данных, которые должны переживать пересоздание containers.

## Частые ошибки

- Подключаться к `localhost` вместо service name.
- Не объявлять named volume в top-level `volumes`.
- Делать `down -v` и удалять данные.
- Публиковать database наружу вместо внутренней network.
- Не отделять frontend/proxy network от backend/database network.

## Мини-шпаргалка

- Compose создает default network.
- Service name - DNS name.
- Top-level `volumes` объявляет named volumes.
- `down` не удаляет named volumes.
- `down -v` удаляет volumes.
- Custom networks помогают изолировать services.
