# Как работает useStorage и KV storage в Nitro?

> [!NOTE]
> `useStorage()` - runtime-agnostic KV storage в Nitro, построенный на `unstorage`. Он абстрагирует filesystem, memory, Redis и другие drivers, чтобы один код работал в разных runtime.

## Зачем нужен storage?

Storage нужен для:

- cache;
- feature flags;
- временных данных;
- rate limit counters;
- generated files metadata;
- small key-value data;
- adapter-friendly persistence.

Это не полноценная замена relational database. Для доменных данных чаще используют Prisma/SQL.

## Минимальное использование

```ts
import { useStorage } from 'nitro/storage';

export default defineHandler(async () => {
  await useStorage().setItem('test:foo', {
    hello: 'world',
  });

  const value = await useStorage().getItem('test:foo');

  return value;
});
```

## Base prefix

```ts
const sessions = useStorage('sessions');

await sessions.setItem('abc', {
  userId: '1',
});

const session = await sessions.getItem('abc');
```

Base prefix помогает разделять storage domains:

```txt
cache
sessions
rate-limit
uploads
features
```

## Методы useStorage

| Метод | Что делает |
|---|---|
| `getItem(key)` | получает значение или `null` |
| `getItems(items)` | получает несколько значений |
| `getItemRaw(key)` | получает raw/binary значение без parsing |
| `setItem(key, value)` | записывает значение |
| `setItems(items)` | записывает несколько значений |
| `setItemRaw(key, value)` | записывает raw/binary значение |
| `hasItem(key)` | проверяет наличие key |
| `removeItem(key)` | удаляет key |
| `getKeys(base?)` | возвращает keys, optionally by prefix |
| `clear(base?)` | очищает storage или prefix |
| `getMeta(key)` | получает metadata |
| `setMeta(key, meta)` | записывает metadata |
| `removeMeta(key)` | удаляет metadata |
| `mount(base, driver)` | динамически монтирует driver |
| `unmount(base)` | демонтирует driver |
| `watch(callback)` | следит за изменениями |
| `unwatch()` | отключает watcher |

Shorthand aliases тоже встречаются: `get`, `set`, `has`, `del`, `remove`, `keys`.

## Типизация

```ts
type FeatureFlags = {
  betaDashboard: boolean;
};

const flags = await useStorage<FeatureFlags>('features').getItem('tenant-1');
```

Или:

```ts
const flags = await useStorage('features').getItem<FeatureFlags>('tenant-1');
```

## Настройка driver

```ts
export default defineConfig({
  storage: {
    redis: {
      driver: 'redis',
      url: process.env.REDIS_URL,
    },
  },
});
```

Использование:

```ts
await useStorage('redis').setItem('foo', 'bar');
```

## `devStorage`

Если production storage недоступен локально:

```ts
export default defineConfig({
  storage: {
    db: {
      driver: 'redis',
      url: process.env.REDIS_URL,
    },
  },
  devStorage: {
    db: {
      driver: 'fs',
      base: './.data/db',
    },
  },
});
```

## Мини-шпаргалка

- `useStorage()` - key-value storage abstraction.
- `useStorage('base')` - storage с prefix/mount.
- Для cache Nitro использует mount point `cache`.
- Для production лучше выбрать persistent shared driver.
- Storage не заменяет SQL/Prisma для доменной модели.
- Не храни секреты в storage без threat model и encryption.
