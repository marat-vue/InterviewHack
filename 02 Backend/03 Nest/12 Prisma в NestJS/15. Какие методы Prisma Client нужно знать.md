# Какие методы Prisma Client нужно знать?

> [!summary]
> Prisma Client генерирует методы для каждой модели. Важно понимать не только список методов, но и сценарии: когда использовать `findUnique`, когда `findFirst`, чем `update` отличается от `updateMany`, зачем нужны `aggregate`, `groupBy`, `$transaction` и raw queries.

## Как выглядит Prisma Client?

Если в schema есть модель:

```prisma
model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  name  String?
}
```

Prisma сгенерирует namespace `prisma.user`:

```ts
this.prisma.user.findMany();
this.prisma.user.create();
this.prisma.user.update();
this.prisma.user.delete();
```

Название свойства обычно совпадает с именем модели в lower camel case: `UserProfile` -> `this.prisma.userProfile`.

## Методы чтения

| Метод | Когда использовать | Что возвращает |
|---|---|---|
| `findUnique` | поиск по unique полю | объект или `null` |
| `findUniqueOrThrow` | unique-поиск, где отсутствие записи считается ошибкой | объект или exception |
| `findFirst` | первая запись по обычному фильтру | объект или `null` |
| `findFirstOrThrow` | первая запись, но отсутствие записи - ошибка | объект или exception |
| `findMany` | список записей | массив |

## findUnique

```ts
const user = await this.prisma.user.findUnique({
  where: { email: 'anna@example.com' },
});
```

`findUnique` принимает только уникальный критерий: `id`, `email`, `slug` или compound unique.

```prisma
model Like {
  userId Int
  postId Int

  @@id([userId, postId])
}
```

```ts
const like = await this.prisma.like.findUnique({
  where: {
    userId_postId: {
      userId: 1,
      postId: 10,
    },
  },
});
```

## findFirst

```ts
const newestAdmin = await this.prisma.user.findFirst({
  where: { role: 'ADMIN' },
  orderBy: { createdAt: 'desc' },
});
```

`findFirst` нужен, когда фильтр не уникальный. Без `orderBy` результат может быть логически неустойчивым: база вернет первую подходящую запись, но "первая" не всегда означает нужную.

## findMany

```ts
const users = await this.prisma.user.findMany({
  where: {
    email: { contains: '@company.com' },
  },
  orderBy: { createdAt: 'desc' },
  skip: 0,
  take: 20,
  select: {
    id: true,
    email: true,
  },
});
```

`findMany` - главный метод для списков, фильтров, пагинации и админских таблиц.

## Методы создания

| Метод | Когда использовать |
|---|---|
| `create` | создать одну запись |
| `createMany` | массово создать записи |
| `createManyAndReturn` | создать несколько записей и вернуть созданные строки, если это поддерживает connector |

```ts
const user = await this.prisma.user.create({
  data: {
    email: 'anna@example.com',
    name: 'Anna',
  },
});
```

```ts
await this.prisma.user.createMany({
  data: [
    { email: 'a@example.com' },
    { email: 'b@example.com' },
  ],
  skipDuplicates: true,
});
```

`createMany` обычно быстрее, чем цикл из многих `create`, потому что Prisma может отправить более компактный запрос в базу.

## Методы обновления

| Метод | Когда использовать |
|---|---|
| `update` | обновить одну запись по unique field |
| `updateMany` | обновить все записи по фильтру |
| `upsert` | создать запись, если ее нет, иначе обновить |

```ts
const user = await this.prisma.user.update({
  where: { id: 1 },
  data: { name: 'Ann' },
});
```

Если записи нет, `update` выбросит ошибку. Поэтому для публичного API часто сначала делают `findUnique` или ловят Prisma error и превращают ее в `NotFoundException`.

```ts
await this.prisma.post.updateMany({
  where: {
    authorId: 1,
    published: false,
  },
  data: {
    published: true,
  },
});
```

`updateMany` возвращает количество измененных записей, а не массив сущностей.

## Upsert

```ts
await this.prisma.user.upsert({
  where: { email: 'anna@example.com' },
  update: { name: 'Anna Updated' },
  create: {
    email: 'anna@example.com',
    name: 'Anna',
  },
});
```

`upsert` полезен для idempotent операций: синхронизация профиля, импорт справочников, создание настроек по умолчанию.

## Методы удаления

```ts
await this.prisma.user.delete({
  where: { id: 1 },
});
```

`delete` удаляет одну запись по unique field. Если записи нет, будет ошибка.

```ts
await this.prisma.session.deleteMany({
  where: {
    expiresAt: { lt: new Date() },
  },
});
```

`deleteMany` удаляет все записи по фильтру и возвращает `{ count }`.

## Count, aggregate и groupBy

```ts
const count = await this.prisma.user.count({
  where: { role: 'ADMIN' },
});
```

`count` нужен для pagination metadata:

```ts
const [items, total] = await this.prisma.$transaction([
  this.prisma.user.findMany({ skip, take }),
  this.prisma.user.count(),
]);
```

`aggregate` считает значения по колонкам:

```ts
const stats = await this.prisma.order.aggregate({
  where: { status: 'PAID' },
  _sum: { total: true },
  _avg: { total: true },
  _max: { createdAt: true },
});
```

`groupBy` группирует строки:

```ts
const result = await this.prisma.order.groupBy({
  by: ['status'],
  _count: { _all: true },
  _sum: { total: true },
});
```

На собеседовании важно сказать: `groupBy` - это аналог SQL `GROUP BY`, а `aggregate` - агрегаты без группировки.

## Relation queries

```ts
const users = await this.prisma.user.findMany({
  include: {
    posts: {
      where: { published: true },
      select: {
        id: true,
        title: true,
      },
    },
  },
});
```

Для фильтрации по связям:

```ts
const users = await this.prisma.user.findMany({
  where: {
    posts: {
      some: {
        published: true,
      },
    },
  },
});
```

## Nested writes

```ts
await this.prisma.user.create({
  data: {
    email: 'anna@example.com',
    posts: {
      create: [
        { title: 'First post' },
        { title: 'Second post' },
      ],
    },
  },
});
```

Nested writes позволяют создать или изменить связанную структуру одним запросом Prisma Client. Это удобно для операций, которые должны быть атомарными.

## Transactions

```ts
const [user, profile] = await this.prisma.$transaction([
  this.prisma.user.create({ data: { email: 'a@example.com' } }),
  this.prisma.profile.create({ data: { bio: 'Hello', userId: 1 } }),
]);
```

Для зависимых операций удобнее interactive transaction:

```ts
await this.prisma.$transaction(async (tx) => {
  const order = await tx.order.create({
    data: { customerId: 1, total: 100 },
  });

  await tx.auditLog.create({
    data: {
      action: 'ORDER_CREATED',
      entityId: order.id,
    },
  });
});
```

## Raw queries

```ts
const rows = await this.prisma.$queryRaw`
  SELECT id, email
  FROM "User"
  WHERE email LIKE ${'%@example.com'}
`;
```

`$queryRaw` используют, когда Prisma API не хватает: сложные database-specific запросы, CTE, window functions, особые индексы. Значения нужно передавать через template placeholders, а не склеивать строки руками.

```ts
await this.prisma.$executeRaw`
  UPDATE "Session"
  SET "revoked" = true
  WHERE "expiresAt" < NOW()
`;
```

`$executeRaw` используют для команд, которые не возвращают строки.

## Как выбрать метод?

| Задача | Метод |
|---|---|
| Получить пользователя по id | `findUnique` |
| Получить последнюю опубликованную статью | `findFirst` + `orderBy` |
| Получить страницу пользователей | `findMany` + `skip/take` или `cursor` |
| Создать пользователя | `create` |
| Импортировать много строк | `createMany` |
| Обновить одну запись | `update` |
| Массово изменить записи | `updateMany` |
| Создать или обновить по unique field | `upsert` |
| Удалить одну запись | `delete` |
| Удалить пачку записей | `deleteMany` |
| Посчитать записи | `count` |
| Посчитать сумму/среднее | `aggregate` |
| Сгруппировать статистику | `groupBy` |
| Выполнить несколько атомарных операций | `$transaction` |
| Написать SQL вручную | `$queryRaw` или `$executeRaw` |

## Мини-шпаргалка

- `findUnique` - только unique filter.
- `findFirst` - обычный фильтр, лучше с `orderBy`.
- `findMany` - списки, фильтры, пагинация.
- `createMany/updateMany/deleteMany` - массовые операции, обычно возвращают count.
- `upsert` полезен для idempotent create-or-update.
- `aggregate` считает по всей выборке, `groupBy` группирует.
- `$transaction` нужен для атомарности.
- Raw queries используй точечно и параметризованно.
