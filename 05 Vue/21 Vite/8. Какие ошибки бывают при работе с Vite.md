# Какие ошибки бывают при работе с Vite?

> [!summary]
> Частые ошибки Vite связаны с env variables, путями assets, proxy, base path, несовместимыми plugins, отличиями dev/prod и попыткой хранить секреты во frontend env.

## Ошибка 1. Env без VITE_

```env
API_URL=https://api.example.com
```

В frontend-коде:

```typescript
import.meta.env.API_URL;
```

Так не сработает. Нужно:

```env
VITE_API_URL=https://api.example.com
```

```typescript
import.meta.env.VITE_API_URL;
```

## Ошибка 2. Секреты во frontend env

```env
VITE_JWT_SECRET=secret
```

Все `VITE_*` значения попадают в client bundle. Это не место для database passwords, JWT secrets и private API keys.

## Ошибка 3. Неправильный base path

Если приложение деплоится не в root:

```txt
https://example.com/my-app/
```

нужно настроить:

```typescript
export default defineConfig({
  base: "/my-app/",
});
```

Иначе assets могут искаться по неправильным URL.

## Ошибка 4. Dev proxy работает, production падает

```typescript
server: {
  proxy: {
    "/api": "http://localhost:3000",
  },
}
```

`server.proxy` работает только в dev server. В production нужен настоящий reverse proxy, backend route или правильный API URL.

## Ошибка 5. Работает в dev, падает после build

Причины:

- неправильный import path;
- case-sensitive paths на Linux;
- browser-only API выполняется во время SSR/build;
- dynamic import path слишком динамический;
- plugin ведет себя иначе в production.

## Мини-шпаргалка

- Client env только с `VITE_`.
- `VITE_*` не секреты.
- `base` важен для subpath deploy.
- `server.proxy` работает только в dev.
- Проверяй `npm run build` и `npm run preview`.
- Следи за case-sensitive путями.
