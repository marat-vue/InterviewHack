## Что обязательно нужно помнить для Nuxt/Nitro?

- SSR/серверный Nuxt в production запускается как Node server: `node .output/server/index.mjs`.
- Контейнер должен слушать не `localhost`, а `0.0.0.0`, обычно через `NITRO_HOST=0.0.0.0`.
- Порт лучше задавать через `NITRO_PORT=3000` или совместимый `PORT`, а наружу публиковать через Compose/Nginx.
- `runtimeConfig` можно менять runtime env-переменными, но public-переменные видны в браузере.
- Внутри Docker Compose приложение ходит к базе по `db:5432`, к Redis по `redis:6379`, а не по `localhost`.
- `depends_on` задает порядок, но readiness для Postgres/Redis лучше проверять healthcheck-ами.
- Prisma migrations в production запускают отдельным controlled step, а не из каждой реплики Nuxt-приложения.
- Postgres data должен жить в named volume, Redis persistence включается явно, если Redis хранит не только disposable cache.
