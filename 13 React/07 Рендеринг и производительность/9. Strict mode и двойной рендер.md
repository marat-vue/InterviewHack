# Почему в Strict Mode бывает двойной рендер?

> [!summary]
> `StrictMode` в development специально выполняет дополнительные проверки: может повторно вызвать render, effects и ref callbacks. Это помогает находить нечистый render, отсутствующий cleanup и deprecated API. В production эти проверки не выполняются.

## Как включают Strict Mode?

```jsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
)
```

Многие шаблоны проектов включают `StrictMode` по умолчанию.

## Что проверяет Strict Mode?

- impure rendering;
- отсутствующий effect cleanup;
- отсутствующий ref cleanup;
- deprecated APIs.

## Пример нечистого render

```jsx
const items = []

function List() {
  items.push('rendered')
  return <ul>{items.map((item) => <li key={item}>{item}</li>)}</ul>
}
```

Если render вызван повторно, внешний массив меняется еще раз. Strict Mode помогает заметить такую проблему.

## Почему effect может запускаться дважды?

В dev Strict Mode React может выполнить:

```text
setup -> cleanup -> setup
```

Это проверка, что effect умеет корректно освобождать ресурсы.

## Что делать?

- Не отключать Strict Mode сразу.
- Убрать side effects из render.
- Добавить cleanup для effects.
- Проверить ref callbacks.
- Помнить, что production не делает эти дополнительные проверки.

## Мини-шпаргалка

- Strict Mode работает только в development.
- Он может повторно вызвать render.
- Он может повторно запустить effects.
- Цель - найти нечистый код.
- Правильный React-код должен переживать эти проверки.
