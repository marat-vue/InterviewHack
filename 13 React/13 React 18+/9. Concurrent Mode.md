# Concurrent Mode

> [!summary]
> `Concurrent Mode` - старое название экспериментального глобального режима React. В React 18 эту идею заменили на stable `Concurrent Features`: React умеет делать render прерываемым, но разработчик включает конкретные возможности через `createRoot`, `useTransition`, `startTransition`, `useDeferredValue`, `Suspense` и streaming SSR.

## Что такое Concurrent Rendering?

Concurrent Rendering - это внутренняя способность React готовить новый UI в фоне, прерывать render, откладывать менее важные обновления и возвращаться к ним позже.

Важно: это не значит, что React рендерит компоненты в нескольких потоках JavaScript. Основной JavaScript по-прежнему выполняется в одном main thread. "Concurrent" означает, что React может планировать работу по приоритетам и не обязан синхронно доводить каждый render до конца.

## Почему раньше говорили Concurrent Mode?

До React 18 существовала идея отдельного режима:

```jsx
// Историческая идея, не актуальный API для обычных проектов
// <ConcurrentMode>
//   <App />
// </ConcurrentMode>
```

Проблема была в том, что "режим" звучал как глобальный переключатель, который мог резко изменить поведение всего приложения и библиотек. Поэтому в React 18 команда React стала говорить не про режим, а про набор возможностей.

## Что такое Concurrent Features?

Concurrent Features - это конкретные API, которые используют новый concurrent renderer:

| Возможность | Что дает |
|---|---|
| `createRoot` | включает новый root API React 18 |
| automatic batching | объединяет несколько state updates в один render |
| `useTransition` | помечает обновление как несрочное и дает `isPending` |
| `startTransition` | помечает обновление как transition без хука |
| `useDeferredValue` | создает отложенную версию значения |
| `Suspense` | позволяет показывать fallback для кода, данных или серверных частей |
| streaming SSR | отправляет HTML частями, не ожидая всю страницу |
| selective hydration | позволяет гидратировать важные части страницы раньше |

## Как React мыслит приоритетами?

Не все обновления одинаково срочные.

Срочные:

- ввод текста;
- клик по кнопке;
- наведение;
- закрытие модального окна;
- перемещение фокуса.

Несрочные:

- фильтрация большого списка;
- переключение тяжелой вкладки;
- построение сложной таблицы;
- рендер результата поиска;
- обновление графика.

## Пример: срочный input и несрочный список

```jsx
import { useState, useTransition } from 'react'

function SearchPage({ products }) {
  const [query, setQuery] = useState('')
  const [filteredProducts, setFilteredProducts] = useState(products)
  const [isPending, startTransition] = useTransition()

  function handleChange(event) {
    const nextQuery = event.target.value

    setQuery(nextQuery)

    startTransition(() => {
      setFilteredProducts(
        products.filter((product) =>
          product.title.toLowerCase().includes(nextQuery.toLowerCase()),
        ),
      )
    })
  }

  return (
    <>
      <input value={query} onChange={handleChange} />
      {isPending && <p>Обновляем список...</p>}
      <ProductList products={filteredProducts} />
    </>
  )
}
```

Здесь ввод должен оставаться мгновенным. Обновление списка может немного подождать.

## Render и commit

Чтобы понимать concurrent rendering, важно разделять две фазы:

| Фаза | Что происходит |
|---|---|
| render | React вызывает компоненты и готовит описание будущего UI |
| commit | React применяет изменения к DOM |

Concurrent rendering относится в первую очередь к render-фазе. React может начать render, прервать его, выбросить незавершенную работу и начать заново с более свежими данными.

Commit-фаза должна быть согласованной: пользователь не должен увидеть "половину" UI от старого состояния и "половину" от нового.

## Что меняется для разработчика?

Компоненты должны быть чистыми:

```jsx
function UserCard({ user }) {
  return <h2>{user.name}</h2>
}
```

Такой компонент безопасен: если React вызовет его несколько раз, ничего плохого не произойдет.

Опасный пример:

```jsx
let renderCount = 0

function UserCard({ user }) {
  renderCount += 1
  localStorage.setItem('lastUser', user.id)

  return <h2>{user.name}</h2>
}
```

Побочные эффекты внутри render опасны, потому что React может вызвать render и не закоммитить результат.

## Что использовать вместо побочных эффектов в render?

Для эффектов есть специальные места:

- `useEffect` - запросы, подписки, логирование после paint;
- `useLayoutEffect` - измерение layout до paint;
- event handlers - действия пользователя;
- server actions/framework API - серверные мутации в современных fullstack-фреймворках.

## Чем Concurrent Features отличаются от Web Workers?

Concurrent Features не переносят тяжелый JavaScript в другой поток.

Если функция реально долго считает CPU-bound задачу, она все равно может блокировать main thread:

```jsx
function veryHeavyCalculation(items) {
  // Если здесь миллионы операций, transition не превратит это в magic.
  return items.sort(expensiveComparator)
}
```

Для тяжелых вычислений нужны:

- оптимизация алгоритма;
- мемоизация;
- виртуализация списков;
- Web Worker;
- перенос работы на сервер.

## Что отвечать на собеседовании?

Concurrent Mode - устаревшее название экспериментального режима. В React 18 корректнее говорить Concurrent Features. React может делать render прерываемым и планировать работу по приоритетам, но разработчик обычно взаимодействует с этим через `createRoot`, transitions, `Suspense`, `useDeferredValue`, streaming SSR и selective hydration.

## Частые ошибки

- Думать, что concurrent rendering - это многопоточность.
- Выполнять побочные эффекты прямо в теле компонента.
- Оборачивать все обновления в `startTransition`.
- Использовать transition для значения controlled input.
- Ожидать, что transition ускорит тяжелый синхронный алгоритм.

## Мини-шпаргалка

- Concurrent Mode - старое экспериментальное название.
- Concurrent Features - стабильные возможности React 18+.
- `createRoot` включает новый root API.
- Срочные updates должны оставаться мгновенными.
- Transition updates можно прерывать и откладывать.
- Render может быть прерван, commit должен быть целостным.
