# Что такое повторный рендер?

> [!summary]
> Повторный рендер - это повторный вызов компонента React после изменения state, props, context, external store или render родителя. Он нужен, чтобы React вычислил новый UI. Повторный render сам по себе не является ошибкой.

## Что вызывает повторный render?

- setter из `useState`;
- `dispatch` из `useReducer`;
- новые props;
- изменение context;
- обновление Zustand/Redux/external store;
- render родителя;
- изменение `key`.

Пример:

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

Клик вызывает повторный render `Counter`.

## Почему render ребенка может повториться?

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  return (
    <>
      <button onClick={() => setCount(count + 1)}>+</button>
      <Child />
    </>
  )
}
```

Когда `Parent` рендерится, React заново рассматривает его children. Это нормально.

## Повторный render - это плохо?

Нет. React создан для повторных render.

Проблема возникает, если:

- render слишком дорогой;
- обновляется слишком большое дерево;
- постоянно создаются новые props для memo-компонентов;
- большой context обновляет много потребителей;
- тяжелый список рендерится на каждый ввод.

## Что не вызывает render?

- изменение `ref.current`;
- изменение обычной переменной;
- мутация объекта без setter;
- изменение localStorage без подписки;
- изменение внешнего объекта без external store.

## Как диагностировать?

- React DevTools Profiler.
- Проверка state ownership.
- Проверка context value.
- Проверка selectors.
- Проверка новых object/function props.
- Разделение тяжелых компонентов.

## Мини-шпаргалка

- Повторный render - нормальная часть React.
- Render нужен, чтобы вычислить новый UI.
- Render не всегда меняет DOM.
- Оптимизировать нужно измеренную проблему.
- Часто помогает правильное место state.
