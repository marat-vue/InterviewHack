# Что такое “nested routes”?

> [!summary]
> Nested routes - это вложенные маршруты, где дочерний route рендерится внутри родительского layout через `<Outlet />`. Они помогают описывать иерархию страниц и не дублировать общие части интерфейса.

## Базовый пример

```jsx
<Routes>
  <Route path="/dashboard" element={<DashboardLayout />}>
    <Route index element={<DashboardHome />} />
    <Route path="profile" element={<ProfilePage />} />
    <Route path="settings" element={<SettingsPage />} />
  </Route>
</Routes>
```

Получаются URL:

```text
/dashboard
/dashboard/profile
/dashboard/settings
```

## Родительский layout

```jsx
import { Link, Outlet } from 'react-router-dom'

function DashboardLayout() {
  return (
    <section>
      <h1>Dashboard</h1>
      <nav>
        <Link to="profile">Profile</Link>
        <Link to="settings">Settings</Link>
      </nav>
      <Outlet />
    </section>
  )
}
```

`Outlet` - место, где появится дочерний route.

## Что такое index route?

```jsx
<Route index element={<DashboardHome />} />
```

Index route показывается, когда пользователь находится ровно на пути родителя:

```text
/dashboard
```

Он не имеет собственного `path`.

## Относительные пути

Вложенные paths обычно пишут без начального `/`:

```jsx
<Route path="settings" element={<SettingsPage />} />
```

Если написать `/settings`, это будет абсолютный route, не вложенный под `/dashboard`.

## Зачем нужны nested routes?

- общий layout для группы страниц;
- sidebar/header без дублирования;
- вложенные ресурсы `/users/:userId/posts`;
- route-level splitting;
- route-level data loading;
- ясная структура URL.

## Мини-шпаргалка

- Nested routes рендерятся внутри родителя.
- Родителю нужен `<Outlet />`.
- `index` route - страница по умолчанию внутри родителя.
- Вложенные paths пишут относительно.
- Это основной способ делать layouts в React Router.
