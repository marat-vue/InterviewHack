# Почему React теперь может прерывать рендер?

> [!summary]
> React может прерывать render, потому что Fiber представляет работу над UI как набор маленьких единиц. Если появляется более срочное обновление, React может отложить текущую render-работу, обработать важное событие и затем продолжить или пересчитать UI.

## Что значит "прервать render"?

Это не значит, что React применил половину DOM-изменений.

Прерывается именно render phase:

```text
React начал вычислять новое дерево
появилось более срочное обновление
React остановил вычисление
обработал срочное обновление
потом вернулся к работе
```

Commit phase применяет только согласованный результат.

## Зачем это нужно?

Чтобы пользовательский ввод был отзывчивым:

```text
тяжелая таблица рендерится
пользователь печатает
input должен реагировать сразу
```

React может дать приоритет вводу, а не тяжелому списку.

## Почему render должен быть чистым?

Плохо:

```jsx
function SearchResults({ query }) {
  analytics.track('render', query)
  return <Results query={query} />
}
```

Если render будет прерван или повторен, analytics отправится лишний раз.

Правильно:

```jsx
useEffect(() => {
  analytics.track('query_changed', query)
}, [query])
```

## Что помогает управлять приоритетом?

- `useTransition`;
- `startTransition`;
- `useDeferredValue`;
- Suspense;
- правильная структура state;
- разделение тяжелых компонентов.

## Мини-шпаргалка

- React может прерывать render phase.
- DOM не обновляется "наполовину".
- Commit применяет готовую версию UI.
- Side effects в render опасны.
- Transitions помогают пометить менее срочные updates.
