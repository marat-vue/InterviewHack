# Чем отличается локальное состояние компонента от глобального

> [!summary] Коротко
> Локальное состояние принадлежит конкретному компоненту или близкой ветке. Глобальное состояние живет в общем store и используется разными независимыми частями приложения.

## Вопрос

Чем отличается локальное состояние компонента от глобального?

## Локальное состояние

```vue
<script setup>
import { ref } from "vue";

const isOpen = ref(false);
const search = ref("");
</script>
```

Такое состояние нужно самому компоненту: открыть dropdown, хранить поле поиска, показать локальную ошибку.

## Глобальное состояние

```typescript
export const useAuthStore = defineStore("auth", {
  state: () => ({
    user: null as User | null,
  }),
});
```

Текущий пользователь нужен header, роутеру, страницам профиля, правам доступа и API-клиенту.

## Как выбрать

Спроси: "Кто использует эти данные?"

- Один компонент - local.
- Родитель и несколько детей - поднять state к родителю.
- Несколько независимых веток - global/store.

## Частая ошибка

Выносить локальное состояние в store слишком рано. Это делает приложение более связанным и сложным.

## Мини-шпаргалка

- Local state живет рядом с UI.
- Global state живет в store.
- Local проще читать и тестировать.
- Global нужен для общих данных приложения.
- Начинай локально, выноси при реальной необходимости.
