# Что такое build context и dockerignore?

> [!summary]
> Build context - это набор файлов, который Docker отправляет builder во время `docker build`. `.dockerignore` исключает лишние файлы из context, ускоряет сборку и не дает случайно положить в image секреты, логи, `node_modules` и мусор.

## Что такое build context?

В команде:

```bash
docker build -t my-api .
```

точка `.` означает build context.

Dockerfile может копировать файлы только из context:

```dockerfile
COPY package*.json ./
COPY src ./src
```

Если файл не входит в context, обычный `COPY` его не увидит.

## Почему context может быть проблемой?

Если context большой, Docker дольше отправляет файлы builder.

Плохо, когда в context попадают:

- `node_modules`;
- `.git`;
- `dist`;
- `coverage`;
- `.env`;
- database dumps;
- logs;
- screenshots;
- local cache;
- secrets.

## .dockerignore

`.dockerignore` работает похоже на `.gitignore`, но для Docker build context.

Пример:

```dockerignore
node_modules
dist
coverage
.git
.env
*.log
Dockerfile
compose.yaml
```

Даже если `Dockerfile` и `.dockerignore` исключены, builder все равно может использовать их для сборки, но их нельзя скопировать в image через `COPY`.

## Типичный .dockerignore для Node.js

```dockerignore
node_modules
npm-debug.log
.pnpm-store
.git
.github
.env
.env.*
dist
coverage
Dockerfile*
compose*.yaml
README.md
```

Иногда `dist` не исключают, если проект копирует уже собранный output. Все зависит от стратегии сборки.

## Частая ошибка с context

Команда:

```bash
docker build -f docker/Dockerfile -t app docker
```

Context здесь - папка `docker`, а не корень проекта. Поэтому:

```dockerfile
COPY package.json ./
```

не найдет `package.json`, если он лежит выше.

Обычно нужно:

```bash
docker build -f docker/Dockerfile -t app .
```

## Что отвечать на собеседовании?

Build context - это директория и файлы, которые Docker передает builder при сборке. Dockerfile может копировать файлы только из этого context. `.dockerignore` исключает лишние файлы, ускоряет build, уменьшает риск утечки secrets и делает image чище. Важно правильно выбирать context в команде `docker build`.

## Частые ошибки

- Не добавлять `.dockerignore`.
- Отправлять в context `node_modules` и `.git`.
- Класть `.env` в context.
- Указывать неправильную папку context.
- Думать, что `COPY ../file` сработает из любого места.
- Исключить файл, который потом нужен для `COPY`.

## Мини-шпаргалка

- Context - файлы, доступные build.
- `docker build .` - context текущая папка.
- `COPY` видит только context.
- `.dockerignore` уменьшает context.
- Не отправляй secrets и `node_modules`.
- `-f` меняет Dockerfile, но не context.
