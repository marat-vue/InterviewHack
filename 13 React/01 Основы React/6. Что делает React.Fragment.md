# Что делает React.Fragment?

> [!summary]
> `React.Fragment` позволяет вернуть несколько элементов из компонента без добавления лишнего DOM-узла. Это полезно, когда JSX нужно сгруппировать, но дополнительный `div` может сломать верстку, семантику или CSS.

## Базовый пример

```jsx
import { Fragment } from 'react'

function ArticlePreview() {
  return (
    <Fragment>
      <h2>React Fragment</h2>
      <p>Fragment группирует элементы без лишней обертки.</p>
    </Fragment>
  )
}
```

Чаще используют короткий синтаксис:

```jsx
function ArticlePreview() {
  return (
    <>
      <h2>React Fragment</h2>
      <p>Fragment группирует элементы без лишней обертки.</p>
    </>
  )
}
```

## Зачем избегать лишних div?

Лишняя обертка может мешать:

- CSS Grid;
- Flexbox;
- таблицам;
- спискам;
- семантической структуре;
- accessibility;
- тестам, которые завязаны на DOM-структуру.

Пример для таблицы:

```jsx
function RowCells() {
  return (
    <>
      <td>React</td>
      <td>Библиотека</td>
    </>
  )
}
```

Если обернуть `td` в `div`, HTML станет некорректным.

## Fragment с key

Короткая запись `<>...</>` не принимает `key`.

Если Fragment используется в списке, нужен полный синтаксис:

```jsx
import { Fragment } from 'react'

function Glossary({ terms }) {
  return (
    <dl>
      {terms.map((term) => (
        <Fragment key={term.id}>
          <dt>{term.name}</dt>
          <dd>{term.description}</dd>
        </Fragment>
      ))}
    </dl>
  )
}
```

## Мини-шпаргалка

- Fragment группирует JSX без DOM-обертки.
- `<>...</>` - короткий синтаксис Fragment.
- Для `key` нужен `<Fragment key={...}>`.
- Fragment полезен для таблиц, списков и семантики.
- Не добавляй `div`, если он нужен только для обхода ограничения JSX.
