# Чем Server Actions отличаются от API Routes?

> [!summary]
> Server Actions - серверные функции для внутренних мутаций UI, а API Routes/Route Handlers - публичные HTTP endpoints. Actions удобны для форм и внутренних операций, Route Handlers нужны для внешних клиентов, webhooks, REST API и полного контроля HTTP.

## Сравнение

| Критерий | Server Actions | API Routes / Route Handlers |
|---|---|---|
| Сущность | серверная функция | HTTP endpoint |
| URL | не проектируется вручную | есть публичный URL |
| Вызов | `<form action={fn}>`, action call | `fetch('/api/...')` |
| Лучший сценарий | внутренние mutations UI | внешние API, webhooks |
| HTTP control | ограниченнее | полный контроль |
| Auth/validation | обязательны | обязательны |
| Revalidation | удобно рядом с mutation | тоже возможно, но вручную |

## Server Action пример

```ts
'use server'

export async function updateProfile(formData: FormData) {
  await requireUser()
  await saveProfile(formData)
  revalidatePath('/profile')
}
```

## Route Handler пример

```ts
export async function POST(request: Request) {
  const body = await request.json()

  if (!isValidWebhook(body)) {
    return Response.json({ error: 'Invalid payload' }, { status: 400 })
  }

  await processWebhook(body)

  return Response.json({ ok: true })
}
```

## Когда выбрать Server Action?

- форма внутри Next.js приложения;
- создание/редактирование записи;
- обновление профиля;
- logout;
- internal mutation;
- нужно сразу сделать `revalidatePath`.

## Когда выбрать Route Handler?

- endpoint для мобильного приложения;
- webhook от Stripe/GitHub;
- публичный REST API;
- OAuth callback;
- file upload endpoint;
- нужен точный контроль headers/status/body;
- API должен вызываться не только из Next UI.

## Что отвечать на собеседовании?

Server Actions - удобный механизм внутренних серверных мутаций, связанный с React/Next UI. Route Handlers - полноценные HTTP endpoints. Если нужен внешний URL или контроль HTTP-протокола, выбирают Route Handler; если нужно обработать форму внутри приложения, часто удобнее Server Action.

## Частые ошибки

- Считать Server Action недоступной для злоумышленника и не делать auth.
- Делать webhook через Server Action.
- Создавать API endpoint для каждой внутренней формы без причины.
- Не возвращать корректные status codes в Route Handler.
- Не делать revalidation после action.

## Мини-шпаргалка

- Action - внутренняя server mutation.
- Route Handler - публичный endpoint.
- Forms - часто Server Actions.
- Webhooks - Route Handlers.
- HTTP statuses - Route Handlers.
- Auth/validation нужны в обоих случаях.
