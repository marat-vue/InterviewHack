# Что такое HOC?

> [!summary]
> HOC, Higher-Order Component, - это функция, которая принимает компонент и возвращает новый компонент с дополнительным поведением или данными. Это старый, но важный React-паттерн, который часто встречается в legacy-коде и библиотеках.

## Простое определение

HOC похож на функцию-обертку:

```text
Component -> withSomething(Component) -> EnhancedComponent
```

Пример:

```jsx
function withAuth(Component) {
  return function ProtectedComponent(props) {
    const user = useCurrentUser()

    if (!user) {
      return <LoginPage />
    }

    return <Component {...props} user={user} />
  }
}
```

Использование:

```jsx
const ProtectedDashboard = withAuth(Dashboard)
```

## Зачем нужны HOC?

Исторически HOC использовали для переиспользования логики:

- авторизация;
- доступ к store;
- analytics;
- feature flags;
- inject props;
- обработка layout;
- работа с данными.

## HOC в реальном мире

Пример из старого ecosystem:

```jsx
export default connect(mapStateToProps)(UserPage)
```

`connect` из React Redux - классический пример HOC-подхода.

## Какие минусы у HOC?

- Wrapper hell.
- Сложнее отследить, откуда пришли props.
- Возможны конфликты имен props.
- Сложнее типизация.
- Стек компонентов становится глубже.

Пример:

```jsx
export default withRouter(withAuth(withTheme(UserPage)))
```

## Что используют сейчас?

Во многих случаях HOC заменяют:

- custom hooks;
- context;
- render props;
- composition;
- route guards;
- framework-level wrappers.

Но HOC полезно знать для собеседований и чтения старого кода.

## Мини-шпаргалка

- HOC - функция, принимающая компонент и возвращающая компонент.
- HOC добавляет данные или поведение.
- Это паттерн, а не отдельный React API.
- Сейчас часто заменяется hooks и composition.
- В legacy-коде HOC встречаются часто.
