# Как совместить Zod и Swagger в NestJS?

> [!summary]
> Nest Swagger хорошо работает с class DTO и decorators. Zod schemas сами по себе не дают NestJS reflection metadata, поэтому для OpenAPI нужно либо описывать схемы вручную, либо использовать community-интеграции, либо держать class DTO для Swagger.

## Проблема

```ts
const createUserSchema = z.object({
  email: z.email(),
});
```

Zod schema - runtime value. `@nestjs/swagger` не увидит ее автоматически так же, как class DTO с `@ApiProperty`.

## Вариант 1. Class DTO для Swagger, Zod для validation

```ts
export class CreateUserDocDto {
  @ApiProperty({ example: 'anna@example.com' })
  email: string;
}
```

```ts
@ApiBody({ type: CreateUserDocDto })
@Post()
create(@Body(new ZodValidationPipe(createUserSchema)) body: CreateUserInput) {}
```

## Вариант 2. Raw OpenAPI schema

```ts
@ApiBody({
  schema: {
    type: 'object',
    properties: {
      email: { type: 'string', format: 'email' },
    },
    required: ['email'],
  },
})
```

## Вариант 3. Community integration

Есть community packages, которые конвертируют Zod schemas в OpenAPI schemas. Перед использованием проверь поддержку версии Zod и NestJS.

## Мини-шпаргалка

- Zod не дает Swagger metadata автоматически.
- Nest Swagger лучше всего работает с class DTO.
- Можно использовать `@ApiBody({ schema })`.
- Можно держать отдельный doc DTO.
- Следи, чтобы Zod validation и OpenAPI schema не разъехались.
