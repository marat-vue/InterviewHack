# Что такое Nitro middleware и порядок выполнения?

> [!NOTE]
> Nitro middleware - это handler, который выполняется до route handler. Он может изменить `event.context`, проверить request, добавить headers или остановить обработку. Обычно middleware не должен возвращать значение.

## Где лежат middleware?

```txt
server/
  middleware/
    01.logger.ts
    02.auth.ts
    03.context.ts
```

Пример:

```ts
// server/middleware/01.logger.ts
export default defineEventHandler((event) => {
  console.log(event.method, event.path);
});
```

## Зачем нужны middleware?

Middleware используют для:

- request logging;
- request id;
- CORS;
- auth pre-check;
- rate limit;
- добавления `event.context.user`;
- tenant resolving;
- feature flags;
- security headers.

## Как добавить данные в `event.context`?

```ts
// server/middleware/02.request-context.ts
export default defineEventHandler((event) => {
  event.context.requestId = crypto.randomUUID();
  event.context.startedAt = Date.now();
});
```

Route:

```ts
export default defineEventHandler((event) => {
  return {
    requestId: event.context.requestId,
  };
});
```

## Почему middleware обычно ничего не возвращает?

Если middleware вернуло значение, Nitro/H3 считает, что response уже готов, и route handler не выполнится.

```ts
export default defineEventHandler((event) => {
  if (event.path === '/blocked') {
    return {
      blocked: true,
    };
  }
});
```

Так можно делать для явного early return, но случайный `return` ломает request flow.

## В каком порядке выполняются middleware?

Middleware выполняются по directory listing order. Поэтому для контроля порядка используют числовой префикс:

```txt
middleware/
  01.logger.ts
  02.auth.ts
  03.rate-limit.ts
```

Если файлов больше 9, лучше использовать `01`, `02`, `10`, а не `1`, `2`, `10`, потому что имена сортируются как строки.

## Как ограничить middleware конкретным path?

Внутри middleware:

```ts
export default defineEventHandler((event) => {
  if (!event.path.startsWith('/api/admin')) {
    return;
  }

  // admin-only logic
});
```

Через Nitro config:

```ts
export default defineConfig({
  handlers: [
    {
      route: '/api/admin/**',
      handler: './server/middleware/admin-auth.ts',
      middleware: true,
    },
  ],
});
```

## Чем middleware отличается от route guard?

Middleware работает на уровне HTTP request. Guard - это архитектурная идея, которую ты можешь реализовать функцией:

```ts
export async function requireAuth(event: H3Event) {
  const session = await getSession(event);

  if (!session) {
    throw createError({
      statusCode: 401,
      statusMessage: 'Unauthorized',
    });
  }

  return session;
}
```

И использовать точечно:

```ts
export default defineHandler(async (event) => {
  const session = await requireAuth(event);

  return {
    user: session.user,
  };
});
```

Точечная функция часто понятнее глобального middleware.

## Мини-шпаргалка

- Middleware выполняется до route handler.
- Данные кладут в `event.context`.
- Возврат значения из middleware останавливает request.
- Порядок контролируют префиксами `01`, `02`, `03`.
- Для auth часто лучше сочетать middleware и явный `requireAuth`.
- Чем меньше глобальной магии, тем проще поддерживать Nitro API.
