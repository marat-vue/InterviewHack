# Feature-Sliced Design

> [!summary]
> Feature-Sliced Design, или FSD, - это методология организации frontend-кода по слоям, бизнес-сущностям и фичам. Ее цель - сделать структуру проекта предсказуемой: понятно, куда класть код, откуда можно импортировать и какие модули не должны знать друг о друге.

## Главная идея

Вместо структуры по техническим типам:

```text
src/
  components/
  hooks/
  utils/
  api/
  store/
```

FSD предлагает структуру по смыслу и уровню ответственности:

```text
src/
  app/
  pages/
  widgets/
  features/
  entities/
  shared/
```

В некоторых описаниях встречается слой `processes`, но в современной практике его часто не используют или заменяют более явным моделированием сценариев.

## Слои FSD

```text
app -> pages -> widgets -> features -> entities -> shared
```

Чем ниже слой, тем он более переиспользуемый и менее зависимый от конкретного экрана.

| Слой | Ответственность | Пример |
|---|---|---|
| `app` | Инициализация приложения | providers, router, global styles |
| `pages` | Конкретные страницы | `CatalogPage`, `ProfilePage` |
| `widgets` | Крупные блоки страницы | `Header`, `ProductList`, `Sidebar` |
| `features` | Пользовательские действия | `add-to-cart`, `login`, `toggle-theme` |
| `entities` | Бизнес-сущности | `user`, `product`, `order` |
| `shared` | Переиспользуемый технический код | `ui`, `api`, `lib`, `config` |

## Правило зависимостей

Главное правило: верхние слои могут импортировать нижние, но нижние не должны импортировать верхние.

```text
pages может импортировать widgets/features/entities/shared
features может импортировать entities/shared
entities может импортировать shared
shared не импортирует ничего из app/pages/widgets/features/entities
```

Плохо:

```ts
// shared/lib/formatPrice.ts
import { userStore } from '@/entities/user' // shared знает про entity
```

Хорошо:

```ts
// entities/product/lib/formatProductPrice.ts
import { formatMoney } from '@/shared/lib/formatMoney'
```

## Slices и segments

Slice - модуль по бизнес-смыслу:

```text
features/add-to-cart/
entities/product/
widgets/header/
pages/catalog/
```

Segment - техническая часть внутри slice:

```text
features/add-to-cart/
  ui/
    AddToCartButton.tsx
  model/
    store.ts
    selectors.ts
  api/
    addToCart.ts
  lib/
    mapError.ts
  index.ts
```

`index.ts` - публичное API slice.

## Public API

Из внешнего кода импортируют только из `index.ts`.

```ts
// хорошо
import { AddToCartButton } from '@/features/add-to-cart'
```

```ts
// плохо
import { AddToCartButton } from '@/features/add-to-cart/ui/AddToCartButton'
```

Public API помогает менять внутреннюю структуру slice без массового рефакторинга импортов.

## Пример страницы

```tsx
// pages/catalog/ui/CatalogPage.tsx
import { ProductFilters } from '@/features/filter-products'
import { ProductList } from '@/widgets/product-list'

export function CatalogPage() {
  return (
    <>
      <ProductFilters />
      <ProductList />
    </>
  )
}
```

Страница собирает готовые блоки, а не содержит всю бизнес-логику внутри себя.

## Мини-шпаргалка

- FSD структурирует код по слоям, slices и segments.
- Импорты идут сверху вниз.
- Slice группирует код по бизнес-смыслу.
- Public API защищает внутренности модуля.
- FSD особенно полезен в средних и больших проектах.
