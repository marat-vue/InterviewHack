# Чем React.memo похож на shouldComponentUpdate?

> [!summary]
> `React.memo` и `shouldComponentUpdate` помогают пропускать лишний render, если входные данные компонента не изменились. `shouldComponentUpdate` используется в классовых компонентах, а `React.memo` - для функциональных.

## shouldComponentUpdate в классе

```jsx
class UserCard extends Component {
  shouldComponentUpdate(nextProps) {
    return nextProps.user.id !== this.props.user.id
  }

  render() {
    return <h2>{this.props.user.name}</h2>
  }
}
```

Метод возвращает `true` или `false`: нужно обновлять компонент или нет.

## React.memo в функциональном компоненте

```jsx
const UserCard = memo(function UserCard({ user }) {
  return <h2>{user.name}</h2>
})
```

`memo` позволяет React пропустить render, если props не изменились по сравнению с прошлым render.

## В чем отличие?

| Механизм | Где используется | Как работает |
|---|---|---|
| `shouldComponentUpdate` | class component | метод вручную решает, обновляться ли |
| `React.memo` | function component | обертка сравнивает props |

У `memo` можно передать свою функцию сравнения:

```jsx
const UserCard = memo(UserCardBase, (prevProps, nextProps) => {
  return prevProps.user.id === nextProps.user.id
})
```

Но кастомное сравнение должно быть очень аккуратным.

## Чем опасна неправильная оптимизация?

Если сравнить только `id`, но забыть про `name`, UI может устареть:

```jsx
return prevProps.user.id === nextProps.user.id
```

Если у того же пользователя изменилось имя, компонент может не обновиться.

## React Compiler

Современный React Compiler может автоматически применять оптимизации, похожие на `memo`, снижая необходимость ручной мемоизации. Но `memo` все еще нужно понимать для существующих проектов, собеседований и ручной оптимизации.

## Мини-шпаргалка

- `shouldComponentUpdate` - class lifecycle для оптимизации.
- `React.memo` - похожая идея для функциональных компонентов.
- Оба механизма могут пропустить render.
- Неправильное сравнение может дать stale UI.
- Мемоизация должна опираться на измерения, а не привычку.
