# Почему Zustand-хуки называются селективными?

> [!summary]
> Zustand-хуки называют селективными, потому что компонент может подписаться не на весь store, а на конкретный slice состояния через selector. Это уменьшает лишние ререндеры и делает зависимости компонента явными.

## Пример selector

```jsx
const userName = useUserStore((state) => state.user.name)
```

Компоненту нужен только `user.name`, а не весь store.

## Что будет без selector?

```jsx
const store = useUserStore()
```

Компонент подписывается на весь store. Любое изменение store может привести к ререндеру этого компонента.

Лучше:

```jsx
const userName = useUserStore((state) => state.user.name)
```

## Selector как контракт

Selector отвечает на вопрос:

```text
Какая часть store нужна этому компоненту?
```

Это делает компонент более честным и проще для анализа.

## Сравнение значений

Zustand сравнивает выбранное значение. Если selector возвращает примитив:

```jsx
state.count
```

все просто.

Если selector возвращает новый объект или массив:

```jsx
state => ({ count: state.count, user: state.user })
```

нужно помнить, что новая ссылка может вызвать ререндер. Для таких случаев используют shallow-сравнение или отдельные selectors.

## Мини-шпаргалка

- Selector выбирает slice из store.
- Компонент подписывается только на выбранное значение.
- Не читай весь store без причины.
- Примитивы проще для сравнения.
- Для объектов и массивов следи за стабильностью ссылок.
