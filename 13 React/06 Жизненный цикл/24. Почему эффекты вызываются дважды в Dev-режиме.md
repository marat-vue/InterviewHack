# Почему эффекты вызываются дважды в Dev-режиме?

> [!summary]
> В development при включенном `StrictMode` React может специально запускать effects дополнительный раз: setup -> cleanup -> setup. Это помогает найти эффекты без корректной очистки и код, который небезопасен при повторной инициализации.

## Что делает Strict Mode?

Strict Mode включает development-only проверки:

- дополнительный render для поиска impure rendering;
- дополнительный запуск effects;
- дополнительный запуск ref callbacks;
- предупреждения о deprecated API.

В production эти проверки не выполняются.

## Пример

```jsx
useEffect(() => {
  const connection = createConnection()
  connection.connect()

  return () => {
    connection.disconnect()
  }
}, [])
```

В dev Strict Mode React может сделать:

```text
connect
disconnect
connect
```

Так проверяется, что cleanup действительно закрывает соединение.

## Что делать, если effect ломается?

Не нужно сразу удалять Strict Mode. Нужно проверить:

- есть ли cleanup;
- идемпотентен ли setup;
- нет ли side effects в render;
- не отправляется ли analytics в mount-effect без защиты;
- не создается ли подписка без отписки.

## Плохая реакция

```jsx
const didRun = useRef(false)

useEffect(() => {
  if (didRun.current) return
  didRun.current = true
  connect()
}, [])
```

Так можно скрыть проблему cleanup, а не исправить ее.

## Мини-шпаргалка

- Двойной effect в dev связан со Strict Mode.
- Это не production-поведение.
- Цель - найти missing cleanup.
- Правильный effect должен переживать setup-cleanup-setup.
- Не отключай проверки, пока не понял причину.
