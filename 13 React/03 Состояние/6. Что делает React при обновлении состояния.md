# Что делает React при обновлении состояния?

> [!summary]
> При обновлении state React планирует новый render, вызывает компонент с новым state, сравнивает новое дерево React-элементов с предыдущим и затем применяет необходимые изменения к DOM на commit-этапе.

## Упрощенная цепочка

```text
1. Пользователь совершил действие
2. Вызвался setter состояния
3. React поставил обновление в очередь
4. React заново вызвал компонент
5. Компонент вернул новый JSX
6. React сравнил старое и новое дерево
7. React применил изменения к DOM
```

## Пример

```jsx
function Toggle() {
  const [enabled, setEnabled] = useState(false)

  return (
    <button onClick={() => setEnabled(!enabled)}>
      {enabled ? 'Включено' : 'Выключено'}
    </button>
  )
}
```

После клика React не "ищет кнопку и меняет текст вручную" в твоем коде. Он заново вызывает `Toggle`, получает другой JSX и обновляет DOM.

## Render phase и commit phase

Render phase:

- React вызывает компоненты;
- вычисляет новое дерево;
- может сравнивать элементы;
- не должен выполнять побочные действия в твоем render-коде.

Commit phase:

- React применяет изменения к DOM;
- обновляет refs;
- запускает layout/effects в нужном порядке.

## Всегда ли обновляется весь экран?

Нет. React может вызвать render нескольких компонентов, но в DOM применит только необходимые изменения.

Например, если изменился только текст кнопки, React не обязан пересоздавать весь layout.

## Почему важно не мутировать state?

Если state мутируется напрямую, React сложнее понять, что изменилось. Новые ссылки на объекты и массивы делают изменения явными.

## Мини-шпаргалка

- Setter ставит обновление в очередь.
- React заново вызывает компонент.
- JSX - новое описание UI.
- Reconciliation определяет нужные изменения.
- DOM меняется на commit-этапе.
