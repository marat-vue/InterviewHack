# Как работать с миграциями Prisma?

> [!summary]
> Prisma migrations превращают изменения `schema.prisma` в SQL-миграции. В разработке часто используют `prisma migrate dev`, а для production применяют уже созданные миграции через `prisma migrate deploy`.

## Создать миграцию

```bash
npx prisma migrate dev --name init
```

Команда:

- сравнит schema с БД;
- создаст migration file;
- применит миграцию локально;
- сгенерирует Prisma Client.

## Production

```bash
npx prisma migrate deploy
```

В production обычно не создают новую миграцию на сервере, а применяют уже закоммиченные migration files.

## Prisma generate

```bash
npx prisma generate
```

Генерация клиента нужна после изменения схемы или при установке зависимостей в CI.

## Seed

Для учебных данных можно использовать seed script, который создает стартовые записи.

## Мини-шпаргалка

- `migrate dev` - разработка.
- `migrate deploy` - production/CI.
- Миграции нужно коммитить.
- После изменения schema нужен generate.
- Не правь production БД вручную без миграции.
