# Почему происходит ререндер при изменении контекста?

> [!summary]
> Компонент, который вызывает `useContext`, подписывается на значение Context. Когда `value` у ближайшего Provider меняется, React обновляет потребителей этого контекста, даже если они обернуты в `memo`.

## Пример

```jsx
const ThemeContext = createContext('light')

function ThemeLabel() {
  const theme = useContext(ThemeContext)
  return <span>{theme}</span>
}
```

Если Provider передаст новое значение:

```jsx
<ThemeContext.Provider value={theme}>
  <ThemeLabel />
</ThemeContext.Provider>
```

`ThemeLabel` перерендерится при изменении `theme`.

## Почему memo не спасает?

`memo` сравнивает props компонента, но context - отдельный источник данных.

```jsx
const ThemeLabel = memo(function ThemeLabel() {
  const theme = useContext(ThemeContext)
  return <span>{theme}</span>
})
```

Если context изменился, компонент должен получить новое значение, поэтому React его обновит.

## Проблема с object value

```jsx
<AuthContext.Provider value={{ user, login, logout }}>
  {children}
</AuthContext.Provider>
```

На каждом render создается новый объект. Даже если `user` не изменился, ссылка `value` новая.

Можно стабилизировать:

```jsx
const value = useMemo(() => ({
  user,
  login,
  logout,
}), [user, login, logout])
```

Но это не отменяет необходимости правильно разделять context.

## Главная причина лишних render

Один большой context:

```jsx
value={{ user, theme, cart, filters, notifications }}
```

Если меняется `cart`, компонент, читающий только `theme`, тоже может обновиться, потому что подписан на общий context value.

## Мини-шпаргалка

- `useContext` подписывает компонент на context value.
- Изменение Provider value обновляет потребителей.
- `memo` не блокирует обновление из context.
- Новый объект в `value` может вызывать лишние render.
- Большой context лучше разделять по смыслу.
