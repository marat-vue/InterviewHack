# Что такое контейнер?

> [!NOTE]
> Контейнер - это запущенный изолированный процесс, созданный из Docker image. У него есть собственная файловая система, сеть, переменные окружения и команда запуска, но он использует ядро операционной системы хоста.

## Простое определение

Контейнер можно представить как коробку для процесса:

```text
process + filesystem + env + network + limits
```

Например, контейнер с Node.js API содержит:

- Node.js runtime;
- `node_modules`;
- код приложения;
- переменные окружения;
- команду `node dist/main.js`;
- сетевые настройки.

## Контейнер живет, пока живет главный процесс

Если главный процесс завершился, контейнер остановится.

```dockerfile
CMD ["node", "dist/main.js"]
```

Если Node.js процесс упал, контейнер тоже перейдет в состояние `Exited`.

## Контейнеры изолированы

Изоляция означает:

- свой process namespace;
- своя файловая система;
- свои переменные окружения;
- своя сеть;
- отдельные лимиты ресурсов;
- отдельный набор capabilities.

Но это не абсолютная безопасность. Контейнеры разделяют ядро host OS, поэтому security-настройки все равно важны.

## Контейнеры одноразовые

Хорошая практика: контейнер можно удалить и создать заново без потери приложения.

```bash
docker rm my-api
docker run my-api
```

Если данные важны, они должны лежать не внутри container filesystem, а во volume, базе данных или внешнем хранилище.

## Пример запуска

```bash
docker run --name web -d -p 8080:80 nginx:alpine
```

Проверка:

```bash
docker ps
docker logs web
docker exec -it web sh
```

## Что отвечать на собеседовании?

Контейнер - это изолированный runtime instance образа. Он запускает один или несколько процессов в собственном окружении, имеет файловую систему и сеть, но использует ядро операционной системы хоста. Контейнеры считаются disposable: их можно пересоздавать, а важные данные нужно хранить во volumes или внешних сервисах.

## Частые ошибки

- Хранить базу данных только внутри container filesystem.
- Думать, что контейнер продолжит работать после завершения главного процесса.
- Править файлы внутри контейнера вручную вместо изменения Dockerfile.
- Путать остановленный контейнер и удаленный контейнер.
- Запускать много разных обязанностей в одном контейнере без необходимости.

## Мини-шпаргалка

- Container - запущенный image.
- Живет, пока живет главный процесс.
- Изолирован, но разделяет host kernel.
- Может быть остановлен, удален и создан заново.
- Данные контейнера эфемерны без volume.
- Для входа внутрь используют `docker exec`.
