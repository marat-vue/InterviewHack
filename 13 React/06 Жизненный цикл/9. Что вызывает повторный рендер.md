# Что вызывает повторный рендер?

> [!summary]
> Повторный render вызывают изменения state, props, context, external store или render родителя. Но повторный render не всегда означает изменение DOM: React сначала вычисляет новый UI, а затем применяет только нужные изменения.

## Основные причины

- `setState` или setter `useState`;
- `dispatch` из `useReducer`;
- новые props;
- изменение Context value;
- обновление external store;
- render родителя;
- изменение `key` и пересоздание компонента.

## Пример state update

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

Клик вызывает setter, React планирует render.

## Пример parent render

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  return (
    <>
      <button onClick={() => setCount(count + 1)}>+</button>
      <Child />
    </>
  )
}
```

Когда `Parent` рендерится, React обычно заново рассматривает `Child`.

## Что не вызывает render?

- изменение `ref.current`;
- изменение обычной переменной;
- мутация объекта без setter;
- изменение localStorage само по себе;
- изменение глобальной переменной без подписки.

## Как диагностировать?

- React DevTools Profiler.
- Проверить state ownership.
- Проверить Context value.
- Проверить новые object/function props.
- Проверить selectors store.
- Проверить Strict Mode в development.

## Мини-шпаргалка

- State update вызывает render.
- Props update вызывает render.
- Context update вызывает потребителей.
- Parent render может привести к render детей.
- Render не равен DOM update.
