# Чем JSX отличается от TSX?

> [!summary]
> JSX - синтаксис HTML-подобной разметки внутри JavaScript. TSX - тот же JSX, но в TypeScript-файле, где работают типы, проверка props, автодополнение и статический анализ.

## Что такое JSX?

JSX позволяет писать разметку рядом с логикой компонента:

```jsx
function Button({ label }) {
  return <button>{label}</button>
}
```

После сборки JSX превращается в JavaScript-вызовы React runtime.

Проблема JSX-файла в том, что props не проверяются TypeScript:

```jsx
<Button label={42} />
```

Компонент мог ожидать строку, но ошибка проявится позже.

## Что такое TSX?

TSX - это JSX внутри TypeScript:

```tsx
type ButtonProps = {
  label: string
}

function Button({ label }: ButtonProps) {
  return <button>{label}</button>
}

<Button label="Save" />
<Button label={42} />
```

Во втором вызове TypeScript покажет ошибку: `number` нельзя передать туда, где ожидается `string`.

## Когда использовать .ts, а когда .tsx?

| Расширение | Когда использовать |
|---|---|
| `.ts` | обычный TypeScript без JSX |
| `.tsx` | файл содержит JSX-разметку |

Пример `.ts`:

```ts
export type User = {
  id: string
  name: string
}

export function formatUserName(user: User) {
  return user.name.trim()
}
```

Пример `.tsx`:

```tsx
function UserName({ user }: { user: User }) {
  return <span>{formatUserName(user)}</span>
}
```

## Чем TSX отличается от HTML?

TSX наследует правила JSX:

```tsx
function App() {
  const className = 'title'

  return (
    <h1 className={className}>
      Hello
    </h1>
  )
}
```

Важные отличия:

- `className`, а не `class`;
- `htmlFor`, а не `for`;
- JavaScript-выражения внутри `{}`;
- компонент должен вернуть один корневой узел или fragment;
- props пишутся в camelCase.

## Типы исчезают после компиляции

TypeScript не добавляет типы в браузерный JavaScript. Он проверяет код до сборки, а затем типы удаляются.

```tsx
type Props = {
  title: string
}

function Card({ title }: Props) {
  return <article>{title}</article>
}
```

В runtime типа `Props` уже нет.

## Что отвечать на собеседовании?

JSX - это синтаксис для описания UI в JavaScript. TSX - JSX внутри TypeScript, где можно типизировать props, state, events и другие контракты React-компонентов. Если файл содержит JSX и TypeScript, он должен быть `.tsx`.

## Частые ошибки

- Писать JSX в `.ts` файле.
- Думать, что TypeScript-типы существуют в runtime.
- Путать JSX с HTML.
- Оставлять props без типов в TSX.
- Использовать `any`, теряя пользу TSX.

## Мини-шпаргалка

- JSX = разметка внутри JavaScript.
- TSX = JSX + TypeScript.
- `.tsx` нужен, если в файле есть JSX.
- Типы проверяются до запуска и удаляются при сборке.
- TSX не делает runtime validation.
