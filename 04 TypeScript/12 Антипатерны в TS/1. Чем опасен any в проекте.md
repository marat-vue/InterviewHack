# Чем опасен any в проекте

> [!summary] Коротко
> `any` отключает проверку типов в конкретном месте и может "заразить" соседний код. Чем больше `any`, тем меньше TypeScript реально защищает проект.

## Вопрос

Чем опасен `any` в проекте?

## Главная проблема

`any` говорит TypeScript: "не проверяй это значение". После этого компилятор разрешает почти любые операции.

```typescript
const value: any = "hello";

value.toFixed(2); // TypeScript не ругается
// runtime: ошибка, потому что строка не имеет toFixed
```

Код выглядит типизированным, но защита отключена.

## Any распространяется дальше

```typescript
function parse(json: string): any {
  return JSON.parse(json);
}

const user = parse("{}");
user.profile.address.city.toUpperCase(); // TypeScript молчит
```

Одно `any` на границе может сделать небезопасной целую цепочку кода.

## Чем заменить

Если тип неизвестен, чаще лучше использовать `unknown`.

```typescript
function parse(json: string): unknown {
  return JSON.parse(json);
}

const value = parse("{}");

if (typeof value === "object" && value !== null) {
  console.log(value);
}
```

`unknown` заставляет сначала проверить значение.

## Когда any допустим

`any` иногда используют в низкоуровневых utility-типах, миграциях или временных местах при подключении старого JS-кода. Важно ограничивать область применения.

## Мини-шпаргалка

- `any` отключает проверку типов.
- Ошибки переносятся из compile time в runtime.
- `any` может распространяться по проекту.
- Для неизвестных данных выбирай `unknown`.
- Если `any` временный, оставляй понятный план удаления.
