# Ререндер компонентов

> [!summary] Коротко
> Ререндер компонента происходит, когда меняется реактивная зависимость, использованная при рендере. Vue пересчитывает виртуальное дерево компонента и применяет нужные изменения к DOM.

## Вопрос

Когда происходит ререндер компонентов во Vue?

## Базовый пример

```vue
<script setup>
import { ref } from "vue";

const count = ref(0);
</script>

<template>
  <button @click="count++">{{ count }}</button>
</template>
```

Компонент читает `count` в шаблоне. Когда `count` меняется, Vue планирует ререндер.

## Ререндер связан с зависимостями

Если реактивное значение не использовалось в рендере, само по себе оно не обязано перерисовывать шаблон.

```vue
<script setup>
import { ref } from "vue";

const visibleCount = ref(0);
const internalCounter = ref(0);
</script>

<template>
  <p>{{ visibleCount }}</p>
</template>
```

Изменение `visibleCount` влияет на template. `internalCounter` повлияет на DOM только если его где-то прочитать в рендере или computed, который используется в рендере.

## Обновления группируются

Vue не обновляет DOM после каждой строки синхронного кода. Он собирает изменения и применяет их в следующем tick.

```typescript
count.value++;
count.value++;

await nextTick(); // DOM уже отражает итоговое значение
```

## Как уменьшить лишние ререндеры

Используй `computed` для производных значений, `key` для стабильных списков, `v-memo` для тяжелых частей и не делай слишком широкое глобальное состояние.

## Мини-шпаргалка

- Ререндер запускает изменение реактивной зависимости render-а.
- Vue группирует обновления.
- DOM обновляется не мгновенно, а после flush.
- Лишние ререндеры часто идут от слишком широких зависимостей.
