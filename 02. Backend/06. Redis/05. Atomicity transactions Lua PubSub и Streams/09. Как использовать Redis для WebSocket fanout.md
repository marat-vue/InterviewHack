# Как использовать Redis для WebSocket fan-out?

> [!NOTE]
> Когда backend запущен в нескольких процессах, WebSocket-клиенты распределены между инстансами. Redis Pub/Sub помогает разослать событие всем инстансам, чтобы каждый отправил его своим локальным клиентам.

## Проблема нескольких инстансов

```txt
Client A connected to API-1
Client B connected to API-2

API-1 peer.publish local -> Client B не получит событие
```

Нужен общий broker:

```txt
API-1 -> Redis PUBLISH -> API-1/API-2 subscribers -> local WebSocket clients
```

## Node.js bus

```ts
import { createClient } from 'redis';

export const publisher = createClient({
  url: process.env.REDIS_URL,
});

export const subscriber = publisher.duplicate();

await publisher.connect();
await subscriber.connect();
```

## Broadcast пример

```ts
const peers = new Set<WebSocket>();

await subscriber.subscribe('chat:messages', (message) => {
  for (const peer of peers) {
    peer.send(message);
  }
});

export async function publishChatMessage(payload: unknown) {
  await publisher.publish('chat:messages', JSON.stringify(payload));
}
```

## Tenant-specific channels

```txt
tenant:42:notifications
tenant:43:notifications
```

Не публикуй private события в общий channel без tenant/user фильтрации.

## Pub/Sub или Streams?

Для online WebSocket notifications обычно Pub/Sub достаточно. Если нужно доставить уведомление пользователю, который был offline, нужно:

- хранить notification в БД;
- или писать событие в Stream;
- или использовать отдельную durable queue.

## Production checklist

- отдельные publisher/subscriber connections;
- reconnect handling;
- message size limits;
- JSON validation;
- auth и tenant isolation;
- graceful shutdown;
- metrics по publish/receive;
- fallback для Redis outage.

## Мини-шпаргалка

- Redis Pub/Sub связывает WebSocket-инстансы.
- Pub/Sub не хранит offline messages.
- Для приватных событий используй tenant/user channels.
- Subscriber connection нельзя использовать как обычный command connection.
- Для durable notifications нужна БД или Streams.
