# Как жизненный цикл связан с Virtual DOM?

> [!summary]
> Virtual DOM связан с жизненным циклом через render и reconciliation. При mount React создает первое дерево элементов, при update получает новое дерево, сравнивает его со старым и на commit-этапе применяет изменения к реальному DOM.

## На mount

```text
component render -> React elements -> DOM creation -> commit
```

React впервые получает описание UI и создает DOM-узлы.

## На update

```text
old tree + new tree -> reconciliation -> DOM updates
```

Компонент возвращает новое описание UI:

```jsx
function Counter({ count }) {
  return <button>Счет: {count}</button>
}
```

React сравнивает старый и новый результат.

## Где участвует key?

В списках `key` помогает React сопоставлять элементы:

```jsx
{items.map((item) => (
  <TodoItem key={item.id} item={item} />
))}
```

Без стабильного key lifecycle дочерних компонентов может вести себя неожиданно: state может сохраняться или сбрасываться не там, где ты ожидаешь.

## Virtual DOM не равен DOM

React element - это описание:

```jsx
<h1>React</h1>
```

Реальный DOM node - браузерный объект на странице. React меняет его только на commit-этапе.

## Мини-шпаргалка

- Virtual DOM участвует в render/reconciliation.
- На mount создается первое дерево UI.
- На update React сравнивает старое и новое дерево.
- Commit применяет изменения к настоящему DOM.
- `key` влияет на сохранение state и lifecycle в списках.
