# Что делает useId?

> [!summary]
> `useId` генерирует стабильный уникальный id, который удобно использовать для accessibility-атрибутов: `htmlFor`, `aria-describedby`, `aria-labelledby`. Он особенно полезен в SSR, потому что помогает избежать несовпадения id на сервере и клиенте.

## Базовый пример

```jsx
function EmailField() {
  const id = useId()

  return (
    <div>
      <label htmlFor={id}>Email</label>
      <input id={id} type="email" />
    </div>
  )
}
```

`label` связан с `input` через один id.

## Несколько связанных id

```jsx
function PasswordField() {
  const id = useId()
  const hintId = `${id}-hint`

  return (
    <div>
      <label htmlFor={id}>Пароль</label>
      <input id={id} aria-describedby={hintId} type="password" />
      <p id={hintId}>Минимум 8 символов</p>
    </div>
  )
}
```

## Почему не Math.random?

Плохо:

```jsx
const id = Math.random().toString()
```

Так id будет меняться при render и может не совпасть между сервером и клиентом.

`useId` создан именно для стабильных id в React-дереве.

## Когда useId не подходит?

Не используй `useId` как key в списках:

```jsx
items.map((item) => <Row key={useId()} />)
```

Keys должны приходить из данных: `item.id`, `slug`, стабильный идентификатор сущности.

## Мини-шпаргалка

- `useId` генерирует id для accessibility.
- Подходит для `label`, `aria-describedby`, `aria-labelledby`.
- Не используй `Math.random()` для id в render.
- Не используй `useId` для keys в списках.
- Особенно полезен в SSR.
