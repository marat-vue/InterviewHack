# Как подключать plugins: admin, twoFactor, organization, username, magic link?

> [!NOTE]
> Better Auth расширяется plugins. Plugin обычно подключается дважды: server plugin в `betterAuth({ plugins: [...] })` и client plugin в `createAuthClient({ plugins: [...] })`, если plugin добавляет client-side методы или flow.

## Server plugin

```ts
import { betterAuth } from 'better-auth';
import { twoFactor } from 'better-auth/plugins';

export const auth = betterAuth({
  plugins: [
    twoFactor(),
  ],
});
```

## Client plugin

```ts
import { createAuthClient } from 'better-auth/vue';
import { twoFactorClient } from 'better-auth/client/plugins';

export const authClient = createAuthClient({
  plugins: [
    twoFactorClient(),
  ],
});
```

## Admin plugin

Admin plugin нужен для:

- управления пользователями;
- ролей уровня приложения;
- permissions;
- impersonation;
- admin operations.

Используй, если в проекте реально есть админка. Admin capabilities должны быть закрыты строгим authorization.

## Two Factor plugin

Two Factor plugin добавляет 2FA flow.

Задачи:

- генерировать/проверять OTP;
- хранить 2FA state;
- отправлять OTP;
- обрабатывать второй шаг входа.

Пример:

```ts
twoFactor({
  otpOptions: {
    async sendOTP({ user, otp }) {
      await emailService.sendOtp(user.email, otp);
    },
  },
});
```

## Organization plugin

Organization plugin нужен для SaaS:

- organizations;
- members;
- invitations;
- organization roles;
- team access.

Если у приложения есть workspace/team model, organization plugin часто лучше, чем одно поле `user.role`.

## Username plugin

Username plugin добавляет username-based flows:

- username field;
- sign in by username;
- validation username;
- profile URLs.

Полезно для social/community apps.

## Magic link plugin

Magic link позволяет входить по ссылке из email без password.

Нужно:

- email provider;
- short-lived tokens;
- правильный redirect;
- rate limit;
- защита от email enumeration.

## Plugin schema

После добавления plugin:

```bash
npx auth@latest generate --config server/utils/auth.ts
npx prisma migrate dev --name add_auth_plugin
```

Почти любой stateful plugin добавляет таблицы/поля.

## Как выбирать plugins?

| Нужно | Plugin |
|---|---|
| Админка пользователей | `admin` |
| 2FA | `twoFactor` |
| SaaS workspaces | `organization` |
| Username login | `username` |
| Passwordless email login | `magicLink` |
| Passkeys | `passkey` |
| Email OTP | `emailOTP` |

Точные имена imports и options проверяй в документации конкретного plugin.

## Мини-шпаргалка

- Server plugin добавляется в `betterAuth`.
- Client plugin добавляется в `createAuthClient`.
- После plugin обновляй Prisma schema.
- Admin/organization plugins требуют особенно аккуратного authorization.
- 2FA/magic link требуют email/SMS provider и rate limit.
- Не подключай plugin "на всякий случай": каждый plugin расширяет surface area и schema.
