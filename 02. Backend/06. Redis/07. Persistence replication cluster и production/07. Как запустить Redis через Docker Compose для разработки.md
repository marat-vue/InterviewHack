# Как запустить Redis через Docker Compose для разработки?

> [!NOTE]
> Docker Compose удобен для локального backend stack: Node.js API, PostgreSQL и Redis можно поднимать одной командой. Для Redis важно добавить volume, healthcheck и отдельный пароль хотя бы в development-like окружении.

## Минимальный compose

```yaml
services:
  redis:
    image: redis:latest
    ports:
      - "6379:6379"
```

Запуск:

```bash
docker compose up -d redis
```

## Compose с password, AOF и healthcheck

```yaml
services:
  redis:
    image: redis:latest
    command:
      - redis-server
      - --appendonly
      - "yes"
      - --requirepass
      - local_password
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "local_password", "PING"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  redis-data:
```

## REDIS_URL для приложения

Если приложение снаружи Docker:

```bash
REDIS_URL="redis://default:local_password@localhost:6379"
```

Если приложение внутри той же compose network:

```bash
REDIS_URL="redis://default:local_password@redis:6379"
```

## Проверка

```bash
docker compose exec redis redis-cli -a local_password PING
```

Посмотреть logs:

```bash
docker compose logs -f redis
```

## Что не копировать в production blindly?

- открытый порт `6379` наружу;
- простой пароль;
- latest tag без pinning;
- отсутствие TLS/private network;
- отсутствие monitoring;
- отсутствие backup;
- небезопасный `protected-mode no`.

## Мини-шпаргалка

- Compose хорош для dev.
- Volume нужен для persistence.
- Healthcheck помогает API ждать Redis.
- Внутри compose host = service name `redis`.
- Не открывай Redis публично.
