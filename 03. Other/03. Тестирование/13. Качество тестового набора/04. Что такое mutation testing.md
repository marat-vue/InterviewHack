# Что такое mutation testing?

> [!summary]
> Mutation testing проверяет качество тестов через намеренные изменения кода. Если тесты не падают после маленькой мутации, значит они выполняют код, но недостаточно хорошо проверяют поведение.

## Простая идея

Допустим, есть код:

```ts
function isAdult(age: number) {
  return age >= 18;
}
```

Mutation testing может заменить `>=` на `>`:

```ts
function isAdult(age: number) {
  return age > 18;
}
```

Если тесты не упали, значит сценарий `age = 18` не проверен.

## Чем отличается от coverage?

Coverage может сказать:

```text
Строка выполнена.
```

Mutation testing спрашивает:

```text
Тест действительно заметит, если логика изменится?
```

Это более строгий сигнал качества.

## Пример слабого теста

```ts
expect(isAdult(20)).toBe(true);
```

Он не поймает ошибку на границе.

Лучше:

```ts
expect(isAdult(17)).toBe(false);
expect(isAdult(18)).toBe(true);
```

## Когда использовать?

Mutation testing полезен:

- для критичной бизнес-логики;
- в библиотеках;
- для validators;
- для финансовых расчетов;
- когда coverage высокий, но доверия к тестам мало.

Минусы:

- медленнее обычных тестов;
- требует настройки;
- не всегда нужен на каждый commit.

## Мини-шпаргалка

- Mutation testing проверяет силу тестов.
- Coverage показывает выполнение, mutation - способность ловить изменения.
- Особенно полезен для критичной логики.
- Не обязательно запускать на каждый PR.
- Граничные значения часто всплывают именно через mutations.
