# Как работают ports и expose?

> [!summary]
> `EXPOSE` в Dockerfile документирует порт внутри контейнера, а `ports` или `-p` публикуют порт контейнера на host. Чтобы открыть сервис в браузере на локальной машине, нужен именно port publishing.

## Два разных порта

У контейнера есть свой network namespace. Если приложение слушает порт `3000` внутри контейнера, это еще не значит, что он доступен на host.

```text
host:8080 -> container:3000
```

Команда:

```bash
docker run -p 8080:3000 my-api
```

Теперь host-порт `8080` ведет к container-порту `3000`.

## Что делает EXPOSE?

```dockerfile
EXPOSE 3000
```

`EXPOSE` не публикует порт на host. Он только документирует, какой порт ожидаемо слушает приложение внутри container.

Для реального доступа нужно:

```bash
docker run -p 3000:3000 my-api
```

или в Compose:

```yaml
services:
  api:
    build: .
    ports:
      - "3000:3000"
```

## ports в Compose

```yaml
ports:
  - "8080:80"
```

Формат:

```text
HOST:CONTAINER
```

Если перепутать порядок, приложение будет недоступно.

## expose в Compose

```yaml
expose:
  - "3000"
```

`expose` делает порт доступным для других контейнеров в сети Compose, но не публикует его на host.

Для frontend/backend разработки обычно:

- backend публикуют наружу: `3000:3000`;
- database часто публикуют наружу только для локального доступа из IDE;
- internal services можно оставить без `ports`.

## Пример

```yaml
services:
  api:
    build: .
    ports:
      - "3000:3000"
    depends_on:
      - db

  db:
    image: postgres:18
    expose:
      - "5432"
```

`api` может подключиться к `db:5432`, но host не сможет подключиться к базе через `localhost:5432`, потому что у `db` нет `ports`.

## Что отвечать на собеседовании?

`EXPOSE` и `expose` документируют или открывают порт внутри docker-сети, но не публикуют его на host. Для доступа с host нужен `-p` в `docker run` или `ports` в Compose. Формат `HOST:CONTAINER`: например, `8080:80` означает порт 8080 на машине ведет на порт 80 внутри контейнера.

## Частые ошибки

- Думать, что `EXPOSE` достаточно для браузера.
- Путать порядок `host:container`.
- Публиковать наружу database ports в production без необходимости.
- Подключаться из контейнера к `localhost`, ожидая другой контейнер.
- Использовать одинаковый host port для нескольких services.

## Мини-шпаргалка

- `EXPOSE` - документация container port.
- `-p 8080:80` - host 8080 -> container 80.
- Compose `ports` публикует порт на host.
- Compose `expose` оставляет порт внутри сети.
- Между контейнерами ходят по имени service.
- `localhost` внутри container - это сам container.
