# Что произойдет, если изменить props напрямую?

> [!summary]
> Прямое изменение props может привести к непредсказуемым багам: React не обязан заметить мутацию, родитель потеряет контроль над данными, а другие компоненты могут получить измененный объект без явного обновления.

## Пример мутации props

```jsx
function CartItem({ item }) {
  item.quantity += 1

  return <p>{item.title}: {item.quantity}</p>
}
```

На первый взгляд значение может измениться, но это неправильная модель. Компонент меняет данные во время render.

## Почему React может не обновить UI?

React часто ориентируется на новые значения и ссылки:

```jsx
setUser(user)
```

Если объект тот же самый, React может считать, что состояние не изменилось. При мутации:

```jsx
user.name = 'Мария'
setUser(user)
```

ссылка остается прежней, поэтому обновление может не дать ожидаемого результата.

## Какие баги возникают?

- UI не обновился.
- Обновился не тот компонент.
- Старые данные внезапно изменились.
- Состояние в DevTools выглядит странно.
- `memo` перестал работать ожидаемо.
- Тесты становятся нестабильными.

## Правильный способ

Создавать новое значение:

```jsx
setUser({
  ...user,
  name: 'Мария',
})
```

Для массива:

```jsx
setItems(items.map((item) =>
  item.id === id
    ? { ...item, quantity: item.quantity + 1 }
    : item
))
```

## Почему это связано с иммутабельностью?

Иммутабельность помогает React и разработчику видеть изменения явно:

```text
старый объект !== новый объект
```

Так проще сравнивать данные, оптимизировать render и искать источник изменений.

## Мини-шпаргалка

- Мутация props нарушает однонаправленный поток данных.
- React может не увидеть изменение, если ссылка не изменилась.
- Объекты и массивы нужно обновлять через копию.
- Не меняй данные во время render.
- Если нужно изменить данные родителя, вызывай callback.
