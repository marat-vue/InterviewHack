# Какие ошибки бывают при работе с Vuetify?

> [!summary]
> Большинство проблем с Vuetify связано с отсутствующим `v-app`, неправильным импортом styles/icons, чрезмерной кастомизацией компонентов, непониманием slots и конфликтами с собственным CSS или Tailwind.

## Нет v-app

Плохо:

```vue
<template>
  <RouterView />
</template>
```

Лучше:

```vue
<template>
  <v-app>
    <v-main>
      <RouterView />
    </v-main>
  </v-app>
</template>
```

Без `v-app` часть layout, overlays и themes может работать неправильно.

## Не импортированы стили

```typescript
import "vuetify/styles";
```

Если забыть стили, компоненты будут выглядеть сломанно.

## Неправильный подход к кастомизации

Плохо: переписывать глубокие внутренние классы каждого компонента.

Лучше:

- использовать props;
- использовать theme;
- использовать defaults;
- использовать slots;
- делать wrapper components для повторяющихся паттернов.

## Конфликт с Tailwind

Vuetify и Tailwind можно совмещать, но нужно понимать границу:

- Vuetify отвечает за готовые компоненты;
- Tailwind - за layout/custom utility styling;
- не стоит одновременно бороться с Vuetify styles через десятки utility classes.

## Мини-шпаргалка

- Проверь наличие `v-app`.
- Импортируй `vuetify/styles`.
- Icons нужно подключать отдельно, если они используются.
- Кастомизируй через props/theme/defaults/slots.
- Не превращай Vuetify components в бесконечную CSS-войну.
