# Какие ошибки в Nitro, Prisma, Better Auth и Vitest встречаются чаще всего?

> [!NOTE]
> Большинство ошибок в Nitro stack связаны не с синтаксисом, а с границами ответственности: handler делает слишком много, PrismaClient создается на каждый request, auth путается с authorization, cache применяется к приватным данным, тесты не изолируют БД.

## Ошибки Nitro

| Ошибка | Почему плохо | Как исправить |
|---|---|---|
| Handler содержит всю бизнес-логику | сложно тестировать и читать | вынести service/repository |
| Middleware случайно возвращает value | route handler не выполняется | не возвращать value без early response |
| Нет validation | runtime input ломает логику | `readValidatedBody`, `getValidatedQuery` |
| Кешируется `/api/me` | можно отдать чужие данные | не кешировать user-specific routes |
| CORS `*` с cookies | cookies не работают/небезопасно | strict origins + credentials |
| Большой body без limit | DoS риск | `assertBodySize` |

## Ошибки Prisma

| Ошибка | Почему плохо | Как исправить |
|---|---|---|
| `new PrismaClient()` в каждом handler | connection leak | singleton |
| `include: { hugeRelation: true }` | тяжелые ответы | `select`, pagination |
| Нет индекса на FK/filter | медленные queries | `@@index` |
| `db push` в production | нет migration history | `migrate deploy` |
| Raw SQL через string concat | SQL injection | `$queryRaw` template |
| Нет test database | тесты портят dev/prod data | отдельная DB |

## Ошибки Better Auth

| Ошибка | Почему плохо | Как исправить |
|---|---|---|
| Неверный catch-all route | auth endpoints 404 | проверить `api/auth/[...all].ts` |
| Не применена generated schema | runtime DB errors | `auth generate` + Prisma migration |
| Неверный `BETTER_AUTH_URL` | cookies/OAuth ломаются | production URL |
| Secret в public config | утечка секрета | env/platform secrets |
| Auth без rate limit | brute force риск | limiter на auth endpoints |
| Session есть, но permissions нет | user делает лишнее | `requireRole/requirePermission` |

## Ошибки Vitest

| Ошибка | Почему плохо | Как исправить |
|---|---|---|
| Тесты зависят от порядка | flaky tests | isolation/cleanup |
| Не чистятся mocks | ложные positives/negatives | `afterEach(vi.clearAllMocks)` |
| Fake timers не возвращаются | ломает другие tests | `vi.useRealTimers` |
| Env stubs остаются | tests влияют друг на друга | `vi.unstubAllEnvs` |
| Prisma data не чистится | unique conflicts | cleanup/transactions |
| Nuxt runtime тестируют обычным Vitest | auto imports падают | `@nuxt/test-utils` |

## Ошибки @nuxt/test-utils

| Ошибка | Почему плохо | Как исправить |
|---|---|---|
| Нет `@vue/test-utils` | `mountSuspended` падает | установить peer dependency |
| Не подключен module | Nuxt env неполный | `@nuxt/test-utils/module` |
| `registerEndpoint` после mount | mock не применяется | регистрировать до mount |
| Путают runtime и e2e helpers | неправильный уровень теста | runtime для component, e2e для app |
| Не проверяют raw response | status/cookies теряются | использовать `fetch`, не `$fetch` |

## Мини-шпаргалка

- Handler должен быть тонким.
- PrismaClient должен быть singleton.
- Cache не должен отдавать private data.
- Better Auth session не заменяет permissions.
- Tests должны быть изолированными.
- Nuxt runtime требует `@nuxt/test-utils`.
