# Почему enum часто считают антипаттерном в TS

> [!summary] Коротко
> `enum` часто считают антипаттерном, потому что он добавляет runtime-код, имеет особенности с числовыми значениями и часто хуже сочетается с JavaScript-экосистемой, чем union строковых литералов.

## Вопрос

Почему `enum` часто считают антипаттерном в TypeScript?

## Enum создает runtime-код

```typescript
enum Status {
  Loading = "loading",
  Success = "success",
  Error = "error",
}
```

В отличие от `type`, обычный `enum` существует после компиляции в JavaScript. Это не всегда плохо, но важно помнить, что это не чистая типовая конструкция.

## Числовые enum могут быть неожиданными

```typescript
enum Direction {
  Up,
  Down,
}

let direction: Direction = 123; // в некоторых сценариях числовые enum слишком широкие
```

Числовые enum исторически имеют поведение, которое может ослаблять строгую модель.

## Частая альтернатива: literal union

```typescript
type Status = "loading" | "success" | "error";

function render(status: Status) {
  switch (status) {
    case "loading":
      return "Загрузка";
    case "success":
      return "Готово";
    case "error":
      return "Ошибка";
  }
}
```

Literal union не добавляет runtime-код и хорошо работает с discriminated union.

## Альтернатива с объектом

Если нужны значения на runtime, можно использовать объект `as const`.

```typescript
const Status = {
  Loading: "loading",
  Success: "success",
  Error: "error",
} as const;

type Status = (typeof Status)[keyof typeof Status];
```

## Когда enum уместен

`enum` может быть нормальным выбором в кодовой базе, где он уже принят, или когда нужен явный runtime-объект и команда понимает его особенности.

## Мини-шпаргалка

- `enum` существует на runtime.
- String literal union часто проще и легче.
- `as const` объект дает runtime-значения без enum.
- Не смешивай enum и строки без явной причины.
