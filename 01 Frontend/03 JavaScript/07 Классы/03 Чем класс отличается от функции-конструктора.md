# Чем класс отличается от функции-конструктора?

> [!NOTE]
> `class` использует прототипы, как функция-конструктор, но имеет более строгие правила и удобный синтаксис.

## Вопрос

Если классы - это синтаксический сахар над прототипами, чем они реально отличаются от функций-конструкторов?

## Функция-конструктор

```javascript
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

const user = new User('Ann');
```

## Класс

```javascript
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    return `Hi, ${this.name}`;
  }
}

const user = new User('Ann');
```

Оба варианта создают объекты с методами в прототипе.

## Важные отличия

| Отличие | Функция-конструктор | `class` |
| --- | --- | --- |
| Вызов без `new` | возможен, но опасен | `TypeError` |
| Strict mode | не обязательно | всегда strict mode внутри |
| Методы | нужно писать в `prototype` | удобный синтаксис внутри класса |
| Hoisting | функция доступна до объявления | class declaration в TDZ |
| Наследование | вручную через прототипы | `extends` и `super` |

## Пример strict-поведения

```javascript
class User {}

User(); // TypeError: Class constructor User cannot be invoked without 'new'
```

## Практический вывод

Классы не вводят классическое ООП как в Java или C#. Они дают удобный и строгий синтаксис поверх прототипной модели JavaScript.

## Мини-шпаргалка

```javascript
class User {} // удобнее и строже
function User() {} // старый паттерн конструктора
```
