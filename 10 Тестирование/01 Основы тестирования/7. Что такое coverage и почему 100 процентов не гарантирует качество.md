# Что такое coverage и почему 100 процентов не гарантирует качество?

> [!summary]
> Coverage показывает, какая часть кода была выполнена во время тестов. Это полезная метрика, но она не говорит, насколько хорошо тесты проверяют поведение и важные риски.

## Что такое coverage?

Coverage отвечает на вопрос: "Какие строки, ветки, функции или statements были выполнены тестами?"

Типичные метрики:

| Метрика | Что показывает |
|---|---|
| statements | выполненные инструкции |
| lines | выполненные строки |
| functions | вызванные функции |
| branches | проверенные ветки `if`, `switch`, ternary |

## Пример высокого, но плохого покрытия

```ts
test('calls function', () => {
  calculateTotal([{ price: 100 }]);

  expect(true).toBe(true);
});
```

Функция выполнена, coverage вырос, но результат не проверен.

## Пример полезного теста

```ts
test('calculates total with quantity', () => {
  const result = calculateTotal([
    { price: 100, quantity: 2 },
    { price: 50, quantity: 1 },
  ]);

  expect(result).toBe(250);
});
```

Этот тест проверяет реальное поведение.

## Когда coverage полезен?

Coverage полезен, чтобы:

- находить полностью непокрытые участки;
- замечать забытые branches;
- контролировать критичные модули;
- видеть динамику в CI.

Но coverage нельзя использовать как единственный показатель качества.

## Почему 100 процентов не гарантирует качество?

Потому что тест может:

- не проверять assertions;
- проверять не то поведение;
- не покрывать важные бизнес-сценарии;
- не проверять integration cases;
- быть завязанным на реализацию.

## Мини-шпаргалка

- Coverage показывает выполнение кода, а не качество проверок.
- Branch coverage часто полезнее line coverage.
- 100 процентов coverage не означает отсутствие багов.
- Низкий coverage помогает найти слепые зоны.
- Главное - покрывать риски и поведение.
