# Как выбрать архитектуру Nuxt проекта?

> [!summary]
> Архитектура Nuxt зависит от продукта: публичный сайт, ecommerce, dashboard, docs, SaaS или full-stack app. Хорошее решение разделяет UI, composables, server API, shared types, domain logic и integration code.

## Маленький сайт

```text
app/
  pages/
  components/
  assets/
nuxt.config.ts
```

Подходит для:

- landing;
- portfolio;
- простой blog.

## Content/docs project

```text
app/
  pages/
  components/
content/
server/
  api/
```

Часто нужны:

- Nuxt Content;
- Nuxt SEO;
- Sitemap;
- OG Image;
- SSG/ISR.

## SaaS/dashboard

```text
app/
  pages/
    dashboard/
    settings/
  components/
  composables/
  middleware/
  plugins/
server/
  api/
shared/
  types/
  utils/
```

Важны:

- auth middleware;
- API client;
- routeRules для public/private zones;
- Pinia/useState;
- server API as BFF.

## Где держать domain logic?

Если логика используется и на клиенте, и на сервере:

```text
shared/utils/
shared/types/
```

Если логика server-only:

```text
server/utils/
```

Если логика UI-only:

```text
app/composables/
app/utils/
```

## Мини-шпаргалка

- Архитектура зависит от типа продукта.
- Public pages и private dashboard часто имеют разные rendering modes.
- `shared/` только для кода без browser/server-specific зависимостей.
- Server-only logic держи в `server/`.
- UI behavior держи в components/composables.
