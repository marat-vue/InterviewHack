# Какие задачи решают layout-компоненты?

> [!summary]
> Layout-компоненты решают задачи общей структуры, переиспользования интерфейса, сохранения состояния при навигации, разделения приложения на зоны, подключения провайдеров и централизованной настройки metadata.

## 1. Общая структура страниц

Layout позволяет один раз описать повторяющиеся части интерфейса:

```tsx
export default function MarketingLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <>
      <Header />
      <main>{children}</main>
      <Footer />
    </>
  )
}
```

Так страницы не дублируют шапку, подвал, сайдбар, сетку и базовую разметку.

## 2. Разные оболочки для разных разделов

У приложения часто есть несколько зон:

- публичный сайт;
- личный кабинет;
- админ-панель;
- документация;
- блог;
- страница авторизации.

Для каждой зоны можно сделать свой layout:

```text
app/
  (site)/
    layout.tsx
    page.tsx
  dashboard/
    layout.tsx
    page.tsx
  admin/
    layout.tsx
    page.tsx
```

Это особенно удобно, когда у разделов разные меню, отступы, темы оформления или правила доступа.

## 3. Сохранение UI при навигации

При переходе между вложенными страницами layout не размонтируется. Поэтому в нем может сохраняться состояние интерфейса:

- открытый/закрытый сайдбар;
- активная вкладка;
- состояние плеера;
- выбранная тема;
- прокрутка в общей области;
- загруженные общие элементы навигации.

Если пользователь переходит с `/dashboard/users` на `/dashboard/settings`, `DashboardLayout` остается на месте, а меняется только вложенная страница.

## 4. Подключение провайдеров

Layout часто используют для провайдеров:

```tsx
// app/providers.tsx
'use client'

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider>
      <QueryClientProvider client={queryClient}>
        {children}
      </QueryClientProvider>
    </ThemeProvider>
  )
}
```

```tsx
// app/layout.tsx
import { Providers } from './providers'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  )
}
```

Так Root Layout остается серверным, а клиентская логика вынесена в отдельный компонент.

## 5. Авторизация и серверные проверки

Layout может быть Server Component, поэтому в нем можно читать серверные данные:

```tsx
// app/dashboard/layout.tsx
import { redirect } from 'next/navigation'
import { getCurrentUser } from '@/lib/auth'

export default async function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  const user = await getCurrentUser()

  if (!user) {
    redirect('/login')
  }

  return <main>{children}</main>
}
```

Это удобно для защиты целого раздела, а не каждой страницы отдельно.

## 6. Metadata и SEO

Layout может задавать metadata для группы страниц:

```tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    template: '%s | Dashboard',
    default: 'Dashboard',
  },
  robots: {
    index: false,
    follow: false,
  },
}
```

Страницы внутри раздела могут уточнять title, description и Open Graph, а layout задает общий шаблон.

## Что отвечать на собеседовании?

Layout-компоненты в Next.js нужны, чтобы не дублировать общую структуру страниц, строить вложенные оболочки маршрутов, сохранять UI между переходами, подключать провайдеры и настраивать metadata для целых разделов приложения.

## Частые ошибки

- Использовать layout только как визуальную обертку и забывать про навигационную структуру.
- Подключать тяжелые клиентские провайдеры в Root Layout без необходимости.
- Проверять доступ на каждой странице, хотя можно защитить весь раздел layout.
- Класть route-specific данные слишком высоко в дереве.
- Дублировать одинаковые Header/Footer в разных `page.tsx`.

## Мини-шпаргалка

- Layout убирает дублирование.
- Layout задает общую оболочку раздела.
- Layout сохраняется при вложенной навигации.
- Layout удобен для providers.
- Layout может проверять доступ к разделу.
- Layout может задавать metadata.
