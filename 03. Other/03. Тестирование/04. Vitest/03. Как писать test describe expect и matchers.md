# Как писать test, describe, expect и matchers?

> [!summary]
> В Vitest тесты пишут через `test` или `it`, группируют через `describe`, а результат проверяют через `expect` и matchers. Matchers описывают, что именно должно быть истинно: равенство, наличие, тип, ошибку, вызов mock-функции.

## Базовый пример

```ts
import { describe, expect, test } from 'vitest';

describe('formatPrice', () => {
  test('formats RUB price', () => {
    expect(formatPrice(1200, 'RUB')).toBe('1 200 ₽');
  });
});
```

`describe` группирует тесты, `test` описывает сценарий, `expect` делает проверку.

## `toBe` и `toEqual`

`toBe` проверяет строгое равенство:

```ts
expect(2 + 2).toBe(4);
```

`toEqual` проверяет структуру объекта:

```ts
expect(user).toEqual({
  id: 1,
  name: 'Ann',
});
```

## Частые matchers

```ts
expect(value).toBeTruthy();
expect(value).toBeFalsy();
expect(items).toHaveLength(3);
expect(text).toContain('Hello');
expect(user).toHaveProperty('email');
expect(fn).toHaveBeenCalled();
expect(fn).toHaveBeenCalledWith(1, 2);
```

## Проверка ошибок

```ts
expect(() => parseJson('{')).toThrow();
expect(() => parseJson('{')).toThrow('Invalid JSON');
```

Для async errors:

```ts
await expect(loadUser(404)).rejects.toThrow('User not found');
```

## `it` или `test`?

`it` и `test` почти взаимозаменяемы:

```ts
it('returns user initials', () => {
  expect(getInitials('Anna Smith')).toBe('AS');
});
```

Главное - единый стиль в проекте.

## Мини-шпаргалка

- `describe` группирует сценарии.
- `test` или `it` объявляет тест.
- `expect` начинает проверку.
- `toBe` - строгое равенство.
- `toEqual` - глубокое сравнение объектов.
- Async errors проверяют через `rejects`.
