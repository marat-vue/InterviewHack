# Как использовать mocks, spies и module mocks в Jest?

> [!summary]
> Jest предоставляет `jest.fn`, `jest.spyOn` и `jest.mock`. Они помогают заменять зависимости, проверять вызовы функций и управлять поведением модулей в тестах.

## `jest.fn`

```ts
const onSave = jest.fn();

onSave({ id: 1 });

expect(onSave).toHaveBeenCalledWith({ id: 1 });
```

Можно задать результат:

```ts
const getUser = jest.fn().mockResolvedValue({
  id: 1,
  name: 'Ann',
});
```

## `jest.spyOn`

```ts
const spy = jest.spyOn(console, 'error').mockImplementation(() => {});

handleError(new Error('Boom'));

expect(spy).toHaveBeenCalled();

spy.mockRestore();
```

Spy удобен, когда нужно наблюдать за существующим методом.

## `jest.mock`

```ts
jest.mock('../api/users', () => ({
  getUser: jest.fn(),
}));
```

Дальше можно настроить mock:

```ts
import { getUser } from '../api/users';

(getUser as jest.Mock).mockResolvedValue({ id: 1, name: 'Ann' });
```

## Очистка mocks

```ts
afterEach(() => {
  jest.clearAllMocks();
});
```

Разница:

- `clearAllMocks` очищает calls/results;
- `resetAllMocks` сбрасывает mock implementations;
- `restoreAllMocks` восстанавливает оригинальные spies.

## Мини-шпаргалка

- `jest.fn` создает mock-функцию.
- `jest.spyOn` следит за существующим методом.
- `jest.mock` подменяет модуль.
- `mockResolvedValue` задает успешный promise.
- `mockRejectedValue` задает ошибку promise.
- Mocks нужно чистить между тестами.
