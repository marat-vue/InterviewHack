# Как тестировать Better Auth flow в Nuxt Nitro?

> [!NOTE]
> Better Auth flow лучше тестировать как integration/e2e: поднять Nuxt/Nitro app, выполнить sign up или sign in через auth endpoint/client, сохранить cookies и проверить protected route. Unit-тестами стоит покрывать свои guards и permission logic.

## Что нужно проверить?

Минимальный auth checklist:

- anonymous user получает `401` на protected route;
- sign up создает пользователя;
- sign in ставит session cookie;
- `/api/me` возвращает текущего пользователя;
- sign out удаляет/отзывает session;
- invalid password не раскрывает лишнюю информацию;
- protected admin route возвращает `403` без role.

## Protected route

```ts
// server/api/me.get.ts
export default defineEventHandler(async (event) => {
  const session = await requireAuth(event);

  return {
    user: session.user,
  };
});
```

## Проверка anonymous

```ts
import { describe, expect, it } from 'vitest';
import { setup, fetch } from '@nuxt/test-utils/e2e';

describe('auth flow', async () => {
  await setup();

  it('rejects anonymous user', async () => {
    const response = await fetch('/api/me');

    expect(response.status).toBe(401);
  });
});
```

## Sign in через raw fetch

```ts
const signInResponse = await fetch('/api/auth/sign-in/email', {
  method: 'POST',
  body: JSON.stringify({
    email: 'anna@example.com',
    password: 'password1234',
  }),
  headers: {
    'content-type': 'application/json',
  },
});

const cookie = signInResponse.headers.get('set-cookie');

expect(cookie).toBeTruthy();
```

Точный path endpoint зависит от Better Auth base path и версии. Если route отличается, проверь mounted Better Auth endpoints в документации/config.

## Request с cookie

```ts
const meResponse = await fetch('/api/me', {
  headers: {
    cookie: cookie!,
  },
});

expect(meResponse.status).toBe(200);
```

## Test database

Auth flow tests должны использовать test database:

```bash
DATABASE_URL="postgresql://test:test@localhost:5432/app_test"
```

Перед тестом:

```bash
npx prisma migrate deploy
```

После тестов чистить таблицы:

```ts
afterEach(async () => {
  await prisma.session.deleteMany();
  await prisma.account.deleteMany();
  await prisma.user.deleteMany();
});
```

Имена моделей зависят от generated Better Auth Prisma schema.

## Unit-test guards отдельно

```ts
it('throws 401 without session', async () => {
  vi.mocked(auth.api.getSession).mockResolvedValue(null);

  await expect(requireAuth(fakeEvent)).rejects.toMatchObject({
    statusCode: 401,
  });
});
```

## Мини-шпаргалка

- Better Auth flow тестируется integration/e2e.
- Anonymous protected route -> `401`.
- Sign in должен вернуть session cookie.
- Protected request должен отправлять cookie.
- Test DB обязательна.
- Твои `requireAuth/requireRole` покрывай unit-тестами.
- Не тестируй internals Better Auth, тестируй свою интеграцию.
