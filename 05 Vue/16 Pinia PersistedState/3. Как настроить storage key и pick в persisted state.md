# Как настроить storage, key и pick в persisted state?

> [!summary]
> Persisted state можно настроить: выбрать storage, задать ключ, сохранить только нужные поля через `pick` и избежать записи временного или чувствительного state.

## Базовая настройка

```typescript
export const useSettingsStore = defineStore("settings", {
  state: () => ({
    theme: "light",
    language: "ru",
    isSaving: false,
  }),
  persist: {
    key: "app-settings",
    pick: ["theme", "language"],
  },
});
```

`isSaving` не сохраняется, потому что это временный UI-флаг.

## Выбор storage

```typescript
persist: {
  storage: sessionStorage,
}
```

`localStorage` переживает закрытие браузера. `sessionStorage` живет в рамках browser tab/session.

## Почему pick важен?

Плохо:

```typescript
persist: true
```

для store:

```typescript
state: () => ({
  user: null,
  accessToken: null,
  permissions: [],
  isLoading: false,
  error: null,
});
```

Так можно случайно сохранить token, ошибку или устаревшие permissions.

Лучше:

```typescript
persist: {
  pick: ["selectedOrganizationId"],
}
```

## Несколько persist configs

Для разных частей store иногда используют разные storages:

```typescript
persist: [
  {
    pick: ["theme"],
    storage: localStorage,
  },
  {
    pick: ["draft"],
    storage: sessionStorage,
  },
]
```

## Мини-шпаргалка

- `key` задает имя записи в storage.
- `storage` выбирает `localStorage`, `sessionStorage` или другой adapter.
- `pick` сохраняет только выбранные поля.
- Не сохраняй loading/error state.
- Не сохраняй tokens просто потому, что это удобно.
