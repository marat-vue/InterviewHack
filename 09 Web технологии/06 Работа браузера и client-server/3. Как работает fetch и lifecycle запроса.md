# Как работает fetch и lifecycle запроса?

> [!summary]
> `fetch` запускает HTTP request из JavaScript. Нужно понимать настройки method, headers, body, credentials, обработку status codes, JSON parsing, abort и отличие HTTP-ошибок от network errors.

## Базовый GET

```ts
const response = await fetch('/api/users');
const users = await response.json();
```

На `404` или `500` `fetch` не бросит exception. Поэтому нужно проверять:

```ts
if (!response.ok) {
  throw new Error(`Request failed: ${response.status}`);
}
```

## POST с JSON

```ts
const response = await fetch('/api/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Accept: 'application/json',
  },
  body: JSON.stringify({
    email: 'anna@example.com',
  }),
});
```

`Content-Type` описывает request body. `Accept` описывает желаемый response.

## Credentials

Для cookie auth на cross-origin:

```ts
fetch('https://api.example.com/me', {
  credentials: 'include',
});
```

Без `credentials: 'include'` cookies могут не отправиться.

## AbortController

```ts
const controller = new AbortController();

const promise = fetch('/api/search?q=vue', {
  signal: controller.signal,
});

controller.abort();
```

Abort полезен для search, route changes, component unmount.

## Network error vs HTTP error

HTTP error:

```txt
Response пришел: 404, 500, 422
```

Network-level error:

```txt
DNS failed, connection refused, CORS blocked, request aborted
```

`catch` обычно ловит именно network-level errors и aborts, а не `404`.

## Мини-шпаргалка

- `fetch` возвращает `Response`.
- Проверяй `response.ok`.
- `Content-Type` - что отправляем.
- `Accept` - что хотим получить.
- Cookies cross-origin требуют `credentials: 'include'`.
- `AbortController` отменяет request.
