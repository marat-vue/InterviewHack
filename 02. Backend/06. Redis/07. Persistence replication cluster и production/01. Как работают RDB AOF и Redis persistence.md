# Как работают RDB, AOF и Redis persistence?

> [!NOTE]
> Redis хранит dataset в памяти, но может сохранять данные на диск через RDB snapshots и AOF log. Persistence выбирают по допустимой потере данных, скорости восстановления и нагрузке.

## Что такое RDB?

RDB - point-in-time snapshot dataset.

Плюсы:

- компактный файл;
- быстрое восстановление;
- удобно для backups;
- меньше overhead при обычных writes.

Минусы:

- можно потерять данные между snapshots;
- snapshot требует fork и может дать latency/memory overhead.

## Что такое AOF?

AOF - append-only file с командами записи.

Плюсы:

- меньше потеря данных при crash;
- можно настроить fsync;
- log можно переписать compact rewrite.

Минусы:

- файл обычно больше RDB;
- может быть больше write overhead;
- rewrite требует ресурсов.

## Варианты fsync

| Режим | Trade-off |
|---|---|
| `always` | максимум durability, медленнее |
| `everysec` | хороший default, потеря до секунды |
| `no` | быстрее, durability хуже |

## Можно ли включить RDB и AOF вместе?

Да. Часто используют оба:

- RDB для backups/snapshots;
- AOF для меньшей потери последних writes.

## Docker пример с AOF

```bash
docker run --name redis-aof \
  -v redis-data:/data \
  -p 6379:6379 \
  -d redis:latest \
  redis-server --appendonly yes --appendfsync everysec
```

## Что важно проверить?

- где лежит `/data`;
- есть ли volume;
- как часто snapshots;
- AOF rewrite;
- restore procedure;
- backup encryption;
- monitoring persistence errors.

## Мини-шпаргалка

- RDB - snapshots.
- AOF - append-only log.
- `appendfsync everysec` - частый компромисс.
- Persistence не заменяет backups.
- Если Redis только cache, persistence может быть не нужна.
