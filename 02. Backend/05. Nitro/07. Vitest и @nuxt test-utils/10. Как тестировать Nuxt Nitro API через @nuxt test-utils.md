# Как тестировать Nuxt Nitro API через @nuxt/test-utils?

> [!NOTE]
> Для Nuxt server API routes удобнее всего использовать `@nuxt/test-utils/e2e`: он поднимает Nuxt/Nitro app, а тест дергает endpoints через `$fetch` или `fetch`.

## Пример API route

```ts
// server/api/health.get.ts
export default defineEventHandler(() => {
  return {
    status: 'ok',
  };
});
```

## E2E test через `$fetch`

```ts
import { describe, expect, it } from 'vitest';
import { setup, $fetch } from '@nuxt/test-utils/e2e';

describe('/api/health', async () => {
  await setup();

  it('returns ok', async () => {
    await expect($fetch('/api/health')).resolves.toEqual({
      status: 'ok',
    });
  });
});
```

`$fetch` возвращает parsed body.

## Test raw response через `fetch`

```ts
import { fetch } from '@nuxt/test-utils/e2e';

it('sets status', async () => {
  const response = await fetch('/api/health');

  expect(response.status).toBe(200);
  expect(response.headers.get('content-type')).toContain('application/json');
});
```

`fetch` полезен для проверки:

- status;
- headers;
- cookies;
- redirects;
- raw body.

## Test POST endpoint

```ts
await expect($fetch('/api/users', {
  method: 'POST',
  body: {
    email: 'anna@example.com',
    name: 'Anna',
  },
})).resolves.toMatchObject({
  email: 'anna@example.com',
});
```

## Test validation error

```ts
it('rejects invalid email', async () => {
  await expect($fetch('/api/users', {
    method: 'POST',
    body: {
      email: 'bad',
    },
  })).rejects.toThrow();
});
```

Для точного status лучше использовать raw `fetch`.

```ts
const response = await fetch('/api/users', {
  method: 'POST',
  body: JSON.stringify({ email: 'bad' }),
  headers: {
    'content-type': 'application/json',
  },
});

expect(response.status).toBe(400);
```

## Test auth route

Для protected route:

```ts
const response = await fetch('/api/me');

expect(response.status).toBe(401);
```

Для полного auth flow нужно:

1. sign up/sign in через Better Auth endpoint;
2. сохранить cookies;
3. дернуть protected endpoint с cookies.

## Когда использовать `registerEndpoint`?

`registerEndpoint` подходит для runtime/component tests, когда component вызывает `$fetch`.

Для настоящего server API e2e лучше поднять Nuxt app через `setup()` и дернуть реальный route.

## Мини-шпаргалка

- `$fetch` - parsed response.
- `fetch` - raw response.
- `setup()` поднимает Nuxt app.
- Validation/status/cookies лучше проверять через raw `fetch`.
- `registerEndpoint` - mock endpoint для runtime tests, не замена реального API e2e.
