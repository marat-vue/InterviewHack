# Как настроить maxmemory, eviction policy и TTL?

> [!NOTE]
> Redis должен иметь memory budget. Без `maxmemory`, TTL и понятной eviction policy cache может занять всю память и привести к outage.

## Что такое maxmemory?

`maxmemory` ограничивает память, которую Redis может использовать под dataset.

```redis
CONFIG SET maxmemory 512mb
```

В `redis.conf`:

```txt
maxmemory 512mb
```

## Что такое eviction policy?

Eviction policy определяет, какие ключи Redis удаляет при нехватке памяти.

Примеры:

```txt
allkeys-lru
volatile-lru
allkeys-lfu
volatile-ttl
noeviction
```

## Как выбрать policy?

| Policy | Когда выбрать |
|---|---|
| `allkeys-lru` | Redis в основном cache |
| `allkeys-lfu` | cache с повторяющимися hot keys |
| `volatile-lru` | удалять только keys с TTL |
| `volatile-ttl` | удалять keys с ближайшим TTL |
| `noeviction` | Redis как database, writes должны падать при лимите |

## Почему TTL все равно нужен?

Eviction - emergency behavior. TTL - normal lifecycle.

Cache key без TTL:

```redis
SET cache:user:1 value
```

лучше:

```redis
SET cache:user:1 value EX 300
```

## Как смотреть memory?

```redis
INFO memory
MEMORY USAGE cache:user:1
```

Что мониторить:

- `used_memory`;
- `used_memory_peak`;
- `mem_fragmentation_ratio`;
- `evicted_keys`;
- `expired_keys`;
- hit ratio.

## Мини-шпаргалка

- `maxmemory` обязателен для cache Redis.
- `allkeys-lru`/`allkeys-lfu` часты для cache.
- `noeviction` лучше для Redis как database.
- TTL - нормальная очистка.
- Eviction - аварийная очистка.
