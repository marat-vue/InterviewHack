# Как useEffect заменяет методы жизненного цикла?

> [!summary]
> `useEffect` часто покрывает сценарии `componentDidMount`, `componentDidUpdate` и `componentWillUnmount`, но мыслить им лучше не как "один lifecycle на компонент", а как отдельную синхронизацию с внешней системой.

## Аналог componentDidMount

```jsx
useEffect(() => {
  console.log('mounted')
}, [])
```

Но в Strict Mode development effect может запускаться дополнительный раз.

## Аналог componentDidUpdate

```jsx
useEffect(() => {
  document.title = title
}, [title])
```

Effect запускается после commit, когда `title` изменился.

## Аналог componentWillUnmount

```jsx
useEffect(() => {
  const subscription = subscribe()

  return () => {
    subscription.unsubscribe()
  }
}, [])
```

Cleanup выполняет очистку.

## Почему это не точная замена?

В классе lifecycle связан с компонентом:

```text
componentDidMount компонента
componentDidUpdate компонента
componentWillUnmount компонента
```

В hooks лучше думать через задачу:

```text
effect для document.title
effect для subscription
effect для analytics
```

Каждый effect синхронизирует одну внешнюю систему.

## Когда нужен useLayoutEffect?

Если код должен выполниться до browser paint, например измерение layout, `useLayoutEffect` ближе к нужному моменту выполнения.

Но для большинства внешних синхронизаций подходит `useEffect`.

## Мини-шпаргалка

- `useEffect(..., [])` похож на mount-сценарий.
- `useEffect(..., [deps])` похож на update по dependencies.
- Cleanup похож на unmount-очистку.
- Effect лучше мыслить как синхронизацию, а не lifecycle hook.
- Для layout до paint используй `useLayoutEffect`.
