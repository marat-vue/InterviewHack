# Как собирать и деплоить Nitro приложение?

> [!NOTE]
> Nitro может собрать один и тот же server code в разные output formats через deployment presets. По умолчанию production output - Node.js server, но Nitro умеет presets для Vercel, Netlify, Cloudflare, AWS Lambda, Azure, Deno, Bun и других платформ.

## Build

Standalone Nitro:

```bash
npx nitro build
```

или script:

```json
{
  "scripts": {
    "build": "nitro build",
    "start": "node .output/server/index.mjs"
  }
}
```

Nuxt:

```bash
npm run build
```

Nuxt использует Nitro для server output.

## Default output

Для Node.js production build entrypoint обычно:

```txt
.output/server/index.mjs
```

Запуск:

```bash
node .output/server/index.mjs
```

Static/public files находятся в:

```txt
.output/public
```

## Что такое preset?

Preset говорит Nitro, под какой runtime/platform собрать output.

Примеры:

| Preset | Где использовать |
|---|---|
| `node_server` | обычный Node.js server |
| `node_cluster` | Node.js cluster |
| `bun` | Bun runtime |
| `deno_server` | Deno server |
| `vercel` | Vercel |
| `netlify` | Netlify functions |
| `netlify_edge` | Netlify Edge |
| `cloudflare_pages` | Cloudflare Pages |
| `cloudflare_module` | Cloudflare Workers module |
| `aws_lambda` | AWS Lambda |
| `azure` | Azure Static Web Apps/functions |
| `firebase_app_hosting` | Firebase App Hosting |

Список provider presets регулярно расширяется, поэтому точное имя лучше проверять в Nitro deploy docs.

## Как задать preset?

Через env:

```bash
NITRO_PRESET=vercel npm run build
```

Или:

```bash
nitro build --preset cloudflare_pages
```

Или config:

```ts
export default defineConfig({
  preset: 'node_server',
});
```

Для CI/CD env-подход обычно удобнее.

## Zero-config providers

Nitro умеет auto-detect некоторых провайдеров в CI/CD, например:

- Vercel;
- Netlify;
- Cloudflare;
- Azure;
- Firebase App Hosting;
- AWS Amplify;
- Zeabur.

Но в monorepo/Turborepo strict env mode auto-detection может не сработать, поэтому preset лучше задавать явно.

## Environment variables Node preset

Для Node server полезны:

| Env | Что делает |
|---|---|
| `NITRO_PORT` или `PORT` | порт |
| `NITRO_HOST` или `HOST` | host |
| `NITRO_UNIX_SOCKET` | unix socket |
| `NITRO_SSL_CERT` и `NITRO_SSL_KEY` | HTTPS для тестов |
| `NITRO_SHUTDOWN_DISABLED` | отключить graceful shutdown |
| `NITRO_SHUTDOWN_SIGNALS` | какие signals обрабатывать |

В production HTTPS чаще терминируется reverse proxy/CDN, а не Nitro server.

## Что проверять перед deploy?

- preset соответствует платформе;
- env variables заданы;
- Prisma migrations применяются;
- Better Auth secret и URL заданы;
- cache storage подходит для нескольких инстансов;
- public assets попали в output;
- routeRules работают на выбранной платформе;
- WebSocket/tasks поддерживаются выбранным preset;
- healthcheck есть;
- logs и errors собираются.

## Мини-шпаргалка

- Build output - `.output`.
- Default production preset - Node.js server.
- Preset задается через `NITRO_PRESET`, `SERVER_PRESET`, config или CLI flag.
- Многие providers auto-detect в CI/CD.
- Для production Node запуск: `node .output/server/index.mjs`.
- Проверяй поддержку WebSocket, cron/tasks, edge APIs и persistent storage на конкретной платформе.
