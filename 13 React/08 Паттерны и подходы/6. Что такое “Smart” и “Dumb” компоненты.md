# Что такое “Smart” и “Dumb” компоненты?

> [!summary]
> Smart/Dumb - это способ разделить компонент на логику и отображение. Smart component знает, откуда взять данные и какие действия выполнить, а Dumb component получает готовые props и просто рисует UI.

## Простое определение

```text
Smart component -> данные, state, API, handlers
Dumb component  -> props, JSX, стили, отображение
```

Эта идея очень близка к Container-Presentational Pattern.

## Dumb component

Dumb component еще называют presentational component.

```jsx
function UserCard({ name, email, onRefresh }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>{email}</p>
      <button onClick={onRefresh}>Refresh</button>
    </article>
  )
}
```

Такой компонент:

- получает данные через props;
- не знает, откуда пришли данные;
- не делает запросы к API;
- не зависит от конкретного store;
- легко тестируется;
- хорошо подходит для Storybook.

## Smart component

Smart component содержит сценарий работы.

```jsx
function UserProfile({ userId }) {
  const { user, isLoading, refetch } = useUser(userId)

  if (isLoading) {
    return <UserCardSkeleton />
  }

  return (
    <UserCard
      name={user.name}
      email={user.email}
      onRefresh={refetch}
    />
  )
}
```

Он знает:

- какой hook вызвать;
- как обработать loading/error;
- какие данные передать в UI;
- какие actions выполнить.

## Современный вариант через кастомные хуки

В современном React логику часто выносят не в отдельный container-компонент, а в custom hook.

```jsx
function useUserProfile(userId) {
  const { data, isLoading, error, refetch } = useUserQuery(userId)

  return {
    user: data,
    isLoading,
    error,
    refresh: refetch,
  }
}

function UserProfile({ userId }) {
  const model = useUserProfile(userId)

  if (model.isLoading) return <UserCardSkeleton />
  if (model.error) return <ErrorMessage error={model.error} />

  return <UserCard user={model.user} onRefresh={model.refresh} />
}
```

## Когда разделение полезно?

- UI переиспользуется с разными источниками данных;
- компонент стал слишком большим;
- нужно отдельно тестировать логику и верстку;
- компонент хочется показать в Storybook без настоящего API;
- одну и ту же карточку надо использовать в разных сценариях.

## Когда можно не разделять?

Если компонент маленький, одноразовый и простой, искусственное деление создаст лишние файлы.

```text
Не каждый компонент должен быть Smart или Dumb.
Главное - не смешивать сложную бизнес-логику с большим JSX без необходимости.
```

## Мини-шпаргалка

- Smart отвечает за "что и откуда".
- Dumb отвечает за "как показать".
- Dumb получает данные через props.
- В современном React роль Smart-слоя часто выполняет custom hook.
- Паттерн помогает тестировать, переиспользовать и читать код.
