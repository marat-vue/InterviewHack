# Что такое container component?

> [!summary]
> Container component - это компонент, который отвечает за получение данных, состояние, бизнес-логику и передачу готовых данных вниз в UI-компоненты. Это архитектурный паттерн, а не специальный API React.

## Простое определение

Container отвечает на вопрос:

```text
Откуда взять данные и что с ними делать?
```

Presentational-компонент отвечает:

```text
Как эти данные показать?
```

## Пример container component

```jsx
function UserListContainer() {
  const [users, setUsers] = useState([])
  const [isLoading, setIsLoading] = useState(true)

  useEffect(() => {
    fetch('/api/users')
      .then((response) => response.json())
      .then(setUsers)
      .finally(() => setIsLoading(false))
  }, [])

  return (
    <UserList
      users={users}
      isLoading={isLoading}
    />
  )
}
```

`UserListContainer` получает данные и передает их в `UserList`.

## Presentational часть

```jsx
function UserList({ users, isLoading }) {
  if (isLoading) {
    return <p>Загрузка...</p>
  }

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  )
}
```

Этот компонент проще переиспользовать и тестировать.

## Нужен ли этот паттерн всегда?

Нет. В небольших компонентах разделение может быть лишним. Сейчас часть задач container-компонентов часто решают:

- custom hooks;
- TanStack Query;
- Zustand/Redux;
- серверные компоненты во фреймворках;
- route loaders.

Но идея разделения данных и отображения остается полезной.

## Мини-шпаргалка

- Container component отвечает за данные и логику.
- Это паттерн, а не API React.
- Он часто передает данные в presentational component.
- Не нужно выделять container для каждого маленького блока.
- Custom hooks часто заменяют container-слой.
