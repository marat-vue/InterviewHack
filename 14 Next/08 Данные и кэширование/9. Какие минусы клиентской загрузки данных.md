# Какие минусы клиентской загрузки данных?

> [!summary]
> Клиентская загрузка данных не плоха сама по себе, но у нее есть минусы: пустой первый HTML, хуже SEO, больше loading states, невозможность безопасно использовать secrets, дополнительный waterfall и рост client-side сложности.

## Пустой первый HTML

```tsx
'use client'

useEffect(() => {
  fetch('/api/products')
    .then((res) => res.json())
    .then(setProducts)
}, [])
```

Пока JS не загрузился и запрос не завершился, пользователь видит loader.

## SEO-проблемы

Если основной контент приходит только после client fetch, crawler может увидеть неполную страницу.

Для:

- статей;
- товаров;
- категорий;
- публичных профилей;
- landing pages

лучше серверная загрузка.

## Нельзя безопасно использовать secrets

Плохо:

```tsx
fetch('https://api.example.com/data', {
  headers: {
    Authorization: `Bearer ${process.env.API_TOKEN}`,
  },
})
```

Клиентский код не должен содержать secret tokens.

## Дополнительный waterfall

```text
HTML -> JS -> React render -> useEffect -> fetch -> render data
```

Серверная загрузка может сократить цепочку.

## Когда клиентская загрузка нормальна?

- поиск по input;
- infinite scroll;
- dashboard widgets;
- user-only data after login;
- optimistic UI;
- live updates;
- данные не нужны для SEO.

## Что отвечать на собеседовании?

Минусы client-side fetching - более поздний контент, SEO-риски, loading states, невозможность использовать secrets и дополнительный network waterfall. Но для интерактивных сценариев client fetching остается нормальным инструментом.

## Частые ошибки

- Демонизировать client fetching полностью.
- Грузить SEO-контент только на клиенте.
- Хранить secrets в браузере.
- Не использовать TanStack Query/SWR для сложного client cache.
- Не показывать error state.

## Мини-шпаргалка

- Минус: пустой HTML.
- Минус: SEO-риски.
- Минус: больше JS/waterfall.
- Минус: нельзя secrets.
- Плюс: интерактивность и live UI.
- Часто лучший вариант - гибрид.
