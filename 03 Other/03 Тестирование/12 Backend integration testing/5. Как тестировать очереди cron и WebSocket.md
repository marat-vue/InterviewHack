# Как тестировать очереди, cron и WebSocket?

> [!summary]
> Очереди, cron jobs и WebSocket тестируют как отдельные асинхронные механизмы. Важно проверять постановку задачи, обработчик, retry/error behavior, расписание и обмен сообщениями между client/server.

## Очереди

Раздели два сценария.

Постановка job:

```ts
await usersService.register(input);

expect(queue.add).toHaveBeenCalledWith('sendWelcomeEmail', {
  userId: expect.any(Number),
});
```

Обработчик job:

```ts
await processor.handle({ data: { userId: 1 } });

expect(emailService.sendWelcomeEmail).toHaveBeenCalledWith(1);
```

## Retry и ошибки

Покрывай:

- job failed;
- retry запланирован;
- dead letter behavior;
- idempotency;
- повторная обработка не создает дубликаты.

## Cron

Cron job лучше тестировать через вызываемый service:

```ts
await subscriptionCron.deactivateExpiredSubscriptions();

expect(subscriptionsRepository.deactivateExpired).toHaveBeenCalled();
```

Само расписание можно проверить отдельно, но чаще важнее logic, которую запускает cron.

## WebSocket

WebSocket-тесты проверяют:

- подключение;
- authentication handshake;
- subscribe/unsubscribe;
- отправку message;
- broadcast нужным пользователям;
- disconnect cleanup.

Сценарий:

```text
Client A подключился -> Client B отправил message -> Client A получил event.
```

## Мини-шпаргалка

- Для очередей отдельно тестируй producer и processor.
- Retry/error/idempotency важнее happy path.
- Cron logic лучше выносить в service.
- WebSocket tests проверяют connect, auth, events и cleanup.
- Асинхронные тесты требуют timeout и надежного ожидания события.
