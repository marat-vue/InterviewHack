# Как разделить dev, prod и test Compose файлы для Nuxt?

> [!NOTE]
> Один огромный `compose.yaml` быстро превращается в кашу. Для Nuxt/Nitro проекта удобно держать базовые services отдельно, dev-настройки в override, production-настройки в prod-файле, а optional tools включать profiles.

## Базовый `compose.yaml`

```yaml
services:
  app:
    build:
      context: .
    environment:
      NITRO_HOST: 0.0.0.0
      NITRO_PORT: 3000
      DATABASE_URL: postgresql://app:secret@db:5432/app
      REDIS_URL: redis://redis:6379
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy

  db:
    image: postgres:18
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      timeout: 3s
      retries: 10

  redis:
    image: redis:8-alpine
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  pgdata:
```

## Dev override

`compose.override.yaml` автоматически подхватывается Compose рядом с `compose.yaml`.

```yaml
services:
  app:
    image: node:22-bookworm-slim
    working_dir: /app
    command: sh -c "corepack enable && pnpm install && pnpm dev --host 0.0.0.0"
    ports:
      - "3000:3000"
    volumes:
      - .:/app
      - nuxt_node_modules:/app/node_modules
    environment:
      CHOKIDAR_USEPOLLING: "true"

  db:
    ports:
      - "5432:5432"

  redis:
    ports:
      - "6379:6379"

volumes:
  nuxt_node_modules:
```

Запуск dev:

```bash
docker compose up
```

## Production file

`compose.prod.yaml`:

```yaml
services:
  app:
    build:
      context: .
    ports: []
    expose:
      - "3000"
    restart: unless-stopped

  nginx:
    image: nginx:1.29-alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./docker/nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      app:
        condition: service_started
    restart: unless-stopped

  db:
    restart: unless-stopped

  redis:
    restart: unless-stopped
```

Запуск production:

```bash
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
```

## Test file

`compose.test.yaml`:

```yaml
services:
  app:
    build:
      context: .
      target: build
    command: pnpm test
    environment:
      NODE_ENV: test
      DATABASE_URL: postgresql://test:test@test-db:5432/test
      REDIS_URL: redis://test-redis:6379
    depends_on:
      test-db:
        condition: service_healthy
      test-redis:
        condition: service_healthy

  test-db:
    image: postgres:18
    environment:
      POSTGRES_USER: test
      POSTGRES_PASSWORD: test
      POSTGRES_DB: test
    tmpfs:
      - /var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U test -d test"]
      interval: 5s
      timeout: 3s
      retries: 10

  test-redis:
    image: redis:8-alpine
    tmpfs:
      - /data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
```

Запуск:

```bash
docker compose -f compose.yaml -f compose.test.yaml run --rm app
```

## Profiles для optional services

```yaml
services:
  pgadmin:
    image: dpage/pgadmin4
    profiles:
      - tools
    ports:
      - "5050:80"
```

Запуск:

```bash
docker compose --profile tools up
```

## Что отвечать на собеседовании?

Я разделяю Compose-конфигурацию по сценариям: базовый файл описывает topology, dev override добавляет bind mounts и открытые ports, prod override добавляет reverse proxy, restart policies и закрывает внутренние ports, test файл поднимает одноразовые зависимости. Optional tools включаются через profiles.

## Частые ошибки

- Смешать dev hot reload и production settings в одном файле.
- Случайно открыть Postgres/Redis в prod override.
- Хранить test data в обычном production volume.
- Не понимать порядок merge при `-f compose.yaml -f compose.prod.yaml`.
- Держать pgAdmin/RedisInsight всегда включенными.
- Использовать один `.env` для всех окружений без контроля.

## Мини-шпаргалка

- Base: common topology.
- Dev: bind mounts and ports.
- Prod: reverse proxy and restart.
- Test: tmpfs and isolated DB.
- Tools: profiles.
- Later `-f` overrides earlier files.
