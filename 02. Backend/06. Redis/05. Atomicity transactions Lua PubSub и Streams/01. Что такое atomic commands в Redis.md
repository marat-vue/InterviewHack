# Что такое atomic commands в Redis?

> [!NOTE]
> Многие Redis-команды атомарны: пока выполняется одна команда, другая команда не меняет те же данные посередине операции. Это основа counters, locks, rate limiting и queue-паттернов.

## Что значит atomic?

Атомарная операция выполняется как единое действие.

Плохо:

```txt
GET counter
counter = counter + 1
SET counter
```

Хорошо:

```redis
INCR counter
```

`INCR` не потеряет updates при конкурентных запросах.

## Примеры атомарных команд

| Команда | Кейс |
|---|---|
| `INCR` | counters, rate limit |
| `DECR` | stock-like simple counter |
| `HINCRBY` | grouped counters |
| `SADD` | unique insert |
| `SREM` | membership delete |
| `SET NX PX` | lock |
| `LPUSH`/`RPOP` | queue operations |
| `ZADD` | ranking update |
| `XADD` | append event |

## Rate limit через atomic increment

```redis
INCR rate:ip:203.0.113.10
EXPIRE rate:ip:203.0.113.10 60
```

В production лучше сделать `INCR + initial EXPIRE` через Lua, чтобы TTL точно ставился атомарно при создании ключа.

## Что если нужно несколько команд атомарно?

Варианты:

- готовая Redis-команда;
- `MULTI/EXEC`;
- Lua script;
- Redis Functions;
- domain-level lock;
- SQL transaction, если это доменные данные.

## Как не злоупотреблять atomicity?

Атомарность Redis не равна distributed transaction между Redis и PostgreSQL. Если операция меняет Redis и SQL, нужно думать об idempotency и компенсирующих действиях.

## Мини-шпаргалка

- Сначала ищи готовую атомарную команду.
- `INCR` лучше, чем `GET` + `SET`.
- `SET NX PX` - базовый lock.
- Multi-step atomic logic - Lua/Functions.
- Redis atomicity не покрывает внешнюю БД.
