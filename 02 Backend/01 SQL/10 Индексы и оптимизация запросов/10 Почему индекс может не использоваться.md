# Почему индекс может не использоваться?

> [!NOTE]
> Наличие индекса не гарантирует, что оптимизатор его выберет. База может решить, что полный scan дешевле, если условие выбирает слишком много строк, статистика устарела или запрос написан так, что индекс плохо применим.

## Низкая селективность

```sql
SELECT *
FROM users
WHERE is_active = true;
```

Если почти все пользователи активны, читать индекс и затем таблицу может быть дороже, чем пройти таблицу целиком.

## Функция вокруг колонки

```sql
SELECT *
FROM users
WHERE lower(email) = 'anna@example.com';
```

Обычный индекс на `email` может не помочь. Нужен expression index:

```sql
CREATE INDEX idx_users_lower_email
ON users (lower(email));
```

## Несовпадение типов

```sql
WHERE user_id = '42'
```

Если `user_id` числовой, приведение типов может ухудшить план. Лучше передавать параметры правильного типа.

## Устаревшая статистика

Оптимизатор принимает решения по статистике таблиц. Если статистика неактуальна, план может быть плохим.

## Мини-шпаргалка

- Индекс выбирает оптимизатор, а не разработчик напрямую.
- Низкая селективность снижает пользу индекса.
- Функции вокруг колонок могут мешать индексу.
- Типы параметров должны совпадать с типами колонок.
- Проверяй реальность через `EXPLAIN`.
