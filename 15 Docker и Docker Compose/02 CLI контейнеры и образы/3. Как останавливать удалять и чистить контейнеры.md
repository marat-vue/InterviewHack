# Как останавливать удалять и чистить контейнеры?

> [!summary]
> Контейнеры можно останавливать через `docker stop`, удалять через `docker rm`, images удалять через `docker rmi`, а неиспользуемые ресурсы чистить через `docker system prune`. Важно понимать разницу между container, image и volume, чтобы случайно не потерять данные.

## Остановить контейнер

```bash
docker stop api
```

Docker отправляет процессу сигнал остановки и дает время завершиться корректно.

Принудительно убить:

```bash
docker kill api
```

`kill` используют реже, когда graceful stop не помогает.

## Запустить остановленный контейнер

```bash
docker start api
```

Это запускает уже существующий container, а не создает новый.

## Удалить контейнер

```bash
docker rm api
```

Если контейнер running, сначала остановить:

```bash
docker stop api
docker rm api
```

Или принудительно:

```bash
docker rm -f api
```

## Удалить image

```bash
docker rmi my-api:latest
```

Image нельзя удалить, если от него зависят containers. Сначала нужно удалить containers.

## Очистить неиспользуемые ресурсы

```bash
docker system prune
```

Очищает:

- stopped containers;
- unused networks;
- dangling images;
- build cache.

Более агрессивно:

```bash
docker system prune -a
```

Это может удалить все images, которые сейчас не используются containers.

## Осторожно с volumes

Volumes не удаляются обычным `docker rm`, потому что в них могут быть важные данные.

Удалить неиспользуемые volumes:

```bash
docker volume prune
```

Удалить volume явно:

```bash
docker volume rm pgdata
```

Перед такими командами нужно понимать, что именно хранится в volume.

## Что отвечать на собеседовании?

`docker stop` останавливает контейнер, `docker start` запускает уже существующий, `docker rm` удаляет контейнер, `docker rmi` удаляет image. Для очистки используют `docker system prune`, но с volumes нужно быть осторожным: именно там часто лежат данные базы.

## Частые ошибки

- Удалить volume с базой данных.
- Путать `docker stop` и `docker rm`.
- Думать, что удаление container удаляет image.
- Использовать `docker system prune -a` не глядя.
- Не понимать, почему image не удаляется из-за existing containers.

## Мини-шпаргалка

- `docker stop` - остановить.
- `docker start` - запустить существующий.
- `docker rm` - удалить container.
- `docker rmi` - удалить image.
- `docker system prune` - очистить мусор.
- `docker volume prune` - опасно для данных.
