# Mutations invalidation optimistic updates и собеседование

> [!summary]
> Для работы и собеседований по TanStack Query важно уверенно объяснять mutation lifecycle: `mutationFn`, `onMutate`, `onError`, `onSuccess`, `onSettled`, invalidation и optimistic update.

## Mutation lifecycle

```tsx
const mutation = useMutation({
  mutationFn: updateTodo,

  onMutate: async (variables) => {
    await queryClient.cancelQueries({ queryKey: ['todos'] })

    const previousTodos = queryClient.getQueryData<Todo[]>(['todos'])

    queryClient.setQueryData<Todo[]>(['todos'], (oldTodos = []) =>
      oldTodos.map((todo) =>
        todo.id === variables.id ? { ...todo, ...variables.patch } : todo,
      ),
    )

    return { previousTodos }
  },

  onError: (error, variables, context) => {
    queryClient.setQueryData(['todos'], context?.previousTodos)
  },

  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['todos'] })
  },
})
```

## Что делает каждый callback?

| Callback | Когда вызывается | Зачем нужен |
|---|---|---|
| `onMutate` | перед mutation | optimistic update, snapshot |
| `onError` | mutation упала | rollback |
| `onSuccess` | mutation успешна | invalidate или update cache |
| `onSettled` | всегда после завершения | финальная синхронизация |

## mutate vs mutateAsync

```tsx
mutation.mutate({ id: '1', title: 'New title' })
```

`mutate` запускает mutation и использует callbacks.

```tsx
await mutation.mutateAsync({ id: '1', title: 'New title' })
```

`mutateAsync` удобен, когда нужно встроить mutation в async flow.

## invalidate или setQueryData?

Используй `invalidateQueries`, если:

- сервер может вернуть сложные побочные изменения;
- список сортируется/фильтруется на backend;
- нужно гарантированно синхронизироваться.

Используй `setQueryData`, если:

- mutation вернула новый объект;
- изменение локально очевидно;
- важна мгновенная реакция UI.

Часто комбинируют оба подхода: сначала `setQueryData`, потом `invalidateQueries`.

## Типичные вопросы на собеседовании

### Что такое queryKey?

Адрес данных в cache. Он должен включать все параметры, которые влияют на результат запроса.

### Чем loading отличается от fetching?

`isPending` означает, что данных еще нет. `isFetching` может быть true при фоновом обновлении, когда старые данные уже отображаются.

### Что такое staleTime?

Время, в течение которого данные считаются свежими и не требуют refetch по умолчанию.

### Почему не хранить server state в Zustand?

Потому что server state требует cache invalidation, retries, refetch, deduplication и синхронизации с backend. TanStack Query уже решает эти задачи.

## Частые ошибки

- Использовать один общий `queryKey` для разных параметров.
- Не делать invalidation после mutation.
- Мутировать cache напрямую.
- Показывать full-page loader при каждом background refetch.
- Делать optimistic update без rollback.
- Ставить бесконечный `staleTime` без понимания последствий.

## Что отвечать на собеседовании?

Mutation в TanStack Query - это операция изменения серверных данных. После успешной mutation обычно делают `invalidateQueries` или `setQueryData`. Для optimistic update используют `onMutate` для snapshot и временного изменения cache, `onError` для rollback и `onSettled` для финальной синхронизации.

## Мини-шпаргалка

- `onMutate` - optimistic update.
- `onError` - rollback.
- `onSuccess` - успешная синхронизация.
- `onSettled` - всегда в конце.
- `isPending` - первый load/mutation pending.
- `isFetching` - любой fetch, включая background.
