# Что делает Readonly

> [!summary] Коротко
> `Readonly<T>` делает все свойства объекта `T` доступными только для чтения. После создания объекта TypeScript запрещает менять эти поля напрямую.

## Вопрос

Что делает `Readonly`?

## Базовый пример

```typescript
type User = {
  id: number;
  name: string;
};

type ReadonlyUser = Readonly<User>;

const user: ReadonlyUser = {
  id: 1,
  name: "Анна",
};

// user.name = "Мария"; // ошибка
```

`Readonly<User>` эквивалентен типу, где каждое поле помечено `readonly`.

```typescript
type ReadonlyUser = {
  readonly id: number;
  readonly name: string;
};
```

## Где полезен

`Readonly` хорошо подходит для конфигов, данных из хранилища, DTO и параметров функций, которые не должны мутироваться.

```typescript
function renderUser(user: Readonly<User>): string {
  return `${user.id}: ${user.name}`;
}
```

## Важный нюанс

`Readonly` работает поверхностно. Вложенные объекты остаются изменяемыми, если их отдельно не сделать readonly.

```typescript
type Profile = {
  settings: {
    theme: string;
  };
};

const profile: Readonly<Profile> = {
  settings: { theme: "dark" },
};

profile.settings.theme = "light"; // разрешено
```

## Мини-шпаргалка

- `Readonly<T>` добавляет `readonly` всем верхнеуровневым полям.
- Не делает глубокую иммутабельность.
- Защищает от случайной мутации на уровне TypeScript.
- На runtime объект не замораживается.
