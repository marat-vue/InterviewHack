# Какие ошибки чаще всего делают в Nuxt?

> [!summary]
> Частые ошибки в Nuxt: отключать SSR из-за `window is not defined`, использовать `$fetch` в setup вместо `useFetch`, хранить secrets в `public`, кэшировать персональные страницы, игнорировать hydration mismatch и ставить модули без понимания их runtime impact.

## Отключают SSR вместо исправления кода

Плохо:

```ts
export default defineNuxtConfig({
  ssr: false,
});
```

только потому что библиотека обращается к `window`.

Лучше:

```ts
if (import.meta.client) {
  initBrowserLibrary();
}
```

или client-only plugin:

```text
app/plugins/library.client.ts
```

## Используют `$fetch` в setup

Плохо:

```ts
const products = await $fetch('/api/products');
```

Лучше:

```ts
const { data: products } = await useFetch('/api/products');
```

Так Nuxt сможет использовать payload.

## Кладут secrets в public config

Плохо:

```ts
runtimeConfig: {
  public: {
    apiSecret: 'secret',
  },
}
```

Все `public` значения доступны в браузере.

## Кэшируют приватные страницы

Плохо:

```ts
routeRules: {
  '/account/**': { swr: 3600 },
}
```

Если HTML зависит от пользователя, общий cache опасен.

## Игнорируют SEO details

SSR не спасет, если:

- одинаковые title на всех страницах;
- нет canonical;
- sitemap пустой;
- robots блокирует site;
- 404 возвращает 200.

## Мини-шпаргалка

- Не отключай SSR как первое решение.
- Для initial data используй `useFetch/useAsyncData`.
- Secrets не кладут в `runtimeConfig.public`.
- Не кэшируй user-specific HTML.
- Hydration warnings нужно чинить.
