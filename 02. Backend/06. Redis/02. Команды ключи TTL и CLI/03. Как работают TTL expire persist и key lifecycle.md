# Как работают TTL, EXPIRE, PERSIST и key lifecycle?

> [!NOTE]
> TTL - одна из главных причин использовать Redis. Он позволяет автоматически удалять временные данные: sessions, tokens, cache entries, rate limit counters, locks и idempotency keys.

## Что такое TTL?

TTL - time to live, время жизни ключа.

```redis
SET session:abc user-1 EX 3600
TTL session:abc
```

Ключ будет удален примерно через час.

## Как задать TTL при записи?

В секундах:

```redis
SET cache:product:42 '{"id":42}' EX 300
```

В миллисекундах:

```redis
SET lock:job:42 token PX 30000
```

Только если ключа нет:

```redis
SET lock:job:42 token NX PX 30000
```

Только если ключ уже есть:

```redis
SET cache:product:42 value XX EX 300
```

## Как задать TTL существующему ключу?

```redis
EXPIRE session:abc 3600
PEXPIRE session:abc 3600000
```

Посмотреть:

```redis
TTL session:abc
PTTL session:abc
```

## Что значат ответы `TTL`?

| Ответ | Значение |
|---|---|
| `> 0` | осталось секунд |
| `-1` | ключ есть, но TTL нет |
| `-2` | ключа нет |

## Как убрать TTL?

```redis
PERSIST session:abc
```

После этого ключ станет persistent и не исчезнет сам.

## Что происходит при overwrite?

Команда `SET key value` без options обычно заменяет значение и сбрасывает TTL.

```redis
SET token abc EX 60
SET token def
TTL token
```

TTL станет `-1`. Чтобы сохранить TTL, используй подходящие options клиента или явно выставляй TTL снова.

## Как использовать TTL в Node.js?

```ts
await redis.set('email-code:user-1', '123456', {
  EX: 60 * 10,
});

const code = await redis.get('email-code:user-1');
```

## Где TTL обязателен?

TTL почти обязателен для:

- cache;
- sessions;
- password reset tokens;
- email verification codes;
- locks;
- rate limit counters;
- idempotency keys;
- temporary OAuth state.

## Мини-шпаргалка

- `EX` - TTL в секундах.
- `PX` - TTL в миллисекундах.
- `TTL`/`PTTL` - посмотреть время жизни.
- `PERSIST` - убрать TTL.
- `SET` без TTL может сбросить старый TTL.
- Временные ключи без TTL - частая причина memory leak.
