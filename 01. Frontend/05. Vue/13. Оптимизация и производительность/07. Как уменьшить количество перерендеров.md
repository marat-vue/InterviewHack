# Как уменьшить количество перерендеров?

> [!NOTE]
> Чтобы уменьшить количество перерендеров во Vue, нужно делать состояние локальнее, вычисления дешевле, props стабильнее, списки предсказуемее, а тяжелые части интерфейса обновлять только тогда, когда это действительно нужно.

## Главное

Перерендер сам по себе не ошибка. Vue устроен так, чтобы обновлять интерфейс при изменении реактивных данных. Проблемы начинаются, когда одно изменение заставляет обновляться слишком большое дерево компонентов или выполняет тяжелые вычисления.

```text
reactive state changed
  -> component render is scheduled
  -> template creates new VNodes
  -> Vue patches changed DOM parts
```

Цель оптимизации - уменьшить объем работы на каждом шаге.

## Держать состояние ближе к месту использования

Если состояние нужно одному компоненту, не стоит класть его в глобальный store.

```vue
<script setup>
import { ref } from "vue";

const isOpen = ref(false);
</script>

<template>
  <button @click="isOpen = !isOpen">Фильтры</button>
  <FilterPanel v-if="isOpen" />
</template>
```

Локальное состояние обновляет только нужную ветку, а не всех подписчиков глобального хранилища.

## Делать props стабильными

Если на каждом рендере создавать новый объект или массив, дочерний компонент будет получать новое значение.

```vue
<!-- хуже -->
<UserCard :options="{ dense: true, theme: currentTheme }" />
```

Лучше вынести объект в `computed`, если он зависит от реактивных данных.

```vue
<script setup>
import { computed } from "vue";

const cardOptions = computed(() => ({
  dense: true,
  theme: currentTheme.value,
}));
</script>

<template>
  <UserCard :options="cardOptions" />
</template>
```

## Использовать computed вместо методов для производных данных

```vue
<script setup>
import { computed, ref } from "vue";

const products = ref([]);

const availableProducts = computed(() =>
  products.value.filter((product) => product.inStock)
);
</script>
```

`computed` кеширует результат и пересчитывается только при изменении зависимостей.

## Разбивать тяжелые компоненты

Если один большой компонент содержит форму, таблицу, фильтры и модалки, любое изменение может затрагивать слишком много шаблона. Лучше выделять самостоятельные компоненты с понятными props.

```vue
<template>
  <ProductFilters v-model="filters" />
  <ProductTable :products="filteredProducts" />
  <ProductSummary :products="filteredProducts" />
</template>
```

Так проще понять, какая часть интерфейса реально зависит от каких данных.

## Следить за списками

Для списков важен стабильный `key`.

```vue
<TodoItem
  v-for="todo in todos"
  :key="todo.id"
  :todo="todo"
/>
```

Не стоит использовать индекс массива как `key`, если элементы могут удаляться, сортироваться или перемещаться.

## Использовать v-memo для редких случаев

`v-memo` позволяет пропустить обновление части шаблона, пока зависимости не изменились.

```vue
<template>
  <UserRow
    v-for="user in users"
    :key="user.id"
    v-memo="[user.id, user.isSelected]"
    :user="user"
  />
</template>
```

Это инструмент для точечной оптимизации, а не замена нормальной архитектуры состояния.

## Мини-шпаргалка

- Локальное состояние обновляет меньше компонентов.
- `computed` лучше методов для дорогих производных данных.
- Стабильные `key` помогают Vue корректно переиспользовать DOM.
- Не создавай новые объекты в шаблоне без необходимости.
- Большие списки лучше виртуализировать.
- `v-memo` применяют точечно после измерений.
