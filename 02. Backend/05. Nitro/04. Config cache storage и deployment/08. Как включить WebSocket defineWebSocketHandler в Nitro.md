# Как включить WebSocket и defineWebSocketHandler в Nitro?

> [!NOTE]
> Nitro поддерживает WebSocket через CrossWS и H3. WebSocket нужен для двусторонней realtime-связи: клиент и сервер могут отправлять сообщения друг другу без нового HTTP-запроса на каждое событие.

## Зачем WebSocket в backend?

WebSocket используют, когда нужны:

- chat;
- live notifications;
- collaborative editing;
- realtime dashboards;
- multiplayer state;
- terminal/log streaming;
- live order status;
- presence, typing indicators, online users.

Если данные идут только с сервера к клиенту, иногда проще Server-Sent Events. Если достаточно обновлять данные раз в несколько секунд, часто проще polling.

## Как включить WebSocket?

```ts
// nitro.config.ts
import { defineConfig } from 'nitro';

export default defineConfig({
  features: {
    websocket: true,
  },
});
```

После этого route file может экспортировать `defineWebSocketHandler`.

## Как создать WebSocket route?

```ts
// routes/chat.ts
import { defineWebSocketHandler } from 'nitro';

export default defineWebSocketHandler({
  open(peer) {
    peer.send({
      type: 'system',
      text: 'Welcome!',
    });
  },
  message(peer, message) {
    const text = message.text();

    peer.send({
      type: 'echo',
      text,
    });
  },
  close(peer, details) {
    console.log('closed', peer.id, details.code, details.reason);
  },
  error(peer, error) {
    console.error('ws error', peer.id, error);
  },
});
```

Route `routes/chat.ts` доступен по:

```txt
ws://localhost:3000/chat
```

## Как подключиться с клиента?

```ts
const ws = new WebSocket('ws://localhost:3000/chat');

ws.addEventListener('open', () => {
  ws.send('Hello from client');
});

ws.addEventListener('message', (event) => {
  console.log('from server:', event.data);
});

ws.addEventListener('close', () => {
  console.log('connection closed');
});
```

В production нужно использовать `wss://`:

```ts
const ws = new WebSocket('wss://api.example.com/chat');
```

## Какие hooks есть у WebSocket handler?

| Hook | Когда вызывается | Для чего нужен |
|---|---|---|
| `upgrade(request)` | до установки соединения | auth, headers, namespace, context |
| `open(peer)` | соединение установлено | welcome message, subscribe, presence |
| `message(peer, message)` | пришло сообщение | parsing, validation, broadcast |
| `close(peer, details)` | соединение закрыто | cleanup, leave notification |
| `error(peer, error)` | ошибка соединения | logging, metrics |

## Как делать auth в `upgrade`?

```ts
// routes/chat.ts
import { defineWebSocketHandler } from 'nitro';

export default defineWebSocketHandler({
  async upgrade(request) {
    const url = new URL(request.url);
    const token = url.searchParams.get('token');
    const user = await verifyWsToken(token);

    if (!user) {
      throw new Response('Unauthorized', {
        status: 401,
      });
    }

    return {
      headers: {
        'x-ws-auth': 'ok',
      },
      namespace: `tenant:${user.tenantId}`,
      context: {
        userId: user.id,
        tenantId: user.tenantId,
      },
    };
  },
  open(peer) {
    peer.send({
      type: 'hello',
      userId: peer.context.userId,
    });
  },
});
```

`upgrade` может вернуть:

| Поле | Зачем нужно |
|---|---|
| `headers` | headers для upgrade response |
| `namespace` | изолированная pub/sub область |
| `context` | данные, доступные дальше как `peer.context` |

Если auth не прошел, можно выбросить `Response` с `401` или `403`.

## Что есть в `peer`?

`peer` - подключенный клиент.

| Свойство | Что значит |
|---|---|
| `peer.id` | уникальный id подключения |
| `peer.namespace` | namespace, в котором живет peer |
| `peer.context` | данные из `upgrade` |
| `peer.request` | исходный upgrade request |
| `peer.peers` | peers в том же namespace |
| `peer.topics` | topics, на которые подписан peer |
| `peer.remoteAddress` | IP, если adapter его предоставляет |
| `peer.websocket` | underlying WebSocket object |

## Какие методы есть у `peer`?

| Метод | Что делает |
|---|---|
| `peer.send(data, options?)` | отправляет сообщение только этому клиенту |
| `peer.subscribe(topic)` | подписывает клиента на topic |
| `peer.unsubscribe(topic)` | отписывает клиента от topic |
| `peer.publish(topic, data, options?)` | отправляет сообщение всем подписчикам topic в namespace, кроме отправителя |
| `peer.close(code?, reason?)` | корректно закрывает соединение |
| `peer.terminate()` | обрывает соединение без close frame |

Пример:

```ts
peer.send({
  type: 'notification',
  text: 'Saved',
});

peer.subscribe('chat');
peer.publish('chat', {
  type: 'message',
  text: 'Hello everyone',
});
peer.close(1000, 'Normal closure');
```

## Какие методы есть у `message`?

| Метод | Что возвращает |
|---|---|
| `message.text()` | строку |
| `message.json<T>()` | JSON, распарсенный как `T` |
| `message.uint8Array()` | `Uint8Array` |
| `message.arrayBuffer()` | `ArrayBuffer` |
| `message.blob()` | `Blob` |

Пример с JSON:

```ts
message(peer, message) {
  const data = message.json<{
    type: 'chat.message';
    text: string;
  }>();

  if (data.type === 'chat.message') {
    peer.publish('chat', {
      userId: peer.context.userId,
      text: data.text,
    });
  }
}
```

Не доверяй JSON из WebSocket. Валидируй payload так же, как HTTP body.

## Как сделать chat через pub/sub topics?

```ts
// routes/chat.ts
import { defineWebSocketHandler } from 'nitro';

export default defineWebSocketHandler({
  open(peer) {
    peer.subscribe('messages');

    peer.send({
      type: 'system',
      text: 'Welcome to chat',
    });

    peer.publish('messages', {
      type: 'system',
      text: `${peer.id} joined`,
    });
  },
  message(peer, message) {
    const text = message.text();

    peer.publish('messages', {
      type: 'message',
      peerId: peer.id,
      text,
    });

    peer.send({
      type: 'message.sent',
      text,
    });
  },
  close(peer) {
    peer.publish('messages', {
      type: 'system',
      text: `${peer.id} left`,
    });
  },
});
```

`peer.publish()` не отправляет сообщение самому отправителю. Если нужно echo sender-у, используй `peer.send()` отдельно.

## Как изолировать комнаты через namespace?

Файл:

```txt
routes/rooms/[room].ts
```

Handler:

```ts
import { defineWebSocketHandler } from 'nitro';

export default defineWebSocketHandler({
  upgrade(request) {
    const url = new URL(request.url);
    const room = url.pathname.split('/').at(-1) || 'general';

    return {
      namespace: `room:${room}`,
    };
  },
  open(peer) {
    peer.subscribe('messages');
    peer.publish('messages', {
      type: 'system',
      text: `${peer.id} joined ${peer.namespace}`,
    });
  },
  message(peer, message) {
    peer.publish('messages', {
      type: 'message',
      text: message.text(),
    });
  },
});
```

Клиенты в `/rooms/a` и `/rooms/b` не получают сообщения друг друга, потому что namespace разный.

## Как использовать Redis для нескольких инстансов?

Встроенный `peer.publish()` работает внутри текущего runtime/namespace. Если приложение запущено в нескольких Node-процессах или нескольких контейнерах, пользователи могут оказаться на разных инстансах. Тогда для fan-out часто нужен внешний broker: Redis Pub/Sub, Redis Streams, NATS, Kafka или managed realtime-сервис.

Минимальный Node-only пример с Redis Pub/Sub:

```ts
// server/utils/ws-bus.ts
import Redis from 'ioredis';

export const pub = new Redis(process.env.REDIS_URL!);
export const sub = new Redis(process.env.REDIS_URL!);
```

```ts
// routes/chat.ts
import { defineWebSocketHandler } from 'nitro';
import { pub, sub } from '../server/utils/ws-bus';

const peers = new Set<any>();
let subscribed = false;

async function ensureRedisSubscription() {
  if (subscribed) {
    return;
  }

  subscribed = true;
  await sub.subscribe('chat:messages');

  sub.on('message', (_channel, raw) => {
    for (const peer of peers) {
      peer.send(raw);
    }
  });
}

export default defineWebSocketHandler({
  async open(peer) {
    peers.add(peer);
    await ensureRedisSubscription();
  },
  async message(peer, message) {
    await pub.publish(
      'chat:messages',
      JSON.stringify({
        userId: peer.context.userId,
        text: message.text(),
      }),
    );
  },
  close(peer) {
    peers.delete(peer);
  },
});
```

Такой пример показывает идею, но production-версия должна добавить validation, auth, channel naming, reconnect handling, graceful shutdown, limits и protection от слишком больших сообщений.

## Какие production-настройки важны?

Проверь:

- поддерживает ли deployment preset WebSocket;
- не отключает ли hosting long-lived connections;
- нужен ли sticky sessions;
- где хранится presence;
- как работает Redis/broker для нескольких инстансов;
- какие лимиты на message size;
- как часто клиент отправляет heartbeat;
- что происходит при reconnect;
- как обновляется auth/session;
- как логируются open/close/error;
- как закрываются соединения при deploy.

Serverless и edge платформы отличаются. Даже если Nitro API одинаковый, поддержка long-lived WebSocket зависит от конкретного runtime.

## Когда выбрать SSE вместо WebSocket?

SSE лучше, если:

- сообщения идут только server -> client;
- нужен простой reconnect;
- нет client -> server realtime-команд;
- достаточно обычного HTTP;
- hosting плохо поддерживает WebSocket.

Пример SSE в Nitro:

```ts
import { defineHandler } from 'nitro';
import { createEventStream } from 'nitro/h3';

export default defineHandler((event) => {
  const stream = createEventStream(event);

  const interval = setInterval(async () => {
    await stream.push(`time: ${new Date().toISOString()}`);
  }, 1000);

  stream.onClosed(() => {
    clearInterval(interval);
  });

  return stream.send();
});
```

## Мини-шпаргалка

- Включение: `features.websocket: true`.
- Handler: `defineWebSocketHandler`.
- Hooks: `upgrade`, `open`, `message`, `close`, `error`.
- Auth лучше делать в `upgrade`.
- `peer.send()` отправляет одному клиенту.
- `peer.publish()` отправляет подписчикам topic в namespace.
- `message.text()` и `message.json<T>()` - самые частые методы.
- Для нескольких инстансов нужен внешний broker, например Redis.
- Не все serverless/edge платформы одинаково поддерживают WebSocket.
