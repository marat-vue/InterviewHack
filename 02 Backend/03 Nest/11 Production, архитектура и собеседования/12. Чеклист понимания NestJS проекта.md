# Чеклист понимания NestJS проекта

> [!summary]
> Этот чеклист помогает проверить, понимаешь ли ты NestJS-проект не фрагментами, а как связанную систему файлов, зависимостей и runtime-слоев.

## Структура

- Можешь найти `main.ts` и объяснить bootstrap.
- Можешь найти `AppModule` и назвать подключенные modules.
- Понимаешь, какие файлы относятся к feature module.
- Отличаешь `common`, `auth`, `database`, `config` и domain modules.
- Понимаешь, зачем provider экспортируется из module.

## Путь запроса

- Можешь пройти путь `POST /users` от controller до database.
- Понимаешь, где сработает `ValidationPipe`.
- Понимаешь, где сработает guard.
- Понимаешь, где interceptor может изменить response.
- Понимаешь, где exception filter форматирует ошибку.

## DI

- Можешь объяснить constructor injection.
- Можешь найти provider в `providers`.
- Можешь понять ошибку "can't resolve dependencies".
- Понимаешь difference между class token и custom token.
- Понимаешь, когда нужен `exports`.

## Практика

- Можешь создать resource через CLI.
- Можешь вручную создать module/controller/service/DTO.
- Можешь подключить config.
- Можешь написать unit test для service.
- Можешь написать e2e test для endpoint.

## Мини-шпаргалка

- NestJS учится через связи между файлами.
- Самый важный маршрут: module -> controller -> service -> provider.
- Ошибки DI почти всегда про module boundaries.
- Request lifecycle объясняет guards/pipes/interceptors.
- Если можешь провести один request по проекту, половина NestJS уже в голове.
