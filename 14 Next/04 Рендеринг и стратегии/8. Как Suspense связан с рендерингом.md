# Как Suspense связан с рендерингом?

> [!summary]
> Suspense позволяет части React-дерева "приостановиться", пока она ждет данные или код, и показать fallback. В Next.js Suspense связан со streaming, loading UI, Server Components и постепенной доставкой страницы.

## Что делает Suspense?

```tsx
import { Suspense } from 'react'

export default function Page() {
  return (
    <Suspense fallback={<CommentsSkeleton />}>
      <Comments />
    </Suspense>
  )
}
```

Если `Comments` ждет данные, React может показать `CommentsSkeleton`, а остальную страницу продолжить рендерить.

## Suspense boundary

`<Suspense>` создает границу ожидания.

```tsx
<>
  <ProductInfo />

  <Suspense fallback={<ReviewsSkeleton />}>
    <Reviews />
  </Suspense>

  <Suspense fallback={<RecommendationsSkeleton />}>
    <Recommendations />
  </Suspense>
</>
```

Отзывы и рекомендации могут загружаться независимо.

## loading.tsx как Suspense

В App Router файл `loading.tsx` автоматически создает loading UI для segment:

```text
app/products/loading.tsx
```

Это удобный route-level Suspense fallback.

## Suspense и data waterfall

Плохой вариант:

```tsx
const user = await getUser()
const orders = await getOrders(user.id)
const recommendations = await getRecommendations(user.id)
```

Если данные независимы, можно распараллелить:

```tsx
const userPromise = getUser()
const statsPromise = getStats()

const [user, stats] = await Promise.all([userPromise, statsPromise])
```

Suspense помогает UI, но не отменяет работу с data dependencies.

## Что отвечать на собеседовании?

Suspense в Next.js помогает не блокировать весь route из-за медленного блока. Он показывает fallback, дает streaming boundary и позволяет доставлять UI постепенно. `loading.tsx` - файловая convention, которая использует эту идею на уровне route segment.

## Частые ошибки

- Думать, что Suspense сам делает fetch.
- Оборачивать всю страницу в один fallback.
- Не отличать loading UI от error UI.
- Пытаться поймать ошибку через Suspense.
- Игнорировать data waterfall.

## Мини-шпаргалка

- Suspense показывает fallback.
- Boundary ограничивает ожидание.
- `loading.tsx` - segment fallback.
- Для ошибок нужен `error.tsx`/Error Boundary.
- Streaming опирается на Suspense.
- Suspense не заменяет оптимизацию запросов.
