# Как работает PostgreSQL replication, logical replication и read replicas?

> [!NOTE]
> Репликация PostgreSQL нужна для high availability, read scaling, migrations и интеграций. Важно различать physical streaming replication и logical replication.

## Physical streaming replication

Primary отправляет WAL на replica.

```txt
primary -> WAL -> standby replica
```

Хорошо для:

- hot standby;
- failover;
- read replicas;
- disaster recovery.

Особенности:

- replica содержит весь cluster/database state;
- обычно используется для HA;
- read replica может отставать.

## Replication lag

Read replica может быть stale.

Риск:

```txt
POST /orders -> write primary
GET /orders/latest -> read replica -> заказа еще нет
```

Для read-after-write часто читают primary или используют sticky read strategy.

## Logical replication

Logical replication передает изменения на уровне tables/rows.

Подходит для:

- selective table replication;
- zero-downtime migrations;
- integration pipelines;
- partial data sync;
- version upgrades.

## Publication/subscription

Идея:

```sql
CREATE PUBLICATION app_pub FOR TABLE users, orders;
```

На другой БД:

```sql
CREATE SUBSCRIPTION app_sub
CONNECTION 'host=... dbname=...'
PUBLICATION app_pub;
```

## Failover

Failover может быть:

- managed provider automatic;
- Patroni/repmgr-based;
- manual;
- orchestrated by platform.

Приложение должно:

- retry transient errors;
- переподключаться;
- не кешировать primary address навсегда;
- понимать read/write split.

## Мини-шпаргалка

- Physical replication - WAL-level replica.
- Logical replication - table/row changes.
- Read replicas могут отставать.
- Read-after-write иногда требует primary.
- Failover требует retry и connection handling.
