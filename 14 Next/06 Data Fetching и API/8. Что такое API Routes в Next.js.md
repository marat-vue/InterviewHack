# Что такое API Routes в Next.js?

> [!summary]
> API Routes - встроенный способ создавать backend endpoints внутри Next.js проекта. В App Router современное название и механизм - Route Handlers в файлах `route.ts`, а в Pages Router это файлы внутри `pages/api`.

## App Router: Route Handler

```text
app/
  api/
    users/
      route.ts
```

URL:

```text
/api/users
```

Код:

```ts
export async function GET() {
  const users = await db.user.findMany()

  return Response.json(users)
}
```

## Поддерживаемые методы

В `route.ts` можно экспортировать функции:

- `GET`;
- `POST`;
- `PUT`;
- `PATCH`;
- `DELETE`;
- `HEAD`;
- `OPTIONS`.

```ts
export async function POST(request: Request) {
  const body = await request.json()
  const user = await createUser(body)

  return Response.json(user, { status: 201 })
}
```

## Pages Router: старый API Routes

```text
pages/
  api/
    users.ts
```

```ts
export default function handler(req, res) {
  res.status(200).json({ ok: true })
}
```

В новых App Router проектах чаще используют `route.ts`.

## Когда нужен Route Handler?

- внешний webhook;
- endpoint для мобильного приложения;
- интеграция с внешним сервисом;
- OAuth callback;
- file upload/download;
- публичный REST endpoint;
- BFF endpoint для клиента.

## Что отвечать на собеседовании?

В App Router API endpoints создаются через Route Handlers: файл `app/api/.../route.ts` и exports `GET`, `POST` и других HTTP-методов. Это серверный код, который возвращает `Response`. В Pages Router похожая идея называлась API Routes и находилась в `pages/api`.

## Частые ошибки

- Называть Route Handler компонентом.
- Возвращать JSX из `route.ts`.
- Создавать Route Handler для запроса, который нужен только Server Component.
- Забывать авторизацию и валидацию.
- Думать, что endpoint не публичный.

## Мини-шпаргалка

- App Router: `app/api/name/route.ts`.
- Export: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.
- Возвращай `Response` или `Response.json`.
- Route Handler - публичный HTTP endpoint.
- Pages Router: `pages/api/*.ts`.
