# Типы ошибок в Реакт приложении

> [!summary]
> В React-приложении ошибки возникают в разных местах: render, effects, event handlers, async-код, routing, SSR, data fetching и валидация форм. Для каждого типа нужен свой способ обработки.

## Ошибки render

```jsx
function UserName({ user }) {
  return <span>{user.name}</span>
}
```

Если `user` равен `undefined`, ошибка произойдет во время render.

Чем обрабатывать:

- проверки данных;
- fallback UI;
- Error Boundary.

## Ошибки effects

```jsx
useEffect(() => {
  async function loadData() {
    const data = await fetchData()
    setData(data)
  }

  loadData()
}, [])
```

Если Promise rejected и нет `try/catch`, ошибка может стать unhandled rejection.

Чем обрабатывать:

- `try/catch`;
- `.catch`;
- cleanup;
- AbortController.

## Ошибки event handlers

```jsx
function SaveButton() {
  async function handleClick() {
    await saveData()
  }

  return <button onClick={handleClick}>Save</button>
}
```

Error Boundary не ловит ошибки внутри событий. Нужно обрабатывать их в самом handler или через слой мутаций.

```jsx
async function handleClick() {
  try {
    await saveData()
  } catch (error) {
    showToast('Failed to save')
  }
}
```

## Ошибки data fetching

Сюда входят:

- HTTP 400/401/403/404/500;
- timeout;
- offline;
- invalid JSON;
- устаревший ответ;
- race condition;
- schema mismatch.

Их удобно нормализовать в API-слое и показывать через error state, toast или route error boundary.

## Ошибки валидации

Это не "краш" приложения, а ожидаемый результат неправильного ввода.

```jsx
if (!email.includes('@')) {
  return 'Email is invalid'
}
```

Их показывают рядом с полем или в summary формы.

## Инфраструктурные ошибки

- chunk load error;
- route not found;
- hydration mismatch;
- ошибка сборки;
- неверный env;
- падение сторонней библиотеки.

Часть из них ловится Error Boundary, часть - фреймворком, мониторингом и CI.

## Мини-шпаргалка

- Render errors ловит Error Boundary.
- Event handler errors ловит `try/catch` внутри handler.
- Async errors нужно явно обрабатывать.
- Validation errors - часть нормального UI.
- Production errors нужно логировать в monitoring.
