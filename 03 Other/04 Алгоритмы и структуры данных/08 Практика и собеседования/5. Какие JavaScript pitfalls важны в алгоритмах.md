# Какие JavaScript pitfalls важны в алгоритмах?

> [!summary]
> В JavaScript-алгоритмах часто ошибаются с `sort`, `shift`, мутацией массивов, сравнением объектов, `Map.get`, unicode-строками, числами, recursion stack и truthy/falsy проверками.

## sort сортирует как строки

```ts
[10, 2, 1].sort() // [1, 10, 2]
```

Правильно:

```ts
nums.sort((a, b) => a - b)
```

## sort мутирует

```ts
const sorted = [...nums].sort((a, b) => a - b)
```

Или:

```ts
const sorted = nums.toSorted((a, b) => a - b)
```

## shift может быть дорогим

```ts
const x = queue.shift()
```

Для BFS лучше:

```ts
let head = 0
const node = queue[head++]
```

## Map.get и falsy

Плохо:

```ts
const count = map.get(key) || 0
```

Лучше:

```ts
const count = map.get(key) ?? 0
```

## Объекты сравниваются по ссылке

```ts
{} === {} // false
```

В `Map` object keys тоже сравниваются по identity.

## Рекурсия может переполнить стек

Глубокий DFS на JS может упасть с:

```text
Maximum call stack size exceeded
```

Для большой глубины используй явный stack.

## Что отвечать на собеседовании?

В JS нужно помнить, что `sort()` без comparator сортирует строки и мутирует массив, `shift()` может быть дорогим, `Map.get` лучше сочетать с `??`, объекты сравниваются по ссылке, а глубокая рекурсия может переполнить call stack. Эти детали часто ломают правильную алгоритмическую идею.

## Частые ошибки

- Comparator возвращает boolean.
- `map.get(x) || default` ломает `0`.
- BFS через `shift`.
- Сравнение массивов через `===`.
- Мутация input без разрешения.
- Игнорирование unicode в строковых задачах.

## Мини-шпаргалка

- Numeric sort needs comparator.
- `sort` mutates.
- Queue: use head index.
- `??`, not `||`, for zero values.
- Objects compare by reference.
- Deep recursion risky.
