# Что делает flushSync?

> [!summary]
> `flushSync` из `react-dom` принудительно заставляет React синхронно применить updates внутри callback и сразу обновить DOM. Это редкий escape hatch для интеграции с браузерными API или сторонними библиотеками; обычный React-код должен обходиться без него.

## Базовый пример

```jsx
import { flushSync } from 'react-dom'

flushSync(() => {
  setIsOpen(true)
})

modalRef.current.focus()
```

После `flushSync` React уже применил DOM-изменения, поэтому следующий код может работать с обновленным DOM.

## Зачем это может понадобиться?

Иногда сторонний API ожидает, что DOM уже обновлен к следующей строке:

- интеграция с imperative UI library;
- browser APIs;
- измерение DOM сразу после state update;
- `beforeprint`;
- редкие focus/selection сценарии.

## Почему это опасно?

`flushSync`:

- может ухудшить performance;
- ломает преимущества batching;
- может вынудить Suspense fallback снова появиться;
- может выполнить pending effects раньше;
- делает код более хрупким.

Официальная рекомендация: использовать как last resort.

## Что использовать вместо?

Чаще достаточно:

- обычного state update;
- `useEffect`;
- `useLayoutEffect`;
- ref callback;
- корректной архитектуры flow.

Если хочется `flushSync`, сначала спроси:

```text
Почему мне нужно читать DOM прямо в следующей строке?
```

## Мини-шпаргалка

- `flushSync` принудительно синхронно обновляет DOM.
- Импортируется из `react-dom`.
- Используется редко для интеграций.
- Может вредить производительности.
- В обычном коде лучше избегать.
