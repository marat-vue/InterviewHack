# Когда использовать @Req и @Res?

> [!summary]
> `@Req()` и `@Res()` дают прямой доступ к request и response underlying platform. Их используют редко, когда нужен низкоуровневый контроль, потому что они могут привязать код к Express или Fastify.

## @Req

```ts
@Get()
find(@Req() req: Request) {
  return req.headers;
}
```

`@Req()` может быть полезен, если нужно прочитать platform-specific поле.

## @Res

```ts
@Get('download')
download(@Res() res: Response) {
  return res.download('report.pdf');
}
```

При использовании `@Res()` ты часто берешь ответственность за отправку ответа вручную.

## Почему осторожно?

Обычный Nest-style:

```ts
return this.usersService.findAll();
```

лучше работает с interceptors, serialization, testing и platform independence.

## passthrough

Если нужно выставить cookie/header, но сохранить Nest response handling:

```ts
@Get()
find(@Res({ passthrough: true }) res: Response) {
  res.cookie('theme', 'dark');
  return { ok: true };
}
```

## Мини-шпаргалка

- `@Req()` дает request object.
- `@Res()` дает response object.
- `@Res()` может отключить стандартную обработку Nest.
- `passthrough` сохраняет Nest response flow.
- Без нужды лучше возвращать value из метода.
