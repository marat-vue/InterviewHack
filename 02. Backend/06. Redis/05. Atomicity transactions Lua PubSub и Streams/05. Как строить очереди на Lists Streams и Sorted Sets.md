# Как строить очереди на Lists, Streams и Sorted Sets?

> [!NOTE]
> Redis можно использовать для очередей разного уровня сложности. Lists подходят для простых FIFO, Streams - для consumer groups и retry, Sorted Sets - для delayed jobs.

## Очередь на List

Producer:

```redis
LPUSH queue:emails '{"type":"welcome","userId":"1"}'
```

Consumer:

```redis
BRPOP queue:emails 0
```

Плюсы:

- просто;
- быстро;
- blocking pop.

Минусы:

- нет встроенного ack;
- сложнее retry;
- нет consumer groups.

## Очередь на Streams

Producer:

```redis
XADD emails * type welcome userId 1
```

Consumer:

```redis
XREADGROUP GROUP email-workers worker-1 STREAMS emails >
XACK emails email-workers message-id
```

Плюсы:

- consumer groups;
- pending entries;
- retry;
- история.

Минусы:

- сложнее модель;
- нужно trimming;
- нужно следить за pending.

## Delayed queue на Sorted Set

```redis
ZADD jobs:delayed 1786000000000 job:42
ZRANGEBYSCORE jobs:delayed -inf 1786000000000 LIMIT 0 10
ZREM jobs:delayed job:42
```

Score - timestamp. Worker забирает jobs, чей timestamp уже наступил.

Чтобы claim был атомарным, лучше Lua script: найти due jobs и удалить их как одну операцию.

## Как выбрать?

| Требование | Выбор |
|---|---|
| Простая локальная очередь | List |
| Несколько workers и retry | Streams |
| Delayed jobs | Sorted Set |
| Cron-like scheduling | Sorted Set + worker |
| High reliability jobs | Specialized queue или Streams с дисциплиной |

## Мини-шпаргалка

- List queue - просто, но мало гарантий.
- Streams - лучше для worker groups.
- Sorted Set - delayed/scheduled jobs.
- Любая очередь требует idempotency.
- Для critical jobs нужны retries, DLQ и monitoring.
