# Что такое MSW и зачем он нужен в тестах?

> [!summary]
> MSW, Mock Service Worker, перехватывает network-запросы и возвращает тестовые ответы. В тестах он позволяет мокать API на уровне HTTP, GraphQL или WebSocket, не подменяя внутреннюю реализацию API-клиента.

## Простое определение

MSW перехватывает запрос:

```text
Компонент -> fetch('/api/user') -> MSW handler -> тестовый response
```

Компонент думает, что общается с настоящим API. Тест при этом контролирует ответ.

## Почему не всегда достаточно `vi.mock`?

`vi.mock('@/api/users')` подменяет модуль. Это быстро, но тест знает внутреннюю структуру приложения.

MSW мокает сеть:

```ts
http.get('/api/users/:id', () => {
  return HttpResponse.json({ id: 1, name: 'Ann' });
});
```

Если завтра API-клиент переедет с `fetch` на Axios, тест с MSW может остаться прежним.

## Где MSW особенно полезен?

- component tests;
- integration tests;
- Storybook;
- e2e-like tests без настоящего backend;
- проверка loading/error/success;
- повторное использование handlers между тестами и development.

## Чем MSW отличается от backend mock?

Backend mock часто подменяет service/repository внутри backend. MSW подменяет network boundary с точки зрения клиента.

Это ближе к реальному поведению frontend.

## Мини-шпаргалка

- MSW мокает API на сетевой границе.
- Подходит для HTTP, GraphQL и WebSocket scenarios.
- Тест не зависит от настоящего backend.
- MSW меньше привязан к реализации API-клиента, чем `vi.mock`.
- Хорошо сочетается с Vitest, Testing Library и Storybook.
