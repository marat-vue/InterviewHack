# Чем ORM отличается от SQL query builder?

> [!summary]
> ORM отображает таблицы на объекты и часто управляет связями, загрузкой и изменениями сущностей. Query builder помогает программно собирать SQL-запросы, но обычно оставляет разработчика ближе к SQL-модели.

## ORM

ORM позволяет работать с сущностями.

```js
const user = await userRepository.findOne({
  where: { email },
  relations: { orders: true },
});
```

Плюсы:

- удобная работа с моделями;
- миграции и relations;
- меньше ручного SQL;
- типизация в некоторых инструментах.

Минусы:

- можно не заметить N+1;
- сложные запросы становятся непрозрачными;
- нужно понимать SQL под капотом.

## Query builder

```js
const users = await db
  .selectFrom('users')
  .select(['id', 'email'])
  .where('is_active', '=', true)
  .execute();
```

Query builder ближе к SQL и удобен для динамических фильтров.

## Главное

ORM и query builder не отменяют SQL. Чтобы писать быстрый backend, нужно понимать joins, индексы, транзакции и планы запросов.

## Мини-шпаргалка

- ORM работает через сущности.
- Query builder строит SQL программно.
- ORM может скрывать дорогие запросы.
- Query builder обычно прозрачнее для сложного SQL.
- В любом случае нужно читать SQL и `EXPLAIN`.
