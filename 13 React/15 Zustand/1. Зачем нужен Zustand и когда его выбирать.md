# Зачем нужен Zustand и когда его выбирать?

> [!summary]
> Zustand нужен, когда нескольким компонентам нужно общее client-side состояние без prop drilling и без тяжелой архитектуры Redux. Он хорошо подходит для UI-состояния, настроек, фильтров, selected entities и сложных интерактивных экранов.

## Какую проблему решает Zustand?

Без state manager часто появляется prop drilling:

```tsx
function App() {
  const [sidebarOpen, setSidebarOpen] = useState(false)

  return (
    <Layout
      sidebarOpen={sidebarOpen}
      setSidebarOpen={setSidebarOpen}
    />
  )
}
```

Если состояние нужно глубоко в дереве, его приходится прокидывать через много компонентов.

С Zustand компонент читает store напрямую:

```tsx
function SidebarButton() {
  const toggleSidebar = useLayoutStore((state) => state.toggleSidebar)

  return <button onClick={toggleSidebar}>Toggle</button>
}
```

## Zustand vs Context

| Критерий | Context | Zustand |
|---|---|---|
| Главная задача | dependency injection | global client state |
| Обновления | все потребители value могут ререндериться | selector подписывает на часть store |
| Boilerplate | мало | мало |
| Middleware | вручную | есть `persist`, `devtools`, `immer` |
| Хорош для | theme, locale, auth object | UI-state, filters, editors |

Context не плохой, но для часто меняющегося state Zustand обычно удобнее.

## Zustand vs Redux Toolkit

Zustand проще:

```tsx
const useStore = create((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
}))
```

Redux Toolkit строже и лучше подходит, когда нужна большая предсказуемая архитектура, actions log, сложные slices и единые conventions для большой команды.

## Что хранить в Zustand?

Хорошие кандидаты:

- открыт ли sidebar;
- активные фильтры;
- выбранный элемент;
- состояние wizard формы;
- настройки таблицы;
- drag-and-drop состояние;
- локальный draft;
- theme preference, если не хватает Context.

Плохие кандидаты:

- список пользователей с сервера;
- результат поиска с pagination;
- данные, требующие refetch;
- optimistic mutation cache;
- данные, которые должны инвалидироваться после мутаций.

Для последнего лучше TanStack Query.

## Что отвечать на собеседовании?

Zustand выбирают для client-side state, когда Context начинает приводить к prop drilling, лишним rerenders или неудобному обновлению состояния. Он проще Redux, хорошо типизируется и позволяет подписываться на отдельные куски store через selectors.

## Мини-шпаргалка

- Zustand - для client state.
- Context - для передачи dependency/value.
- TanStack Query - для server state.
- Redux Toolkit - для более строгой architecture.
- Selector важен для производительности.
