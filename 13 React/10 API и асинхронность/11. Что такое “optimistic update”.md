# Что такое “optimistic update”?

> [!summary]
> Optimistic update - это прием, при котором UI обновляется сразу после действия пользователя, не дожидаясь ответа сервера. Если сервер подтверждает операцию, UI уже выглядит правильно; если возвращает ошибку, изменение откатывают.

## Пример сценария

Пользователь нажал Like.

```text
1. UI сразу показывает liked = true
2. Запрос уходит на сервер
3. Если успех - ничего не меняем
4. Если ошибка - возвращаем старое состояние
```

Так интерфейс ощущается мгновенным.

## Пример с TanStack Query

```jsx
const queryClient = useQueryClient()

const likeMutation = useMutation({
  mutationFn: likePost,

  onMutate: async (postId) => {
    await queryClient.cancelQueries({ queryKey: ['post', postId] })

    const previousPost = queryClient.getQueryData(['post', postId])

    queryClient.setQueryData(['post', postId], (post) => ({
      ...post,
      isLiked: true,
      likesCount: post.likesCount + 1,
    }))

    return { previousPost }
  },

  onError: (_error, postId, context) => {
    queryClient.setQueryData(['post', postId], context.previousPost)
  },

  onSettled: (_data, _error, postId) => {
    queryClient.invalidateQueries({ queryKey: ['post', postId] })
  },
})
```

## Зачем cancelQueries?

Перед optimistic update часто отменяют активный refetch:

```jsx
await queryClient.cancelQueries({ queryKey: ['post', postId] })
```

Иначе старый refetch может прийти после optimistic update и перезаписать UI устаревшими данными.

## Где применять?

Хорошие кандидаты:

- лайки;
- сохранение настроек;
- добавление комментария;
- checkbox/toggle;
- drag-and-drop reorder;
- отметка задачи выполненной.

Плохие кандидаты:

- оплата;
- перевод денег;
- критичные операции без простого rollback;
- операции со сложной серверной бизнес-логикой.

## Риски

- нужно уметь откатить изменение;
- нужно повторить часть серверной логики на клиенте;
- возможны race conditions;
- пользователь может быстро сделать несколько мутаций подряд;
- optimistic UI может временно показать неверные данные.

## Мини-шпаргалка

- Optimistic update обновляет UI до ответа сервера.
- На ошибке нужен rollback.
- На завершении часто делают invalidate/refetch.
- Хорошо подходит для быстрых обратимых действий.
- Для критичных операций лучше дождаться сервера.
