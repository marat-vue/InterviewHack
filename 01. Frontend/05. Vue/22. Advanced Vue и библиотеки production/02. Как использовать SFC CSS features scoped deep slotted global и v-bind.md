# Как использовать SFC CSS features: scoped, deep, slotted, global и v-bind?

> [!NOTE]
> SFC CSS features позволяют держать стили рядом с компонентом, изолировать селекторы, управлять стилями дочерних компонентов и прокидывать реактивные значения из JavaScript в CSS.

## Вопрос

Как использовать CSS-возможности `.vue` файлов: `scoped`, `:deep()`, `:slotted()`, `:global()`, CSS Modules и `v-bind()`?

## Зачем это нужно

В Vue-проекте стили часто живут на нескольких уровнях:

- глобальные tokens и reset;
- layout-стили приложения;
- стили конкретного компонента;
- стили UI-библиотеки;
- динамические стили, зависящие от props или state.

SFC CSS features помогают не превращать это в хаос: локальные стили остаются локальными, а намеренные выходы наружу становятся явными.

## `scoped`

`<style scoped>` ограничивает стили текущим компонентом.

```vue
<template>
  <article class="card">
    <h2 class="title">{{ title }}</h2>
  </article>
</template>

<style scoped>
.card {
  border: 1px solid #d1d5db;
  padding: 16px;
}

.title {
  font-size: 20px;
}
</style>
```

Vue compiler добавляет специальный data-атрибут к элементам компонента и переписывает селекторы так, чтобы они применялись только к ним.

Когда использовать:

- компонентные стили;
- небольшие layout-правила внутри компонента;
- стили, которые не должны вытекать наружу.

Когда не стоит:

- design tokens;
- reset/normalize;
- typography scale на уровне приложения;
- классы, которые специально должны быть общими.

## Стили родителя и корневой элемент ребенка

Даже при `scoped` родитель может стилизовать корневой элемент дочернего компонента. Это сделано специально, чтобы родитель мог управлять layout-положением ребенка.

```vue
<template>
  <UserCard class="grid-item" />
</template>

<style scoped>
.grid-item {
  min-width: 0;
}
</style>
```

Важно: родитель не должен лезть глубоко во внутреннюю разметку ребенка без явной причины.

## `:deep()`

`:deep()` позволяет применить scoped-стиль к внутренним элементам дочернего компонента или HTML, который находится глубже.

```vue
<template>
  <BaseEditor class="editor" />
</template>

<style scoped>
.editor :deep(.ProseMirror) {
  min-height: 240px;
  outline: none;
}
</style>
```

Где применять:

- стилизация third-party компонентов;
- интеграция редакторов, календарей, charts;
- точечная настройка UI-библиотеки, если нет prop/theme API.

Чего избегать:

- больших каскадных переопределений;
- зависимости от нестабильных внутренних классов библиотеки;
- использования `:deep()` как основного способа темизации.

Лучше сначала проверить, есть ли у библиотеки официальные props, tokens, theme или slots.

## `:slotted()`

`:slotted()` стилизует элементы, которые пришли в slot от родителя.

```vue
<template>
  <section class="panel">
    <slot />
  </section>
</template>

<style scoped>
:slotted(h2) {
  margin-top: 0;
}

:slotted(a) {
  color: #2563eb;
}
</style>
```

Когда применять:

- компонент-контейнер задает правила для контента в slot;
- markdown/content-renderer;
- layout-компоненты вроде `Panel`, `Article`, `Sidebar`.

Важно: slot-контент принадлежит родителю, поэтому не стоит делать слишком агрессивные правила.

## `:global()`

`:global()` объявляет глобальный селектор внутри scoped style.

```vue
<style scoped>
:global(body.modal-open) {
  overflow: hidden;
}
</style>
```

Использовать аккуратно. Если глобальных правил много, лучше вынести их в отдельный global CSS-файл.

Хорошие кейсы:

- один глобальный класс состояния;
- интеграция с внешним DOM;
- временный bridge при миграции.

Плохие кейсы:

- глобальная тема приложения;
- reset;
- переопределение половины UI-библиотеки.

## CSS Modules

CSS Modules создают объект классов и хорошо подходят, когда нужен явный доступ к class name из JS.

```vue
<template>
  <button :class="$style.button">
    Сохранить
  </button>
</template>

<style module>
.button {
  padding: 8px 12px;
}
</style>
```

С именованным модулем:

```vue
<template>
  <button :class="classes.primaryButton">
    Сохранить
  </button>
</template>

<style module="classes">
.primaryButton {
  background: #2563eb;
}
</style>
```

Когда выбирать CSS Modules:

- проект уже использует modules;
- нужно передавать class names в JS;
- нужно избежать конфликтов без атрибута `scoped`.

Для обычных Vue-компонентов чаще достаточно `<style scoped>`.

## `v-bind()` в CSS

`v-bind()` внутри CSS позволяет использовать значения из `<script setup>` как CSS custom properties.

```vue
<script setup lang="ts">
const props = withDefaults(
  defineProps<{
    accent?: string;
  }>(),
  {
    accent: "#2563eb",
  },
);
</script>

<template>
  <button class="button">
    Сохранить
  </button>
</template>

<style scoped>
.button {
  background: v-bind("props.accent");
  color: white;
}
</style>
```

Vue компилирует это в CSS-переменные и обновляет их реактивно.

Где удобно:

- dynamic colors;
- размеры из props;
- CSS-переменные для компонента;
- theme-aware компоненты без inline styles.

## Практический пример: карточка с настройками

```vue
<script setup lang="ts">
const props = withDefaults(
  defineProps<{
    tone?: "info" | "success" | "danger";
  }>(),
  {
    tone: "info",
  },
);

const colors = {
  info: "#2563eb",
  success: "#16a34a",
  danger: "#dc2626",
};
</script>

<template>
  <article class="notice">
    <slot />
  </article>
</template>

<style scoped>
.notice {
  border-left: 4px solid v-bind("colors[props.tone]");
  padding: 12px 16px;
}

.notice :deep(code) {
  font-size: 0.9em;
}

:slotted(p:first-child) {
  margin-top: 0;
}
</style>
```

## Частые ошибки

- Использовать `:deep()` вместо нормального публичного API компонента.
- Делать глобальные стили внутри каждого SFC.
- Думать, что `scoped` полностью изолирует приложение от CSS-каскада. Наследуемые свойства вроде `color` и `font-family` все равно наследуются.
- Стилизовать внутренности UI-библиотеки по нестабильным class names.
- Пихать все динамические стили в inline `:style`, хотя иногда лучше CSS variables через `v-bind()`.
- Делать слишком сложные селекторы в `scoped`, увеличивая стоимость CSS matching.

## Что отвечать на собеседовании

SFC CSS во Vue дает локальные стили через `scoped`, controlled escape hatches через `:deep`, `:slotted` и `:global`, CSS Modules для явных class maps и `v-bind()` для реактивных CSS-переменных. В production важно не злоупотреблять глубокими селекторами, сначала использовать theme/props/slots библиотек и держать глобальные стили отдельно.

## Мини-шпаргалка

- `scoped` - локальные стили компонента.
- `:deep()` - точечный доступ к дочерней разметке.
- `:slotted()` - стили для slot-контента.
- `:global()` - глобальный селектор внутри SFC.
- `<style module>` - CSS Modules.
- `v-bind()` в CSS - реактивные значения из JS в CSS.
