# Глубокая рекурсия

> [!summary] Коротко
> При слишком глубокой рекурсии в JavaScript может произойти переполнение стека вызовов: `RangeError: Maximum call stack size exceeded`.

## Вопрос

Что произойдет при очень глубокой рекурсии?

## Почему возникает ошибка

Каждый вызов функции занимает место в call stack.

```javascript
function countDown(n) {
  if (n === 0) return;

  countDown(n - 1);
}

countDown(100000);
```

При большой глубине стек может закончиться.

Типичная ошибка:

```text
RangeError: Maximum call stack size exceeded
```

## Бесконечная рекурсия

```javascript
function loop() {
  loop();
}

loop();
```

Здесь нет базового случая, поэтому функция вызывает себя бесконечно, пока стек не переполнится.

## Глубокая, но конечная рекурсия

Даже если базовый случай есть, глубина может быть слишком большой.

```javascript
function sum(n) {
  if (n === 0) return 0;

  return n + sum(n - 1);
}

sum(1_000_000); // риск переполнения стека
```

## Как избежать

### Заменить циклом

```javascript
function sum(n) {
  let total = 0;

  for (let i = 1; i <= n; i++) {
    total += i;
  }

  return total;
}
```

### Использовать явный стек

```javascript
function traverse(root) {
  const stack = [root];

  while (stack.length > 0) {
    const node = stack.pop();

    for (const child of node.children) {
      stack.push(child);
    }
  }
}
```

Так можно обходить глубокие структуры без рекурсивных вызовов.

## Tail call optimization

В спецификации есть идея оптимизации хвостовых вызовов, но в популярных JavaScript-движках рассчитывать на нее в обычной разработке не стоит.

## Мини-шпаргалка

| Проблема | Решение |
| --- | --- |
| нет базового случая | добавить условие остановки |
| глубина слишком большая | заменить циклом |
| глубокое дерево | использовать явный стек |
| много вложенных вызовов | разбить алгоритм |
| надежда на TCO | не полагаться в JS |
