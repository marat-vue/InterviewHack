# Что такое hash table?

> [!summary]
> Hash table - структура данных для хранения ключ-значение с быстрым доступом по ключу. В JavaScript роль готовой hash table чаще всего выполняют `Map`, `Set` и иногда plain object.

## Основная идея

Hash table превращает key в индекс через hash function:

```text
key -> hash -> bucket -> value
```

Так можно быстро находить значение по ключу.

## В JavaScript

Для алгоритмов обычно не пишут hash table с нуля, а используют:

```ts
const map = new Map<string, number>()
const set = new Set<string>()
```

## Пример: частоты

```ts
function firstUniqueChar(s: string): string | null {
  const count = new Map<string, number>()

  for (const char of s) {
    count.set(char, (count.get(char) ?? 0) + 1)
  }

  for (const char of s) {
    if (count.get(char) === 1) return char
  }

  return null
}
```

Time `O(n)`, space `O(k)`, где `k` - число разных символов.

## Collisions

Collision - ситуация, когда разные keys попадают в один bucket.

Hash table решает это через:

- chaining;
- open addressing;
- другие стратегии.

На JS-собеседовании обычно достаточно понимать идею, а не реализацию движка.

## Что отвечать на собеседовании?

Hash table хранит пары ключ-значение и использует hash function для быстрого доступа. Средняя сложность `get/set/has` обычно считается `O(1)`, но в худшем случае может деградировать. В JavaScript для практических задач я использую `Map` и `Set`.

## Частые ошибки

- Гарантировать `O(1)` как абсолютную истину.
- Не учитывать память `O(n)`.
- Использовать `includes` вместо `Set.has`.
- Путать hash table с sorted map.
- Забывать про equality object keys по ссылке.

## Мини-шпаргалка

- Hash table = key -> value.
- `Map` - hash map-like коллекция.
- `Set` - hash set-like коллекция.
- Средний доступ - `O(1)`.
- Частоты и индексы - классический кейс.
- Collisions существуют, но обычно скрыты.
