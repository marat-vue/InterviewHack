# Как поддерживать зависимости безопасными?

> [!summary]
> Node.js-проекты зависят от npm-пакетов, поэтому безопасность включает lockfile, регулярные обновления, audit, минимизацию зависимостей, проверку lifecycle scripts и осторожность с abandoned-пакетами.

## Lockfile

`package-lock.json`, `pnpm-lock.yaml` или `yarn.lock` фиксирует конкретные версии зависимостей.

```bash
npm ci
```

`npm ci` устанавливает зависимости строго по lockfile и хорошо подходит для CI.

## Audit

```bash
npm audit
```

Audit показывает известные уязвимости. Важно не просто запускать команду, а оценивать:

- затронут ли production-код;
- доступна ли безопасная версия;
- не ломает ли обновление API;
- можно ли заменить пакет.

## Минимизация зависимостей

Каждая зависимость - это чужой код в твоем процессе. Для простых задач иногда лучше использовать встроенный Node.js API.

```js
import { randomUUID } from 'node:crypto';
```

Не обязательно ставить пакет ради UUID.

## Lifecycle scripts

Пакеты могут запускать scripts при установке. В чувствительных окружениях это нужно учитывать и ограничивать.

## Мини-шпаргалка

- Коммить lockfile.
- В CI используй `npm ci`.
- Регулярно проверяй audit.
- Не ставь пакет ради одной простой функции.
- Следи за scripts и abandoned-зависимостями.
