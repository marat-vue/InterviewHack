# Как писать functions, procedures и triggers в PostgreSQL?

> [!NOTE]
> PostgreSQL позволяет переносить часть логики в БД через functions, procedures и triggers. Это мощно для audit, constraints и denormalized counters, но может сделать систему непрозрачной, если злоупотреблять.

## Function

```sql
CREATE FUNCTION normalize_email(email text)
RETURNS text
LANGUAGE sql
IMMUTABLE
AS $$
  SELECT lower(trim(email));
$$;
```

Использование:

```sql
SELECT normalize_email(' Admin@Example.com ');
```

## Procedure

Procedure вызывается через `CALL` и может использовать transaction control в подходящих условиях.

```sql
CREATE PROCEDURE archive_old_events()
LANGUAGE plpgsql
AS $$
BEGIN
  DELETE FROM events
  WHERE created_at < now() - interval '1 year';
END;
$$;

CALL archive_old_events();
```

## Trigger

Trigger вызывает function на событие таблицы.

```sql
CREATE FUNCTION set_updated_at()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$;

CREATE TRIGGER users_set_updated_at
BEFORE UPDATE ON users
FOR EACH ROW
EXECUTE FUNCTION set_updated_at();
```

## Trigger timing

| Timing | Когда |
|---|---|
| `BEFORE` | до изменения строки |
| `AFTER` | после изменения |
| `INSTEAD OF` | вместо операции, чаще для views |

Scope:

- `FOR EACH ROW`;
- `FOR EACH STATEMENT`.

## Когда использовать triggers?

Хорошо:

- `updated_at`;
- audit log;
- consistency check, которую сложно забыть;
- denormalized counters;
- automatic search vector update.

Плохо:

- скрытая бизнес-логика;
- внешние HTTP вызовы;
- сложные workflows;
- логика, которую приложение должно явно контролировать.

## Мини-шпаргалка

- Function возвращает значение.
- Procedure вызывается через `CALL`.
- Trigger function возвращает `trigger`.
- `BEFORE` может менять `NEW`.
- Triggers полезны, но легко создают скрытую магию.
