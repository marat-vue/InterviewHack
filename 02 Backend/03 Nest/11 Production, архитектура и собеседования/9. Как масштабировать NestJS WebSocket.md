# Как масштабировать NestJS WebSocket?

> [!summary]
> WebSocket-соединение живет в конкретном процессе, поэтому при нескольких инстансах NestJS нужны sticky sessions и общий pub/sub или adapter, чтобы сообщения доходили до клиентов на разных инстансах.

## Проблема

```txt
client A -> app-1
client B -> app-2
event on app-3
```

Если app-3 не знает о socket на app-1, сообщение не дойдет без общего механизма.

## Что нужно?

- load balancer с WebSocket upgrade;
- sticky sessions или state-aware gateway;
- Redis adapter/pub-sub;
- shared auth/session strategy;
- мониторинг connected clients.

## Socket.IO adapter

Для Socket.IO часто используют Redis adapter, чтобы события распространялись между инстансами.

## Мини-шпаргалка

- WebSocket state живет в процессе.
- Несколько инстансов требуют общей шины событий.
- Sticky sessions часто нужны на load balancer.
- Redis pub/sub помогает broadcast между instances.
- Auth handshake нужно проектировать отдельно.
