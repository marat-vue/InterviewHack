# Что делает Suspense в React 18?

> [!summary]
> В React 18 Suspense стал важной частью concurrent rendering и streaming SSR. Он по-прежнему показывает `fallback`, пока часть дерева не готова, но теперь особенно важен для серверного streaming и постепенной загрузки UI.

## Базовая идея Suspense

```jsx
import { lazy, Suspense } from 'react'

const SettingsPage = lazy(() => import('./SettingsPage'))

function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <SettingsPage />
    </Suspense>
  )
}
```

Если `SettingsPage` еще не готов, React показывает `PageSkeleton`.

## Что изменилось в React 18?

Ключевые улучшения:

- Suspense стал основой streaming SSR;
- React может отправлять HTML частями;
- Suspense boundaries помогают разделять независимые зоны загрузки;
- transitions помогают избежать резкой замены уже видимого UI на fallback;
- concurrent renderer может продолжать более важную работу.

## Suspense и сервер

```jsx
function ProductPage() {
  return (
    <ProductLayout>
      <ProductInfo />

      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />
      </Suspense>
    </ProductLayout>
  )
}
```

В streaming SSR сервер может отправить `ProductLayout` и fallback сразу, а `Reviews` дослать позже.

## Suspense не делает fetch сам

Плохо думать:

```text
Suspense = замена fetch
```

Правильнее:

```text
Suspense = механизм ожидания Suspense-enabled ресурса
```

Обычный `fetch` внутри `useEffect` Suspense не активирует.

## Suspense и ошибки

Suspense отвечает за ожидание. Ошибки обрабатывает Error Boundary.

```jsx
<ErrorBoundary fallback={<ErrorFallback />}>
  <Suspense fallback={<Loading />}>
    <LazyPage />
  </Suspense>
</ErrorBoundary>
```

## Мини-шпаргалка

- Suspense показывает fallback.
- В React 18 Suspense особенно важен для streaming SSR.
- Обычный `useEffect + fetch` не suspend-ит.
- Ошибки ловит Error Boundary.
- Boundaries лучше ставить вокруг независимых зон UI.
