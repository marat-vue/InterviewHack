# Почему setState не изменяет состояние мгновенно?

> [!summary]
> Setter состояния в React не меняет переменную state прямо в текущем render. Он планирует обновление. Новое значение станет доступно при следующем render, поэтому сразу после вызова setter в текущей функции ты часто видишь старое значение.

## Пример

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  function handleClick() {
    setCount(count + 1)
    console.log(count)
  }

  return <button onClick={handleClick}>{count}</button>
}
```

Если `count` был `0`, `console.log(count)` выведет `0`, а не `1`.

## Почему так?

Каждый render имеет свой snapshot значений:

```text
render #1: count = 0
handleClick из render #1 тоже видит count = 0
setCount(1) планирует render #2
render #2: count = 1
```

State внутри уже выполненного обработчика не "переписывается".

## Как обновлять на основе предыдущего значения?

Используй updater function:

```jsx
setCount((prevCount) => prevCount + 1)
```

Это особенно важно при нескольких обновлениях подряд:

```jsx
setCount((count) => count + 1)
setCount((count) => count + 1)
setCount((count) => count + 1)
```

React применит обновления последовательно.

## Как выполнить код после изменения UI?

Если нужно реагировать на изменение state:

```jsx
useEffect(() => {
  console.log('count изменился:', count)
}, [count])
```

Если нужно значение прямо в обработчике, вычисли его заранее:

```jsx
const nextCount = count + 1
setCount(nextCount)
console.log(nextCount)
```

## Мини-шпаргалка

- Setter планирует обновление, а не меняет state в текущем render.
- Текущий обработчик видит snapshot старого state.
- Для обновления от предыдущего значения используй updater function.
- Для реакции на изменение используй `useEffect`.
- Несколько обновлений могут batching-обрабатываться вместе.
