# Как глубже устроены SFC, script setup и compiler macros?

> [!NOTE]
> SFC (`.vue`) - это формат Vue-компонента с блоками `template`, `script` и `style`, а `<script setup>` - compile-time синтаксис поверх Composition API. Большая часть его "магии" работает на этапе сборки, а не в runtime.

## Вопрос

Как глубже устроены Single-File Components, `<script setup>` и compiler macros во Vue?

## Что такое SFC

SFC - Single-File Component, то есть файл `.vue`, который обычно содержит:

```vue
<template>
  <button class="counter" @click="count++">
    {{ label }}: {{ count }}
  </button>
</template>

<script setup lang="ts">
import { ref } from "vue";

defineProps<{
  label: string;
}>();

const count = ref(0);
</script>

<style scoped>
.counter {
  padding: 8px 12px;
}
</style>
```

SFC нужен, чтобы держать разметку, логику и стили компонента рядом. Это не значит "смешать все в кашу"; это значит описать один UI-модуль в одном месте.

## Что делает `<script setup>`

`<script setup>` компилируется как тело функции `setup()` компонента.

Это дает несколько важных последствий:

- top-level переменные доступны в шаблоне без `return`;
- импортированные компоненты можно сразу использовать в `<template>`;
- код внутри `<script setup>` выполняется для каждого экземпляра компонента;
- compiler macros не импортируются и исчезают после компиляции;
- `defineProps` и `defineEmits` поднимаются в module scope, поэтому не могут ссылаться на локальные переменные из setup scope.

Пример:

```vue
<script setup lang="ts">
import UserAvatar from "@/components/UserAvatar.vue";
import { computed } from "vue";

const props = defineProps<{
  firstName: string;
  lastName: string;
}>();

const fullName = computed(() => `${props.firstName} ${props.lastName}`);
</script>

<template>
  <UserAvatar :name="fullName" />
</template>
```

## Какие compiler macros нужно знать

### `defineProps`

Описывает входные props компонента.

TypeScript-вариант:

```vue
<script setup lang="ts">
const props = defineProps<{
  id: number;
  title: string;
  disabled?: boolean;
}>();
</script>
```

Runtime-вариант:

```vue
<script setup>
const props = defineProps({
  id: {
    type: Number,
    required: true,
  },
  title: {
    type: String,
    default: "Без названия",
  },
});
</script>
```

Когда использовать:

- type-only синтаксис - когда проект на TypeScript;
- runtime-синтаксис - когда нужны runtime validators или JavaScript-проект без TS.

### `withDefaults`

Задает значения по умолчанию для type-only props.

```vue
<script setup lang="ts">
const props = withDefaults(
  defineProps<{
    page?: number;
    pageSize?: number;
    variant?: "plain" | "card";
  }>(),
  {
    page: 1,
    pageSize: 20,
    variant: "plain",
  },
);
</script>
```

Зачем нужно:

- не смешивать TS-описание props с runtime object-синтаксисом;
- явно показать, какие optional props становятся фактически заданными.

### `defineEmits`

Описывает события компонента.

```vue
<script setup lang="ts">
const emit = defineEmits<{
  save: [payload: { title: string }];
  cancel: [];
}>();

function submit() {
  emit("save", { title: "Vue" });
}
</script>
```

Что важно:

- события - часть публичного API компонента;
- событие должно называться как действие пользователя или изменение состояния;
- `update:modelValue` используется для `v-model`.

### `defineModel`

Упрощает объявление `v-model` в дочернем компоненте.

```vue
<script setup lang="ts">
const model = defineModel<string>({
  required: true,
});
</script>

<template>
  <input v-model="model" />
</template>
```

Раньше то же самое писали через `modelValue` и `update:modelValue`:

```vue
<script setup lang="ts">
defineProps<{
  modelValue: string;
}>();

defineEmits<{
  "update:modelValue": [value: string];
}>();
</script>
```

Несколько моделей:

```vue
<script setup lang="ts">
const firstName = defineModel<string>("firstName");
const lastName = defineModel<string>("lastName");
</script>
```

Использование:

```vue
<UserNameFields
  v-model:first-name="form.firstName"
  v-model:last-name="form.lastName"
/>
```

Важный нюанс: если задать `default` в `defineModel`, а родитель передаст `undefined`, можно получить рассинхронизацию между локальным значением ребенка и состоянием родителя. Для обязательных полей чаще лучше `required: true`.

### `defineExpose`

Открывает наружу методы или свойства компонента при доступе через template ref.

```vue
<script setup lang="ts">
function focus() {
  input.value?.focus();
}

const input = useTemplateRef<HTMLInputElement>("input");

defineExpose({
  focus,
});
</script>

<template>
  <input ref="input" />
</template>
```

Когда использовать:

- компоненты-поля с методом `focus`;
- модалки с методами `open`/`close`;
- интеграция с imperative API.

Когда не использовать:

- для обычной передачи данных;
- вместо props/emits;
- чтобы родитель управлял внутренним состоянием ребенка без явного контракта.

### `defineOptions`

Задает options компонента прямо внутри `<script setup>`.

```vue
<script setup lang="ts">
defineOptions({
  name: "BaseButton",
  inheritAttrs: false,
});
</script>
```

Частые кейсы:

- задать `name`;
- отключить автоматический проброс атрибутов через `inheritAttrs: false`;
- задать совместимые component options без отдельного `<script>`.

### `defineSlots`

Типизирует slots компонента.

```vue
<script setup lang="ts">
defineSlots<{
  default(props: { user: { id: number; name: string } }): unknown;
  actions(props: { disabled: boolean }): unknown;
}>();
</script>
```

Зачем нужно:

- IDE подсказывает slot props;
- родитель получает понятный контракт;
- меньше ошибок в сложных table/list/form компонентах.

### `useSlots` и `useAttrs`

`useSlots()` дает доступ к slots внутри `<script setup>`, а `useAttrs()` - к fallthrough attributes.

```vue
<script setup lang="ts">
import { computed, useAttrs, useSlots } from "vue";

const attrs = useAttrs();
const slots = useSlots();

const hasFooter = computed(() => Boolean(slots.footer));
</script>
```

Их используют, когда нужно принять решение в JS-логике, а не только в шаблоне.

## Top-level await

В `<script setup>` можно использовать `await` на верхнем уровне:

```vue
<script setup lang="ts">
const user = await fetchUser();
</script>
```

Такой компонент становится async dependency и обычно должен рендериться внутри `Suspense`.

```vue
<Suspense>
  <UserProfile />

  <template #fallback>
    <UserProfileSkeleton />
  </template>
</Suspense>
```

В Nuxt чаще используют `useAsyncData`, `useFetch` или server-side data fetching, потому что Nuxt добавляет свой слой SSR/hydration.

## Generic SFC

Generic SFC полезны для универсальных компонентов: таблиц, selects, autocomplete, data lists.

```vue
<script setup lang="ts" generic="T extends { id: string | number }">
defineProps<{
  items: T[];
  getLabel: (item: T) => string;
}>();

const selected = defineModel<T | null>();
</script>
```

Пример использования:

```vue
<EntitySelect
  v-model="selectedUser"
  :items="users"
  :get-label="(user) => user.name"
/>
```

## Обычный `<script>` рядом с `<script setup>`

Иногда рядом оставляют обычный `<script>`:

```vue
<script lang="ts">
export const USER_CARD_KIND = "user-card";
</script>

<script setup lang="ts">
defineOptions({
  name: "UserCard",
});
</script>
```

Когда это оправдано:

- нужен module-level export;
- нужно выполнить код один раз при импорте модуля;
- есть legacy option, которую неудобно перенести.

В большинстве компонентов достаточно только `<script setup>`.

## Частые ошибки

- Импортировать `defineProps`, `defineEmits`, `defineModel` из `vue`. Это compiler macros, импорт не нужен.
- Ссылаться из `defineProps` на локальную переменную из setup scope.
- Делать `defineExpose` для всего внутреннего state.
- Использовать `defineModel` везде, где достаточно обычного `:value` и `@select`.
- Держать слишком много бизнес-логики прямо в SFC вместо composables/stores.
- Путать top-level module scope и instance scope.

## Что отвечать на собеседовании

`<script setup>` - это рекомендуемый синтаксис для Composition API в SFC. Он компилируется в `setup()`, автоматически открывает top-level bindings шаблону и дает compiler macros для props, emits, model, slots, expose и options. Важно понимать, что macros работают на этапе компиляции, поэтому у них есть ограничения по scope. В production это делает компоненты короче, лучше типизирует публичный контракт и снижает boilerplate.

## Мини-шпаргалка

- `defineProps` - входные данные компонента.
- `withDefaults` - defaults для type-only props.
- `defineEmits` - события компонента.
- `defineModel` - `v-model` контракт.
- `defineExpose` - публичные методы через ref.
- `defineOptions` - options внутри `<script setup>`.
- `defineSlots` - типизация slots.
- `useAttrs` - доступ к fallthrough attributes.
- `useSlots` - доступ к slots.
- top-level `await` делает компонент async dependency.
- generic SFC нужны для универсальных типизированных компонентов.
