# Как писать where, select, include, orderBy и pagination?

> [!NOTE]
> Большая часть Prisma-запросов строится вокруг `where`, `select`, `include`, `orderBy`, `skip`, `take` и `cursor`. Эти options определяют фильтрацию, форму ответа, связанные данные, сортировку и пагинацию.

## `where`

```ts
await prisma.user.findMany({
  where: {
    email: {
      contains: '@example.com',
    },
    emailVerified: true,
  },
});
```

Типовые filters:

| Filter | Что делает |
|---|---|
| `equals` | равно |
| `not` | не равно/не условие |
| `in` | входит в список |
| `notIn` | не входит в список |
| `lt` | меньше |
| `lte` | меньше или равно |
| `gt` | больше |
| `gte` | больше или равно |
| `contains` | содержит строку |
| `startsWith` | начинается со строки |
| `endsWith` | заканчивается строкой |
| `mode: 'insensitive'` | case-insensitive поиск там, где поддерживается |

## AND OR NOT

```ts
await prisma.post.findMany({
  where: {
    OR: [
      { title: { contains: 'nitro', mode: 'insensitive' } },
      { content: { contains: 'nitro', mode: 'insensitive' } },
    ],
    NOT: {
      status: 'DELETED',
    },
  },
});
```

## `select`

`select` выбирает только нужные поля:

```ts
await prisma.user.findMany({
  select: {
    id: true,
    email: true,
  },
});
```

Плюсы:

- меньше данных из БД;
- меньше риск вернуть secret fields;
- ясный API response;
- лучше TypeScript type.

## `include`

`include` добавляет relation:

```ts
await prisma.user.findMany({
  include: {
    posts: true,
  },
});
```

Relation можно фильтровать:

```ts
await prisma.user.findMany({
  include: {
    posts: {
      where: {
        published: true,
      },
      select: {
        id: true,
        title: true,
      },
    },
  },
});
```

## `select` или `include`?

| Нужно | Используй |
|---|---|
| Только конкретные поля модели | `select` |
| Вернуть связи | `include` |
| Вернуть связи, но ограничить поля | `include` + nested `select` |
| Не вернуть password/hash/secret | `select` |

## `orderBy`

```ts
await prisma.post.findMany({
  orderBy: [
    { createdAt: 'desc' },
    { id: 'asc' },
  ],
});
```

Для стабильной пагинации добавляй tie-breaker, например `id`.

## Offset pagination

```ts
const page = 2;
const limit = 20;

const users = await prisma.user.findMany({
  skip: (page - 1) * limit,
  take: limit,
  orderBy: {
    createdAt: 'desc',
  },
});
```

Плюсы:

- просто;
- удобно для админок;
- легко считать страницы.

Минусы:

- на больших offsets может быть медленно;
- при изменении данных возможны повторы/пропуски.

## Cursor pagination

```ts
await prisma.post.findMany({
  take: 20,
  cursor: {
    id: cursorId,
  },
  skip: 1,
  orderBy: {
    id: 'asc',
  },
});
```

Плюсы:

- лучше для больших списков;
- стабильнее при scrolling;
- меньше нагрузка на глубоких страницах.

Минусы:

- сложнее UI;
- нужен cursor;
- не так удобно прыгать на произвольную страницу.

## Count для pagination metadata

```ts
const [items, total] = await prisma.$transaction([
  prisma.user.findMany({ skip, take }),
  prisma.user.count({ where }),
]);
```

Так список и count выполняются в одном transaction batch.

## Мини-шпаргалка

- `where` - filter.
- `select` - какие поля вернуть.
- `include` - какие связи вернуть.
- `orderBy` - сортировка.
- `skip/take` - offset pagination.
- `cursor/take/skip: 1` - cursor pagination.
- Для публичного API не возвращай лишние поля.
- Для стабильной сортировки добавляй tie-breaker.
