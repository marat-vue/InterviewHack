# Что делает useDeferredValue()?

> [!summary]
> `useDeferredValue` возвращает отложенную версию значения. Срочный UI получает новое значение сразу, а тяжелая часть интерфейса может обновиться позже с меньшим приоритетом. Это помогает сохранить отзывчивость при поиске, фильтрации, табах, графиках и больших списках.

## Базовая идея

Допустим, пользователь печатает в input, а ниже находится тяжелый список.

Если список фильтруется на каждый символ синхронно, input может начать тормозить. `useDeferredValue` позволяет разделить:

- настоящее значение для input;
- отложенное значение для тяжелого UI.

```jsx
import { useDeferredValue, useMemo, useState } from 'react'

function SearchPage({ products }) {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)

  const filteredProducts = useMemo(() => {
    return products.filter((product) =>
      product.title.toLowerCase().includes(deferredQuery.toLowerCase()),
    )
  }, [products, deferredQuery])

  return (
    <>
      <input
        value={query}
        onChange={(event) => setQuery(event.target.value)}
      />
      <ProductList products={filteredProducts} />
    </>
  )
}
```

Input использует `query` и остается быстрым. Список использует `deferredQuery` и может немного отставать.

## Как показать, что UI устарел?

Можно сравнить актуальное и отложенное значение:

```jsx
function SearchPage({ products }) {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)
  const isStale = query !== deferredQuery

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />

      <div style={{ opacity: isStale ? 0.5 : 1 }}>
        <SearchResults query={deferredQuery} products={products} />
      </div>
    </>
  )
}
```

Это часто лучше, чем дергать spinner на каждый символ.

## Чем useDeferredValue похож на debounce?

Оба помогают при частых изменениях:

- пользователь печатает;
- значение меняется много раз подряд;
- тяжелую работу не хочется делать слишком резко.

## Чем отличается от debounce?

| Критерий | `useDeferredValue` | debounce |
|---|---|---|
| Механизм | приоритеты React | таймер |
| Задержка | зависит от нагрузки | фиксированная, например 300 мс |
| Render | может быть прерван React | React не знает о таймере |
| Лучший сценарий | тяжелый render UI | запросы, автосохранение, API calls |

`useDeferredValue` не заменяет debounce для сетевых запросов.

Для API поиска часто нужен debounce:

```jsx
useEffect(() => {
  const timeoutId = setTimeout(() => {
    fetch(`/api/search?q=${query}`)
  }, 300)

  return () => clearTimeout(timeoutId)
}, [query])
```

А `useDeferredValue` помогает, когда тяжелый именно render.

## Чем отличается от startTransition?

Оба API говорят React: "это не срочно", но делают это с разных сторон.

| API | Что помечает | Когда удобно |
|---|---|---|
| `startTransition` | state update | ты контролируешь момент `setState` |
| `useTransition` | state update + `isPending` | нужен pending indicator |
| `useDeferredValue` | значение | значение уже пришло, но зависимый UI можно отложить |

Пример с `startTransition`:

```jsx
const [query, setQuery] = useState('')
const [filteredProducts, setFilteredProducts] = useState(products)
const [isPending, startTransition] = useTransition()

function handleChange(event) {
  const nextQuery = event.target.value

  setQuery(nextQuery)

  startTransition(() => {
    setFilteredProducts(filterProducts(products, nextQuery))
  })
}
```

Пример с `useDeferredValue`:

```jsx
const [query, setQuery] = useState('')
const deferredQuery = useDeferredValue(query)

return <SearchResults query={deferredQuery} />
```

## Как useDeferredValue связан с Suspense?

Если отложенное значение приводит к загрузке данных через Suspense-enabled источник, React может продолжать показывать старые результаты, пока новые готовятся.

```jsx
function SearchPage() {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />

      <Suspense fallback={<SearchSkeleton />}>
        <SearchResults query={deferredQuery} />
      </Suspense>
    </>
  )
}
```

Так пользователь не теряет уже показанный контент при каждом символе.

## Когда использовать?

Хорошие сценарии:

- большой список;
- тяжелая таблица;
- результаты поиска;
- график;
- Markdown preview;
- подсветка синтаксиса;
- дерево файлов;
- сложные вычисления, привязанные к render.

Плохие сценарии:

- controlled input value;
- валидация, которая должна быть мгновенной;
- критичные данные формы;
- сетевой debounce;
- исправление плохого алгоритма.

## Что отвечать на собеседовании?

`useDeferredValue` создает отложенную версию значения, чтобы тяжелый UI обновлялся с меньшим приоритетом. В отличие от debounce, он не ставит фиксированный таймер, а работает через планировщик React. В отличие от `startTransition`, он помечает не update, а уже существующее значение.

## Частые ошибки

- Использовать deferred value как `value` у input.
- Думать, что хук отменяет API-запросы.
- Забывать оптимизировать сам тяжелый компонент.
- Считать его заменой `useMemo`.
- Использовать там, где задержка данных опасна для UX.

## Мини-шпаргалка

- `const deferred = useDeferredValue(value)`.
- Актуальное значение - для срочного UI.
- Deferred value - для тяжелого UI.
- Не debounce, а приоритеты React.
- Хорошо сочетается с `Suspense`.
