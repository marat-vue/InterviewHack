# Какие production настройки важны для Nitro?

> [!NOTE]
> Production Nitro - это не только `nitro build`. Нужно настроить env, secrets, database migrations, cache/storage, auth cookies, CORS, rate limits, logs, monitoring, deployment preset и graceful shutdown.

## Runtime и preset

Сначала выбери runtime:

```txt
Node server
Serverless
Edge
Bun/Deno
Provider preset
```

От выбора зависит:

- можно ли держать long-lived connections;
- как работает cache memory;
- поддерживаются ли WebSocket;
- доступны ли Node APIs;
- как запускать cron/tasks;
- где хранить файлы.

## Secrets

Все secrets должны быть в env/platform secrets:

```bash
DATABASE_URL=""
BETTER_AUTH_SECRET=""
BETTER_AUTH_URL=""
REDIS_URL=""
OAUTH_CLIENT_ID=""
OAUTH_CLIENT_SECRET=""
```

Не коммить:

- `.env`;
- private keys;
- production database URLs;
- OAuth secrets;
- Better Auth secret.

## Database

Для Prisma:

```bash
npx prisma migrate deploy
```

Production не должен автоматически запускать `migrate dev`.

Проверь:

- connection pool;
- serverless pooling/proxy;
- migrations in CI/CD;
- seed только для нужной среды;
- backup/restore strategy.

## Cache/storage

Memory cache подходит только для одного процесса и простых случаев.

Для production с несколькими инстансами:

```ts
export default defineConfig({
  storage: {
    cache: {
      driver: 'redis',
      url: process.env.REDIS_URL,
    },
  },
});
```

Иначе разные инстансы будут иметь разные cache values.

## CORS

Не оставляй permissive CORS без причины:

```ts
handleCors(event, {
  origin: ['https://app.example.com'],
  methods: ['GET', 'POST', 'PATCH', 'DELETE'],
  credentials: true,
});
```

Если используешь cookies, CORS должен быть согласован с:

- `credentials`;
- cookie `SameSite`;
- `Secure`;
- доменами frontend/backend.

## Auth cookies

Для production:

```txt
HttpOnly = true
Secure = true
SameSite = Lax/Strict/None по необходимости
Path = /
Domain = только если нужно
Max-Age = осознанно
```

`SameSite=None` требует `Secure=true`.

## Rate limits и body limits

Добавь:

- body size limit;
- rate limit на auth endpoints;
- rate limit на public POST;
- upload size checks;
- webhook signature validation.

```ts
assertBodySize(event, 1024 * 1024);
```

## Logging и observability

Нужны:

- request id;
- structured logs;
- error reporting;
- latency;
- status code distribution;
- DB query latency;
- external API failures;
- WebSocket connection metrics.

## Graceful shutdown

Для Node preset проверь signals:

```bash
NITRO_SHUTDOWN_SIGNALS="SIGINT SIGTERM"
```

При shutdown важно:

- перестать принимать новые requests;
- завершить текущие;
- закрыть DB connections;
- flush logs/metrics.

## Мини-шпаргалка

- Выбери правильный preset.
- Secrets только в env/platform secrets.
- Prisma production: `migrate deploy`.
- Cache для multi-instance - внешний storage.
- CORS и cookies настраиваются вместе.
- Auth endpoints требуют rate limit.
- Нужны logs, metrics, error reporting.
- Проверяй поддержку WebSocket/tasks/storage на целевой платформе.
