# Что делает NonNullable

> [!summary] Коротко
> `NonNullable<T>` удаляет из типа `null` и `undefined`. Остальные варианты остаются без изменений.

## Вопрос

Что делает `NonNullable`?

## Базовый пример

```typescript
type MaybeName = string | null | undefined;

type Name = NonNullable<MaybeName>;
// string
```

## С union

```typescript
type ApiValue = string | number | null | undefined;

type SafeValue = NonNullable<ApiValue>;
// string | number
```

## Где полезен

`NonNullable` удобен после проверки, нормализации или в helper-типах.

```typescript
type User = {
  profile?: {
    email?: string | null;
  };
};

type Profile = NonNullable<User["profile"]>;
type Email = NonNullable<Profile["email"]>;
```

## Runtime-проверка отдельно

`NonNullable` не проверяет данные во время выполнения. Сначала значение нужно реально проверить.

```typescript
function assertExists<T>(value: T): NonNullable<T> {
  if (value === null || value === undefined) {
    throw new Error("Value is empty");
  }

  return value;
}
```

## Мини-шпаргалка

- `NonNullable<T>` убирает `null` и `undefined`.
- Работает с union.
- Не заменяет runtime-проверку.
- Часто используется с indexed access types.
