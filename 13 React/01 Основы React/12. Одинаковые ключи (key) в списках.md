# Что будет, если в списке одинаковые key?

> [!summary]
> Одинаковые `key` ломают способность React однозначно сопоставлять элементы списка. Из-за этого возможны неправильные обновления, потеря состояния, странное поведение input и предупреждения в консоли.

## Пример ошибки

```jsx
function ProductList({ products }) {
  return (
    <ul>
      {products.map((product) => (
        <li key={product.category}>{product.title}</li>
      ))}
    </ul>
  )
}
```

Если несколько товаров имеют одну категорию, ключи повторятся:

```text
key="laptops"
key="laptops"
key="laptops"
```

React не сможет надежно понять, какой элемент какой.

## Что значит "уникальный key"?

Key должен быть уникальным среди элементов одного массива:

```jsx
{products.map((product) => (
  <ProductCard key={product.id} product={product} />
))}
```

При этом ключи не обязаны быть уникальными во всем приложении. Два разных списка могут использовать одинаковые id, если они находятся в разных наборах соседних элементов.

## Чем опасны одинаковые key?

Возможные последствия:

- React обновит не тот элемент;
- состояние компонента сохранится не там;
- input покажет старое значение;
- анимация сработает некорректно;
- компонент не размонтируется там, где ожидалось;
- появится warning в консоли.

## Плохие источники key

Не стоит использовать:

```jsx
key={Math.random()}
```

```jsx
key={Date.now()}
```

```jsx
key={product.category}
```

если значение может повторяться или меняться.

## Что делать, если id нет?

Варианты:

- добавить id на backend;
- создать id при создании элемента и сохранить его в данных;
- использовать стабильный уникальный slug;
- аккуратно использовать index только для полностью статичных списков.

Пример:

```jsx
const newTodo = {
  id: crypto.randomUUID(),
  title: 'Выучить keys',
}
```

Важно: id создается один раз при создании данных, а не при каждом render.

## Мини-шпаргалка

- Одинаковые keys создают неоднозначность.
- Key уникален среди соседних элементов списка.
- Не используй `Math.random()` во время render.
- Лучше всего подходит стабильный id из данных.
- Warning про key нельзя игнорировать как "просто предупреждение".
