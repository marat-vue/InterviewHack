# Как работает SSG и prerender?

> [!summary]
> SSG генерирует HTML на build-time. В Nuxt это делают через `nuxt generate` или `prerender` route rules. Prerendered pages можно отдавать со static/CDN hosting, что дает быстрый response и простую инфраструктуру.

## Что такое SSG?

SSG, Static Site Generation:

```text
Build -> Nuxt проходит routes -> генерирует HTML и payload -> deploy static files
```

Подходит для:

- blog;
- docs;
- marketing pages;
- portfolio;
- каталогов, которые редко меняются.

## Команда

```bash
npm run generate
```

Обычно она вызывает:

```bash
nuxt generate
```

## Prerender через routeRules

```ts
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true },
    '/about': { prerender: true },
  },
});
```

## Динамические routes

Для динамических страниц нужно убедиться, что Nuxt знает, какие URL нужно сгенерировать.

Пример:

```ts
export default defineNuxtConfig({
  nitro: {
    prerender: {
      routes: ['/blog/nuxt-ssr', '/blog/nuxt-seo'],
    },
  },
});
```

## Когда SSG неудобен?

SSG становится сложнее, если:

- тысячи динамических страниц;
- данные часто меняются;
- нужен user-specific content;
- страницы зависят от cookies/session;
- нельзя заранее знать список routes.

## Мини-шпаргалка

- SSG генерирует HTML на build-time.
- `nuxt generate` делает static output.
- `prerender: true` можно задавать per route.
- Динамические routes нужно явно обнаружить или передать.
- SSG хорош для стабильного публичного контента.
