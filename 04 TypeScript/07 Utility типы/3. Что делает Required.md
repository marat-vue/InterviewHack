# Что делает Required

> [!summary] Коротко
> `Required<T>` делает все свойства типа `T` обязательными. Это обратная операция к `Partial<T>` на верхнем уровне объекта.

## Вопрос

Что делает `Required`?

## Базовый пример

```typescript
type UserDraft = {
  name?: string;
  email?: string;
};

type User = Required<UserDraft>;
```

`User` эквивалентен такому типу:

```typescript
type User = {
  name: string;
  email: string;
};
```

## Где полезен

`Required` удобен, когда на раннем этапе объект может быть неполным, но после валидации должен стать полным.

```typescript
type ConfigDraft = {
  apiUrl?: string;
  retries?: number;
};

function normalizeConfig(config: ConfigDraft): Required<ConfigDraft> {
  return {
    apiUrl: config.apiUrl ?? "/api",
    retries: config.retries ?? 3,
  };
}
```

## Важный нюанс

`Required` убирает `?`, но не делает вложенные поля обязательными глубоко.

```typescript
type Settings = {
  theme?: {
    name?: string;
  };
};

type StrictSettings = Required<Settings>;
// theme: { name?: string }
```

## `Required` не валидирует runtime

Тип помогает компилятору, но не проверяет реальные данные из API. Для внешних данных все равно нужна валидация.

## Мини-шпаргалка

- `Required<T>` убирает optional-модификаторы.
- Работает поверхностно.
- Часто используется после нормализации конфигов и форм.
- Противоположен `Partial<T>`.
