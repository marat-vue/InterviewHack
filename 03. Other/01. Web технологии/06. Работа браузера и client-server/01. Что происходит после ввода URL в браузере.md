# Что происходит после ввода URL в браузере?

> [!summary]
> После ввода URL браузер разбирает адрес, ищет IP через DNS, устанавливает соединение, выполняет TLS handshake для HTTPS, отправляет HTTP request, получает response, парсит HTML и загружает дополнительные ресурсы.

## Упрощенная цепочка

```txt
URL
 -> DNS lookup
 -> TCP connection
 -> TLS handshake
 -> HTTP request
 -> HTTP response
 -> HTML parsing
 -> CSS/JS/images loading
 -> render
```

В реальности browser может использовать cache, service worker, HTTP/2 connection reuse, preload scanner и другие оптимизации.

## 1. Browser разбирает URL

```txt
https://example.com:443/products?page=2#reviews
```

Browser выделяет:

- scheme: `https`;
- host: `example.com`;
- port: `443`;
- path: `/products`;
- query: `page=2`;
- fragment: `reviews`.

Fragment `#reviews` не отправляется на server. Он нужен browser/client-side code.

## 2. DNS lookup

Browser должен узнать IP адрес домена:

```txt
example.com -> 93.184.216.34
```

DNS может быть закеширован browser, OS, router или DNS provider.

## 3. TCP и TLS

Для HTTPS browser устанавливает TCP connection, затем TLS.

TLS проверяет certificate и создает защищенный канал.

## 4. HTTP request

```http
GET /products?page=2 HTTP/2
Host: example.com
Accept: text/html
```

Server возвращает HTML.

## 5. Browser строит страницу

Browser парсит HTML, находит CSS, JS, images, fonts и отправляет дополнительные requests.

## Мини-шпаргалка

- URL разбирается на scheme, host, port, path, query, fragment.
- DNS превращает domain в IP.
- HTTPS требует TLS handshake.
- Fragment не уходит на server.
- HTML обычно запускает цепочку дополнительных requests.
