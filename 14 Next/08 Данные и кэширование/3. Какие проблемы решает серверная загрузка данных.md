# Какие проблемы решает серверная загрузка данных?

> [!summary]
> Серверная загрузка данных решает проблемы пустого первого HTML, SEO, social preview, защиты secrets, лишнего client JavaScript и data waterfall после mount. Но она не отменяет необходимость кеширования, error handling и правильной архитектуры.

## Проблема пустого HTML

Client-only загрузка часто дает:

```html
<main>
  <p>Loading...</p>
</main>
```

Серверная загрузка позволяет отдать:

```html
<h1>Product title</h1>
<p>Product description</p>
```

## SEO и social sharing

Поисковики и социальные сети лучше работают, когда title, description, Open Graph и основной контент доступны на сервере.

```tsx
export async function generateMetadata({ params }: Props) {
  const product = await getProduct((await params).id)

  return {
    title: product.title,
    description: product.description,
  }
}
```

## Secrets и backend access

```tsx
const data = await fetch('https://api.example.com/private', {
  headers: {
    Authorization: `Bearer ${process.env.API_TOKEN}`,
  },
})
```

Такой токен должен оставаться на сервере.

## Меньше client JavaScript

Если данные и HTML готовятся в Server Component, не нужно отправлять в браузер код загрузки, парсинга и части библиотек.

## Что отвечать на собеседовании?

Серверная загрузка решает проблемы SEO, первого контента, защиты секретов и лишнего client-side waterfall. Пользователь и crawler получают HTML с данными раньше. Но серверная загрузка требует думать о cache, TTFB, ошибках и персонализации.

## Частые ошибки

- Считать серверную загрузку всегда быстрее.
- Не кешировать дорогие запросы.
- Загружать пользовательские данные как публичные.
- Игнорировать `notFound()` для отсутствующих ресурсов.
- Не разделять read и mutation flows.

## Мини-шпаргалка

- Решает пустой HTML.
- Улучшает SEO.
- Держит secrets на сервере.
- Уменьшает client JS.
- Требует cache strategy.
- Не заменяет error handling.
