# Что такое idempotency в REST?

> [!summary]
> Idempotency означает, что повтор одного и того же запроса приводит к тому же итоговому состоянию. Это особенно важно для retries, нестабильной сети, платежей, заказов и API behind proxies.

## Простой пример

```http
PUT /api/users/1

{
  "name": "Anna"
}
```

Если отправить request один раз или пять раз, имя пользователя останется `Anna`.

## Неидемпотентный пример

```http
POST /api/orders

{
  "productId": 10,
  "quantity": 1
}
```

Если browser, mobile app или proxy повторит request, можно создать два заказа.

## Idempotency-Key

Для опасных `POST` операций используют idempotency key:

```http
POST /api/payments
Idempotency-Key: payment_01HZX
```

Server сохраняет результат первого request с таким ключом. Если такой же request повторится, server вернет тот же результат, а не создаст новую операцию.

## Где важно?

- payments;
- order creation;
- file processing;
- booking;
- sending email/SMS;
- imports;
- webhook handlers.

## Frontend-угол

На frontend idempotency помогает пережить:

- двойной клик по submit;
- retry после timeout;
- unstable mobile network;
- повторную отправку формы после refresh.

Но кнопку все равно нужно disabled-ить на время submit. Idempotency key - защита backend-уровня, а не замена нормального UX.

## Мини-шпаргалка

- `GET`, `PUT`, `DELETE` обычно idempotent.
- `POST` обычно не idempotent.
- Повтор request может случиться из-за retry или пользователя.
- Для критичных операций нужен `Idempotency-Key`.
- Idempotency хранится и проверяется на backend.
