# Hydration в React 18

> [!summary]
> Hydration - это процесс, при котором React берет HTML, уже сгенерированный на сервере, и подключает к нему клиентскую интерактивность. В React 18 для этого используется `hydrateRoot`, а вместе с `Suspense` становятся доступны streaming SSR и selective hydration.

## Что такое hydration?

При SSR сервер отправляет готовый HTML:

```html
<div id="root">
  <button>Like</button>
</div>
```

Пользователь быстро видит разметку, но кнопка еще не умеет реагировать на React-события. Затем на клиент загружается JavaScript, и React "оживляет" эту разметку: привязывает event handlers, восстанавливает состояние компонентов и делает приложение интерактивным.

Это и есть hydration.

## hydrateRoot

В React 18 используется API из `react-dom/client`:

```jsx
import { hydrateRoot } from 'react-dom/client'
import { App } from './App'

hydrateRoot(
  document.getElementById('root'),
  <App />,
)
```

Для обычного client-only приложения используется `createRoot`, а для SSR - `hydrateRoot`.

```jsx
import { createRoot, hydrateRoot } from 'react-dom/client'

createRoot(document.getElementById('root')).render(<App />)

hydrateRoot(document.getElementById('root'), <App />)
```

## Почему нельзя использовать createRoot для SSR-разметки?

`createRoot` создает клиентский root и рендерит приложение заново. Если в контейнере уже лежит серверный HTML, React не будет воспринимать его как результат SSR-hydration.

`hydrateRoot` говорит React: "в контейнере уже есть HTML, нужно подключиться к нему".

## Hydration mismatch

Hydration mismatch возникает, когда HTML сервера не совпадает с первым render на клиенте.

Проблемный пример:

```jsx
function TimeLabel() {
  return <p>{new Date().toLocaleTimeString()}</p>
}
```

Сервер сгенерировал время `12:00:00`, а клиент при hydration получил `12:00:02`. Разметка отличается.

Безопаснее:

```jsx
function TimeLabel() {
  const [time, setTime] = useState(null)

  useEffect(() => {
    setTime(new Date().toLocaleTimeString())
  }, [])

  if (time === null) {
    return <p>Загружаем время...</p>
  }

  return <p>{time}</p>
}
```

Первый render одинаковый, клиентское время появляется после hydration.

## Частые причины mismatch

- `Date.now()` или `new Date()` прямо в render;
- `Math.random()` в render;
- чтение `window`, `document`, `localStorage` на первом render;
- разные locale/timezone на сервере и клиенте;
- условный render по browser-only данным;
- разные версии данных на сервере и клиенте;
- невалидная HTML-вложенность.

## onRecoverableError

`hydrateRoot` может принимать options:

```jsx
hydrateRoot(
  document.getElementById('root'),
  <App />,
  {
    onRecoverableError(error, errorInfo) {
      console.error('Hydration recoverable error:', error, errorInfo)
    },
  },
)
```

Это полезно для логирования ошибок hydration и диагностики в продакшене.

## Selective hydration

В React 18 hydration тесно связана с `Suspense`.

```jsx
function Page() {
  return (
    <>
      <Header />

      <Suspense fallback={<CommentsSkeleton />}>
        <Comments />
      </Suspense>
    </>
  )
}
```

React может гидратировать разные Suspense-границы независимо. Если пользователь взаимодействует с важной частью страницы, React может приоритизировать hydration этой части.

## Hydration и streaming SSR

Streaming SSR отправляет HTML частями:

```jsx
renderToPipeableStream(<App />, {
  onShellReady() {
    stream.pipe(response)
  },
})
```

Hydration на клиенте затем подключает интерактивность к уже пришедшей разметке. В связке с Suspense это позволяет:

- быстрее показать shell страницы;
- не ждать самые медленные блоки;
- гидратировать важные части раньше;
- улучшить perceived performance.

## Hydration и useLayoutEffect

`useLayoutEffect` не выполняется на сервере. Если компонент зависит от layout-измерений, нужно следить, чтобы первый серверный HTML и первый клиентский render не расходились.

Иногда такой компонент делают client-only:

```jsx
function ClientOnly({ children }) {
  const [mounted, setMounted] = useState(false)

  useEffect(() => {
    setMounted(true)
  }, [])

  if (!mounted) {
    return null
  }

  return children
}
```

## Что отвечать на собеседовании?

Hydration - это подключение React к HTML, который уже пришел с сервера. В React 18 для этого используют `hydrateRoot`. Новая модель лучше работает с `Suspense`, streaming SSR и selective hydration, но требует, чтобы первый render на сервере и клиенте совпадал.

## Частые ошибки

- Использовать `createRoot` вместо `hydrateRoot` для SSR.
- Игнорировать hydration mismatch warnings.
- Генерировать случайные значения в render.
- Читать browser API на сервере.
- Делать серверный HTML и первый клиентский render разными.

## Мини-шпаргалка

- SSR дает HTML, hydration подключает интерактивность.
- React 18 SSR entrypoint: `hydrateRoot`.
- `createRoot` - для client-only приложения.
- Mismatch означает различие сервера и первого клиента.
- `Suspense` помогает selective hydration.
- Streaming SSR и hydration работают вместе.
