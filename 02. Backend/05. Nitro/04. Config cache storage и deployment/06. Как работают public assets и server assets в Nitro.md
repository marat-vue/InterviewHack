# Как работают public assets и server assets в Nitro?

> [!NOTE]
> Nitro различает public assets, которые напрямую доступны клиенту, и server assets, которые доступны только server code. Public assets подходят для изображений, robots.txt и static files; server assets - для шаблонов, приватных файлов и программного чтения.

## Public assets

Файлы в `public/` автоматически отдаются браузеру:

```txt
public/
  image.png       -> /image.png
  robots.txt      -> /robots.txt
  files/demo.pdf  -> /files/demo.pdf
```

В production Nitro копирует public assets в `.output/public` и создает manifest с metadata.

## Headers public assets

Nitro автоматически работает с:

- `ETag`;
- `Last-Modified`;
- conditional requests;
- `304 Not Modified`.

Это значит, что static assets могут эффективно кешироваться браузером/CDN.

## Custom public asset directories

```ts
export default defineConfig({
  publicAssets: [
    {
      dir: './static',
      baseURL: '/static',
      maxAge: 60 * 60 * 24 * 7,
    },
  ],
});
```

Используй, если:

- assets лежат не в `public`;
- нужен отдельный base URL;
- нужно задать cache max age;
- проект мигрирует со старой структуры.

## Server assets

Server assets не доступны напрямую из браузера. Они bundle-ятся для server-side доступа.

Примеры:

- email templates;
- SQL templates;
- private certificates;
- markdown templates;
- protected downloads metadata.

Пример структуры:

```txt
server/assets/
  emails/
    welcome.html
```

## Когда использовать public, а когда server assets?

| Нужно | Куда класть |
|---|---|
| Логотип, картинка, favicon | `public/` |
| `robots.txt` | `public/` |
| публичный PDF | `public/` |
| email template | server assets |
| приватный файл | server assets/storage |
| файл, доступный только после auth | server route + storage/server assets |

## Protected downloads

Для приватного файла не кладем его в `public/`. Лучше:

```txt
server/routes/api/files/[id].get.ts
```

Handler:

```ts
export default defineHandler(async (event) => {
  await requireAuth(event);

  const file = await fileService.getReadableFile(getRouterParam(event, 'id'));

  return new Response(file.stream, {
    headers: {
      'content-type': file.contentType,
    },
  });
});
```

## Мини-шпаргалка

- `public/` доступен браузеру напрямую.
- Public assets получают cache metadata.
- `publicAssets` настраивает дополнительные директории.
- Server assets доступны только server code.
- Приватные файлы нельзя класть в `public/`.
- Для protected downloads делай server route с auth check.
