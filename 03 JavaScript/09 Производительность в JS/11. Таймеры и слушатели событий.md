# Таймеры и слушатели событий

> [!summary] Коротко
> Таймеры и слушатели событий нужно очищать, иначе они могут продолжать работать после удаления компонента и удерживать память.

## Вопрос

Почему важно очищать таймеры и обработчики событий?

## Основная проблема

`setInterval`, `setTimeout`, `addEventListener` и подписки создают связи между объектами. Если компонент или DOM-элемент уже не нужен, но обработчик продолжает на него ссылаться, память может не освободиться.

## Пример с event listener

```javascript
function mount() {
  window.addEventListener('resize', handleResize);
}

function unmount() {
  window.removeEventListener('resize', handleResize);
}
```

Для удаления обработчика нужна та же ссылка на функцию.

## Пример с interval

```javascript
const intervalId = setInterval(() => {
  updateData();
}, 1000);

clearInterval(intervalId);
```

Если интервал не очистить, он будет продолжать вызывать callback.

## Таймер с AbortController

```javascript
const controller = new AbortController();

element.addEventListener('click', handleClick, {
  signal: controller.signal,
});

controller.abort();
```

`AbortController` может централизованно снять обработчик, если API поддерживает `signal`.

## Что очищать

- `setInterval`;
- долгие `setTimeout`;
- listeners на `window` и `document`;
- observers;
- WebSocket-подписки;
- store-подписки.

## Мини-шпаргалка

```javascript
removeEventListener(type, handler);
clearTimeout(timeoutId);
clearInterval(intervalId);
observer.disconnect();
```
