# Что находится в nuxt.config.ts?

> [!summary]
> `nuxt.config.ts` - главный конфигурационный файл Nuxt. В нем подключают modules, CSS, runtime config, route rules, app head, devtools, image/fonts/icon настройки, experimental features и другие параметры приложения.

## Пример конфига

```ts
export default defineNuxtConfig({
  devtools: { enabled: true },

  modules: [
    '@nuxt/image',
    '@nuxt/icon',
    '@nuxt/fonts',
    '@nuxtjs/seo',
  ],

  css: ['~/assets/css/main.css'],

  app: {
    head: {
      htmlAttrs: { lang: 'ru' },
      titleTemplate: '%s · Frontend Notes',
    },
  },

  runtimeConfig: {
    apiSecret: '',
    public: {
      apiBase: '/api',
    },
  },

  routeRules: {
    '/': { prerender: true },
    '/blog/**': { swr: 3600 },
    '/admin/**': { ssr: false },
  },
});
```

## Частые разделы

| Поле | Зачем нужно |
|---|---|
| `modules` | подключение Nuxt-модулей |
| `css` | глобальные стили |
| `app.head` | базовые meta/head |
| `runtimeConfig` | server/public config |
| `routeRules` | rendering/cache per route |
| `devtools` | Nuxt DevTools |
| `nitro` | server runtime config |

## Почему не все класть в config?

`nuxt.config.ts` должен описывать приложение, а не превращаться в склад бизнес-логики.

Хорошая практика:

- modules и global config - в `nuxt.config.ts`;
- UI tokens - в `app.config.ts`;
- runtime secrets - через environment variables;
- бизнес-логику - в services/composables/server utils.

## Мини-шпаргалка

- `nuxt.config.ts` - главный config Nuxt.
- `defineNuxtConfig` дает типизацию.
- `modules` подключают Nuxt-модули.
- `routeRules` управляют rendering/cache.
- Secrets нельзя класть прямо в config как значения.
