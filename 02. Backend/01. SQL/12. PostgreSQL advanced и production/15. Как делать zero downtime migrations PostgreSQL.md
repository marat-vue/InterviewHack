# Как делать zero-downtime migrations PostgreSQL?

> [!NOTE]
> Zero-downtime migration - это изменение схемы без остановки приложения. Главный принцип: миграция должна быть совместима со старой и новой версией кода, а опасные операции нужно разбивать на шаги.

## Expand and contract

Pattern:

1. Expand schema.
2. Deploy code that writes both/new format.
3. Backfill data.
4. Switch reads.
5. Stop old writes.
6. Drop old schema later.

## Добавление nullable column

```sql
ALTER TABLE users ADD COLUMN last_seen_at timestamptz;
```

Обычно безопасно.

## Добавление NOT NULL

Опасно сразу:

```sql
ALTER TABLE users ADD COLUMN status text NOT NULL DEFAULT 'active';
```

Безопаснее:

```sql
ALTER TABLE users ADD COLUMN status text;

UPDATE users
SET status = 'active'
WHERE status IS NULL;

ALTER TABLE users ALTER COLUMN status SET DEFAULT 'active';
ALTER TABLE users ALTER COLUMN status SET NOT NULL;
```

Backfill лучше делать batch-ами.

## Создание индекса

На большой таблице:

```sql
CREATE INDEX CONCURRENTLY users_email_idx ON users (email);
```

`CONCURRENTLY` снижает блокировки, но нельзя выполнять внутри обычной transaction block.

## Добавление constraint безопаснее

```sql
ALTER TABLE orders
ADD CONSTRAINT orders_total_positive
CHECK (total >= 0) NOT VALID;

ALTER TABLE orders
VALIDATE CONSTRAINT orders_total_positive;
```

`NOT VALID` позволяет добавить constraint без полной проверки старых строк сразу.

## Что нельзя делать без плана?

- drop column, которую читает старый код;
- rename column/table без compatibility layer;
- change type на большой таблице;
- add not null with expensive default;
- create index без `CONCURRENTLY`;
- long transaction migrations.

## Мини-шпаргалка

- Expand/contract - базовый pattern.
- Backfill batch-ами.
- Индексы на больших таблицах: `CREATE INDEX CONCURRENTLY`.
- Constraints: `NOT VALID` + `VALIDATE`.
- Drop старого - отдельным релизом после переключения кода.
