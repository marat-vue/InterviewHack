# Какие Vue библиотеки кроме Pinia, Router, Vuetify и VueUse стоит знать?

> [!NOTE]
> В основном Vue-разделе уже есть Pinia, Vue Router, Vuetify, VueUse, Tailwind, Vite и Motion. Но на реальных проектах часто встречаются еще формы, i18n, server state, headless UI, virtual lists, charts и auto-import tooling.

## Вопрос

Какие Vue-библиотеки кроме Pinia, Vue Router, Vuetify и VueUse стоит знать и когда их использовать?

## Почему это отдельная тема

Vue core не пытается закрыть все задачи приложения. Экосистема обычно добавляет:

- validation;
- i18n;
- server-state cache;
- UI primitives;
- tables;
- virtualization;
- charts;
- icons;
- auto imports;
- typed/generated routes.

На собеседовании важно не перечислить 30 названий, а объяснить, зачем категория нужна и когда она оправдана.

## Forms validation: `vee-validate`

`vee-validate` используют для сложных форм:

- nested fields;
- validation schema;
- field arrays;
- touched/dirty/errors meta;
- async validation;
- интеграция с `zod`, `yup` или другими schema validators.

Пример:

```vue
<script setup lang="ts">
import { useForm, useField } from "vee-validate";
import { z } from "zod";
import { toTypedSchema } from "@vee-validate/zod";

const schema = toTypedSchema(
  z.object({
    email: z.string().email(),
    password: z.string().min(8),
  }),
);

const { handleSubmit, errors } = useForm({
  validationSchema: schema,
});

const { value: email } = useField<string>("email");
const { value: password } = useField<string>("password");

const submit = handleSubmit(async (values) => {
  await api.auth.login(values);
});
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model="email" type="email" />
    <p>{{ errors.email }}</p>

    <input v-model="password" type="password" />
    <p>{{ errors.password }}</p>

    <button type="submit">Войти</button>
  </form>
</template>
```

Когда не нужно:

- форма из 1-2 полей;
- validation полностью простая;
- UI-библиотека уже закрывает сценарий.

Важно: frontend validation улучшает UX, но backend validation все равно обязательна.

## I18n: `vue-i18n`

`vue-i18n` нужен для мультиязычных приложений.

```typescript
import { createI18n } from "vue-i18n";

export const i18n = createI18n({
  legacy: false,
  locale: "ru",
  fallbackLocale: "en",
  messages: {
    ru: {
      nav: {
        home: "Главная",
      },
    },
    en: {
      nav: {
        home: "Home",
      },
    },
  },
});
```

Подключение:

```typescript
createApp(App).use(i18n).mount("#app");
```

Использование:

```vue
<script setup lang="ts">
import { useI18n } from "vue-i18n";

const { t, locale } = useI18n();
</script>

<template>
  <button @click="locale = 'en'">
    {{ t("nav.home") }}
  </button>
</template>
```

Что учитывать:

- pluralization;
- форматирование дат/чисел;
- lazy loading locale messages;
- fallback locale;
- SEO для разных языков;
- хранение выбранного locale.

## Server state: TanStack Query for Vue

TanStack Query нужен, когда данных с сервера много и ими нужно управлять как cache.

Он закрывает:

- cache by query key;
- loading/error states;
- retries;
- refetch;
- invalidation;
- pagination;
- optimistic updates;
- background refresh.

Подключение:

```bash
npm i @tanstack/vue-query
```

```typescript
import { VueQueryPlugin } from "@tanstack/vue-query";

createApp(App).use(VueQueryPlugin).mount("#app");
```

Пример:

```vue
<script setup lang="ts">
import { useQuery, useMutation, useQueryClient } from "@tanstack/vue-query";

const queryClient = useQueryClient();

const usersQuery = useQuery({
  queryKey: ["users"],
  queryFn: () => api.users.list(),
});

const removeUser = useMutation({
  mutationFn: (id: number) => api.users.remove(id),
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ["users"] });
  },
});
</script>
```

Когда нужен:

- несколько экранов используют одни server data;
- нужны retries/cache/invalidation;
- есть pagination/infinite loading;
- нужно разделить server state и client state.

Когда не нужен:

- один простой запрос;
- проект на Nuxt, где уже используется `useFetch`/`useAsyncData` и Nitro API;
- данные не кешируются и не переиспользуются.

## Headless UI: Reka UI или Headless UI Vue

Headless-библиотеки дают поведение и accessibility без готового visual style.

Подходящий сценарий:

- нужен custom design;
- dropdown/dialog/select/tabs должны быть accessible;
- Tailwind или своя дизайн-система;
- не хочется тянуть полноценный UI-kit.

Примерная идея:

```vue
<DialogRoot v-model:open="isOpen">
  <DialogTrigger>Открыть</DialogTrigger>
  <DialogPortal>
    <DialogOverlay />
    <DialogContent>
      <DialogTitle>Настройки</DialogTitle>
    </DialogContent>
  </DialogPortal>
</DialogRoot>
```

Плюс: сложные keyboard/focus patterns решены библиотекой.

Минус: внешний вид нужно проектировать самостоятельно.

## Virtual lists: `vue-virtual-scroller`

Virtualization нужна, когда список содержит сотни или тысячи элементов.

Без virtualization:

```vue
<UserRow v-for="user in users" :key="user.id" :user="user" />
```

DOM может стать слишком большим.

С virtualization рендерятся только видимые элементы.

Когда применять:

- логи;
- таблицы;
- большие select/autocomplete;
- infinite lists;
- search results.

Когда не применять:

- 20-100 элементов;
- список маленький и простой;
- SEO-контент, который должен быть в HTML.

## Charts: ECharts или Chart.js wrappers

Charts нужны для dashboards и аналитики.

Критерии выбора:

- типы графиков;
- responsive;
- accessibility;
- SSR compatibility;
- размер bundle;
- возможность lazy-load;
- экспорт изображений;
- поддержка tooltips/zoom.

Практический совет: charts часто тяжелые, поэтому их лучше lazy-load на routes, где они реально нужны.

## Icons: `lucide-vue-next` или MDI

Иконки нужны почти в каждом приложении, но важно не импортировать огромный набор целиком.

```typescript
import { Save, Trash2 } from "lucide-vue-next";
```

```vue
<Save aria-hidden="true" />
<button aria-label="Удалить">
  <Trash2 aria-hidden="true" />
</button>
```

Icon-only buttons должны иметь accessible name через `aria-label`, видимый текст или tooltip + label.

## Auto imports

`unplugin-auto-import` может автоматически импортировать `ref`, `computed`, `watch`, router composables и свои composables.

Плюсы:

- меньше boilerplate;
- удобно в больших Vue/Nuxt-like проектах;
- generated `.d.ts` дает типы.

Минусы:

- магия в build pipeline;
- новичкам сложнее понимать источник функций;
- нужно следить за generated types;
- в тестах и tooling должны работать те же настройки.

## Components auto registration

`unplugin-vue-components` автоматически регистрирует компоненты.

Плюсы:

- меньше ручных imports;
- удобно для design system;
- integration resolvers для UI libraries.

Минусы:

- сложнее искать dependencies;
- возможны конфликты имен;
- нужен контроль структуры компонентов.

## Typed/file-based routes: `unplugin-vue-router`

File-based routing и generated typed routes полезны, если хочется Nuxt-like DX в обычном Vue/Vite SPA.

Плюсы:

- routes генерируются по файлам;
- меньше ручной route-конфигурации;
- typed route names/params;
- удобнее code splitting.

Минусы:

- дополнительный build plugin;
- команда должна понимать conventions;
- нужна настройка types.

## Как не переборщить

Для каждой библиотеки спросите:

- есть ли уже решение в Vue core или текущем UI-kit;
- сколько кода она реально экономит;
- есть ли SSR/browser ограничения;
- нужен ли wrapper;
- кто будет обновлять зависимость;
- как тестировать интеграцию;
- можно ли удалить библиотеку без переписывания половины проекта.

## Частые ошибки

- Ставить `vee-validate` для одной формы с email.
- Ставить TanStack Query и параллельно писать собственный cache слой.
- Использовать headless UI без проверки keyboard/focus.
- Подключить chart library глобально, хотя графики есть на одной странице.
- Использовать auto-imports без generated types в репозитории.
- Выбирать библиотеку без проверки SSR.

## Что отвечать на собеседовании

Кроме Pinia, Router, Vuetify и VueUse во Vue-экосистеме часто используют `vee-validate` для сложных форм, `vue-i18n` для мультиязычности, TanStack Query for Vue для server state, headless UI-библиотеки для accessible primitives, virtual scroller для больших списков, chart libraries для dashboards, icon libraries и Vite plugins для auto imports/routes. Но библиотеку ставят только после проверки задачи, SSR, TypeScript, bundle size, accessibility и поддержки.

## Мини-шпаргалка

- `vee-validate` - сложные формы.
- `vue-i18n` - мультиязычность.
- TanStack Query - server state cache.
- Headless UI - доступные primitives без стилей.
- Virtual scroller - большие списки.
- Charts - dashboards, лучше lazy-load.
- Icons - точечные imports.
- Auto imports/routes - DX, но добавляют build magic.
