# Что такое модульная архитектура NestJS?

> [!summary]
> Модульная архитектура NestJS делит приложение на функциональные части. Каждый module группирует controllers, providers и imports/exports, связанные с конкретной областью приложения.

## Пример доменного модуля

```ts
@Module({
  controllers: [UsersController],
  providers: [UsersService],
  exports: [UsersService],
})
export class UsersModule {}
```

`UsersModule` собирает все, что относится к пользователям.

## Зачем нужны модули?

- разделять приложение по доменам;
- контролировать видимость providers;
- упрощать тестирование;
- избегать огромного `AppModule`;
- переиспользовать фичи.

## Хорошее разбиение

```txt
AppModule
  AuthModule
  UsersModule
  OrdersModule
  ConfigModule
  DatabaseModule
```

## Частая ошибка

Складывать все сервисы и контроллеры в `AppModule`. Так проект быстро становится трудным для поддержки.

## Мини-шпаргалка

- Module группирует связанную функциональность.
- Feature module отвечает за доменную область.
- Providers видны внутри модуля.
- Для использования снаружи provider нужно экспортировать.
- Хороший Nest-проект начинается с границ модулей.
