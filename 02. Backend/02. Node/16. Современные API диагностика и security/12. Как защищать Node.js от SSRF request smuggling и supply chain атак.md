# Как защищать Node.js от SSRF, request smuggling и supply chain атак?

> [!NOTE]
> Базовая безопасность Node.js - это не только secrets и SQL injection. Для backend-сервисов важны SSRF, request smuggling, dependency confusion, malicious packages, body limits и безопасная обработка proxy headers.

## SSRF

SSRF возникает, когда пользователь заставляет сервер сделать запрос во внутреннюю сеть.

Плохо:

```js
const response = await fetch(req.query.url);
```

Защита:

- allowlist hostnames;
- запрет private IP ranges;
- запрет redirects в опасные места;
- timeout;
- response size limit;
- DNS rebinding protection;
- отдельный egress proxy.

## Request smuggling

Request smuggling связан с неоднозначным разбором HTTP между proxy и backend.

Практики:

- использовать актуальный Node.js;
- держать reverse proxy обновленным;
- не принимать нестандартные комбинации headers;
- ограничивать body size;
- настраивать timeouts;
- тестировать HTTP/1.1 edge cases.

## Body limits

```js
app.use(express.json({
  limit: '1mb',
}));
```

Без лимита body endpoint может стать memory DoS.

## Supply chain

Риски:

- dependency confusion;
- typosquatting;
- compromised maintainer;
- malicious postinstall;
- устаревшие transitive dependencies.

Практики:

- lockfile в Git;
- `npm ci` в CI;
- private registry scopes;
- audit + SCA tooling;
- pin Node.js LTS;
- минимизировать dependencies;
- review install scripts;
- использовать `overrides` для срочных фиксов.

## Proxy headers

Не доверяй `x-forwarded-for` без настройки trusted proxy.

Плохо:

```js
const ip = req.headers['x-forwarded-for'];
```

Лучше настраивать framework/reverse proxy так, чтобы trusted headers принимались только от известных proxy.

## Мини-шпаргалка

- SSRF защищают allowlist и запрет private IP.
- Body size limits обязательны.
- Request smuggling лечится обновлениями, proxy config и timeouts.
- Supply chain требует lockfile, audit, registry hygiene.
- Proxy headers нельзя слепо считать правдой.
