# Как подключить Redis к Nuxt Nitro в Docker Compose?

> [!NOTE]
> Redis в Nuxt/Nitro используют для cache, sessions, rate limiting, queues, pub/sub и Nitro storage. В Compose приложение подключается к Redis по host `redis`, а persistence включают только если данные Redis должны переживать restart.

## Минимальный Redis service

```yaml
services:
  redis:
    image: redis:8-alpine
    ports:
      - "6379:6379"
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
```

Connection string внутри Compose:

```env
REDIS_URL=redis://redis:6379
NUXT_REDIS_URL=redis://redis:6379
```

С host-машины:

```env
REDIS_URL=redis://localhost:6379
```

## Redis с AOF persistence

```yaml
services:
  redis:
    image: redis:8-alpine
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  redisdata:
```

AOF полезен, если Redis хранит sessions, queues или важные counters. Для чистого disposable cache persistence может быть лишней.

## Redis с password для dev/stage

```yaml
services:
  redis:
    image: redis:8-alpine
    command: ["redis-server", "--appendonly", "yes", "--requirepass", "${REDIS_PASSWORD}"]
    environment:
      REDIS_PASSWORD: ${REDIS_PASSWORD}
    healthcheck:
      test: ["CMD-SHELL", "redis-cli -a \"$$REDIS_PASSWORD\" ping | grep PONG"]
      interval: 5s
      timeout: 3s
      retries: 10
```

URL:

```env
REDIS_URL=redis://:secret@redis:6379
```

Для production лучше использовать секреты и ACL, а не хранить пароль в compose-файле.

## Подключение в Nitro через node-redis

```ts
import { createClient } from 'redis'

let client: ReturnType<typeof createClient> | undefined

export async function useRedis() {
  if (!client) {
    const config = useRuntimeConfig()

    client = createClient({
      url: config.redisUrl || process.env.REDIS_URL
    })

    client.on('error', (error) => {
      console.error('Redis error', error)
    })

    await client.connect()
  }

  return client
}
```

Route:

```ts
export default defineEventHandler(async () => {
  const redis = await useRedis()
  const value = await redis.get('health:redis')

  return { redis: value ?? 'ok' }
})
```

## Nitro storage через Redis

Пример идеи:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    redisUrl: ''
  },
  nitro: {
    storage: {
      cache: {
        driver: 'redis',
        url: process.env.REDIS_URL
      }
    }
  }
})
```

Использование в server code:

```ts
export default defineEventHandler(async () => {
  const storage = useStorage('cache')

  await storage.setItem('hello', { value: 'world' })

  return await storage.getItem('hello')
})
```

Проверяй конкретный driver и пакет под версию Nitro/unstorage, потому что storage drivers обновляются отдельно.

## Redis для rate limiting

```ts
export default defineEventHandler(async (event) => {
  const redis = await useRedis()
  const ip = getRequestIP(event, { xForwardedFor: true }) ?? 'unknown'
  const key = `rate:${ip}`

  const count = await redis.incr(key)

  if (count === 1) {
    await redis.expire(key, 60)
  }

  if (count > 100) {
    throw createError({
      statusCode: 429,
      statusMessage: 'Too Many Requests'
    })
  }

  return { ok: true }
})
```

## Что отвечать на собеседовании?

Redis в Nuxt/Nitro Docker-проекте поднимается отдельным Compose service. Приложение подключается к `redis:6379`, а не к `localhost`. Redis можно использовать для cache, sessions, rate limiting и queues. Persistence через AOF/volume включают, если данные важны, а для обычного cache можно оставить Redis disposable.

## Частые ошибки

- Считать Redis заменой PostgreSQL.
- Использовать `localhost` внутри container.
- Включать persistence для cache без необходимости.
- Не обрабатывать reconnect/error events клиента.
- Открывать `6379` наружу в production.
- Хранить password в git.

## Мини-шпаргалка

- Internal URL: `redis://redis:6379`.
- With password: `redis://:password@redis:6379`.
- Healthcheck: `redis-cli ping`.
- Persistence: `--appendonly yes` + volume.
- Cache can be disposable.
- Sessions/queues требуют более аккуратной durability.
