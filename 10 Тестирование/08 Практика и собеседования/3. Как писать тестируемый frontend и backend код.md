# Как писать тестируемый frontend и backend код?

> [!summary]
> Тестируемый код имеет явные зависимости, понятные входы и выходы, небольшие функции, чистую бизнес-логику и меньше скрытого глобального состояния. Такой код проще проверять и безопаснее менять.

## Общий принцип

Код трудно тестировать, если он:

- сразу ходит в сеть;
- сам читает глобальные переменные;
- смешивает UI, бизнес-логику и I/O;
- зависит от текущей даты без возможности подмены;
- создает зависимости внутри функции;
- делает слишком много вещей сразу.

## Frontend

Плохо:

```ts
async function submit() {
  const response = await fetch('/api/orders');
  state.order = await response.json();
}
```

Лучше вынести API:

```ts
export function useOrderSubmit(apiClient: ApiClient) {
  async function submit() {
    return apiClient.createOrder();
  }

  return { submit };
}
```

Теперь в тесте можно передать fake `apiClient`.

## Backend

Плохо:

```ts
class UserService {
  async createUser(email: string) {
    const prisma = new PrismaClient();
    return prisma.user.create({ data: { email } });
  }
}
```

Лучше dependency injection:

```ts
class UserService {
  constructor(private readonly users: UserRepository) {}

  async createUser(email: string) {
    return this.users.create({ email });
  }
}
```

## Что улучшает тестируемость?

- pure functions для расчетов;
- dependency injection;
- отдельный слой API/client;
- отдельный слой repository;
- явные errors;
- маленькие компоненты;
- стабильные selectors;
- контроль времени через injectable clock или fake timers.

## Мини-шпаргалка

- Явные зависимости проще мокать.
- Pure functions проще тестировать.
- Не смешивай бизнес-логику и I/O.
- Не создавай тяжелые зависимости внутри функции.
- Тестируемость часто является признаком хорошей архитектуры.
