# Какие задачи лучше решать серверными компонентами?

> [!summary]
> Серверными компонентами лучше решать задачи, где не нужна интерактивность в браузере: загрузка данных, чтение БД, работа с секретами, построение SEO-контента, рендеринг больших статичных блоков и уменьшение клиентского JavaScript.

## Data fetching

```tsx
export default async function OrdersPage() {
  const orders = await db.order.findMany()

  return <OrdersTable orders={orders} />
}
```

Если данные нужны для первого HTML и не требуют client interaction, Server Component - хорошее место.

## SEO-контент

```tsx
export default async function ArticlePage({ params }: Props) {
  const { slug } = await params
  const article = await getArticle(slug)

  return (
    <article>
      <h1>{article.title}</h1>
      <div>{article.content}</div>
    </article>
  )
}
```

Контент доступен в HTML, что лучше для поисковиков и preview.

## Работа с секретами

```tsx
export default async function BillingPage() {
  const invoices = await stripe.invoices.list({
    customer: process.env.STRIPE_CUSTOMER_ID,
  })

  return <Invoices invoices={invoices.data} />
}
```

Секреты должны оставаться на сервере.

## Большие зависимости

Если библиотека нужна только для server render, ее не нужно отправлять клиенту:

```tsx
import { markdownToHtml } from '@/shared/lib/markdown'

export default async function DocsPage() {
  const html = await markdownToHtml(await getMarkdown())

  return <div dangerouslySetInnerHTML={{ __html: html }} />
}
```

## Когда не подходит?

Server Component не подходит для:

- `onClick`;
- `useState`;
- `useEffect`;
- drag and drop;
- modals;
- client-side forms;
- browser APIs;
- animation state.

## Что отвечать на собеседовании?

Server Components лучше использовать для статичного или серверного контента: data fetching, DB/API access, secrets, SEO, markdown, каталогов, таблиц и больших неинтерактивных блоков. Интерактивные части выносят в маленькие Client Components.

## Частые ошибки

- Делать Server Component там, где нужен `onClick`.
- Переносить весь UI в Client Component из-за одной интерактивной кнопки.
- Передавать в Client Component несериализуемые данные.
- Использовать Server Component как замену backend authorization.
- Забывать обработку not found и errors.

## Мини-шпаргалка

- Server Component - для данных и HTML.
- Хорош для SEO-контента.
- Безопасен для env secrets.
- Уменьшает client JS.
- Не умеет browser events.
- Интерактивность выноси в Client Component.
