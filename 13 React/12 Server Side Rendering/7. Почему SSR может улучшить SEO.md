# Почему SSR может улучшить SEO?

> [!summary]
> SSR может улучшить SEO, потому что поисковый бот получает готовый HTML с контентом, ссылками и meta-тегами уже в первом ответе. В CSR этот контент часто появляется только после загрузки и выполнения JavaScript.

## Контент доступен сразу

CSR:

```html
<div id="root"></div>
<script src="/bundle.js"></script>
```

Боту нужно выполнить JavaScript, дождаться запросов и только потом увидеть текст.

SSR:

```html
<main>
  <h1>How React SSR works</h1>
  <p>Full article text...</p>
</main>
```

Контент находится в HTML сразу.

## Ссылки видны сразу

Для индексации важны внутренние ссылки.

```html
<a href="/blog/react-ssr">React SSR</a>
<a href="/blog/react-router">React Router</a>
```

Если ссылки появляются только после client render, crawler может увидеть их позже или не увидеть в нужный момент.

## Meta-теги и social preview

SSR помогает отдавать уникальные meta-теги для каждой страницы:

```html
<title>React SSR Guide</title>
<meta name="description" content="Learn server rendering in React">
<meta property="og:title" content="React SSR Guide">
```

Это влияет на сниппеты, Open Graph preview и качество шаринга ссылок.

## Core Web Vitals

SSR может улучшить LCP, если главный контент приходит в HTML и быстро отображается.

Но SSR сам по себе не гарантирует хороший SEO. Можно испортить страницу:

- медленным TTFB;
- тяжелой hydration;
- плохими meta;
- отсутствием semantic HTML;
- плохим robots/sitemap;
- layout shift.

## Что сказать на собеседовании?

```text
SSR улучшает SEO не магически, а потому что crawler получает содержательный HTML
на первом request. Но SEO зависит не только от SSR: важны meta, semantic HTML,
performance, sitemap, robots.txt и качество контента.
```

## Мини-шпаргалка

- SSR отдает готовый HTML.
- Бот быстрее видит текст, ссылки и meta.
- Open Graph теги формируются на сервере.
- SSR может улучшить LCP.
- SSR не заменяет полноценную SEO-оптимизацию.
