# Почему JSX требует один корневой элемент?

> [!summary]
> Компонент React должен вернуть одно значение. Поэтому несколько соседних JSX-элементов нужно обернуть в общий родительский элемент или в `React.Fragment`.

## Проблемный пример

Так писать нельзя:

```jsx
function Header() {
  return (
    <h1>Профиль</h1>
    <p>Настройки пользователя</p>
  )
}
```

Компонент пытается вернуть два соседних значения одновременно.

## Вариант с обычным DOM-элементом

```jsx
function Header() {
  return (
    <div>
      <h1>Профиль</h1>
      <p>Настройки пользователя</p>
    </div>
  )
}
```

Работает, но добавляет лишний `div` в DOM.

## Вариант с Fragment

```jsx
function Header() {
  return (
    <>
      <h1>Профиль</h1>
      <p>Настройки пользователя</p>
    </>
  )
}
```

Fragment группирует элементы для React, но не создает лишний DOM-узел.

## Почему это связано с JavaScript?

JSX-компонент возвращает JavaScript-значение:

```jsx
return <h1>Профиль</h1>
```

А вот две JSX-ноды рядом - это уже синтаксически не одно выражение:

```jsx
return <h1>Профиль</h1><p>Текст</p>
```

Поэтому нужен контейнер.

## Когда лучше `div`, а когда Fragment?

Используй `div`, если нужен реальный контейнер:

- для layout;
- для CSS;
- для `ref`;
- для обработчиков;
- для ARIA-ролей.

Используй Fragment, если контейнер нужен только для группировки JSX.

## Мини-шпаргалка

- Компонент возвращает одно значение.
- Несколько соседних элементов нужно обернуть.
- `div` добавляет узел в DOM.
- Fragment не добавляет лишний DOM-узел.
- Короткий синтаксис Fragment: `<>...</>`.
