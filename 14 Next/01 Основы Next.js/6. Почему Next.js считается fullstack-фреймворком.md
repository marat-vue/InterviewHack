# Почему Next.js считается fullstack-фреймворком?

> [!summary]
> Next.js считается fullstack-фреймворком, потому что в одном проекте можно писать UI, серверную загрузку данных, backend endpoints, Server Actions, middleware, metadata, кеширование и интеграции с базой данных.

## Что значит fullstack в контексте Next.js?

Это не значит, что Next.js заменяет любой backend. Это значит, что фреймворк умеет выполнять server-side код рядом с React UI.

В одном проекте могут быть:

```text
app/
  page.tsx
  api/
    users/
      route.ts
  actions.ts
lib/
  db.ts
```

## Server Components

Server Component может читать данные на сервере:

```tsx
export default async function UsersPage() {
  const users = await db.user.findMany()

  return <UserList users={users} />
}
```

Код работы с БД не должен попадать в браузер.

## Route Handlers

Route Handler создает endpoint:

```ts
export async function GET() {
  const users = await db.user.findMany()

  return Response.json(users)
}
```

Файл `app/api/users/route.ts` становится URL `/api/users`.

## Server Actions

Server Action позволяет сделать мутацию:

```ts
'use server'

export async function updateProfile(formData: FormData) {
  await db.user.update({
    where: { id: await getCurrentUserId() },
    data: { name: String(formData.get('name')) },
  })
}
```

Ее можно связать с формой.

## Где границы?

Next.js может быть fullstack, но иногда отдельный backend все равно нужен:

- сложная domain logic;
- микросервисы;
- очереди и воркеры;
- WebSocket gateway;
- тяжелые интеграции;
- отдельная команда backend;
- строгие требования безопасности.

## Что отвечать на собеседовании?

Next.js fullstack, потому что умеет выполнять серверный код: Server Components, Route Handlers, Server Actions, middleware, data fetching и cache. Но он не обязан заменять отдельный backend. Часто Next.js работает как BFF между UI и основным API.

## Частые ошибки

- Писать секреты в Client Component.
- Думать, что Server Action не нужно защищать.
- Заменять сложный backend одним Next-приложением без анализа.
- Путать Route Handler и Server Component.
- Игнорировать runtime ограничения хостинга.

## Мини-шпаргалка

- Server Component читает данные на сервере.
- Route Handler создает HTTP endpoint.
- Server Action выполняет server mutation.
- Middleware работает до route.
- Next.js часто используют как BFF.
- Fullstack не значит "backend больше не нужен".
