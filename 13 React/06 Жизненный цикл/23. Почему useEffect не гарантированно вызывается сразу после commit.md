# Почему useEffect не гарантированно вызывается сразу после commit?

> [!summary]
> `useEffect` относится к passive effects. Обычно он выполняется после commit и после того, как браузер получил возможность отрисовать экран. Поэтому его не используют для задач, которые должны синхронно изменить layout до первого paint.

## Что происходит после commit?

Упрощенно:

```text
render phase
commit phase
useLayoutEffect
browser paint
useEffect
```

`useEffect` специально не блокирует paint, чтобы интерфейс мог быстрее появиться на экране.

## Когда это важно?

Если нужно измерить DOM и поправить позицию до того, как пользователь увидит кадр, `useEffect` может быть слишком поздним:

```jsx
useEffect(() => {
  const rect = tooltipRef.current.getBoundingClientRect()
  setPosition(calculatePosition(rect))
}, [])
```

Пользователь может увидеть "прыжок".

Для таких задач используют:

```jsx
useLayoutEffect(() => {
  const rect = tooltipRef.current.getBoundingClientRect()
  setPosition(calculatePosition(rect))
}, [])
```

## Для чего подходит useEffect?

- запросы;
- подписки;
- timers;
- analytics;
- localStorage;
- синхронизация с внешней системой;
- действия, которые не должны блокировать paint.

## Важный нюанс

`useEffect` все равно запускается после того, как React применил DOM-изменения. Но точный момент относительно paint и планировщика не стоит использовать как жесткую гарантию для layout-sensitive кода.

## Мини-шпаргалка

- `useEffect` - passive effect.
- Обычно выполняется после paint.
- Он не должен блокировать первый кадр.
- Для layout до paint используй `useLayoutEffect`.
- Для большинства внешних синхронизаций `useEffect` подходит лучше.
