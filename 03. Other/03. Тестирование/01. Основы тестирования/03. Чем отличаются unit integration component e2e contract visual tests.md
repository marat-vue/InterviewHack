# Чем отличаются unit, integration, component, e2e, contract и visual tests?

> [!summary]
> Разные виды тестов отвечают на разные вопросы. Unit tests проверяют маленькую логику, integration tests - совместную работу частей, component tests - поведение UI-компонента, e2e tests - путь пользователя, contract tests - договор между сервисами, visual tests - внешний вид.

## Unit tests

Вопрос: "Правильно ли работает маленькая часть кода сама по себе?"

```ts
expect(normalizeEmail(' USER@EXAMPLE.COM ')).toBe('user@example.com');
```

Подходит для:

- pure functions;
- composables;
- helpers;
- domain services;
- validators.

## Integration tests

Вопрос: "Правильно ли несколько частей работают вместе?"

```ts
const result = await authService.login('ann@example.com', 'secret');

expect(result.accessToken).toEqual(expect.any(String));
```

Подходит для:

- service + repository;
- route + validation + handler;
- component + store;
- module + database.

## Component tests

Вопрос: "Компонент ведет себя правильно для пользователя?"

```ts
const wrapper = mount(LoginForm);

await wrapper.find('input[type="email"]').setValue('ann@example.com');
await wrapper.find('button').trigger('click');

expect(wrapper.emitted('submit')).toBeTruthy();
```

Подходит для Vue, React, Svelte и других UI-компонентов.

## E2E tests

Вопрос: "Работает ли полный пользовательский путь?"

Пример сценария:

```text
Открыть сайт -> войти -> добавить товар в корзину -> оформить заказ.
```

Для e2e часто используют Playwright или Cypress.

## Contract tests

Вопрос: "Поставщик и потребитель API одинаково понимают контракт?"

Например, frontend ожидает:

```json
{
  "id": 1,
  "email": "ann@example.com"
}
```

Если backend переименует `email` в `mail`, contract test должен подсветить проблему до релиза.

## Visual tests

Вопрос: "Не сломался ли внешний вид?"

Visual tests делают screenshot и сравнивают его с эталоном. Они полезны для:

- дизайн-систем;
- критичных экранов;
- regressions в верстке;
- компонентов с большим количеством состояний.

## Мини-шпаргалка

- Unit - маленькая логика.
- Integration - связь частей.
- Component - UI-компонент и действия пользователя.
- E2E - весь пользовательский путь.
- Contract - API-договор между системами.
- Visual - внешний вид и верстка.
