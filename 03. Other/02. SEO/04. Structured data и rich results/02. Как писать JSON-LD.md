# Как писать JSON-LD?

> [!summary]
> JSON-LD - это способ добавить structured data через `<script type="application/ld+json">`. Он удобен тем, что не смешивает HTML-разметку контента с машинным описанием сущностей.

## Базовая структура

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Как работает robots.txt",
  "datePublished": "2026-07-20",
  "author": {
    "@type": "Person",
    "name": "Мария Иванова"
  }
}
</script>
```

## Что означают поля?

| Поле | Смысл |
|---|---|
| `@context` | словарь, обычно `https://schema.org` |
| `@type` | тип сущности |
| `headline` | заголовок |
| `author` | автор |
| `datePublished` | дата публикации |
| `image` | изображение |

## Где размещать JSON-LD?

Обычно в `<head>` или в HTML страницы:

```html
<head>
  <title>...</title>
  <script type="application/ld+json">...</script>
</head>
```

Для SPA важно, чтобы разметка корректно появлялась для текущего маршрута и не оставалась от предыдущей страницы.

## Как генерировать безопасно?

В приложении лучше генерировать JSON из объекта, а не вручную склеивать строку:

```ts
const schema = {
  '@context': 'https://schema.org',
  '@type': 'BreadcrumbList',
  itemListElement: breadcrumbs.map((item, index) => ({
    '@type': 'ListItem',
    position: index + 1,
    name: item.name,
    item: item.url,
  })),
}
```

Потом сериализовать через `JSON.stringify`.

## Мини-шпаргалка

- JSON-LD кладут в `<script type="application/ld+json">`.
- Данные должны совпадать с видимым контентом.
- Не склеивай JSON руками, если можно сериализовать объект.
- Для SPA следи за обновлением разметки при навигации.
- Проверяй результат валидатором.
