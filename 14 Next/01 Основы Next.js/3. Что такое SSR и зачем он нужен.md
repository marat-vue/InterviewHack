# Что такое SSR и зачем он нужен?

> [!summary]
> SSR, или Server-Side Rendering, означает, что HTML страницы формируется на сервере для запроса пользователя. В Next.js SSR полезен для динамических страниц, SEO, быстрого первого контента и работы с request-specific данными.

## Как работает SSR?

При SSR браузер не получает пустой контейнер и не ждет, пока весь UI соберется на клиенте.

Упрощенный flow:

1. Пользователь запрашивает URL.
2. Сервер Next.js выполняет нужный route.
3. Сервер загружает данные.
4. React рендерится в HTML.
5. Браузер показывает HTML.
6. Клиентский JavaScript гидратирует интерактивные части.

## Пример в App Router

```tsx
export default async function ProfilePage() {
  const user = await getCurrentUser()

  return (
    <main>
      <h1>{user.name}</h1>
      <p>{user.email}</p>
    </main>
  )
}
```

Если страница использует request-specific данные, например cookies, headers или uncached fetch, она становится динамической.

## Когда SSR полезен?

- личный кабинет с данными текущего пользователя;
- страница заказа;
- контент зависит от cookies/headers;
- данные часто меняются;
- важны SEO и первый HTML;
- нельзя заранее сгенерировать страницу.

## SSR vs CSR

| Критерий | SSR | CSR |
|---|---|---|
| HTML с контентом | приходит с сервера | создается в браузере |
| SEO | обычно лучше | зависит от JS indexing |
| TTFB | может быть выше | ниже для пустого shell |
| JS на клиенте | нужен для интерактива | нужен для всего UI |
| Персонализация | удобно | удобно после загрузки API |

## SSR не означает, что JS не нужен

Если на странице есть Client Components, им нужен JavaScript:

```tsx
import { AddToCartButton } from './AddToCartButton'

export default async function ProductPage() {
  const product = await getProduct()

  return (
    <>
      <h1>{product.title}</h1>
      <AddToCartButton productId={product.id} />
    </>
  )
}
```

HTML товара может прийти с сервера, но кнопка корзины гидратируется на клиенте.

## Что отвечать на собеседовании?

SSR в Next.js нужен, когда страницу нельзя полностью подготовить заранее или когда важны SEO и быстрый первый контент. Сервер формирует HTML на request, а интерактивные Client Components затем гидратируются в браузере. SSR не отменяет client JavaScript.

## Частые ошибки

- Думать, что SSR всегда быстрее SSG.
- Делать SSR для полностью статичных страниц.
- Путать SSR и Server Components.
- Считать, что SSR убирает hydration.
- Игнорировать кеширование и получать медленный TTFB.

## Мини-шпаргалка

- SSR генерирует HTML на сервере.
- Хорош для request-specific данных.
- Улучшает SEO для контентных страниц.
- Требует server runtime.
- Client Components все равно гидратируются.
- Для статики чаще выгоднее SSG/ISR.
