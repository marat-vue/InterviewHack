# Как типизировать Vue components, props, emits, slots, template refs и v-model?

> [!NOTE]
> TypeScript во Vue нужен не только для props. Хорошая типизация описывает публичный контракт компонента: входные данные, события, модели, slots, exposed methods и refs на DOM/компоненты.

## Вопрос

Как типизировать Vue-компоненты: props, emits, slots, template refs, `v-model` и exposed methods?

## Базовая настройка

Для Vue SFC обычно используют:

```vue
<script setup lang="ts">
// TypeScript включен
</script>
```

В Vite-проекте важно иметь:

```json
{
  "compilerOptions": {
    "strict": true,
    "jsx": "preserve",
    "moduleResolution": "Bundler",
    "types": ["vite/client"]
  }
}
```

И проверку типов:

```json
{
  "scripts": {
    "typecheck": "vue-tsc --noEmit"
  }
}
```

## Props

Type-only props:

```vue
<script setup lang="ts">
const props = defineProps<{
  id: number;
  title: string;
  size?: "sm" | "md" | "lg";
  disabled?: boolean;
}>();
</script>
```

Props с defaults:

```vue
<script setup lang="ts">
const props = withDefaults(
  defineProps<{
    size?: "sm" | "md" | "lg";
    disabled?: boolean;
  }>(),
  {
    size: "md",
    disabled: false,
  },
);
</script>
```

Runtime props:

```vue
<script setup lang="ts">
import type { PropType } from "vue";

interface User {
  id: number;
  name: string;
}

defineProps({
  user: {
    type: Object as PropType<User>,
    required: true,
  },
  status: {
    type: String as PropType<"active" | "blocked">,
    default: "active",
  },
});
</script>
```

Когда нужен runtime-синтаксис:

- JavaScript-проект;
- нужны validators;
- props-конфигурация создается как runtime object;
- требуется совместимость с Options API.

## Emits

Современный tuple-синтаксис:

```vue
<script setup lang="ts">
const emit = defineEmits<{
  save: [payload: { title: string; body: string }];
  cancel: [];
  remove: [id: number];
}>();

emit("save", {
  title: "Vue",
  body: "Composition API",
});
</script>
```

События должны описывать внешний контракт:

- `save`;
- `cancel`;
- `select`;
- `remove`;
- `update:modelValue`;
- `submit`.

Не стоит эмитить внутренние технические события, если родителю они не нужны.

## `v-model` через `defineModel`

Одна модель:

```vue
<script setup lang="ts">
const value = defineModel<string>({
  required: true,
});
</script>

<template>
  <input v-model="value" />
</template>
```

Именованные модели:

```vue
<script setup lang="ts">
const start = defineModel<Date | null>("start");
const end = defineModel<Date | null>("end");
</script>
```

Использование:

```vue
<DateRangePicker
  v-model:start="filters.start"
  v-model:end="filters.end"
/>
```

Модификаторы:

```vue
<script setup lang="ts">
const [title, modifiers] = defineModel<string, "trim" | "uppercase">();

function normalize() {
  if (modifiers.trim) {
    title.value = title.value.trim();
  }

  if (modifiers.uppercase) {
    title.value = title.value.toUpperCase();
  }
}
</script>
```

## Slots

Типизация slots через `defineSlots`:

```vue
<script setup lang="ts">
interface Row {
  id: number;
  name: string;
}

defineProps<{
  rows: Row[];
}>();

defineSlots<{
  default(props: { row: Row; index: number }): unknown;
  empty(): unknown;
}>();
</script>

<template>
  <div v-if="rows.length">
    <slot
      v-for="(row, index) in rows"
      :key="row.id"
      :row="row"
      :index="index"
    />
  </div>

  <slot v-else name="empty" />
</template>
```

Родитель получает подсказки по `row` и `index`:

```vue
<DataList :rows="users">
  <template #default="{ row }">
    {{ row.name }}
  </template>
</DataList>
```

## Template refs на DOM

Современный вариант:

```vue
<script setup lang="ts">
import { useTemplateRef } from "vue";

const input = useTemplateRef<HTMLInputElement>("input");

function focusInput() {
  input.value?.focus();
}
</script>

<template>
  <input ref="input" />
</template>
```

Классический вариант:

```vue
<script setup lang="ts">
import { ref } from "vue";

const input = ref<HTMLInputElement | null>(null);
</script>

<template>
  <input ref="input" />
</template>
```

## Template refs на компонент

Дочерний компонент:

```vue
<!-- BaseModal.vue -->
<script setup lang="ts">
function open() {}
function close() {}

defineExpose({
  open,
  close,
});
</script>
```

Родитель:

```vue
<script setup lang="ts">
import { useTemplateRef } from "vue";
import BaseModal from "./BaseModal.vue";

const modal = useTemplateRef<InstanceType<typeof BaseModal>>("modal");

function showModal() {
  modal.value?.open();
}
</script>

<template>
  <BaseModal ref="modal" />
</template>
```

Для generic-компонентов иногда используют helper-типы вроде `ComponentExposed` из `vue-component-type-helpers`, потому что `InstanceType` не всегда корректно раскрывает generic exposed API.

## Provide/inject

Типизированный ключ:

```typescript
import type { InjectionKey, Ref } from "vue";

export interface ThemeContext {
  currentTheme: Ref<"light" | "dark">;
  toggleTheme: () => void;
}

export const themeKey: InjectionKey<ThemeContext> = Symbol("theme");
```

Provider:

```typescript
provide(themeKey, {
  currentTheme,
  toggleTheme,
});
```

Consumer:

```typescript
const theme = inject(themeKey);

if (!theme) {
  throw new Error("Theme provider is missing");
}
```

## Generic components

```vue
<script setup lang="ts" generic="T extends { id: string | number }">
defineProps<{
  items: T[];
  label: (item: T) => string;
}>();

const selected = defineModel<T | null>();
</script>
```

Это удобно для:

- selects;
- tables;
- autocomplete;
- list builders;
- headless UI-компонентов.

## Типизация composables

```typescript
import { computed, toValue, type MaybeRefOrGetter } from "vue";

export function useFilteredItems<T>(
  items: MaybeRefOrGetter<T[]>,
  predicate: MaybeRefOrGetter<(item: T) => boolean>,
) {
  return computed(() => toValue(items).filter(toValue(predicate)));
}
```

Так composable сохраняет тип элемента и принимает raw value, ref или getter.

## Частые ошибки

- Писать `any` для props, потому что "и так понятно".
- Не типизировать emits и потом передавать неправильный payload.
- Использовать `defineModel` без понимания, что это публичный двусторонний контракт.
- Типизировать component ref как `any` вместо exposed API.
- Не запускать `vue-tsc`, полагаясь только на Vite dev server.
- Делать slots без типизации в table/list/form компонентах.

## Что отвечать на собеседовании

В Vue с TypeScript нужно типизировать весь контракт компонента: props через `defineProps`, defaults через `withDefaults`, события через `defineEmits`, `v-model` через `defineModel`, slots через `defineSlots`, DOM refs через `useTemplateRef<HTMLInputElement>`, component refs через exposed API и `InstanceType`. Для проекта обязательно запускать `vue-tsc`, потому что Vite transpile-ит код, но не заменяет полноценную проверку типов SFC.

## Мини-шпаргалка

- `lang="ts"` - TypeScript в SFC.
- `defineProps<T>()` - props.
- `withDefaults()` - default values.
- `defineEmits<T>()` - events.
- `defineModel<T>()` - `v-model`.
- `defineSlots<T>()` - slots.
- `useTemplateRef<T>()` - DOM/component refs.
- `InjectionKey<T>` - typed provide/inject.
- `vue-tsc --noEmit` - обязательная typecheck-команда.
