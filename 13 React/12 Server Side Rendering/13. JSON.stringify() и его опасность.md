# JSON.stringify() и его опасность

> [!summary]
> При SSR опасно вставлять результат `JSON.stringify()` прямо в inline `<script>`, если данные могут содержать пользовательский ввод. JSON-строка может закрыть тег `script` и выполнить XSS-код.

## Опасный пример

```js
const html = `
  <script>
    window.__INITIAL_DATA__ = ${JSON.stringify(data)}
  </script>
`
```

Если `data.name` содержит:

```html
</script><script>alert('xss')</script>
```

браузер может закрыть первый `<script>` и выполнить новый.

## Почему JSON.stringify недостаточно?

`JSON.stringify` экранирует JSON-строки, но не делает данные безопасными для HTML-контекста.

Опасные последовательности:

- `</script>`;
- `<`;
- `>`;
- `&`;
- Unicode separators в старых окружениях;
- HTML-комментарии в некоторых контекстах.

## Безопасное экранирование

Минимальная идея:

```js
const safeJson = JSON.stringify(data)
  .replace(/</g, '\\u003C')
  .replace(/>/g, '\\u003E')
  .replace(/&/g, '\\u0026')
```

Теперь `<` не сможет начать HTML-тег или закрыть `<script>`.

## Готовая сериализация

В production часто используют проверенные библиотеки:

```js
import serialize from 'serialize-javascript'

const safeData = serialize(data, {
  isJSON: true,
})
```

Главное - понимать, какой именно HTML/JS context ты заполняешь.

## JSON script tag

Можно хранить JSON как текст:

```html
<script id="initial-data" type="application/json">
  {"user":{"name":"Ada"}}
</script>
```

И читать на клиенте:

```js
const data = JSON.parse(
  document.getElementById('initial-data').textContent,
)
```

Даже в таком варианте пользовательский HTML нужно экранировать корректно, если он попадает в документ.

## Мини-шпаргалка

- `JSON.stringify` не равен безопасной HTML-сериализации.
- Самая опасная строка - `</script>`.
- Экранируй `<`, `>`, `&`.
- Используй проверенные serializer-библиотеки.
- SSR initial data - важная зона XSS-риска.
