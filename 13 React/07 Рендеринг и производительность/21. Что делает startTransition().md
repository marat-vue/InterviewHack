# Что делает startTransition()?

> [!summary]
> `startTransition` помечает обновления state как несрочные. React может выполнить их в фоне и отдавать приоритет срочным действиям пользователя: вводу, кликам, фокусу и другим интерактивным обновлениям.

## Базовый синтаксис

```jsx
import { startTransition } from 'react'

startTransition(() => {
  setTab('posts')
})
```

Функция внутри `startTransition` вызывается сразу, но обновления state, запланированные синхронно внутри нее, получают статус Transition.

## Зачем это нужно?

Представь поиск по большой таблице:

```jsx
function SearchPage({ allItems }) {
  const [query, setQuery] = useState('')
  const [filteredItems, setFilteredItems] = useState(allItems)

  function handleChange(event) {
    const nextQuery = event.target.value

    setQuery(nextQuery)
    setFilteredItems(filterItems(allItems, nextQuery))
  }
}
```

`setQuery` нужен срочно: пользователь печатает, input должен обновляться мгновенно.

`setFilteredItems` может быть тяжелым: список можно обновить чуть позже.

```jsx
function handleChange(event) {
  const nextQuery = event.target.value

  setQuery(nextQuery)

  startTransition(() => {
    setFilteredItems(filterItems(allItems, nextQuery))
  })
}
```

Теперь ввод остается отзывчивым, а тяжелый список обновляется как менее приоритетная работа.

## Чем отличается от useTransition?

`startTransition` не дает флаг pending:

```jsx
startTransition(() => {
  setPage(nextPage)
})
```

`useTransition` дает `isPending`:

```jsx
const [isPending, startTransition] = useTransition()

function selectTab(tab) {
  startTransition(() => {
    setTab(tab)
  })
}

return (
  <>
    {isPending && <Spinner />}
    <Tabs onSelect={selectTab} />
  </>
)
```

Если нужно показать индикатор состояния перехода, используй `useTransition`.

## Важные ограничения

Transition не подходит для управления значением input:

```jsx
startTransition(() => {
  setInputValue(event.target.value) // плохо для controlled input
})
```

Controlled input должен обновляться срочно, иначе пользователь почувствует задержку.

Также важно: `startTransition` помечает только state updates, которые произошли во время синхронного выполнения callback.

```jsx
startTransition(() => {
  setPage('/users')
})
```

Если после `await` нужно обновить state как transition, обновление обычно снова оборачивают в `startTransition`.

## Где применяется?

- переключение вкладок с тяжелым содержимым;
- фильтрация больших списков;
- навигация внутри Suspense-enabled router;
- обновление графиков;
- смена страницы, где часть UI может догружаться.

## Мини-шпаргалка

- `startTransition` помечает обновления как несрочные.
- Срочные updates, например input value, оставляют обычными.
- Transition update может быть прерван и перезапущен.
- Для pending-индикатора нужен `useTransition`.
- Это инструмент UX, а не замена debouncing или кешированию.
