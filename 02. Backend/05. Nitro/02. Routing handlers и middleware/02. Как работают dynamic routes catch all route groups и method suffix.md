# Как работают dynamic routes, catch-all, route groups и method suffix?

> [!NOTE]
> Nitro file-based routing поддерживает static routes, dynamic params через `[param]`, catch-all через `[...param]`, route groups через папки в скобках и method-specific файлы вроде `.get.ts` или `.post.ts`.

## Static route

```txt
server/routes/about.ts
  -> /about

server/routes/api/status.get.ts
  -> GET /api/status
```

Static route подходит для фиксированного URL.

## Dynamic route

```txt
server/routes/api/users/[id].get.ts
  -> GET /api/users/:id
```

Чтение параметра:

```ts
import { defineHandler } from 'nitro';
import { getRouterParam } from 'h3';

export default defineHandler((event) => {
  const id = getRouterParam(event, 'id');

  return {
    id,
  };
});
```

## Несколько params

```txt
server/routes/api/orgs/[org]/repos/[repo].get.ts
  -> GET /api/orgs/:org/repos/:repo
```

```ts
import { getRouterParams } from 'h3';

export default defineHandler((event) => {
  const { org, repo } = getRouterParams(event);

  return {
    org,
    repo,
  };
});
```

## Catch-all route

Catch-all забирает остаток path.

```txt
server/routes/docs/[...slug].get.ts
  -> GET /docs/*
```

```ts
export default defineHandler((event) => {
  const slug = getRouterParam(event, 'slug');

  return {
    slug,
  };
});
```

Если пришел URL:

```txt
/docs/backend/nitro/routing
```

`slug` будет примерно:

```txt
backend/nitro/routing
```

## Catch-all fallback

Файл:

```txt
server/routes/[...].ts
```

можно использовать как fallback для unmatched routes.

Это полезно для:

- custom 404;
- SPA fallback;
- proxy fallback;
- compatibility layer.

## Route groups

Папка в скобках группирует файлы, но не влияет на URL:

```txt
server/routes/api/
  (admin)/
    users.get.ts
  (public)/
    health.get.ts
```

URL:

```txt
GET /api/users
GET /api/health
```

Route groups нужны для организации:

- public/admin;
- v1/v2 implementation groups;
- domain folders;
- feature folders;
- experimental routes.

## Method suffix

```txt
hello.get.ts
hello.post.ts
hello.patch.ts
```

Если route имеет `.get.ts`, POST-запрос его не сматчит.

Это лучше, чем писать один большой handler:

```ts
if (event.method === 'GET') {}
if (event.method === 'POST') {}
```

## Environment suffix

Nitro поддерживает environment-specific handlers:

```txt
server/routes/debug.get.dev.ts
server/routes/debug.get.prod.ts
server/routes/cache.prerender.ts
```

Это полезно, когда:

- dev-only endpoint не должен попасть в production;
- production route отличается от dev;
- route нужен только для prerender.

## Как избежать конфликтов?

Хорошие правила:

- не создавать одновременно `users.ts` и `users.get.ts` без необходимости;
- не делать слишком широкие catch-all routes в начале проекта;
- dynamic params называть явно: `[userId]`, `[postId]`, `[slug]`;
- route groups использовать только для организации;
- method suffix ставить почти всегда для API.

## Мини-шпаргалка

- `[id]` - один dynamic param.
- `[...slug]` - catch-all param.
- `[...].ts` - fallback route.
- `(admin)` - route group без влияния на URL.
- `.get.ts`, `.post.ts` - method-specific routes.
- `.dev.ts`, `.prod.ts`, `.prerender.ts` - environment-specific handlers.
