# Чем локальное состояние отличается от глобального?

> [!summary]
> Локальное состояние принадлежит конкретному компоненту или небольшой ветке UI. Глобальное состояние доступно многим частям приложения. Хорошая архитектура не делает все глобальным: глобальность увеличивает связанность и стоимость изменений.

## Локальное состояние

Примеры:

- открыт ли dropdown;
- текст в локальном input;
- активная вкладка внутри карточки;
- hover/expanded-состояние;
- состояние маленькой формы.

```jsx
function Tabs() {
  const [activeTab, setActiveTab] = useState('profile')
  return <TabContent activeTab={activeTab} />
}
```

Если state нужен только `Tabs`, он должен оставаться там.

## Глобальное состояние

Примеры:

- текущий пользователь;
- тема;
- язык интерфейса;
- корзина;
- feature flags;
- данные, нужные во многих разделах.

Глобальное состояние можно хранить через:

- Context;
- Zustand;
- Redux Toolkit;
- Jotai;
- TanStack Query для server state;
- state фреймворка.

## Почему не нужно делать все глобальным?

Минусы:

- сложнее отслеживать изменения;
- больше компонентов зависят от одного источника;
- выше риск лишних render;
- сложнее тестировать;
- локальная UI-логика смешивается с бизнес-состоянием.

## Как выбрать?

Задай вопросы:

```text
Кто использует это состояние?
Должно ли оно переживать размонтирование компонента?
Нужно ли синхронизировать его с URL или backend?
Это UI-состояние или бизнес-данные?
```

Если ответ "использует только один компонент", почти всегда начинай с локального state.

## Мини-шпаргалка

- Локальное state живет рядом с UI.
- Глобальное state нужно многим частям приложения.
- Не делай state глобальным заранее.
- Server state лучше не смешивать с client UI state.
- Поднимай state по необходимости, а не по привычке.
