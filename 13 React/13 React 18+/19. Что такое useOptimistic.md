# Что такое useOptimistic?

> [!summary]
> `useOptimistic` - React hook для optimistic UI: интерфейс показывает ожидаемый результат сразу, пока асинхронная операция еще выполняется. Он особенно полезен для комментариев, лайков, чатов, списков задач и корзины.

## Что такое optimistic UI?

Optimistic UI - это подход, при котором приложение ведет себя так, будто операция уже успешно выполнена.

Пользователь нажал Like:

1. UI сразу увеличил счетчик.
2. Запрос ушел на сервер.
3. Если сервер подтвердил - реальное состояние догнало UI.
4. Если сервер вернул ошибку - UI возвращается к реальным данным или показывает ошибку.

## Сигнатура

```jsx
const [optimisticState, addOptimistic] = useOptimistic(
  state,
  updateFn,
)
```

| Часть | Что означает |
|---|---|
| `state` | реальное состояние из props, loader, server response или cache |
| `optimisticState` | состояние, которое React показывает во время pending action |
| `addOptimistic` | функция для добавления optimistic update |
| `updateFn` | чистая функция, которая строит optimistic state |

`updateFn` должна быть pure:

```jsx
(currentState, optimisticValue) => nextState
```

## Пример: добавление комментария

```jsx
import { useOptimistic } from 'react'

function Comments({ comments, createComment }) {
  const [optimisticComments, addOptimisticComment] = useOptimistic(
    comments,
    (currentComments, text) => [
      ...currentComments,
      {
        id: `temp-${Date.now()}`,
        text,
        sending: true,
      },
    ],
  )

  async function formAction(formData) {
    const text = formData.get('text')

    addOptimisticComment(text)
    await createComment(text)
  }

  return (
    <form action={formAction}>
      {optimisticComments.map((comment) => (
        <p key={comment.id}>
          {comment.text}
          {comment.sending && ' (sending)'}
        </p>
      ))}

      <input name="text" />
      <button>Send</button>
    </form>
  )
}
```

## Что происходит при ошибке?

`useOptimistic` не делает магию за бизнес-логику. Он показывает optimistic state во время async action. Когда реальное состояние не изменилось или action завершилась ошибкой, UI возвращается к актуальному `state`.

Ошибку все равно нужно обработать:

```jsx
async function formAction(formData) {
  const text = formData.get('text')

  addOptimisticComment(text)

  try {
    await createComment(text)
  } catch (error) {
    toast.error('Comment was not saved')
  }
}
```

## Где useOptimistic особенно полезен?

Хорошие сценарии:

- лайки;
- добавление комментария;
- отправка сообщения;
- добавление товара в корзину;
- toggle favorite;
- reorder списка;
- простые операции, которые обычно успешны.

Плохие сценарии:

- платежи;
- удаление аккаунта;
- критичные юридические действия;
- операции, где ошибка вероятна и последствия серьезные;
- сложные транзакции, где пользователь должен увидеть подтвержденный результат.

## useOptimistic vs ручной optimistic update

Ручной подход часто требует:

- хранить старое состояние;
- применять временное состояние;
- ловить ошибку;
- откатывать;
- синхронизировать с cache.

`useOptimistic` делает optimistic state частью React-модели и хорошо сочетается с Actions.

## Что отвечать на собеседовании?

`useOptimistic` позволяет временно показать UI как будто async action уже успешно завершилась. Он принимает реальное состояние и pure update-функцию, возвращает optimistic state и функцию для добавления optimistic update. Это улучшает perceived performance, но ошибки и бизнес-ограничения все равно нужно обрабатывать.

## Частые ошибки

- Использовать optimistic UI для критичных операций.
- Мутировать массив внутри `updateFn`.
- Забывать показать пользователю ошибку.
- Думать, что `useOptimistic` сам сохраняет данные на сервере.
- Генерировать нестабильные ключи так, что список дергается.

## Мини-шпаргалка

- `useOptimistic(state, updateFn)`.
- `updateFn` должна быть pure.
- UI обновляется до ответа сервера.
- Хорошо работает с Actions.
- Для ошибок нужна отдельная обработка.
