# Что делает componentDidUpdate?

> [!summary]
> `componentDidUpdate` - lifecycle method классового компонента, который вызывается после обновления компонента из-за изменения props или state. Он не вызывается при первом render и часто используется для синхронизации с внешними системами после update.

## Базовый пример

```jsx
class UserPage extends Component {
  componentDidUpdate(prevProps) {
    if (prevProps.userId !== this.props.userId) {
      this.loadUser(this.props.userId)
    }
  }

  render() {
    return <h1>Пользователь {this.props.userId}</h1>
  }
}
```

Сравнение с `prevProps` обязательно, иначе можно легко создать лишнюю работу или бесконечный цикл.

## Почему нужна проверка?

Плохо:

```jsx
componentDidUpdate() {
  this.setState({ updated: true })
}
```

`setState` внутри `componentDidUpdate` вызовет новый update, потом снова `componentDidUpdate`, и так далее.

Правильно:

```jsx
componentDidUpdate(prevProps) {
  if (prevProps.userId !== this.props.userId) {
    this.setState({ updated: true })
  }
}
```

## Аналог в функциональном компоненте

```jsx
function UserPage({ userId }) {
  useEffect(() => {
    loadUser(userId)
  }, [userId])

  return <h1>Пользователь {userId}</h1>
}
```

`useEffect` с dependency запускается после commit, когда `userId` изменился.

## Когда встречается?

- legacy-код;
- классовые компоненты;
- старые библиотеки;
- миграция на hooks;
- Error Boundary рядом с class components.

## Мини-шпаргалка

- `componentDidUpdate` вызывается после update.
- Не вызывается при initial render.
- Нужно сравнивать `prevProps` и `prevState`.
- `setState` внутри требует условия.
- В функциях чаще используют `useEffect`.
