# Почему при роутинге страница не перезагружается?

> [!summary]
> В клиентском роутинге React Router перехватывает навигацию, меняет URL через History API и рендерит новый компонент внутри уже загруженного приложения. Браузер не запрашивает новый HTML-документ, поэтому полной перезагрузки нет.

## Что делает обычная ссылка?

```html
<a href="/about">About</a>
```

Обычно браузер:

```text
1. Переходит по href
2. Делает request на сервер
3. Получает HTML
4. Заново строит страницу
```

## Что делает Link?

```jsx
import { Link } from 'react-router-dom'

<Link to="/about">About</Link>
```

React Router:

- перехватывает click;
- отменяет стандартный reload;
- вызывает History API;
- обновляет location;
- рендерит подходящий route.

## History API

Браузер позволяет менять адрес без перезагрузки:

```js
history.pushState(null, '', '/about')
```

React Router использует этот механизм и синхронизирует его с React state.

## Когда перезагрузка все равно будет?

- обычный `<a href="/about">`, если переход не обработан роутером;
- `window.location.href = '/about'`;
- переход на другой домен;
- обновление страницы пользователем;
- открытие URL напрямую;
- сервер не настроен отдавать `index.html` для SPA route.

## Почему нужен fallback на сервере?

Если пользователь откроет `/profile` напрямую, браузер запросит:

```text
GET /profile
```

В SPA физического файла `/profile` нет. Сервер должен вернуть `index.html`, чтобы React Router уже на клиенте показал нужную страницу.

## Мини-шпаргалка

- `<Link>` предотвращает полный reload.
- URL меняется через History API.
- React Router обновляет компонентное дерево.
- При прямом заходе на SPA route сервер должен вернуть `index.html`.
- Для внешних ссылок обычный reload нормален.
