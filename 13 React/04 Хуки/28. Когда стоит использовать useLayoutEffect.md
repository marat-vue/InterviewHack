# Когда стоит использовать useLayoutEffect?

> [!summary]
> `useLayoutEffect` стоит использовать только тогда, когда нужно прочитать layout из DOM и синхронно изменить UI до отрисовки кадра. В большинстве случаев подходит обычный `useEffect`.

## Хороший сценарий: tooltip

```jsx
function Tooltip({ targetRect }) {
  const ref = useRef(null)
  const [height, setHeight] = useState(0)

  useLayoutEffect(() => {
    setHeight(ref.current.getBoundingClientRect().height)
  }, [])

  return (
    <div
      ref={ref}
      style={{ top: targetRect.top - height }}
    >
      Подсказка
    </div>
  )
}
```

Без `useLayoutEffect` пользователь мог бы увидеть tooltip в неправильной позиции на один кадр.

## Хорошие сценарии

- tooltip/popover positioning;
- измерение высоты/ширины перед paint;
- синхронная коррекция scroll;
- layout-sensitive animation setup;
- интеграция с imperative layout library.

## Плохие сценарии

Не стоит использовать `useLayoutEffect` для:

- обычных API-запросов;
- логирования;
- analytics;
- подписок, которые не влияют на первый paint;
- простых вычислений;
- всего, что не требует блокировки paint.

Пример, где лучше `useEffect`:

```jsx
useEffect(() => {
  document.title = title
}, [title])
```

## Как принять решение?

Спроси:

```text
Увидит ли пользователь неправильный layout, если код выполнится после paint?
```

Если нет, используй `useEffect`.

## Мини-шпаргалка

- `useLayoutEffect` нужен для layout до paint.
- Он может блокировать отрисовку.
- Для запросов и подписок обычно нужен `useEffect`.
- Используй его точечно и коротко.
- Если сомневаешься, начни с `useEffect`.
