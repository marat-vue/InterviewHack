> [!summary]
> При парсинге HTML браузер читает поток символов, распознает токены, создает элементы и постепенно строит DOM-дерево.

## Главное

Парсинг HTML - это процесс превращения текста разметки в структуру, с которой браузер и JavaScript могут работать.

```text
HTML text
  -> tokens
  -> nodes
  -> DOM tree
```

## Пример

```html
<p>Привет, <strong>HTML</strong></p>
```

Браузер видит:

```text
start tag: p
text: "Привет, "
start tag: strong
text: "HTML"
end tag: strong
end tag: p
```

Затем строит дерево:

```text
p
  "Привет, "
  strong
    "HTML"
```

## HTML парсится терпимо

HTML-парсер умеет исправлять часть ошибок. Например, если закрыть тег неявно, браузер может сам восстановить структуру.

```html
<ul>
  <li>Первый
  <li>Второй
</ul>
```

Браузер поймет, что первый `li` нужно закрыть перед вторым. Это удобно, но полагаться на автоисправления не стоит: разные ошибки могут приводить к неожиданному DOM.

## Скрипты могут останавливать парсинг

Обычный скрипт без `defer` и `async` блокирует парсинг HTML.

```html
<script src="/app.js"></script>
```

Браузер должен скачать и выполнить скрипт, потому что он может изменить документ через `document.write` или DOM API.

Чаще для обычных приложений используют `defer`.

```html
<script src="/app.js" defer></script>
```

## Почему порядок важен

Браузер читает HTML сверху вниз. Если JavaScript пытается найти элемент до того, как он был распарсен, он может получить `null`.

```html
<script>
  console.log(document.querySelector("#app")); // null
</script>

<div id="app"></div>
```

`defer` или размещение скрипта в конце `body` решает эту проблему.

## Мини-шпаргалка

- Парсинг превращает HTML-текст в DOM.
- Браузер читает HTML сверху вниз.
- HTML-парсер может исправлять некоторые ошибки.
- Обычный `<script>` блокирует парсинг.
- `defer` позволяет выполнить скрипт после построения DOM.
