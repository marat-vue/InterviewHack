# Почему Zustand называют минималистичным state-менеджером?

> [!summary]
> Zustand называют минималистичным, потому что для создания глобального store обычно достаточно одной функции `create`: без reducers, action creators, Provider-оберток и большого количества шаблонного кода.

## Минимальный store

```jsx
import { create } from 'zustand'

const useBearStore = create((set) => ({
  bears: 0,
  increase: () => set((state) => ({ bears: state.bears + 1 })),
}))
```

Использование:

```jsx
const bears = useBearStore((state) => state.bears)
const increase = useBearStore((state) => state.increase)
```

Это весь базовый API для многих задач.

## Что не обязательно в Zustand?

Обычно не нужны:

- обязательный Provider;
- action types;
- dispatch;
- reducer;
- selector hooks вручную;
- большое количество файлов;
- сложная настройка.

Но это не значит, что архитектура не нужна. Store все равно нужно проектировать осознанно.

## Почему minimal не значит primitive?

Zustand поддерживает:

- selectors;
- subscriptions;
- middleware;
- persist;
- immer;
- devtools;
- vanilla stores;
- TypeScript;
- работу вне React.

Минимализм здесь про низкий порог входа, а не про отсутствие возможностей.

## Где он особенно удобен?

- небольшие и средние приложения;
- UI state;
- feature-level stores;
- прототипы;
- dashboards;
- shared filters;
- modals;
- cart-like state.

## Мини-шпаргалка

- Zustand требует мало boilerplate.
- Store сам является hook.
- Provider обычно не нужен.
- Selectors помогают подписываться на часть state.
- Минимализм не отменяет дисциплину в структуре store.
