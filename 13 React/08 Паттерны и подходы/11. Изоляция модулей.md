# Изоляция модулей

> [!summary]
> Изоляция модулей означает, что каждая фича, сущность или виджет имеет четкие границы и общается с остальным приложением через публичное API. Это уменьшает связанность и делает рефакторинг безопаснее.

## Что такое модуль?

В frontend-приложении модулем может быть:

- фича `login`;
- сущность `product`;
- виджет `header`;
- страница `checkout`;
- общий UI-компонент `button`;
- пакет в монорепозитории.

Модуль должен иметь понятную ответственность и ограниченный внешний интерфейс.

## Плохой пример: импорт из внутренностей

```ts
import { normalizeUser } from '@/entities/user/model/private/normalizeUser'
import { UserAvatar } from '@/entities/user/ui/avatar/UserAvatar'
```

Проблема: внешний код знает структуру папок внутри `user`. Любой рефакторинг сломает импорты.

## Хороший пример: публичное API

```ts
import { normalizeUser, UserAvatar } from '@/entities/user'
```

Внутри:

```ts
// entities/user/index.ts
export { UserAvatar } from './ui/UserAvatar'
export { normalizeUser } from './model/normalizeUser'
export type { User } from './model/types'
```

Теперь модуль может менять внутренние файлы, не ломая потребителей.

## Что дает изоляция?

- меньше циклических зависимостей;
- проще удалять фичи;
- проще заменять реализацию;
- понятнее code ownership;
- легче тестировать модули;
- меньше случайных импортов "куда попало".

## Правила границ

Полезные правила:

- модуль экспортирует только то, что разрешено использовать снаружи;
- внутренние helpers не импортируются напрямую;
- нижние слои не знают о верхних;
- модуль не мутирует чужой state напрямую;
- связь между модулями идет через props, events, store actions или API.

## Пример с заменой реализации

```ts
// раньше
export { useCart } from './model/reduxCart'

// позже
export { useCart } from './model/zustandCart'
```

Если внешний код импортировал `useCart` из `@/entities/cart`, ему не важно, что внутри заменили Redux на Zustand.

## Мини-шпаргалка

- Модуль должен иметь границы.
- Импортируй из public API, а не из внутренних файлов.
- Изоляция снижает связанность.
- Хороший модуль можно переписать без массового изменения проекта.
- Правила импортов стоит закреплять линтером.
