# Можно ли изменять props внутри компонента?

> [!summary]
> Props внутри компонента изменять нельзя. Их нужно воспринимать как read-only данные, которые пришли от родителя. Если компоненту нужно менять данные, он должен использовать собственный state или попросить родителя изменить данные через callback.

## Плохой пример

```jsx
function UserCard({ user }) {
  user.name = 'Новое имя'

  return <h2>{user.name}</h2>
}
```

Так делать нельзя: компонент мутирует объект, который принадлежит родителю или внешнему состоянию.

## Почему props read-only?

React строит UI как функцию от props и state:

```text
UI = f(props, state)
```

Если компонент начинает менять props, поток данных становится непредсказуемым:

- родитель не знает, что данные изменились;
- React может не увидеть изменение ссылки;
- другие компоненты могут получить неожиданно измененный объект;
- отладка становится сложнее.

## Как правильно менять данные?

Родитель хранит state и передает ребенку данные и callback:

```jsx
function UserPage() {
  const [user, setUser] = useState({ name: 'Анна' })

  function renameUser(name) {
    setUser({ ...user, name })
  }

  return <UserCard user={user} onRename={renameUser} />
}

function UserCard({ user, onRename }) {
  return (
    <>
      <h2>{user.name}</h2>
      <button onClick={() => onRename('Мария')}>
        Переименовать
      </button>
    </>
  )
}
```

## А если нужно локально изменить начальное значение?

Можно использовать prop как initial value для state:

```jsx
function EditableName({ initialName }) {
  const [name, setName] = useState(initialName)

  return (
    <input
      value={name}
      onChange={(event) => setName(event.target.value)}
    />
  )
}
```

Но важно понимать: если `initialName` потом изменится у родителя, локальный `name` автоматически не синхронизируется.

## Мини-шпаргалка

- Props нельзя мутировать.
- Props принадлежат родителю.
- Для изменений используют state и callback.
- Объекты и массивы из props тоже нельзя менять напрямую.
- Prop можно использовать как initial value, но это отдельное локальное состояние.
