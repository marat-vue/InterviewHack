# Что делает “Flux Architecture”?

> [!summary]
> Flux Architecture - это подход к управлению состоянием с однонаправленным потоком данных. Пользовательское действие создает action, action попадает в store, store обновляет состояние, а view перерисовывается на основе нового состояния.

## Главная схема

```text
View -> Action -> Dispatcher -> Store -> View
```

В современных библиотеках отдельного dispatcher может не быть как явного объекта, но идея остается: изменение состояния происходит через понятное действие, а UI читает результат из store.

## Зачем появился Flux?

В сложных UI много мест могут менять данные:

- формы;
- кнопки;
- websocket events;
- ответы API;
- background sync;
- route changes.

Если данные могут обновлять друг друга хаотично, становится трудно понять, почему UI находится в таком состоянии.

Flux вводит однонаправленный поток.

## Пример на псевдокоде

Action:

```js
const action = {
  type: 'cart/addProduct',
  payload: { productId: 'p1' },
}
```

Store:

```js
function cartReducer(state, action) {
  switch (action.type) {
    case 'cart/addProduct':
      return {
        ...state,
        productIds: [...state.productIds, action.payload.productId],
      }
    default:
      return state
  }
}
```

View:

```jsx
function AddToCartButton({ productId }) {
  const dispatch = useDispatch()

  return (
    <button
      onClick={() => dispatch({
        type: 'cart/addProduct',
        payload: { productId },
      })}
    >
      Add to cart
    </button>
  )
}
```

## Flux и Redux

Redux вдохновлен Flux, но упростил некоторые идеи:

| Flux | Redux |
|---|---|
| Может быть несколько stores | Обычно один store |
| Есть dispatcher | Dispatch встроен в store |
| Store содержит state и update logic | Update logic обычно в reducers |
| Концепция | Конкретная библиотека/подход |

## Flux и React

React хорошо сочетается с Flux, потому что React view декларативен:

```text
state изменился -> React заново вычислил UI
```

Flux отвечает за поток данных, React - за отображение результата.

## Плюсы

- предсказуемые изменения state;
- проще debug;
- легче логировать actions;
- проще делать time travel debugging;
- понятная граница между UI и состоянием.

## Минусы

- boilerplate;
- избыточность для маленьких приложений;
- нужно дисциплинированно моделировать actions;
- server state лучше не всегда хранить как обычный client state.

## Мини-шпаргалка

- Flux = однонаправленный поток данных.
- View создает action.
- Store меняет state.
- View обновляется из state.
- Redux - популярная реализация идей Flux.
