# Как настроить runtimeConfig, env и secrets Nuxt в Docker?

> [!NOTE]
> В Nuxt важно различать build-time env, runtime env и public env. Серверные секреты должны оставаться на Nitro/server стороне, а `NUXT_PUBLIC_*` попадает в клиентский код и виден пользователю.

## Пример `nuxt.config.ts`

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    databaseUrl: '',
    redisUrl: '',
    authSecret: '',

    public: {
      siteUrl: '',
      apiBase: '/api'
    }
  }
})
```

Эти значения можно переопределять env-переменными:

```env
NUXT_DATABASE_URL=postgresql://app:secret@db:5432/app
NUXT_REDIS_URL=redis://redis:6379
NUXT_AUTH_SECRET=dev-secret
NUXT_PUBLIC_SITE_URL=http://localhost:3000
NUXT_PUBLIC_API_BASE=/api
```

## Почему иногда нужен и `DATABASE_URL`, и `NUXT_DATABASE_URL`?

Prisma schema часто читает:

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

Nuxt runtimeConfig читает:

```ts
const config = useRuntimeConfig()
const databaseUrl = config.databaseUrl
```

Поэтому в Docker можно передать оба значения:

```yaml
environment:
  DATABASE_URL: postgresql://app:secret@db:5432/app
  NUXT_DATABASE_URL: postgresql://app:secret@db:5432/app
```

Так Prisma CLI и Nuxt runtime получают один и тот же connection string.

## Public env не является секретом

```env
NUXT_PUBLIC_SITE_URL=https://example.com
NUXT_PUBLIC_API_BASE=/api
```

Эти значения можно использовать на клиенте:

```ts
const config = useRuntimeConfig()
console.log(config.public.siteUrl)
```

Но сюда нельзя класть:

- database password;
- auth secret;
- Redis password;
- private API keys;
- OAuth client secret.

## `env_file` в Compose

```yaml
services:
  app:
    env_file:
      - .env
```

`.env`:

```env
NODE_ENV=production
NITRO_HOST=0.0.0.0
NITRO_PORT=3000
DATABASE_URL=postgresql://app:secret@db:5432/app
NUXT_DATABASE_URL=postgresql://app:secret@db:5432/app
NUXT_REDIS_URL=redis://redis:6379
NUXT_AUTH_SECRET=dev-secret
NUXT_PUBLIC_SITE_URL=http://localhost:3000
```

## Compose substitution и container env

Есть два разных механизма:

```text
.env рядом с compose.yaml -> подстановка ${VAR} в YAML
env_file/environment -> переменные внутри контейнера
```

Пример:

```yaml
services:
  app:
    image: my-nuxt:${APP_VERSION}
    environment:
      NUXT_PUBLIC_SITE_URL: ${NUXT_PUBLIC_SITE_URL}
```

`APP_VERSION` влияет на Compose YAML, а `NUXT_PUBLIC_SITE_URL` попадет в container env.

## Docker secrets

Для Compose можно передать secret как файл:

```yaml
services:
  app:
    secrets:
      - auth_secret
    environment:
      AUTH_SECRET_FILE: /run/secrets/auth_secret

secrets:
  auth_secret:
    file: ./secrets/auth_secret.txt
```

В коде нужно прочитать файл:

```ts
import { readFileSync } from 'node:fs'

export function readSecret(name: string) {
  const path = process.env[`${name}_FILE`]
  return path ? readFileSync(path, 'utf8').trim() : process.env[name]
}
```

## Где использовать runtimeConfig в Nitro route?

```ts
export default defineEventHandler(() => {
  const config = useRuntimeConfig()

  return {
    siteUrl: config.public.siteUrl,
    hasDatabaseUrl: Boolean(config.databaseUrl)
  }
})
```

Серверные поля runtimeConfig доступны только на сервере, public-поля доступны и на клиенте.

## Что отвечать на собеседовании?

В Nuxt Docker-проекте env делятся на runtime server env и public env. Секреты передаются в container через `environment`, `env_file`, secret manager или Docker secrets, а публичные значения идут через `NUXT_PUBLIC_*`. Для Prisma часто нужен `DATABASE_URL`, а для Nuxt runtimeConfig можно дополнительно передавать `NUXT_DATABASE_URL`.

## Частые ошибки

- Класть секреты в `NUXT_PUBLIC_*`.
- Думать, что `.env` всегда попадает внутрь контейнера.
- Использовать `localhost` в database URL внутри Compose.
- Менять runtime env и ждать, что уже запущенный container сам обновится.
- Встраивать production secrets во время `docker build`.
- Не валидировать env при старте приложения.

## Мини-шпаргалка

- Server config: `NUXT_DATABASE_URL`, `NUXT_AUTH_SECRET`.
- Public config: `NUXT_PUBLIC_*`.
- Prisma: часто нужен `DATABASE_URL`.
- Docker Compose service host: `db`, `redis`.
- Secrets не хранят в image.
- Public env виден в браузере.
