# Почему нельзя хранить промисы в состоянии?

> [!summary]
> В обычном client-side React state должен хранить данные для render, а не саму асинхронную операцию. Promise не сообщает React автоматически, что он завершился, плохо сериализуется и часто приводит к side effects в render.

## Плохой пример

```jsx
function UserPage() {
  const [userPromise] = useState(fetch('/api/user'))

  return <div>{String(userPromise)}</div>
}
```

В state лежит не пользователь, а Promise. React не узнает сам, когда Promise resolved, и не превратит его в данные для UI.

## Еще опаснее: then в render

```jsx
function UserPage() {
  const [user, setUser] = useState(null)
  const promise = fetch('/api/user')

  promise.then((data) => setUser(data)) // плохо

  return <div>{user?.name}</div>
}
```

Это side effect во время render. Он может запускаться много раз и создавать бесконечные запросы.

## Что хранить вместо Promise?

Обычно хранят результат и статус:

```jsx
const [user, setUser] = useState(null)
const [status, setStatus] = useState('idle')
const [error, setError] = useState(null)
```

И обновляют их после выполнения запроса:

```jsx
useEffect(() => {
  let ignore = false

  async function loadUser() {
    try {
      setStatus('loading')
      const data = await fetchUser()

      if (!ignore) {
        setUser(data)
        setStatus('success')
      }
    } catch (error) {
      if (!ignore) {
        setError(error)
        setStatus('error')
      }
    }
  }

  loadUser()

  return () => {
    ignore = true
  }
}, [])
```

## А как же Suspense и use?

В React есть механизмы, где Promise участвует в render-модели: Suspense-enabled data sources и API `use`. Но это не означает, что Promise надо просто класть в `useState`.

Для обычных клиентских запросов безопаснее использовать:

- `useEffect` + state;
- TanStack Query;
- SWR;
- framework loaders;
- Server Components.

## Почему Promise в state неудобен?

- нельзя удобно показать loading/error/result;
- трудно отменять;
- трудно дедуплицировать;
- сложно тестировать;
- плохо для DevTools и сериализации;
- легко получить stale result.

## Мини-шпаргалка

- State хранит данные для UI, а не "обещание данных".
- Promise completion сам по себе не вызывает render.
- Не вызывай `.then(setState)` во время render.
- Для server state используй query cache или effect.
- Suspense - отдельная интеграционная модель, а не повод хранить Promise в state.
