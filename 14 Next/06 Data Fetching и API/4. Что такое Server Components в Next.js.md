# Что такое Server Components в Next.js?

> [!summary]
> Server Components в Next.js - компоненты React, которые выполняются на сервере и могут получать данные без клиентского `useEffect`. В App Router они используются по умолчанию и особенно важны для data fetching, SEO и уменьшения JS bundle.

## Почему они важны для data fetching?

Server Component может быть async:

```tsx
export default async function Page() {
  const users = await db.user.findMany()

  return <UserList users={users} />
}
```

Это устраняет типичный client waterfall:

```text
HTML -> JS -> useEffect -> fetch -> render data
```

Вместо этого:

```text
server fetch -> HTML with data -> hydration only where needed
```

## Что можно делать?

- получать данные из API;
- читать БД;
- использовать ORM;
- читать `process.env`;
- работать с cookies/headers через Next APIs;
- рендерить SEO-контент.

## Что нельзя?

- `useState`;
- `useEffect`;
- `onClick`;
- `window`;
- `localStorage`;
- browser-only SDK.

## Server Component не равен API endpoint

Server Component возвращает UI, а Route Handler возвращает HTTP response.

```tsx
// Server Component
return <UserList users={users} />
```

```ts
// Route Handler
return Response.json(users)
```

## Что отвечать на собеседовании?

Server Components позволяют получать данные на сервере прямо в компоненте и не отправлять код этого компонента в браузер. В Next.js App Router это базовая модель для страниц, layouts и статичного/серверного UI.

## Частые ошибки

- Считать Server Component endpoint'ом.
- Использовать client hooks.
- Создавать лишний `/api` route для запроса из Server Component.
- Передавать несериализуемые props в Client Component.
- Путать Server Components и SSR.

## Мини-шпаргалка

- Server Components по умолчанию в `app`.
- Можно `await` данные.
- Код не попадает в client bundle.
- Хороши для SEO.
- Для интерактива нужен Client Component.
- Endpoint создается через `route.ts`, не Server Component.
