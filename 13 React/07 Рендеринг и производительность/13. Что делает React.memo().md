# Что делает React.memo()?

> [!summary]
> `React.memo` запоминает результат render функционального компонента и пропускает повторный render, если props не изменились. Это оптимизация, а не способ исправить архитектуру или запретить обновления навсегда.

## Простое определение

```jsx
const MemoizedComponent = memo(Component)
```

Если родитель рендерится снова, React сравнит предыдущие props и новые props. Если они равны, компонент можно не вызывать повторно.

```jsx
import { memo } from 'react'

const UserName = memo(function UserName({ name }) {
  console.log('render UserName')
  return <span>{name}</span>
})
```

## Что будет без memo?

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  return (
    <>
      <button onClick={() => setCount(count + 1)}>{count}</button>
      <UserName name="Ada" />
    </>
  )
}
```

Когда `Parent` обновляется, React заново вызывает его дочернее дерево. Если `UserName` легкий, это нормально. Если он дорогой или таких компонентов сотни, `memo` может помочь.

## Как сравниваются props?

По умолчанию `memo` использует поверхностное сравнение через `Object.is`.

```jsx
memo(UserCard)
```

Примитивы сравниваются ожидаемо:

```jsx
<UserCard name="Ada" age={36} />
```

А объекты, массивы и функции сравниваются по ссылке:

```jsx
<UserCard user={{ name: 'Ada' }} /> // новая ссылка на каждом render
```

Чтобы `memo` был полезен, такие props часто стабилизируют:

```jsx
const user = useMemo(() => ({ name: 'Ada' }), [])
const onSelect = useCallback(() => selectUser(user.id), [user.id])

return <UserCard user={user} onSelect={onSelect} />
```

## Можно ли задать свое сравнение?

Да, вторым аргументом:

```jsx
const ProductRow = memo(
  function ProductRow({ product }) {
    return <div>{product.title}</div>
  },
  (prevProps, nextProps) => {
    return prevProps.product.id === nextProps.product.id &&
      prevProps.product.updatedAt === nextProps.product.updatedAt
  },
)
```

Но custom compare надо писать осторожно. Если пропустить важный prop, UI может показывать устаревшие данные.

## Что memo не предотвращает?

Компонент все равно обновится, если:

- изменился его собственный state;
- изменился context, который компонент читает;
- изменился external store, на который он подписан;
- изменился `key`;
- React выполняет дополнительный development render в Strict Mode.

## Мини-шпаргалка

- `memo` оптимизирует функциональный компонент по props.
- Сравнение по умолчанию поверхностное.
- Новые объекты и функции ломают мемоизацию.
- `memo` не защищает от обновлений state/context.
- Применяй после измерений или на явно дорогих компонентах.
