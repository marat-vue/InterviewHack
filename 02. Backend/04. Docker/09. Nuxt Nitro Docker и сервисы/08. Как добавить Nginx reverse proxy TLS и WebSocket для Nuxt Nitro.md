# Как добавить Nginx reverse proxy, TLS и WebSocket для Nuxt Nitro?

> [!NOTE]
> Nginx перед Nuxt/Nitro нужен как публичная точка входа: TLS termination, proxy headers, сжатие, лимиты body, routing и единый порт наружу. Сам Nuxt/Nitro остается внутренним service на `app:3000`.

## Compose с Nginx

```yaml
services:
  nginx:
    image: nginx:1.29-alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./docker/nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
      - ./docker/nginx/certs:/etc/nginx/certs:ro
    depends_on:
      app:
        condition: service_started
    restart: unless-stopped

  app:
    build: .
    expose:
      - "3000"
    environment:
      NITRO_HOST: 0.0.0.0
      NITRO_PORT: 3000
```

`expose` документирует внутренний порт для Docker-сети, но не публикует его на host.

## Nginx config для Nuxt/Nitro

```nginx
upstream nuxt_app {
  server app:3000;
}

server {
  listen 80;
  server_name example.com;

  client_max_body_size 10m;

  location / {
    proxy_pass http://nuxt_app;
    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
```

Для WebSocket важны:

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

## HTTPS termination

Пример с сертификатами:

```nginx
server {
  listen 443 ssl http2;
  server_name example.com;

  ssl_certificate /etc/nginx/certs/fullchain.pem;
  ssl_certificate_key /etc/nginx/certs/privkey.pem;

  location / {
    proxy_pass http://nuxt_app;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

В production сертификаты часто выдает load balancer, Traefik, Caddy, cloud provider или certbot sidecar. Главное, чтобы Nuxt/Nitro получал корректные forwarded headers.

## Static assets

Nuxt/Nitro сам умеет отдавать `.output/public`. Обычно достаточно проксировать все в app.

Если хочется отдельно кешировать assets:

```nginx
location /_nuxt/ {
  proxy_pass http://nuxt_app;
  proxy_set_header Host $host;
  add_header Cache-Control "public, max-age=31536000, immutable";
}
```

Не ставь aggressive cache на HTML, API и user-specific responses.

## API routing

Если Nuxt и backend API в одном Nitro-приложении:

```text
/api/* -> тот же app:3000
```

Если API отдельный:

```nginx
location /api/ {
  proxy_pass http://api:4000/;
}

location / {
  proxy_pass http://nuxt_app;
}
```

Важно не потерять trailing slash semantics в `proxy_pass`.

## Что отвечать на собеседовании?

Nginx в Docker Compose часто ставят перед Nuxt/Nitro как reverse proxy. Наружу открываются `80/443`, а Nuxt service остается внутри Docker network на `app:3000`. Nginx передает `Host`, `X-Forwarded-*` headers, поддерживает WebSocket upgrade и может завершать TLS. Postgres и Redis при этом наружу не публикуются.

## Частые ошибки

- Проксировать на `localhost:3000` из Nginx container.
- Не передавать `X-Forwarded-Proto`.
- Забыть WebSocket `Upgrade` headers.
- Кешировать HTML как immutable asset.
- Публиковать и Nginx, и app port наружу без причины.
- Не задать `client_max_body_size` для upload-сценариев.

## Мини-шпаргалка

- Nginx -> `app:3000`.
- App listens -> `0.0.0.0:3000`.
- Public ports -> `80`, `443`.
- WebSocket -> `Upgrade` and `Connection`.
- Forwarded headers -> `Host`, `X-Forwarded-*`.
- DB/Redis -> internal only.
