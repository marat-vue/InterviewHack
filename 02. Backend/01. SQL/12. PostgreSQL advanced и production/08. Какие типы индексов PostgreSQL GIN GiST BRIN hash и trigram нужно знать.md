# Какие типы индексов PostgreSQL GIN, GiST, BRIN, hash и trigram нужно знать?

> [!NOTE]
> B-tree - default, но PostgreSQL имеет несколько типов индексов под разные операторы и данные. Правильный индекс зависит не от колонки, а от запроса и operator class.

## B-tree

Default индекс:

```sql
CREATE INDEX users_email_idx ON users (email);
```

Подходит для:

- equality;
- range;
- sorting;
- prefix-like patterns при подходящих условиях.

## GIN

GIN хорош для composite values:

- `jsonb`;
- arrays;
- full-text search;
- trigram search.

```sql
CREATE INDEX events_payload_gin_idx ON events USING gin (payload);
```

Для JSONB:

```sql
SELECT *
FROM events
WHERE payload @> '{"type": "user.created"}';
```

## GiST

GiST полезен для:

- geometric data;
- ranges;
- exclusion constraints;
- full-text search в некоторых cases.

```sql
CREATE INDEX bookings_period_gist_idx ON bookings USING gist (period);
```

## BRIN

BRIN хранит summary по ranges страниц. Хорош для огромных таблиц, где данные физически упорядочены:

- time-series;
- append-only events;
- logs by timestamp.

```sql
CREATE INDEX events_created_at_brin_idx ON events USING brin (created_at);
```

BRIN маленький и дешевый, но не заменяет B-tree для точечных lookup.

## Hash index

Hash index подходит для equality, но B-tree часто достаточно. Используй hash index только если понимаешь, почему B-tree не подходит.

```sql
CREATE INDEX users_external_id_hash_idx ON users USING hash (external_id);
```

## Trigram index

Через extension:

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE INDEX users_name_trgm_idx
ON users USING gin (name gin_trgm_ops);
```

Полезно для:

```sql
WHERE name ILIKE '%mar%'
```

## Мини-шпаргалка

- B-tree - default.
- GIN - JSONB, arrays, full-text, trigram.
- GiST - ranges/geo/exclusion.
- BRIN - огромные append-only/time-series таблицы.
- Trigram - быстрый fuzzy/substring search.
- Индекс выбирают под оператор и запрос.
