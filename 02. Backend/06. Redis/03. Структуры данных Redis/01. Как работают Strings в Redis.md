# Как работают Strings в Redis?

> [!NOTE]
> String - самый простой и самый универсальный тип Redis. Это binary-safe значение до большого размера, которое используют для cache, tokens, counters, serialized JSON и locks.

## Когда использовать String?

String подходит для:

- cache entry;
- access token / reset token;
- feature flag;
- counter;
- lock value;
- small serialized JSON;
- idempotency result;
- last seen timestamp.

## Базовые команды

```redis
SET user:1:name Marat
GET user:1:name
DEL user:1:name
```

С TTL:

```redis
SET cache:product:42 '{"id":42,"name":"Keyboard"}' EX 300
```

Только если ключа нет:

```redis
SET lock:job:42 worker-1 NX PX 30000
```

## Counters

```redis
INCR views:post:42
DECR stock:product:42
INCRBY balance:user:1 100
DECRBY balance:user:1 30
```

`INCR` и `DECR` атомарны. Это делает strings удобными для rate limiting и счетчиков.

## Multiple keys

```redis
MSET user:1:name Marat user:1:role admin
MGET user:1:name user:1:role
```

В Redis Cluster multi-key команды требуют, чтобы ключи были в одном hash slot. Для этого используют hash tags:

```txt
user:{1}:name
user:{1}:role
```

## Node.js пример

```ts
await redis.set('cache:user:1', JSON.stringify({
  id: '1',
  email: 'admin@example.com',
}), {
  EX: 60 * 5,
});

const raw = await redis.get('cache:user:1');
const user = raw ? JSON.parse(raw) : null;
```

## Когда String хуже Hash?

Если нужно часто обновлять отдельные поля:

```txt
user:1 -> JSON string
```

может быть хуже, чем:

```txt
user:1 -> hash { email, name, role }
```

Потому что для JSON string нужно прочитать весь объект, распарсить, изменить и записать обратно.

## Мини-шпаргалка

- `GET`/`SET` - базовые операции.
- `SET EX` - cache/session/token.
- `SET NX PX` - lock.
- `INCR`/`DECR` - атомарные counters.
- String хорош для small values.
- Для частичных обновлений лучше Hash или RedisJSON.
