# Как настраивать meta tags в SPA и SSR?

> [!summary]
> Meta tags должны соответствовать конкретной странице, а не всему приложению. В frontend-проектах важно, где и когда они появляются: в исходном HTML, после SSR или только после клиентского JavaScript.

## Какие meta tags нужны чаще всего?

```html
<title>SEO аудит сайта: чеклист и примеры</title>
<meta name="description" content="Пошаговый SEO-аудит: индексация, скорость, structured data и контент.">
<link rel="canonical" href="https://example.com/seo-audit">

<meta property="og:title" content="SEO аудит сайта">
<meta property="og:description" content="Чеклист и примеры технического SEO-аудита.">
<meta property="og:image" content="https://example.com/og/seo-audit.png">
```

## В чем проблема SPA?

В SPA исходный HTML часто один:

```html
<title>App</title>
<div id="app"></div>
```

Потом JavaScript меняет title и meta. Для соцсетей, мессенджеров и некоторых ботов это может быть проблемой, потому что они не всегда выполняют JS как браузер.

## Как лучше в SSR?

SSR должен вернуть готовый `<head>`:

```html
<title>Купить ноутбук Apple MacBook Pro 14</title>
<meta name="description" content="Цена, характеристики и наличие MacBook Pro 14.">
<link rel="canonical" href="https://shop.example.com/laptops/macbook-pro-14">
```

Так страница понятна сразу.

## Что проверять?

- Уникальный title.
- Уникальный description.
- Canonical для текущего URL.
- Open Graph для шаринга.
- Отсутствие старых meta после client navigation.
- Корректный `noindex` для закрытых страниц.

## Мини-шпаргалка

- Meta tags должны быть уникальными для важных страниц.
- SSR/SSG надежнее для публичных страниц.
- В SPA проверяй, что head обновляется при навигации.
- Canonical должен совпадать с основной версией URL.
- Open Graph важен для ссылок в соцсетях и мессенджерах.
