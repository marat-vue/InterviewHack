# Как создать singleton Redis client и lifecycle подключения?

> [!NOTE]
> Redis client не нужно создавать на каждый request. В Node.js обычно создают один shared client на процесс и закрывают его при graceful shutdown.

## Почему не создавать client на каждый request?

Плохо:

```ts
app.get('/api/users/:id', async () => {
  const redis = createClient({
    url: process.env.REDIS_URL,
  });

  await redis.connect();
});
```

Риски:

- много TCP connections;
- connection leaks;
- большая latency;
- Redis `maxclients` exhaustion;
- сложнее error handling.

## Singleton module

```ts
// redis.ts
import { createClient } from 'redis';

export const redis = createClient({
  url: process.env.REDIS_URL,
});

redis.on('error', (error) => {
  console.error('Redis error', error);
});

export async function connectRedis() {
  if (!redis.isOpen) {
    await redis.connect();
  }
}

export async function closeRedis() {
  if (redis.isOpen) {
    await redis.quit();
  }
}
```

## App bootstrap

```ts
await connectRedis();

app.listen(3000);
```

## Graceful shutdown

```ts
process.on('SIGTERM', async () => {
  await closeRedis();
  process.exit(0);
});

process.on('SIGINT', async () => {
  await closeRedis();
  process.exit(0);
});
```

## Нужно ли отдельное подключение для Pub/Sub?

Да. Subscriber connection после `SUBSCRIBE` нельзя использовать как обычный command connection.

```ts
export const publisher = redis.duplicate();
export const subscriber = redis.duplicate();

await publisher.connect();
await subscriber.connect();
```

## Что делать в serverless?

В serverless средах lifecycle отличается:

- можно переиспользовать client между warm invocations;
- cold starts создают новый client;
- нужно следить за connection count;
- иногда нужен managed/serverless-friendly Redis provider;
- connection pooling для Redis не такой, как для SQL, но max clients все равно важен.

## Мини-шпаргалка

- Один Redis client на процесс для обычных команд.
- Отдельный client для Pub/Sub subscriber.
- Подключайся на bootstrap.
- Закрывайся на shutdown.
- Не создавай client на каждый request.
