# Как управлять pagination, filters и сортировками?

> [!summary]
> Pagination, filters и сортировки помогают пользователю изучать каталог, но могут создавать дубли и бесконечные URL. SEO-задача - отделить полезные посадочные страницы от технических состояний интерфейса.

## Pagination

Страницы пагинации могут быть индексируемыми, если на них есть уникальный список элементов:

```text
/blog?page=2
/catalog/laptops?page=3
```

Обычно каждая страница пагинации имеет self-canonical:

```html
<link rel="canonical" href="https://example.com/blog?page=2">
```

## Filters

Фильтры бывают полезными и техническими.

Полезно:

```text
/laptops/apple
/laptops/gaming
```

Технически:

```text
/laptops?sort=price&page=9&view=grid
```

## Sorting

Сортировки обычно не нужно индексировать:

```text
?sort=price_asc
?sort=popular
```

Они меняют порядок, а не создают новую смысловую страницу.

## Что использовать?

| Сценарий | Решение |
|---|---|
| Полезный фильтр со спросом | отдельный URL, index, canonical на себя |
| Сортировка | canonical на основную страницу или noindex |
| Session/query params | canonical без параметров |
| Бесконечные комбинации | noindex/robots/ограничение ссылок |
| Пагинация | чаще self-canonical |

## Мини-шпаргалка

- Не каждый filter URL достоин индекса.
- Сортировка обычно не создает новую SEO-страницу.
- Пагинацию нельзя бездумно canonical на первую страницу.
- Внутренние ссылки должны вести на полезные фильтры.
- Решение зависит от спроса и качества страницы.
