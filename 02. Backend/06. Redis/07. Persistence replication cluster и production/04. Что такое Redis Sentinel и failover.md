# Что такое Redis Sentinel и failover?

> [!NOTE]
> Redis Sentinel обеспечивает monitoring, notification и automatic failover для Redis primary/replica setup. Это HA-слой для Redis без Cluster sharding.

## Зачем Sentinel?

Sentinel нужен, чтобы:

- следить за primary;
- обнаруживать падение;
- выбрать replica;
- promoted replica сделать новым primary;
- сообщить clients новый address;
- помогать с high availability.

## Архитектура

```txt
Sentinel 1
Sentinel 2 -> monitors Redis primary + replicas
Sentinel 3
```

Несколько Sentinel instances нужны для quorum и устойчивости.

## Что такое failover?

Failover:

1. Sentinel замечает, что primary недоступен.
2. Sentinels достигают quorum.
3. Выбирается replica.
4. Replica становится primary.
5. Остальные replicas переключаются на новый primary.
6. Clients переподключаются.

## Что важно для приложения?

Клиент должен уметь работать с Sentinel:

- узнавать текущий primary;
- переподключаться после failover;
- не держать навсегда старый address;
- корректно retry-ить операции.

## Sentinel или Cluster?

| Требование | Выбор |
|---|---|
| HA без sharding | Sentinel |
| Dataset помещается на один primary | Sentinel |
| Нужно sharding по узлам | Cluster |
| Нужно horizontal scaling writes | Cluster |

## Ограничения

- failover не мгновенный;
- возможна потеря последних async writes;
- clients должны поддерживать Sentinel;
- нужно минимум несколько Sentinel processes;
- network partitions требуют аккуратной настройки quorum.

## Мини-шпаргалка

- Sentinel = HA/failover.
- Sentinel не sharding.
- Нужны несколько Sentinel instances.
- Clients должны поддерживать discovery primary.
- Async replication значит, что последние writes могут потеряться.
