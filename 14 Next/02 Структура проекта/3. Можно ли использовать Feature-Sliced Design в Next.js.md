# Можно ли использовать Feature-Sliced Design в Next.js?

> [!summary]
> Да, FSD можно использовать в Next.js, но важно разделить зоны ответственности: `app` отвечает за роутинг и композицию страниц, а FSD-слои (`shared`, `entities`, `features`, `widgets`) хранят бизнес-логику, UI и переиспользуемые модули.

## Главный принцип

`app` - это routing layer, а не место для всей бизнес-логики.

Хороший вариант:

```text
src/
  app/
    (public)/
      page.tsx
    dashboard/
      page.tsx
      layout.tsx
  shared/
    ui/
    api/
    lib/
  entities/
    user/
    product/
  features/
    add-to-cart/
    update-profile/
  widgets/
    header/
    product-list/
```

## Как выглядит page.tsx?

`page.tsx` собирает страницу из widgets/features:

```tsx
import { ProductList } from '@/widgets/product-list'
import { getProducts } from '@/entities/product/api'

export default async function ProductsPage() {
  const products = await getProducts()

  return <ProductList products={products} />
}
```

Страница не должна превращаться в огромный компонент на тысячу строк.

## Где хранить Server Actions?

Варианты:

```text
features/update-profile/actions.ts
entities/product/api.ts
app/dashboard/actions.ts
```

Главное правило: action должна лежать там, где ее проще понимать и защищать. Для переиспользуемой бизнес-операции лучше `features` или `entities`, для route-specific действия можно оставить рядом с route.

## Server и Client Components в FSD

Client Component помечают явно:

```tsx
'use client'

export function AddToCartButton() {
  return <button>Add to cart</button>
}
```

Не ставь `'use client'` на весь `widgets` или `app` без необходимости. Лучше держать client boundary как можно ниже.

## Что отвечать на собеседовании?

FSD совместим с Next.js, если `app` использовать как слой маршрутизации и композиции, а бизнес-модули держать в FSD-слоях. Важно учитывать Server/Client boundaries: server-only код не должен импортироваться в Client Components.

## Частые ошибки

- Класть весь проект в `app`.
- Делать `page.tsx` огромной бизнес-страницей.
- Ставить `'use client'` слишком высоко.
- Импортировать server-only код в client module.
- Смешивать route groups и FSD слои без соглашений.

## Мини-шпаргалка

- `app` - routes и composition.
- `shared` - общий UI/lib/api.
- `entities` - бизнес-сущности.
- `features` - пользовательские действия.
- `widgets` - крупные UI-блоки.
- Client boundary держи ниже.
