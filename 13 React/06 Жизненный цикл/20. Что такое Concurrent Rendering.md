# Что такое Concurrent Rendering?

> [!summary]
> Concurrent Rendering - это способность React готовить несколько версий UI, прерывать менее срочную render-работу и отдавать приоритет более важным обновлениям. Это внутренняя модель, которая делает возможными transitions, Suspense и более отзывчивый интерфейс.

## Простое объяснение

Concurrent Rendering не значит, что JavaScript выполняется в нескольких потоках.

Правильнее:

```text
React может планировать render-работу, разбивать ее на части и выбирать, что важнее сделать сейчас.
```

Например:

```text
пользователь печатает в input
одновременно обновляется тяжелый список
React сначала сохраняет отзывчивость input
```

## Что concurrent rendering дает?

- interruptible render;
- приоритет срочных обновлений;
- transitions;
- плавную работу тяжелого UI;
- подготовку UI в фоне;
- лучшую интеграцию с Suspense.

## Render vs commit

Concurrent поведение относится в первую очередь к render phase.

Commit phase должен применить готовый результат к DOM согласованно. Пользователь не должен видеть "половину" нового UI.

## Как включается?

В React 18+ concurrent-возможности доступны через современный root:

```jsx
import { createRoot } from 'react-dom/client'

createRoot(document.getElementById('root')).render(<App />)
```

Но конкретные эффекты проявляются через APIs вроде `useTransition`, Suspense, deferred values.

## Частые заблуждения

- Concurrent Rendering не делает CPU быстрее.
- Это не Web Workers.
- Это не значит, что все renders параллельны.
- Это не освобождает от оптимизации тяжелых компонентов.
- Нельзя делать side effects в render.

## Мини-шпаргалка

- Concurrent Rendering - планирование и прерывание render-работы.
- JavaScript остается однопоточным в обычном React-коде.
- Срочные updates могут перебить менее срочные.
- Commit применяет только готовый UI.
- Чистый render обязателен.
