# Почему `[] == false`

> [!NOTE] Коротко
> `[] == false` возвращает `true`, потому что `==` запускает цепочку неявных преобразований: `false` превращается в `0`, пустой массив превращается в `""`, а пустая строка превращается в `0`.

## Вопрос

Почему `[] == false` возвращает `true`?

## Результат

```javascript
[] == false;  // true
[] === false; // false
```

Строгое сравнение сразу говорит `false`, потому что массив и boolean - разные типы.

Нестрогое сравнение пытается привести типы.

## Разбор по шагам

Исходное выражение:

```javascript
[] == false
```

### Шаг 1. Boolean превращается в number

```javascript
false -> 0
```

Получаем:

```javascript
[] == 0
```

### Шаг 2. Массив превращается в primitive

Для массива вызывается преобразование к примитиву. Пустой массив превращается в пустую строку.

```javascript
[].toString(); // ""
```

Получаем:

```javascript
"" == 0
```

### Шаг 3. Строка превращается в number

```javascript
Number(""); // 0
```

Получаем:

```javascript
0 == 0 // true
```

## Почему это важно

Пустой массив сам по себе truthy:

```javascript
Boolean([]); // true

if ([]) {
  console.log("Сработает");
}
```

Но при `== false` он становится равен `false` из-за правил сравнения.

```javascript
Boolean([]); // true
[] == false; // true
```

Это хороший пример того, почему `==` может сбивать с толку.

## Как писать понятнее

Проверка на пустой массив:

```javascript
const items = [];

if (items.length === 0) {
  console.log("Массив пустой");
}
```

Проверка, что значение является массивом:

```javascript
Array.isArray(items);
```

## Мини-шпаргалка

```javascript
[] == false;       // true
[] === false;      // false
Boolean([]);       // true
[].toString();     // ""
Number("");        // 0
```
