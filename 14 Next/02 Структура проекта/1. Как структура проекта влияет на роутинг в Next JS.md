# Как структура проекта влияет на роутинг в Next JS?

> [!summary]
> В App Router структура папки `app` напрямую формирует маршруты. Каждая папка становится route segment, а специальные файлы вроде `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx` и `route.ts` задают поведение сегмента.

## Главный принцип

В Next.js нет отдельного центрального файла routes. URL строится из папок.

```text
app/
  page.tsx
  about/
    page.tsx
  blog/
    [slug]/
      page.tsx
```

Результат:

- `app/page.tsx` -> `/`;
- `app/about/page.tsx` -> `/about`;
- `app/blog/[slug]/page.tsx` -> `/blog/:slug`.

## Что такое route segment?

Каждая папка внутри `app` - сегмент маршрута:

```text
app/dashboard/settings/page.tsx
```

URL:

```text
/dashboard/settings
```

`dashboard` и `settings` - route segments.

## Специальные файлы

| Файл | Что делает |
|---|---|
| `page.tsx` | создает публичную страницу |
| `layout.tsx` | общая оболочка сегмента |
| `template.tsx` | оболочка, которая перемонтируется |
| `loading.tsx` | loading UI для Suspense |
| `error.tsx` | error boundary сегмента |
| `global-error.tsx` | глобальная ошибка всего app |
| `not-found.tsx` | 404 UI |
| `route.ts` | HTTP endpoint |

## Файлы без page.tsx не создают URL

```text
app/
  dashboard/
    layout.tsx
    settings/
      page.tsx
```

Если в `dashboard` нет `page.tsx`, то `/dashboard` может не существовать как страница, но layout применится к `/dashboard/settings`.

## Что отвечать на собеседовании?

В App Router структура `app` является картой маршрутов. Папки задают URL-сегменты, `page.tsx` создает страницу, `layout.tsx` задает обертку, а специальные файлы позволяют описывать загрузку, ошибки, 404 и HTTP endpoints на уровне конкретного сегмента.

## Частые ошибки

- Думать, что любая папка сразу создает страницу.
- Забывать `page.tsx`.
- Класть route-only файлы в FSD-слои вне `app`.
- Путать `route.ts` и `page.tsx`.
- Создавать конфликтующие routes через route groups.

## Мини-шпаргалка

- `app` управляет роутингом.
- Папка = route segment.
- `page.tsx` = публичная страница.
- `layout.tsx` = shell для сегмента.
- `[id]` = dynamic segment.
- `(group)` = группировка без URL-сегмента.
