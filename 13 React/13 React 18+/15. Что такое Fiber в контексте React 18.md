# Что такое Fiber в контексте React 18?

> [!summary]
> Fiber - внутренняя архитектура React, которая представляет UI как дерево маленьких единиц работы. Благодаря Fiber React может разделять render на части, назначать приоритеты обновлениям, прерывать render-фазу и поддерживать concurrent features: transitions, Suspense, streaming SSR и selective hydration.

## Что такое Fiber простыми словами?

До Fiber React работал более синхронно: если начался render большого дерева, React должен был пройти его до конца. Пока это происходило, браузер мог хуже реагировать на ввод, клики и другие важные действия.

Fiber сделал render более управляемым. React может:

- разбить работу на небольшие шаги;
- поставить менее важную работу на паузу;
- обработать срочное обновление;
- выбросить устаревший render;
- начать render заново с более свежими данными.

## Что такое fiber-узел?

Fiber-узел - это внутренний объект React, который примерно соответствует компоненту или DOM-элементу в дереве.

Упрощенно:

```js
const fiber = {
  type: UserCard,
  key: 'user-42',
  child: null,
  sibling: null,
  return: null,
  pendingProps: {},
  memoizedProps: {},
  memoizedState: null,
  stateNode: null,
}
```

Это не публичный API. Его не нужно использовать в приложении напрямую, но полезно понимать идею: React хранит дерево UI в структуре, с которой можно работать постепенно.

## Render phase и commit phase

Fiber особенно важен из-за разделения на две фазы.

| Фаза | Что делает React | Можно ли прервать |
|---|---|---|
| render | вызывает компоненты, строит новое Fiber-дерево, сравнивает изменения | да |
| commit | применяет изменения к DOM, вызывает layout effects | нет |

Render-фаза должна быть чистой:

```jsx
function UserCard({ user }) {
  return <h2>{user.name}</h2>
}
```

Такой компонент можно безопасно вызвать несколько раз.

Плохой пример:

```jsx
function UserCard({ user }) {
  localStorage.setItem('lastUser', user.id)

  return <h2>{user.name}</h2>
}
```

Если React начнет render, потом прервет его и не сделает commit, побочный эффект уже случится. Поэтому побочные эффекты выносят в `useEffect`, `useLayoutEffect` или обработчики событий.

## Как Fiber связан с React 18?

React 18 сделал concurrent renderer доступным через новый root API:

```jsx
import { createRoot } from 'react-dom/client'

createRoot(document.getElementById('root')).render(<App />)
```

Именно Fiber позволяет этим возможностям работать:

| Возможность React 18+ | Как помогает Fiber |
|---|---|
| `useTransition` | низкоприоритетный render можно отложить |
| `startTransition` | React получает сигнал о несрочном update |
| `useDeferredValue` | часть UI может отставать без блокировки input |
| `Suspense` | дерево может ожидать код или данные на границе |
| automatic batching | несколько updates группируются перед render |
| selective hydration | React гидратирует важные части раньше |

## Пример: input и тяжелый список

```jsx
import { useState, useTransition } from 'react'

function Search({ items }) {
  const [query, setQuery] = useState('')
  const [visibleItems, setVisibleItems] = useState(items)
  const [isPending, startTransition] = useTransition()

  function handleChange(event) {
    const nextQuery = event.target.value

    setQuery(nextQuery)

    startTransition(() => {
      setVisibleItems(
        items.filter((item) =>
          item.title.toLowerCase().includes(nextQuery.toLowerCase()),
        ),
      )
    })
  }

  return (
    <>
      <input value={query} onChange={handleChange} />
      {isPending && <p>Обновляем результаты...</p>}
      <SearchResults items={visibleItems} />
    </>
  )
}
```

Срочное обновление `query` должно пройти быстро. Обновление списка может быть прервано, если пользователь продолжил ввод.

## Fiber не делает JavaScript многопоточным

Важная собеседовательная ловушка: Fiber не переносит render в отдельный поток.

Если внутри render есть тяжелая синхронная функция, она все еще блокирует main thread:

```jsx
function Report({ rows }) {
  const result = verySlowCalculation(rows)

  return <Chart data={result} />
}
```

Для настоящих CPU-bound задач нужны другие инструменты:

- оптимизация алгоритма;
- `useMemo` для предотвращения повторных расчетов;
- виртуализация списков;
- Web Worker;
- перенос вычислений на сервер.

## Что отвечать на собеседовании?

Fiber - это внутренняя архитектура React, в которой UI представлен как дерево единиц работы. Она позволяет React разделять render и commit, прерывать render-фазу, приоритизировать обновления и реализовывать concurrent features. Fiber не является публичным API и не означает многопоточность.

## Частые ошибки

- Думать, что Fiber - это Virtual DOM.
- Считать Fiber публичным API.
- Делать побочные эффекты в render-фазе.
- Ожидать, что Fiber ускорит любой тяжелый алгоритм.
- Путать interruptible render и synchronous commit.

## Мини-шпаргалка

- Fiber - внутренняя архитектура React.
- Fiber-узлы описывают работу по обновлению UI.
- Render-фазу можно прервать.
- Commit-фаза применяет изменения целостно.
- Fiber лежит в основе concurrent features.
