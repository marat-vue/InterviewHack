# Чем отличаются SSR, CSR, SSG, ISR и SWR?

> [!summary]
> SSR рендерит страницу на каждый request, CSR рендерит в браузере, SSG генерирует HTML на build-time, ISR обновляет статическую страницу после истечения времени, SWR быстро отдает stale cache и обновляет его в фоне.

## SSR

```text
Request -> server renders HTML -> response
```

Подходит для:

- динамического публичного контента;
- страниц с персонализацией;
- SEO-страниц, где данные часто меняются.

## CSR

```text
Browser получает shell -> JS рендерит UI
```

Подходит для:

- admin panels;
- закрытых dashboards;
- highly interactive app после login.

В Nuxt:

```ts
export default defineNuxtConfig({
  ssr: false,
});
```

## SSG

```text
Build time -> generate HTML files -> static hosting
```

Подходит для:

- blogs;
- документации;
- лендингов;
- страниц, которые редко меняются.

В Nuxt:

```bash
npm run generate
```

## ISR

ISR, Incremental Static Regeneration, позволяет кэшировать page response и пересобирать ее после TTL.

```ts
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': { isr: 3600 },
  },
});
```

Поддержка зависит от deployment platform/preset.

## SWR

SWR, stale-while-revalidate:

```text
Отдать stale cache быстро -> обновить cache в фоне
```

```ts
export default defineNuxtConfig({
  routeRules: {
    '/products/**': { swr: 300 },
  },
});
```

## Мини-шпаргалка

- SSR - render on request.
- CSR - render in browser.
- SSG - generate at build time.
- ISR - static cache with regeneration.
- SWR - stale cache now, refresh in background.
- Nuxt позволяет смешивать режимы через `routeRules`.
