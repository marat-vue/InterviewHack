# Как настроить тесты в CI pipeline?

> [!summary]
> CI pipeline должен быстро и надежно проверять качество: install, lint, typecheck, unit/component tests, build, backend integration tests, e2e и отчеты. Не все проверки обязаны запускаться на каждый commit, но критичные должны блокировать merge.

## Базовый pipeline

```bash
npm ci
npm run lint
npm run typecheck
npm run test:run
npm run build
```

Для большинства frontend-проектов это минимальный здоровый набор.

## Расширенный pipeline

```text
Pull request:
  lint
  typecheck
  unit/component tests
  build
  selected e2e

Main branch:
  full e2e
  Storybook build
  coverage report
  visual tests

Nightly:
  all browsers
  contract tests
  performance smoke
```

## Что параллелить?

Можно запускать параллельно:

- lint;
- typecheck;
- unit tests;
- build;
- Storybook build.

E2E тоже можно параллелить, но только при изолированных данных.

## Coverage в CI

Coverage report полезен, если:

- показывает diff coverage;
- не заставляет писать бессмысленные тесты;
- помогает видеть непокрытые критичные файлы;
- не является единственным quality gate.

## Артефакты

Сохраняй:

- coverage html;
- Playwright traces;
- screenshots/videos failures;
- Storybook static build;
- junit report, если нужен CI-интерфейсу.

## Мини-шпаргалка

- CI должен блокировать очевидно плохой код.
- Unit/component tests запускай на каждый PR.
- E2E можно делить на smoke и full suite.
- Артефакты помогают debug-ить падения.
- Чем медленнее проверка, тем аккуратнее выбирай частоту запуска.
