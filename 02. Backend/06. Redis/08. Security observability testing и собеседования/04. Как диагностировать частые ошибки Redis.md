# Как диагностировать частые ошибки Redis?

> [!NOTE]
> Redis-ошибки часто выглядят как случайная latency или HTTP 500 в приложении. Быстрая диагностика начинается с connectivity, auth, command type, memory, slowlog и client lifecycle.

## `ECONNREFUSED`

Причины:

- Redis не запущен;
- неправильный host/port;
- Docker network mismatch;
- firewall/security group;
- приложение внутри compose использует `localhost` вместо `redis`.

Проверка:

```bash
redis-cli -u "$REDIS_URL" PING
```

## `NOAUTH Authentication required`

Причины:

- Redis требует password;
- URL без credentials;
- неправильный username;
- provider changed credentials.

Проверка:

```bash
redis-cli -u redis://user:password@host:6379 PING
```

## `WRONGTYPE Operation against a key holding the wrong kind of value`

Причина: код ожидает один тип, а ключ уже создан с другим типом.

Проверка:

```redis
TYPE key
```

Решение:

- исправить key naming;
- удалить конфликтующий ключ;
- добавить namespace/version.

## `OOM command not allowed`

Причина: Redis достиг memory limit и eviction policy не может освободить память.

Проверка:

```redis
INFO memory
CONFIG GET maxmemory-policy
```

Решение:

- добавить TTL;
- увеличить memory;
- поменять eviction policy;
- удалить big keys;
- исправить cache pollution.

## Высокая latency

Проверка:

```redis
SLOWLOG GET 20
INFO clients
INFO memory
```

Ищи:

- `KEYS`;
- big `HGETALL`;
- huge `LRANGE`;
- Lua scripts;
- blocked clients;
- persistence fork spikes.

## `MOVED` или `CROSSSLOT`

Это Redis Cluster:

- client должен быть cluster-aware;
- multi-key operations должны попадать в один hash slot;
- используй hash tags `{...}`.

## Мини-шпаргалка

- Connectivity: `PING`.
- Auth: проверь URL/user/password.
- Type error: `TYPE key`.
- Memory: `INFO memory`.
- Slow commands: `SLOWLOG GET`.
- Cluster errors: hash slots и cluster-aware client.
