# Как браузер отправляет cookies и credentials?

> [!summary]
> Browser отправляет cookies автоматически, если совпадают правила cookie и настройки request. Для `fetch` на cross-origin запросах важно явно указать `credentials: 'include'`, а server должен корректно настроить CORS.

## Same-origin request

Если frontend и API на одном origin:

```txt
https://app.example.com -> https://app.example.com/api/me
```

Browser обычно отправит подходящие cookies автоматически.

## Cross-origin request

Если frontend и API на разных origins:

```txt
https://app.example.com -> https://api.example.com/me
```

Для `fetch` нужно:

```ts
fetch('https://api.example.com/me', {
  credentials: 'include',
});
```

Без этого browser может не отправить cookies в cross-origin request.

## Что должен вернуть server?

```http
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
```

Если используются credentials, нельзя ставить:

```http
Access-Control-Allow-Origin: *
```

Нужно указать конкретный origin.

## Credentials - это не только cookies

В browser context credentials могут включать:

- cookies;
- TLS client certificates;
- HTTP authentication credentials.

Bearer token в `Authorization` header ты обычно добавляешь вручную, но CORS все равно может потребовать preflight.

## Мини-шпаргалка

- Browser сам решает, какие cookies подходят request.
- Для cross-origin `fetch` с cookies нужен `credentials: 'include'`.
- Server должен вернуть `Access-Control-Allow-Credentials: true`.
- С credentials нельзя использовать wildcard `*` для allowed origin.
- `SameSite=None` требует `Secure`.
