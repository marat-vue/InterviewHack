# Что такое реляционная база данных?

> [!NOTE]
> Реляционная база данных хранит данные в таблицах, где строки описывают сущности или факты, столбцы описывают свойства, а связи между таблицами задаются ключами и ограничениями.

## Таблица

Таблица похожа на строго описанную коллекцию объектов.

```sql
CREATE TABLE users (
  id bigint PRIMARY KEY,
  email text NOT NULL,
  created_at timestamp NOT NULL
);
```

Каждая строка - один пользователь, каждый столбец - свойство пользователя.

## Отношения

Реляционная модель хороша тем, что данные можно связывать.

```sql
CREATE TABLE orders (
  id bigint PRIMARY KEY,
  user_id bigint REFERENCES users(id),
  total numeric(10, 2) NOT NULL
);
```

`orders.user_id` указывает на `users.id`.

## Почему не хранить все в одной таблице?

Одна огромная таблица приводит к дублированию, аномалиям обновления и слабой целостности.

```txt
orders: user_email, user_name, product_name, product_price, ...
```

Если email пользователя изменится, его придется обновлять во многих строках.

## Мини-шпаргалка

- Реляционная БД хранит данные в таблицах.
- Строка - запись.
- Столбец - атрибут.
- Связи задаются ключами.
- Нормальная модель данных уменьшает дублирование.
