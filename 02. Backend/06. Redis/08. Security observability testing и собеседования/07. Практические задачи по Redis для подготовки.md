# Практические задачи по Redis для подготовки

> [!NOTE]
> Redis лучше учить руками. Эти задачи покрывают основные backend-сценарии: cache, rate limit, sessions, locks, queues, Streams, Pub/Sub и observability.

## Задача 1: cache-aside

Сделай функцию:

```ts
getUser(userId: string)
```

Требования:

- сначала `GET cache:user:<id>`;
- при miss прочитать fake DB;
- записать cache с TTL 5 минут;
- при update удалить cache.

## Задача 2: fixed window rate limiter

Сделай middleware:

```txt
100 requests / minute / IP
```

Команды:

```redis
INCR
EXPIRE
TTL
```

Усложнение: отдельный limit для `/login`.

## Задача 3: leaderboard

Используй Sorted Set:

```redis
ZADD
ZINCRBY
ZRANGE REV WITHSCORES
ZREVRANK
```

Нужно:

- добавить score;
- получить top-10;
- получить rank пользователя.

## Задача 4: lock для cache rebuild

Используй:

```redis
SET lock:key token NX PX 30000
```

Release через Lua compare-and-delete.

## Задача 5: Pub/Sub notifications

Сделай:

- publisher;
- subscriber;
- два Node.js процесса;
- проверку, что сообщение приходит обоим subscribers.

## Задача 6: Streams worker

Сделай:

- `XADD jobs`;
- `XGROUP CREATE`;
- worker через `XREADGROUP`;
- `XACK`;
- обработку pending через `XAUTOCLAIM`.

## Задача 7: Docker Compose

Собери compose:

- Node.js API;
- Redis;
- healthcheck;
- password;
- volume.

## Задача 8: troubleshooting

Найди и исправь:

- key без TTL;
- `KEYS *`;
- big list;
- wrong key type;
- Redis client на каждый request.

## Мини-шпаргалка

- Каждая задача должна иметь tests или ручные команды проверки.
- Для TTL проверяй `TTL`.
- Для cache проверяй hit/miss.
- Для Streams проверяй pending.
- Для performance смотри `SLOWLOG` и `INFO`.
