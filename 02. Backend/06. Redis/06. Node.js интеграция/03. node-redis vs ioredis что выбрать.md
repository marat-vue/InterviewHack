# node-redis vs ioredis: что выбрать?

> [!NOTE]
> В Node.js чаще всего встречаются два клиента: официальный `redis` (`node-redis`) и `ioredis`. Для новых проектов обычно начинают с официального клиента, но `ioredis` по-прежнему часто используют в экосистеме, особенно в старых проектах и некоторых queue libraries.

## Что такое node-redis?

`node-redis` - официальный Redis client для Node.js.

Плюсы:

- официальная документация Redis;
- promises;
- auto-pipelining;
- Redis Stack commands;
- активная поддержка;
- понятный API.

Пример:

```ts
import { createClient } from 'redis';

const redis = createClient({
  url: process.env.REDIS_URL,
});

await redis.connect();
```

## Что такое ioredis?

`ioredis` - популярный Redis client, который долго был стандартом во многих Node.js проектах.

Плюсы:

- зрелая экосистема;
- часто используется queue libraries;
- удобный API для некоторых Cluster/Sentinel сценариев;
- много legacy проектов на нем.

Пример:

```ts
import Redis from 'ioredis';

const redis = new Redis(process.env.REDIS_URL!);
```

## Как выбрать?

| Ситуация | Выбор |
|---|---|
| Новый проект без legacy | `redis` |
| Проект уже на `ioredis` | оставайся на `ioredis` |
| Библиотека требует `ioredis` | `ioredis` |
| Следуешь официальным Redis docs | `redis` |
| Нужно минимально менять старый код | текущий клиент |

## Можно ли использовать оба?

Технически можно, но обычно не стоит:

- два connection pool/lifecycle;
- разные APIs;
- сложнее mocking/testing;
- больше dependency surface.

Исключение: конкретная библиотека требует отдельный client.

## Что важно независимо от клиента?

- singleton connection;
- error handling;
- reconnect/backoff;
- timeouts;
- graceful shutdown;
- separate Pub/Sub connections;
- key naming;
- TTL;
- observability.

## Мини-шпаргалка

- `redis` - официальный default.
- `ioredis` - зрелый и распространенный.
- Не смешивай клиенты без причины.
- Architecture patterns важнее конкретного клиента.
- Смотри, что уже принято в codebase.
