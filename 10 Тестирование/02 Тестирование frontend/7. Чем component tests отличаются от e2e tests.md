# Чем component tests отличаются от e2e tests?

> [!summary]
> Component tests запускают отдельный компонент или небольшую связку компонентов в контролируемом окружении. E2E tests запускают приложение целиком и проверяют реальный пользовательский путь через браузер, роутинг, сеть и backend.

## Component tests

Component test отвечает: "Компонент работает правильно в заданном состоянии?"

```ts
const wrapper = mount(ProductCard, {
  props: {
    product: { id: 1, title: 'Keyboard', price: 5000 },
  },
});

expect(wrapper.text()).toContain('Keyboard');
```

Плюсы:

- быстрее e2e;
- проще подготовить state;
- легче проверить edge cases;
- хорошо подходят для UI-библиотек.

## E2E tests

E2E test отвечает: "Пользователь может пройти весь сценарий?"

```ts
await page.goto('/products');
await page.getByText('Keyboard').click();
await page.getByRole('button', { name: 'В корзину' }).click();
await expect(page.getByText('Товар добавлен')).toBeVisible();
```

Плюсы:

- проверяют приложение целиком;
- ловят ошибки интеграции;
- дают уверенность в бизнес-критичных flows.

## Что выбрать?

Для UI-состояний удобнее component tests:

- кнопка loading;
- empty state;
- ошибка валидации;
- разные props.

Для пользовательских flows удобнее e2e:

- регистрация;
- оплата;
- создание заказа;
- восстановление пароля.

## Мини-шпаргалка

- Component tests быстрее и точечнее.
- E2E tests реалистичнее, но дороже.
- Один компонент с 20 состояниями лучше проверять component tests.
- Один критичный путь через приложение лучше проверять e2e.
- Хорошая стратегия использует оба уровня.
