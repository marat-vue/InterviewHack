# Как работают fallthrough attributes, inheritAttrs, useAttrs и wrapper components?

> [!NOTE]
> Fallthrough attributes - это атрибуты и listeners, которые родитель передал компоненту, но компонент не объявил как props или emits. Vue может автоматически повесить их на корневой элемент или дать вам управлять этим вручную.

## Вопрос

Как работают fallthrough attributes, `inheritAttrs`, `useAttrs` и как проектировать wrapper-компоненты?

## Что такое fallthrough attributes

Если родитель пишет:

```vue
<BaseButton
  id="save-button"
  class="primary-action"
  data-testid="save"
  @click="save"
>
  Сохранить
</BaseButton>
```

А `BaseButton` не объявляет `id`, `class`, `data-testid` и `click` как props/emits, эти значения становятся fallthrough attributes.

Если у компонента один root element, Vue автоматически применит их к root:

```vue
<template>
  <button class="button">
    <slot />
  </button>
</template>
```

Итоговый HTML будет примерно таким:

```html
<button id="save-button" class="button primary-action" data-testid="save">
  Сохранить
</button>
```

## Что входит в `$attrs`

В `$attrs` попадают:

- обычные HTML-атрибуты: `id`, `title`, `aria-label`, `data-testid`;
- `class` и `style`;
- listeners вроде `onClick`, если событие не объявлено в `emits`;
- нестандартные атрибуты, которые не являются props.

Не попадают:

- объявленные props;
- объявленные emits;
- slots.

## Автоматическое наследование

Простой wrapper можно написать без дополнительной логики:

```vue
<template>
  <button class="base-button">
    <slot />
  </button>
</template>
```

Использование:

```vue
<BaseButton
  type="submit"
  aria-label="Сохранить форму"
  @click="trackClick"
>
  Сохранить
</BaseButton>
```

`type`, `aria-label` и `click` попадут на `<button>`.

## `class` и `style` объединяются

Если у ребенка уже есть `class`, а родитель передает свой, Vue объединит их:

```vue
<BaseButton class="mt-4" />
```

```vue
<template>
  <button class="base-button">
    <slot />
  </button>
</template>
```

Итог:

```html
<button class="base-button mt-4"></button>
```

Это полезно для layout-классов, но опасно, если родитель начинает переопределять внутреннюю стилизацию ребенка.

## Когда нужен `inheritAttrs: false`

Иногда root element - не тот элемент, на который должны попасть атрибуты.

Плохой пример:

```vue
<template>
  <label class="field">
    <span>{{ label }}</span>
    <input />
  </label>
</template>
```

Если родитель передаст `placeholder`, он попадет на `<label>`, а не на `<input>`.

Правильно:

```vue
<script setup lang="ts">
defineOptions({
  inheritAttrs: false,
});

defineProps<{
  label: string;
}>();
</script>

<template>
  <label class="field">
    <span>{{ label }}</span>
    <input v-bind="$attrs" />
  </label>
</template>
```

Теперь:

```vue
<BaseInput
  label="Email"
  type="email"
  autocomplete="email"
  placeholder="mail@example.com"
/>
```

`type`, `autocomplete`, `placeholder` попадут на `<input>`.

## `useAttrs`

В `<script setup>` можно получить attrs через `useAttrs()`.

```vue
<script setup lang="ts">
import { computed, useAttrs } from "vue";

defineOptions({
  inheritAttrs: false,
});

const attrs = useAttrs();

const inputAttrs = computed(() => {
  const { class: _class, style: _style, ...rest } = attrs;
  return rest;
});
</script>

<template>
  <div class="field" :class="$attrs.class">
    <input v-bind="inputAttrs" />
  </div>
</template>
```

Зачем это нужно:

- разделить `class` wrapper-а и attrs внутреннего input;
- фильтровать attrs;
- условно прокидывать listeners;
- строить wrapper-компоненты для UI-kit.

Нюанс: объект `attrs` обновляется при изменении атрибутов, но это не обычный deep reactive state. Не стоит строить сложную бизнес-логику вокруг `useAttrs`.

## Несколько root elements

Если у компонента несколько root elements, Vue не знает, куда автоматически применить attrs.

```vue
<template>
  <header>...</header>
  <main>...</main>
</template>
```

В таком случае нужно явно указать:

```vue
<template>
  <header>...</header>
  <main v-bind="$attrs">...</main>
</template>
```

Иначе Vue предупредит о нераспределенных fallthrough attributes.

## `emits` влияет на listeners

Если компонент объявил событие:

```vue
<script setup lang="ts">
const emit = defineEmits<{
  click: [event: MouseEvent];
}>();
</script>
```

То listener `@click` больше не является fallthrough attribute. Он относится к событию компонента.

Это важно для wrapper-компонентов:

```vue
<script setup lang="ts">
const emit = defineEmits<{
  click: [event: MouseEvent];
}>();
</script>

<template>
  <button @click="emit('click', $event)">
    <slot />
  </button>
</template>
```

Если `click` не объявить в `emits`, listener может быть проброшен на root button автоматически. Если объявить - вы сами отвечаете за emit.

## Практический wrapper: `BaseTextField`

```vue
<script setup lang="ts">
import { computed, useAttrs } from "vue";

defineOptions({
  inheritAttrs: false,
});

const props = withDefaults(
  defineProps<{
    id?: string;
    label: string;
    error?: string;
  }>(),
  {
    error: "",
  },
);

const model = defineModel<string>({
  required: true,
});

const attrs = useAttrs();

const describedBy = computed(() =>
  props.error ? `${props.id}-error` : undefined,
);
</script>

<template>
  <div class="field" :class="$attrs.class">
    <label v-if="id" class="field__label" :for="id">
      {{ label }}
    </label>

    <input
      :id="id"
      v-model="model"
      class="field__control"
      :aria-invalid="Boolean(error)"
      :aria-describedby="describedBy"
      v-bind="{ ...attrs, class: undefined }"
    />

    <p v-if="error" :id="`${id}-error`" class="field__error">
      {{ error }}
    </p>
  </div>
</template>
```

## Частые ошибки

- Не отключить `inheritAttrs`, когда attrs должны попасть не на root, а на внутренний элемент.
- Случайно повесить `type`, `placeholder`, `aria-*` на wrapper `<div>`.
- Объявить `click` в `emits`, но забыть реально вызвать `emit("click")`.
- Передавать все `$attrs` сразу на несколько элементов.
- Использовать `$attrs` как замену props там, где нужен явный компонентный контракт.
- Ломать accessibility, теряя `id`, `for`, `aria-describedby` при создании wrapper input.

## Что отвечать на собеседовании

Fallthrough attributes - это механизм Vue для атрибутов и listeners, которые не объявлены как props/emits. По умолчанию они падают на root element, `class` и `style` объединяются. Если root не подходит, ставят `inheritAttrs: false` и вручную прокидывают `$attrs` или `useAttrs()` на нужный элемент. Это особенно важно для wrapper-компонентов вокруг `input`, `button`, компонентов UI-kit и accessible form controls.

## Мини-шпаргалка

- `$attrs` - не props и не emits.
- Один root - attrs применяются автоматически.
- Несколько roots - нужно явно `v-bind="$attrs"`.
- `inheritAttrs: false` отключает автоматический проброс.
- `useAttrs()` нужен в `<script setup>`.
- `class` и `style` merge-ятся.
- Объявленные `emits` больше не fallthrough listeners.
