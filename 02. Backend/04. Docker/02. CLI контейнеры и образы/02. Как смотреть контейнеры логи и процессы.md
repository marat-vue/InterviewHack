# Как смотреть контейнеры логи и процессы?

> [!NOTE]
> Для диагностики контейнеров чаще всего используют `docker ps`, `docker logs`, `docker exec`, `docker inspect`, `docker stats` и `docker top`. Эти команды помогают понять, запущен ли контейнер, что он пишет в stdout/stderr, какие env и ports у него есть и что происходит внутри.

## Посмотреть running containers

```bash
docker ps
```

Показывает только запущенные контейнеры.

Посмотреть все, включая остановленные:

```bash
docker ps -a
```

## Посмотреть logs

```bash
docker logs api
```

Следить за логами в реальном времени:

```bash
docker logs -f api
```

Последние строки:

```bash
docker logs --tail=100 api
```

Важно: Docker собирает то, что процесс пишет в `stdout` и `stderr`. Поэтому приложения в контейнере обычно логируют в консоль, а не в файл внутри container filesystem.

## Зайти внутрь контейнера

```bash
docker exec -it api sh
```

Если внутри есть bash:

```bash
docker exec -it api bash
```

`exec` запускает новую команду внутри уже работающего контейнера.

## Посмотреть подробную информацию

```bash
docker inspect api
```

Там можно найти:

- IP address;
- mounted volumes;
- env variables;
- ports;
- network settings;
- restart policy;
- command;
- health status.

## Посмотреть процессы

```bash
docker top api
```

Полезно, если контейнер вроде running, но непонятно, какой процесс внутри живет.

## Посмотреть ресурсы

```bash
docker stats
```

Показывает CPU, memory, network I/O и block I/O.

## Быстрый сценарий отладки

```bash
docker ps -a
docker logs api --tail=100
docker inspect api
docker exec -it api sh
```

Если контейнер сразу падает, сначала смотри `docker logs`, потому что `exec` работает только с running container.

## Что отвечать на собеседовании?

Для диагностики контейнера я сначала смотрю `docker ps -a`, затем `docker logs`, потом `docker inspect` для ports, env, mounts и network. Если контейнер работает, могу зайти через `docker exec -it container sh`. Для ресурсов использую `docker stats`, для процессов - `docker top`.

## Частые ошибки

- Пытаться сделать `docker exec` в остановленный контейнер.
- Искать logs в файле внутри контейнера, хотя приложение пишет в stdout.
- Смотреть только `docker ps` и не видеть exited containers.
- Не проверять `inspect`, когда проблема с портами или env.
- Думать, что `docker logs` покажет логи, если приложение пишет только в свой файл.

## Мини-шпаргалка

- `docker ps` - running containers.
- `docker ps -a` - все containers.
- `docker logs -f` - live logs.
- `docker exec -it` - команда внутри container.
- `docker inspect` - подробная конфигурация.
- `docker stats` - ресурсы.
- `docker top` - процессы.
