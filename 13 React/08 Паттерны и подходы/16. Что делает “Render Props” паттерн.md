# Что делает “Render Props” паттерн?

> [!summary]
> Render Props - это паттерн, где компонент получает функцию, вызывающуюся для рендера UI. Компонент владеет логикой, а родитель решает, как отобразить полученные данные.

## Базовая идея

```jsx
function DataLoader({ render }) {
  const data = useData()

  return render(data)
}
```

Использование:

```jsx
<DataLoader
  render={(data) => <UserList users={data.users} />}
/>
```

`DataLoader` получает данные, но не знает, как именно их показывать.

## Пример с состоянием курсора

```jsx
function MouseTracker({ render }) {
  const [position, setPosition] = useState({ x: 0, y: 0 })

  function handleMouseMove(event) {
    setPosition({ x: event.clientX, y: event.clientY })
  }

  return (
    <div onMouseMove={handleMouseMove}>
      {render(position)}
    </div>
  )
}
```

Использование:

```jsx
<MouseTracker
  render={({ x, y }) => (
    <p>
      Cursor: {x}, {y}
    </p>
  )}
/>
```

## Вариант через children

Очень часто render prop передают как `children`.

```jsx
<MouseTracker>
  {({ x, y }) => <p>Cursor: {x}, {y}</p>}
</MouseTracker>
```

Компонент:

```jsx
function MouseTracker({ children }) {
  const position = useMousePosition()

  return children(position)
}
```

Этот вариант также называют Function as Child.

## Чем render props заменили custom hooks?

До hooks render props часто использовали для переиспользования stateful logic.

```jsx
const position = useMousePosition()

return <p>Cursor: {position.x}, {position.y}</p>
```

Custom hook обычно проще: меньше вложенности в JSX и легче комбинировать несколько источников логики.

## Когда render props все еще полезны?

- когда нужен компонент-обертка с контролем над layout;
- когда API библиотеки уже построен на render props;
- когда нужно передать управление отображением наружу;
- когда функция-ребенок делает API выразительнее.

## Мини-шпаргалка

- Render prop - функция, которая возвращает JSX.
- Компонент дает данные, родитель рисует UI.
- Function as Child - разновидность render props.
- Custom hooks часто проще для переиспользования логики.
- Паттерн полезно знать для старого и библиотечного React-кода.
