# Как работают несколько вызовов setState подряд?

> [!summary]
> Несколько вызовов setter состояния подряд не всегда означают несколько немедленных render. React ставит обновления в очередь и может сгруппировать их через batching. Если новое значение зависит от предыдущего, нужно использовать updater function.

## Пример с одинаковым snapshot

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  function handleClick() {
    setCount(count + 1)
    setCount(count + 1)
    setCount(count + 1)
  }

  return <button onClick={handleClick}>{count}</button>
}
```

Все три вызова используют `count` из текущего render. Если он был `0`, каждый вызов фактически говорит: "установи `1`".

## Правильно через updater

```jsx
function handleClick() {
  setCount((count) => count + 1)
  setCount((count) => count + 1)
  setCount((count) => count + 1)
}
```

Теперь React применит обновления последовательно:

```text
0 -> 1 -> 2 -> 3
```

## Что если разные state?

```jsx
setName('Анна')
setIsEditing(false)
setError(null)
```

React может сгруппировать эти обновления и сделать один render. Это обычно хорошо для производительности.

## Можно ли полагаться на порядок?

Очередь updater-функций для одного state применяется последовательно:

```jsx
setCount((count) => count + 1)
setCount((count) => count * 2)
```

Если было `2`, получится:

```text
2 -> 3 -> 6
```

## Как избежать путаницы?

- Используй updater, если нужно старое значение.
- Не пытайся читать новое state сразу после setter.
- Для сложных связанных обновлений рассмотри `useReducer`.
- Не смешивай много независимых смыслов в одном state-объекте без причины.

## Мини-шпаргалка

- Setter не меняет state мгновенно в текущем render.
- Несколько обновлений могут быть сгруппированы.
- `setCount(count + 1)` использует snapshot.
- `setCount((count) => count + 1)` использует очередь обновлений.
- Для сложной логики удобен reducer.
