# Как типизировать контекст?

> [!summary]
> Контекст в React типизируют через `createContext<T | null>(null)` или `createContext<T | undefined>(undefined)` и почти всегда оборачивают в кастомный хук, который проверяет наличие Provider. Это убирает `null` из потребителей и делает ошибку понятной.

## Базовый паттерн

```tsx
import { createContext, useContext } from 'react'

type ThemeContextValue = {
  theme: 'light' | 'dark'
  toggleTheme: () => void
}

const ThemeContext = createContext<ThemeContextValue | null>(null)

export function useTheme() {
  const context = useContext(ThemeContext)

  if (context === null) {
    throw new Error('useTheme must be used within ThemeProvider')
  }

  return context
}
```

Теперь потребитель получает не `ThemeContextValue | null`, а чистый `ThemeContextValue`.

## Provider

```tsx
type ThemeProviderProps = {
  children: React.ReactNode
}

export function ThemeProvider({ children }: ThemeProviderProps) {
  const [theme, setTheme] = useState<'light' | 'dark'>('light')

  const value = useMemo<ThemeContextValue>(() => {
    return {
      theme,
      toggleTheme: () => {
        setTheme((currentTheme) =>
          currentTheme === 'light' ? 'dark' : 'light',
        )
      },
    }
  }, [theme])

  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  )
}
```

`useMemo` нужен не для типизации, а чтобы значение context не создавало новую ссылку на каждый render без причины.

## Когда можно задать default value?

Default value уместен, если context действительно имеет смысл без Provider:

```tsx
type Config = {
  apiUrl: string
  locale: 'ru' | 'en'
}

const ConfigContext = createContext<Config>({
  apiUrl: '/api',
  locale: 'ru',
})
```

Но для auth, theme, current user, permissions и похожих зависимостей чаще лучше `null` и проверка в custom hook.

## Context с reducer

```tsx
type State = {
  count: number
}

type Action =
  | { type: 'increment' }
  | { type: 'decrement' }

type CounterContextValue = {
  state: State
  dispatch: React.Dispatch<Action>
}

const CounterContext = createContext<CounterContextValue | null>(null)
```

Использование:

```tsx
function CounterButton() {
  const { dispatch } = useCounter()

  return (
    <button onClick={() => dispatch({ type: 'increment' })}>
      Increment
    </button>
  )
}
```

TypeScript не даст отправить несуществующий action type.

## Разделение state и actions

Иногда полезно разделять контексты:

```tsx
const UserStateContext = createContext<User | null>(null)
const UserActionsContext = createContext<{ logout: () => void } | null>(null)
```

Это может уменьшить лишние rerenders, если компоненты читают только actions.

## Что не стоит делать?

Плохой вариант:

```tsx
const ThemeContext = createContext({} as ThemeContextValue)
```

Так TypeScript перестает предупреждать о проблеме, но в runtime можно получить ошибку.

Лучше явно обработать отсутствие Provider.

## Что отвечать на собеседовании?

Контекст типизируют через `createContext<Value | null>(null)` и кастомный hook `useContextName`, который бросает понятную ошибку, если Provider отсутствует. Provider типизирует `children` как `React.ReactNode`, а value часто мемоизируют. Для reducer context dispatch типизируют как `React.Dispatch<Action>`.

## Частые ошибки

- Использовать `as any` или фиктивный `{}` default.
- Экспортировать context напрямую вместо custom hook.
- Забывать типизировать `children`.
- Не мемоизировать объект `value`, если он создается на каждом render.
- Класть в один context слишком много несвязанных данных.

## Мини-шпаргалка

- `createContext<Value | null>(null)`.
- Custom hook убирает `null` для потребителей.
- `children: React.ReactNode`.
- `dispatch: React.Dispatch<Action>`.
- Не используй фиктивные default values.
