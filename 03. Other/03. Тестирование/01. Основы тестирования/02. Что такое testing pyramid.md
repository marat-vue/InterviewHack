# Что такое testing pyramid?

> [!summary]
> Testing pyramid - это модель баланса тестов: много быстрых unit tests, меньше integration/component tests и еще меньше дорогих e2e tests. Идея в том, чтобы получать максимум уверенности за разумное время и стоимость поддержки.

## Как выглядит пирамида?

Классическая пирамида:

```text
        E2E tests
   Integration tests
       Unit tests
```

Чем выше уровень, тем тест ближе к реальному пользовательскому сценарию, но тем он медленнее, дороже и хрупче.

## Unit tests

Unit tests проверяют маленькую изолированную часть кода: функцию, метод, composable, service.

```ts
expect(formatPrice(1200, 'USD')).toBe('$1,200.00');
```

Плюсы:

- быстрые;
- легко запускать часто;
- хорошо помогают при рефакторинге.

Минусы:

- не проверяют, что части системы правильно связаны между собой.

## Integration tests

Integration tests проверяют взаимодействие нескольких частей: service + repository, component + store, controller + validation.

```ts
const order = await orderService.createOrder(userId, items);

expect(order.total).toBe(3000);
expect(repository.save).toHaveBeenCalled();
```

Плюсы:

- находят ошибки на границах модулей;
- ближе к реальности, чем unit tests.

Минусы:

- сложнее setup;
- могут быть медленнее.

## E2E tests

E2E tests проверяют полный путь пользователя через приложение: браузер, UI, API, база.

```text
Пользователь открывает корзину -> нажимает оплатить -> видит страницу успеха.
```

Плюсы:

- дают высокую уверенность в критичных flows;
- проверяют систему почти как реальный пользователь.

Минусы:

- медленные;
- зависят от окружения;
- дороже в поддержке.

## Почему нельзя писать только E2E?

Потому что e2e-тесты тяжелые. Если каждый мелкий кейс проверять через браузер и настоящую систему, тестовый набор станет медленным и нестабильным.

Лучше так:

- бизнес-логику покрывать unit tests;
- связи модулей покрывать integration tests;
- самые важные пользовательские маршруты покрывать e2e tests.

## Мини-шпаргалка

- Пирамида тестирования - это баланс стоимости и уверенности.
- Unit tests быстрые и дешевые.
- Integration tests проверяют связи.
- E2E tests проверяют реальные пользовательские flows.
- Чем выше уровень, тем меньше тестов обычно нужно.
