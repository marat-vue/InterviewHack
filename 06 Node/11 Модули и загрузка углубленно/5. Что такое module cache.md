# Что такое module cache?

> [!summary]
> Module cache - механизм, из-за которого модуль после первой загрузки обычно переиспользуется повторно. Это ускоряет работу и позволяет модулям хранить состояние, но может удивлять в тестах и при side effects.

## CommonJS cache

```js
// counter.cjs
let count = 0;

module.exports.increment = () => {
  count += 1;
  return count;
};
```

```js
const a = require('./counter.cjs');
const b = require('./counter.cjs');

console.log(a.increment()); // 1
console.log(b.increment()); // 2
```

`a` и `b` получают один и тот же экземпляр модуля.

## Зачем нужен cache?

- не выполнять один и тот же файл много раз;
- ускорить загрузку;
- позволить singleton-паттернам работать;
- сохранить состояние модуля.

## Side effects

Код на верхнем уровне модуля выполняется при первой загрузке.

```js
console.log('module loaded');

export const value = 42;
```

Повторный импорт обычно не напечатает сообщение заново.

## В тестах

Module cache может мешать, если тесты зависят от чистого состояния. Тогда лучше проектировать модули без скрытого состояния или явно создавать новые экземпляры через функции-фабрики.

## Мини-шпаргалка

- Модуль обычно выполняется один раз.
- Повторная загрузка возвращает cached exports.
- Верхнеуровневые side effects выполняются при первой загрузке.
- Cache полезен для производительности.
- Скрытое состояние модуля усложняет тестирование.
