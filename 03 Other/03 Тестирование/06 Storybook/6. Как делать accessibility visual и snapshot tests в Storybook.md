# Как делать accessibility, visual и snapshot tests в Storybook?

> [!summary]
> Storybook удобен для дополнительных проверок UI: accessibility checks помогают находить проблемы доступности, visual tests ловят изменения внешнего вида, snapshot tests фиксируют структуру render output. Все эти проверки лучше строить поверх качественных stories.

## Accessibility testing

Accessibility tests проверяют, нет ли типичных проблем доступности:

- отсутствует label;
- плохой contrast;
- интерактивный элемент недоступен с клавиатуры;
- неверные ARIA-атрибуты;
- modal не управляет focus.

В Storybook для этого используют accessibility addon и проверки на основе rendered DOM.

## Visual testing

Visual testing сравнивает screenshot story с эталоном.

Хорошие кандидаты:

- Button states;
- Input states;
- Modal;
- Table empty/loading/error;
- responsive cards;
- design system components.

Чтобы visual tests были стабильнее:

- фиксируй дату;
- отключай случайные данные;
- контролируй animations;
- используй стабильные fonts;
- делай stories маленькими и предсказуемыми.

## Snapshot testing

Snapshot фиксирует структуру результата:

```ts
expect(container).toMatchSnapshot();
```

Но snapshot легко становится шумным, если компонент часто меняет разметку.

## Как выбрать тип проверки?

| Проверка | Что ловит |
|---|---|
| accessibility | проблемы доступности |
| visual | изменения внешнего вида |
| snapshot | изменения структуры |
| interaction | изменения поведения |

## Мини-шпаргалка

- Accessibility tests проверяют доступность rendered DOM.
- Visual tests ловят CSS/UI regressions.
- Snapshot tests полезны для стабильной структуры.
- Качественные stories - основа всех проверок.
- Не обновляй snapshots и screenshots без осмотра diff.
