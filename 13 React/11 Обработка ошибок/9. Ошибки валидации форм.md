# Ошибки валидации форм

> [!summary]
> Ошибки валидации форм - это ожидаемые пользовательские ошибки, а не падение приложения. Их нужно показывать рядом с полями, связывать с input через ARIA, учитывать touched/dirty state и отдельно обрабатывать серверные ошибки.

## Типы ошибок формы

- client validation: поле пустое, неверный email, короткий пароль;
- server validation: email уже занят, промокод недействителен;
- network error: запрос не отправился;
- permission error: нет прав на действие;
- root/form error: общая ошибка, не привязанная к конкретному полю.

## Минимальная модель state

```jsx
const [values, setValues] = useState({
  email: '',
  password: '',
})

const [touched, setTouched] = useState({})
const [errors, setErrors] = useState({})
const [formError, setFormError] = useState(null)
const [isSubmitting, setIsSubmitting] = useState(false)
```

`errors` лучше хранить отдельно от `values`.

## Пример с Zod

```jsx
const schema = z.object({
  email: z.string().email('Enter a valid email'),
  password: z.string().min(8, 'Minimum 8 characters'),
})

function validate(values) {
  const result = schema.safeParse(values)

  if (result.success) {
    return {}
  }

  return Object.fromEntries(
    result.error.issues.map((issue) => [
      issue.path[0],
      issue.message,
    ]),
  )
}
```

## Отображение ошибки поля

```jsx
function EmailField({ value, error, touched, onChange, onBlur }) {
  const showError = touched && error

  return (
    <div>
      <label htmlFor="email">Email</label>
      <input
        id="email"
        value={value}
        onChange={onChange}
        onBlur={onBlur}
        aria-invalid={showError ? 'true' : 'false'}
        aria-describedby={showError ? 'email-error' : undefined}
      />
      {showError && (
        <p id="email-error" role="alert">
          {error}
        </p>
      )}
    </div>
  )
}
```

## Когда показывать ошибки?

Хороший UX:

- не показывать ошибку до первого взаимодействия;
- показывать после `blur`;
- после submit показать все ошибки;
- при submit сфокусировать первое ошибочное поле;
- не стирать серверную ошибку молча, если пользователь ее не исправил.

## React Hook Form

```jsx
const {
  register,
  handleSubmit,
  formState: { errors, isSubmitting },
  setError,
} = useForm({
  resolver: zodResolver(schema),
})

async function onSubmit(values) {
  try {
    await registerUser(values)
  } catch (error) {
    setError('root', {
      message: 'Registration failed',
    })
  }
}
```

```jsx
<form onSubmit={handleSubmit(onSubmit)}>
  {errors.root && <p role="alert">{errors.root.message}</p>}

  <input {...register('email')} aria-invalid={!!errors.email} />
  {errors.email && <p role="alert">{errors.email.message}</p>}

  <button disabled={isSubmitting}>Submit</button>
</form>
```

## Мини-шпаргалка

- Validation error - нормальная ветка UI.
- Client errors и server errors нужно маппить отдельно.
- Используй `touched`, `dirty`, `errors`, `isSubmitting`.
- Для доступности нужны `aria-invalid`, `aria-describedby`, `role="alert"`.
- После submit полезно фокусировать первое поле с ошибкой.
