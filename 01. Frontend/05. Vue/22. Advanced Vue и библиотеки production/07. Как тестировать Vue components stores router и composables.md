# Как тестировать Vue components, stores, router и composables?

> [!NOTE]
> Тестирование Vue - это не проверка "отрендерился ли div". Хороший тест проверяет пользовательское поведение, контракт компонента, события, асинхронные состояния, store/router-интеграцию и ошибки.

## Вопрос

Как тестировать Vue-компоненты, composables, Pinia stores и Vue Router?

## Что подключить

Минимальный набор для Vue + Vite:

```bash
npm i -D vitest @vue/test-utils happy-dom vue-tsc
```

Если тестируются Pinia stores:

```bash
npm i -D @pinia/testing
```

Если нужны пользовательские проверки DOM:

```bash
npm i -D @testing-library/vue @testing-library/jest-dom
```

## Настройка Vitest

```typescript
// vite.config.ts
import vue from "@vitejs/plugin-vue";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [vue()],
  test: {
    environment: "happy-dom",
    globals: true,
    setupFiles: ["./src/test/setup.ts"],
  },
});
```

```typescript
// src/test/setup.ts
import "@testing-library/jest-dom/vitest";
```

Скрипты:

```json
{
  "scripts": {
    "test": "vitest",
    "test:run": "vitest run",
    "typecheck": "vue-tsc --noEmit"
  }
}
```

## Что тестировать

В Vue-компоненте обычно проверяют:

- что пользователь видит правильный текст/состояние;
- что props влияют на rendering;
- что interaction вызывает expected effect;
- что компонент эмитит правильные события;
- что slots рендерятся;
- что loading/error/empty states работают;
- что accessibility-контракт не сломан;
- что интеграция со store/router работает на уровне поведения.

Не стоит тестировать:

- внутреннюю реализацию `ref`;
- private methods;
- точную структуру DOM без необходимости;
- implementation details UI-библиотеки.

## Vue Test Utils: основные методы

| Метод | Зачем нужен |
| --- | --- |
| `mount(Component, options)` | полностью монтирует компонент |
| `shallowMount(Component, options)` | монтирует компонент, но stub-ит дочерние компоненты |
| `wrapper.find(selector)` | ищет элемент, возвращает wrapper даже если не найден |
| `wrapper.get(selector)` | ищет элемент и падает, если не найден |
| `wrapper.text()` | текст компонента |
| `wrapper.html()` | HTML компонента, полезно для debug |
| `wrapper.exists()` | существует ли найденный элемент |
| `wrapper.classes()` | CSS-классы |
| `wrapper.attributes()` | HTML-атрибуты |
| `wrapper.trigger(event)` | вызывает DOM event |
| `wrapper.setValue(value)` | меняет значение input/select/textarea |
| `wrapper.emitted()` | события, которые эмитил компонент |
| `wrapper.props()` | props дочернего компонента |
| `wrapper.unmount()` | размонтирует компонент |
| `flushPromises()` | дожидается pending promises |

## Базовый тест компонента

```vue
<!-- BaseCounter.vue -->
<script setup lang="ts">
const count = defineModel<number>({
  required: true,
});
</script>

<template>
  <button type="button" @click="count++">
    Count: {{ count }}
  </button>
</template>
```

```typescript
import { mount } from "@vue/test-utils";
import { describe, expect, it } from "vitest";
import BaseCounter from "./BaseCounter.vue";

describe("BaseCounter", () => {
  it("increments value through v-model", async () => {
    const wrapper = mount(BaseCounter, {
      props: {
        modelValue: 1,
        "onUpdate:modelValue": (value: number) => {
          wrapper.setProps({ modelValue: value });
        },
      },
    });

    await wrapper.get("button").trigger("click");

    expect(wrapper.text()).toContain("Count: 2");
    expect(wrapper.emitted("update:modelValue")).toEqual([[2]]);
  });
});
```

## Props, slots и emits

```typescript
const wrapper = mount(UserCard, {
  props: {
    user: { id: 1, name: "Anna" },
  },
  slots: {
    actions: "<button>Delete</button>",
  },
});

expect(wrapper.text()).toContain("Anna");
expect(wrapper.text()).toContain("Delete");

await wrapper.get("[data-testid='select']").trigger("click");

expect(wrapper.emitted("select")).toEqual([[{ id: 1, name: "Anna" }]]);
```

## Асинхронные компоненты и запросы

```typescript
import { flushPromises, mount } from "@vue/test-utils";
import { beforeEach, expect, it, vi } from "vitest";
import UserProfile from "./UserProfile.vue";

beforeEach(() => {
  vi.stubGlobal(
    "fetch",
    vi.fn(() =>
      Promise.resolve({
        ok: true,
        json: () => Promise.resolve({ id: 1, name: "Anna" }),
      }),
    ),
  );
});

it("renders loaded user", async () => {
  const wrapper = mount(UserProfile);

  expect(wrapper.text()).toContain("Загрузка");

  await flushPromises();

  expect(wrapper.text()).toContain("Anna");
});
```

## Тестирование composable

Простой composable без lifecycle можно тестировать как функцию:

```typescript
import { describe, expect, it } from "vitest";
import { usePagination } from "./usePagination";

describe("usePagination", () => {
  it("calculates offset", () => {
    const pagination = usePagination(2, 20);

    expect(pagination.offset.value).toBe(20);

    pagination.next();

    expect(pagination.offset.value).toBe(40);
  });
});
```

Composable с lifecycle лучше тестировать через test component:

```typescript
import { mount } from "@vue/test-utils";
import { defineComponent } from "vue";
import { expect, it, vi } from "vitest";
import { useOnlineStatus } from "./useOnlineStatus";

it("cleans listeners on unmount", () => {
  const add = vi.spyOn(window, "addEventListener");
  const remove = vi.spyOn(window, "removeEventListener");

  const Component = defineComponent({
    setup() {
      useOnlineStatus();
      return () => null;
    },
  });

  const wrapper = mount(Component);
  wrapper.unmount();

  expect(add).toHaveBeenCalledWith("online", expect.any(Function));
  expect(remove).toHaveBeenCalledWith("online", expect.any(Function));
});
```

## Тестирование Pinia

```typescript
import { createTestingPinia } from "@pinia/testing";
import { mount } from "@vue/test-utils";
import { describe, expect, it, vi } from "vitest";
import UserMenu from "./UserMenu.vue";
import { useAuthStore } from "@/stores/auth";

describe("UserMenu", () => {
  it("calls logout action", async () => {
    const wrapper = mount(UserMenu, {
      global: {
        plugins: [
          createTestingPinia({
            createSpy: vi.fn,
            initialState: {
              auth: {
                user: { id: 1, name: "Anna" },
              },
            },
          }),
        ],
      },
    });

    const auth = useAuthStore();

    await wrapper.get("[data-testid='logout']").trigger("click");

    expect(auth.logout).toHaveBeenCalledOnce();
  });
});
```

`createTestingPinia` по умолчанию stub-ит actions. Если нужно выполнить реальные actions:

```typescript
createTestingPinia({
  createSpy: vi.fn,
  stubActions: false,
});
```

## Тестирование Vue Router

```typescript
import { mount } from "@vue/test-utils";
import { createMemoryHistory, createRouter } from "vue-router";
import { expect, it } from "vitest";
import AppLayout from "./AppLayout.vue";

it("renders active route", async () => {
  const router = createRouter({
    history: createMemoryHistory(),
    routes: [
      { path: "/", component: { template: "<h1>Home</h1>" } },
      { path: "/profile", component: { template: "<h1>Profile</h1>" } },
    ],
  });

  router.push("/profile");
  await router.isReady();

  const wrapper = mount(AppLayout, {
    global: {
      plugins: [router],
    },
  });

  expect(wrapper.text()).toContain("Profile");
});
```

Для unit-теста компонента, которому нужен только `useRouter`, часто проще mock:

```typescript
vi.mock("vue-router", () => ({
  useRouter: () => ({
    push: vi.fn(),
  }),
  useRoute: () => ({
    params: { id: "1" },
  }),
}));
```

## Что mock-ать

Хорошо mock-ать:

- сетевые клиенты;
- router navigation;
- analytics;
- browser API, которых нет в test environment;
- тяжелые дочерние компоненты.

Плохо mock-ать:

- весь компонент под тестом;
- каждую внутреннюю функцию;
- Vue reactivity;
- user interaction.

## Частые ошибки

- Проверять implementation details вместо поведения.
- Забывать `await` перед `trigger`, `setValue`, `flushPromises`.
- Использовать `shallowMount` и думать, что проверена интеграция.
- Не ставить `router.isReady()`.
- Не подключать Pinia в `global.plugins`.
- Писать snapshot-тесты на большие компоненты вместо конкретных assertions.
- Не запускать `vue-tsc`.

## Что отвечать на собеседовании

Для Vue обычно используют Vitest как test runner и Vue Test Utils или Testing Library для component tests. Unit-тесты проверяют composables и stores, component-тесты - props, slots, events и пользовательские действия, integration-тесты - работу с Router/Pinia. Важно тестировать публичное поведение, ждать async updates через `await`, `flushPromises`, подключать реальные plugins там, где проверяется интеграция, и не заменять typecheck тестами.

## Мини-шпаргалка

- `vitest` - test runner.
- `@vue/test-utils` - mount Vue components.
- `mount` - полный mount.
- `shallowMount` - дочерние компоненты stub-ятся.
- `trigger`/`setValue` - user interaction.
- `emitted` - проверка emits.
- `flushPromises` - ожидание promises.
- `createTestingPinia` - Pinia в тестах.
- `createMemoryHistory` - Router без browser history.
- `vue-tsc --noEmit` - проверка типов SFC.
