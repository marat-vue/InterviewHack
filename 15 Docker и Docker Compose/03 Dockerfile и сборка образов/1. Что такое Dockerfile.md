# Что такое Dockerfile?

> [!summary]
> Dockerfile - это текстовый рецепт сборки Docker image. В нем описывают base image, рабочую директорию, зависимости, копирование файлов, переменные окружения, пользователя и команду запуска приложения.

## Минимальный пример для Node.js

```dockerfile
FROM node:22-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .

EXPOSE 3000
CMD ["npm", "start"]
```

Сборка:

```bash
docker build -t my-api .
```

Запуск:

```bash
docker run -p 3000:3000 my-api
```

## Как Dockerfile превращается в image?

Каждая инструкция создает слой или metadata:

```text
FROM -> base layer
WORKDIR -> metadata/filesystem state
COPY -> files layer
RUN -> filesystem layer
CMD -> default command metadata
```

Если слой не изменился, Docker может взять его из cache.

## Почему порядок инструкций важен?

Плохо:

```dockerfile
COPY . .
RUN npm ci
```

При любом изменении исходного кода dependency install запустится заново.

Лучше:

```dockerfile
COPY package*.json ./
RUN npm ci
COPY . .
```

Теперь `npm ci` переиспользуется из cache, пока не изменился `package-lock.json`.

## Dockerfile - часть контракта проекта

Хороший Dockerfile отвечает на вопросы:

- какая версия runtime нужна;
- как установить зависимости;
- какие файлы нужны в image;
- какая команда запускает приложение;
- какой порт приложение слушает;
- от какого пользователя работает процесс;
- что не должно попадать в image.

## Что отвечать на собеседовании?

Dockerfile - это декларативный файл инструкций для сборки image. Он начинается с `FROM`, затем обычно задает `WORKDIR`, копирует manifest зависимостей, устанавливает зависимости через `RUN`, копирует код, задает `EXPOSE` и команду запуска через `CMD` или `ENTRYPOINT`. Хороший Dockerfile учитывает cache, безопасность и минимальный размер image.

## Частые ошибки

- Копировать весь проект до установки зависимостей.
- Не использовать `.dockerignore`.
- Оставлять dev-зависимости в production image.
- Запускать приложение под root без необходимости.
- Класть `.env` и secrets в image.
- Использовать слишком большой base image.

## Мини-шпаргалка

- Dockerfile собирает image.
- `FROM` задает base image.
- `RUN` выполняется на build stage.
- `CMD` выполняется при запуске container.
- Порядок слоев влияет на cache.
- `.dockerignore` уменьшает build context.
