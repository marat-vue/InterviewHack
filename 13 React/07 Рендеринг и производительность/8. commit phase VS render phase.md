# Чем commit phase отличается от render phase?

> [!summary]
> Render phase вычисляет, каким должен быть UI, а commit phase применяет готовые изменения к DOM. Render должен быть чистым и может быть прерван, commit связан с реальными изменениями интерфейса.

## Render phase

Во время render phase:

- React вызывает компоненты;
- компоненты возвращают JSX;
- React строит новое дерево;
- React сравнивает его со старым;
- DOM еще не меняется.

Пример чистого render:

```jsx
function UserName({ user }) {
  return <h1>{user.name}</h1>
}
```

## Commit phase

Во время commit phase:

- React добавляет/удаляет DOM-узлы;
- обновляет attributes;
- устанавливает refs;
- запускает layout effects;
- после paint запускает passive effects.

## Где доступны refs?

DOM ref становится доступен после commit:

```jsx
const inputRef = useRef(null)

useLayoutEffect(() => {
  inputRef.current.focus()
}, [])

return <input ref={inputRef} />
```

## Почему нельзя делать side effects в render?

Render phase может быть вызвана несколько раз и даже не закончиться commit. Если сделать side effect в render, он может произойти без соответствующего DOM-результата.

Правильно:

- в event handler - реакция на действие пользователя;
- в `useEffect` - внешняя синхронизация после paint;
- в `useLayoutEffect` - layout-sensitive код до paint.

## Мини-шпаргалка

- Render phase вычисляет UI.
- Commit phase меняет DOM.
- Render может быть прерван.
- Commit применяет готовый результат.
- Effects запускаются после commit.
