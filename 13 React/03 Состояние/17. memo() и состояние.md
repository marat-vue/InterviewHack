# Как memo связан с состоянием?

> [!summary]
> `React.memo` может пропустить render компонента, если его props не изменились. Но он не блокирует обновления собственного state компонента: если внутри memo-компонента изменился state, компонент все равно отрендерится.

## Что делает memo?

```jsx
const UserCard = memo(function UserCard({ user }) {
  return <h2>{user.name}</h2>
})
```

`memo` говорит React:

```text
Если props такие же, можно переиспользовать прошлый результат render.
```

## memo не отменяет локальный state

```jsx
const Counter = memo(function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  )
})
```

Клик обновляет state внутри `Counter`, поэтому компонент отрендерится, даже если props не менялись.

## Почему memo иногда не помогает?

```jsx
<UserCard user={{ name: 'Анна' }} />
```

На каждом render родителя создается новый объект. Для `memo` это новые props:

```text
{} !== {}
```

Лучше передать стабильный объект из state, props или `useMemo`, если это действительно нужно.

## memo и мутация state

Если мутировать объект:

```jsx
user.name = 'Мария'
setUser(user)
```

ссылка останется прежней. Это может мешать корректным обновлениям и оптимизациям.

## Когда использовать memo?

Используй `memo`, когда:

- компонент часто получает те же props;
- render компонента дорогой;
- есть подтверждение через Profiler;
- props можно сделать стабильными.

Не нужно оборачивать все компоненты механически.

## Мини-шпаргалка

- `memo` сравнивает props, а не запрещает render навсегда.
- Собственный state memo-компонента все равно обновляет его.
- Новые объекты и функции ломают пользу memo.
- Мутации state делают оптимизации ненадежными.
- Сначала профилируй, потом мемоизируй.
