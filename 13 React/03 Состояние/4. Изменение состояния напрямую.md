# Почему нельзя изменять состояние напрямую?

> [!summary]
> State в React нужно считать read-only. Если изменить объект или массив напрямую, React может не увидеть обновление, оптимизации сломаются, а UI станет непредсказуемым. Вместо мутации нужно создавать новое значение и передавать его в setter.

## Плохой пример с объектом

```jsx
const [user, setUser] = useState({
  name: 'Анна',
  age: 28,
})

function rename() {
  user.name = 'Мария'
  setUser(user)
}
```

Объект изменился, но ссылка осталась той же. React может не обновить UI ожидаемым образом.

## Правильный пример

```jsx
function rename() {
  setUser({
    ...user,
    name: 'Мария',
  })
}
```

Мы создаем новый объект:

```text
старый user !== новый user
```

Так React получает явный сигнал изменения.

## Плохой пример с массивом

```jsx
items.push(newItem)
setItems(items)
```

Массив мутирован напрямую.

Правильно:

```jsx
setItems([...items, newItem])
```

Удаление:

```jsx
setItems(items.filter((item) => item.id !== id))
```

Обновление элемента:

```jsx
setItems(items.map((item) =>
  item.id === id
    ? { ...item, done: !item.done }
    : item
))
```

## Почему иммутабельность, immutability, важна?

Она помогает:

- React понимать, что данные изменились;
- корректно работать `memo`;
- легче отлаживать изменения;
- избегать скрытых side effects;
- писать предсказуемые reducer;
- делать undo/redo и историю изменений.

## Мини-шпаргалка

- State нельзя менять напрямую.
- Объекты обновляют через копию `{ ...obj }`.
- Массивы обновляют через `map`, `filter`, spread.
- `push`, `splice`, прямое присваивание полей - мутации.
- Setter должен получить новое значение или updater function.
