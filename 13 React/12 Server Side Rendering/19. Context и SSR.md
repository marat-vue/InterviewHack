# Context и SSR

> [!summary]
> React Context работает при SSR: значение provider влияет на серверный HTML. Главный риск - изоляция данных между запросами и совпадение context value на сервере и клиенте во время hydration.

## Context участвует в server render

```jsx
const LocaleContext = createContext('en')

function App() {
  const locale = useContext(LocaleContext)

  return <html lang={locale}>...</html>
}
```

На сервере:

```jsx
const html = renderToString(
  <LocaleContext.Provider value="ru">
    <App />
  </LocaleContext.Provider>,
)
```

HTML будет создан с `lang="ru"`.

## Provider на каждый request

Плохо хранить request-specific данные в глобальном mutable объекте:

```js
let currentUser = null
```

При параллельных запросах данные одного пользователя могут протечь к другому.

Правильно создавать дерево provider внутри обработки request:

```jsx
app.get('*', async (req, res) => {
  const user = await getUser(req)
  const locale = getLocale(req)

  const html = renderToString(
    <AuthContext.Provider value={user}>
      <LocaleContext.Provider value={locale}>
        <App />
      </LocaleContext.Provider>
    </AuthContext.Provider>,
  )

  res.send(createDocument(html, { user, locale }))
})
```

## Hydration требует одинаковых значений

Если сервер отрендерил:

```jsx
<ThemeContext.Provider value="dark">
```

а клиент стартует с:

```jsx
<ThemeContext.Provider value="light">
```

может быть hydration mismatch или визуальный flash.

Initial context data нужно безопасно передать клиенту.

## Context для server state?

Context можно использовать для:

- locale;
- theme;
- current user;
- feature flags;
- request metadata;
- initial query cache.

Но не стоит складывать в один context огромный объект всего приложения: при изменении value обновятся все потребители.

## Мини-шпаргалка

- Context работает в SSR.
- Provider должен создаваться в рамках request.
- Request-specific данные нельзя держать в глобальном mutable state.
- Значения server/client должны совпасть при hydration.
- Для больших данных лучше query cache или state manager с SSR-гидрацией.
