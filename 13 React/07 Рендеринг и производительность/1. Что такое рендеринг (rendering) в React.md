# Что такое рендеринг (rendering) в React?

> [!summary]
> Рендеринг в React - это процесс вызова компонентов, чтобы понять, какой UI должен быть показан на экране. Render не равен изменению DOM: React сначала вычисляет новое дерево, а затем на commit-этапе применяет только необходимые изменения.

## Простое определение

React render - это:

```text
React вызывает компонент -> компонент возвращает JSX -> React понимает, что нужно показать
```

Пример:

```jsx
function Greeting({ name }) {
  return <h1>Привет, {name}</h1>
}
```

Когда React рендерит `Greeting`, он вызывает функцию и получает React-элемент.

## Какие шаги есть у обновления UI?

Официально удобно думать о трех шагах:

```text
Trigger -> Render -> Commit
```

Trigger:

- начальный render;
- обновление state;
- обновление props/context/store.

Render:

- React вызывает компоненты;
- компоненты возвращают JSX.

Commit:

- React применяет изменения к DOM.

## Render не всегда меняет DOM

Компонент может рендериться, но DOM не изменится:

```jsx
function Clock({ time }) {
  return (
    <>
      <h1>{time}</h1>
      <input />
    </>
  )
}
```

Если обновился только `time`, React не обязан пересоздавать `input`.

## Почему render должен быть чистым?

Render может быть вызван повторно, прерван или выполнен в development Strict Mode для проверки. Поэтому внутри render нельзя делать side effects.

Плохо:

```jsx
function Page() {
  sendAnalytics('render')
  return <main />
}
```

Лучше выполнять такие действия в `useEffect` или event handler.

## Мини-шпаргалка

- Rendering = React вызывает компоненты.
- Render возвращает описание UI.
- DOM меняется на commit-этапе.
- Render должен быть чистым.
- Повторный render не всегда означает DOM update.
