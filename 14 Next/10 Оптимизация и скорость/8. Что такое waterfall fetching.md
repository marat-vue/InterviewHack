# Что такое waterfall fetching?

> [!summary]
> Waterfall fetching - это последовательная загрузка данных, когда каждый следующий запрос начинается только после завершения предыдущего. Если запросы независимы, такой водопад искусственно замедляет страницу и ухудшает LCP, TTFB и UX.

## Как выглядит waterfall?

Плохо:

```ts
const user = await getUser()
const posts = await getPosts(user.id)
const comments = await getComments(posts[0].id)
```

Иногда такая последовательность оправдана: `posts` действительно нужен `user.id`.

Но часто waterfall появляется случайно:

```ts
const profile = await getProfile()
const recommendations = await getRecommendations()
const notifications = await getNotifications()
```

Если эти запросы не зависят друг от друга, они должны стартовать параллельно.

## Как сделать параллельно?

```ts
const [profile, recommendations, notifications] = await Promise.all([
  getProfile(),
  getRecommendations(),
  getNotifications(),
])
```

Теперь общее время примерно равно самому долгому запросу, а не сумме всех трех.

## Waterfall в Client Components

Частый источник водопада - цепочка `useEffect`:

```tsx
'use client'

export function ProfilePage() {
  const [user, setUser] = useState<User | null>(null)
  const [orders, setOrders] = useState<Order[]>([])

  useEffect(() => {
    fetch('/api/user')
      .then((res) => res.json())
      .then(setUser)
  }, [])

  useEffect(() => {
    if (!user) return

    fetch(`/api/orders?userId=${user.id}`)
      .then((res) => res.json())
      .then(setOrders)
  }, [user])
}
```

Проблема:

```text
load JS -> render -> fetch user -> render -> fetch orders -> render
```

Если данные нужны для первого экрана, часто лучше загрузить их на сервере.

## Waterfall в Server Components

В Server Components тоже можно случайно сделать последовательные запросы:

```tsx
export default async function Page() {
  const products = await getProducts()
  const categories = await getCategories()

  return <Catalog products={products} categories={categories} />
}
```

Если запросы независимы:

```tsx
export default async function Page() {
  const productsPromise = getProducts()
  const categoriesPromise = getCategories()

  const [products, categories] = await Promise.all([
    productsPromise,
    categoriesPromise,
  ])

  return <Catalog products={products} categories={categories} />
}
```

## Preload pattern

Иногда удобно стартовать запрос заранее:

```ts
// lib/posts.ts
import { cache } from 'react'

export const getPost = cache(async (slug: string) => {
  return db.post.findUnique({ where: { slug } })
})

export function preloadPost(slug: string) {
  void getPost(slug)
}
```

```tsx
// app/blog/[slug]/page.tsx
export default async function Page({ params }: Props) {
  const { slug } = await params
  preloadPost(slug)

  return (
    <>
      <PostHeader slug={slug} />
      <PostBody slug={slug} />
    </>
  )
}
```

Так можно начать загрузку раньше и избежать лишнего ожидания в глубине дерева.

## Suspense и streaming

Если блоки независимы, их можно разделить:

```tsx
import { Suspense } from 'react'

export default function DashboardPage() {
  return (
    <>
      <Suspense fallback={<StatsSkeleton />}>
        <Stats />
      </Suspense>
      <Suspense fallback={<FeedSkeleton />}>
        <Feed />
      </Suspense>
    </>
  )
}
```

Это не всегда отменяет сами запросы, но позволяет не блокировать весь UI одним медленным блоком.

## Когда waterfall нормален?

Waterfall оправдан, если второй запрос реально зависит от результата первого:

```ts
const user = await getUserByEmail(email)
const invoices = await getInvoicesByUserId(user.id)
```

Проблема начинается там, где зависимость искусственная.

## Что отвечать на собеседовании?

Waterfall fetching - это последовательная цепочка запросов, где каждый следующий стартует после предыдущего. Если запросы независимы, это замедляет страницу, потому что время складывается. В Next.js с этим борются через `Promise.all`, загрузку данных на сервере, preload pattern, Suspense, streaming и правильное разделение Client/Server Components.

## Частые ошибки

- Делать несколько независимых `await` подряд.
- Запускать первый экран через цепочку `useEffect`.
- Не отличать реальную зависимость данных от случайной последовательности.
- Думать, что Server Components автоматически убирают все waterfalls.
- Блокировать всю страницу одним медленным запросом.
- Не использовать Suspense для независимых тяжелых блоков.

## Мини-шпаргалка

- Waterfall - запросы идут последовательно.
- Независимые запросы запускай через `Promise.all`.
- Для первого экрана лучше server-side loading.
- `useEffect`-цепочки часто создают waterfall.
- Suspense помогает не блокировать весь UI.
- Последовательность нормальна, если есть реальная зависимость.
