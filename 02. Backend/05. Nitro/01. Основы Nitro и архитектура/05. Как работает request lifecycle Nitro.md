# Как работает request lifecycle Nitro?

> [!NOTE]
> Request lifecycle Nitro - это путь HTTP-запроса от входа в server runtime до ответа клиенту. Важные этапы: request hook, route rules, middleware, route matching, handler, response/error hooks.

## Упрощенная схема

```txt
Request
  -> server runtime
  -> Nitro request hook
  -> route rules
  -> global middleware
  -> route matching
  -> route handler
  -> response conversion
  -> response hooks
  -> client
```

## Что происходит в начале?

Nitro получает запрос от runtime. Runtime может быть разным:

- Node.js;
- Bun;
- Deno;
- Cloudflare Workers;
- serverless platform;
- Nuxt preview/server.

Nitro приводит запрос к совместимой модели и передает его в H3.

## Что такое `event`?

Для каждого запроса создается `H3Event`. Это объект-контекст текущего запроса.

```ts
export default defineHandler((event) => {
  return {
    method: event.method,
    path: event.path,
  };
});
```

В `event` обычно используют:

- `event.req` - web `Request`;
- `event.res` - подготовка response;
- `event.context` - данные текущего запроса;
- `event.url` - parsed URL;
- `event.method` - HTTP method;
- `event.path` - path запроса.

## Когда работают route rules?

Route rules применяются до handler. Они могут:

- добавить headers;
- включить cache/SWR;
- сделать redirect;
- включить proxy;
- включить CORS;
- включить basic auth;
- пометить route как static/prerender.

```ts
export default defineConfig({
  routeRules: {
    '/api/**': {
      cors: true,
      headers: {
        'x-api': 'true',
      },
    },
    '/old-page': {
      redirect: '/new-page',
    },
  },
});
```

## Когда работают middleware?

Middleware из `server/middleware` выполняются перед route handler.

```ts
// server/middleware/01.request-id.ts
export default defineEventHandler((event) => {
  event.context.requestId = crypto.randomUUID();
});
```

Если middleware вернет значение, обработка остановится, и это значение станет response. Поэтому middleware обычно ничего не возвращают.

## Как выбирается route handler?

Nitro сопоставляет URL с file-based route или programmatic route.

```txt
server/routes/api/users/[id].get.ts
  -> GET /api/users/:id
```

Если method suffix не совпадает, route не подходит.

## Как формируется response?

Handler может вернуть:

- plain object;
- array;
- string;
- number/boolean;
- `Response`;
- stream;
- redirect/no content helper;
- error.

```ts
export default defineHandler(() => {
  return {
    ok: true,
  };
});
```

H3 автоматически преобразует возвращенное значение в HTTP response.

## Как обрабатываются ошибки?

В handler можно бросить ошибку:

```ts
throw createError({
  statusCode: 404,
  statusMessage: 'User not found',
});
```

В development браузер может получить HTML error page, а в production ошибки обычно отдаются как JSON. Детали зависят от `Accept` headers и среды.

## Мини-шпаргалка

- Каждый запрос получает `H3Event`.
- Route rules применяются до handler.
- Middleware выполняются до route handler.
- Middleware не должен возвращать значение без явной причины.
- Handler возвращает значение, а H3 превращает его в response.
- Ошибки лучше делать через `createError`/HTTP errors, а не случайные строки.
