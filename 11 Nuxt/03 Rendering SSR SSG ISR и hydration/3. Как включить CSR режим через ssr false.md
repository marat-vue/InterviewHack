# Как включить CSR режим через ssr false?

> [!summary]
> CSR-режим в Nuxt включается через `ssr: false`. Тогда приложение работает как SPA: HTML генерируется в браузере, а серверный рендеринг страниц отключается.

## Глобальное отключение SSR

```ts
export default defineNuxtConfig({
  ssr: false,
});
```

Теперь Nuxt-приложение ведет себя как SPA.

## Когда это уместно?

CSR подходит для:

- внутренних dashboards;
- admin panels;
- приложений после login;
- страниц, где SEO не важно;
- heavy client-only tools.

## Что меняется?

При `ssr: false`:

- initial HTML почти пустой;
- контент появляется после загрузки JS;
- `useFetch` выполняется на клиенте;
- SEO для динамического контента хуже;
- server API через `server/api` может продолжать работать, если deployment поддерживает Nitro server.

## Per-route CSR

Можно отключить SSR только для части routes:

```ts
export default defineNuxtConfig({
  routeRules: {
    '/admin/**': { ssr: false },
  },
});
```

Так публичный сайт может быть SSR/SSG, а dashboard - CSR.

## Частая ошибка

Не надо отключать SSR только потому, что появилась ошибка `window is not defined`.

Лучше исправить browser-only код:

```ts
if (import.meta.client) {
  console.log(window.innerWidth);
}
```

## Мини-шпаргалка

- `ssr: false` превращает Nuxt в SPA.
- Это ухудшает SEO для публичного контента.
- Для dashboard CSR может быть нормальным выбором.
- SSR можно отключить per route через `routeRules`.
- Не лечи browser-only ошибки глобальным отключением SSR.
