# Что такое ISR и какую проблему он решает?

> [!summary]
> ISR, или Incremental Static Regeneration, позволяет сочетать скорость статической страницы с периодическим обновлением данных после build. В Next.js это полезно для каталогов, блогов, документации и страниц, где контент должен обновляться, но не обязательно на каждый request.

## Какую проблему решает ISR?

SSG быстрый, но у него есть проблема: если данные изменились, нужно пересобрать сайт.

Представь каталог из 50 000 товаров:

- цена меняется часто;
- пересобирать все страницы долго;
- SSR на каждый request может быть дорогим;
- хочется скорость CDN.

ISR дает компромисс: страница остается статической, но может обновляться по времени или по событию.

## Time-based revalidation

В App Router можно задать revalidate для fetch:

```tsx
export default async function ProductsPage() {
  const products = await fetch('https://api.example.com/products', {
    next: { revalidate: 3600 },
  }).then((res) => res.json())

  return <ProductList products={products} />
}
```

Данные будут считаться свежими в течение часа.

## Route segment revalidate

Можно задать revalidate на уровне route:

```tsx
export const revalidate = 3600

export default async function BlogPage() {
  const posts = await getPosts()
  return <PostList posts={posts} />
}
```

## On-demand revalidation

После мутации можно инвалидировать путь:

```ts
'use server'

import { revalidatePath } from 'next/cache'

export async function createPost(formData: FormData) {
  await db.post.create({ data: { title: String(formData.get('title')) } })
  revalidatePath('/blog')
}
```

Или по тегу:

```tsx
await fetch('https://api.example.com/posts', {
  next: { tags: ['posts'] },
})
```

```ts
revalidateTag('posts')
```

## Что отвечать на собеседовании?

ISR - механизм обновления статически сгенерированных страниц или данных без полной пересборки сайта. Он сохраняет преимущества SSG, но позволяет обновлять контент по времени через `revalidate` или по событию через `revalidatePath` и `revalidateTag`.

## Частые ошибки

- Думать, что ISR обновляет страницу мгновенно для каждого пользователя.
- Использовать ISR для real-time данных.
- Забывать, что `no-store` делает route динамическим.
- Не понимать разницу между path и tag revalidation.
- Использовать слишком маленький revalidate без причины.

## Мини-шпаргалка

- ISR = SSG + обновление.
- `next: { revalidate: 3600 }` - revalidate fetch.
- `export const revalidate = 3600` - revalidate route segment.
- `revalidatePath('/blog')` - обновить путь.
- `revalidateTag('posts')` - обновить данные по тегу.
- Для real-time нужен dynamic rendering или client subscription.
