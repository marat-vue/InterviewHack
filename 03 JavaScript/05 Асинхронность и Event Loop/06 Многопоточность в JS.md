# Многопоточность в JS

> [!NOTE] Коротко
> Основной JavaScript-код выполняется в одном потоке, но для настоящей параллельности можно использовать Web Workers или Worker Threads.

## Вопрос

Почему JavaScript не использует многопоточность напрямую и как тогда выполнять тяжелые задачи?

## Основная идея

JavaScript в браузере исторически работает с DOM. Если бы несколько потоков одновременно меняли один и тот же DOM, пришлось бы постоянно решать проблемы гонок, блокировок и синхронизации.

Поэтому основной JS-поток выполняет код последовательно. Это делает модель проще и предсказуемее.

## Асинхронность не равна многопоточности

```javascript
setTimeout(() => {
  console.log('timer');
}, 0);

console.log('sync');

// sync
// timer
```

Таймер не создает второй поток для вашего JS-кода. Он просто откладывает callback в очередь.

## Где все-таки есть параллельность

Среда выполнения может делать часть работы вне основного потока:

- браузерные Web API;
- сетевые операции;
- таймеры;
- thread pool в Node.js;
- внутренние потоки движка для GC или JIT.

Но ваш callback затем возвращается в основной поток JavaScript.

## Web Worker

```javascript
const worker = new Worker('worker.js');

worker.postMessage({ numbers: [1, 2, 3] });

worker.onmessage = (event) => {
  console.log(event.data);
};
```

Worker выполняет код отдельно от основного потока и общается с ним через сообщения.

## Когда нужен отдельный поток

- тяжелые вычисления;
- обработка больших массивов данных;
- парсинг больших файлов;
- кодирование изображений или видео;
- задачи, которые могут подвесить интерфейс.

## Мини-шпаргалка

```javascript
// Асинхронность:
// не блокируем ожидание

// Многопоточность:
// реально выполняем работу в другом потоке
```
