# Что делает normalize.css

> [!summary]
> **normalize.css** приводит дефолтные стили браузеров к более единообразному виду, не удаляя их полностью. Это более мягкий подход, чем классический reset CSS.

## Главное

Браузеры по умолчанию стилизуют элементы немного по-разному. `normalize.css` старается сделать это поведение более предсказуемым.

```text
browser defaults
  -> normalize.css
  -> more consistent base
  -> project styles
```

## Чем normalize отличается от reset

| Подход | Идея |
| --- | --- |
| Reset CSS | Сбросить дефолтные стили почти до нуля |
| normalize.css | Сохранить полезные дефолты и выровнять различия |

Например, normalize не обязан убирать все отступы у заголовков и списков, если они полезны.

## Когда использовать

- Нужна единая база между браузерами.
- Проект не хочет полностью обнулять все дефолты.
- Команда хочет меньше неожиданных различий в элементах форм, тексте и HTML5-элементах.

## Современный подход

Многие проекты используют не полный normalize, а собственный небольшой base/reset.

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}

body {
  margin: 0;
  font-family: system-ui, sans-serif;
}
```

Важно понимать, какую базу использует проект, а не слепо подключать любую библиотеку.

## Мини-шпаргалка

- normalize.css выравнивает стили браузеров.
- Он мягче, чем reset.
- Сохраняет полезные дефолтные стили.
- Подключается до проектных CSS-правил.
- В современных проектах часто заменяется своим base.css.
