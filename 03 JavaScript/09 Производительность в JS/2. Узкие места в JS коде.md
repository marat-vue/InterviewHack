# Узкие места в JS коде

> [!summary] Коротко
> Узкое место - часть кода или системы, которая ограничивает общую скорость работы приложения.

## Вопрос

Какие основные bottlenecks бывают в JavaScript-коде?

## Определение

Узкое место - самая медленная или самая ограничивающая часть процесса. Оптимизация других частей почти не даст эффекта, пока bottleneck остается прежним.

## Частые узкие места

| Область | Проблема |
| --- | --- |
| CPU | тяжелые вычисления, большие циклы |
| DOM | частые изменения, reflow/repaint |
| Network | много запросов, большие payload |
| Memory | утечки, лишние ссылки |
| Event Loop | long tasks, блокировка main thread |
| Algorithms | плохая сложность на больших данных |

## CPU-bound пример

```javascript
for (let i = 0; i < 1_000_000_000; i++) {
  // тяжелая синхронная работа
}
```

Такой код занимает main thread и делает интерфейс неотзывчивым.

## DOM bottleneck

```javascript
items.forEach((item) => {
  list.innerHTML += `<li>${item}</li>`;
});
```

Многократная перезапись `innerHTML` может быть дорогой. Лучше собрать результат один раз или использовать `DocumentFragment`.

## Как искать узкое место

1. Измерить, а не угадывать.
2. Использовать Performance/Profiler.
3. Найти самые долгие задачи.
4. Проверить объем данных.
5. Оптимизировать конкретную причину.

## Мини-шпаргалка

```text
measure first -> find bottleneck -> optimize bottleneck -> measure again
```
