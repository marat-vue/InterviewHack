# Чем Object отличается от Map?

> [!summary]
> `Object` - обычный JS-объект со строковыми/symbol ключами и prototype-наследованием, а `Map` - специализированная коллекция ключ-значение, где ключом может быть любое значение. Для алгоритмов чаще удобнее `Map`.

## Object как словарь

```ts
const count: Record<string, number> = {}

count.apple = 1
count.apple = (count.apple ?? 0) + 1
```

Работает хорошо для простых строковых ключей.

## Map как словарь

```ts
const count = new Map<string, number>()

count.set('apple', (count.get('apple') ?? 0) + 1)
```

У `Map` явный API и удобный `size`.

## Сравнение

| Критерий | Object | Map |
| --- | --- | --- |
| Ключи | string/symbol | любые значения |
| Размер | `Object.keys(obj).length` | `map.size` |
| Prototype keys | есть риск | нет такого риска |
| Итерация | через `Object.entries` | `for...of map` |
| Алгоритмы | можно | часто удобнее |

## Объектные ключи

```ts
const a = { id: 1 }
const b = { id: 1 }

const map = new Map<object, string>()
map.set(a, 'first')

console.log(map.get(a)) // first
console.log(map.get(b)) // undefined
```

Объекты сравниваются по ссылке, не по содержимому.

## Что отвечать на собеседовании?

Для частот по строкам можно использовать object или `Map`, но `Map` лучше выражает намерение "словарь" и поддерживает ключи любых типов. Object хорош для простых records, особенно когда структура заранее известна. В алгоритмах я обычно выбираю `Map`, чтобы избежать проблем с prototype keys и удобно работать с `size`, `has`, `get`, `set`.

## Частые ошибки

- Использовать object для ключей-объектов и получать `"[object Object]"`.
- Проверять наличие через truthy-value вместо `has`.
- Не учитывать prototype keys.
- Путать `Record<string, T>` и `Map<K, V>`.
- Ожидать value equality для object keys.

## Мини-шпаргалка

- Object - хорошо для known shape.
- Map - хорошо для dynamic dictionary.
- Map keys могут быть любыми.
- Object keys чаще string/symbol.
- `map.size` удобнее.
- Object keys с объектами опасны.
