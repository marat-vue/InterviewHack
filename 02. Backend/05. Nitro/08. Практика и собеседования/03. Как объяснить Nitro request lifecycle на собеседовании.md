# Как объяснить Nitro request lifecycle на собеседовании?

> [!NOTE]
> Лучший ответ про lifecycle должен показать путь запроса: runtime принимает HTTP request, Nitro/H3 создает event, применяются route rules и middleware, выбирается handler, handler возвращает значение, H3 превращает его в response, errors и hooks обрабатываются по lifecycle.

## Короткий ответ

```txt
Request приходит в Nitro runtime.
Nitro создает H3Event.
Сначала применяются routeRules и global middleware.
Потом Nitro матчится на route handler.
Handler читает event, выполняет логику и возвращает значение.
H3 преобразует значение в HTTP response.
Ошибки превращаются в HTTP error response.
```

## Более подробный ответ

```txt
Client request
  -> deployment runtime
  -> Nitro server
  -> H3Event
  -> request hooks
  -> route rules
  -> middleware
  -> route matching
  -> handler
  -> response conversion
  -> response/error hooks
  -> client
```

## Что такое `H3Event`?

`H3Event` - объект текущего запроса. В нем есть:

- request;
- response metadata;
- URL;
- method/path;
- context;
- runtime helpers.

```ts
export default defineHandler((event) => {
  return {
    method: event.method,
    path: event.path,
  };
});
```

## Где работают routeRules?

`routeRules` применяются до handler и позволяют декларативно настроить:

- headers;
- cache;
- SWR;
- redirect;
- proxy;
- CORS;
- basic auth.

Пример:

```ts
routeRules: {
  '/api/**': {
    cors: true,
  },
  '/blog/**': {
    swr: 600,
  },
}
```

## Где работают middleware?

Middleware выполняется до route handler.

```ts
export default defineEventHandler((event) => {
  event.context.requestId = crypto.randomUUID();
});
```

Если middleware возвращает value, обработка останавливается.

## Где handler?

Handler - файл route:

```ts
// server/api/users/[id].get.ts
export default defineEventHandler(async (event) => {
  const id = getRouterParam(event, 'id');

  return userService.findById(id);
});
```

## Как формируется response?

Handler может вернуть:

- object -> JSON;
- string -> text;
- `Response`;
- stream;
- redirect;
- `noContent`;
- error.

## Какие детали добавляют силы ответу?

Можно сказать:

- Nitro code-splits route handlers;
- route middleware должны быть аккуратными, потому что работают на каждый request;
- user-specific endpoints нельзя кешировать без правильного cache key;
- runtime/preset влияет на доступные APIs;
- в Nuxt часть helpers auto-imported.

## Мини-шпаргалка

- Начинай с `Request -> H3Event -> middleware -> handler -> response`.
- Упомяни route rules до handler.
- Упомяни `event.context`.
- Упомяни automatic response conversion.
- Упомяни error handling через HTTP errors.
- Добавь, что deployment preset влияет на runtime behavior.
