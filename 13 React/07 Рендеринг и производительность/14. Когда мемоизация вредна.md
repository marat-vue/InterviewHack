# Когда мемоизация вредна?

> [!summary]
> Мемоизация вредна, когда ее стоимость выше пользы: компонент дешевый, зависимости меняются каждый render, код становится сложнее или появляется риск stale closure. `memo`, `useMemo` и `useCallback` - инструменты точечной оптимизации, а не стиль написания всего React-кода.

## Почему мемоизация не бесплатна?

React должен:

- сохранить предыдущее значение;
- сохранить зависимости;
- сравнить зависимости;
- иногда выполнить дополнительную функцию сравнения props;
- удерживать больше объектов в памяти.

Если вычисление дешевое, проверка кэша может быть дороже самого вычисления.

```jsx
// Лишнее усложнение
const title = useMemo(() => `${firstName} ${lastName}`, [firstName, lastName])

// Лучше
const title = `${firstName} ${lastName}`
```

## Случай 1: компонент слишком простой

```jsx
const Label = memo(function Label({ text }) {
  return <span>{text}</span>
})
```

`span` рендерится быстро, а `memo` добавляет сравнение props. Такой код редко дает пользу.

## Случай 2: props всегда новые

```jsx
const UserCard = memo(function UserCard({ user, onOpen }) {
  return <button onClick={onOpen}>{user.name}</button>
})

function Page() {
  return (
    <UserCard
      user={{ name: 'Ada' }}
      onOpen={() => console.log('open')}
    />
  )
}
```

Здесь `memo` почти бесполезен: `user` и `onOpen` каждый раз новые.

## Случай 3: неверные зависимости

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  const alertCount = useCallback(() => {
    alert(count)
  }, []) // ошибка: count не указан
}
```

Функция запомнит старый `count`. Такой баг бывает неприятнее, чем лишний render.

## Случай 4: custom compare скрывает изменения

```jsx
const Row = memo(
  function Row({ user, isSelected }) {
    return <div className={isSelected ? 'selected' : ''}>{user.name}</div>
  },
  (prev, next) => prev.user.id === next.user.id,
)
```

Если `isSelected` изменится, компонент может не обновиться, потому что сравнение смотрит только на `user.id`.

## Случай 5: архитектурная проблема замаскирована memo

Иногда лучше не мемоизировать все подряд, а изменить поток данных:

- держать state ближе к месту использования;
- не класть локальные данные в глобальный store;
- разбить большой context на несколько маленьких;
- вынести тяжелый список в отдельный компонент;
- нормализовать данные.

## Как принимать решение?

Хороший порядок:

```text
1. Написать простой код
2. Проверить UX
3. Измерить через Profiler
4. Найти конкретное узкое место
5. Добавить memo/useMemo/useCallback точечно
6. Проверить, стало ли лучше
```

## Мини-шпаргалка

- Мемоизация добавляет накладные расходы.
- Она полезна не всегда, а в конкретных горячих местах.
- Нестабильные props делают `memo` бесполезным.
- Неверные зависимости создают stale closure.
- Сначала измеряй, потом оптимизируй.
