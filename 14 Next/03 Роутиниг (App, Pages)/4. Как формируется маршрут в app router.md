# Как формируется маршрут в app router?

> [!summary]
> В App Router маршрут формируется как путь от папки `app` до ближайшего `page.tsx`. Папки становятся сегментами URL, а специальные файлы внутри сегмента управляют layout, loading, errors, not found и HTTP endpoints.

## Базовое правило

```text
app/
  page.tsx
  blog/
    page.tsx
  blog/
    [slug]/
      page.tsx
```

Результат:

- `app/page.tsx` -> `/`;
- `app/blog/page.tsx` -> `/blog`;
- `app/blog/[slug]/page.tsx` -> `/blog/:slug`.

## page.tsx делает маршрут публичным

Папка без `page.tsx` не обязана быть доступной страницей.

```text
app/
  dashboard/
    layout.tsx
    settings/
      page.tsx
```

Здесь `/dashboard/settings` существует, а `/dashboard` не обязательно существует, если нет `dashboard/page.tsx`.

## Специальные файлы сегмента

```text
app/
  dashboard/
    layout.tsx
    loading.tsx
    error.tsx
    page.tsx
```

| Файл | Роль |
|---|---|
| `page.tsx` | UI страницы |
| `layout.tsx` | persistent wrapper |
| `loading.tsx` | fallback во время загрузки |
| `error.tsx` | error boundary сегмента |
| `not-found.tsx` | 404 UI |
| `route.ts` | HTTP handler вместо страницы |

## Route groups не попадают в URL

```text
app/
  (marketing)/
    about/
      page.tsx
```

URL:

```text
/about
```

## Что отвечать на собеседовании?

В App Router Next.js строит URL из папок внутри `app`, но маршрут становится публичным только при наличии `page.tsx`. Специальные файлы в сегменте не добавляют URL сами по себе, а описывают поведение route: layout, loading, error, not found или route handler.

## Частые ошибки

- Считать `layout.tsx` страницей.
- Создавать `route.ts` и `page.tsx` для одного и того же route handler сценария без понимания.
- Ждать URL-сегмент от route group.
- Забывать `page.tsx` в конечной папке.
- Делать глубокую структуру без продуктовой причины.

## Мини-шпаргалка

- Путь строится от `app`.
- Папка = URL segment.
- `page.tsx` = страница.
- `(group)` не входит в URL.
- `[slug]` входит как dynamic param.
- `layout.tsx` оборачивает детей.
