# Как бороться с cache stampede, TTL jitter, locks и stale-while-revalidate?

> [!NOTE]
> Cache stampede возникает, когда много запросов одновременно получают cache miss и все идут в БД. Redis ускоряет систему, но без защиты cache может усилить нагрузку при массовом истечении TTL.

## Что такое cache stampede?

```txt
10 000 requests
  -> key expired
  -> 10 000 DB queries
  -> database overload
```

Это часто происходит с популярными ключами и одинаковым TTL.

## TTL jitter

Добавляй случайный разброс TTL:

```ts
function ttlWithJitter(baseSeconds: number, jitterSeconds: number) {
  return baseSeconds + Math.floor(Math.random() * jitterSeconds);
}

await redis.set(key, JSON.stringify(value), {
  EX: ttlWithJitter(300, 60),
});
```

Так ключи не истекают одновременно.

## Lock на rebuild

```ts
async function getCachedProduct(id: string) {
  const key = `cache:product:${id}`;
  const cached = await redis.get(key);

  if (cached) {
    return JSON.parse(cached);
  }

  const lockKey = `lock:rebuild:${key}`;
  const lockValue = crypto.randomUUID();

  const locked = await redis.set(lockKey, lockValue, {
    NX: true,
    PX: 10_000,
  });

  if (!locked) {
    await new Promise((resolve) => setTimeout(resolve, 50));
    const retry = await redis.get(key);

    if (retry) {
      return JSON.parse(retry);
    }
  }

  const fresh = await db.product.findUnique({
    where: {
      id,
    },
  });

  await redis.set(key, JSON.stringify(fresh), {
    EX: ttlWithJitter(300, 60),
  });

  return fresh;
}
```

В production lock release нужно делать безопасно: удалять lock только если value совпадает.

## Stale-while-revalidate

Идея:

- храни value дольше, чем freshness TTL;
- если value stale, отдай старое быстро;
- обнови cache в фоне.

Пример shape:

```ts
type CacheEntry<T> = {
  value: T;
  freshUntil: number;
};
```

```ts
if (entry && entry.freshUntil > Date.now()) {
  return entry.value;
}

if (entry) {
  event.waitUntil?.(refreshCache());
  return entry.value;
}
```

## Какие endpoint-ы особенно уязвимы?

- home page data;
- catalog;
- popular product;
- expensive aggregations;
- dashboard metrics;
- external API proxy;
- search suggestions.

## Мини-шпаргалка

- Stampede = массовый miss по популярному ключу.
- TTL jitter уменьшает синхронное истечение.
- Lock ограничивает rebuild одним worker-ом.
- SWR отдает stale быстро и обновляет в фоне.
- Locks должны иметь TTL и unique token.
