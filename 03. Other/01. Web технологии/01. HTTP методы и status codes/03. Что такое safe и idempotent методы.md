# Что такое safe и idempotent методы?

> [!summary]
> Safe method не должен менять состояние сервера. Idempotent method можно повторить несколько раз, и итоговое состояние будет таким же, как после одного запроса. Эти свойства важны для кеширования, retries и проектирования REST API.

## Safe methods

Safe method предназначен для чтения.

```http
GET /api/articles
HEAD /api/articles/1
OPTIONS /api/articles/1
```

`GET` может писать технические логи или метрики, но не должен создавать заказ, списывать деньги или менять профиль пользователя.

Плохой пример:

```http
GET /api/orders/create?productId=10
```

Такой endpoint опасен: browser, crawler, prefetch или cache layer могут выполнить `GET`, не ожидая изменения данных.

## Idempotent methods

Idempotent значит: один и тот же запрос можно повторить, а результат в системе останется тем же.

```http
PUT /api/users/1

{
  "name": "Anna"
}
```

Если отправить этот `PUT` пять раз, имя все равно будет `Anna`.

`DELETE /users/1` тоже обычно idempotent по смыслу: после первого удаления пользователя уже нет, после повторного он все еще отсутствует. Но конкретный status code может отличаться: первый раз `204`, второй раз `404` или тоже `204`.

## POST обычно не idempotent

```http
POST /api/orders

{
  "productId": 10
}
```

Если отправить такой запрос дважды, можно создать два заказа.

Для платежей и заказов часто добавляют idempotency key:

```http
POST /api/payments
Idempotency-Key: 5f7f8f6e-4d53-4c37-9f4f-1f9df5a1c101
```

Server запоминает ключ и не выполняет одну и ту же операцию повторно.

## Таблица

| Метод | Safe | Idempotent |
|---|---:|---:|
| `GET` | да | да |
| `HEAD` | да | да |
| `OPTIONS` | да | да |
| `PUT` | нет | да |
| `PATCH` | нет | зависит от реализации |
| `DELETE` | нет | обычно да |
| `POST` | нет | обычно нет |

## Мини-шпаргалка

- Safe - не меняет состояние.
- Idempotent - повтор не меняет итоговое состояние.
- `GET` не должен выполнять действия.
- `POST` может создать дубликаты при retry.
- Idempotency key нужен для платежей, заказов и других критичных операций.
