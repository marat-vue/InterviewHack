# Компонентный подход

> [!summary]
> Компонентный подход - это способ строить интерфейс из небольших независимых частей. Каждый компонент отвечает за свой фрагмент UI, принимает данные через props и может быть переиспользован в разных местах приложения.

## Что такое компонент в этом подходе?

Компонент можно представить как функцию, которая получает входные данные и возвращает UI.

```jsx
function Button({ children, variant = 'primary', onClick }) {
  return (
    <button className={`button button_${variant}`} onClick={onClick}>
      {children}
    </button>
  )
}
```

Использование:

```jsx
<Button onClick={saveUser}>Save</Button>
<Button variant="secondary" onClick={cancel}>Cancel</Button>
```

Один компонент описывает общий внешний вид и поведение кнопки, а конкретный текст и обработчик приходят снаружи.

## Из чего складывается компонентная архитектура?

Обычно компонент содержит или связывает:

- JSX-разметку;
- props;
- локальный state;
- event handlers;
- hooks;
- стили;
- тесты;
- дочерние компоненты.

В хорошей структуре компонент не пытается знать все обо всем приложении. Он решает свою задачу.

## Композиция вместо наследования

React делает ставку на композицию:

```jsx
function PageLayout({ header, sidebar, children }) {
  return (
    <div className="layout">
      <header>{header}</header>
      <aside>{sidebar}</aside>
      <main>{children}</main>
    </div>
  )
}
```

Использование:

```jsx
<PageLayout
  header={<Header />}
  sidebar={<Navigation />}
>
  <ProfilePage />
</PageLayout>
```

Компоненты собираются друг из друга, а не наследуются как классы.

## Почему это масштабируется?

Компонентный подход помогает:

- переиспользовать UI;
- изолировать изменения;
- делить работу между разработчиками;
- тестировать части отдельно;
- строить дизайн-систему;
- легче читать дерево интерфейса.

## Где проходит граница компонента?

Хороший компонент обычно имеет понятную ответственность:

```text
Button - действие
UserCard - отображение пользователя
ProductList - список товаров
CheckoutForm - форма оформления
```

Если компонент называется `Page` и содержит запросы, формы, таблицы, модалки, бизнес-правила и стили для всего экрана, его стоит разделить.

## Мини-шпаргалка

- React-приложение - дерево компонентов.
- Компонент принимает props и возвращает UI.
- Композиция важнее наследования.
- Границы компонентов должны отражать ответственность.
- Переиспользование не должно превращаться в слишком абстрактный компонент.
