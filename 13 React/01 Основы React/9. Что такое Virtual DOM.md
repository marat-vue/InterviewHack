# Что такое Virtual DOM?

> [!summary]
> Virtual DOM - это распространенное объяснение того, что React хранит легковесное описание UI и сравнивает новое описание со старым, чтобы понять, какие изменения нужно применить к настоящему DOM. Важно не сводить React только к Virtual DOM: современный React также опирается на Fiber, scheduling и разные режимы рендеринга.

## Простое объяснение

Компонент возвращает React-элементы:

```jsx
function Title() {
  return <h1>React</h1>
}
```

React получает описание:

```js
{
  type: 'h1',
  props: {
    children: 'React'
  }
}
```

Это не настоящий DOM-узел, а описание того, что нужно показать.

## Зачем это нужно?

Работа с DOM может быть дорогой и неудобной. React позволяет:

- описывать UI декларативно;
- сравнивать старое и новое описание;
- применять только нужные изменения;
- скрыть ручные DOM-операции;
- строить UI из компонентов.

## Что происходит при обновлении?

```text
1. Изменился state или props
2. React вызывает компонент заново
3. Получает новое дерево React-элементов
4. Сравнивает его с предыдущим
5. Применяет изменения к DOM на commit-этапе
```

Этот процесс связан с reconciliation.

## Важный нюанс

Фраза "Virtual DOM делает React быстрым" слишком упрощает реальность.

Правильнее:

```text
Virtual DOM дает React удобную модель декларативного UI. Производительность зависит от reconciliation, структуры компонентов, keys, мемоизации, размера дерева, количества state updates и работы браузера.
```

## Мини-шпаргалка

- Virtual DOM - описание UI в памяти.
- Это не копия DOM один в один, а модель React-элементов.
- При обновлении React сравнивает старый и новый результат render.
- Реальный DOM меняется на commit-этапе.
- Virtual DOM не освобождает от заботы о производительности.
