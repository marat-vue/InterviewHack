# Что такое SAVEPOINT?

> [!summary]
> `SAVEPOINT` создает точку внутри транзакции, к которой можно откатиться, не отменяя всю транзакцию. Это полезно для частичного восстановления после ошибки.

## Пример

```sql
BEGIN;

INSERT INTO orders (id, user_id)
VALUES (1, 10);

SAVEPOINT before_items;

INSERT INTO order_items (order_id, product_id, quantity)
VALUES (1, 999, 1);

ROLLBACK TO SAVEPOINT before_items;

COMMIT;
```

Вставка заказа сохраняется, а неудачные позиции можно откатить.

## Когда полезно?

- пакетная обработка;
- сложные импорты;
- частичный retry;
- тесты;
- миграции с несколькими шагами.

## Не злоупотреблять

`SAVEPOINT` не должен заменять понятную бизнес-логику. Если транзакция становится слишком сложной, возможно, стоит пересмотреть процесс.

## Мини-шпаргалка

- `SAVEPOINT` - точка отката внутри транзакции.
- `ROLLBACK TO SAVEPOINT` откатывает часть действий.
- Вся транзакция остается открытой.
- Полезно для batch-операций.
- Поддержка и поведение могут отличаться по СУБД.
