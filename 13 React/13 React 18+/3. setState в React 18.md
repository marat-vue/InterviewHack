# setState в React 18

> [!summary]
> В React 18 изменилось окружение вокруг state updates: появился automatic batching почти во всех async-контекстах, transitions для несрочных updates и concurrent renderer, который может прерывать render. Сам принцип state остается прежним: setter планирует обновление, а не меняет значение мгновенно.

## Automatic batching

```jsx
function handleClick() {
  setCount((count) => count + 1)
  setFlag((flag) => !flag)
  // один render
}
```

В React 18 batching работает и вне React event handlers:

```jsx
fetch('/api/user').then(() => {
  setUserLoaded(true)
  setStatus('success')
  // React 18: один render
})
```

```jsx
setTimeout(() => {
  setCount((count) => count + 1)
  setFlag(true)
  // React 18: один render
}, 1000)
```

## State все еще не меняется мгновенно

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  function handleClick() {
    setCount(count + 1)
    console.log(count) // старое значение из текущего render
  }
}
```

Если нужно несколько updates от предыдущего значения, используй functional update:

```jsx
setCount((count) => count + 1)
setCount((count) => count + 1)
setCount((count) => count + 1)
```

## Transitions

```jsx
const [isPending, startTransition] = useTransition()

function selectTab(tab) {
  startTransition(() => {
    setTab(tab)
  })
}
```

Такой update получает меньший приоритет. React может отложить его, если нужно сначала обработать срочное действие.

## Render может быть прерван

Concurrent renderer может начать render, понять, что пришло более важное обновление, и выбросить незавершенную работу.

Поэтому render должен быть чистым:

```jsx
function Page() {
  // Нельзя делать side effects здесь
  return <main />
}
```

## flushSync

Если нужно синхронно обновить DOM, есть escape hatch:

```jsx
import { flushSync } from 'react-dom'

flushSync(() => {
  setOpen(true)
})

dialogRef.current.focus()
```

Использовать редко: `flushSync` ухудшает планирование React.

## Мини-шпаргалка

- React 18 расширил automatic batching.
- Setter планирует update, а не меняет переменную текущего render.
- Functional update защищает от stale state.
- Transition updates имеют меньший приоритет.
- `flushSync` нужен только для редких интеграций с DOM.
