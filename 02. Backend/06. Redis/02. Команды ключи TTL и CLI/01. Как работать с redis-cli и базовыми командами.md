# Как работать с redis-cli и базовыми командами?

> [!NOTE]
> `redis-cli` - главный инструмент ручной проверки Redis. На собеседовании и в production debugging важно уметь подключиться, проверить ключ, TTL, тип значения, memory и slow commands.

## Как подключиться?

Локально:

```bash
redis-cli
```

Через Docker:

```bash
docker exec -it interviewhack-redis redis-cli
```

С URL:

```bash
redis-cli -u redis://default:password@localhost:6379
```

С TLS-managed Redis часто используют `rediss://`.

## Какие команды проверить первыми?

```redis
PING
SET hello world
GET hello
DEL hello
EXISTS hello
```

Ответ `PONG` на `PING` означает, что Redis доступен и отвечает.

## Как посмотреть тип ключа?

```redis
TYPE user:1
```

Типы:

```txt
string
list
set
zset
hash
stream
none
```

`none` значит, что ключ не существует.

## Как работать с TTL?

```redis
SET session:abc user-1 EX 3600
TTL session:abc
PERSIST session:abc
EXPIRE session:abc 60
```

`TTL`:

- `> 0` - осталось секунд;
- `-1` - ключ есть, TTL нет;
- `-2` - ключа нет.

## Как выбрать базу?

```redis
SELECT 0
SELECT 1
```

В Redis Cluster доступна только database `0`, поэтому не строй архитектуру на `SELECT` как на namespace. Лучше используй prefixes.

## Как вывести server info?

```redis
INFO
INFO memory
INFO clients
INFO stats
INFO replication
```

`INFO` полезен для диагностики:

- memory;
- connected clients;
- command stats;
- replication state;
- persistence state;
- CPU.

## Как безопасно искать ключи?

Локально можно:

```redis
KEYS user:*
```

В production лучше:

```redis
SCAN 0 MATCH user:* COUNT 100
```

`SCAN` возвращает cursor. Нужно повторять, пока cursor не станет `0`.

## Мини-шпаргалка

- `PING` - проверка связи.
- `TYPE` - тип ключа.
- `TTL` - время жизни.
- `INFO memory` - память.
- `SCAN` - безопасный обход.
- `KEYS` не использовать на production hot path.
