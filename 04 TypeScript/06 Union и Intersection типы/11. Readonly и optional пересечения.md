# Readonly и optional пересечения

> [!summary] Коротко
> При пересечении объектных типов TypeScript объединяет требования к полям. `readonly`, обязательность и тип значения могут влиять на итоговый тип неожиданно.

## Вопрос

Как ведут себя `readonly` и optional-поля при intersection?

## Обязательное плюс опциональное

Если одно и то же поле в одном типе обязательное, а в другом опциональное, итоговое поле обычно становится обязательным.

```typescript
type A = { name?: string };
type B = { name: string };

type C = A & B;

const user: C = { name: "Анна" };
```

Логика такая: значение должно удовлетворять обоим типам, а `B` требует `name`.

## Совместимые типы поля

```typescript
type A = { value?: string | number };
type B = { value: string };

type C = A & B;
// value: string
```

Итоговый тип поля становится пересечением требований.

## Несовместимые типы поля

```typescript
type A = { id: string };
type B = { id: number };

type C = A & B;
// id: never
```

Такой тип практически невозможно создать корректно.

## Readonly

Если одно пересекаемое требование говорит, что поле readonly, итоговый тип может вести себя как readonly в местах записи.

```typescript
type A = { readonly id: string };
type B = { name: string };

type C = A & B;

const value: C = { id: "1", name: "Анна" };
// value.id = "2"; // ошибка
```

## Мини-шпаргалка

- Intersection объединяет требования.
- Обязательное поле сильнее опционального.
- Несовместимые типы поля приводят к `never`.
- Конфликты в intersection лучше замечать рано и упрощать модель.
