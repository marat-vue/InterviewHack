# Как Google обрабатывает JavaScript?

> [!summary]
> Google умеет обрабатывать JavaScript, но это не означает, что любой SPA автоматически будет идеально индексироваться. Чем больше важного контента зависит от JS, тем внимательнее нужно проверять rendered HTML, скорость и маршрутизацию.

## Упрощенная схема

```text
1. Googlebot скачивает HTML
2. Находит ссылки и ресурсы
3. Может поставить страницу в очередь на рендеринг
4. Выполняет JavaScript
5. Анализирует итоговый DOM
6. Индексирует подходящий контент
```

## Что может пойти не так?

- JS-файл закрыт в robots.txt.
- Bundle слишком тяжелый.
- API недоступен для робота.
- Контент появляется после пользовательского действия.
- Ошибка JS ломает рендер.
- Meta tags меняются только на клиенте и слишком поздно.
- Ссылки не являются настоящими `<a href>`.

## Как проверять?

Проверяй не только исходный код страницы, но и rendered HTML:

- URL Inspection в Search Console;
- Rich Results Test;
- Mobile-Friendly/рендеринг-инструменты;
- `view-source` плюс DevTools Elements;
- серверный HTML при SSR/SSG.

## Лучший подход для важных SEO-страниц

Если страница должна привлекать органический трафик, лучше чтобы основной контент был доступен без ожидания тяжелого client-side рендера.

Подходы:

- SSR для динамических страниц;
- SSG для статических страниц;
- ISR/SWR для часто обновляемого контента;
- prerender для ограниченного набора SPA-маршрутов.

## Мини-шпаргалка

- Google может выполнять JS, но это дополнительный этап.
- Важный контент лучше отдавать в HTML.
- JS и API должны быть доступны роботу.
- Проверяй rendered HTML.
- Настоящие ссылки важны для discovery.
