# Server Components в React 19

> [!summary]
> В React 19 APIs для React Server Components стали стабильными для библиотек и фреймворков. Но RSC по-прежнему требуют framework/bundler integration: это не функция, которую можно просто включить в любой SPA. Главная польза RSC - меньше клиентского JavaScript, серверный доступ к данным и более четкое разделение server/client boundaries.

## Что изменилось в React 19?

React Server Components начали развиваться раньше, но в React 19 важная часть API стала стабильной.

Это означает:

- фреймворки могут строить production-интеграции поверх стабильных API;
- Server Components, Server Functions и directives имеют официальную модель;
- React документирует server/client boundaries как часть платформы.

Но это не означает, что в обычном Vite SPA можно просто написать `async function Component()` и получить RSC. Нужна поддержка фреймворка.

## Что такое server/client boundary?

Server Component выполняется на сервере:

```jsx
async function ProductsPage() {
  const products = await db.product.findMany()

  return (
    <main>
      <h1>Products</h1>
      <ProductGrid products={products} />
    </main>
  )
}
```

Client Component начинается с директивы:

```jsx
'use client'

import { useState } from 'react'

export function AddToCartButton({ productId }) {
  const [isAdded, setIsAdded] = useState(false)

  return (
    <button onClick={() => setIsAdded(true)}>
      {isAdded ? 'Added' : 'Add to cart'}
    </button>
  )
}
```

Если поставить `'use client'` в большом верхнем компоненте, вся его ветка станет клиентской. Поэтому границу клиента держат как можно ниже.

## Server Functions и 'use server'

React 19 также документирует Server Functions. Функцию можно пометить директивой:

```jsx
'use server'

export async function createProduct(formData) {
  const title = formData.get('title')

  await db.product.create({
    data: { title },
  })
}
```

Во фреймворке такую функцию можно связать с формой:

```jsx
import { createProduct } from './actions'

export default function ProductForm() {
  return (
    <form action={createProduct}>
      <input name="title" />
      <button>Create</button>
    </form>
  )
}
```

Важно: Server Functions - это не "просто импорт серверной функции в браузер". Фреймворк превращает вызов в безопасное клиент-серверное взаимодействие.

## RSC и безопасность

Server Components помогают держать секреты на сервере:

```jsx
async function BillingPage() {
  const invoices = await stripe.invoices.list({
    customer: process.env.STRIPE_CUSTOMER_ID,
  })

  return <Invoices invoices={invoices.data} />
}
```

Такой код не должен попадать в клиентский bundle.

Но RSC не отменяют правила безопасности:

- проверяй права пользователя на сервере;
- валидируй входные данные;
- не передавай секреты в props клиентских компонентов;
- считай Server Function публичной точкой входа, которую надо защищать.

## RSC и производительность

RSC помогают:

- уменьшить client bundle;
- убрать лишние client-side запросы;
- рендерить данные ближе к БД;
- не отправлять тяжелые server-only зависимости в браузер;
- комбинировать streaming и Suspense.

Но RSC не решают автоматически:

- плохие SQL-запросы;
- отсутствие кеширования;
- медленный backend;
- слишком большие JSON payload;
- плохую архитектуру client boundaries.

## Когда использовать Server Components?

Хорошие кандидаты:

- страницы каталога;
- профили;
- dashboard summaries;
- markdown/content pages;
- серверная навигация;
- чтение данных из БД;
- компоненты без интерактивности.

Client Components нужны для:

- форм с локальным состоянием;
- dropdown;
- модалок;
- drag and drop;
- `useState`, `useEffect`, `useRef`;
- browser API;
- обработчиков событий.

## Что отвечать на собеседовании?

В React 19 Server Components получили стабильную официальную модель для фреймворков. Они выполняются на сервере, не отправляют свой код клиенту и позволяют читать данные на сервере. Для интерактивности нужна граница `'use client'`, для серверных мутаций - Server Functions с `'use server'`. RSC требуют framework/bundler support.

## Частые ошибки

- Говорить, что RSC полностью заменяют SSR.
- Считать, что RSC работают без фреймворка.
- Ставить `'use client'` в корневой layout без необходимости.
- Передавать server-only объекты в Client Components.
- Забывать авторизацию и валидацию в Server Functions.

## Мини-шпаргалка

- React 19 стабилизировал RSC APIs для фреймворков.
- Server Component code не едет в браузер.
- Client boundary задается через `'use client'`.
- Server Functions помечаются через `'use server'`.
- Нужна интеграция фреймворка и сборщика.
- Безопасность все равно остается обязанностью разработчика.
