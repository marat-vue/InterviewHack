# Как использовать transactions MULTI, EXEC, WATCH и DISCARD?

> [!NOTE]
> Redis transactions позволяют поставить несколько команд в очередь и выполнить их подряд через `EXEC`. Это не SQL-транзакции с rollback, поэтому важно понимать ограничения.

## Как выглядит базовая transaction?

```redis
MULTI
SET user:1:name Marat
INCR stats:users-updated
EXEC
```

После `MULTI` Redis не выполняет команды сразу, а ставит их в очередь. `EXEC` выполняет очередь.

## Что делает DISCARD?

```redis
MULTI
SET a 1
SET b 2
DISCARD
```

`DISCARD` отменяет очередь до `EXEC`.

## Есть ли rollback?

SQL-style rollback нет. Если команда внутри `EXEC` завершилась ошибкой из-за типа данных, другие команды могут уже выполниться.

Например:

```redis
SET user:1:name Marat
MULTI
INCR user:1:name
SET audit:last update
EXEC
```

`INCR` даст ошибку, потому что value не число, но соседняя команда может выполниться. Поэтому validation и правильная модель ключей важны.

## Что делает WATCH?

`WATCH` включает optimistic locking:

```redis
WATCH account:1:balance
GET account:1:balance
MULTI
SET account:1:balance 900
EXEC
```

Если другой клиент изменил watched key до `EXEC`, transaction не выполнится.

## Пример optimistic update в Node.js

```ts
async function decrementStock(productId: string) {
  const key = `stock:${productId}`;

  while (true) {
    await redis.watch(key);

    const current = Number(await redis.get(key));

    if (current <= 0) {
      await redis.unwatch();
      return false;
    }

    const result = await redis
      .multi()
      .set(key, String(current - 1))
      .exec();

    if (result !== null) {
      return true;
    }
  }
}
```

На практике для decrement лучше использовать атомарный Lua script, чтобы не гонять retry-loop между клиентом и сервером.

## Когда использовать transactions?

Transactions подходят:

- для простой группы команд;
- когда нужно выполнить commands подряд;
- когда optimistic lock достаточно прост;
- когда не нужна сложная branching logic.

Для сложной атомарной логики лучше Lua.

## Мини-шпаргалка

- `MULTI` - начать очередь.
- `EXEC` - выполнить очередь.
- `DISCARD` - отменить очередь.
- `WATCH` - optimistic locking.
- Redis transaction не SQL transaction.
- Rollback выполненных команд нет.
- Lua часто лучше для сложных атомарных операций.
