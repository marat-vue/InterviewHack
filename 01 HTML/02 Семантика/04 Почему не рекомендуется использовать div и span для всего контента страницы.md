# Почему не рекомендуется использовать div и span для всего контента страницы?

> [!NOTE]
> `div` и `span` не несут собственного смысла. Если использовать их для всего, страница становится менее понятной для браузера, скринридеров, поисковых систем и разработчиков.

## Главное

`div` и `span` - нейтральные контейнеры. Они полезны для группировки и стилизации, но не должны заменять семантические элементы.

```html
<!-- плохо -->
<div class="title">Контакты</div>
<div class="button">Отправить</div>

<!-- лучше -->
<h1>Контакты</h1>
<button type="submit">Отправить</button>
```

## Что теряется при div-верстке

- Нативное поведение элементов.
- Клавиатурная доступность.
- Понятная структура документа.
- Навигация по landmarks и заголовкам.
- Читаемость кода.
- Дополнительный контекст для SEO.

## Пример с кнопкой

```html
<!-- плохо -->
<div class="button" onclick="save()">Сохранить</div>
```

Такой элемент не является кнопкой для браузера. Его нужно вручную дорабатывать: `tabindex`, обработка клавиш, ARIA-роль.

```html
<!-- лучше -->
<button type="button">Сохранить</button>
```

`button` уже имеет нужное поведение по умолчанию.

## Когда div и span уместны

`div` подходит для нейтрального блочного контейнера, а `span` - для небольшого inline-фрагмента без отдельного смысла.

```html
<div class="card">
  <p>Цена: <span class="price">1990 ₽</span></p>
</div>
```

Здесь `div` и `span` используются для структуры и стилизации, а не вместо смысловых элементов.

## Мини-шпаргалка

- `div` и `span` семантически нейтральны.
- Не заменяй ими `button`, `a`, `h1`, `nav`, `main`, `form`.
- Нативные элементы дают готовое поведение.
- Нейтральные контейнеры нужны, но не для всего подряд.
- Сначала выбирай тег по смыслу, потом добавляй CSS.
