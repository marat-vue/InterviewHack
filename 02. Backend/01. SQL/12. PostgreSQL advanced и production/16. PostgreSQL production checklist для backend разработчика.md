# PostgreSQL production checklist для backend-разработчика

> [!NOTE]
> Production PostgreSQL - это не только SQL-запросы. Backend-разработчик должен понимать connection limits, indexes, migrations, backups, autovacuum, security, observability и retry-поведение приложения.

## Schema

- primary keys есть;
- foreign keys осознанны;
- `NOT NULL` стоит там, где поле обязательно;
- `CHECK` constraints фиксируют простые invariants;
- indexes соответствуют реальным запросам;
- JSONB не заменяет всю relational модель;
- migrations backward-compatible.

## Queries

- нет N+1;
- pagination не ломается на больших offset;
- user input параметризован;
- slow queries проверены через `EXPLAIN (ANALYZE, BUFFERS)`;
- transactions короткие;
- retry есть для serialization/deadlock errors.

## Connections

- app pool настроен;
- pool size считается по всем replicas;
- PgBouncer нужен при большом числе clients;
- timeouts заданы;
- idle transactions мониторятся;
- migrations используют отдельную role.

## Maintenance

- autovacuum не выключен;
- `ANALYZE` работает;
- bloat мониторится;
- long transactions отслеживаются;
- backup свежий;
- restore проверен;
- PITR настроен, если нужен.

## Security

- app user не superuser;
- least privilege;
- RLS для multi-tenant, если нужно;
- secrets в secret manager;
- SQL injection закрыта параметрами;
- audit для чувствительных операций.

## Observability

- slow query log;
- query latency;
- connection count;
- locks/deadlocks;
- replication lag;
- cache hit ratio;
- table/index size;
- autovacuum activity.

## Мини-шпаргалка

- Хорошая БД защищает invariants, а не только хранит строки.
- Индекс без запроса бессмыслен.
- Backup без restore drill не считается.
- Long transactions вредят vacuum.
- Runtime role и migration role разделяй.
