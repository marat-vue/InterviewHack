# Что нового про API use (чтение ресурсов, Promise и т.д.)?

> [!summary]
> `use` - React API для чтения context или Promise прямо во время render. В отличие от обычных хуков, `use` можно вызывать в условиях и циклах, но он все равно должен вызываться во время render компонента или хука. При чтении Promise компонент suspends, поэтому нужен `Suspense`.

## Что умеет use?

`use` умеет читать два типа значений:

- context;
- Promise.

```jsx
import { use } from 'react'
```

## use(context)

`use(context)` похож на `useContext`, но его можно вызывать условно.

```jsx
import { createContext, use } from 'react'

const ThemeContext = createContext('light')

function Button({ shouldUseTheme }) {
  if (shouldUseTheme) {
    const theme = use(ThemeContext)
    return <button className={theme}>Save</button>
  }

  return <button>Save</button>
}
```

Обычный `useContext` нельзя было бы вызывать внутри `if`, потому что хуки должны вызываться в одном порядке.

## use(promise)

`use(promise)` читает результат Promise.

```jsx
import { Suspense, use } from 'react'

function UserName({ userPromise }) {
  const user = use(userPromise)

  return <h2>{user.name}</h2>
}

function Page({ userPromise }) {
  return (
    <Suspense fallback={<p>Loading user...</p>}>
      <UserName userPromise={userPromise} />
    </Suspense>
  )
}
```

Если Promise pending, компонент приостанавливает render, а ближайший `Suspense` показывает fallback.

## Почему не стоит просто создавать Promise в render?

Плохой пример:

```jsx
function UserName({ userId }) {
  const user = use(fetch(`/api/users/${userId}`).then((res) => res.json()))

  return <h2>{user.name}</h2>
}
```

Если Promise создается заново при каждом render, можно получить повторные запросы и нестабильное поведение.

Лучше использовать:

- Server Component с `async/await`;
- cache/framework data layer;
- Promise, созданный выше и переданный в компонент;
- Suspense-enabled библиотеку данных.

## use в Server Components

В Server Components часто проще использовать `await`:

```jsx
async function UserPage({ userId }) {
  const user = await db.user.findUnique({ where: { id: userId } })

  return <h1>{user.name}</h1>
}
```

`use` полезен там, где нужно читать Promise в компонентной модели, но в серверном коде `async/await` часто понятнее.

## use в Client Components

Client Component может читать Promise через `use`, но обычно Promise должен быть стабильным и созданным вне render или переданным сверху.

```jsx
'use client'

import { use } from 'react'

function Message({ messagePromise }) {
  const message = use(messagePromise)

  return <p>{message}</p>
}
```

На практике такие сценарии часто контролирует фреймворк.

## use и Suspense

Без `Suspense` pending Promise некуда "поймать":

```jsx
<Suspense fallback={<MessageSkeleton />}>
  <Message messagePromise={messagePromise} />
</Suspense>
```

Если Promise rejected, нужен Error Boundary:

```jsx
<ErrorBoundary fallback={<p>Could not load message</p>}>
  <Suspense fallback={<p>Loading...</p>}>
    <Message messagePromise={messagePromise} />
  </Suspense>
</ErrorBoundary>
```

## use - это хук?

Несмотря на название, `use` имеет особые правила.

Похоже на хуки:

- вызывается во время render;
- нельзя вызывать в произвольной callback-функции;
- нельзя вызывать после `await` вне component render logic.

Отличается от хуков:

- можно вызывать в `if`;
- можно вызывать в циклах;
- можно читать context условно.

## Что отвечать на собеседовании?

`use` - React API для чтения Promise или Context во время render. При чтении Promise React приостанавливает компонент и использует ближайший Suspense fallback. `use(context)` можно вызывать условно, в отличие от `useContext`. В реальных проектах важно не создавать нестабильные Promise прямо в render.

## Частые ошибки

- Создавать новый `fetch()` прямо внутри render.
- Забывать про `Suspense`.
- Забывать про Error Boundary для rejected Promise.
- Думать, что `use` полностью заменяет data fetching библиотеку.
- Путать `use` с обычными хуками и их правилами.

## Мини-шпаргалка

- `use(context)` читает context.
- `use(promise)` читает результат Promise.
- Pending Promise вызывает Suspense.
- Rejected Promise должен попасть в Error Boundary.
- `use` можно вызывать в условиях и циклах.
- Не создавай нестабильные Promise в render.
