# Чем Jest отличается от Vitest?

> [!summary]
> Jest - зрелый и широко распространенный test runner, а Vitest - современный runner, глубоко интегрированный с Vite. Для Vite/Vue проектов чаще удобнее Vitest, для старых проектов и многих backend/NestJS кодовых баз часто встречается Jest.

## Главное отличие

Vitest создавался под Vite-экосистему:

- читает Vite config;
- хорошо работает с Vite plugins;
- удобен для ESM;
- быстрее вписывается в Vue/Vite проекты.

Jest появился раньше и имеет огромную экосистему:

- много готовых гайдов;
- часто используется в enterprise;
- встречается в NestJS;
- привычен многим командам.

## Сравнение

| Критерий | Vitest | Jest |
|---|---|---|
| Vite integration | сильная | ограниченная |
| API | похож на Jest | классический |
| mocks | `vi` | `jest` |
| snapshots | есть | есть |
| coverage | есть | есть |
| legacy adoption | ниже | выше |
| Vue/Vite DX | обычно лучше | сложнее |

## Пример похожего API

Vitest:

```ts
import { expect, test, vi } from 'vitest';

const fn = vi.fn();
```

Jest:

```ts
const fn = jest.fn();

test('works', () => {
  expect(fn).not.toHaveBeenCalled();
});
```

## Что выбрать в новом проекте?

Если проект на Vite/Vue, разумный выбор - Vitest.

Если проект уже на Jest, миграция нужна только при реальной пользе:

- медленные тесты;
- боль с ESM;
- сложная Vite-интеграция;
- желание унифицировать frontend toolchain.

## Мини-шпаргалка

- Vitest лучше ложится на Vite.
- Jest чаще встречается в старых и backend-проектах.
- API похож, но mocks называются `vi` и `jest`.
- Для Vue/Vite чаще выбирают Vitest.
- На собеседовании важно знать оба инструмента на уровне концепций.
