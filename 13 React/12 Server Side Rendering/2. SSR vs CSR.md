# SSR vs CSR

> [!summary]
> CSR рендерит интерфейс в браузере после загрузки JavaScript. SSR рендерит HTML на сервере до отправки ответа. Главное различие - где появляется первый осмысленный HTML: на клиенте или на сервере.

## CSR

CSR, или Client-Side Rendering:

```text
Server sends HTML shell -> browser downloads JS -> React renders UI
```

HTML:

```html
<div id="root"></div>
<script src="/app.js"></script>
```

Плюсы:

- простая раздача статики;
- дешево хостить на CDN;
- быстрые переходы внутри SPA;
- удобно для admin/dashboard приложений;
- меньше серверной логики.

Минусы:

- первый контент зависит от загрузки JS;
- хуже для SEO без дополнительных техник;
- на слабых устройствах старт может быть медленным;
- social preview может быть пустым.

## SSR

SSR, или Server-Side Rendering:

```text
Browser requests page -> server renders HTML -> browser paints content -> hydration
```

HTML:

```html
<div id="root">
  <h1>Product title</h1>
  <p>Product description</p>
</div>
<script src="/app.js"></script>
```

Плюсы:

- контент доступен сразу;
- лучше SEO;
- корректные meta/og теги;
- лучше perceived performance для публичных страниц;
- можно подготовить данные на сервере.

Минусы:

- выше нагрузка на сервер;
- сложнее deploy;
- hydration может быть дорогой;
- нужно избегать browser-only кода на сервере;
- возможны hydration mismatch.

## Таблица

| Критерий | CSR | SSR |
|---|---|---|
| Где создается HTML | В браузере | На сервере |
| Первый HTML | Почти пустой shell | Готовый контент |
| SEO | Сложнее | Обычно лучше |
| Нагрузка | Клиент | Сервер + клиент |
| Интерактивность | После JS render | После hydration |
| Хостинг | Простая статика | Нужен сервер/edge/framework |

## Что выбрать?

CSR часто подходит для:

- админок;
- личных кабинетов;
- internal tools;
- приложений за логином;
- сложных интерактивных UI.

SSR часто подходит для:

- e-commerce;
- блогов;
- документации;
- маркетинговых страниц;
- новостей;
- публичных профилей.

## Мини-шпаргалка

- CSR сначала грузит JS, потом строит UI.
- SSR сначала отдает HTML, потом гидрирует UI.
- SSR не отменяет клиентский JavaScript.
- CSR проще, SSR полезнее для публичного content.
- Современные фреймворки часто смешивают оба подхода.
