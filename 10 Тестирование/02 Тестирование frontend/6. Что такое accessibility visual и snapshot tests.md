# Что такое accessibility, visual и snapshot tests?

> [!summary]
> Accessibility tests проверяют доступность интерфейса, visual tests - внешний вид, snapshot tests - текстовый снимок результата. Эти тесты полезны, но не заменяют проверку поведения.

## Accessibility tests

Accessibility tests помогают находить проблемы, которые мешают пользоваться интерфейсом:

- нет label у input;
- кнопка недоступна с клавиатуры;
- плохой контраст;
- modal не управляет focus;
- иконка без accessible name.

Пример идеи:

```ts
expect(button.attributes('aria-label')).toBe('Закрыть');
```

Для автоматических проверок часто используют axe-инструменты и Storybook accessibility addon.

## Visual tests

Visual tests сравнивают screenshot компонента или страницы с эталоном.

Они полезны для:

- дизайн-систем;
- кнопок, полей, таблиц;
- responsive states;
- regression checks после изменения CSS.

Минус: visual tests могут шуметь из-за шрифтов, анимаций, дат и различий окружения.

## Snapshot tests

Snapshot test сохраняет результат и сравнивает его с будущими запусками.

```ts
expect(wrapper.html()).toMatchSnapshot();
```

Snapshot удобен для стабильных структур, но опасен, если его обновляют автоматически без осмотра.

## Когда использовать?

| Тип | Когда полезен |
|---|---|
| accessibility | формы, модалки, меню, дизайн-система |
| visual | внешний вид критичных компонентов |
| snapshot | стабильная структура или сериализованные данные |

## Мини-шпаргалка

- Accessibility tests помогают не ломать доступность.
- Visual tests ловят изменения внешнего вида.
- Snapshot tests фиксируют снимок результата.
- Snapshot не заменяет проверку смысла.
- Анимации и даты лучше стабилизировать.
