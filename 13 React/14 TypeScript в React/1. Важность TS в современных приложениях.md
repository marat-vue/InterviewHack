# Важность TS в современных приложениях

> [!summary]
> TypeScript в React нужен не "для красоты", а для контроля контрактов: props, state, context, handlers, API-ответов и переиспользуемых компонентов. Он ловит ошибки до запуска приложения, улучшает автодополнение и делает рефакторинг безопаснее.

## Что TypeScript дает React-проекту?

React-приложение состоит из связей:

- родитель передает props ребенку;
- компонент хранит state;
- форма вызывает handler;
- context передает значение глубоко в дерево;
- API возвращает данные;
- кастомный хук прячет бизнес-логику.

TypeScript помогает описать эти связи явно.

```tsx
type UserCardProps = {
  user: {
    id: string
    name: string
    avatarUrl?: string
  }
  onSelect: (userId: string) => void
}

function UserCard({ user, onSelect }: UserCardProps) {
  return (
    <button onClick={() => onSelect(user.id)}>
      {user.name}
    </button>
  )
}
```

Если передать неправильный `user` или неправильный `onSelect`, ошибка появится еще в редакторе.

## Главные преимущества

| Что типизируем | Что получаем |
|---|---|
| props | компонент нельзя использовать с неправильными данными |
| state | меньше случайных `null`, неправильных enum и мутирования |
| events | `event.currentTarget.value` типизирован |
| refs | понятно, какой DOM-элемент лежит в `ref.current` |
| context | потребитель знает форму значения |
| API | легче валидировать и использовать ответы сервера |

## TypeScript не заменяет runtime validation

Важный нюанс: TypeScript не проверяет данные в runtime.

```tsx
type User = {
  id: string
  name: string
}

async function getUser(): Promise<User> {
  const response = await fetch('/api/user')
  return response.json()
}
```

TypeScript верит обещанию `Promise<User>`, но сервер может вернуть что угодно. Для внешних данных нужны runtime-валидаторы вроде Zod.

## Где TS особенно полезен?

TypeScript сильнее всего помогает в проектах, где есть:

- много компонентов;
- общие UI-kit компоненты;
- сложные формы;
- server state;
- глобальное состояние;
- разные роли пользователя;
- API-контракты;
- командная разработка.

## Типы как документация

Хороший тип отвечает на вопрос "как этим пользоваться":

```tsx
type ModalProps = {
  open: boolean
  title: string
  children: React.ReactNode
  onClose: () => void
}
```

По этому типу уже понятно:

- модалка controlled;
- заголовок обязателен;
- внутрь можно передать любой React-контент;
- закрытие контролируется родителем.

## Что отвечать на собеседовании?

TypeScript делает React-компоненты более надежными за счет статической проверки контрактов. Он типизирует props, state, events, refs, context и API-слои, помогает IDE подсказывать код и снижает риск ошибок при рефакторинге. При этом внешние данные все равно нужно валидировать в runtime.

## Частые ошибки

- Типизировать все через `any`.
- Верить API-ответу без runtime validation.
- Описывать слишком широкие типы вроде `object`.
- Дублировать типы вместо переиспользования.
- Считать TypeScript заменой тестам.

## Мини-шпаргалка

- TS описывает контракты между частями React-приложения.
- Props и state должны быть максимально конкретными.
- Внешние данные требуют runtime validation.
- Хорошие типы помогают читать код.
- `any` временно удобно, но ломает пользу TS.
