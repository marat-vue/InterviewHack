# Что делает useDeferredValue?

> [!summary]
> `useDeferredValue` позволяет отложить обновление части UI. Срочное значение обновляется сразу, а тяжелая часть интерфейса может временно использовать старое значение, чтобы не блокировать ввод.

## Базовый пример

```jsx
function SearchPage() {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)

  return (
    <>
      <input
        value={query}
        onChange={(event) => setQuery(event.target.value)}
      />
      <SearchResults query={deferredQuery} />
    </>
  )
}
```

`input` обновляется срочно, а `SearchResults` может немного отставать.

## Чем это отличается от debounce?

`debounce` задерживает само изменение:

```text
подождать 300 мс после последнего ввода
```

`useDeferredValue` не задает фиксированную задержку. React сам решает, когда обновить менее срочную часть UI, чтобы сохранить отзывчивость.

## Как показать stale state?

```jsx
const isStale = query !== deferredQuery

return (
  <div style={{ opacity: isStale ? 0.5 : 1 }}>
    <SearchResults query={deferredQuery} />
  </div>
)
```

Так пользователь видит, что результаты еще догоняют ввод.

## Когда использовать?

- тяжелые списки;
- таблицы;
- графики;
- поиск по большому набору данных;
- медленно рендерящиеся панели;
- когда нельзя легко оптимизировать компонент.

## Мини-шпаргалка

- `useDeferredValue` откладывает обновление значения для части UI.
- Срочный input остается отзывчивым.
- Это не то же самое, что debounce.
- Можно показывать stale UI мягко через opacity/indicator.
- Лучше использовать вместе с оптимизацией тяжелого компонента.
