# Чем отличается BrowserRouter от HashRouter?

> [!summary]
> `BrowserRouter` использует обычные красивые URL через History API, например `/products/42`. `HashRouter` хранит маршрут после `#`, например `/#/products/42`, поэтому сервер видит только корень сайта.

## BrowserRouter

```jsx
import { BrowserRouter } from 'react-router-dom'

<BrowserRouter>
  <App />
</BrowserRouter>
```

URL:

```text
https://example.com/products/42
```

Плюсы:

- красивые URL;
- лучше для SEO и аналитики;
- привычное поведение сайта;
- стандартный выбор для продакшена.

Минус:

- сервер должен отдавать `index.html` для всех frontend routes.

Если открыть `/products/42` напрямую, сервер не должен вернуть 404.

## HashRouter

```jsx
import { HashRouter } from 'react-router-dom'

<HashRouter>
  <App />
</HashRouter>
```

URL:

```text
https://example.com/#/products/42
```

Все после `#` не отправляется на сервер. Сервер получает запрос только к `/`, а React Router читает hash в браузере.

Плюсы:

- работает на простом статическом хостинге;
- не требует server fallback;
- удобно для GitHub Pages и legacy-хостинга.

Минусы:

- URL менее аккуратные;
- хуже для SEO;
- не всегда удобно для backend и аналитики.

## Таблица

| Критерий | BrowserRouter | HashRouter |
|---|---|---|
| URL | `/catalog` | `/#/catalog` |
| Использует | History API | hash fragment |
| Нужна настройка сервера | Да | Обычно нет |
| Прямой заход на route | Нужен fallback | Работает проще |
| Продакшен SPA | Обычно да | Только при ограничениях |

## Что выбрать?

Обычно выбирают `BrowserRouter`.

`HashRouter` используют, когда нельзя настроить сервер, CDN или hosting rewrite.

## Мини-шпаргалка

- `BrowserRouter` дает чистые URL.
- `HashRouter` кладет route после `#`.
- Hash fragment не отправляется на сервер.
- BrowserRouter требует fallback на `index.html`.
- Для нормального хостинга чаще выбирают BrowserRouter.
