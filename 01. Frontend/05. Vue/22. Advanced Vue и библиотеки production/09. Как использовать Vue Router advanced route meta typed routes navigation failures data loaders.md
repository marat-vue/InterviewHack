# Как использовать Vue Router advanced: route meta, typed routes, navigation failures и data loaders?

> [!NOTE]
> Vue Router - это не только `router-link` и `router-view`. В production важны meta, guards, lazy routes, scroll behavior, typed route names/params, обработка navigation failures и стратегия загрузки данных.

## Вопрос

Как использовать продвинутые возможности Vue Router: route meta, typed routes, navigation failures и data loading?

## Базовая настройка

```typescript
import { createRouter, createWebHistory } from "vue-router";

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    {
      path: "/",
      name: "home",
      component: () => import("@/pages/HomePage.vue"),
    },
    {
      path: "/users/:id",
      name: "user-details",
      component: () => import("@/pages/UserDetailsPage.vue"),
      props: true,
      meta: {
        requiresAuth: true,
        title: "Пользователь",
      },
    },
  ],
});
```

## Какие методы Router нужно знать

| API | Зачем нужен |
| --- | --- |
| `router.push(location)` | перейти на новый route с записью в history |
| `router.replace(location)` | перейти без новой записи в history |
| `router.go(delta)` | переместиться по history |
| `router.back()` | назад |
| `router.forward()` | вперед |
| `router.resolve(location)` | получить resolved route/href |
| `router.beforeEach(guard)` | global guard перед навигацией |
| `router.beforeResolve(guard)` | guard перед подтверждением навигации |
| `router.afterEach(hook)` | hook после навигации |
| `router.isReady()` | дождаться initial navigation |
| `router.addRoute(route)` | добавить route динамически |
| `router.removeRoute(name)` | удалить route |
| `router.hasRoute(name)` | проверить наличие route |
| `router.getRoutes()` | получить все route records |
| `useRouter()` | router instance в Composition API |
| `useRoute()` | current route в Composition API |
| `onBeforeRouteLeave()` | leave guard внутри компонента |
| `onBeforeRouteUpdate()` | update guard внутри компонента |

## Route meta

Route meta хранит дополнительную информацию о маршруте:

```typescript
const routes = [
  {
    path: "/admin",
    name: "admin",
    component: () => import("@/pages/AdminPage.vue"),
    meta: {
      requiresAuth: true,
      roles: ["admin"],
      title: "Админка",
    },
  },
];
```

Типизация meta:

```typescript
// router.d.ts
import "vue-router";

declare module "vue-router" {
  interface RouteMeta {
    title?: string;
    requiresAuth?: boolean;
    roles?: string[];
    layout?: "default" | "empty" | "admin";
  }
}
```

Использование:

```typescript
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    return {
      name: "login",
      query: { redirect: to.fullPath },
    };
  }
});

router.afterEach((to) => {
  document.title = `${to.meta.title ?? "App"}`;
});
```

## Navigation guards

Global guard:

```typescript
router.beforeEach(async (to) => {
  const auth = useAuthStore();

  if (to.meta.requiresAuth && !auth.isAuthenticated) {
    return { name: "login" };
  }
});
```

Route-level guard:

```typescript
{
  path: "/settings",
  component: () => import("@/pages/SettingsPage.vue"),
  beforeEnter: (to) => {
    if (!canOpenSettings()) {
      return { name: "home" };
    }
  },
}
```

Component-level guard:

```vue
<script setup lang="ts">
import { onBeforeRouteLeave } from "vue-router";

const hasUnsavedChanges = ref(false);

onBeforeRouteLeave(() => {
  if (hasUnsavedChanges.value) {
    return window.confirm("Есть несохраненные изменения. Уйти?");
  }
});
</script>
```

Guard может:

- вернуть `false`, чтобы отменить navigation;
- вернуть route location, чтобы сделать redirect;
- выбросить error;
- вернуть `undefined`/`true`, чтобы разрешить navigation.

## Composition API

```vue
<script setup lang="ts">
import { computed, watch } from "vue";
import { useRoute, useRouter, onBeforeRouteUpdate } from "vue-router";

const route = useRoute();
const router = useRouter();

const userId = computed(() => Number(route.params.id));

watch(
  () => route.params.id,
  async (id) => {
    await loadUser(Number(id));
  },
  { immediate: true },
);

onBeforeRouteUpdate((to) => {
  if (!to.params.id) {
    return { name: "users" };
  }
});

function openUser(id: number) {
  router.push({ name: "user-details", params: { id } });
}
</script>
```

Не стоит watch-ить весь `route`, лучше watch-ить конкретные поля: `route.params.id`, `route.query.page`.

## Navigation failures

`router.push()` возвращает Promise. Навигация может не закончиться успешным переходом.

```typescript
import {
  isNavigationFailure,
  NavigationFailureType,
} from "vue-router";

const failure = await router.push("/profile");

if (isNavigationFailure(failure, NavigationFailureType.aborted)) {
  console.log("Переход отменен guard-ом");
}
```

Типы failures:

- `aborted` - navigation отменена guard-ом;
- `cancelled` - началась новая navigation до завершения текущей;
- `duplicated` - переход на текущий route.

Где полезно:

- закрывать меню только после успешной navigation;
- показывать сообщение при отмене;
- логировать неожиданные failures;
- тестировать guards.

## Typed routes

Typed routes помогают ловить ошибки в route names и params на этапе TypeScript.

Пример ручного описания:

```typescript
import "vue-router";

declare module "vue-router" {
  interface RouteNamedMap {
    home: {
      path: "/";
      name: "home";
      params: Record<never, never>;
    };
    "user-details": {
      path: "/users/:id";
      name: "user-details";
      params: { id: string };
    };
  }
}
```

Теперь TypeScript может подсказать:

```typescript
router.push({
  name: "user-details",
  params: { id: "42" },
});
```

На практике для больших проектов часто используют file-based routes и генерацию типов, например через `unplugin-vue-router`, чтобы не писать карту вручную.

## Lazy routes и code splitting

```typescript
{
  path: "/reports",
  name: "reports",
  component: () => import("@/pages/ReportsPage.vue"),
}
```

Так страница попадет в отдельный chunk и загрузится только при переходе.

Можно назвать chunk через bundler-комментарии, если команда использует такую конвенцию, но в Vite обычно достаточно dynamic import и анализа bundle.

## Data loading

Есть несколько стратегий.

### Загрузка после navigation

```vue
<script setup lang="ts">
const route = useRoute();
const isLoading = ref(false);
const user = ref<User | null>(null);

watch(
  () => route.params.id,
  async (id) => {
    isLoading.value = true;

    try {
      user.value = await api.users.getById(String(id));
    } finally {
      isLoading.value = false;
    }
  },
  { immediate: true },
);
</script>
```

Плюсы:

- переход быстрый;
- легко показать skeleton;
- пользователь сразу видит shell страницы.

Минусы:

- страница может открыться в loading state;
- нужно обрабатывать race conditions.

### Загрузка до navigation

```typescript
{
  path: "/users/:id",
  component: () => import("@/pages/UserDetailsPage.vue"),
  beforeEnter: async (to) => {
    const user = await api.users.getById(String(to.params.id));

    if (!user) {
      return { name: "not-found" };
    }
  },
}
```

Плюсы:

- можно не открывать страницу без данных;
- удобно для auth/permissions/not-found.

Минусы:

- navigation ждет запрос;
- нужен progress indicator.

### Защита от race conditions

```typescript
let controller: AbortController | null = null;

watch(
  () => route.params.id,
  async (id) => {
    controller?.abort();
    controller = new AbortController();

    user.value = await api.users.getById(String(id), {
      signal: controller.signal,
    });
  },
);
```

## Scroll behavior

```typescript
const router = createRouter({
  history: createWebHistory(),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) {
      return savedPosition;
    }

    if (to.hash) {
      return {
        el: to.hash,
        behavior: "smooth",
      };
    }

    return { top: 0 };
  },
});
```

## Частые ошибки

- Watch-ить весь `route`, создавая лишние запросы.
- Хранить auth redirect без `to.fullPath`.
- Забывать `router.isReady()` в тестах и initial mount.
- Использовать path strings вместо named routes в большом проекте.
- Не обрабатывать duplicated/aborted navigation.
- Делать все data loading только в global guards.
- Использовать `index` или mutable params в ключах route components.

## Что отвечать на собеседовании

В production Vue Router важно проектировать routes как контракт: names, params, meta, guards, lazy loading, scroll behavior и data loading. `meta` удобно использовать для auth, title и layout. Guards могут отменять navigation или делать redirect. В Composition API используют `useRoute`, `useRouter`, `onBeforeRouteLeave`, `onBeforeRouteUpdate`, а watch лучше делать по конкретным params/query. Navigation failures помогают отличать успешный переход от отмененного или дублирующегося.

## Мини-шпаргалка

- `meta` - auth/title/layout/permissions.
- `beforeEach` - global auth guard.
- `beforeEnter` - guard конкретного route.
- `onBeforeRouteLeave` - защита от ухода со страницы.
- `router.push` - Promise, возможен navigation failure.
- `isNavigationFailure` - проверка failure.
- named routes лучше path strings.
- lazy `component: () => import(...)` - code splitting.
- data loading бывает до navigation и после navigation.
