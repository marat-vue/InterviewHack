# Как работают setup, teardown и filtering?

> [!summary]
> Setup и teardown помогают подготовить состояние до теста и очистить его после теста. Filtering позволяет запускать не весь набор, а конкретные файлы, группы или отдельные тесты.

## Hooks в Vitest

Основные hooks:

```ts
beforeAll(() => {});
afterAll(() => {});
beforeEach(() => {});
afterEach(() => {});
```

Пример:

```ts
beforeEach(() => {
  setActivePinia(createPinia());
});

afterEach(() => {
  vi.restoreAllMocks();
});
```

## `beforeEach` или `beforeAll`?

`beforeEach` выполняется перед каждым тестом. Он хорош для изоляции:

```ts
beforeEach(() => {
  cart.clear();
});
```

`beforeAll` выполняется один раз перед группой:

```ts
beforeAll(async () => {
  await startTestDatabase();
});
```

Если состояние меняется в тестах, безопаснее `beforeEach`.

## Очистка mocks

```ts
afterEach(() => {
  vi.clearAllMocks();
});
```

Разница:

- `clearAllMocks` очищает историю вызовов;
- `resetAllMocks` сбрасывает реализации mocks;
- `restoreAllMocks` восстанавливает оригинальные реализации spies.

## Как запускать часть тестов?

По файлу:

```bash
npx vitest src/cart/cart.test.ts
```

По имени:

```bash
npx vitest -t "adds item"
```

Временно:

```ts
test.only('debug this case', () => {});
test.skip('not ready yet', () => {});
```

`only` нельзя оставлять в коде перед commit.

## Мини-шпаргалка

- `beforeEach` хорош для изоляции.
- `beforeAll` хорош для дорогого общего setup.
- `afterEach` часто чистит mocks.
- `test.only` помогает debug, но не должен попадать в main.
- Filtering ускоряет работу с большим набором тестов.
