# Какие методы есть у Zod schemas?

> [!summary]
> Zod состоит из constructors (`z.string`, `z.object`, `z.array`) и методов schemas (`min`, `max`, `optional`, `nullable`, `refine`, `transform`, `pick`, `omit`, `extend`). Для NestJS особенно важны parsing methods, object methods, string/number validators и методы композиции.

## Главная идея

В Zod ты сначала создаешь schema, а потом вызываешь методы, которые уточняют правила.

```ts
const emailSchema = z.string().trim().toLowerCase().email();
```

Каждый метод возвращает новую schema. Исходная schema не мутируется, поэтому схемы удобно переиспользовать.

## Parsing methods

| Метод | Что делает | Когда использовать |
|---|---|---|
| `parse` | валидирует и возвращает данные или выбрасывает ошибку | скрипты, тесты, места где exception удобен |
| `safeParse` | возвращает `{ success, data/error }` | NestJS pipes, controllers, ручная обработка ошибок |
| `parseAsync` | async-версия `parse` | async `refine` |
| `safeParseAsync` | async-версия `safeParse` | async validation без try/catch |

```ts
const result = createUserSchema.safeParse(body);

if (!result.success) {
  throw new BadRequestException(result.error.issues);
}

return result.data;
```

## Primitive constructors

```ts
z.string();
z.number();
z.int();
z.bigint();
z.boolean();
z.date();
z.null();
z.undefined();
z.unknown();
z.any();
z.never();
```

Для API обычно лучше избегать `z.any()`: оно отключает пользу validation. Если структура неизвестна, чаще подходит `z.unknown()` и дальнейшая проверка.

## String methods

```ts
const usernameSchema = z
  .string()
  .trim()
  .min(3)
  .max(30)
  .regex(/^[a-z0-9_]+$/);
```

Частые методы:

| Метод | Назначение |
|---|---|
| `min(n)` | минимальная длина |
| `max(n)` | максимальная длина |
| `length(n)` | точная длина |
| `regex(regexp)` | проверка регулярным выражением |
| `startsWith(value)` | строка начинается с value |
| `endsWith(value)` | строка заканчивается value |
| `includes(value)` | строка содержит value |
| `trim()` | убрать пробелы по краям |
| `toLowerCase()` | привести к lower case |
| `toUpperCase()` | привести к upper case |

Форматы в Zod 4 часто задаются отдельными helpers:

```ts
z.email();
z.uuid();
z.url();
z.jwt();
z.iso.date();
z.iso.datetime();
```

В старом коде можно встретить стиль `z.string().email()`. В новых материалах лучше ориентироваться на актуальный Zod 4 API.

## Number methods

```ts
const limitSchema = z
  .number()
  .int()
  .min(1)
  .max(100);
```

Частые методы:

| Метод | Назначение |
|---|---|
| `int()` | только целое число |
| `min(n)` / `gte(n)` | минимум |
| `max(n)` / `lte(n)` | максимум |
| `gt(n)` | строго больше |
| `lt(n)` | строго меньше |
| `positive()` | больше 0 |
| `nonnegative()` | 0 или больше |
| `multipleOf(n)` | кратность |

Для query params часто нужен coercion:

```ts
const querySchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  limit: z.coerce.number().int().min(1).max(100).default(20),
});
```

Без `z.coerce.number()` строка `'10'` останется строкой и не пройдет `z.number()`.

## Optional, nullable и default

```ts
const schema = z.object({
  nickname: z.string().optional(),
  middleName: z.string().nullable(),
  bio: z.string().nullish(),
  role: z.enum(['user', 'admin']).default('user'),
});
```

| Метод | Что разрешает |
|---|---|
| `optional()` | поле может быть `undefined` или отсутствовать |
| `nullable()` | значение может быть `null` |
| `nullish()` | значение может быть `null` или `undefined` |
| `default(value)` | подставляет значение, если input `undefined` |
| `catch(value)` | возвращает fallback при ошибке validation |

В DTO для `PATCH` часто используют `partial()`, а не вручную добавляют `optional()` к каждому полю.

## Object methods

```ts
const userSchema = z.object({
  email: z.email(),
  name: z.string().min(2),
  password: z.string().min(8),
});

const publicUserSchema = userSchema.omit({ password: true });
const updateUserSchema = userSchema.partial();
const userEmailSchema = userSchema.pick({ email: true });
```

| Метод | Для чего нужен |
|---|---|
| `pick` | оставить только выбранные поля |
| `omit` | убрать выбранные поля |
| `partial` | сделать поля optional |
| `required` | сделать поля обязательными |
| `extend` | добавить или заменить поля |
| `safeExtend` | расширить schema безопаснее при refinements |
| `strictObject` | запретить лишние поля |
| `looseObject` | разрешить лишние поля |

Пример для NestJS:

```ts
export const createUserSchema = z.object({
  email: z.email(),
  name: z.string().min(2),
  password: z.string().min(8),
});

export const updateUserSchema = createUserSchema
  .omit({ email: true })
  .partial();
```

## Array methods

```ts
const idsSchema = z.array(z.uuid()).min(1).max(100);
```

| Метод | Назначение |
|---|---|
| `min(n)` | минимум элементов |
| `max(n)` | максимум элементов |
| `length(n)` | точное количество |
| `nonempty()` | массив не пустой |

Для bulk endpoints массив нужно ограничивать сверху, иначе пользователь может случайно отправить слишком большой payload.

## Enum, literal и unions

```ts
const roleSchema = z.enum(['user', 'admin']);
const sortOrderSchema = z.literal(['asc', 'desc']);

const paymentSchema = z.discriminatedUnion('type', [
  z.object({ type: z.literal('card'), cardToken: z.string() }),
  z.object({ type: z.literal('cash') }),
]);
```

`z.discriminatedUnion` обычно удобнее обычного `z.union`, когда у вариантов есть общее поле-дискриминатор.

## refine и superRefine

```ts
const passwordSchema = z
  .string()
  .min(8)
  .refine((value) => /[A-Z]/.test(value), {
    message: 'Password must contain uppercase letter',
  });
```

`refine` подходит для одной проверки. `superRefine` нужен, когда нужно добавить несколько ошибок или проверить несколько полей сразу.

```ts
const registerSchema = z.object({
  password: z.string().min(8),
  confirmPassword: z.string(),
}).superRefine((data, ctx) => {
  if (data.password !== data.confirmPassword) {
    ctx.addIssue({
      code: 'custom',
      path: ['confirmPassword'],
      message: 'Passwords do not match',
    });
  }
});
```

## transform и preprocess

```ts
const normalizedEmailSchema = z
  .string()
  .trim()
  .toLowerCase();
```

Для более сложного преобразования:

```ts
const slugSchema = z.string().transform((value) =>
  value.trim().toLowerCase().replace(/\s+/g, '-'),
);
```

Если нужно обработать input до основной проверки, часто используют coercion:

```ts
const dateSchema = z.coerce.date();
```

## Type helpers

```ts
type CreateUserInput = z.input<typeof createUserSchema>;
type CreateUserOutput = z.output<typeof createUserSchema>;
type CreateUser = z.infer<typeof createUserSchema>;
```

`z.infer` обычно равен output type. Разница между input и output важна, если есть `transform` или `coerce`.

## Мини-шпаргалка

- `parse/safeParse` запускают validation.
- `optional`, `nullable`, `nullish`, `default` описывают отсутствие значения.
- `min/max/regex/email/uuid/url` - частые проверки строк.
- `int/min/max/positive` - частые проверки чисел.
- `pick/omit/partial/extend` помогают собирать DTO из базовой schema.
- `refine/superRefine` нужны для бизнес-правил.
- `transform/coerce` меняют input перед выдачей результата.
- `z.infer`, `z.input`, `z.output` связывают validation с TypeScript.
