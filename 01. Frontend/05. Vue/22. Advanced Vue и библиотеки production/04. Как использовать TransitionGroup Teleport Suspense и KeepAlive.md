# Как использовать TransitionGroup, Teleport, Suspense и KeepAlive?

> [!NOTE]
> Vue имеет встроенные компоненты для UI-сценариев, которые часто пытаются решить вручную: анимации, списки, порталы, async UI и кеширование компонентных инстансов.

## Вопрос

Как использовать встроенные компоненты `Transition`, `TransitionGroup`, `Teleport`, `Suspense` и `KeepAlive`?

## Зачем нужны встроенные компоненты

Они закрывают задачи, которые в обычном DOM требуют много ручного кода:

- `Transition` - анимация появления/исчезновения одного элемента или компонента.
- `TransitionGroup` - анимация списка, добавления, удаления и перемещения элементов.
- `Teleport` - рендер части компонента в другое место DOM.
- `Suspense` - fallback для async dependencies.
- `KeepAlive` - кеширование динамических компонентов без уничтожения state.

## `Transition`

`Transition` оборачивает один элемент или компонент.

```vue
<template>
  <button @click="isOpen = !isOpen">Toggle</button>

  <Transition name="fade">
    <div v-if="isOpen" class="panel">
      Контент
    </div>
  </Transition>
</template>

<style scoped>
.fade-enter-active,
.fade-leave-active {
  transition: opacity 0.2s ease;
}

.fade-enter-from,
.fade-leave-to {
  opacity: 0;
}
</style>
```

Vue добавляет CSS-классы:

- `*-enter-from` - старт enter-анимации;
- `*-enter-active` - активная enter-анимация;
- `*-enter-to` - финал enter-анимации;
- `*-leave-from` - старт leave-анимации;
- `*-leave-active` - активная leave-анимация;
- `*-leave-to` - финал leave-анимации.

Полезные props:

- `name` - префикс CSS-классов;
- `mode` - порядок enter/leave, например `out-in`;
- `appear` - анимировать первый рендер;
- `duration` - явно задать длительность;
- `css` - отключить CSS transitions и управлять через JS hooks;
- `type` - указать `transition` или `animation`, если Vue не может определить сам.

JS hooks:

```vue
<Transition
  @before-enter="onBeforeEnter"
  @enter="onEnter"
  @after-enter="onAfterEnter"
  @leave="onLeave"
>
  <div v-if="isOpen" />
</Transition>
```

Их используют для интеграции с animation libraries, например Motion или GSAP.

## `TransitionGroup`

`TransitionGroup` нужен для списков. У каждого элемента должен быть стабильный `key`.

```vue
<template>
  <TransitionGroup name="list" tag="ul" class="todos">
    <li v-for="todo in todos" :key="todo.id">
      {{ todo.title }}
    </li>
  </TransitionGroup>
</template>

<style scoped>
.list-enter-active,
.list-leave-active {
  transition: all 0.2s ease;
}

.list-enter-from,
.list-leave-to {
  opacity: 0;
  transform: translateY(8px);
}

.list-move {
  transition: transform 0.2s ease;
}
</style>
```

Важные props:

- `tag` - какой HTML-тег рендерить как контейнер;
- `name` - CSS-префикс;
- `move-class` - класс для анимации перемещения;
- те же transition hooks, что и у `Transition`.

Когда применять:

- sortable lists;
- notifications;
- chips/tags;
- корзина;
- таблица с добавлением/удалением строк.

Частая ошибка - использовать index как key. Для анимированных списков это особенно заметно ломает поведение.

## `Teleport`

`Teleport` рендерит часть шаблона в другой DOM-контейнер.

```vue
<template>
  <button @click="isOpen = true">Открыть</button>

  <Teleport to="body">
    <div v-if="isOpen" class="modal-backdrop">
      <section class="modal" role="dialog" aria-modal="true">
        <button @click="isOpen = false">Закрыть</button>
        <slot />
      </section>
    </div>
  </Teleport>
</template>
```

Зачем нужен:

- modals;
- popovers;
- dropdowns, которые должны выходить за пределы `overflow: hidden`;
- toasts;
- overlays.

Полезные props:

- `to` - CSS selector или DOM element, куда рендерить;
- `disabled` - временно отключить teleport;
- `defer` - отложить поиск target, если он появится позже в рамках того же mount/update цикла.

Важный нюанс: логически компонент остается дочерним во Vue tree. Props, emits, provide/inject и devtools-иерархия продолжают работать как раньше. Меняется только физическое место DOM.

## `Suspense`

`Suspense` показывает fallback, пока async dependencies не готовы.

```vue
<template>
  <Suspense>
    <UserProfile />

    <template #fallback>
      <UserProfileSkeleton />
    </template>
  </Suspense>
</template>
```

Async dependency может появиться из-за top-level `await`:

```vue
<script setup lang="ts">
const user = await fetchUser();
</script>
```

Или из-за async component:

```typescript
import { defineAsyncComponent } from "vue";

const UserProfile = defineAsyncComponent(() =>
  import("@/components/UserProfile.vue"),
);
```

События:

- `pending` - началась загрузка async dependency;
- `resolve` - dependency готова;
- `fallback` - показан fallback.

Важно: `Suspense` в Vue долго оставался experimental API, поэтому в production стоит сверяться с текущей документацией и особенностями фреймворка. В Nuxt async rendering чаще завязан на Nuxt data fetching и собственную обработку loading/error states.

## `KeepAlive`

`KeepAlive` кеширует inactive component instances вместо уничтожения.

```vue
<template>
  <KeepAlive>
    <component :is="currentTabComponent" />
  </KeepAlive>
</template>
```

Где полезно:

- tabs;
- wizard steps;
- редакторы;
- фильтры и формы, где нужно сохранить локальное состояние;
- страницы в SPA, если используется динамический компонент.

Props:

- `include` - какие компоненты кешировать;
- `exclude` - какие не кешировать;
- `max` - максимум кешируемых инстансов.

```vue
<KeepAlive :include="['UserTab', 'SettingsTab']" :max="5">
  <component :is="currentTabComponent" />
</KeepAlive>
```

Компоненты внутри `KeepAlive` получают дополнительные lifecycle hooks:

```vue
<script setup lang="ts">
import { onActivated, onDeactivated } from "vue";

onActivated(() => {
  refreshIfStale();
});

onDeactivated(() => {
  pausePolling();
});
</script>
```

`onActivated` вызывается, когда компонент снова становится активным. `onDeactivated` - когда он уходит в кеш.

## Комбинация `Transition` и `KeepAlive`

```vue
<template>
  <Transition name="fade" mode="out-in">
    <KeepAlive>
      <component :is="currentView" :key="currentViewName" />
    </KeepAlive>
  </Transition>
</template>
```

Так можно одновременно кешировать состояние вкладок и анимировать переключение.

## Частые ошибки

- Использовать `TransitionGroup` без стабильного `key`.
- Анимировать список по index, а не по id.
- Делать модалку без `Teleport`, а потом бороться с `z-index` и `overflow`.
- Забывать про focus management и `aria-modal` у модалок.
- Кешировать слишком много через `KeepAlive` без `max`.
- Ожидать, что `KeepAlive` сам обновит устаревшие данные.
- Использовать `Suspense` там, где нужен обычный локальный loading state.

## Что отвечать на собеседовании

`Transition` и `TransitionGroup` отвечают за анимации элементов и списков, `Teleport` переносит DOM-узлы в другой контейнер без потери Vue-иерархии, `Suspense` дает fallback для async components/setup, а `KeepAlive` кеширует component instances и добавляет `activated/deactivated` lifecycle. В production важно использовать стабильные keys, ограничивать cache, управлять focus у overlays и не путать визуальное место DOM с логической Vue-иерархией.

## Мини-шпаргалка

- `Transition` - один элемент/компонент.
- `TransitionGroup` - список, нужен стабильный `key`.
- `Teleport` - modal/popover/toast в `body` или другой target.
- `Suspense` - fallback для async dependencies.
- `KeepAlive` - кеширование component instances.
- `onActivated`/`onDeactivated` - lifecycle для кешированных компонентов.
