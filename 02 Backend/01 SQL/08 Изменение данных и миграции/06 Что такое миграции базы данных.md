# Что такое миграции базы данных?

> [!NOTE]
> Миграции базы данных - версионированные изменения схемы и данных: создание таблиц, добавление колонок, индексов, constraints и перенос данных между версиями приложения.

## Зачем нужны миграции?

Код приложения хранится в Git и меняется по версиям. Схема базы тоже должна изменяться предсказуемо.

```sql
ALTER TABLE users
ADD COLUMN last_login_at timestamp;
```

Такое изменение оформляют как миграцию.

## Up и down

Многие инструменты описывают два направления:

- `up` - применить изменение;
- `down` - откатить изменение.

Но не все миграции безопасно или полностью откатываются, особенно если удаляли данные.

## Безопасные миграции

Для production важно:

- не блокировать таблицу надолго;
- не удалять колонку сразу, если старый код еще ее читает;
- делать backfill осторожно;
- добавлять constraints в несколько шагов при больших таблицах;
- деплоить код и схему совместимо.

## Мини-шпаргалка

- Миграция - версия изменения БД.
- Миграции должны быть в репозитории.
- Production-миграции проектируют с учетом блокировок.
- Удаление данных трудно откатить.
- Код и схема должны быть совместимы во время деплоя.
