# Что такое SSG и в каких случаях он используется?

> [!summary]
> SSG, или Static Site Generation, означает, что HTML создается заранее, обычно во время build. В Next.js это подходит для страниц, которые можно подготовить до запроса пользователя: блог, документация, лендинги, публичные каталоги и маркетинговые страницы.

## Как работает SSG?

Упрощенно:

1. Запускается build.
2. Next.js выполняет код страниц.
3. Формируется HTML.
4. Готовые файлы кладутся в build output.
5. Пользователи получают HTML быстро, часто через CDN.

```tsx
export default async function BlogPage() {
  const posts = await fetch('https://api.example.com/posts').then((res) => res.json())

  return <PostList posts={posts} />
}
```

Если данные кешируются и не требуют request-specific информации, route может быть предварительно отрендерен статически.

## Когда использовать SSG?

Хорошие сценарии:

- документация;
- блог;
- лендинг;
- портфолио;
- help center;
- страницы категорий, которые редко меняются;
- публичные страницы без персонализации.

## SSG vs SSR

| Критерий | SSG | SSR |
|---|---|---|
| Когда создается HTML | заранее | на каждый request |
| Скорость отдачи | очень высокая | зависит от сервера и данных |
| Персонализация | почти нет | удобно |
| Нагрузка на сервер | низкая | выше |
| Актуальность | зависит от rebuild/revalidate | актуально на request |

## generateStaticParams

Для динамических routes можно заранее указать параметры:

```tsx
export async function generateStaticParams() {
  const posts = await getPosts()

  return posts.map((post) => ({
    slug: post.slug,
  }))
}

export default async function PostPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  const post = await getPost(slug)

  return <Article post={post} />
}
```

Так Next.js может заранее подготовить страницы `/blog/a`, `/blog/b` и другие.

## Что отвечать на собеседовании?

SSG - это генерация страниц заранее. Она дает отличную скорость и дешевую раздачу через CDN, но плохо подходит для персонализированных или постоянно меняющихся данных. В App Router статический rendering часто получается автоматически, если route не использует динамические данные.

## Частые ошибки

- Использовать SSG для данных текущего пользователя.
- Забывать, что build может стать долгим при тысячах страниц.
- Путать SSG и ISR.
- Хранить секреты в клиентском коде статической страницы.
- Не настраивать обновление контента.

## Мини-шпаргалка

- SSG создает HTML заранее.
- Лучший выбор для стабильного публичного контента.
- Быстро отдается через CDN.
- Для динамических params есть `generateStaticParams`.
- Для обновляемой статики нужен ISR.
