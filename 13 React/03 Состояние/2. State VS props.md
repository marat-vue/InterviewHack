# Чем state отличается от props?

> [!summary]
> Props - это входные данные, которые компонент получает от родителя. State - это внутренняя память компонента, которую компонент может обновлять через setter. Props приходят сверху, state живет внутри.

## Короткое сравнение

| Критерий | Props | State |
|---|---|---|
| Кто задает | родитель | сам компонент |
| Можно ли менять напрямую | нет | нет, только через setter |
| Откуда приходит | извне | внутри компонента |
| Зачем нужен | настройка и данные для компонента | интерактивность и изменяемые данные |
| Что вызывает render | изменение props | обновление state |

## Пример props

```jsx
function UserName({ name }) {
  return <h2>{name}</h2>
}

function App() {
  return <UserName name="Анна" />
}
```

`UserName` не решает, каким будет `name`. Он получает его от `App`.

## Пример state

```jsx
function LikeButton() {
  const [liked, setLiked] = useState(false)

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? 'Нравится' : 'Поставить лайк'}
    </button>
  )
}
```

`liked` хранится внутри `LikeButton`.

## Как они работают вместе?

Родитель хранит state и передает его ребенку как props:

```jsx
function App() {
  const [theme, setTheme] = useState('light')

  return (
    <ThemeSwitcher
      theme={theme}
      onChangeTheme={setTheme}
    />
  )
}
```

Для `App` значение `theme` - state. Для `ThemeSwitcher` это prop.

## Как отвечать на собеседовании?

```text
Props - данные, которые компонент получает от родителя и не изменяет. State - локальные данные компонента, изменение которых планирует новый render. Одно и то же значение может быть state для родителя и prop для ребенка.
```

## Мини-шпаргалка

- Props приходят извне.
- State хранится внутри.
- Props и state нельзя мутировать напрямую.
- Setter state запускает обновление.
- State родителя часто становится props ребенка.
