# Как работают вложенные layout?

> [!summary]
> Вложенные layout в Next.js строятся по структуре папок внутри `app`. Каждый `layout.tsx` оборачивает страницы и дочерние layout своего сегмента, поэтому итоговая страница получается как цепочка оболочек от Root Layout до `page.tsx`.

## Базовый пример

```text
app/
  layout.tsx
  page.tsx
  dashboard/
    layout.tsx
    page.tsx
    settings/
      layout.tsx
      page.tsx
```

Для маршрута `/dashboard/settings` дерево будет таким:

```tsx
<RootLayout>
  <DashboardLayout>
    <SettingsLayout>
      <SettingsPage />
    </SettingsLayout>
  </DashboardLayout>
</RootLayout>
```

Каждый уровень отвечает только за свой участок интерфейса.

## Как это выглядит в коде?

```tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <div className="dashboard">
      <aside>Меню кабинета</aside>
      <main>{children}</main>
    </div>
  )
}
```

```tsx
// app/dashboard/settings/layout.tsx
export default function SettingsLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <section>
      <nav>Вкладки настроек</nav>
      {children}
    </section>
  )
}
```

Страница `app/dashboard/settings/page.tsx` не импортирует эти layout. Next.js применяет их автоматически.

## Что сохраняется при навигации?

Если пользователь переходит:

```text
/dashboard/settings/profile -> /dashboard/settings/security
```

сохраняются:

- Root Layout;
- Dashboard Layout;
- Settings Layout.

Меняется только page-сегмент ниже общего layout.

Если пользователь переходит:

```text
/dashboard/settings -> /dashboard/users
```

сохраняются:

- Root Layout;
- Dashboard Layout.

А `SettingsLayout` уже не нужен и будет заменен.

## Зачем это нужно на практике?

Вложенные layout позволяют делать архитектуру интерфейса слоями:

```text
Root Layout       -> html, body, fonts, providers
Dashboard Layout  -> sidebar, user menu, auth check
Settings Layout   -> settings tabs
Page              -> конкретный экран
```

Так легче понимать, где должна лежать логика:

- глобальное - в Root Layout;
- общее для раздела - в layout раздела;
- общее для подраздела - во вложенном layout;
- уникальное - в page.

## Нюанс с данными

Layout сохраняется между переходами, поэтому не стоит класть в высокий layout данные, которые должны обновляться при каждом переходе страницы.

Если нужны данные конкретной страницы, лучше загрузить их в `page.tsx`:

```tsx
// app/dashboard/users/page.tsx
export default async function UsersPage() {
  const users = await getUsers()
  return <UsersTable users={users} />
}
```

А в layout оставить только общее:

```tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({ children }: { children: React.ReactNode }) {
  return <DashboardShell>{children}</DashboardShell>
}
```

## Что отвечать на собеседовании?

Вложенные layout в Next.js работают через структуру папок. Каждый `layout.tsx` оборачивает все дочерние страницы и layout своего сегмента. При навигации Next.js переиспользует общие layout, поэтому состояние и оболочка сохраняются, а меняется только более глубокий сегмент маршрута.

## Частые ошибки

- Думать, что layout надо импортировать вручную.
- Класть все layout в одну папку вместо использования структуры маршрутов.
- Помещать page-specific данные в Root Layout.
- Не понимать, какой layout сохранится при переходе.
- Путать вложенные layout с вложенными URL без файловой структуры.

## Мини-шпаргалка

- Layout наследуются сверху вниз.
- Каждый сегмент может иметь свой `layout.tsx`.
- Страница оборачивается всеми родительскими layout.
- Общие layout сохраняются при навигации.
- Чем выше layout, тем шире его зона ответственности.
- Данные лучше держать как можно ближе к месту использования.
