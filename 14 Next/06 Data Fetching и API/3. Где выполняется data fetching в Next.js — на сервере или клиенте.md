# Где выполняется data fetching в Next.js — на сервере или клиенте?

> [!summary]
> В Next.js data fetching может выполняться и на сервере, и на клиенте. В App Router по умолчанию предпочтителен серверный fetching в Server Components, а клиентский fetching используют для интерактивных, пользовательских или часто меняющихся client-side сценариев.

## Серверный fetching

```tsx
export default async function ProductsPage() {
  const products = await getProducts()

  return <ProductList products={products} />
}
```

Выполняется:

- в Server Components;
- в Route Handlers;
- в Server Actions;
- в `generateMetadata`;
- в `generateStaticParams`.

Плюсы:

- HTML приходит с данными;
- лучше SEO;
- можно использовать secrets;
- меньше client JavaScript;
- можно читать БД напрямую.

## Клиентский fetching

```tsx
'use client'

export function SearchResults({ query }: { query: string }) {
  const resultsQuery = useQuery({
    queryKey: ['search', query],
    queryFn: () => searchProducts(query),
  })

  return <Results data={resultsQuery.data} />
}
```

Подходит для:

- поиска с вводом;
- infinite scroll;
- realtime обновлений;
- private dashboard widgets;
- client-only interactions;
- данных, не нужных для первого HTML.

## Как выбирать?

| Вопрос | Лучше |
|---|---|
| Нужно SEO? | сервер |
| Нужны secrets/DB? | сервер |
| Нужен `useState`/interaction? | клиент |
| Данные зависят от input в браузере? | клиент |
| Нужно показать контент в первом HTML? | сервер |

## Что отвечать на собеседовании?

В Next.js данные можно получать в обеих средах. App Router поощряет серверный fetching для первого HTML и SEO, но client-side fetching остается нормальным для интерактивных сценариев. Главное - осознанно выбирать место выполнения.

## Частые ошибки

- Делать все fetch на клиенте по привычке из React SPA.
- Делать все fetch на сервере и усложнять интерактивность.
- Использовать browser APIs в серверном fetching.
- Хранить secrets в клиентских запросах.
- Дублировать один и тот же запрос на сервере и клиенте.

## Мини-шпаргалка

- Server fetching - HTML, SEO, secrets.
- Client fetching - interaction, live UI.
- Server Component может быть `async`.
- Client Component использует hooks/effects/libraries.
- Выбор зависит от UX и безопасности.
