# Что делает reconciliation algorithm?

> [!summary]
> Reconciliation algorithm - это механизм React, который сравнивает старое и новое дерево элементов после render и решает, какие части UI сохранить, обновить, удалить или создать заново. Он напрямую влияет на производительность, keys и сохранение state.

## Простая схема

```text
state/props changed
React вызывает render
получает новое дерево
сравнивает со старым
планирует DOM updates
commit применяет изменения
```

## Главное правило: тип элемента

Если тип элемента изменился:

```jsx
{isTitle ? <h1>React</h1> : <p>React</p>}
```

React обычно заменит узел, потому что `h1` и `p` - разные типы.

Если тип тот же:

```jsx
<button className={isActive ? 'active' : ''}>Сохранить</button>
```

React обновит props/attributes и продолжит сравнение детей.

## Компоненты и state

Если на той же позиции остается тот же component type, React обычно сохраняет state:

```jsx
<Counter />
```

Если component type или key меняется, state может сброситься.

## Списки и key

```jsx
{items.map((item) => (
  <TodoItem key={item.id} item={item} />
))}
```

`key` помогает React понять, какие элементы были добавлены, удалены или перемещены.

Плохой key может привести к:

- неправильному сохранению state;
- багам в input;
- лишним mount/unmount;
- некорректным анимациям.

## Мини-шпаргалка

- Reconciliation сравнивает старое и новое дерево React.
- Тип элемента влияет на замену или обновление.
- `key` важен для списков и сохранения state.
- Reconciliation происходит до commit.
- Понимание reconciliation помогает объяснять render-баги.
