# Как защищать routes через requireAuth, roles и permissions?

> [!NOTE]
> Better Auth помогает получить session, но authorization нужно проектировать отдельно: роли, permissions, ownership checks, admin checks, tenant checks. В Nitro удобно вынести это в `requireAuth`, `requireRole`, `requirePermission`.

## Базовый `requireAuth`

```ts
// server/utils/require-auth.ts
import { createError, type H3Event } from 'h3';
import { auth } from './auth';

export async function requireAuth(event: H3Event) {
  const session = await auth.api.getSession({
    headers: event.req.headers,
  });

  if (!session) {
    throw createError({
      statusCode: 401,
      statusMessage: 'Unauthorized',
    });
  }

  return session;
}
```

Использование:

```ts
export default defineHandler(async (event) => {
  const session = await requireAuth(event);

  return {
    user: session.user,
  };
});
```

## `requireRole`

```ts
export async function requireRole(event: H3Event, roles: string[]) {
  const session = await requireAuth(event);
  const role = session.user.role;

  if (!role || !roles.includes(role)) {
    throw createError({
      statusCode: 403,
      statusMessage: 'Forbidden',
    });
  }

  return session;
}
```

Route:

```ts
export default defineHandler(async (event) => {
  await requireRole(event, ['admin']);

  return adminService.getStats();
});
```

## Ownership check

Роль не всегда нужна. Иногда пользователь может менять только свой ресурс:

```ts
export default defineHandler(async (event) => {
  const session = await requireAuth(event);
  const id = getRouterParam(event, 'id')!;

  if (session.user.id !== id) {
    throw createError({
      statusCode: 403,
      statusMessage: 'Forbidden',
    });
  }

  return userService.updateProfile(id, await readBody(event));
});
```

## Permission check

```ts
const permissionsByRole = {
  admin: ['users:read', 'users:write'],
  support: ['users:read'],
  user: [],
} as const;

export async function requirePermission(event: H3Event, permission: string) {
  const session = await requireAuth(event);
  const role = session.user.role ?? 'user';
  const permissions = permissionsByRole[role] ?? [];

  if (!permissions.includes(permission as never)) {
    throw createError({
      statusCode: 403,
      statusMessage: 'Forbidden',
    });
  }

  return session;
}
```

## Где хранить role?

Варианты:

- поле `role` в user table;
- отдельная таблица memberships;
- Better Auth admin plugin;
- Better Auth organization plugin;
- custom authorization tables.

Для SaaS с командами обычно одной `user.role` мало. Нужны organization memberships:

```txt
User
Organization
Membership(userId, organizationId, role)
```

## Middleware или explicit guard?

Global middleware:

```ts
if (event.path.startsWith('/api/admin')) {
  await requireRole(event, ['admin']);
}
```

Explicit guard в route:

```ts
await requireRole(event, ['admin']);
```

Explicit guard проще читать и тестировать. Middleware удобно для больших path groups.

## 401 или 403?

| Статус | Когда |
|---|---|
| `401 Unauthorized` | пользователь не authenticated |
| `403 Forbidden` | пользователь authenticated, но нет прав |

## Мини-шпаргалка

- `requireAuth` проверяет session.
- `requireRole` проверяет роль.
- `requirePermission` проверяет конкретное право.
- Ownership check нужен для пользовательских ресурсов.
- Для SaaS думай про organization/membership.
- Better Auth отвечает за auth, но domain authorization остается за приложением.
