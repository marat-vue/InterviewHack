# Как тестировать миграции, seed, rollback и constraints?

> [!summary]
> Backend integration tests должны проверять не только код приложения, но и поведение базы: миграции применяются, seed создает нужные данные, constraints защищают инварианты, transaction rollback не оставляет частично записанные данные.

## Миграции

Минимальная проверка:

```text
Создать пустую тестовую БД -> применить миграции -> приложение стартует -> healthcheck проходит.
```

Если миграция сломана, это должно обнаружиться до deploy.

## Seed

Seed нужен для базовых справочников:

- roles;
- permissions;
- тарифы;
- статусы;
- feature flags.

Тест:

```ts
await runSeed();

const roles = await prisma.role.findMany();

expect(roles.map((role) => role.name)).toEqual(
  expect.arrayContaining(['admin', 'user']),
);
```

## Constraints

Проверяй важные ограничения:

```ts
await prisma.user.create({ data: { email: 'ann@example.com' } });

await expect(
  prisma.user.create({ data: { email: 'ann@example.com' } }),
).rejects.toThrow();
```

Так ты убеждаешься, что уникальность защищена не только в service, но и на уровне БД.

## Rollback

```ts
await expect(service.createOrderWithInvalidItem(input)).rejects.toThrow();

const orders = await prisma.order.findMany();
const items = await prisma.orderItem.findMany();

expect(orders).toHaveLength(0);
expect(items).toHaveLength(0);
```

## Мини-шпаргалка

- Миграции должны прогоняться на тестовой БД.
- Seed нужно тестировать, если от него зависит приложение.
- Constraints защищают данные даже при ошибках кода.
- Rollback проверяется через состояние базы после ошибки.
- Такие тесты лучше запускать на настоящей тестовой БД.
