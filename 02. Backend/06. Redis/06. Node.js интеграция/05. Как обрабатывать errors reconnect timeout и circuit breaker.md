# Как обрабатывать errors, reconnect, timeout и circuit breaker?

> [!NOTE]
> Redis outage не должен автоматически превращать весь backend в outage. Для cache-сценариев приложение часто должно уметь деградировать: пропустить cache, сходить в БД и залогировать проблему.

## Error listener обязателен

```ts
redis.on('error', (error) => {
  logger.error({
    error,
  }, 'Redis error');
});
```

Без listener-а connection error может уронить процесс.

## Cache fallback

```ts
async function getFromCache<T>(key: string): Promise<T | null> {
  try {
    const value = await redis.get(key);
    return value ? JSON.parse(value) as T : null;
  } catch (error) {
    logger.warn({
      error,
      key,
    }, 'Redis cache read failed');

    return null;
  }
}
```

Для cache read ошибка Redis часто должна означать miss, не HTTP 500.

## Write failure

```ts
try {
  await redis.set(key, JSON.stringify(value), {
    EX: 300,
  });
} catch (error) {
  logger.warn({
    error,
    key,
  }, 'Redis cache write failed');
}
```

Cache write failure не должен ломать успешный DB read.

## Когда Redis error должен ломать request?

Если Redis используется как источник истины:

- session store;
- idempotency guard;
- rate limit для login;
- lock для critical operation;
- stream/job queue;

ошибка Redis уже может быть критичной. Тогда нужно возвращать 503/429/500 в зависимости от сценария.

## Timeout wrapper

```ts
async function withTimeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  const timeout = new Promise<never>((_, reject) => {
    setTimeout(() => reject(new Error('Redis timeout')), ms);
  });

  return Promise.race([promise, timeout]);
}
```

Использование:

```ts
const cached = await withTimeout(redis.get(key), 100);
```

## Circuit breaker идея

Если Redis часто падает:

- временно не ходить в Redis;
- отдавать cache miss;
- периодически пробовать восстановиться;
- не создавать лавину timeout-ов.

Можно использовать готовую библиотеку circuit breaker или простую shared-state защиту.

## Мини-шпаргалка

- Error listener обязателен.
- Cache read error часто превращается в miss.
- Cache write error часто логируется и игнорируется.
- Session/rate-limit/idempotency Redis errors критичнее.
- Добавляй timeout и circuit breaker для устойчивости.
