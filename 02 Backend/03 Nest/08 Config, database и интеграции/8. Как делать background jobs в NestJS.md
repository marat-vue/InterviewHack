# Как делать background jobs в NestJS?

> [!summary]
> Background jobs выносят долгую работу из HTTP-запроса: отправку email, генерацию отчетов, обработку файлов, retries внешних API. В NestJS для этого часто используют очереди вроде BullMQ или отдельные workers.

## Почему не в request?

```ts
@Post('reports')
async createReport() {
  return this.reportsService.generateHugeReport();
}
```

Клиент будет ждать, request может оборваться, а серверный handler будет занят.

## С очередью

```txt
HTTP request -> enqueue job -> 202 Accepted
worker -> process job
```

Controller:

```ts
@Post('reports')
async createReport() {
  const jobId = await this.reportsQueue.add('generate', {});
  return { jobId };
}
```

## Что важно?

- retries;
- idempotency;
- dead letter queue;
- job status;
- concurrency limits;
- observability.

## Мини-шпаргалка

- Долгую работу лучше выносить в jobs.
- HTTP endpoint может вернуть `202 Accepted`.
- Worker выполняет задачу отдельно.
- Job должен быть идемпотентным.
- Очереди требуют мониторинга.
