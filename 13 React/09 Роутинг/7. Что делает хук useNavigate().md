# Что делает хук useNavigate()?

> [!summary]
> `useNavigate` возвращает функцию для программной навигации. Ее используют, когда переход должен произойти из кода: после submit формы, после логина, при закрытии модалки или в результате пользовательского действия.

## Базовый пример

```jsx
import { useNavigate } from 'react-router-dom'

function LoginForm() {
  const navigate = useNavigate()

  async function handleSubmit(event) {
    event.preventDefault()
    await login()
    navigate('/dashboard')
  }

  return <form onSubmit={handleSubmit}>...</form>
}
```

## Синтаксис

```jsx
const navigate = useNavigate()

navigate('/profile')
navigate('/login', { replace: true })
navigate('/checkout', { state: { fromCart: true } })
navigate(-1)
```

## Основные варианты

Обычный переход:

```jsx
navigate('/settings')
```

Замена текущей записи в истории:

```jsx
navigate('/login', { replace: true })
```

Это полезно после logout или redirect, чтобы пользователь не вернулся кнопкой Back на запрещенную страницу.

Передача временного state:

```jsx
navigate('/profile', {
  state: { justLoggedIn: true },
})
```

Чтение:

```jsx
const location = useLocation()
const justLoggedIn = location.state?.justLoggedIn
```

Навигация по истории:

```jsx
navigate(-1) // назад
navigate(1)  // вперед
```

## useNavigate vs Link vs Navigate

| Инструмент | Когда использовать |
|---|---|
| `<Link to="/page" />` | Обычная кликабельная ссылка |
| `<Navigate to="/login" />` | Редирект как результат render |
| `navigate('/page')` | Переход из обработчика или эффекта |

## Важное про loaders/actions

В data routers часто лучше делать redirect в `loader` или `action`, если переход связан с загрузкой данных или submit формы. `useNavigate` остается удобным для UI-событий внутри компонента.

## Мини-шпаргалка

- `useNavigate` нужен для перехода из кода.
- Работает только внутри Router.
- `replace: true` заменяет запись history.
- `state` передает временные данные в `location.state`.
- Для обычных ссылок используй `Link`, а не кнопку с `navigate`.
