# Что значит state lifting, подъем состояния?

> [!summary]
> State lifting - это перенос состояния из дочернего компонента в ближайшего общего родителя, чтобы несколько компонентов могли использовать и изменять одно и то же значение согласованно.

## Когда нужен подъем состояния?

Представь два sibling-компонента:

```text
SearchInput
ProductList
```

`SearchInput` меняет поисковую строку, а `ProductList` должен фильтроваться по ней. Значит, state должен жить в общем родителе.

## Пример

```jsx
function ProductsPage({ products }) {
  const [query, setQuery] = useState('')

  const visibleProducts = products.filter((product) =>
    product.title.toLowerCase().includes(query.toLowerCase())
  )

  return (
    <>
      <SearchInput query={query} onQueryChange={setQuery} />
      <ProductList products={visibleProducts} />
    </>
  )
}
```

`query` поднят в `ProductsPage`, потому что нужен и input, и списку.

## Дочерний controlled component

```jsx
function SearchInput({ query, onQueryChange }) {
  return (
    <input
      value={query}
      onChange={(event) => onQueryChange(event.target.value)}
    />
  )
}
```

`SearchInput` не хранит собственный `query`, а получает его через props.

## Как найти ближайшего общего родителя?

Алгоритм:

1. Определи компоненты, которым нужны данные.
2. Найди их ближайшего общего родителя.
3. Перенеси state туда.
4. Передай значение вниз через props.
5. Передай callbacks для изменений.

## State lifting vs global state

Подъем состояния не означает "положить все в глобальный store".

Если значение нужно только в рамках одной страницы, достаточно ближайшего общего родителя. Глобальное состояние нужно только когда данные реально нужны далеко и многим частям приложения.

## Мини-шпаргалка

- State lifting нужен для синхронизации sibling-компонентов.
- State поднимают к ближайшему общему родителю.
- Значение идет вниз через props.
- Изменение идет вверх через callback.
- Не путай state lifting с глобальным store.
