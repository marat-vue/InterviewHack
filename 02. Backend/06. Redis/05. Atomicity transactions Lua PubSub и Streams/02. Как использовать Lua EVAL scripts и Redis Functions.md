# Как использовать Lua, EVAL scripts и Redis Functions?

> [!NOTE]
> Lua scripts позволяют выполнить сложную логику атомарно на стороне Redis. Это полезно для rate limit, safe lock release, token bucket, idempotency и операций “прочитать-проверить-записать”.

## Зачем Lua?

Lua нужен, когда одной команды мало:

```txt
GET value
check condition
SET new value
EXPIRE key
```

Если делать это из приложения, между командами могут вмешаться другие клиенты. Lua выполняется атомарно внутри Redis.

## Safe lock release

```redis
EVAL "
if redis.call('GET', KEYS[1]) == ARGV[1] then
  return redis.call('DEL', KEYS[1])
end
return 0
" 1 lock:job:42 token-123
```

Удаляем lock только если value совпадает.

## Lua в Node.js

```ts
const releaseLockScript = `
if redis.call("GET", KEYS[1]) == ARGV[1] then
  return redis.call("DEL", KEYS[1])
end
return 0
`;

await redis.eval(releaseLockScript, {
  keys: ['lock:job:42'],
  arguments: [token],
});
```

## Rate limit Lua

```ts
const script = `
local current = redis.call("INCR", KEYS[1])
if current == 1 then
  redis.call("EXPIRE", KEYS[1], ARGV[1])
end
return current
`;

const count = await redis.eval(script, {
  keys: [`rate:${ip}`],
  arguments: ['60'],
});
```

`INCR` и первый `EXPIRE` выполняются вместе.

## Ограничения Lua

- script должен быть быстрым;
- долгий script блокирует Redis;
- нельзя делать сетевые запросы из Lua;
- нужно аккуратно передавать keys через `KEYS`, arguments через `ARGV`;
- в Cluster все keys script должны быть в одном slot.

## Redis Functions

Redis Functions позволяют загрузить function library на сервер и вызывать ее по имени. Это удобнее, чем постоянно отправлять длинный Lua script.

Общее правило:

- для простых cases хватит `EVAL`;
- для повторяемой production-логики стоит изучить Functions.

## Мини-шпаргалка

- Lua = атомарная server-side логика.
- Используй `KEYS` для ключей и `ARGV` для аргументов.
- Scripts должны быть короткими и быстрыми.
- Safe lock release почти всегда делается Lua.
- В Cluster keys должны быть в одном hash slot.
