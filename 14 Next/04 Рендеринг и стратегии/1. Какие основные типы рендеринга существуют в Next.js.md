# Какие основные типы рендеринга существуют в Next.js?

> [!summary]
> В Next.js важно различать static rendering, dynamic rendering, ISR, client-side rendering, hydration и streaming. App Router может комбинировать эти подходы внутри одного приложения, а иногда и внутри одного route через Suspense.

## Основные стратегии

| Стратегия | Когда создается контент | Для чего подходит |
|---|---|---|
| SSG/static rendering | заранее | блоги, docs, лендинги |
| SSR/dynamic rendering | на request | персонализация, cookies, свежие данные |
| ISR | статически + обновление | каталоги, CMS, новости |
| CSR | в браузере | интерактивные widgets, private dashboards |
| Streaming | частями | медленные блоки, Suspense |

## Static rendering

```tsx
export default async function BlogPage() {
  const posts = await getCachedPosts()
  return <PostList posts={posts} />
}
```

Если route не зависит от request-specific данных, Next.js может отрендерить его статически.

## Dynamic rendering

```tsx
import { cookies } from 'next/headers'

export default async function AccountPage() {
  const cookieStore = await cookies()
  const user = await getUser(cookieStore)

  return <Account user={user} />
}
```

Использование cookies/headers или uncached data делает route динамическим.

## ISR

```tsx
export const revalidate = 3600
```

Route может оставаться статическим, но обновляться раз в заданный интервал.

## CSR

```tsx
'use client'

export function SearchBox() {
  const [query, setQuery] = useState('')
  return <input value={query} onChange={(e) => setQuery(e.target.value)} />
}
```

Client Components нужны для интерактивности.

## Streaming

```tsx
<Suspense fallback={<RevenueSkeleton />}>
  <RevenueChart />
</Suspense>
```

Next.js может отправить shell страницы раньше, а медленный блок доставить позже.

## Что отвечать на собеседовании?

Next.js поддерживает несколько стратегий рендеринга: static rendering/SSG для заранее готового контента, dynamic rendering/SSR для request-specific данных, ISR для обновляемой статики, CSR для клиентской интерактивности и streaming для постепенной отправки UI.

## Частые ошибки

- Думать, что страница целиком всегда SSR.
- Использовать Client Components для всего.
- Делать dynamic rendering без необходимости.
- Путать ISR и client refetch.
- Не понимать, что Suspense влияет на streaming.

## Мини-шпаргалка

- Static - быстро и кешируемо.
- Dynamic - свежо и персонализировано.
- ISR - static с обновлением.
- CSR - интерактивность в браузере.
- Streaming - UI приходит частями.
- Server Components не равны SSR.
