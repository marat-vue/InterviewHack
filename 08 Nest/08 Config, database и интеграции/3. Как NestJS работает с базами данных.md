# Как NestJS работает с базами данных?

> [!summary]
> NestJS database-agnostic: он не навязывает конкретную базу или ORM. Можно использовать Prisma, TypeORM, MikroORM, Sequelize, Knex, Mongoose или обычный Node.js driver.

## Главная идея

NestJS дает DI и modules, а конкретный database layer выбирает проект.

```txt
Controller -> Service -> Repository/ORM -> Database
```

## Варианты

| Инструмент | Когда встречается |
|---|---|
| Prisma | type-safe queries, migrations |
| TypeORM | decorators/entities, repository pattern |
| MikroORM | Data Mapper, Unit of Work |
| Mongoose | MongoDB |
| Knex | query builder |
| pg/mysql2 | raw driver |

## Где держать database logic?

Не стоит писать SQL/ORM-запросы прямо в controller. Обычно database-доступ уходит в service, repository или отдельный infrastructure provider.

## Мини-шпаргалка

- NestJS не привязан к одной БД.
- Database client должен быть provider.
- Controllers не должны знать детали БД.
- Transactions лучше проектировать на уровне use case.
- ORM не отменяет понимание SQL.
