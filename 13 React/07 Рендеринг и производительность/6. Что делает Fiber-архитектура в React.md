# Что делает Fiber-архитектура в React?

> [!summary]
> Fiber-архитектура представляет React-дерево как набор fiber-узлов и позволяет React планировать render-работу: разбивать ее на части, назначать приоритеты, прерывать менее срочные обновления и поддерживать concurrent features.

## Зачем нужен Fiber?

Для больших интерфейсов render может быть дорогим. Fiber дает React возможность:

- не выполнять всю работу одним длинным блоком;
- прерывать render;
- возвращаться к работе позже;
- выбрасывать устаревший render;
- отдавать приоритет срочным updates;
- поддерживать transitions и Suspense.

## Что такое fiber-узел?

Упрощенно fiber-узел хранит информацию о части UI:

- component type;
- props;
- state;
- parent/child/sibling связи;
- pending work;
- effects;
- приоритет обновления.

Это внутренняя структура React, с которой разработчик напрямую не работает.

## Как это связано с производительностью?

Fiber не делает тяжелый компонент бесплатным. Но он помогает React управлять работой:

```text
срочный ввод пользователя > тяжелое обновление списка
```

Если список тяжелый, все равно нужны:

- виртуализация;
- мемоизация;
- правильный state placement;
- разделение компонентов;
- transitions.

## Мини-шпаргалка

- Fiber - внутренняя архитектура React.
- Она позволяет планировать render-работу.
- Render phase может быть прервана.
- Commit phase применяет готовые изменения.
- Fiber не отменяет обычные performance-практики.
