# Как тестировать auth, validation, errors и permissions?

> [!summary]
> Auth и permissions нужно тестировать отдельно от happy path. Проверяй отсутствие токена, неверный токен, истекший токен, недостаток прав, доступ к чужим данным, ошибки валидации и формат error response.

## Authentication и authorization

Authentication отвечает: "Кто ты?"

Authorization отвечает: "Что тебе разрешено?"

Тесты должны покрывать оба уровня:

```text
Без токена -> 401
С токеном обычного пользователя -> 403 для admin route
С токеном владельца ресурса -> 200
С токеном другого пользователя -> 403 или 404
```

## Validation tests

```ts
await request(app.getHttpServer())
  .post('/users')
  .send({ email: 'not-email', password: '123' })
  .expect(400)
  .expect(({ body }) => {
    expect(body.message).toEqual(expect.arrayContaining([
      expect.stringContaining('email'),
    ]));
  });
```

## Auth tests

```ts
await request(app.getHttpServer())
  .get('/profile')
  .expect(401);
```

```ts
await request(app.getHttpServer())
  .get('/admin/users')
  .set('Authorization', `Bearer ${userToken}`)
  .expect(403);
```

## Error shape

API должен возвращать предсказуемый формат ошибки:

```json
{
  "statusCode": 400,
  "message": ["email must be an email"],
  "error": "Bad Request"
}
```

Тесты помогают не сломать этот контракт.

## Мини-шпаргалка

- `401` - пользователь не аутентифицирован.
- `403` - пользователь известен, но доступа нет.
- Validation errors должны иметь стабильный формат.
- Проверяй доступ к чужим ресурсам.
- Ошибки важнее happy path для безопасности.
