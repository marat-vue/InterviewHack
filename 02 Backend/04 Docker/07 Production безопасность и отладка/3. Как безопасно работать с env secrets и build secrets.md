# Как безопасно работать с env secrets и build secrets?

> [!summary]
> Secrets нельзя запекать в Dockerfile, image layers или frontend public env. Runtime secrets передают через secret manager, orchestrator, Docker secrets, CI/CD variables или защищенные env, а build secrets - через специальные механизмы BuildKit.

## Что нельзя делать?

Плохо:

```dockerfile
ENV DATABASE_PASSWORD=super-secret
RUN echo "$NPM_TOKEN" > .npmrc
```

Почему плохо:

- значение может попасть в image layers;
- значение может быть видно в history;
- image может уйти в registry;
- secret сложно отозвать из уже собранного image.

## Runtime env

Для локальной разработки:

```yaml
services:
  api:
    env_file:
      - .env
```

Для production лучше использовать:

- secret manager cloud provider;
- orchestrator secrets;
- CI/CD protected variables;
- Docker secrets;
- runtime environment platform.

## Docker secrets в Compose

```yaml
services:
  api:
    image: my-api
    secrets:
      - db_password

secrets:
  db_password:
    file: ./secrets/db_password.txt
```

Secret будет доступен внутри container как файл, обычно в `/run/secrets/...`.

## Build secrets через BuildKit

```dockerfile
# syntax=docker/dockerfile:1

FROM node:22-alpine
WORKDIR /app

RUN --mount=type=secret,id=npm_token \
  NPM_TOKEN="$(cat /run/secrets/npm_token)" npm ci
```

Build:

```bash
docker build --secret id=npm_token,src=.npm_token -t app .
```

Build secret не должен сохраняться в final image.

## Frontend env не секретны

Vite:

```text
VITE_API_URL
```

Next:

```text
NEXT_PUBLIC_API_URL
```

Все, что попало в client bundle, пользователь может увидеть. Нельзя хранить там tokens, private keys, database URLs.

## Что отвечать на собеседовании?

Secrets нельзя хранить в Dockerfile, image layers и public frontend env. Runtime secrets передают через защищенное окружение: secret manager, orchestrator secrets, Docker secrets или CI/CD variables. Build-time secrets нужно передавать через BuildKit `--mount=type=secret`, чтобы они не попадали в layers и history.

## Частые ошибки

- Копировать `.env` в image.
- Использовать `ARG NPM_TOKEN` и считать это безопасным.
- Пушить image с secrets в registry.
- Класть secrets в `NEXT_PUBLIC_*` или `VITE_*`.
- Хранить production `.env` в git.
- Логировать secrets при старте приложения.

## Мини-шпаргалка

- Secrets не должны быть в image.
- `.env` в dev, secret manager в prod.
- BuildKit secrets для build-time доступа.
- `ARG` не безопасен для secrets.
- Public frontend env видны пользователю.
- Не логируй sensitive values.
