# Как использовать profiles override и несколько Compose файлов?

> [!summary]
> Compose profiles и несколько Compose-файлов помогают разделять базовую конфигурацию, dev-инструменты, production-настройки и optional services. Это позволяет не держать все сценарии в одном огромном YAML.

## Profiles

Profiles позволяют запускать service только при необходимости.

```yaml
services:
  api:
    build: .

  adminer:
    image: adminer
    ports:
      - "8080:8080"
    profiles:
      - tools
```

Обычный запуск:

```bash
docker compose up
```

`adminer` не запустится.

Запуск с profile:

```bash
docker compose --profile tools up
```

## Зачем profiles?

- dev tools;
- mailhog;
- adminer;
- pgadmin;
- debug containers;
- optional workers;
- observability stack.

## Несколько Compose файлов

Базовый файл:

```yaml
# compose.yaml
services:
  api:
    image: my-api:latest
    environment:
      NODE_ENV: production
```

Dev override:

```yaml
# compose.dev.yaml
services:
  api:
    build: .
    command: npm run dev
    volumes:
      - .:/app
    environment:
      NODE_ENV: development
```

Запуск:

```bash
docker compose -f compose.yaml -f compose.dev.yaml up
```

Второй файл переопределяет или дополняет первый.

## Автоматический compose.override.yaml

Compose может автоматически читать `compose.override.yaml` рядом с базовым файлом.

Частый паттерн:

- `compose.yaml` - общая база;
- `compose.override.yaml` - локальная разработка;
- `compose.prod.yaml` - production-like настройки.

## Что отвечать на собеседовании?

Profiles позволяют включать optional services только при нужном сценарии, например debug tools. Несколько Compose-файлов позволяют держать базовую конфигурацию отдельно от dev или production overrides. При запуске через несколько `-f` файлы объединяются, а более поздние переопределяют значения предыдущих.

## Частые ошибки

- Держать dev, prod и debug в одном огромном YAML.
- Случайно запускать debug tools в production.
- Не понимать порядок `-f` файлов.
- Переопределить `command` и сломать container startup.
- Хранить production secrets в compose override.

## Мини-шпаргалка

- `profiles` - optional services.
- `--profile tools` - включить profile.
- `-f a -f b` - объединить файлы.
- Поздний файл переопределяет ранний.
- `compose.override.yaml` часто для dev.
- Разделяй base/dev/prod настройки.
