# Как готовить тестовую базу через Testcontainers?

> [!summary]
> Testcontainers поднимает настоящие сервисы в Docker для тестов: PostgreSQL, Redis, RabbitMQ и другие. Это позволяет проверять интеграции с реальной БД или брокером без общей ручной тестовой инфраструктуры.

## Зачем Testcontainers?

Моки не ловят проблемы:

- SQL dialect;
- migrations;
- constraints;
- transactions;
- connection settings;
- Redis commands;
- broker behavior.

Testcontainers поднимает disposable container на время теста или всего test suite.

## Пример PostgreSQL

```ts
import { PostgreSqlContainer } from '@testcontainers/postgresql';

const container = await new PostgreSqlContainer('postgres:16')
  .withDatabase('testdb')
  .withUsername('test')
  .withPassword('test')
  .start();

const databaseUrl = container.getConnectionUri();
```

После этого `databaseUrl` можно передать приложению или ORM.

## Global setup

Для больших наборов тестов контейнер часто поднимают один раз:

```text
global setup -> start PostgreSQL -> run migrations -> tests -> teardown
```

Так быстрее, чем стартовать БД на каждый тест.

## Что важно учесть?

- Docker должен быть доступен в CI;
- контейнеры нужно останавливать;
- миграции должны выполняться перед тестами;
- данные нужно очищать между тестами;
- параллельные тесты требуют изоляции.

## Мини-шпаргалка

- Testcontainers дает настоящую БД/Redis/broker в Docker.
- Это реалистичнее, чем mock database.
- Подходит для integration tests.
- В CI нужен Docker.
- Контейнеры и данные нужно аккуратно очищать.
