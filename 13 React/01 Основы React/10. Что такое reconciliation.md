# Что такое reconciliation?

> [!summary]
> Reconciliation - это процесс, в котором React сравнивает результат нового render с предыдущим деревом и решает, какие части UI нужно обновить. Именно здесь особенно важны типы элементов и `key` в списках.

## Простое определение

Когда state меняется, React вызывает компонент заново:

```jsx
function Counter({ count }) {
  return <button>Счет: {count}</button>
}
```

Было:

```jsx
<button>Счет: 1</button>
```

Стало:

```jsx
<button>Счет: 2</button>
```

React понимает, что тип элемента тот же (`button`), поэтому нужно обновить текст, а не пересоздавать весь узел.

## Какие правила важны?

React использует эвристики:

- если тип элемента изменился, старое поддерево обычно заменяется;
- если тип тот же, React обновляет props и продолжает сравнение детей;
- в списках `key` помогает сопоставить элементы между render;
- разные component types на одной позиции обычно приводят к сбросу состояния.

## Пример с изменением типа

```jsx
{isTitle ? <h1>React</h1> : <p>React</p>}
```

`h1` и `p` - разные типы. React заменит узел.

## Пример с одинаковым типом

```jsx
<button className={isActive ? 'active' : ''}>
  Сохранить
</button>
```

Тип тот же (`button`), меняется только `className`.

## Reconciliation и key

```jsx
{users.map((user) => (
  <UserCard key={user.id} user={user} />
))}
```

`key` говорит React, какой элемент списка соответствует какому объекту данных. Это важно при добавлении, удалении и сортировке.

## Мини-шпаргалка

- Reconciliation сравнивает старое и новое дерево UI.
- Тип элемента влияет на сохранение или сброс поддерева.
- `key` помогает сопоставлять элементы списков.
- Render не равен немедленному изменению DOM.
- DOM меняется после reconciliation на commit-этапе.
