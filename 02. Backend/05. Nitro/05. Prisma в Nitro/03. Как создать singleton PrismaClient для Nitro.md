# Как создать singleton PrismaClient для Nitro?

> [!NOTE]
> `PrismaClient` нужно создавать аккуратно. В development с hot reload нельзя бесконечно создавать новые подключения, а в serverless/edge нужно учитывать lifecycle runtime. Самый частый Nitro-подход - вынести singleton в `server/utils/prisma.ts`.

## Простой вариант

```ts
// server/utils/prisma.ts
import { PrismaClient } from '@prisma/client';

export const prisma = new PrismaClient();
```

Использование:

```ts
export default defineHandler(() => {
  return prisma.user.findMany();
});
```

В Nuxt server utils могут auto-imported, но явный import тоже нормален.

## Development-safe singleton

В dev hot reload может заново выполнять modules. Чтобы не плодить clients:

```ts
// server/utils/prisma.ts
import { PrismaClient } from '@prisma/client';

const globalForPrisma = globalThis as unknown as {
  prisma?: PrismaClient;
};

export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({
    log: process.env.NODE_ENV === 'development'
      ? ['query', 'error', 'warn']
      : ['error'],
  });

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma;
}
```

## Где использовать PrismaClient?

Хорошо:

```txt
server/utils/prisma.ts
server/repositories/userRepository.ts
server/services/userService.ts
server/routes/api/users.get.ts
```

Плохо:

```ts
export default defineHandler(async () => {
  const prisma = new PrismaClient();

  return prisma.user.findMany();
});
```

Так новый client создается на каждый request.

## Нужно ли вызывать `$disconnect`?

В long-running Node server обычно не нужно disconnect после каждого запроса.

Можно закрывать при shutdown:

```ts
export default definePlugin((nitroApp) => {
  nitroApp.hooks.hook('close', async () => {
    await prisma.$disconnect();
  });
});
```

Если выбранная версия Nitro/hooks не дает нужный hook, закрытие connections настраивают через runtime/process lifecycle или платформу.

## Serverless замечания

В serverless:

- functions могут иметь cold starts;
- глобальный singleton может переиспользоваться между invocations;
- connection pool может быстро исчерпаться;
- для PostgreSQL часто нужен pooler/proxy;
- Prisma Accelerate/Data Proxy или managed pooling могут быть полезны.

## Edge замечания

Не каждый Prisma setup подходит для edge runtime. Проверяй:

- поддерживает ли Prisma Client выбранный runtime;
- нужен ли driver adapter;
- есть ли Node-specific APIs;
- как подключается database;
- можно ли использовать HTTP-based database/proxy.

Если Nitro preset edge, сначала проверь compatibility Prisma для конкретной БД.

## Мини-шпаргалка

- Не создавай `new PrismaClient()` внутри каждого request.
- Вынеси client в `server/utils/prisma.ts`.
- В dev используй `globalThis` singleton pattern.
- В Node server не делай `$disconnect` после каждого route.
- В serverless думай о connection pool.
- В edge проверяй совместимость Prisma runtime.
