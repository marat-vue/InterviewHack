# Что такое “Atomic Design” в React-архитектуре?

> [!summary]
> Atomic Design - это подход к организации UI как системы компонентов: от маленьких базовых элементов до готовых страниц. В React он помогает строить дизайн-системы, переиспользуемые компоненты и понятную иерархию интерфейса.

## Пять уровней Atomic Design

```text
Atoms -> Molecules -> Organisms -> Templates -> Pages
```

| Уровень | Что это | Пример |
|---|---|---|
| Atoms | Минимальные UI-элементы | `Button`, `Input`, `Icon`, `Badge` |
| Molecules | Небольшие сочетания атомов | `SearchField`, `PriceInput`, `FormRow` |
| Organisms | Самостоятельные блоки интерфейса | `Header`, `ProductCard`, `FiltersPanel` |
| Templates | Макет страницы без конкретных данных | `CatalogTemplate`, `ProfileLayout` |
| Pages | Готовая страница с данными и сценариями | `CatalogPage`, `ProfilePage` |

## Пример в React

Atom:

```jsx
function Button({ children, variant = 'primary', onClick }) {
  return (
    <button className={`button button_${variant}`} onClick={onClick}>
      {children}
    </button>
  )
}
```

Molecule:

```jsx
function SearchField({ value, onChange, onSubmit }) {
  return (
    <form onSubmit={onSubmit}>
      <Input value={value} onChange={onChange} />
      <Button>Search</Button>
    </form>
  )
}
```

Organism:

```jsx
function Header({ query, onQueryChange, onSearch }) {
  return (
    <header>
      <Logo />
      <SearchField value={query} onChange={onQueryChange} onSubmit={onSearch} />
      <UserMenu />
    </header>
  )
}
```

## Возможная структура папок

```text
src/
  ui/
    atoms/
      button/
      input/
    molecules/
      search-field/
      form-row/
    organisms/
      header/
      product-card/
    templates/
      catalog-template/
    pages/
      catalog-page/
```

В реальном проекте Atomic Design часто смешивают с feature-based архитектурой: атомы и базовые молекулы кладут в `shared/ui`, а бизнес-блоки - в `features`, `widgets` или `pages`.

## Плюсы

- единый UI language;
- проще поддерживать дизайн-систему;
- компоненты легче переиспользовать;
- удобно писать Storybook;
- проще обсуждать UI с дизайнером.

## Минусы и ловушки

- не всегда понятно, molecule это или organism;
- можно начать дробить слишком мелко;
- бизнес-логика плохо укладывается в чистую атомарную иерархию;
- для больших приложений одного Atomic Design часто недостаточно.

## Мини-шпаргалка

- Atomic Design строит UI снизу вверх.
- Atoms - самые маленькие элементы.
- Molecules - связки элементов.
- Organisms - крупные блоки.
- Pages - реальные экраны с данными.
- Для архитектуры приложения Atomic Design лучше сочетать с feature-based подходом.
