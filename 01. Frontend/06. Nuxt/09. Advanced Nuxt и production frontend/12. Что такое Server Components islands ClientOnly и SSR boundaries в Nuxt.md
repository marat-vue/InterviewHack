# Что такое Server Components, islands, ClientOnly и SSR boundaries в Nuxt?

> [!NOTE]
> Nuxt по умолчанию рендерит приложение на сервере и затем гидратирует его на клиенте. Но не каждый компонент должен отправлять JavaScript в браузер, и не каждый browser-only компонент можно рендерить на сервере.

## Какие boundaries есть?

| Инструмент | Где выполняется | Для чего |
| --- | --- | --- |
| Обычный component | SSR + client hydration | Большинство UI. |
| `.client.vue` | Только client | Browser-only libraries, maps, charts. |
| `.server.vue` | Server component/island | Content-heavy UI без client JS. |
| `<ClientOnly>` | Client-only subtree | Обернуть кусок, который нельзя SSR. |
| `<NuxtIsland>` | Server-rendered island | Явно отрендерить server island. |
| Lazy hydration | SSR HTML + отложенная hydration | Снизить нагрузку на main thread. |

## `.client.vue`

```text
app/components/Map.client.vue
```

```vue
<template>
  <div ref="mapEl" />
</template>

<script setup lang="ts">
const mapEl = ref<HTMLElement | null>(null)

onMounted(async () => {
  const mapLibrary = await import('some-browser-map')
  mapLibrary.createMap(mapEl.value)
})
</script>
```

Этот компонент не будет рендериться на сервере.

## `<ClientOnly>`

```vue
<template>
  <ClientOnly fallback-tag="span" fallback="Загрузка карты">
    <Map />
  </ClientOnly>
</template>
```

Используй `<ClientOnly>`, когда:

- компонент обращается к `window`;
- библиотека требует DOM;
- SSR markup невозможно сделать корректным;
- временный fallback лучше, чем hydration mismatch.

## `.server.vue`

```text
app/components/MarkdownPreview.server.vue
```

```vue
<script setup lang="ts">
const props = defineProps<{
  markdown: string
}>()

const html = await renderMarkdown(props.markdown)
</script>

<template>
  <article v-html="html" />
</template>
```

Server component полезен, если:

- тяжелая зависимость нужна только на сервере;
- компонент статический;
- не нужно client interactivity;
- важно уменьшить JS bundle.

## `<NuxtIsland>`

```vue
<template>
  <NuxtIsland
    name="MarkdownPreview"
    :props="{ markdown: '# Hello' }"
  />
</template>
```

Island рендерится отдельно на сервере. На client navigation это может быть отдельный network request.

## Ограничения islands

Важно помнить:

- island изолирован от основного Vue app;
- state через `provide/inject`, Pinia и `useState` не шарится напрямую;
- route middleware не выполняется при render island;
- props должны быть JSON-serializable;
- props могут попасть в URL/query/logs;
- частые islands увеличивают количество запросов на client navigation.

Данные лучше передавать явно через props, а не пытаться читать текущий route внутри island.

## Selective client hydration

Если в server component нужен маленький интерактивный кусок:

```ts
export default defineNuxtConfig({
  experimental: {
    componentIslands: {
      selectiveClient: true
    }
  }
})
```

Внутри `.server.vue`:

```vue
<template>
  <article>
    <MarkdownBody />
    <LikeButton nuxt-client />
  </article>
</template>
```

Это advanced/experimental сценарий. Перед production обязательно проверяй limitations.

## SSR-safe проверка

Плохо:

```ts
const width = window.innerWidth
```

Хорошо:

```ts
const width = ref(0)

onMounted(() => {
  width.value = window.innerWidth
})
```

или:

```ts
if (import.meta.client) {
  console.log(window.innerWidth)
}
```

## Как выбирать?

| Сценарий | Выбор |
| --- | --- |
| Обычная карточка товара | Обычный component. |
| Интерактивная форма | Обычный component. |
| Map/chart library только для browser | `.client.vue` или `<ClientOnly>`. |
| Markdown/docs rendering без интерактивности | `.server.vue` или island. |
| Маркетинговый блок с одной интерактивной кнопкой | Server component + small client child, если оправдано. |
| Виджет с частыми обновлениями | Обычный hydrated component. |

## Что отвечать на собеседовании?

В Nuxt SSR не означает, что весь код безопасен для сервера. Browser-only код нужно выносить в `.client.vue`, `onMounted`, `import.meta.client` или `<ClientOnly>`. Server components и islands позволяют рендерить часть UI только на сервере и не отправлять JS в браузер, но имеют ограничения по state, route context, props serialization и дополнительным запросам при client navigation.

## Частые ошибки

- Использовать `window` в top-level `<script setup>`.
- Прятать все в `<ClientOnly>` и терять SSR/SEO преимущества.
- Делать слишком много islands на странице.
- Передавать sensitive data в island props.
- Ожидать, что Pinia state автоматически доступен внутри island.
- Использовать experimental selective hydration без проверки production behavior.

## Мини-шпаргалка

- Browser-only: `.client.vue`, `<ClientOnly>`, `onMounted`.
- Server-only component: `.server.vue`.
- Explicit island: `<NuxtIsland>`.
- Islands do not share app state directly.
- Props serializable and not secret.
- Частая интерактивность - обычный component.
