# Чем отличается “Uncontrolled Component”?

> [!summary]
> Uncontrolled Component хранит свое значение внутри DOM или внутри собственного внутреннего state. Родитель не управляет каждым изменением через `value`, а может прочитать значение позже через `ref` или получить финальный результат через callback.

## Пример с ref

```jsx
function LoginForm() {
  const emailRef = useRef(null)

  function handleSubmit(event) {
    event.preventDefault()
    console.log(emailRef.current.value)
  }

  return (
    <form onSubmit={handleSubmit}>
      <input ref={emailRef} defaultValue="" />
      <button>Login</button>
    </form>
  )
}
```

Здесь React не хранит значение `input` на каждый символ. Значение живет в DOM.

## defaultValue вместо value

Для uncontrolled input используют `defaultValue`:

```jsx
<input defaultValue="Ada" />
```

`defaultValue` задает начальное значение. После этого input меняется сам.

Если использовать `value`, компонент становится controlled:

```jsx
<input value={email} onChange={(event) => setEmail(event.target.value)} />
```

## Uncontrolled UI-компонент

Компонент может хранить состояние внутри себя:

```jsx
function Accordion({ defaultOpen = false }) {
  const [isOpen, setIsOpen] = useState(defaultOpen)

  return (
    <section>
      <button onClick={() => setIsOpen((value) => !value)}>
        Toggle
      </button>
      {isOpen && <div>Content</div>}
    </section>
  )
}
```

Родитель не знает текущее `isOpen` и не управляет им.

## Controlled vs uncontrolled

| Критерий | Controlled | Uncontrolled |
|---|---|---|
| Источник истины | React state родителя | DOM или внутренний state |
| Синхронизация | Максимальная | Ограниченная |
| Кода | Больше | Меньше |
| Валидация на вводе | Удобнее | Сложнее |
| Простые формы | Иногда избыточно | Часто удобно |

## Когда uncontrolled удобен?

- простая форма без live validation;
- поле нужно прочитать только при submit;
- file input;
- интеграция со сторонней DOM-библиотекой;
- компонент должен сам управлять своим раскрытием.

## Важное правило

Не переключай компонент между controlled и uncontrolled режимами во время жизни.

Плохо:

```jsx
<input value={maybeValue} />
```

Если `maybeValue` иногда `undefined`, input может начать uncontrolled, а потом стать controlled. Лучше явно задать пустую строку:

```jsx
<input value={maybeValue ?? ''} />
```

## Мини-шпаргалка

- Uncontrolled component не получает текущее значение через `value`.
- Для начального значения используют `defaultValue` или `defaultChecked`.
- Значение можно читать через `ref`.
- Для сложной валидации чаще удобнее controlled.
- Нельзя случайно менять режим controlled/uncontrolled.
