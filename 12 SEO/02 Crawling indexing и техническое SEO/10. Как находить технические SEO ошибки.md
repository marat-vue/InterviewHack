# Как находить технические SEO ошибки?

> [!summary]
> Технический SEO-аудит проверяет, может ли поисковик нормально найти, скачать, отрендерить, понять и проиндексировать страницы. Это база перед работой с контентом и продвижением.

## С чего начать аудит?

Порядок:

1. Проверить статус-коды важных страниц.
2. Проверить robots.txt.
3. Проверить sitemap.xml.
4. Проверить canonical.
5. Проверить индексацию в Search Console.
6. Проверить title, description и headings.
7. Проверить JS-рендеринг.
8. Проверить Core Web Vitals.
9. Проверить structured data.
10. Проверить внутренние ссылки.

## Какие ошибки искать?

| Ошибка | Почему опасна |
|---|---|
| Важная страница закрыта в robots.txt | робот не может ее обойти |
| На важной странице стоит `noindex` | страница выпадет из индекса |
| Canonical ведет не туда | поисковик может выбрать другой URL |
| Sitemap содержит `404` или redirect | карта сайта загрязнена |
| Много soft 404 | плохое качество индекса |
| Title одинаковые | сложнее понять уникальность страниц |
| Контент появляется только после действия пользователя | робот может его не увидеть |

## Мини-команды для разработчика

```bash
curl -I https://example.com/page
```

Проверить статус и заголовки.

```bash
curl https://example.com/robots.txt
```

Проверить robots.txt.

```bash
curl -L -I https://example.com/old-page
```

Проверить цепочку редиректов.

## Что фиксировать в отчете?

Для каждой проблемы:

- URL;
- тип ошибки;
- ожидаемое поведение;
- фактическое поведение;
- влияние на SEO;
- приоритет;
- способ исправления;
- как проверить после фикса.

## Мини-шпаргалка

- Начинай с доступности и индексации.
- Проверяй важные шаблоны страниц, а не только главную.
- Любая SEO-ошибка должна иметь URL-пример.
- Аудит без приоритизации мало помогает команде.
- После фикса нужно перепроверять фактический HTML и Search Console.
