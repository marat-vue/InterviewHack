# Что делает startTransition()?

> [!summary]
> `startTransition` помечает state updates как transition без использования хука. Это полезно, если нужно назначить обновлению меньший приоритет, но не нужен флаг `isPending`.

## Импорт

```jsx
import { startTransition } from 'react'
```

## Базовый пример

```jsx
function selectTab(nextTab) {
  startTransition(() => {
    setTab(nextTab)
  })
}
```

React получает сигнал: это обновление не срочное, его можно прервать или отложить ради более важной работы.

## Когда использовать standalone API?

`startTransition` без хука удобен:

- в helper-функциях;
- в state manager integrations;
- в callbacks вне компонента;
- когда pending indicator не нужен;
- когда update планируется из общего слоя.

Если нужен `isPending`, используй `useTransition`.

## Пример с external action

```jsx
import { startTransition } from 'react'

export function updateRouteState(setRoute, nextRoute) {
  startTransition(() => {
    setRoute(nextRoute)
  })
}
```

## Важное ограничение

`startTransition` должен синхронно обернуть state updates.

```jsx
startTransition(() => {
  setPage('/reports')
})
```

Если update происходит после `await`, его может понадобиться обернуть снова:

```jsx
startTransition(async () => {
  const data = await loadData()

  startTransition(() => {
    setData(data)
  })
})
```

## Не для input value

```jsx
startTransition(() => {
  setInputValue(event.target.value) // плохо
})
```

Controlled input должен обновляться срочно.

## Мини-шпаргалка

- `startTransition` помечает updates как несрочные.
- Не дает `isPending`.
- Не делает код многопоточным.
- Не используй для срочного ввода.
- Для UI-индикатора нужен `useTransition`.
