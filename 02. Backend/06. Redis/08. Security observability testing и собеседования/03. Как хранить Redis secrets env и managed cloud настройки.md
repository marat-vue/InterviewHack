# Как хранить Redis secrets, env и managed cloud настройки?

> [!NOTE]
> Redis credentials - полноценные production secrets. Утечка `REDIS_URL` может дать доступ к sessions, cache, tokens, queues и internal events.

## Какие env обычно нужны?

```bash
REDIS_URL="rediss://api:password@redis.example.com:6380"
REDIS_KEY_PREFIX="prod:api"
REDIS_TLS="true"
```

Иногда managed provider дает:

```bash
REDIS_HOST=""
REDIS_PORT=""
REDIS_USERNAME=""
REDIS_PASSWORD=""
```

## Где хранить secrets?

Хорошо:

- platform secrets;
- CI/CD secrets;
- secret manager;
- Kubernetes Secret;
- encrypted local env для development.

Плохо:

- README;
- committed `.env`;
- screenshots;
- logs;
- issue tracker;
- frontend bundle.

## Как не логировать пароль?

Плохо:

```ts
console.log(process.env.REDIS_URL);
```

Лучше:

```ts
logger.info({
  redisConfigured: Boolean(process.env.REDIS_URL),
}, 'Redis config loaded');
```

## Managed cloud checklist

Проверь:

- private endpoint;
- TLS;
- ACL/users;
- memory limit;
- eviction policy;
- persistence/backups;
- metrics;
- maintenance window;
- max connections;
- region рядом с приложением;
- failover behavior.

## Local development

`.env.local`:

```bash
REDIS_URL="redis://default:local_password@localhost:6379"
```

Файл должен быть в `.gitignore`.

## Мини-шпаргалка

- Redis URL часто содержит пароль.
- Не логируй полный URL.
- Managed Redis настрой через private endpoint и TLS.
- Secrets должны жить вне Git.
- Region влияет на latency.
