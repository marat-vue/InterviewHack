# Как формируется итоговый title?

> [!summary]
> Итоговый `<title>` в Next.js формируется через наследование metadata от layout к page. Родительский layout может задавать `title.default` и `title.template`, а дочерняя страница может задать конкретный `title`, который будет подставлен в шаблон.

## Базовый вариант

```tsx
// app/about/page.tsx
export const metadata = {
  title: 'О проекте',
}
```

Результат:

```html
<title>О проекте</title>
```

Если нет шаблона от layout, строка становится обычным title.

## Title template

Обычно в Root Layout задают общий шаблон сайта:

```tsx
// app/layout.tsx
export const metadata = {
  title: {
    default: 'Frontend Notes',
    template: '%s | Frontend Notes',
  },
}
```

А на странице задают конкретный title:

```tsx
// app/next/page.tsx
export const metadata = {
  title: 'Next.js',
}
```

Результат:

```html
<title>Next.js | Frontend Notes</title>
```

`%s` - место, куда Next.js подставляет title дочерней страницы.

## Для чего нужен title.default?

Если layout задает `title.template`, ему нужен `title.default`.

```tsx
export const metadata = {
  title: {
    default: 'Мой сайт',
    template: '%s | Мой сайт',
  },
}
```

`default` используется, когда дочерний segment не указал свой title.

Например главная страница может получить:

```html
<title>Мой сайт</title>
```

А страница блога:

```html
<title>Блог | Мой сайт</title>
```

## title.absolute

Иногда нужно полностью проигнорировать родительский template:

```tsx
export const metadata = {
  title: {
    absolute: 'Документация API',
  },
}
```

Это полезно для страниц, где брендовый хвост не нужен или должен быть другим.

## Вложенные layout

```text
app/
  layout.tsx
  dashboard/
    layout.tsx
    settings/
      page.tsx
```

Пример:

```tsx
// app/layout.tsx
export const metadata = {
  title: {
    default: 'Site',
    template: '%s | Site',
  },
}
```

```tsx
// app/dashboard/settings/page.tsx
export const metadata = {
  title: 'Settings',
}
```

Результат:

```html
<title>Settings | Site</title>
```

Чем ближе metadata к странице, тем конкретнее значение. Родительские layout задают общие правила, а page задает смысл конкретного экрана.

## Dynamic title

С `generateMetadata` правила те же:

```tsx
export async function generateMetadata({ params }: Props) {
  const { slug } = await params
  const post = await getPost(slug)

  return {
    title: post.title,
  }
}
```

Если сверху есть template `'%s | Blog'`, итог будет:

```html
<title>Название статьи | Blog</title>
```

## Хорошие правила для title

- Делай title уникальным для каждой важной страницы.
- Ставь главный смысл ближе к началу.
- Не превращай title в набор ключевых слов.
- Используй шаблон сайта в layout.
- Для страниц пагинации и фильтров явно решай, нужен ли уникальный title.
- Не делай title слишком длинным: поисковик может обрезать его в выдаче.

## Что отвечать на собеседовании?

Итоговый title в Next.js собирается через Metadata API. Родительский layout может задать `title.default` и `title.template`, а дочерняя page или вложенный layout задает конкретный `title`. Если нужно обойти шаблон, используют `title.absolute`. Для динамических страниц title возвращают из `generateMetadata`.

## Частые ошибки

- Забывать `default` рядом с `template`.
- Думать, что `title.template` применится к самому segment, где он объявлен, а не к дочерним.
- Делать одинаковые title для всех страниц.
- Злоупотреблять `title.absolute`.
- Писать title только под поисковик, а не под человека.
- Дублировать title в JSX вручную.

## Мини-шпаргалка

- `title: 'Page'` - конкретный title.
- `title.default` - fallback.
- `title.template` - шаблон для дочерних страниц.
- `%s` - место подстановки.
- `title.absolute` - игнорирует template.
- `generateMetadata` может вернуть динамический title.
