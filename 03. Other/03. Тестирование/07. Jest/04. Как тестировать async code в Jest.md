# Как тестировать async code в Jest?

> [!summary]
> Асинхронный код в Jest тестируют через `async/await`, возвращаемые promises, `resolves`, `rejects` или callback `done`. Главное - не дать тесту завершиться раньше, чем выполнится асинхронная проверка.

## `async/await`

```ts
test('loads user', async () => {
  const user = await loadUser(1);

  expect(user.name).toBe('Ann');
});
```

Это самый читаемый вариант.

## `resolves`

```ts
test('resolves with user', async () => {
  await expect(loadUser(1)).resolves.toEqual({
    id: 1,
    name: 'Ann',
  });
});
```

## `rejects`

```ts
test('rejects if user not found', async () => {
  await expect(loadUser(999)).rejects.toThrow('User not found');
});
```

Важно поставить `await`. Без него assertion может не выполниться до завершения теста.

## Callback `done`

Для callback-style API:

```ts
test('calls callback with data', (done) => {
  fetchData((error, data) => {
    expect(error).toBeNull();
    expect(data).toBe('hello');
    done();
  });
});
```

Если есть возможность, лучше обернуть callback API в promise и использовать `async/await`.

## Проверка количества assertions

```ts
test('handles error', async () => {
  expect.assertions(1);

  try {
    await loadUser(999);
  } catch (error) {
    expect(error).toBeInstanceOf(Error);
  }
});
```

Это защищает от ситуации, когда `catch` не выполнился.

## Мини-шпаргалка

- Лучший стиль для async tests - `async/await`.
- `resolves` проверяет fulfilled promise.
- `rejects` проверяет rejected promise.
- Callback tests используют `done`.
- Всегда await-ь async assertions.
