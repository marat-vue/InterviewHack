# Что такое sticky sessions и почему они важны для WebSocket?

> [!summary]
> Sticky sessions заставляют load balancer отправлять одного клиента на один и тот же backend-инстанс. Это важно для WebSocket и stateful-сессий, потому что постоянное соединение живет внутри конкретного процесса.

## Проблема при масштабировании

Допустим, есть три инстанса:

```txt
client -> load balancer -> app-1
                       -> app-2
                       -> app-3
```

HTTP-запросы можно распределять между ними свободно, если приложение stateless. Но WebSocket-соединение установлено с конкретным инстансом.

## Что делают sticky sessions?

Load balancer запоминает клиента и направляет его на тот же backend.

```txt
client A -> app-1
client B -> app-2
client A -> app-1
```

## WebSocket и общие события

Если пользователь подключен к `app-1`, а событие произошло на `app-3`, нужно доставить сообщение между инстансами.

Обычно используют:

- Redis pub/sub;
- message broker;
- adapter библиотеки;
- внешний realtime-сервис.

## Когда sticky не нужен?

Если весь state вынесен наружу, а соединениями управляет отдельный gateway или broker, sticky sessions могут быть не нужны. Но для обычного WebSocket-сервера о них нужно помнить.

## Мини-шпаргалка

- Sticky sessions привязывают клиента к инстансу.
- WebSocket-соединение живет внутри конкретного процесса.
- При нескольких инстансах нужен межпроцессный broadcast.
- Stateless HTTP проще масштабировать.
- Для Socket.IO часто нужен adapter, например Redis adapter.
