# Почему Fiber делает React асинхронным?

> [!summary]
> Fiber не делает JavaScript многопоточным. Он делает render-работу React планируемой и потенциально прерываемой: React может начать вычислять UI, отложить менее срочную работу и сначала обработать более важное обновление.

## Что значит "асинхронный" в этом контексте?

Обычно имеют в виду:

```text
React не обязан синхронно закончить всю render-работу сразу после update.
```

Он может:

- поставить update в очередь;
- выбрать приоритет;
- начать render;
- прервать render;
- продолжить позже;
- commit-нуть готовый результат.

## Что остается синхронным?

Commit phase должна применить готовые DOM-изменения согласованно.

Пользователь не должен увидеть:

```text
половина старого UI + половина нового UI
```

## Пример

```jsx
startTransition(() => {
  setFilter(nextFilter)
})
```

Обновление фильтра тяжелого списка можно пометить как transition. Если пользователь продолжит печатать, React может сначала обработать ввод.

## Почему это важно для кода?

Render должен быть чистым:

```jsx
function Component() {
  // нельзя: side effect в render
  localStorage.setItem('x', '1')
  return <div />
}
```

Если render повторится или будет выброшен, side effect уже произошел, хотя UI мог не попасть в DOM.

## Мини-шпаргалка

- Fiber делает render-работу планируемой.
- Это не Web Worker и не многопоточность.
- Render может быть отложен или прерван.
- Commit применяет готовый результат.
- Side effects должны быть вне render.
