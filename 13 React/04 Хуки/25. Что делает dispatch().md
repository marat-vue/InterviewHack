# Что делает dispatch?

> [!summary]
> `dispatch` - функция, которую возвращает `useReducer`. Она отправляет action в reducer. Reducer получает текущее состояние и action, а затем возвращает новое состояние.

## Базовый пример

```jsx
function reducer(state, action) {
  switch (action.type) {
    case 'increment':
      return { count: state.count + 1 }
    case 'reset':
      return { count: 0 }
    default:
      return state
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 })

  return (
    <>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'reset' })}>Сброс</button>
      <span>{state.count}</span>
    </>
  )
}
```

`dispatch({ type: 'increment' })` не меняет state напрямую. Он сообщает reducer, что произошло.

## Что такое action?

Action - объект или значение, описывающее событие:

```jsx
dispatch({
  type: 'fieldChanged',
  field: 'email',
  value: 'user@mail.com',
})
```

Хороший action отвечает на вопрос:

```text
Что произошло в интерфейсе или домене?
```

## Почему dispatch удобен?

- Handlers становятся короче.
- Логика обновлений собрана в reducer.
- Actions легче логировать.
- Reducer можно тестировать отдельно.
- Сложные переходы state становятся явными.

## Важный нюанс

`dispatch` имеет стабильную идентичность. Поэтому обычно его не нужно добавлять в dependency array, если речь именно о dispatch из `useReducer`.

Но action-creator функции, которые ты создаешь сам, уже могут зависеть от props/state.

## Частые ошибки

- Делать side effects внутри reducer.
- Мутировать state в reducer.
- Отправлять слишком общие actions вроде `{ type: 'change' }`.
- Дублировать reducer-логику в компонентах.
- Использовать reducer для слишком простого boolean-флага без пользы.

## Мини-шпаргалка

- `dispatch` отправляет action.
- Action описывает событие.
- Reducer вычисляет новый state.
- Reducer должен быть чистым.
- `dispatch` удобен для сложной логики обновлений.
