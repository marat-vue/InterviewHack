# Когда React выполняет useLayoutEffect?

> [!summary]
> React выполняет `useLayoutEffect` после commit-этапа, когда DOM уже обновлен, но до того, как браузер успеет отрисовать экран. Поэтому он подходит для измерений и синхронной корректировки layout.

## Последовательность

```text
1. React вызывает render
2. React применяет изменения к DOM, commit
3. React запускает useLayoutEffect
4. Если внутри есть setState, React сразу делает повторный render
5. Браузер рисует экран
6. React запускает обычные useEffect
```

Ключевой момент: пользователь не видит промежуточный неправильный layout.

## Пример с измерением

```jsx
function Box() {
  const boxRef = useRef(null)
  const [width, setWidth] = useState(0)

  useLayoutEffect(() => {
    setWidth(boxRef.current.getBoundingClientRect().width)
  }, [])

  return <div ref={boxRef}>Ширина: {width}</div>
}
```

React сначала вставляет `div` в DOM, потом измеряет его, потом при необходимости обновляет state до paint.

## Что происходит при изменении dependencies?

Если dependencies изменились:

```text
cleanup старого layout effect -> setup нового layout effect
```

Это похоже на `useEffect`, но момент выполнения раньше.

## Strict Mode

В development Strict Mode React может выполнить дополнительный цикл setup-cleanup-setup. Это проверка корректности cleanup.

Если код ломается от повторного запуска, проблема не в Strict Mode, а в том, что effect не умеет безопасно очищаться.

## Мини-шпаргалка

- `useLayoutEffect` запускается после commit.
- Он запускается до browser paint.
- State update внутри него выполняется сразу, до показа кадра.
- Cleanup выполняется перед новым setup и при unmount.
- В Strict Mode development возможен дополнительный запуск.
