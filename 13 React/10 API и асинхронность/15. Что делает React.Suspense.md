# Что делает React.Suspense?

> [!summary]
> `<Suspense>` позволяет React показать запасной UI, пока часть дерева не готова к отображению. Самый стабильный и распространенный кейс - lazy loading компонентов через `React.lazy`; для data fetching Suspense работает только со Suspense-enabled источниками.

## Базовый пример с lazy

```jsx
import { lazy, Suspense } from 'react'

const SettingsPage = lazy(() => import('./SettingsPage'))

function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <SettingsPage />
    </Suspense>
  )
}
```

Пока загружается chunk с `SettingsPage`, React показывает `fallback`.

## Как работает Suspense?

```text
1. React рендерит subtree
2. Часть subtree suspends
3. React ищет ближайший Suspense выше
4. Показывает fallback
5. Когда ресурс готов, React повторяет render
6. Показывает настоящий UI
```

## Что может suspend?

Suspense срабатывает не на любой async-код.

Работает с:

- `React.lazy`;
- framework data fetching;
- cached Promise через `use`;
- библиотеками, которые явно поддерживают Suspense.

Не работает автоматически с:

```jsx
useEffect(() => {
  fetch('/api/user')
}, [])
```

Для обычного fetch в effect нужен свой loading state или query-библиотека.

## Несколько Suspense boundaries

```jsx
function ProductPage() {
  return (
    <>
      <ProductInfo />

      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />
      </Suspense>

      <Suspense fallback={<RecommendationsSkeleton />}>
        <Recommendations />
      </Suspense>
    </>
  )
}
```

Так страница может показываться частями.

## Suspense и Error Boundary

`Suspense` отвечает за ожидание.

`Error Boundary` отвечает за ошибку.

```jsx
<ErrorBoundary fallback={<ErrorFallback />}>
  <Suspense fallback={<Loading />}>
    <LazyPage />
  </Suspense>
</ErrorBoundary>
```

Если lazy-import отклонится, ошибка попадет в ближайший Error Boundary.

## Мини-шпаргалка

- Suspense показывает `fallback`.
- `React.lazy` должен быть внутри Suspense.
- Suspense не ловит обычный `fetch` в `useEffect`.
- Несколько boundaries улучшают постепенную загрузку UI.
- Ошибки обрабатывает Error Boundary, не Suspense.
