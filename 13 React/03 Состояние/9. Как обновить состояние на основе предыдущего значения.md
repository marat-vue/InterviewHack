# Как обновить состояние на основе предыдущего значения?

> [!summary]
> Если новое состояние зависит от предыдущего, в setter нужно передавать updater function. Это защищает от устаревших значений, batching и нескольких обновлений подряд.

## Плохой пример

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  function incrementThreeTimes() {
    setCount(count + 1)
    setCount(count + 1)
    setCount(count + 1)
  }

  return <button onClick={incrementThreeTimes}>{count}</button>
}
```

Если `count` был `0`, все три вызова используют значение `0` из текущего render. Итог может быть `1`, а не `3`.

## Правильный вариант

```jsx
function incrementThreeTimes() {
  setCount((count) => count + 1)
  setCount((count) => count + 1)
  setCount((count) => count + 1)
}
```

React поставит updater-функции в очередь и применит их последовательно.

## Как это читать?

```jsx
setCount((previousCount) => previousCount + 1)
```

Смысл:

```text
Возьми актуальное предыдущее значение и верни следующее.
```

## Обновление объекта от предыдущего state

```jsx
setUser((user) => ({
  ...user,
  name: 'Мария',
}))
```

Обновление массива:

```jsx
setItems((items) => [...items, newItem])
```

Удаление из массива:

```jsx
setItems((items) => items.filter((item) => item.id !== id))
```

## Когда updater function особенно нужна?

- несколько обновлений подряд;
- обновление внутри async callback;
- обновление в таймере;
- новое значение зависит от старого;
- setter передается глубоко в компонент;
- есть риск stale closure.

## Мини-шпаргалка

- Если новое state зависит от старого, используй updater function.
- `setCount(count + 1)` берет значение из текущего render.
- `setCount((count) => count + 1)` берет актуальное значение из очереди.
- Updater помогает при batching.
- Для объектов и массивов все равно нужно возвращать новое значение.
