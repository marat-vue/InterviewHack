# Какие методы Vitest нужно знать?

> [!NOTE]
> В Vitest важно знать test API, lifecycle hooks, assertions и `vi` utilities. Этого хватает для большинства Nitro unit/integration tests.

## Test API

| Метод | Зачем нужен |
|---|---|
| `test(name, fn)` | объявить test case |
| `it(name, fn)` | alias для `test`, часто читается как "it should..." |
| `describe(name, fn)` | сгруппировать tests |
| `test.only` / `it.only` | запустить только один test |
| `test.skip` / `it.skip` | пропустить test |
| `test.todo` | отметить будущий test |
| `test.each` | parameterized tests |
| `describe.each` | parameterized suites |
| `test.concurrent` | concurrent test |
| `test.fails` | test, который ожидаемо падает |

Пример:

```ts
describe.each([
  [1, 2, 3],
  [2, 2, 4],
])('sum', (a, b, expected) => {
  it(`returns ${expected}`, () => {
    expect(a + b).toBe(expected);
  });
});
```

## Lifecycle hooks

| Метод | Когда выполняется |
|---|---|
| `beforeAll` | один раз перед suite |
| `afterAll` | один раз после suite |
| `beforeEach` | перед каждым test |
| `afterEach` | после каждого test |

Пример:

```ts
import { afterEach, beforeAll } from 'vitest';

beforeAll(async () => {
  await prisma.$connect();
});

afterEach(async () => {
  await prisma.user.deleteMany();
});
```

## Основные expect matchers

| Matcher | Что проверяет |
|---|---|
| `toBe` | strict equality |
| `toEqual` | deep equality |
| `toStrictEqual` | более строгая deep equality |
| `toContain` | содержит элемент/строку |
| `toMatchObject` | объект частично совпадает |
| `toHaveProperty` | есть property |
| `toBeTruthy` / `toBeFalsy` | truthy/falsy |
| `toBeNull` / `toBeUndefined` | null/undefined |
| `toThrow` | функция бросает ошибку |
| `resolves` / `rejects` | promise success/error |
| `toMatchInlineSnapshot` | inline snapshot |

Пример:

```ts
await expect(userService.findById('missing')).rejects.toThrow('not found');
```

## Mock assertions

| Matcher | Что проверяет |
|---|---|
| `toHaveBeenCalled` | mock был вызван |
| `toHaveBeenCalledTimes` | количество вызовов |
| `toHaveBeenCalledWith` | args вызова |
| `toHaveBeenLastCalledWith` | args последнего вызова |
| `toHaveReturned` | mock вернул значение |
| `toHaveReturnedWith` | mock вернул конкретное значение |

## `vi` methods

| Метод | Зачем нужен |
|---|---|
| `vi.fn()` | создать mock function |
| `vi.spyOn(obj, method)` | следить за методом объекта |
| `vi.mock(module, factory?)` | замокать module |
| `vi.doMock(module, factory?)` | dynamic mock |
| `vi.importActual(module)` | получить реальный module внутри mock |
| `vi.mocked(value)` | типизированный mocked value |
| `vi.clearAllMocks()` | очистить call history |
| `vi.resetAllMocks()` | reset mock implementation/history |
| `vi.restoreAllMocks()` | восстановить original spies |
| `vi.useFakeTimers()` | включить fake timers |
| `vi.useRealTimers()` | вернуть real timers |
| `vi.setSystemTime(date)` | замокать текущую дату |
| `vi.advanceTimersByTime(ms)` | продвинуть timers |
| `vi.stubEnv(name, value)` | замокать env |
| `vi.unstubAllEnvs()` | очистить env stubs |
| `vi.stubGlobal(name, value)` | замокать global |
| `vi.unstubAllGlobals()` | очистить global stubs |

## Мини-шпаргалка

- `test/it/describe` - структура tests.
- `beforeEach/afterEach` - setup/cleanup.
- `expect` - assertions.
- `vi.fn` - mock function.
- `vi.spyOn` - spy на существующий метод.
- `vi.mock` - module mock.
- `vi.useFakeTimers` - timers/date tests.
- `vi.stubEnv` - env-dependent tests.
