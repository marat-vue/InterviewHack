# Что делает useLayoutEffect() при SSR?

> [!summary]
> `useLayoutEffect` не выполняется на сервере, потому что на сервере нет DOM и layout. Если компонент зависит от DOM-измерений до paint, его SSR-версия может быть некорректной, поэтому такой код нужно выносить в client-only логику или заменять на `useEffect`, когда это возможно.

## Почему возникает проблема?

`useLayoutEffect` нужен для синхронной работы с DOM после commit, но до paint:

```jsx
useLayoutEffect(() => {
  const rect = elementRef.current.getBoundingClientRect()
  setWidth(rect.width)
}, [])
```

На сервере:

- нет DOM;
- нет layout;
- нет `getBoundingClientRect`;
- нет paint.

React не может выполнить такой effect при SSR.

## Что использовать вместо?

Если эффект не должен блокировать paint, используй `useEffect`:

```jsx
useEffect(() => {
  document.title = title
}, [title])
```

Если компонент не может корректно отображаться без layout-измерений, сделай его client-only или покажи fallback до mount.

```jsx
function ClientOnlyChart() {
  const [mounted, setMounted] = useState(false)

  useEffect(() => {
    setMounted(true)
  }, [])

  if (!mounted) {
    return <ChartSkeleton />
  }

  return <Chart />
}
```

## useIsomorphicLayoutEffect

В библиотеках иногда используют:

```jsx
const useIsomorphicLayoutEffect =
  typeof window !== 'undefined' ? useLayoutEffect : useEffect
```

Это убирает warning, но не делает DOM доступным на сервере. Логику все равно нужно проектировать так, чтобы первый HTML был корректным.

## Когда useLayoutEffect оправдан?

- измерение размеров;
- синхронное позиционирование popover/tooltip;
- предотвращение visual flicker;
- интеграции с DOM-библиотеками;
- scroll/focus до paint.

Для обычных запросов, подписок и логирования нужен `useEffect`.

## Мини-шпаргалка

- `useLayoutEffect` не выполняется на сервере.
- На сервере нет DOM и layout.
- По возможности используй `useEffect`.
- Для DOM-only UI можно отложить render до mount.
- `useIsomorphicLayoutEffect` - библиотечный компромисс, не магия.
