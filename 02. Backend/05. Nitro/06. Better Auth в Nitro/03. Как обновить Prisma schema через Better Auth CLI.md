# Как обновить Prisma schema через Better Auth CLI?

> [!NOTE]
> Better Auth CLI умеет сгенерировать database schema для выбранного adapter и plugins. Для Prisma CLI поддерживает schema generation, но миграции нужно применять через Prisma: `prisma migrate dev`, `prisma migrate deploy` или `db push` для прототипа.

## Зачем CLI?

Better Auth использует таблицы для:

- users;
- sessions;
- accounts;
- verification tokens;
- plugin-specific data.

Писать эти модели вручную можно, но CLI снижает риск забыть поля.

## Generate schema

```bash
npx auth@latest generate --config server/utils/auth.ts
```

Если config лежит в стандартном месте, CLI может найти его сам. Но для Nitro лучше явно указать path:

```bash
npx auth@latest generate --config server/utils/auth.ts
```

## Что делает `generate`?

Для Prisma `generate` обновляет Prisma schema моделями, нужными Better Auth и подключенными plugins.

После генерации:

```bash
npx prisma format
npx prisma migrate dev --name add_better_auth
npx prisma generate
```

Для быстрого prototype:

```bash
npx prisma db push
```

## Почему не `auth migrate` для Prisma?

Better Auth `migrate` напрямую применяет schema для built-in Kysely adapter. Для Prisma migration workflow должен идти через Prisma tools.

Правильный production путь:

```txt
npx auth@latest generate --config server/utils/auth.ts
  -> review prisma/schema.prisma
  -> npx prisma migrate dev --name add_auth
  -> commit migration
  -> npx prisma migrate deploy на production
```

## CLI options

| Option | Что делает |
|---|---|
| `--config` | path к auth config |
| `--output` | куда сохранить generated schema |
| `--yes` | пропустить confirmation prompt |

## Что делать после добавления plugin?

Если добавил plugin:

```ts
plugins: [
  twoFactor(),
]
```

нужно снова:

```bash
npx auth@latest generate --config server/utils/auth.ts
npx prisma migrate dev --name add_two_factor
```

Плагины часто добавляют свои таблицы/поля.

## Что проверять в generated schema?

Проверь:

- имена моделей;
- `@map`/`@@map`, если у тебя custom naming;
- типы id;
- date/timestamp types;
- indexes;
- unique constraints;
- compatibility с существующими таблицами;
- provider-specific differences.

## Мини-шпаргалка

- Для Prisma используй `auth generate`, а не `auth migrate`.
- После generate запускай Prisma migration.
- Generated schema нужно review-ить.
- После добавления plugin снова генерируй schema.
- Production применяет migrations через `prisma migrate deploy`.
