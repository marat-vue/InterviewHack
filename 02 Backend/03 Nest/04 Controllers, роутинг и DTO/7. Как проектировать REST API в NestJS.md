# Как проектировать REST API в NestJS?

> [!summary]
> REST API в NestJS проектируют вокруг ресурсов, HTTP-методов, DTO, status codes и понятных ошибок. NestJS дает decorators и validation, но REST-смысл остается таким же, как в обычном HTTP API.

## Пример routes

```ts
@Controller('users')
export class UsersController {
  @Get()
  findAll() {}

  @Get(':id')
  findOne() {}

  @Post()
  create() {}

  @Patch(':id')
  update() {}

  @Delete(':id')
  remove() {}
}
```

## DTO по операциям

```txt
CreateUserDto
UpdateUserDto
UserResponseDto
```

Входной DTO не обязан совпадать с response DTO.

## Ошибки

Для ожидаемых ошибок используй HTTP exceptions.

```ts
throw new NotFoundException('User not found');
```

## Мини-шпаргалка

- Controller route должен отражать ресурс.
- DTO описывает контракт.
- Service содержит use case.
- HTTP status должен соответствовать результату.
- Ошибки лучше делать единообразными.
