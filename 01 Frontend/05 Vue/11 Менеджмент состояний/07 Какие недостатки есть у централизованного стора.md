# Какие недостатки есть у централизованного стора?

> [!NOTE] Коротко
> Централизованный стор может усложнить приложение, если выносить туда все подряд. Он повышает связанность, размывает владение данными и иногда делает простую локальную логику слишком тяжелой.

## Вопрос

Какие недостатки есть у централизованного стора?

## Лишняя глобальность

Если локальный флаг попал в store, его теоретически может менять любой компонент.

```typescript
// Плохой кандидат для глобального store
const isDropdownOpen = ref(false);
```

Такой state чаще должен жить рядом с dropdown.

## Сложнее понять владельца

Когда данные глобальны, труднее быстро понять, какой экран или компонент отвечает за их изменение.

## Больше boilerplate

Для простого состояния store может добавить лишние файлы, imports, actions и соглашения.

## Риск "большого общего объекта"

Если store растет без структуры, он превращается в глобальную переменную с реактивностью. Это усложняет поддержку и тестирование.

## Как избежать проблем

Начинай с локального state. Выноси в store только то, что реально нужно разным независимым частям приложения.

## Мини-шпаргалка

- Store не должен хранить все состояние приложения.
- Локальные UI-флаги лучше держать локально.
- Большой store сложнее тестировать и понимать.
- Хороший store описывает общие бизнес-данные.
- Выносить state стоит по необходимости, а не заранее.
