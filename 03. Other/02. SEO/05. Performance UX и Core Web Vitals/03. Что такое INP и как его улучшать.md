# Что такое INP и как его улучшать?

> [!summary]
> INP, Interaction to Next Paint, оценивает отзывчивость страницы на взаимодействия пользователя. Плохой INP часто связан с тяжелым JavaScript, длинными задачами в main thread и дорогими обработчиками событий.

## Что измеряет INP?

INP смотрит, сколько времени проходит между взаимодействием и следующим визуальным обновлением.

Взаимодействия:

- click;
- tap;
- key press.

Плохой сценарий:

```text
Пользователь нажал кнопку -> main thread занят -> интерфейс реагирует через 800 мс
```

## Почему INP ухудшается?

- Большой bundle.
- Долгие синхронные вычисления.
- Тяжелые обработчики событий.
- Частые перерендеры.
- Большие списки без виртуализации.
- Сторонние скрипты.
- Hydration тяжелого приложения.

## Как улучшать INP?

- Делить код через dynamic imports.
- Уменьшать JavaScript на странице.
- Выносить тяжелые вычисления в Web Worker.
- Использовать debounce/throttle.
- Виртуализировать большие списки.
- Упрощать обработчики событий.
- Избегать лишних reactive dependencies.
- Профилировать компоненты.

Пример:

```ts
const SearchPanel = defineAsyncComponent(() => import('./SearchPanel.vue'))
```

Так тяжелый код поиска можно загрузить позже.

## Как отвечать на собеседовании?

```text
INP показывает отзывчивость интерфейса. Если main thread занят большим JS или тяжелым рендером, пользователь видит задержку после клика или ввода. Улучшение INP обычно связано с уменьшением JS, разбиением задач, оптимизацией обработчиков и профилированием.
```

## Мини-шпаргалка

- INP - метрика отзывчивости.
- Главный враг INP - занятый main thread.
- Большой JS может вредить и UX, и SEO.
- Оптимизируй обработчики, рендеры и сторонние скрипты.
- Профилирование важнее угадывания.
