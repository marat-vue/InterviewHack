# Чем layout отличается от обычного React-компонента?

> [!summary]
> Layout технически является React-компонентом, но в Next.js он имеет специальную роль: определяется файлом `layout.tsx`, автоматически включается в дерево маршрута, сохраняется при навигации и может участвовать в metadata и серверной маршрутизации.

## Обычный компонент подключается вручную

```tsx
import { Header } from '@/components/header'

export default function Page() {
  return (
    <>
      <Header />
      <main>Контент</main>
    </>
  )
}
```

Обычный React-компонент существует там, где ты его импортировал и отрендерил.

## Layout подключается автоматически

```text
app/
  dashboard/
    layout.tsx
    users/
      page.tsx
```

```tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <div>
      <DashboardSidebar />
      {children}
    </div>
  )
}
```

Страница `/dashboard/users` автоматически окажется внутри `DashboardLayout`.

## Главное отличие - роль в маршрутизации

| Критерий | Обычный React-компонент | `layout.tsx` |
| --- | --- | --- |
| Как подключается | Через `import` | По файловой структуре |
| Связан с маршрутом | Нет, если не используется в route-файле | Да |
| Получает `children` | Только если сам так спроектирован | Практически всегда |
| Сохраняется при навигации | Зависит от родителя | Да, внутри своего сегмента |
| Может задавать metadata | Нет | Да |
| Root-версия требует `<html>`/`<body>` | Нет | Да |
| По умолчанию Server Component | Зависит от места использования | Да |

## Отличие в жизненном цикле навигации

Если пользователь переходит:

```text
/dashboard/users -> /dashboard/settings
```

то:

- `app/dashboard/layout.tsx` остается;
- его состояние не сбрасывается;
- меняется только вложенная страница;
- Next.js может загрузить только нужный новый сегмент.

Обычный компонент может вести себя так же только если его родитель остается в дереве. У layout это поведение встроено в маршрутизацию.

## Отличие от template.tsx

`layout.tsx` сохраняется между переходами, а `template.tsx` создает новый экземпляр для каждого перехода внутри сегмента.

```text
layout.tsx   -> сохраняет состояние
template.tsx -> перемонтируется
```

`template.tsx` используют, когда нужно принудительно сбросить состояние, запустить анимацию входа или заново выполнить эффекты клиентского компонента.

## Что отвечать на собеседовании?

Layout - это React-компонент со специальной файловой конвенцией Next.js. Его не импортируют вручную в страницы: Next.js сам вставляет его в дерево маршрута. В отличие от обычного компонента, layout сохраняется при навигации внутри сегмента, может быть вложенным, может задавать metadata и участвует в архитектуре App Router.

## Частые ошибки

- Говорить, что layout - это просто wrapper-компонент.
- Не упоминать автоматическую связь с файловой маршрутизацией.
- Путать `layout.tsx` и `template.tsx`.
- Ожидать, что layout всегда будет перемонтироваться.
- Делать обычный компонент layout-ом только по названию файла вне папки `app`.

## Мини-шпаргалка

- Обычный компонент подключается через `import`.
- `layout.tsx` подключается файловой маршрутизацией.
- Layout сохраняется между переходами.
- Layout может задавать `metadata`.
- Root Layout обязан вернуть `<html>` и `<body>`.
- Для сброса состояния есть `template.tsx`.
