# Как писать interaction tests через play function?

> [!summary]
> Interaction tests в Storybook проверяют поведение компонента прямо на story. `play` function выполняется после render story и может имитировать действия пользователя: ввод, click, submit и проверки результата.

## Зачем нужны interaction tests?

Обычная story показывает состояние. Interaction test проверяет сценарий:

```text
Открыть форму -> ввести email -> нажать submit -> увидеть success/error.
```

Это удобно, потому что тест связан с живым примером компонента.

## Пример `play`

```ts
import { expect, userEvent, within } from 'storybook/test';

export const FilledForm: Story = {
  args: {},
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);

    await userEvent.type(canvas.getByLabelText('Email'), 'ann@example.com');
    await userEvent.click(canvas.getByRole('button', { name: 'Войти' }));

    await expect(canvas.getByText('Проверьте почту')).toBeVisible();
  },
};
```

## Что такое canvas?

`canvasElement` - DOM-область конкретной story. Через `within(canvasElement)` тест ищет элементы внутри story, а не во всем документе.

## Что проверять через play?

- открытие dropdown;
- заполнение формы;
- переключение tabs;
- показ error state;
- modal open/close;
- disabled/loading behavior.

## Чем отличается от component test?

Interaction test живет рядом со story и полезен для UI-документации. Component test в Vitest чаще проще запускать как обычный тестовый набор.

В реальных проектах можно использовать оба подхода:

- Vitest для быстрой логики и component tests;
- Storybook play для документированных UI-сценариев.

## Мини-шпаргалка

- `play` выполняется после render story.
- `within(canvasElement)` ограничивает поиск текущей story.
- `userEvent` имитирует действия пользователя.
- Interaction tests хорошо подходят для форм и интерактивных компонентов.
- Это дополнение к обычным тестам, а не полная замена.
