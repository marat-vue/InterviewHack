# Как типизировать Redis wrappers, repositories и serialization?

> [!NOTE]
> Redis хранит strings/binary values, поэтому в TypeScript важно явно контролировать serialization, parsing и key builders. Иначе cache bugs превращаются в runtime сюрпризы.

## Почему нужен wrapper?

Плохо:

```ts
await redis.set(`u:${id}`, JSON.stringify(user));
```

Разные файлы начнут придумывать разные keys и TTL.

Лучше:

```ts
export function userCacheKey(userId: string) {
  return `cache:user:${userId}`;
}
```

## Typed JSON helpers

```ts
export async function getJson<T>(key: string): Promise<T | null> {
  const value = await redis.get(key);
  return value ? JSON.parse(value) as T : null;
}

export async function setJson(
  key: string,
  value: unknown,
  ttlSeconds: number,
) {
  await redis.set(key, JSON.stringify(value), {
    EX: ttlSeconds,
  });
}
```

## Repository example

```ts
type UserCache = {
  id: string;
  email: string;
  name: string | null;
};

export class UserCacheRepository {
  private key(userId: string) {
    return `cache:user:${userId}`;
  }

  async get(userId: string) {
    return getJson<UserCache>(this.key(userId));
  }

  async set(user: UserCache) {
    await setJson(this.key(user.id), user, 60 * 5);
  }

  async delete(userId: string) {
    await redis.del(this.key(userId));
  }
}
```

## Runtime validation

TypeScript cast не проверяет runtime data. Для важного cache можно валидировать Zod:

```ts
const parsed = UserCacheSchema.safeParse(JSON.parse(value));

if (!parsed.success) {
  await redis.del(key);
  return null;
}
```

## Serialization pitfalls

JSON теряет:

- `Date` как Date object;
- `Map`;
- `Set`;
- `BigInt`;
- class instances;
- `undefined` fields.

Для дат храни ISO strings:

```ts
createdAt: user.createdAt.toISOString()
```

## Мини-шпаргалка

- Не размазывай key strings по проекту.
- Делай key builders.
- Делай `getJson`/`setJson`.
- Валидируй важные cache entries.
- TTL должен быть частью repository contract.
