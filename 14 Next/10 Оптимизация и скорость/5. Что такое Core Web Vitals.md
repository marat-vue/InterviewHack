# Что такое Core Web Vitals?

> [!summary]
> Core Web Vitals - это ключевые пользовательские метрики качества страницы от Google. Сейчас основной набор состоит из LCP, INP и CLS: загрузка главного контента, отзывчивость и визуальная стабильность.

## Почему это именно пользовательские метрики?

Core Web Vitals отвечают не на вопрос "сколько миллисекунд занял код", а на вопрос "как пользователь ощущает страницу".

Пользователю важно:

- быстро увидеть главный контент;
- быстро получить реакцию на действие;
- не страдать от прыгающей верстки.

Именно это измеряют LCP, INP и CLS.

## LCP

LCP, Largest Contentful Paint, измеряет время появления самого крупного видимого контентного элемента.

Обычно это:

- hero image;
- крупный заголовок;
- главный текстовый блок;
- большое изображение товара;
- обложка статьи.

Хороший ориентир:

```text
LCP <= 2.5 s
```

Что улучшает LCP в Next.js:

- server rendering;
- static generation;
- `next/image`;
- `priority` для hero image;
- быстрый backend;
- кэширование;
- меньше блокирующего JS.

## INP

INP, Interaction to Next Paint, измеряет задержку реакции страницы на пользовательские взаимодействия.

Примеры:

- клик по кнопке;
- ввод в поле;
- открытие меню;
- переключение вкладки.

Хороший ориентир:

```text
INP <= 200 ms
```

Что ухудшает INP:

- большой JS-бандл;
- тяжелая гидратация;
- сложные синхронные вычисления;
- слишком много перерендеров;
- тяжелые Client Components;
- выполнение аналитики и сторонних скриптов в main thread.

## CLS

CLS, Cumulative Layout Shift, измеряет неожиданные сдвиги layout.

Хороший ориентир:

```text
CLS <= 0.1
```

Что ухудшает CLS:

- картинки без размеров;
- рекламные блоки без зарезервированного места;
- поздно загружающиеся шрифты;
- динамический контент над уже видимой областью;
- skeleton, который отличается по размеру от итогового блока.

В Next.js помогает `next/image`, потому что он требует размеры или корректное `fill`-поведение и помогает избежать layout shift.

## Что случилось с FID?

Раньше в Core Web Vitals была метрика FID, First Input Delay. Сейчас вместо нее используется INP, потому что INP лучше описывает отзывчивость страницы в течение всего ее жизненного цикла, а не только первую задержку ввода.

На собеседовании лучше говорить про INP, а FID упоминать как устаревшую метрику.

## Как измерять Core Web Vitals?

Инструменты:

- PageSpeed Insights;
- Lighthouse;
- Chrome DevTools;
- Search Console;
- Chrome UX Report;
- RUM-аналитика;
- библиотека `web-vitals`.

Важно различать:

- lab: контролируемая проверка, удобно для разработки;
- field: реальные пользователи, устройства и сети.

## Что отвечать на собеседовании?

Core Web Vitals - это три ключевые метрики качества пользовательского опыта: LCP измеряет скорость появления главного контента, INP - отзывчивость интерфейса, CLS - визуальную стабильность. Они важны для UX и SEO, измеряются по реальным пользователям и помогают понять, где страница медленная именно с точки зрения человека.

## Частые ошибки

- Говорить FID как актуальную основную метрику вместо INP.
- Считать, что Core Web Vitals - это только SEO, а не UX.
- Оптимизировать LCP и забывать про INP.
- Не проверять мобильные устройства.
- Исправлять Lighthouse, но не смотреть реальные данные.
- Убирать CLS только визуально, не резервируя размеры.

## Мини-шпаргалка

- LCP - загрузка главного контента.
- INP - отзывчивость на действия.
- CLS - стабильность layout.
- FID устарел как основная метрика.
- Ориентиры: 2.5s, 200ms, 0.1.
- Field-данные важнее идеального локального прогона.
