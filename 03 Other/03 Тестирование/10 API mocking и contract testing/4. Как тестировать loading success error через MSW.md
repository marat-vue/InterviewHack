# Как тестировать loading, success и error через MSW?

> [!summary]
> MSW удобен для проверки разных API-состояний: успешный ответ, пустой список, ошибка сервера, validation error, задержка ответа. Это помогает тестировать UI как реальный пользовательский сценарий.

## Success

```ts
server.use(
  http.get('/api/profile', () => {
    return HttpResponse.json({ id: 1, name: 'Ann' });
  }),
);

render(ProfilePage);

expect(await screen.findByText('Ann')).toBeInTheDocument();
```

## Empty state

```ts
server.use(
  http.get('/api/products', () => {
    return HttpResponse.json([]);
  }),
);

render(ProductList);

expect(await screen.findByText('Товаров пока нет')).toBeInTheDocument();
```

## Error state

```ts
server.use(
  http.get('/api/profile', () => {
    return HttpResponse.json(
      { message: 'Unauthorized' },
      { status: 401 },
    );
  }),
);

render(ProfilePage);

expect(await screen.findByText('Войдите в аккаунт')).toBeInTheDocument();
```

## Loading state

```ts
server.use(
  http.get('/api/profile', async () => {
    await delay(300);

    return HttpResponse.json({ id: 1, name: 'Ann' });
  }),
);

render(ProfilePage);

expect(screen.getByText('Загрузка...')).toBeInTheDocument();
```

## Что обязательно покрывать?

- success;
- empty;
- validation error;
- auth error;
- server error;
- slow response;
- retry, если он есть.

## Мини-шпаргалка

- MSW помогает честно тестировать async UI.
- `findBy...` удобен для данных, которые появятся позже.
- `server.use` задает сценарий под конкретный тест.
- Empty и error states важны не меньше success.
- Loading лучше тестировать с контролируемой задержкой.
