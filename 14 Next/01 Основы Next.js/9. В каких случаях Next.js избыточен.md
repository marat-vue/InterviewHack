# В каких случаях Next.js избыточен?

> [!summary]
> Next.js избыточен, если проекту не нужны SSR, SSG, SEO, server runtime, файловый роутинг, backend endpoints и production-оптимизации фреймворка. Иногда обычный React SPA на Vite проще, дешевле и понятнее.

## Когда Next.js может быть лишним?

### Внутренняя админка

Если приложение доступно только после логина и не индексируется:

```text
/dashboard
/reports
/settings
```

SEO не важно, а данные все равно грузятся из API на клиенте. В таком случае Vite SPA может быть проще.

### Маленький виджет

Если нужен встраиваемый widget или микрофронтенд без маршрутизации, Next.js может добавить лишний runtime.

### Полностью client-side приложение

Например:

- редактор диаграмм;
- paint-like tool;
- offline-first app;
- сложная интерактивная доска.

Главная ценность здесь в client state и performance в браузере, а не в SSR.

### Когда hosting ограничен

Next.js с SSR требует server runtime. Если доступен только простой static hosting, нужно либо static export, либо SPA.

## Когда Next.js все-таки оправдан?

Next.js полезен, если есть:

- публичные страницы;
- SEO;
- контентные страницы;
- e-commerce;
- SSR/SSG/ISR;
- Server Components;
- backend endpoints;
- auth через cookies;
- сложные metadata.

## Как выбрать между Vite и Next.js?

| Вопрос | Если да | Если нет |
|---|---|---|
| Нужен SEO? | Next.js | Vite возможен |
| Нужен SSR/SSG? | Next.js | Vite проще |
| Есть server runtime? | Next.js подходит | Vite/static лучше |
| Это dashboard после login? | возможно Vite | Next при доп. причинах |
| Нужен fullstack в одном проекте? | Next.js | внешний backend + SPA |

## Что отвечать на собеседовании?

Next.js не всегда нужен. Его выбирают ради production-возможностей: SSR, SSG, ISR, SEO, Server Components, backend layer и оптимизаций. Если приложение закрытое, полностью клиентское и не требует server rendering, Vite SPA может быть более простым решением.

## Частые ошибки

- Выбирать Next.js только из-за популярности.
- Использовать SSR для каждой страницы без необходимости.
- Игнорировать сложность кеширования.
- Делать все Client Components и не получать преимущества Next.js.
- Не учитывать ограничения деплоя.

## Мини-шпаргалка

- Next.js не обязателен для каждой React-задачи.
- Для закрытой SPA часто достаточно Vite.
- Для SEO и SSR Next.js сильнее.
- Server runtime усложняет деплой.
- Static export имеет ограничения.
