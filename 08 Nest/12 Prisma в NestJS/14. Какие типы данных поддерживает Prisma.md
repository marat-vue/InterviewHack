# Какие типы данных поддерживает Prisma?

> [!summary]
> Prisma schema использует собственные типы данных, которые потом мапятся на типы конкретной базы данных. Важно различать scalar types, enum, relation fields, lists, optional fields, default values и native database types через `@db.*`.

## Зачем знать типы Prisma?

На собеседовании часто спрашивают не только "как создать модель", но и почему поле описано именно так:

- `Int` или `BigInt`;
- `Float` или `Decimal`;
- `String` или `String @db.Text`;
- `DateTime` или строка с ISO date;
- nullable поле или optional поле в DTO;
- enum в Prisma или справочная таблица.

Если тип выбран неправильно, приложение может терять точность денег, ломать сортировку дат, хранить невалидный JSON или создавать неудобные миграции.

## Основные scalar types

| Тип Prisma | Что хранит | Пример в TypeScript | Где часто используется |
|---|---|---|---|
| `String` | текст | `string` | email, name, slug, uuid |
| `Boolean` | true/false | `boolean` | flags, status toggles |
| `Int` | целое число | `number` | id, count, position |
| `BigInt` | большое целое число | `bigint` | внешние id, большие счетчики |
| `Float` | число с плавающей точкой | `number` | координаты, приблизительные значения |
| `Decimal` | точное decimal-число | `Prisma.Decimal` | деньги, цены, проценты |
| `DateTime` | дата и время | `Date` | `createdAt`, `updatedAt`, deadlines |
| `Json` | JSON-значение | `Prisma.JsonValue` | metadata, settings, payload |
| `Bytes` | бинарные данные | `Buffer` или `Uint8Array` | hash, binary payload |

## String

```prisma
model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  name  String
}
```

`String` подходит для обычного текста. Если база поддерживает разные текстовые типы, можно уточнить native type:

```prisma
model Article {
  id      Int    @id @default(autoincrement())
  title   String @db.VarChar(200)
  content String @db.Text
}
```

`@db.VarChar(200)` говорит базе ограничить длину на уровне колонки. `@db.Text` обычно используют для длинного текста.

## Int и BigInt

```prisma
model Product {
  id       Int    @id @default(autoincrement())
  viewLong BigInt
}
```

`Int` удобен для обычных id и счетчиков. `BigInt` нужен, когда значение может выйти за безопасные пределы обычного JavaScript number.

В NestJS будь внимателен: `bigint` нельзя напрямую сериализовать в JSON стандартным `JSON.stringify`. Иногда приходится конвертировать его в строку перед ответом клиенту.

## Float и Decimal

```prisma
model Product {
  id       Int     @id @default(autoincrement())
  rating   Float
  price    Decimal @db.Decimal(10, 2)
}
```

`Float` подходит для приблизительных чисел: rating, координаты, коэффициенты. Для денег лучше использовать `Decimal`, потому что `Float` может давать ошибки округления.

```ts
import { Prisma } from '../generated/prisma';

const product = await this.prisma.product.create({
  data: {
    price: new Prisma.Decimal('199.90'),
  },
});
```

## Boolean

```prisma
model Post {
  id        Int     @id @default(autoincrement())
  published Boolean @default(false)
}
```

`Boolean` хорошо работает для простых флагов. Если состояний больше двух, обычно лучше enum:

```prisma
enum PostStatus {
  DRAFT
  PUBLISHED
  ARCHIVED
}
```

## DateTime

```prisma
model User {
  id        Int      @id @default(autoincrement())
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

`DateTime` в Prisma Client обычно приходит как JavaScript `Date`. На API-границе его часто отдают как ISO string.

```ts
const users = await this.prisma.user.findMany({
  where: {
    createdAt: {
      gte: new Date('2026-01-01T00:00:00.000Z'),
    },
  },
});
```

## Json

```prisma
model AuditLog {
  id       Int  @id @default(autoincrement())
  payload  Json
}
```

`Json` удобен для гибкой metadata, но им не стоит заменять нормальную модель данных. Если по полю нужно часто фильтровать, сортировать или строить связи, лучше вынести данные в отдельную таблицу.

```ts
await this.prisma.auditLog.create({
  data: {
    payload: {
      action: 'USER_CREATED',
      actorId: 1,
    },
  },
});
```

## Enum

```prisma
enum UserRole {
  USER
  ADMIN
  MODERATOR
}

model User {
  id   Int      @id @default(autoincrement())
  role UserRole @default(USER)
}
```

Enum хорош, когда набор значений небольшой и меняется редко. Если значения должны редактироваться админкой, локализоваться или иметь дополнительные поля, лучше отдельная таблица.

## Optional и nullable

```prisma
model User {
  id       Int     @id @default(autoincrement())
  email    String  @unique
  nickname String?
}
```

`String?` означает, что в базе поле может быть `NULL`. Это не то же самое, что "поле можно не передавать в DTO".

```ts
await this.prisma.user.update({
  where: { id: 1 },
  data: {
    nickname: null,
  },
});
```

`null` явно записывает пустое значение. Если поле в `data` не передать вообще, Prisma его не изменит.

## Lists

```prisma
model Post {
  id   Int      @id @default(autoincrement())
  tags String[]
}
```

Scalar lists поддерживаются не всеми базами одинаково. Для тегов в серьезном приложении часто лучше сделать отдельную модель `Tag` и связь many-to-many, особенно если нужны поиск, статистика или уникальность тегов.

## Relation fields

```prisma
model Post {
  id       Int  @id @default(autoincrement())
  authorId Int
  author   User @relation(fields: [authorId], references: [id])
}
```

`author` - это relation field. Оно не является обычной колонкой в таблице. Колонка здесь `authorId`, а `author` говорит Prisma, как связаны модели.

## Unsupported

```prisma
model GeoPoint {
  id       Int                         @id @default(autoincrement())
  location Unsupported("geography")
}
```

`Unsupported` используют, когда база умеет тип, которого Prisma не представляет как обычный scalar type. Работать с такими полями часто приходится через raw SQL.

## Как выбирать тип на практике?

```prisma
model Order {
  id          String   @id @default(uuid()) @db.Uuid
  customerId  String   @db.Uuid
  total       Decimal  @db.Decimal(12, 2)
  status      Status   @default(PENDING)
  metadata    Json?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  customer Customer @relation(fields: [customerId], references: [id])

  @@index([customerId, createdAt])
}
```

Здесь:

- `String @db.Uuid` выбран для uuid id;
- `Decimal @db.Decimal(12, 2)` выбран для денег;
- `Status` ограничивает жизненный цикл заказа;
- `Json?` хранит необязательную metadata;
- `DateTime` отвечает за аудит;
- relation field `customer` связывает заказ с клиентом.

## Мини-шпаргалка

- `String`, `Boolean`, `Int`, `BigInt`, `Float`, `Decimal`, `DateTime`, `Json`, `Bytes` - основные scalar types.
- Деньги почти всегда лучше хранить через `Decimal`, а не `Float`.
- `String?` в Prisma означает nullable column.
- `undefined` в `data` обычно значит "не менять поле", `null` значит "записать NULL".
- `@db.*` уточняет native database type.
- Relation field описывает связь, но не всегда является отдельной колонкой.
