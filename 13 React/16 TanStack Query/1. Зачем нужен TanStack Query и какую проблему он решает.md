# Зачем нужен TanStack Query и какую проблему он решает?

> [!summary]
> TanStack Query нужен для данных, которые приходят с сервера. Он решает проблемы загрузки, кеширования, повторных запросов, фонового обновления, ошибок, мутаций и синхронизации UI после изменения данных.

## Проблема обычного fetch в React

```tsx
function UsersPage() {
  const [users, setUsers] = useState<User[]>([])
  const [isLoading, setIsLoading] = useState(false)
  const [error, setError] = useState<Error | null>(null)

  useEffect(() => {
    setIsLoading(true)
    fetchUsers()
      .then(setUsers)
      .catch(setError)
      .finally(() => setIsLoading(false))
  }, [])

  if (isLoading) return <Loader />
  if (error) return <ErrorMessage error={error} />

  return <UserList users={users} />
}
```

Этот код не отвечает на важные вопросы:

- что делать при повторном заходе на страницу?
- когда данные устаревают?
- как обновить список после создания пользователя?
- как не делать два одинаковых запроса одновременно?
- как refetch при фокусе окна?
- как обработать retry?

## Как выглядит с TanStack Query?

```tsx
function UsersPage() {
  const usersQuery = useQuery({
    queryKey: ['users'],
    queryFn: fetchUsers,
  })

  if (usersQuery.isPending) return <Loader />
  if (usersQuery.isError) return <ErrorMessage error={usersQuery.error} />

  return <UserList users={usersQuery.data} />
}
```

Меньше ручного состояния, больше встроенной логики.

## Что TanStack Query делает автоматически?

| Возможность | Что означает |
|---|---|
| cache | хранит результат запроса |
| deduplication | не дублирует одинаковые активные запросы |
| stale state | отличает свежие и устаревшие данные |
| refetch | умеет обновлять данные |
| retry | повторяет упавшие запросы |
| background updates | обновляет без полного сброса UI |
| invalidation | обновляет связанные данные после мутации |
| mutations | управляет POST/PUT/PATCH/DELETE |

## TanStack Query не является HTTP-клиентом

Он не заменяет `fetch` или `axios`.

Ты сам пишешь функцию:

```tsx
async function fetchUsers() {
  const response = await fetch('/api/users')

  if (!response.ok) {
    throw new Error('Failed to fetch users')
  }

  return response.json()
}
```

А TanStack Query управляет жизненным циклом результата.

## Что отвечать на собеседовании?

TanStack Query нужен не для самого запроса, а для управления server state вокруг запроса: кеш, статусы, refetch, retry, invalidation и mutation lifecycle. Он уменьшает ручной `useEffect` boilerplate и делает работу с серверными данными предсказуемее.

## Мини-шпаргалка

- Fetch делает HTTP-запрос.
- TanStack Query управляет результатом запроса.
- Server state нельзя удобно хранить как обычный local state.
- После mutations чаще всего нужна invalidation.
- Query cache живет в `QueryClient`.
