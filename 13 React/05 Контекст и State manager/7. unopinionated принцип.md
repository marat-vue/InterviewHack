# Что означает unopinionated принцип в Zustand?

> [!summary]
> Unopinionated означает, что Zustand не навязывает жесткую архитектуру приложения. Он дает маленький API для store, `set`, `get`, selectors и middleware, а структуру папок, разбиение store и стиль actions команда выбирает сама.

## Простое определение

Opinionated инструмент говорит:

```text
Делай структуру именно так.
```

Unopinionated инструмент говорит:

```text
Вот базовые примитивы. Собери архитектуру под свой проект.
```

Zustand ближе ко второму варианту.

## Что Zustand не навязывает?

- Единую структуру папок.
- Обязательные reducers.
- Обязательный Provider.
- Action types.
- Один глобальный store.
- Нормализацию данных.
- Конкретный подход к async.
- Конкретный подход к middleware.

## Почему это удобно?

Минимализм Zustand полезен, когда нужно быстро создать store:

```jsx
const useUiStore = create((set) => ({
  isSidebarOpen: false,
  toggleSidebar: () =>
    set((state) => ({ isSidebarOpen: !state.isSidebarOpen })),
}))
```

Нет boilerplate, поэтому легко начать.

## В чем риск?

Если инструмент ничего не навязывает, команда должна сама договориться:

- где лежат stores;
- один store или несколько;
- где actions;
- как именовать selectors;
- как разделять client state и server state;
- когда использовать middleware;
- как тестировать store.

Без правил unopinionated подход превращается в хаос.

## Хорошая практика

Для больших проектов лучше иметь соглашения:

```text
features/cart/model/cart.store.ts
features/auth/model/auth.store.ts
shared/model/theme.store.ts
```

И не складывать все в один `useAppStore`.

## Мини-шпаргалка

- Zustand unopinionated: он не навязывает архитектуру.
- Это дает гибкость и низкий boilerplate.
- Команда сама отвечает за структуру store.
- Для больших проектов нужны внутренние соглашения.
- Unopinionated не значит "без архитектуры".
