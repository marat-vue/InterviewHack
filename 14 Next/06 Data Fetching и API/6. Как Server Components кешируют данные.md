# Как Server Components кешируют данные?

> [!summary]
> Server Components сами по себе не являются "кешем", но в Next.js серверная загрузка данных интегрирована с кешированием через `fetch`, `revalidate`, tags и route cache. Главный инструмент управления кешем для HTTP-запросов - расширенный Next.js `fetch`.

## Важное уточнение

Кеширует не "компонент как функция", а результат данных и/или route output в зависимости от стратегии.

```tsx
export default async function Page() {
  const posts = await fetch('https://api.example.com/posts', {
    next: { revalidate: 3600 },
  }).then((res) => res.json())

  return <PostList posts={posts} />
}
```

Здесь кеширование задается для `fetch`.

## Основные режимы fetch

```tsx
await fetch(url, { cache: 'force-cache' })
```

Кешируемый запрос.

```tsx
await fetch(url, { cache: 'no-store' })
```

Всегда свежий запрос, route становится динамичнее.

```tsx
await fetch(url, { next: { revalidate: 60 } })
```

Кеш с обновлением по времени.

```tsx
await fetch(url, { next: { tags: ['posts'] } })
```

Кеш с тегом для on-demand invalidation.

## Что если используется ORM?

`fetch` cache работает для HTTP-запросов. Если ты читаешь БД через ORM:

```tsx
const posts = await db.post.findMany()
```

Нужно отдельно понимать стратегию кеширования: route-level static/dynamic behavior, `revalidate`, cache utilities или собственный слой кеша.

## Что отвечать на собеседовании?

Server Components позволяют получать данные на сервере, а Next.js управляет кешированием через расширенный `fetch` и route caching. Для `fetch` можно задавать `force-cache`, `no-store`, `next.revalidate` и `next.tags`. ORM-запросы не становятся автоматически fetch-cache.

## Частые ошибки

- Говорить, что любой запрос в Server Component автоматически кешируется одинаково.
- Не различать HTTP `fetch` и ORM-запрос.
- Забывать `revalidateTag` для тегированных данных.
- Использовать `no-store` без причины.
- Не учитывать, что cookies/headers могут сделать route dynamic.

## Мини-шпаргалка

- `fetch` в Next.js расширен.
- `force-cache` - кешировать.
- `no-store` - не кешировать.
- `next.revalidate` - обновлять по времени.
- `next.tags` - тегировать данные.
- ORM требует отдельного понимания кеша.
