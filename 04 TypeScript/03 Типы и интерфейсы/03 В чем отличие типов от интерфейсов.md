# В чем отличие типов от интерфейсов?

> [!NOTE] Коротко
> `interface` в основном описывает объекты и может расширяться декларативно, а `type` может описывать почти любой тип.

## Вопрос

Когда использовать `type`, а когда `interface`?

## Главное отличие

`interface` хорошо подходит для описания формы объекта. `type` более универсален: им можно описать union, intersection, литералы, кортежи, функции и сложные типовые выражения.

## Interface

```typescript
interface User {
  id: number;
  name: string;
}
```

## Type

```typescript
type User = {
  id: number;
  name: string;
};

type Status = 'idle' | 'loading' | 'success';
```

## Сравнение

| Возможность | `interface` | `type` |
| --- | --- | --- |
| Описать объект | да | да |
| Описать union | нет напрямую | да |
| Описать tuple | нет напрямую | да |
| `extends` | да | через `&` |
| Declaration merging | да | нет |
| `implements` у класса | да | да, если объектная форма |

## Declaration merging

```typescript
interface User {
  id: number;
}

interface User {
  name: string;
}
```

Итоговый `User` будет иметь оба поля.

## Практическое правило

Для публичных объектных контрактов часто выбирают `interface`. Для union, utility types, mapped types и сложных комбинаций - `type`.

## Мини-шпаргалка

```typescript
interface Props { id: number }
type Status = 'idle' | 'loading';
type WithId = User & { id: number };
```
