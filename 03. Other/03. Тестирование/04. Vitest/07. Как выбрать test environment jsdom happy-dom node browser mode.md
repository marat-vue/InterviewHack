# Как выбрать test environment: jsdom, happy-dom, node или browser mode?

> [!summary]
> Test environment определяет, в каком окружении выполняются тесты. Для backend и чистой логики подходит `node`, для DOM-компонентов - `jsdom` или `happy-dom`, для более реалистичных браузерных проверок - Vitest Browser Mode.

## `node`

`node` подходит для:

- backend services;
- pure functions;
- composables без DOM;
- validators;
- utilities.

```ts
test: {
  environment: 'node',
}
```

В `node` нет настоящего `document`, `window` и браузерного layout.

## `jsdom`

`jsdom` имитирует DOM в Node.js:

```ts
test: {
  environment: 'jsdom',
}
```

Подходит для:

- Vue component tests;
- событий;
- работы с `document`;
- базовой проверки rendered HTML.

Минус: это не настоящий браузерный движок.

## `happy-dom`

`happy-dom` - альтернатива jsdom. Часто быстрее, но совместимость может отличаться.

```ts
test: {
  environment: 'happy-dom',
}
```

Выбор между `jsdom` и `happy-dom` обычно делают по совместимости проекта.

## Browser Mode

Vitest Browser Mode запускает тесты в реальном браузерном окружении.

Он полезен, когда важны:

- настоящие browser APIs;
- rendering behavior;
- component tests ближе к браузеру;
- ситуации, где jsdom недостаточно.

Но он сложнее и тяжелее обычного `jsdom`.

## Мини-шпаргалка

- `node` - backend и чистая логика.
- `jsdom` - частый выбор для Vue component tests.
- `happy-dom` - быстрая DOM-альтернатива.
- Browser Mode - реальный браузер, больше реализма и стоимости.
- Выбирай самое простое окружение, которое честно проверяет сценарий.
