# Изоляция API от UI

> [!summary]
> Изоляция API от UI означает, что React-компоненты не должны знать детали HTTP-запросов, URL, headers, токенов и формата ответа. Компонент вызывает понятную функцию или hook, а слой API отвечает за транспорт и преобразование данных.

## Плохой пример

```jsx
function UsersPage() {
  const [users, setUsers] = useState([])

  useEffect(() => {
    fetch('/api/users', {
      headers: {
        Authorization: `Bearer ${localStorage.getItem('token')}`,
      },
    })
      .then((response) => response.json())
      .then(setUsers)
  }, [])

  return <UsersList users={users} />
}
```

Компонент знает слишком много:

- endpoint;
- способ авторизации;
- формат ответа;
- transport API;
- обработку ошибок.

## API слой

```ts
// shared/api/httpClient.ts
export async function httpClient<T>(url: string, options?: RequestInit): Promise<T> {
  const response = await fetch(url, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      ...options?.headers,
    },
  })

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`)
  }

  return response.json()
}
```

```ts
// entities/user/api/userApi.ts
export function getUsers() {
  return httpClient<User[]>('/api/users')
}

export function getUser(userId: string) {
  return httpClient<User>(`/api/users/${userId}`)
}
```

## UI через query hook

```jsx
function UsersPage() {
  const { data: users = [], isLoading, error } = useQuery({
    queryKey: ['users'],
    queryFn: getUsers,
  })

  if (isLoading) return <UsersSkeleton />
  if (error) return <ErrorMessage error={error} />

  return <UsersList users={users} />
}
```

Теперь UI не зависит от деталей `fetch`.

## Можно вынести и query hook

```ts
export function useUsersQuery() {
  return useQuery({
    queryKey: ['users'],
    queryFn: getUsers,
  })
}
```

Компонент:

```jsx
function UsersPage() {
  const { data: users = [] } = useUsersQuery()

  return <UsersList users={users} />
}
```

## Что хранить в API-слое?

- HTTP client;
- endpoints;
- request/response types;
- mappers;
- auth headers;
- error normalization;
- retry policy;
- base URL;
- abort support.

## Плюсы

- компоненты проще читать;
- легче тестировать;
- меньше дублирования;
- проще поменять `fetch` на Axios или GraphQL client;
- единая обработка ошибок;
- легче мокать API через MSW.

## Мини-шпаргалка

- UI должен знать "получить пользователей", а не "как собрать HTTP-запрос".
- API-функции лучше хранить отдельно.
- Query hooks могут быть отдельным слоем над API.
- Ошибки и headers лучше нормализовать централизованно.
- Изоляция API поддерживает SRP и тестируемость.
