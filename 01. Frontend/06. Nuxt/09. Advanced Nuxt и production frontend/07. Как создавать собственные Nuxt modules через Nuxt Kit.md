# Как создавать собственные Nuxt modules через Nuxt Kit?

> [!NOTE]
> Nuxt module - это способ расширить Nuxt-проект на этапе dev/build: добавить plugins, components, composables, server routes, templates, runtime config, hooks и интеграции. Это нужно, когда повторяющаяся настройка должна стать переиспользуемой.

## Когда нужен свой module?

Свой module полезен, если нужно:

- подключить внутреннюю analytics/instrumentation;
- добавить shared UI components;
- автоматически зарегистрировать server routes;
- настроить integration с CMS;
- добавить runtime config и types;
- повторять один setup в нескольких Nuxt-проектах.

Если задача локальная для одного приложения, начни с обычного plugin/composable.

## Минимальный module

`modules/my-module.ts`:

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule'
  },
  defaults: {
    enabled: true
  },
  setup(options, nuxt) {
    if (!options.enabled) {
      return
    }

    nuxt.hook('ready', () => {
      console.log('my-module ready')
    })
  }
})
```

Подключение:

```ts
export default defineNuxtConfig({
  modules: ['~/modules/my-module'],
  myModule: {
    enabled: true
  }
})
```

## Важные функции Nuxt Kit

| Функция | Зачем |
| --- | --- |
| `defineNuxtModule` | Описывает module, options, defaults, setup. |
| `createResolver` | Помогает резолвить пути относительно module file. |
| `addPlugin` | Добавляет Nuxt plugin из module. |
| `addComponent` | Регистрирует component. |
| `addComponentsDir` | Регистрирует директорию компонентов. |
| `addImports` | Добавляет auto-import composable/function. |
| `addImportsDir` | Добавляет auto-import директорию. |
| `addServerHandler` | Добавляет Nitro server route или middleware. |
| `addTemplate` | Генерирует virtual/generated file. |
| `addTypeTemplate` | Генерирует type declarations. |
| `installModule` | Подключает другой module из своего module. |
| `extendViteConfig` | Меняет Vite config. |

## `createResolver`

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup(_options, nuxt) {
    const resolver = createResolver(import.meta.url)

    console.log(resolver.resolve('./runtime/plugin'))
  }
})
```

Не строй пути через ручную конкатенацию строк.

## Добавить plugin

```ts
import { addPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup() {
    const resolver = createResolver(import.meta.url)

    addPlugin(resolver.resolve('./runtime/plugin'))
  }
})
```

`runtime/plugin.ts`:

```ts
export default defineNuxtPlugin(() => {
  return {
    provide: {
      hello: () => 'hello'
    }
  }
})
```

## Добавить component

```ts
import { addComponent, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup() {
    const resolver = createResolver(import.meta.url)

    addComponent({
      name: 'UiButton',
      filePath: resolver.resolve('./runtime/components/UiButton.vue')
    })
  }
})
```

После этого:

```vue
<template>
  <UiButton>Сохранить</UiButton>
</template>
```

## Добавить composable auto-import

```ts
import { addImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup() {
    const resolver = createResolver(import.meta.url)

    addImports({
      name: 'useFeatureFlags',
      from: resolver.resolve('./runtime/composables/useFeatureFlags')
    })
  }
})
```

## Добавить server route

```ts
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup() {
    const resolver = createResolver(import.meta.url)

    addServerHandler({
      route: '/api/module-health',
      handler: resolver.resolve('./runtime/server/health.get')
    })
  }
})
```

## Hooks

```ts
export default defineNuxtModule({
  setup(_options, nuxt) {
    nuxt.hook('pages:extend', (pages) => {
      pages.push({
        name: 'module-page',
        path: '/module-page',
        file: '/absolute/path/to/page.vue'
      })
    })
  }
})
```

Hooks позволяют изменить Nuxt build/runtime behavior без patching core.

## Что отвечать на собеседовании?

Nuxt module расширяет Nuxt на этапе dev/build. Через Nuxt Kit можно добавить plugins, components, composables, server handlers, generated templates и изменить config через hooks. Свой module нужен, когда настройку надо переиспользовать между проектами или скрыть интеграционную сложность за понятным API.

## Частые ошибки

- Делать module для одной мелкой настройки одного проекта.
- Использовать абсолютные пути вместо `createResolver`.
- Не объявлять `meta.configKey`.
- Не типизировать options.
- Генерировать файлы нестабильно и ломать cache.
- Подключать runtime dependency как devDependency.

## Мини-шпаргалка

- `defineNuxtModule` - entrypoint.
- `setup(options, nuxt)` - логика.
- `addPlugin` - runtime plugin.
- `addComponent` - component.
- `addImports` - composables.
- `addServerHandler` - Nitro route.
- `nuxt.hook` - расширение lifecycle.
