# Как писать tests, expect и matchers в Jest?

> [!summary]
> В Jest тесты пишут через `test` или `it`, группируют через `describe`, а проверки делают через `expect`. Matchers позволяют проверять равенство, структуру объектов, строки, массивы, ошибки и вызовы mock-функций.

## Базовый пример

```ts
describe('sum', () => {
  test('adds two numbers', () => {
    expect(sum(2, 3)).toBe(5);
  });
});
```

## `toBe` и `toEqual`

`toBe` используй для primitive values и ссылочного равенства:

```ts
expect(status).toBe('success');
```

`toEqual` используй для объектов и массивов:

```ts
expect(user).toEqual({
  id: 1,
  email: 'ann@example.com',
});
```

## Частые matchers

```ts
expect(value).toBeNull();
expect(value).toBeDefined();
expect(value).toBeTruthy();
expect(items).toHaveLength(2);
expect(text).toMatch(/hello/i);
expect(array).toContain('admin');
expect(user).toHaveProperty('email');
```

## Partial matching

Когда весь объект проверять не нужно:

```ts
expect(user).toEqual(expect.objectContaining({
  email: 'ann@example.com',
}));
```

Для массивов:

```ts
expect(users).toEqual(expect.arrayContaining([
  expect.objectContaining({ role: 'admin' }),
]));
```

## Ошибки

```ts
expect(() => parseJson('{')).toThrow();
expect(() => parseJson('{')).toThrow('Invalid JSON');
```

## Мини-шпаргалка

- `test` и `it` объявляют тест.
- `describe` группирует тесты.
- `expect` начинает assertion.
- `toBe` - strict equality.
- `toEqual` - deep equality.
- `objectContaining` удобен для частичных проверок.
