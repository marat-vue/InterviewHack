# Какие вопросы по тестированию задают на собеседовании?

> [!summary]
> На собеседовании по тестированию frontend/backend чаще проверяют не знание команд, а понимание стратегии: что тестировать, какой уровень выбрать, как мокать зависимости, почему тесты бывают flaky и как сделать код тестируемым.

## Базовые вопросы

**Что такое unit test?**  
Unit test проверяет маленькую часть кода в изоляции: функцию, service, composable, validator.

**Что такое integration test?**  
Integration test проверяет совместную работу нескольких частей: component + store, service + repository, endpoint + validation.

**Что такое e2e test?**  
E2E test проверяет полный пользовательский путь через приложение.

**Что такое testing pyramid?**  
Это идея баланса: много быстрых unit tests, меньше integration/component tests и немного дорогих e2e tests.

## Frontend-вопросы

**Что тестировать в компоненте?**  
Props rendering, events, forms, conditional states, loading/error, slots, router/store interactions.

**Почему не стоит тестировать implementation details?**  
Потому что тесты ломаются при безопасном рефакторинге. Лучше проверять видимое поведение и публичный контракт.

**Как тестировать `v-model` во Vue?**  
Через `setValue` и проверку emitted event `update:modelValue`.

**Зачем нужен Storybook?**  
Для разработки компонентов в изоляции, документации состояний, interaction/accessibility/visual testing.

## Backend-вопросы

**Что тестировать в backend service?**  
Бизнес-правила, ошибки, permissions, вызовы зависимостей, итоговое состояние.

**Как тестировать endpoint?**  
Отправить HTTP request в тестовое приложение и проверить status, body, headers, side effects.

**Надо ли мокать базу?**  
Для unit tests можно. Но repositories, transactions и constraints лучше проверять на тестовой БД.

## Инструменты

**Vitest или Jest?**  
Vitest удобнее для Vite/Vue. Jest часто встречается в legacy, Node.js и NestJS.

**Что такое mock, stub, spy, fake?**  
Stub возвращает данные, spy следит за вызовами, mock имитирует зависимость и проверяет взаимодействия, fake является упрощенной рабочей реализацией.

## Мини-шпаргалка

- Интервьюеру важна стратегия, а не только синтаксис.
- Говори про риски, уровни тестов и стоимость поддержки.
- Умей объяснить mocks, coverage и flaky tests.
- Для frontend делай акцент на поведении пользователя.
- Для backend - на данных, auth, transactions и errors.
