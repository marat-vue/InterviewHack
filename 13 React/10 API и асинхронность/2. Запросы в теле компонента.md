# Запросы в теле компонента

> [!summary]
> Запросы нельзя выполнять прямо в теле клиентского React-компонента, потому что render должен быть чистым и синхронным. Иначе запрос будет запускаться при каждом render, может создать бесконечный цикл и сломать concurrent-поведение.

## Плохой пример

```jsx
function UserPage() {
  const [user, setUser] = useState(null)

  fetch('/api/user')
    .then((response) => response.json())
    .then(setUser)

  return <div>{user?.name}</div>
}
```

Что произойдет:

```text
render -> fetch -> setUser -> render -> fetch -> setUser -> ...
```

Получается цикл запросов.

## Почему render должен быть чистым?

React ожидает, что компонент:

- получает props/state;
- возвращает JSX;
- не меняет внешний мир во время render.

Запрос к серверу - side effect. Его нельзя делать во время вычисления UI.

## Почему async component не подходит в клиентском React?

```jsx
async function UserPage() {
  const user = await fetchUser()

  return <h1>{user.name}</h1>
}
```

Обычный Client Component должен синхронно вернуть JSX. `async` компонент возвращает Promise, а не React node.

Исключение: Server Components и фреймворковые механизмы, где async render поддержан на сервере.

## Правильный вариант через useEffect

```jsx
function UserPage() {
  const [user, setUser] = useState(null)

  useEffect(() => {
    let ignore = false

    async function loadUser() {
      const data = await fetch('/api/user').then((response) => response.json())

      if (!ignore) {
        setUser(data)
      }
    }

    loadUser()

    return () => {
      ignore = true
    }
  }, [])

  if (!user) return <p>Loading...</p>

  return <h1>{user.name}</h1>
}
```

## Еще лучше для server state

```jsx
function UserPage() {
  const { data, isLoading } = useQuery({
    queryKey: ['user'],
    queryFn: fetchUser,
  })

  if (isLoading) return <p>Loading...</p>

  return <h1>{data.name}</h1>
}
```

Query-библиотека берет на себя cache, refetch, retries, deduplication и stale state.

## Мини-шпаргалка

- Не вызывай `fetch` в теле client component.
- Render может выполняться много раз.
- Side effects выносят в `useEffect`, event handlers или framework loaders.
- Async Client Component - ошибка концепции.
- Server Components являются отдельным исключением.
