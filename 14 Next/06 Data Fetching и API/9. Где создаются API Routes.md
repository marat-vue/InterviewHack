# Где создаются API Routes?

> [!summary]
> В App Router API endpoints создаются в файлах `route.ts` внутри `app`, чаще всего по пути `app/api/.../route.ts`. В Pages Router legacy API Routes создаются в `pages/api`.

## App Router

```text
app/
  api/
    products/
      route.ts
```

Endpoint:

```text
/api/products
```

```ts
export async function GET() {
  return Response.json(await getProducts())
}
```

## Dynamic API route

```text
app/
  api/
    products/
      [id]/
        route.ts
```

Endpoint:

```text
/api/products/42
```

```ts
export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> },
) {
  const { id } = await params
  const product = await getProduct(id)

  return Response.json(product)
}
```

## Pages Router

```text
pages/
  api/
    products.ts
```

Endpoint:

```text
/api/products
```

## route.ts рядом с page.tsx?

Для одного и того же route segment нельзя одновременно использовать `route.ts` и `page.tsx` как один и тот же HTTP endpoint/UI route. Обычно UI страницы живут в обычных segments, а API - в `app/api`.

## Что отвечать на собеседовании?

В современном Next.js API создаются через Route Handlers в `app/api/.../route.ts`. Имя файла всегда `route.ts`, а HTTP-методы задаются named exports. В старом Pages Router API лежали в `pages/api`.

## Частые ошибки

- Называть файл `users.ts` внутри `app/api`.
- Экспортировать default handler в App Router.
- Путать `params` в route handler с query string.
- Забывать, что Route Handler доступен по URL.
- Использовать Route Handler вместо Server Action для внутренней формы.

## Мини-шпаргалка

- App Router: `route.ts`.
- Обычно путь: `app/api/.../route.ts`.
- Method exports: `GET`, `POST`.
- Dynamic params через `[id]`.
- Pages Router: `pages/api`.
