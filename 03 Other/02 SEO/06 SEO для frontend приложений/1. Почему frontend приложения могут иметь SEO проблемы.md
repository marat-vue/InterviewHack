# Почему frontend-приложения могут иметь SEO-проблемы?

> [!summary]
> Frontend-приложения часто зависят от JavaScript, клиентской маршрутизации и асинхронной загрузки данных. Если важный контент, meta tags или status codes появляются слишком поздно или неверно, SEO страдает.

## Где обычно ломается SEO?

- Пустой HTML до выполнения JS.
- Один title на все маршруты.
- Нет meta description для страниц.
- Клиентский роутер не отдает корректный `404`.
- Контент загружается только после действия пользователя.
- Ссылки сделаны через `button` или `div`, а не через `<a>`.
- Structured data не обновляются при навигации.
- Canonical одинаковый на всех страницах.
- Фильтры создают много дублей.

## Пример пустого HTML

```html
<div id="app"></div>
<script src="/assets/app.js"></script>
```

Если основной контент появляется только после выполнения JS, поисковику нужно рендерить страницу. Это не всегда мгновенно и может быть проблемой для больших сайтов.

## Почему пользователю тоже плохо?

SEO-проблемы часто совпадают с UX-проблемами:

- медленный первый экран;
- прыгающий layout;
- долго неработающие кнопки;
- плохой preview в соцсетях;
- неправильные страницы ошибок.

## Что помогает?

- SSR;
- SSG;
- prerender;
- корректные meta tags;
- нормальные status codes;
- настоящие ссылки;
- sitemap;
- canonical;
- оптимизация JS;
- проверка rendered HTML.

## Мини-шпаргалка

- SPA может индексироваться, но требует аккуратности.
- Для SEO важен итоговый HTML и доступность контента.
- Маршруты должны иметь свои meta tags.
- Status codes должны соответствовать реальности.
- SSR/SSG часто проще и надежнее для SEO-страниц.
