# Что такое Docker?

> [!summary]
> Docker - это платформа для упаковки, доставки и запуска приложений в контейнерах. Он помогает запускать приложение с нужными версиями Node.js, PostgreSQL, Redis, системных библиотек и настроек независимо от конкретной машины разработчика или сервера.

## Какую проблему решает Docker?

Классическая боль разработки:

```text
У меня работает, у тебя не работает, на сервере тоже не работает.
```

Причины:

- разные версии Node.js;
- разные версии npm/pnpm;
- локально установлен PostgreSQL одной версии, на сервере другой;
- отсутствуют системные библиотеки;
- разные переменные окружения;
- разработчик забыл шаг установки;
- CI/CD собирает проект в другом окружении.

Docker позволяет описать окружение как код.

## Основная идея

Ты создаешь image:

```text
Node.js runtime + зависимости + код приложения + команда запуска
```

А потом запускаешь из него container:

```bash
docker run my-api
```

Контейнер получает изолированную файловую систему, сеть и процесс, но использует ядро host OS.

## Docker не равен виртуальной машине

Docker-контейнер - это не полноценная ОС внутри ОС. Это изолированный процесс с собственным окружением.

Поэтому контейнеры обычно:

- легче VM;
- быстрее стартуют;
- проще масштабируются;
- удобны для CI/CD;
- хорошо подходят для микросервисов и локальной разработки.

## Из чего состоит Docker-экосистема?

- Docker Engine - запускает контейнеры.
- Docker CLI - команды `docker run`, `docker build`, `docker ps`.
- Dockerfile - рецепт сборки image.
- Image - неизменяемый шаблон приложения.
- Container - запущенный экземпляр image.
- Registry - место хранения images, например Docker Hub.
- Docker Compose - запуск нескольких контейнеров через `compose.yaml`.

## Пример

```bash
docker run -d -p 8080:80 nginx:alpine
```

Что происходит:

1. Docker ищет image `nginx:alpine` локально.
2. Если image нет, скачивает его из registry.
3. Создает container.
4. Запускает Nginx внутри container.
5. Пробрасывает порт `8080` хоста на порт `80` container.

## Что отвечать на собеседовании?

Docker - это инструмент контейнеризации, который позволяет упаковать приложение вместе с зависимостями в image и запускать его одинаково в разных окружениях. Контейнеры изолируют процесс, файловую систему и сеть, но используют ядро host OS, поэтому они легче виртуальных машин.

## Частые ошибки

- Думать, что Docker - это виртуальная машина.
- Считать container постоянным хранилищем данных.
- Путать image и container.
- Устанавливать зависимости вручную внутри running container и думать, что они сохранятся в image.
- Класть secrets прямо в Dockerfile.
- Использовать Docker без понимания volumes и networks.

## Мини-шпаргалка

- Docker нужен для одинакового окружения.
- Image - шаблон.
- Container - запущенный image.
- Dockerfile - рецепт image.
- Registry - хранилище images.
- Compose - несколько сервисов одной командой.
