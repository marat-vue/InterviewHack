# Что такое getStaticProps?

> [!summary]
> `getStaticProps` - legacy API Pages Router для загрузки данных во время build и генерации статической страницы. В App Router он не используется; его роль обычно выполняют async Server Components, `generateStaticParams`, `fetch` cache и `revalidate`.

## Где используется?

Только в Pages Router:

```text
pages/
  blog.tsx
```

```tsx
export async function getStaticProps() {
  const posts = await getPosts()

  return {
    props: { posts },
  }
}

export default function BlogPage({ posts }) {
  return <PostList posts={posts} />
}
```

## Что делает?

`getStaticProps`:

- выполняется на сервере;
- выполняется во время build;
- передает props странице;
- помогает создать статический HTML;
- может использовать `revalidate` для ISR в Pages Router.

## ISR в Pages Router

```tsx
export async function getStaticProps() {
  const posts = await getPosts()

  return {
    props: { posts },
    revalidate: 60,
  }
}
```

## App Router аналог

```tsx
export const revalidate = 60

export default async function BlogPage() {
  const posts = await getPosts()

  return <PostList posts={posts} />
}
```

В `app` не пишут `getStaticProps`.

## Что отвечать на собеседовании?

`getStaticProps` - это Pages Router функция для SSG. Она важна для legacy-проектов, но в App Router ее нет. В современных Next.js проектах данные обычно получают прямо в async Server Components и управляют статикой/ISR через cache и revalidate.

## Частые ошибки

- Пытаться использовать `getStaticProps` в папке `app`.
- Считать, что это клиентская функция.
- Не понимать связь с `getStaticPaths`.
- Переносить Pages Router код в App Router без адаптации.
- Забывать, что build-time данные могут устареть.

## Мини-шпаргалка

- Только Pages Router.
- Выполняется на сервере.
- Обычно build time.
- Возвращает `{ props }`.
- Для ISR возвращает `revalidate`.
- В App Router не используется.
