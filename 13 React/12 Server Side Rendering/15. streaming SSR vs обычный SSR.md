# streaming SSR vs обычный SSR

> [!summary]
> Обычный SSR ждет, пока вся страница будет готова, и только потом отправляет HTML. Streaming SSR отправляет HTML частями: shell и fallback могут прийти сразу, а медленные Suspense-области досылаются позже.

## Обычный SSR

```text
request
-> fetch all data
-> render full HTML
-> send response
-> browser paints page
```

Проблема: один медленный блок может задержать всю страницу.

```jsx
const html = renderToString(<App />)
response.send(html)
```

`renderToString` прост, но не умеет ждать delayed content по частям так, как современные streaming API.

## Streaming SSR

```text
request
-> render shell
-> start streaming HTML
-> send fallbacks for slow parts
-> stream completed parts later
```

```jsx
import { renderToPipeableStream } from 'react-dom/server'

const { pipe } = renderToPipeableStream(<App />, {
  bootstrapScripts: ['/client.js'],
  onShellReady() {
    response.setHeader('content-type', 'text/html')
    pipe(response)
  },
})
```

Браузер начинает получать HTML раньше и может парсить документ параллельно с серверным render.

## Suspense как граница потока

```jsx
function ProductPage() {
  return (
    <Layout>
      <ProductInfo />

      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />
      </Suspense>
    </Layout>
  )
}
```

`Layout` и `ProductInfo` можно показать сразу. `Reviews` могут быть досланы позже.

## Сравнение

| Критерий | Обычный SSR | Streaming SSR |
|---|---|---|
| Ответ сервера | Одним HTML | HTML chunks |
| Медленный блок | Блокирует всю страницу | Может быть за Suspense fallback |
| Первый показ shell | Позже | Раньше |
| Работа с Suspense | Ограниченно | Нативно |
| Сложность | Ниже | Выше |
| Ошибки после начала ответа | Проще | Сложнее |

## Когда streaming полезен?

- страница состоит из независимых блоков;
- часть данных грузится медленно;
- важен быстрый shell;
- используется Suspense;
- есть крупные страницы с комментариями, рекомендациями, графиками;
- фреймворк умеет streaming из коробки.

## Когда обычного SSR достаточно?

- страница маленькая;
- все данные быстрые;
- нет Suspense-enabled data loading;
- важна простота;
- HTML должен быть полностью готов до отправки, например для некоторых crawlers.

## Мини-шпаргалка

- Обычный SSR отдает HTML после полного render.
- Streaming SSR начинает отдавать HTML раньше.
- Suspense boundary управляет медленными зонами.
- `onShellReady` подходит для пользователей.
- `onAllReady` полезен, если нужно дождаться всего HTML.
