# Как тестировать async code, timers и dates в Vitest?

> [!summary]
> Асинхронный код тестируют через `async/await`, `resolves`, `rejects` и ожидание promises. Таймеры и даты лучше контролировать через fake timers и `vi.setSystemTime`, чтобы тесты не зависели от реального времени.

## Async success

```ts
test('loads user', async () => {
  await expect(loadUser(1)).resolves.toEqual({
    id: 1,
    name: 'Ann',
  });
});
```

Или:

```ts
const user = await loadUser(1);

expect(user.name).toBe('Ann');
```

## Async error

```ts
test('throws if user not found', async () => {
  await expect(loadUser(999)).rejects.toThrow('User not found');
});
```

Важно вернуть или await-нуть promise. Иначе тест может завершиться раньше проверки.

## Fake timers

```ts
beforeEach(() => {
  vi.useFakeTimers();
});

afterEach(() => {
  vi.useRealTimers();
});

test('calls callback after delay', () => {
  const callback = vi.fn();

  debounce(callback, 300)();
  vi.advanceTimersByTime(300);

  expect(callback).toHaveBeenCalledTimes(1);
});
```

## Mock current date

```ts
vi.useFakeTimers();
vi.setSystemTime(new Date('2026-01-01T00:00:00Z'));

expect(getCurrentYear()).toBe(2026);

vi.useRealTimers();
```

Так тест не сломается завтра, через месяц или на другой машине.

## Мини-шпаргалка

- Async tests должны использовать `await` или return promise.
- `resolves` проверяет успешный promise.
- `rejects` проверяет rejected promise.
- Fake timers делают debounce/throttle/delay тестируемыми.
- `vi.setSystemTime` стабилизирует дату.
