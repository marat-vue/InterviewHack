# Какие ошибки чаще всего делают в тестах?

> [!summary]
> Частые ошибки в тестах: проверка реализации вместо поведения, слишком большие snapshots, отсутствие cleanup, зависимость от порядка тестов, реальные внешние запросы, слабые assertions и игнорирование ошибок/edge cases.

## Слабые assertions

Плохо:

```ts
expect(response).toBeTruthy();
```

Лучше:

```ts
expect(response.status).toBe(201);
expect(response.body.email).toBe('ann@example.com');
```

## Проверка реализации

Плохо:

```ts
expect(wrapper.vm.isLoading).toBe(false);
```

Лучше:

```ts
expect(wrapper.get('button').attributes('disabled')).toBeUndefined();
expect(wrapper.text()).toContain('Сохранить');
```

## Большие snapshots

Плохо:

```ts
expect(wrapper.html()).toMatchSnapshot();
```

Если snapshot огромный, разработчики начнут обновлять его не глядя.

Лучше точечные проверки:

```ts
expect(wrapper.text()).toContain('Заказ оформлен');
expect(wrapper.find('[data-testid="success-icon"]').exists()).toBe(true);
```

## Flaky tests

Flaky test иногда проходит, иногда падает.

Причины:

- реальные таймеры;
- случайные данные;
- зависимость от timezone;
- реальный network;
- общая база без очистки;
- тесты зависят от порядка запуска.

## Слишком много моков

Если тест мокает почти все, он может проверять только собственные mocks.

Сигнал проблемы:

```text
20 строк setup mocks
1 строка действия
1 слабый assertion
```

В таком случае иногда лучше integration test или fake implementation.

## Мини-шпаргалка

- Проверяй конкретный результат.
- Не тестируй внутренности без необходимости.
- Большие snapshots быстро теряют смысл.
- Изолируй тесты и очищай состояние.
- Не ходи во внешний интернет из unit/component tests.
- Тест должен падать по понятной причине.
