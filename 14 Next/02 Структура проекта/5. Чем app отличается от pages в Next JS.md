# Чем app отличается от pages в Next JS?

> [!summary]
> `app` - современный App Router, построенный вокруг React Server Components, layouts, nested routing и новых data fetching API. `pages` - старый Pages Router с файлами страниц, `getServerSideProps`, `getStaticProps` и API Routes.

## Короткое сравнение

| Возможность | App Router `app` | Pages Router `pages` |
|---|---|---|
| Страница | `app/blog/page.tsx` | `pages/blog.tsx` |
| Dynamic route | `app/blog/[slug]/page.tsx` | `pages/blog/[slug].tsx` |
| Layouts | встроены через `layout.tsx` | обычно через `_app.tsx` |
| Server Components | да, по умолчанию | нет как основная модель |
| Data fetching | async Server Components, fetch cache | `getStaticProps`, `getServerSideProps` |
| API | `app/api/*/route.ts` | `pages/api/*.ts` |
| Metadata | Metadata API | `next/head` |

## App Router

```text
app/
  layout.tsx
  page.tsx
  blog/
    [slug]/
      page.tsx
```

Server Component:

```tsx
export default async function BlogPostPage({ params }: Props) {
  const { slug } = await params
  const post = await getPost(slug)

  return <Article post={post} />
}
```

## Pages Router

```text
pages/
  index.tsx
  blog/
    [slug].tsx
```

Data fetching:

```tsx
export async function getServerSideProps() {
  const post = await getPost()

  return { props: { post } }
}
```

## Можно ли использовать оба?

В проекте может быть и `app`, и `pages`, но лучше не смешивать без причины. Это усложняет обучение, архитектуру и миграцию.

Смешивание иногда встречается:

- при постепенной миграции;
- если часть legacy routes еще в Pages Router;
- если команда переносит проект поэтапно.

## Что отвечать на собеседовании?

`app` - новый App Router, где компоненты серверные по умолчанию, есть layouts, nested routing, streaming, Metadata API и новая модель data fetching. `pages` - старый Pages Router с `getStaticProps`, `getServerSideProps`, `_app`, `_document` и `pages/api`.

## Частые ошибки

- Использовать `getServerSideProps` в `app`.
- Использовать `next/head` вместо Metadata API в App Router.
- Думать, что `pages` уже нельзя использовать.
- Смешивать импорты `next/router` и `next/navigation`.
- Переносить Pages Router паттерны без адаптации.

## Мини-шпаргалка

- `app` - App Router.
- `pages` - Pages Router.
- В `app` нет `getServerSideProps`.
- В `app` metadata через `metadata`/`generateMetadata`.
- В App Router навигация из `next/navigation`.
- В Pages Router навигация из `next/router`.
