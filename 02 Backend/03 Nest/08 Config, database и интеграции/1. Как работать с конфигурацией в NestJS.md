# Как работать с конфигурацией в NestJS?

> [!summary]
> Для конфигурации NestJS обычно используют `@nestjs/config`: он загружает env-переменные, предоставляет `ConfigModule` и `ConfigService`, а также поддерживает validation и typed config.

## Подключение

```ts
@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
    }),
  ],
})
export class AppModule {}
```

## Использование

```ts
@Injectable()
export class AppService {
  constructor(private readonly config: ConfigService) {}

  getPort() {
    return this.config.get<number>('PORT', 3000);
  }
}
```

## Почему не читать process.env везде?

Если читать `process.env` по всему проекту, сложно валидировать конфиг и искать зависимости. `ConfigService` делает доступ централизованным.

## Мини-шпаргалка

- `@nestjs/config` - стандартный config package.
- `ConfigModule.forRoot` подключает конфиг.
- `isGlobal: true` делает ConfigService доступным глобально.
- Env нужно валидировать при старте.
- Секреты нельзя коммитить в `.env`.
