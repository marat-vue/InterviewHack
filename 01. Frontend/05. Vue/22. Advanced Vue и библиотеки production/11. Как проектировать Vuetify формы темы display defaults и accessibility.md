# Как проектировать Vuetify формы, темы, display, defaults и accessibility?

> [!NOTE]
> Vuetify ускоряет разработку Material Design UI, но production-качество зависит от темы, defaults, формы, responsive-подхода, accessibility и понимания того, где использовать props/slots вместо CSS-переопределений.

## Вопрос

Как проектировать Vuetify-приложение: подключение, темы, forms, validation, display helpers, defaults и accessibility?

## Когда использовать Vuetify

Vuetify подходит, если:

- нужен готовый UI-kit;
- команда принимает Material Design-подход;
- важны готовые компоненты: tables, dialogs, forms, navigation, date pickers;
- нужно быстро собрать admin panel, CRM, dashboard, internal tool;
- нужна единая тема и predictable API.

Vuetify может быть лишним, если:

- нужен уникальный маркетинговый дизайн;
- проект очень маленький;
- команда уже строит headless components + Tailwind;
- критичен минимальный bundle и нужны только 3-4 компонента.

## Подключение

```bash
npm i vuetify
npm i -D vite-plugin-vuetify
```

`vite.config.ts`:

```typescript
import vue from "@vitejs/plugin-vue";
import vuetify from "vite-plugin-vuetify";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [
    vue(),
    vuetify({
      autoImport: true,
    }),
  ],
});
```

`src/plugins/vuetify.ts`:

```typescript
import "vuetify/styles";
import { createVuetify } from "vuetify";
import { aliases, mdi } from "vuetify/iconsets/mdi";

export const vuetify = createVuetify({
  icons: {
    defaultSet: "mdi",
    aliases,
    sets: {
      mdi,
    },
  },
});
```

`main.ts`:

```typescript
import { createApp } from "vue";
import App from "./App.vue";
import { vuetify } from "./plugins/vuetify";

createApp(App).use(vuetify).mount("#app");
```

## Theme

```typescript
export const vuetify = createVuetify({
  theme: {
    defaultTheme: "light",
    themes: {
      light: {
        dark: false,
        colors: {
          primary: "#2563eb",
          secondary: "#64748b",
          surface: "#ffffff",
          error: "#dc2626",
          warning: "#d97706",
          success: "#16a34a",
        },
      },
      dark: {
        dark: true,
        colors: {
          primary: "#60a5fa",
          surface: "#111827",
        },
      },
    },
  },
});
```

Использование:

```vue
<v-btn color="primary">Сохранить</v-btn>
<v-alert type="error">Ошибка</v-alert>
<v-card color="surface">...</v-card>
```

Переключение:

```vue
<script setup lang="ts">
import { useTheme } from "vuetify";

const theme = useTheme();

function toggleTheme() {
  theme.global.name.value =
    theme.global.current.value.dark ? "light" : "dark";
}
</script>
```

## Defaults

Defaults задают стандартные props компонентов.

```typescript
export const vuetify = createVuetify({
  defaults: {
    VBtn: {
      variant: "flat",
      rounded: "lg",
    },
    VTextField: {
      variant: "outlined",
      density: "comfortable",
      hideDetails: "auto",
    },
    VCard: {
      rounded: "lg",
      elevation: 0,
    },
  },
});
```

Зачем нужно:

- меньше повторяющихся props;
- единый visual language;
- проще менять дизайн системно;
- меньше CSS overrides.

## Display и responsive logic

Vuetify дает `useDisplay()`:

```vue
<script setup lang="ts">
import { computed } from "vue";
import { useDisplay } from "vuetify";

const { mobile, mdAndUp, width } = useDisplay();

const drawerMode = computed(() =>
  mobile.value ? "temporary" : "permanent",
);
</script>

<template>
  <v-navigation-drawer :temporary="mobile" :permanent="mdAndUp">
    ...
  </v-navigation-drawer>

  <span>{{ width }}</span>
</template>
```

Полезные значения:

- `xs`, `sm`, `md`, `lg`, `xl`, `xxl`;
- `smAndUp`, `mdAndUp`, `lgAndUp`;
- `smAndDown`, `mdAndDown`, `lgAndDown`;
- `mobile`;
- `width`, `height`;
- `platform`.

Не стоит строить весь responsive UI только в JS. Layout лучше держать в CSS/grid/flex, а `useDisplay` применять для behavioral differences: drawer mode, dialog fullscreen, количество колонок в data fetch.

## Forms

Базовая форма:

```vue
<script setup lang="ts">
import { useTemplateRef, ref } from "vue";
import type { VForm } from "vuetify/components";

const form = useTemplateRef<VForm>("form");
const isValid = ref(false);

const email = ref("");
const password = ref("");

const rules = {
  required: (value: string) => Boolean(value) || "Обязательное поле",
  email: (value: string) =>
    /.+@.+\..+/.test(value) || "Введите корректный email",
  minPassword: (value: string) =>
    value.length >= 8 || "Минимум 8 символов",
};

async function submit() {
  const result = await form.value?.validate();

  if (!result?.valid) {
    return;
  }

  await login({
    email: email.value,
    password: password.value,
  });
}
</script>

<template>
  <v-form ref="form" v-model="isValid" @submit.prevent="submit">
    <v-text-field
      v-model="email"
      label="Email"
      type="email"
      autocomplete="email"
      :rules="[rules.required, rules.email]"
    />

    <v-text-field
      v-model="password"
      label="Пароль"
      type="password"
      autocomplete="current-password"
      :rules="[rules.required, rules.minPassword]"
    />

    <v-btn type="submit" color="primary">
      Войти
    </v-btn>
  </v-form>
</template>
```

Методы `v-form`:

- `validate()` - запускает validation и возвращает результат;
- `reset()` - сбрасывает значения controlled fields, если компоненты поддерживают reset;
- `resetValidation()` - сбрасывает только validation state.

Правила `rules`:

- функция возвращает `true`, если значение валидно;
- функция возвращает строку с ошибкой, если невалидно;
- можно использовать массив правил;
- async validation лучше применять осторожно, чтобы не создавать лишние запросы на каждый ввод.

## `v-model` в Vuetify

Vuetify-компоненты активно используют `v-model`:

```vue
<v-dialog v-model="isDialogOpen" max-width="560">
  ...
</v-dialog>

<v-select
  v-model="selectedRole"
  :items="roles"
  item-title="label"
  item-value="value"
/>
```

У многих компонентов есть именованные модели:

```vue
<v-data-table
  v-model:page="page"
  v-model:items-per-page="pageSize"
  :items="items"
/>
```

## Slots и props

В Vuetify сначала ищут официальный prop или slot, а уже потом CSS override.

```vue
<v-data-table :items="users" :headers="headers">
  <template #item.status="{ item }">
    <v-chip :color="item.status === 'active' ? 'success' : 'warning'">
      {{ item.status }}
    </v-chip>
  </template>

  <template #no-data>
    Пользователи не найдены
  </template>
</v-data-table>
```

## Accessibility

Vuetify дает основу, но разработчик отвечает за:

- понятные labels;
- правильные `aria-label` для icon-only buttons;
- фокус после закрытия dialogs;
- читаемые error messages;
- контраст custom theme colors;
- корректные titles и landmark layout;
- отсутствие disabled controls без объяснения причины.

Icon-only button:

```vue
<v-btn icon="mdi-delete" aria-label="Удалить пользователя" />
```

## Performance

Практические правила:

- включить `vite-plugin-vuetify` и auto import;
- не импортировать все иконки пачкой;
- использовать lazy routes для тяжелых страниц;
- не рендерить огромные таблицы без pagination/virtualization;
- выбирать `density` и `defaults` системно;
- анализировать bundle после добавления больших компонентов.

## Частые ошибки

- Переопределять Vuetify через глубокие CSS-селекторы вместо theme/defaults/props/slots.
- Смешивать Vuetify, Tailwind и custom CSS без правил ответственности.
- Делать custom theme с плохим contrast.
- Забывать `aria-label` на icon buttons.
- Хранить form validation только в UI, без backend validation.
- Делать async rules на каждый keypress без debounce/cache.
- Не проверять mobile drawer/dialog behavior.

## Что отвечать на собеседовании

Vuetify подключают как Vue plugin через `createVuetify`, настраивают theme, icons и defaults. Для форм используют `v-form`, `rules`, `validate`, `reset`, `resetValidation`, а состояние контролируют через `v-model`. Responsive behavior строят через CSS и `useDisplay`, но behavioral differences можно переключать в JS. В production важно пользоваться props/slots/theme/defaults вместо хаотичных CSS overrides, проверять accessibility и bundle size.

## Мини-шпаргалка

- `createVuetify` - создание plugin.
- `theme` - цвета и dark/light.
- `defaults` - стандартные props компонентов.
- `useTheme` - runtime theme control.
- `useDisplay` - breakpoints/platform.
- `v-form.validate()` - проверка формы.
- `rules` - массив validation rules.
- `v-model` - состояние Vuetify-компонентов.
- props/slots раньше CSS overrides.
