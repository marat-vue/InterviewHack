# Почему Web Worker не имеет доступа к DOM

> [!summary] Коротко
> Web Worker не имеет доступа к DOM, потому что DOM живет в основном потоке браузера и должен изменяться предсказуемо.

## Вопрос

Почему worker не может напрямую менять элементы страницы?

## Определение

Web Worker выполняется в отдельном потоке. DOM связан с основным потоком, где происходят события, layout, paint и взаимодействие пользователя с интерфейсом.

Если бы worker мог менять DOM напрямую, несколько потоков могли бы одновременно изменять одну и ту же структуру. Это усложнило бы модель браузера: появились бы гонки данных, блокировки и непредсказуемые состояния интерфейса.

## Что будет недоступно

```javascript
// worker.js

console.log(document); // ReferenceError
console.log(window);   // ReferenceError
```

В worker нет `document` и обычного `window`.

## Как обновлять DOM правильно

Worker считает данные и отправляет результат в основной поток.

```javascript
// main.js
worker.onmessage = (event) => {
  resultElement.textContent = event.data.result;
};
```

```javascript
// worker.js
self.postMessage({ result: 42 });
```

DOM меняет основной поток, а тяжелая работа остается в worker.

## Что доступно в worker

- `self`;
- `fetch`;
- таймеры;
- `postMessage`;
- некоторые API хранения и обработки данных;
- `importScripts()` в classic worker.

## Мини-шпаргалка

```text
Worker: вычисляет данные
Main thread: получает сообщение и обновляет DOM
```
