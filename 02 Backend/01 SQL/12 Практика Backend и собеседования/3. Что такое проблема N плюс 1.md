# Что такое проблема N плюс 1?

> [!summary]
> N+1 - проблема, когда приложение сначала делает один запрос за списком сущностей, а потом по одному запросу на каждую строку списка. Это резко увеличивает количество запросов к базе.

## Пример

```txt
1 запрос: SELECT * FROM users LIMIT 100
100 запросов: SELECT * FROM orders WHERE user_id = ?
```

Итого 101 запрос вместо одного или нескольких пакетных.

## Решение через JOIN

```sql
SELECT u.id, u.email, o.id AS order_id
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
WHERE u.id IN (1, 2, 3);
```

## Решение через batch loading

```sql
SELECT *
FROM orders
WHERE user_id IN (1, 2, 3, 4);
```

Приложение затем группирует заказы по `user_id`.

## Где встречается?

- ORM lazy loading;
- GraphQL resolvers;
- шаблоны страниц;
- вложенные списки;
- сериализация API-ответов.

## Мини-шпаргалка

- N+1 = один запрос за списком плюс N запросов за деталями.
- Лечится join, eager loading или batch loading.
- Следи за SQL-логами.
- GraphQL часто требует DataLoader-подход.
- Индексы на FK все равно нужны.
