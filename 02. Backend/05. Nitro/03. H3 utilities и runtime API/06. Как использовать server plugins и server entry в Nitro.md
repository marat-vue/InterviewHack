# Как использовать server plugins и server entry в Nitro?

> [!NOTE]
> Nitro plugins расширяют runtime behavior при старте приложения, а server entry позволяет задать собственную точку входа перед route matching. Plugins удобны для hooks, SDK, логирования и интеграций; server entry нужен для более низкоуровневого контроля.

## Что такое Nitro plugin?

Plugin - файл в `server/plugins`, который выполняется при инициализации Nitro runtime.

```ts
// server/plugins/logger.ts
export default definePlugin((nitroApp) => {
  nitroApp.hooks.hook('request', (event) => {
    console.log(event.method, event.path);
  });
});
```

## Зачем нужны plugins?

Plugins используют для:

- request/response hooks;
- metrics;
- tracing;
- error reporting;
- CORS adapters;
- database warmup;
- SDK initialization;
- Nitro app extension;
- registering custom middleware.

## Пример plugin для ошибок

```ts
// server/plugins/error-reporting.ts
export default definePlugin((nitroApp) => {
  nitroApp.hooks.hook('error', async (error, { event }) => {
    await reportError(error, {
      path: event?.path,
      requestId: event?.context.requestId,
    });
  });
});
```

## Чем plugin отличается от middleware?

| Инструмент | Когда выполняется | Для чего нужен |
|---|---|---|
| Plugin | при старте runtime | hooks, SDK, global setup |
| Middleware | на каждый request до route | request checks/context |
| Handler | на matched route | бизнес-операция |

## Что такое server entry?

Server entry - кастомная точка входа, которую Nitro может использовать до обычной обработки routes.

```ts
// nitro.config.ts
export default defineConfig({
  serverEntry: './server.ts',
});
```

`serverEntry` может быть:

- `web` format - объект/handler с Web-compatible API;
- `node` format - Node-style `(req, res)` handler;
- `false` - отключить auto-detection.

## Server entry как middleware

```ts
// server.ts
import { defineHandler } from 'nitro';

export default defineHandler((event) => {
  event.context.requestId = crypto.randomUUID();

  // Если ничего не вернуть, request продолжит идти к routes.
});
```

Если server entry возвращает response, request lifecycle останавливается.

## Когда нужен server entry?

Server entry нужен редко. Он полезен, если:

- нужно интегрировать внешний server handler;
- нужен Node-style adapter;
- нужен global middleware до route matching;
- нужно контролировать fallback behavior;
- переносишь существующее приложение в Nitro.

В обычном Nitro/Nuxt-проекте чаще хватает `server/plugins` и `server/middleware`.

## Мини-шпаргалка

- Plugin - runtime setup при старте Nitro.
- Middleware - per-request logic до route.
- Server entry - низкоуровневая точка входа.
- Если server entry ничего не возвращает, request идет дальше.
- Если server entry возвращает response, routes уже не выполняются.
- Для большинства проектов начинай с plugins/middleware, server entry трогай только при реальной необходимости.
