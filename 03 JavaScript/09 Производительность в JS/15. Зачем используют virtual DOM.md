# Зачем используют virtual DOM

> [!summary] Коротко
> Virtual DOM - легковесное представление UI в памяти, которое помогает фреймворку вычислять минимальные изменения реального DOM.

## Вопрос

Зачем React и похожие библиотеки используют Virtual DOM?

## Определение

Virtual DOM - JavaScript-структура, описывающая интерфейс. При изменении состояния фреймворк строит новое представление, сравнивает его со старым и решает, какие реальные DOM-операции нужны.

Это не магическая гарантия максимальной скорости, а архитектурный прием для декларативного обновления UI.

## Упрощенный пример

```javascript
const virtualNode = {
  type: 'button',
  props: {
    className: 'primary',
    children: 'Save',
  },
};
```

Такой объект дешевле анализировать, чем сразу выполнять много DOM-операций.

## Зачем это полезно

- декларативное описание интерфейса;
- централизованное обновление UI;
- batch-обновления;
- меньше ручной работы с DOM;
- предсказуемая модель компонентов.

## Важный нюанс

Virtual DOM сам по себе не всегда быстрее ручного оптимального DOM-кода. Его сила в удобной модели обновлений и автоматическом применении изменений.

## Мини-шпаргалка

```text
state changes -> new virtual tree -> diff -> real DOM patch
```
