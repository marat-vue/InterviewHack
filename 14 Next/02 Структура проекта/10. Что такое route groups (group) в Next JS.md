# Что такое route groups (group) в Next JS?

> [!summary]
> Route Groups - папки в круглых скобках, например `(marketing)` или `(dashboard)`. Они помогают группировать routes и layouts в `app`, но не добавляют сегмент в URL.

## Как выглядит route group?

```text
app/
  (marketing)/
    page.tsx
    pricing/
      page.tsx
  (app)/
    dashboard/
      page.tsx
```

URL:

- `app/(marketing)/page.tsx` -> `/`;
- `app/(marketing)/pricing/page.tsx` -> `/pricing`;
- `app/(app)/dashboard/page.tsx` -> `/dashboard`.

Сами `(marketing)` и `(app)` в URL не попадают.

## Зачем нужны route groups?

### Организация проекта

```text
app/
  (public)/
  (auth)/
  (dashboard)/
```

Так проще отделить публичные страницы, auth flow и внутреннее приложение.

### Разные layouts

```text
app/
  (auth)/
    layout.tsx
    login/
      page.tsx
  (dashboard)/
    layout.tsx
    dashboard/
      page.tsx
```

Login может быть без sidebar, dashboard - с sidebar.

### Разделение командной ответственности

Route groups помогают держать большие sections отдельно, не портя URL.

## Важный конфликт

Нельзя иметь два routes с одинаковым URL:

```text
app/
  (admin)/
    settings/
      page.tsx
  (user)/
    settings/
      page.tsx
```

Оба дают `/settings`, это конфликт.

## Что отвечать на собеседовании?

Route Groups - это папки в скобках внутри `app`, которые не влияют на URL. Они нужны для логической группировки routes, разных layouts и организации больших приложений. Нужно следить, чтобы группы не создавали одинаковые URL.

## Частые ошибки

- Думать, что `(admin)` появится в URL.
- Создавать одинаковые paths в разных groups.
- Использовать groups вместо нормальной архитектуры.
- Класть слишком много логики в route group.
- Путать route groups с dynamic segments `[id]`.

## Мини-шпаргалка

- `(group)` не попадает в URL.
- Route groups помогают структуре.
- Можно задавать разные layouts.
- Следи за конфликтами URL.
- `[id]` - dynamic segment, `(id)` - group.
