# ts-ignore

> [!summary] Коротко
> `// @ts-ignore` отключает ошибку TypeScript на следующей строке. Это опасно, потому что скрывает любые ошибки на этой строке, даже новые.

## Вопрос

Почему `ts-ignore` считают антипаттерном?

## Что делает ts-ignore

```typescript
// @ts-ignore
const value: number = "hello";
```

TypeScript проигнорирует ошибку. Но runtime-проблема никуда не исчезнет.

## Главная опасность

`@ts-ignore` скрывает все ошибки на следующей строке, а не только одну конкретную.

```typescript
// @ts-ignore
user.profile.address.city.toUpperCase();
```

Если в этой строке появится новая ошибка, TypeScript тоже промолчит.

## Лучше использовать ts-expect-error

```typescript
// @ts-expect-error Проверяем, что неверный тип действительно запрещен
createUser({ age: "wrong" });
```

`@ts-expect-error` сам станет ошибкой, если TypeScript больше не видит проблемы. Это полезно в тестах типов.

## Еще лучше - исправить тип

```typescript
if (user.profile?.address?.city) {
  user.profile.address.city.toUpperCase();
}
```

Часто вместо подавления ошибки нужен narrowing, корректный тип или runtime-проверка.

## Мини-шпаргалка

- `@ts-ignore` скрывает ошибку на следующей строке.
- Может прятать новые ошибки.
- Для ожидаемых ошибок лучше `@ts-expect-error`.
- В продакшен-коде сначала ищи типовое решение.
