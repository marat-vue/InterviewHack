# Что делает хук useSyncExternalStore()?

> [!summary]
> `useSyncExternalStore` подключает React-компонент к внешнему хранилищу данных: Redux, Zustand, browser API, собственному event emitter, `localStorage`, media query или любому store вне React. Хук нужен, чтобы React получал согласованный snapshot данных даже при concurrent rendering и SSR.

## Зачем нужен этот хук?

React хорошо работает со своим состоянием:

```jsx
const [count, setCount] = useState(0)
```

Но в реальных приложениях данные часто живут снаружи:

- Redux store;
- Zustand store;
- глобальный event emitter;
- `window.innerWidth`;
- `navigator.onLine`;
- `localStorage`;
- WebSocket cache;
- состояние роутера.

Если просто подписаться через `useEffect`, при concurrent rendering можно получить tearing: разные части UI на один момент видят разные версии внешнего store.

`useSyncExternalStore` дает React официальный протокол: как подписаться на внешний источник и как синхронно прочитать актуальный snapshot.

## Сигнатура

```jsx
const snapshot = useSyncExternalStore(
  subscribe,
  getSnapshot,
  getServerSnapshot,
)
```

| Аргумент | Что делает |
|---|---|
| `subscribe` | подписывает React на изменения store |
| `getSnapshot` | возвращает текущее значение на клиенте |
| `getServerSnapshot` | возвращает значение для SSR и hydration |

Третий аргумент нужен, если компонент может рендериться на сервере.

## Минимальный внешний store

```jsx
let count = 0
const listeners = new Set()

export const counterStore = {
  getSnapshot() {
    return count
  },

  subscribe(listener) {
    listeners.add(listener)

    return () => {
      listeners.delete(listener)
    }
  },

  increment() {
    count += 1
    listeners.forEach((listener) => listener())
  },
}
```

Подключение к React:

```jsx
import { useSyncExternalStore } from 'react'
import { counterStore } from './counterStore'

function Counter() {
  const count = useSyncExternalStore(
    counterStore.subscribe,
    counterStore.getSnapshot,
    () => 0,
  )

  return (
    <button onClick={counterStore.increment}>
      Count: {count}
    </button>
  )
}
```

## Почему нельзя просто useEffect + useState?

Такой код часто выглядит нормально:

```jsx
function Counter() {
  const [count, setCount] = useState(counterStore.getSnapshot())

  useEffect(() => {
    return counterStore.subscribe(() => {
      setCount(counterStore.getSnapshot())
    })
  }, [])

  return <button>{count}</button>
}
```

Но у него есть проблемы:

- первый render может получить устаревшее значение;
- SSR и клиент могут стартовать с разными данными;
- React не может гарантировать консистентность snapshot во время concurrent render;
- подписка появляется только после commit.

`useSyncExternalStore` встроен в планировщик React и дает более надежный контракт.

## Пример: online/offline status

```jsx
import { useSyncExternalStore } from 'react'

function subscribe(callback) {
  window.addEventListener('online', callback)
  window.addEventListener('offline', callback)

  return () => {
    window.removeEventListener('online', callback)
    window.removeEventListener('offline', callback)
  }
}

function getSnapshot() {
  return navigator.onLine
}

function getServerSnapshot() {
  return true
}

export function useOnlineStatus() {
  return useSyncExternalStore(
    subscribe,
    getSnapshot,
    getServerSnapshot,
  )
}
```

Использование:

```jsx
function StatusBadge() {
  const isOnline = useOnlineStatus()

  return (
    <span>
      {isOnline ? 'Online' : 'Offline'}
    </span>
  )
}
```

## Требования к getSnapshot

`getSnapshot` должен возвращать одинаковый результат, если данные не изменились.

Плохо:

```jsx
function getSnapshot() {
  return { count }
}
```

Такой код каждый раз возвращает новый объект. React может решить, что snapshot постоянно меняется.

Лучше:

```jsx
let currentSnapshot = { count: 0 }

function setCount(nextCount) {
  currentSnapshot = { count: nextCount }
  listeners.forEach((listener) => listener())
}

function getSnapshot() {
  return currentSnapshot
}
```

Если snapshot - объект или массив, его нужно кэшировать и менять только при реальном изменении данных.

## Как работает с SSR?

На сервере нет `window`, `document`, `navigator` и многих browser API. Поэтому нужен `getServerSnapshot`.

```jsx
const width = useSyncExternalStore(
  subscribeToResize,
  () => window.innerWidth,
  () => 1024,
)
```

Первое значение на клиенте во время hydration должно совпадать с серверным. Иначе можно получить hydration mismatch.

## Где это встречается в реальных библиотеках?

Чаще всего разработчик не пишет `useSyncExternalStore` вручную, но пользуется библиотеками, которые применяют его внутри:

- Redux;
- Zustand;
- React Router;
- библиотеки для media queries;
- библиотеки для синхронизации с `localStorage`;
- внешние кэши данных.

## Что отвечать на собеседовании?

`useSyncExternalStore` - официальный хук React 18 для подписки на external store. Он принимает `subscribe`, `getSnapshot` и опционально `getServerSnapshot`, защищает от tearing при concurrent rendering и помогает корректно работать с SSR.

## Частые ошибки

- Возвращать новый объект из `getSnapshot` на каждый вызов.
- Не возвращать cleanup из `subscribe`.
- Читать `window` в `getServerSnapshot`.
- Использовать хук для обычного локального state.
- Забывать, что первое клиентское значение должно совпасть с серверным.

## Мини-шпаргалка

- `subscribe` сообщает React, когда store изменился.
- `getSnapshot` синхронно читает текущее значение.
- `getServerSnapshot` нужен для SSR.
- Snapshot должен быть стабильным между изменениями.
- Хук нужен для external store, а не для обычного `useState`.
