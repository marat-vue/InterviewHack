# Что такое NuxtApp, lifecycle hooks и runWithContext?

> [!NOTE]
> `NuxtApp` - runtime-контекст Nuxt-приложения. Через него доступны provided values, hooks, payload, SSR context и utilities, которые нужны plugins, composables и advanced integration code.

## Как получить NuxtApp?

```ts
const nuxtApp = useNuxtApp()
```

Обычно это нужно в:

- plugins;
- composables;
- custom API clients;
- instrumentation;
- error handling;
- code, которому нужен `$provided` helper.

## Provide/inject через plugin

`app/plugins/api.ts`:

```ts
export default defineNuxtPlugin(() => {
  const config = useRuntimeConfig()

  const api = $fetch.create({
    baseURL: config.public.apiBase
  })

  return {
    provide: {
      api
    }
  }
})
```

Использование:

```ts
const { $api } = useNuxtApp()

const { data } = await useAsyncData('profile', () => {
  return $api('/profile')
})
```

В TypeScript лучше добавить типизацию provided значения.

## Object syntax plugin

```ts
export default defineNuxtPlugin({
  name: 'analytics',
  enforce: 'post',
  async setup(nuxtApp) {
    nuxtApp.hook('page:finish', () => {
      console.log('page finished')
    })
  },
  env: {
    islands: false
  }
})
```

Поля:

| Поле | Зачем |
| --- | --- |
| `name` | Имя plugin для отладки и ordering. |
| `enforce` | `pre`, `default`, `post` порядок выполнения. |
| `dependsOn` | Зависимость от другого plugin. |
| `setup` | Основная функция plugin. |
| `hooks` | Declarative hooks. |
| `env.islands` | Выполнять ли plugin при render server islands. |

## Hooks в runtime

```ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('app:created', () => {
    console.log('created')
  })

  nuxtApp.hook('page:start', () => {
    console.log('navigation started')
  })

  nuxtApp.hook('page:finish', () => {
    console.log('navigation finished')
  })
})
```

Hooks полезны для:

- analytics;
- loading state;
- logging;
- metrics;
- error reporting;
- route instrumentation.

## `runWithContext`

Иногда Nuxt composable нужно вызвать там, где Nuxt context потерян, например внутри callback внешней библиотеки.

```ts
export default defineNuxtPlugin((nuxtApp) => {
  const api = $fetch.create({
    async onResponseError({ response }) {
      if (response.status === 401) {
        await nuxtApp.runWithContext(() => navigateTo('/login'))
      }
    }
  })

  return {
    provide: {
      api
    }
  }
})
```

Без `runWithContext` `navigateTo`, `useRouter`, `useRuntimeConfig` и другие composables могут не найти текущий Nuxt context.

## SSR context

На сервере можно получить request-specific данные:

```ts
export default defineNuxtPlugin((nuxtApp) => {
  if (import.meta.server) {
    const event = nuxtApp.ssrContext?.event
    const url = event?.path

    console.log('SSR request', url)
  }
})
```

Важно: SSR context существует только на server side. На client side его нет.

## Payload

```ts
const nuxtApp = useNuxtApp()

console.log(nuxtApp.payload.data)
console.log(nuxtApp.payload.state)
```

Payload переносит SSR data и state на клиент, чтобы избежать повторного запроса при hydration.

## Когда не нужен `useNuxtApp`?

Не используй его просто “потому что можно”. Для обычного кода лучше:

- `useFetch`;
- `useAsyncData`;
- `useRuntimeConfig`;
- `useRoute`;
- `useRouter`;
- обычные composables.

`useNuxtApp` нужен, когда работаешь с инфраструктурным контекстом приложения.

## Что отвечать на собеседовании?

`NuxtApp` - это runtime context Nuxt. Через `useNuxtApp()` можно получить injected values, hooks, payload и SSR context. Plugins часто используют `provide`, чтобы добавить `$api` или `$analytics`. `runWithContext` нужен, когда Nuxt composable вызывается из callback, где обычный context потерян.

## Частые ошибки

- Вызывать `useNuxtApp` вне Nuxt lifecycle.
- Держать request-specific данные в module-level singleton.
- Использовать SSR context на клиенте.
- Не типизировать provided `$api`.
- Пихать business logic в plugin вместо composable/service.
- Использовать plugin для того, что можно сделать обычным import.

## Мини-шпаргалка

- `useNuxtApp()` - runtime context.
- `provide` - `$api`, `$analytics`, `$featureFlags`.
- `nuxtApp.hook` - runtime events.
- `runWithContext` - восстановить context для composables.
- `nuxtApp.ssrContext` - только server.
- `payload` - SSR data/state для hydration.
