# Как работает Redis Pub/Sub?

> [!NOTE]
> Redis Pub/Sub - механизм публикации сообщений в channels. Он быстрый и простой, но сообщения не сохраняются: offline subscriber их не получит.

## Как работает Pub/Sub?

Subscriber:

```redis
SUBSCRIBE notifications
```

Publisher:

```redis
PUBLISH notifications '{"type":"user.created","id":"1"}'
```

Все активные подписчики channel получают сообщение.

## Node.js пример

Для Pub/Sub нужны разные connections:

```ts
import { createClient } from 'redis';

const publisher = createClient({
  url: process.env.REDIS_URL,
});

const subscriber = publisher.duplicate();

await publisher.connect();
await subscriber.connect();

await subscriber.subscribe('notifications', (message) => {
  console.log('message:', JSON.parse(message));
});

await publisher.publish('notifications', JSON.stringify({
  type: 'user.created',
  id: '1',
}));
```

## Когда использовать Pub/Sub?

Pub/Sub подходит для:

- WebSocket fan-out;
- online notifications;
- cache invalidation messages;
- low-latency broadcast;
- coordination между инстансами.

## Когда Pub/Sub не подходит?

Pub/Sub не подходит, если:

- нужно хранить историю;
- нужен retry;
- подписчики могут быть offline;
- нужна гарантированная обработка;
- нужно replay.

Тогда лучше Streams.

## Pattern subscriptions

```redis
PSUBSCRIBE tenant:*:notifications
```

Это подписка по pattern. Удобно, но может усложнить routing и observability.

## Мини-шпаргалка

- `PUBLISH` - отправить.
- `SUBSCRIBE` - подписаться.
- `PSUBSCRIBE` - pattern subscription.
- Pub/Sub delivery - at-most-once.
- Offline subscribers теряют сообщения.
- Для reliable processing выбирай Streams.
