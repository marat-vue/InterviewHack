> [!summary]
> При загрузке HTML браузер получает документ, парсит разметку, строит DOM, загружает связанные ресурсы, строит CSSOM, формирует render tree и рисует страницу.

## Общая схема

```text
HTML response
  -> parse HTML
  -> build DOM
  -> load CSS, JS, images, fonts
  -> build CSSOM
  -> create render tree
  -> layout
  -> paint
  -> composite
```

## Получение HTML

Браузер отправляет запрос к серверу и получает HTML-документ.

```http
GET / HTTP/1.1
Host: example.com
```

После ответа браузер начинает читать HTML сверху вниз.

## Построение DOM

HTML превращается в дерево объектов - DOM.

```html
<main>
  <h1>Каталог</h1>
  <p>Список товаров</p>
</main>
```

Упрощенно:

```text
main
  h1
    "Каталог"
  p
    "Список товаров"
```

## Загрузка связанных ресурсов

Во время парсинга браузер встречает ссылки на CSS, JS, изображения и шрифты.

```html
<link rel="stylesheet" href="/styles.css" />
<script src="/app.js" defer></script>
<img src="/cover.jpg" alt="Обложка" />
```

Часть ресурсов может блокировать дальнейшую обработку. Например, обычный `<script>` без `defer` может остановить парсинг HTML до выполнения скрипта.

## Построение render tree

DOM описывает структуру, CSSOM описывает стили. Вместе они дают render tree - дерево видимых элементов с вычисленными стилями.

Элементы вроде `<head>` не попадают в render tree, потому что они не отображаются на странице.

## Layout и paint

- **Layout**: браузер вычисляет размеры и позиции элементов.
- **Paint**: браузер рисует текст, фон, границы, изображения.
- **Composite**: браузер собирает слои в итоговую картинку.

## Мини-шпаргалка

- HTML парсится сверху вниз.
- DOM - дерево элементов документа.
- CSSOM - дерево CSS-правил.
- Render tree содержит видимые элементы.
- Layout считает размеры и позиции.
- Paint рисует пиксели.
- `defer` помогает не блокировать парсинг HTML.
