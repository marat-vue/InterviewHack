# Что означает “idempotent request”?

> [!summary]
> Idempotent request - это запрос, повторное выполнение которого имеет тот же эффект на сервере, что и один вызов. Идемпотентность важна для retries, сетевых сбоев, проектирования API и защиты от случайных дублей.

## Простое определение

```text
Один и тот же запрос отправили 1 раз или 10 раз.
Итоговое состояние сервера одинаковое.
```

Пример:

```http
DELETE /api/users/42
```

После первого запроса пользователя нет. После повторного запроса пользователя все еще нет. Итоговое состояние одинаковое.

## HTTP-методы и идемпотентность

| Метод | Обычно идемпотентен | Почему |
|---|---|---|
| `GET` | Да | Только читает данные |
| `HEAD` | Да | Читает headers без body |
| `OPTIONS` | Да | Описывает возможности |
| `PUT` | Да | Заменяет ресурс одним и тем же состоянием |
| `DELETE` | Да | Итог: ресурс удален |
| `POST` | Нет | Может создать новый ресурс при каждом вызове |
| `PATCH` | Не гарантированно | Зависит от операции |

## PUT vs PATCH

`PUT` обычно заменяет ресурс целиком:

```http
PUT /api/users/42
Content-Type: application/json

{ "name": "Ada", "role": "admin" }
```

Повтор того же запроса оставляет ресурс в том же состоянии.

`PATCH` может быть идемпотентным или нет.

Идемпотентный PATCH:

```http
PATCH /api/users/42

{ "name": "Ada" }
```

Неидемпотентный PATCH:

```http
PATCH /api/counter

{ "increment": 1 }
```

Каждый повтор увеличит счетчик.

## Почему это важно во frontend?

Frontend может повторить запрос, если:

- пользователь нажал кнопку дважды;
- сеть оборвалась;
- retry сделал HTTP-client;
- вкладка восстановила соединение;
- mutation повторилась после ошибки.

Для неидемпотентных операций нужны:

- disabled button на время submit;
- idempotency key;
- защита от double submit;
- серверная дедупликация;
- аккуратная обработка retries.

## Idempotency key

Для критичных `POST`, например оплаты, часто используют idempotency key.

```http
POST /api/payments
Idempotency-Key: 1f7b8c2d-...
```

Сервер понимает, что повтор с тем же ключом - это не новая операция, а повтор прежней.

## Мини-шпаргалка

- Идемпотентность говорит об итоговом состоянии сервера.
- `GET`, `PUT`, `DELETE` обычно идемпотентны.
- `POST` обычно не идемпотентен.
- `PATCH` зависит от смысла операции.
- Для платежей и заказов нужен idempotency key или защита от дублей.
