# Для чего нужен тип React.ReactNode?

> [!summary]
> `React.ReactNode` описывает все, что React умеет отрендерить: элементы, строки, числа, `null`, `undefined`, boolean, arrays, fragments и portals. Чаще всего его используют для `children` и props, которые принимают произвольный React-контент.

## Что входит в React.ReactNode?

`React.ReactNode` - широкий тип для renderable content.

В него входят:

- React elements: `<div />`, `<Button />`;
- строки;
- числа;
- `null`;
- `undefined`;
- boolean значения;
- массивы renderable значений;
- fragments;
- portals.

```tsx
type CardProps = {
  children: React.ReactNode
}

function Card({ children }: CardProps) {
  return <article>{children}</article>
}
```

Такой компонент принимает:

```tsx
<Card>Hello</Card>
<Card>{42}</Card>
<Card><strong>Important</strong></Card>
<Card>{condition && <span>Visible</span>}</Card>
```

## ReactNode для props

`ReactNode` подходит не только для `children`:

```tsx
type EmptyStateProps = {
  icon?: React.ReactNode
  title: React.ReactNode
  action?: React.ReactNode
}

function EmptyState({ icon, title, action }: EmptyStateProps) {
  return (
    <section>
      {icon}
      <h2>{title}</h2>
      {action}
    </section>
  )
}
```

Так можно передать текст, элемент, fragment или условный JSX.

## ReactNode vs ReactElement

| Тип | Что означает |
|---|---|
| `React.ReactNode` | все, что React может отрендерить |
| `React.ReactElement` | конкретный React element |
| `React.JSX.Element` | JSX element, который вернул JSX |

Пример, где нужен именно `ReactNode`:

```tsx
type Props = {
  children: React.ReactNode
}
```

Если написать слишком узко:

```tsx
type Props = {
  children: React.ReactElement
}
```

Тогда строка уже не подойдет:

```tsx
<Component>Plain text</Component>
```

## Когда ReactElement полезнее?

Если prop должен быть именно одним элементом:

```tsx
type TooltipProps = {
  trigger: React.ReactElement
  content: React.ReactNode
}
```

Теперь `trigger` ожидает элемент:

```tsx
<Tooltip trigger={<button>Open</button>} content="Details" />
```

Но для большинства `children` нужен `ReactNode`.

## children обязателен или нет?

Если children обязателен:

```tsx
type LayoutProps = {
  children: React.ReactNode
}
```

Если опционален:

```tsx
type ButtonProps = {
  children?: React.ReactNode
}
```

## Что отвечать на собеседовании?

`React.ReactNode` - самый широкий тип для всего, что можно отрендерить в React. Его используют для `children` и props вроде `icon`, `label`, `fallback`, `action`. В отличие от `ReactElement`, он допускает строки, числа, `null`, `undefined`, boolean и массивы.

## Частые ошибки

- Типизировать `children` как `JSX.Element`, когда нужен текст или массив.
- Использовать `ReactNode` там, где нужен строго один element.
- Забывать `children?`, если children опционален.
- Думать, что boolean рендерится как текст.
- Использовать `any` для renderable props.

## Мини-шпаргалка

- `ReactNode` - все, что React может отрендерить.
- Для `children` обычно нужен `React.ReactNode`.
- `ReactElement` уже, чем `ReactNode`.
- `children?: React.ReactNode` - children необязателен.
- Для строго одного элемента используй `React.ReactElement`.
