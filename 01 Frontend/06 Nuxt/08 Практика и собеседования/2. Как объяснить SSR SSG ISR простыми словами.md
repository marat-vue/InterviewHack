# Как объяснить SSR, SSG и ISR простыми словами?

> [!summary]
> SSR - готовим страницу на каждый запрос, SSG - готовим страницу заранее при сборке, ISR - готовим статическую страницу и периодически обновляем ее после запросов. Это разные способы решить баланс свежести, скорости и стоимости.

## SSR

Объяснение:

```text
Пользователь пришел -> сервер прямо сейчас собрал HTML -> отправил пользователю.
```

Плюсы:

- свежие данные;
- SEO;
- подходит для dynamic pages.

Минусы:

- server work на каждый request;
- выше TTFB, если render/data медленные.

## SSG

Объяснение:

```text
Мы заранее собрали HTML на build-time -> CDN быстро отдает готовый файл.
```

Плюсы:

- очень быстро;
- простой hosting;
- меньше server cost.

Минусы:

- данные могут устареть;
- dynamic routes нужно заранее знать.

## ISR

Объяснение:

```text
Отдаем cached/static страницу -> через заданное время разрешаем обновить ее.
```

Плюсы:

- быстро как cache;
- контент обновляется без полного rebuild;
- хорошо для blog/catalog pages.

Минусы:

- поведение зависит от platform;
- есть окно устаревших данных;
- нельзя бездумно применять к персональным страницам.

## Как выбрать?

| Нужно | Выбор |
|---|---|
| всегда свежие данные | SSR |
| максимальная скорость и редкие изменения | SSG |
| быстрый сайт с периодическим обновлением | ISR/SWR |
| закрытый dashboard | CSR |

## Мини-шпаргалка

- SSR - render on request.
- SSG - render at build-time.
- ISR - cached static with regeneration.
- SWR - stale now, refresh in background.
- Выбор зависит от свежести, SEO, скорости и персонализации.
