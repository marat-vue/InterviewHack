# Когда выполняется эффект без зависимостей?

> [!summary]
> Если вызвать `useEffect` без массива зависимостей, effect будет выполняться после каждого commit компонента. Это нужно редко, потому что легко получить лишнюю работу или бесконечный цикл обновлений.

## Пример без зависимостей

```jsx
useEffect(() => {
  console.log('Компонент отрендерился')
})
```

Такой effect выполнится после каждого render, который дошел до commit.

## Почему это опасно?

Если внутри effect обновить state, можно получить цикл:

```jsx
useEffect(() => {
  setCount(count + 1)
})
```

Цепочка:

```text
render -> effect -> setState -> render -> effect -> setState -> ...
```

## Когда это может быть уместно?

Редко, например:

- отладочное логирование;
- синхронизация с внешней системой после любого commit;
- измерения, которые действительно должны происходить после каждого обновления.

Но чаще стоит указать зависимости:

```jsx
useEffect(() => {
  document.title = title
}, [title])
```

## Отличие от пустого массива

Без массива:

```jsx
useEffect(() => {
  // после каждого commit
})
```

С пустым массивом:

```jsx
useEffect(() => {
  // после первого commit
}, [])
```

В development Strict Mode эффект с пустым массивом может запускаться дополнительный раз для проверки cleanup.

## Мини-шпаргалка

- Без dependencies effect выполняется после каждого commit.
- Это часто приводит к лишним действиям.
- `setState` внутри такого effect может создать бесконечный цикл.
- Обычно лучше явно указать зависимости.
- Пустой массив `[]` - другой сценарий, не "без зависимостей".
