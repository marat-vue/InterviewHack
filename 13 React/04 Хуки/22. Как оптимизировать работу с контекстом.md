# Как оптимизировать работу с контекстом?

> [!summary]
> Оптимизация Context обычно сводится к разделению данных по смыслу, стабилизации `value`, уменьшению количества потребителей и выносу часто меняющегося состояния в более подходящий store. Context хорош для передачи данных, но не всегда хорош для частых точечных обновлений.

## Проблема: один большой context

```jsx
<AppContext.Provider value={{ user, theme, cart, filters }}>
  {children}
</AppContext.Provider>
```

Если изменится `filters`, все потребители `AppContext` могут обновиться, даже если им нужен только `theme`.

## Решение 1: разделить context

```jsx
<AuthProvider>
  <ThemeProvider>
    <CartProvider>
      {children}
    </CartProvider>
  </ThemeProvider>
</AuthProvider>
```

Теперь изменение корзины не обязано затрагивать тему или пользователя.

## Решение 2: стабилизировать value

```jsx
const value = useMemo(() => ({
  theme,
  setTheme,
}), [theme])

return (
  <ThemeContext.Provider value={value}>
    {children}
  </ThemeContext.Provider>
)
```

Это помогает не создавать новый объект без необходимости.

## Решение 3: разделить state и actions

```jsx
const ThemeStateContext = createContext(null)
const ThemeActionsContext = createContext(null)
```

Компоненты, которым нужен только `setTheme`, не будут зависеть от `theme`, если читать actions отдельно.

## Решение 4: использовать state manager

Если состояние:

- часто меняется;
- большое;
- нужно многим компонентам;
- требует selectors;
- должно обновлять только точечных подписчиков;

то Context может быть не лучшим инструментом. Подойдут Zustand, Redux Toolkit, Jotai или другой store.

## Мини-шпаргалка

- Не делай один context для всего приложения.
- Разделяй context по смыслу.
- Стабилизируй object value через `useMemo`, если это нужно.
- Разделяй state и actions при частых обновлениях.
- Для selector-based подписок лучше state manager.
