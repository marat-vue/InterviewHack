# Чем Next.js быстрее обычного SPA?

> [!summary]
> Next.js часто быстрее обычного SPA на первом входе, потому что может отдавать готовый HTML, получать данные на сервере, кешировать результат, разделять код по маршрутам и уменьшать количество JavaScript через Server Components.

## Как загружается классическое SPA?

Типичная схема:

```text
HTML shell -> JS bundle -> React render -> API request -> render data
```

Пользователь часто сначала получает почти пустой HTML:

```html
<div id="root"></div>
<script src="/assets/app.js"></script>
```

Контент появляется только после загрузки и выполнения JavaScript.

## Как может загружаться Next.js?

В App Router Next.js может отдать уже подготовленный HTML/RSC payload:

```text
server render / static render -> HTML with content -> hydration only where needed
```

Это улучшает:

- FCP;
- LCP;
- SEO;
- скорость первого экрана;
- работу на слабых устройствах.

## 1. SSR, SSG и ISR

Next.js поддерживает несколько стратегий:

| Стратегия | Что дает |
| --- | --- |
| SSR | HTML создается на сервере под запрос |
| SSG | HTML создается заранее на build |
| ISR | Страница статична, но периодически обновляется |

Обычное SPA обычно рендерит основной контент в браузере, а Next.js может подготовить его заранее или на сервере.

## 2. Server Components

Server Components не отправляют свой код в браузер как интерактивный JS.

```tsx
// Server Component
export default async function ProductsPage() {
  const products = await getProducts()
  return <ProductsList products={products} />
}
```

Если компонент не использует `useState`, `useEffect`, обработчики событий и browser APIs, его можно оставить серверным.

Польза:

- меньше JS-бандл;
- меньше гидратации;
- меньше нагрузки на main thread;
- безопаснее работа с секретами и базой.

## 3. Автоматический code splitting

Next.js разделяет код по route segments. Пользователь не должен скачивать весь код сайта при первом заходе.

```text
/pricing   -> код pricing
/dashboard -> код dashboard
/blog      -> код blog
```

Это особенно заметно на больших проектах.

## 4. Оптимизация изображений и шрифтов

Next.js дает специальные инструменты:

- `next/image` - размеры, lazy loading, оптимизация формата;
- `next/font` - локальная оптимизация шрифтов, меньше внешних запросов;
- preload/priority для важных ресурсов.

Это помогает LCP и CLS.

## 5. Prefetch и быстрая навигация

Компонент `Link` может заранее подгружать данные и код маршрута, когда ссылка появляется в viewport.

```tsx
import Link from 'next/link'

export function Nav() {
  return <Link href="/dashboard">Dashboard</Link>
}
```

Первый вход получает плюсы server rendering, а последующие переходы ощущаются как SPA-навигация.

## 6. Кэширование

Next.js имеет несколько уровней кеширования:

- Data Cache;
- Full Route Cache;
- Router Cache;
- request memoization;
- image cache.

Обычное SPA тоже может кешировать данные, но в Next.js многие механизмы встроены в серверную модель.

## Важный нюанс

Next.js не всегда быстрее автоматически.

Можно испортить производительность, если:

- все сделать Client Components;
- грузить основной контент в `useEffect`;
- отключить кэш без причины;
- использовать огромные библиотеки на первом экране;
- не оптимизировать изображения;
- сделать медленный backend.

## Что отвечать на собеседовании?

Next.js быстрее обычного SPA прежде всего на первом входе: он может отдавать готовый HTML через SSR, SSG или ISR, получать данные на сервере, уменьшать клиентский JS через Server Components, автоматически делить код по маршрутам и использовать встроенные оптимизации изображений, шрифтов, prefetch и кэширования. После первого входа навигация может оставаться быстрой и похожей на SPA.

## Частые ошибки

- Говорить, что Next.js всегда быстрее любого SPA.
- Объяснять ускорение только SSR.
- Забывать про Server Components и размер JS.
- Использовать `getStaticProps` как основной пример для App Router.
- Переносить SPA-паттерны с `useEffect` для всех данных в Next.js.
- Не учитывать, что медленный сервер может испортить SSR.

## Мини-шпаргалка

- SPA часто начинает с пустого HTML.
- Next.js может отдать готовый HTML.
- Server Components уменьшают JS.
- Code splitting работает по маршрутам.
- `next/image` и `next/font` помогают LCP/CLS.
- Prefetch ускоряет переходы.
- Кэширование снижает повторную работу.
