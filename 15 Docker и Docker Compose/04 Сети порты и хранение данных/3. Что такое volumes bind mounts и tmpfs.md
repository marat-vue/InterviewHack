# Что такое volumes bind mounts и tmpfs?

> [!summary]
> Docker дает несколько способов хранить данные: volumes управляются Docker и подходят для постоянных данных, bind mounts связывают папку host с container и удобны в разработке, tmpfs хранит данные в памяти и исчезает после остановки.

## Почему нужны mounts?

Файловая система container disposable. Если контейнер удалить, его writable layer исчезнет.

Для базы данных это опасно:

```text
container removed -> database files gone
```

Поэтому данные выносят во volume.

## Volume

```bash
docker volume create pgdata
docker run -v pgdata:/var/lib/postgresql/data postgres:18
```

Volume:

- управляется Docker;
- не зависит от конкретной папки проекта;
- переживает удаление container;
- хорошо подходит для database data;
- проще переносится между контейнерами.

## Bind mount

```bash
docker run -v "$(pwd)":/app node:22-alpine
```

Bind mount связывает конкретную папку host с папкой внутри container.

Удобно для:

- dev hot reload;
- локального кода;
- конфигов;
- Nginx config;
- логов в dev.

Но bind mount зависит от структуры host и может иметь проблемы с правами и производительностью.

## tmpfs

```bash
docker run --tmpfs /tmp my-app
```

`tmpfs` хранит данные в памяти host. После остановки данные исчезают.

Подходит для:

- временных файлов;
- sensitive runtime files;
- кеша, который не нужно сохранять.

## Compose пример

```yaml
services:
  api:
    build: .
    volumes:
      - .:/app
      - /app/node_modules

  db:
    image: postgres:18
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

Здесь:

- `.:/app` - bind mount для кода;
- `/app/node_modules` - anonymous volume, чтобы host не затер зависимости контейнера;
- `pgdata` - named volume для базы.

## Что выбрать?

| Задача | Лучше использовать |
| --- | --- |
| Данные PostgreSQL | Named volume |
| Код в dev | Bind mount |
| Nginx config | Bind mount |
| Временные файлы | tmpfs |
| Production persistent data | Volume или внешнее хранилище |

## Что отвечать на собеседовании?

Volumes - Docker-managed хранилища, которые переживают lifecycle контейнера и подходят для постоянных данных. Bind mounts монтируют конкретную папку host внутрь container и удобны для разработки. tmpfs хранит данные в памяти и исчезает после остановки. Для базы чаще используют named volume, для hot reload - bind mount.

## Частые ошибки

- Хранить данные базы только в container filesystem.
- Использовать bind mount для production database без причины.
- Затирать `node_modules` bind mount-ом проекта.
- Не понимать, почему volume не удалился вместе с container.
- Удалять volumes через prune без проверки.

## Мини-шпаргалка

- Volume - managed by Docker.
- Bind mount - host path -> container path.
- tmpfs - in memory.
- База данных - volume.
- Dev code - bind mount.
- Container filesystem не для важных данных.
