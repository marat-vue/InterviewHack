# Что такое test matrix и risk based testing?

> [!summary]
> Test matrix помогает явно перечислить, какие сценарии, роли, устройства, браузеры и состояния нужно проверить. Risk based testing помогает выбирать тесты не по количеству строк кода, а по вероятности и цене ошибки.

## Что такое test matrix?

Test matrix - таблица проверок.

Пример для checkout:

| Сценарий | Guest | User | Admin |
|---|---:|---:|---:|
| открыть корзину | да | да | да |
| применить промокод | да | да | нет |
| оплатить заказ | да | да | нет |
| увидеть историю заказов | нет | да | нет |

Матрица помогает увидеть пропущенные состояния.

## Еще пример

| Состояние API | UI |
|---|---|
| loading | skeleton |
| success with data | list |
| success empty | empty state |
| 401 | login required |
| 403 | no permissions |
| 500 | retry/error message |

## Risk based testing

Risk based testing отвечает:

```text
Что вероятнее сломается и что дороже всего сломать?
```

Высокий риск:

- платежи;
- auth;
- permissions;
- персональные данные;
- сложные формы;
- миграции БД;
- интеграции с внешними сервисами.

## Как использовать на практике?

1. Составь список critical flows.
2. Выпиши роли и состояния.
3. Раздели checks по уровням: unit, component, integration, e2e.
4. Покрой дорогие ошибки в первую очередь.
5. Добавляй регрессионные тесты после багов.

## Мини-шпаргалка

- Test matrix показывает, что именно проверяется.
- Risk based testing фокусируется на цене ошибки.
- Не все сценарии равны по важности.
- Роли, permissions и error states лучше выносить в матрицу.
- Матрица помогает не полагаться на память.
