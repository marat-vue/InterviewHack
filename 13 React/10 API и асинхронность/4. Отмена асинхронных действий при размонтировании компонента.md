# Отмена асинхронных действий при размонтировании компонента

> [!summary]
> Async-действия нужно отменять или корректно очищать, чтобы не получать устаревшие данные, race conditions, лишние сетевые запросы, утечки подписок и таймеры, которые продолжают работать после ухода со страницы.

## Какие проблемы решает cleanup?

Основные проблемы:

- компонент размонтировался, а запрос все еще идет;
- пользователь быстро сменил `id`, и старый ответ пришел позже нового;
- таймер продолжает тикать;
- websocket или подписка продолжают слушать события;
- Strict Mode в development быстро выявляет отсутствие cleanup.

## Отмена fetch через AbortController

```jsx
useEffect(() => {
  const controller = new AbortController()

  async function loadUser() {
    try {
      const response = await fetch(`/api/users/${userId}`, {
        signal: controller.signal,
      })

      const data = await response.json()
      setUser(data)
    } catch (error) {
      if (error.name === 'AbortError') {
        return
      }

      setError(error)
    }
  }

  loadUser()

  return () => {
    controller.abort()
  }
}, [userId])
```

`AbortController` создает `signal`, который передается в `fetch`. При cleanup вызывается `abort()`, и запрос отменяется.

## Race condition

Сценарий:

```text
1. userId = 1 -> запрос A
2. userId = 2 -> запрос B
3. B пришел первым -> показали user 2
4. A пришел позже -> случайно перезаписал UI user 1
```

Защита:

```jsx
useEffect(() => {
  let ignore = false

  fetchUser(userId).then((user) => {
    if (!ignore) {
      setUser(user)
    }
  })

  return () => {
    ignore = true
  }
}, [userId])
```

## Таймеры

```jsx
useEffect(() => {
  const id = setInterval(() => {
    setSeconds((seconds) => seconds + 1)
  }, 1000)

  return () => clearInterval(id)
}, [])
```

## Подписки и WebSocket

```jsx
useEffect(() => {
  const socket = new WebSocket('wss://example.com')

  socket.addEventListener('message', handleMessage)

  return () => {
    socket.removeEventListener('message', handleMessage)
    socket.close()
  }
}, [])
```

## Важный нюанс React 18+

В React 18 warning про `setState` после unmount был убран, но это не значит, что cleanup больше не нужен. Race conditions, лишняя сеть и незакрытые подписки остаются реальными проблемами.

## Мини-шпаргалка

- Cleanup выполняется перед повторным эффектом и при unmount.
- `fetch` отменяют через `AbortController`.
- Таймеры очищают через `clearTimeout`/`clearInterval`.
- Подписки закрывают через `unsubscribe`, `removeEventListener`, `close`.
- Race condition часто опаснее, чем сам unmount.
