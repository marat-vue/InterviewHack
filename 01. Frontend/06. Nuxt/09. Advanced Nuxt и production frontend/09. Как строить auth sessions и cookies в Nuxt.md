# Как строить auth, sessions и cookies в Nuxt?

> [!NOTE]
> Auth в Nuxt нужно защищать с двух сторон: client route middleware улучшает UX, но настоящая защита должна быть на server routes. Для cookie-based sessions удобно использовать `nuxt-auth-utils` или полноценный auth provider.

## Какие есть варианты auth?

| Вариант | Когда подходит |
| --- | --- |
| `nuxt-auth-utils` | Full-stack Nuxt, sealed cookie session, простой session auth. |
| Better Auth | Более богатые auth scenarios, adapters, providers, roles. |
| External backend auth | Nuxt как frontend к отдельному API. |
| OAuth/OIDC provider | Enterprise login, social login, SSO. |
| JWT in memory + refresh cookie | SPA-like frontend с отдельным API. |

## Установка `nuxt-auth-utils`

```bash
npx nuxi module add auth-utils
```

`.env`:

```env
NUXT_SESSION_PASSWORD=a-random-password-with-at-least-32-characters
```

Пароль нужен для sealed cookies. В production это должен быть настоящий secret из secret manager/CI variables.

## Login API route

`server/api/login.post.ts`:

```ts
import { z } from 'zod'

const loginSchema = z.object({
  email: z.email(),
  password: z.string().min(8)
})

export default defineEventHandler(async (event) => {
  const body = await readValidatedBody(event, loginSchema.parse)

  const user = await findUserByEmail(body.email)

  if (!user || !await verifyPassword(user, body.password)) {
    throw createError({
      statusCode: 401,
      statusMessage: 'Bad credentials'
    })
  }

  await setUserSession(event, {
    user: {
      id: user.id,
      email: user.email,
      name: user.name
    }
  })

  return { ok: true }
})
```

## Login page

`app/pages/login.vue`:

```vue
<script setup lang="ts">
const { fetch: refreshSession, loggedIn } = useUserSession()

const form = reactive({
  email: '',
  password: ''
})

const errorMessage = ref('')

async function login() {
  errorMessage.value = ''

  try {
    await $fetch('/api/login', {
      method: 'POST',
      body: form
    })

    await refreshSession()
    await navigateTo('/dashboard')
  } catch {
    errorMessage.value = 'Неверная почта или пароль'
  }
}

watchEffect(() => {
  if (loggedIn.value) {
    navigateTo('/dashboard')
  }
})
</script>

<template>
  <form @submit.prevent="login">
    <input v-model="form.email" type="email" autocomplete="email">
    <input v-model="form.password" type="password" autocomplete="current-password">
    <p v-if="errorMessage">{{ errorMessage }}</p>
    <button type="submit">Войти</button>
  </form>
</template>
```

## Protect app routes

`app/middleware/authenticated.ts`:

```ts
export default defineNuxtRouteMiddleware(() => {
  const { loggedIn } = useUserSession()

  if (!loggedIn.value) {
    return navigateTo('/login')
  }
})
```

Page:

```vue
<script setup lang="ts">
definePageMeta({
  middleware: ['authenticated']
})
</script>
```

Это защита UX. Она не заменяет server-side authorization.

## Protect server routes

`server/api/me.get.ts`:

```ts
export default defineEventHandler(async (event) => {
  const session = await requireUserSession(event)

  return {
    user: session.user
  }
})
```

`server/api/admin/users.get.ts`:

```ts
export default defineEventHandler(async (event) => {
  const session = await requireUserSession(event)

  if (session.user.role !== 'admin') {
    throw createError({
      statusCode: 403,
      statusMessage: 'Forbidden'
    })
  }

  return await listUsers()
})
```

## Logout

```vue
<script setup lang="ts">
const { clear } = useUserSession()

async function logout() {
  await clear()
  await navigateTo('/login')
}
</script>

<template>
  <button @click="logout">
    Выйти
  </button>
</template>
```

## Cookies и безопасность

Для session cookies важны:

- `httpOnly`;
- `secure` в HTTPS;
- `sameSite`;
- expiration;
- rotation;
- CSRF strategy;
- secret rotation policy.

Если используешь bearer tokens в browser storage, понимай риски XSS. Для SSR Nuxt чаще удобнее httpOnly cookie session.

## Что отвечать на собеседовании?

В Nuxt auth состоит из client UX-защиты и server-side защиты. Route middleware может редиректить гостя с `/dashboard`, но API routes обязательно должны проверять session на сервере. `nuxt-auth-utils` хранит session в sealed cookies и дает helpers вроде `setUserSession`, `useUserSession`, `requireUserSession`. Секрет session задается через `NUXT_SESSION_PASSWORD`.

## Частые ошибки

- Защищать только page middleware и оставлять `/api/*` открытым.
- Класть JWT в `localStorage` без понимания XSS-рисков.
- Делать `NUXT_SESSION_PASSWORD` коротким или публичным.
- Хранить password hash/secret в session payload.
- Не различать 401 и 403.
- Не обновлять client session после login/logout.

## Мини-шпаргалка

- Client route guard: `defineNuxtRouteMiddleware`.
- Server guard: `requireUserSession`.
- Login: `setUserSession`.
- Client state: `useUserSession`.
- Secret: `NUXT_SESSION_PASSWORD`.
- API всегда защищай на server side.
