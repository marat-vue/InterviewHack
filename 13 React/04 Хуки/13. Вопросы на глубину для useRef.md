# Какие вопросы на глубину задают про useRef?

> [!summary]
> На собеседованиях про `useRef` часто проверяют разницу между ref и state, момент заполнения `ref.current`, работу с DOM, stale closures и понимание того, почему изменение ref не вызывает render.

## Почему изменение ref не обновляет UI?

```jsx
function Counter() {
  const countRef = useRef(0)

  return (
    <button onClick={() => countRef.current++}>
      {countRef.current}
    </button>
  )
}
```

Клик изменит `countRef.current`, но текст на кнопке не обновится. React не отслеживает изменения ref.

Если значение нужно показывать, нужен state:

```jsx
const [count, setCount] = useState(0)
```

## Когда ref.current получает DOM-элемент?

После commit:

```jsx
const inputRef = useRef(null)

return <input ref={inputRef} />
```

До первого commit `inputRef.current` равен `null`. После монтирования React присваивает DOM-узел. При размонтировании вернет `null`.

## Можно ли использовать ref против stale closure?

Иногда ref используют, чтобы хранить последнее значение:

```jsx
const latestValueRef = useRef(value)

useEffect(() => {
  latestValueRef.current = value
}, [value])
```

Потом async callback может читать `latestValueRef.current`. Это escape hatch, а не замена нормальным dependencies.

## Чем ref отличается от переменной?

Обычная переменная сбрасывается при каждом render:

```jsx
let timeoutId
```

Ref сохраняется:

```jsx
const timeoutRef = useRef(null)
```

Поэтому ref удобен для timer id, previous value и DOM nodes.

## Можно ли передать ref в свой компонент?

В React 19 ref можно передавать как prop в компоненты, которые это поддерживают. В legacy-коде и библиотеках часто встречается `forwardRef`, который явно пробрасывает ref внутрь.

## Мини-шпаргалка

- Ref сохраняется между render.
- Изменение ref не вызывает render.
- DOM ref заполняется после commit.
- Ref помогает хранить mutable values.
- Для отображаемых данных используй state, а не ref.
