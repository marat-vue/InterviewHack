# Как настроить runtimeConfig, env и секреты в Nitro?

> [!NOTE]
> `runtimeConfig` - это способ задать конфигурацию, которую можно менять через переменные окружения без изменения кода. В Nitro env keys мапятся через префикс `NITRO_`, а в Nuxt runtime config обычно задается в `nuxt.config.ts`.

## Зачем нужен runtimeConfig?

Runtime config нужен для значений, которые отличаются между окружениями:

- database URL;
- API tokens;
- feature flags;
- OAuth credentials;
- Better Auth secret;
- public API base URL;
- Redis URL;
- payment provider keys.

Не стоит hardcode-ить такие значения в route handler.

## Standalone Nitro config

```ts
// nitro.config.ts
import { defineConfig } from 'nitro';

export default defineConfig({
  runtimeConfig: {
    databaseUrl: '',
    authSecret: '',
    publicApiBase: 'http://localhost:3000',
  },
});
```

Чтение:

```ts
import { useRuntimeConfig } from 'nitro/runtime-config';

export default defineHandler(() => {
  const config = useRuntimeConfig();

  return {
    apiBase: config.publicApiBase,
  };
});
```

## Env mapping

Ключи из `runtimeConfig` можно переопределять env-переменными:

```bash
NITRO_DATABASE_URL="postgresql://..."
NITRO_AUTH_SECRET="..."
NITRO_PUBLIC_API_BASE="https://api.example.com"
```

Nested config:

```ts
export default defineConfig({
  runtimeConfig: {
    database: {
      host: 'localhost',
      port: 5432,
    },
  },
});
```

Env:

```bash
NITRO_DATABASE_HOST="db.example.com"
NITRO_DATABASE_PORT="5432"
```

Важно: env может переопределить только ключи, которые уже объявлены в config. Нельзя добавить новый ключ только через env.

## Nuxt runtime config

В Nuxt:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    authSecret: '',
    databaseUrl: '',
    public: {
      apiBase: '/api',
    },
  },
});
```

В server code:

```ts
export default defineEventHandler(() => {
  const config = useRuntimeConfig();

  return {
    apiBase: config.public.apiBase,
  };
});
```

`runtimeConfig.public` доступен и клиенту, поэтому туда нельзя класть секреты.

## Что можно хранить в runtimeConfig?

Можно:

- строки;
- числа;
- boolean;
- plain objects;
- arrays.

Нельзя:

- class instances;
- functions;
- database clients;
- SDK instances;
- secrets в public config.

Runtime config должен быть serializable.

## Где хранить `.env`?

Обычно:

```txt
.env
.env.example
```

`.env` не коммитят, `.env.example` коммитят:

```bash
DATABASE_URL=""
BETTER_AUTH_SECRET=""
BETTER_AUTH_URL="http://localhost:3000"
NITRO_PRESET="node_server"
```

## Мини-шпаргалка

- `runtimeConfig` - конфиг, меняемый через env.
- Nitro env prefix - `NITRO_`.
- Nested keys становятся `NITRO_DATABASE_HOST`.
- Объявляй все ключи в config заранее.
- В Nuxt secrets только вне `runtimeConfig.public`.
- Runtime config должен быть serializable.
