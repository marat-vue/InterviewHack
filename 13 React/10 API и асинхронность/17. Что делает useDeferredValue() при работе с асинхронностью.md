# Что делает useDeferredValue() при работе с асинхронностью?

> [!summary]
> `useDeferredValue` возвращает отложенную версию значения. React сначала обновляет срочный UI, например input, а тяжелую часть интерфейса, зависящую от deferred value, может перерендерить позже и прервать при новых изменениях.

## Базовый пример

```jsx
function SearchPage({ products }) {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)

  const filteredProducts = useMemo(() => {
    return products.filter((product) => product.title.includes(deferredQuery))
  }, [products, deferredQuery])

  return (
    <>
      <input value={query} onChange={(event) => setQuery(event.target.value)} />
      <ProductList products={filteredProducts} />
    </>
  )
}
```

`query` обновляет input сразу. `deferredQuery` может отставать, чтобы тяжелый список не блокировал ввод.

## Как показать, что список устарел?

```jsx
const isStale = query !== deferredQuery

return (
  <div style={{ opacity: isStale ? 0.5 : 1 }}>
    <SearchResults query={deferredQuery} />
  </div>
)
```

Пользователь видит старые результаты, пока новые готовятся.

## useDeferredValue и Suspense

`useDeferredValue` интегрирован с Suspense: если background render с новым значением suspends, React может продолжить показывать старый UI вместо резкого fallback.

Это полезно для поиска, где новые данные могут догружаться.

```jsx
function SearchPage() {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)

  return (
    <>
      <SearchInput value={query} onChange={setQuery} />
      <Suspense fallback={<ResultsSkeleton />}>
        <Results query={deferredQuery} />
      </Suspense>
    </>
  )
}
```

## Чем отличается от debounce?

Debounce ждет фиксированную паузу по времени.

`useDeferredValue` не задает задержку в миллисекундах. React планирует работу по приоритетам и может прерывать background render.

## useDeferredValue vs startTransition

| API | Что откладывает |
|---|---|
| `useDeferredValue(value)` | Использование значения |
| `startTransition(() => setState())` | Обновление state |

Если ты контролируешь место `setState`, удобно использовать transition. Если значение пришло сверху через props, часто удобнее `useDeferredValue`.

## Мини-шпаргалка

- `useDeferredValue` откладывает значение.
- Срочный UI остается отзывчивым.
- Старое значение может отображаться, пока новое считается.
- Это не debounce и не фиксированная задержка.
- Хорошо подходит для поиска, фильтрации и тяжелых списков.
