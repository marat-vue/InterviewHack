# Как key влияет на рендер?

> [!summary]
> `key` помогает React сопоставлять элементы списка между render. Он влияет не только на производительность, но и на сохранение или сброс локального состояния дочерних компонентов.

## Базовый пример

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo) => (
        <TodoItem key={todo.id} todo={todo} />
      ))}
    </ul>
  )
}
```

`todo.id` должен быть стабильным идентификатором задачи.

## Что делает key?

Key отвечает на вопрос:

```text
Какой новый элемент соответствует какому старому элементу?
```

Это особенно важно при:

- добавлении в начало списка;
- удалении из середины;
- сортировке;
- фильтрации;
- drag-and-drop;
- input внутри списка.

## Почему index опасен?

```jsx
{todos.map((todo, index) => (
  <TodoItem key={index} todo={todo} />
))}
```

Если порядок меняется, индексы перестают соответствовать тем же сущностям. React может сохранить state не у того элемента.

## Key может сбросить state

Иногда это полезно:

```jsx
<ProfileForm key={userId} userId={userId} />
```

При смене `userId` React создаст новый экземпляр формы и сбросит локальное состояние.

## Мини-шпаргалка

- Key нужен для сопоставления элементов списка.
- Key должен быть стабильным.
- Key уникален среди соседей.
- Index подходит только для статичных списков.
- Изменение key может сбросить state компонента.
