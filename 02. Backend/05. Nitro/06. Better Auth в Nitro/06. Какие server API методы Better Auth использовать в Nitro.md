# Какие server API методы Better Auth использовать в Nitro?

> [!NOTE]
> На сервере Nitro используют `auth.api.*`. Самый частый метод - `auth.api.getSession({ headers })`, потому что protected routes должны узнать текущего пользователя по cookies/session headers.

## `auth.api.getSession`

```ts
export default defineHandler(async (event) => {
  const session = await auth.api.getSession({
    headers: event.req.headers,
  });

  return {
    session,
  };
});
```

Используется для:

- `/api/me`;
- protected routes;
- authorization checks;
- SSR/server-side user lookup.

## `auth.api.signInEmail`

Server-side sign in:

```ts
const result = await auth.api.signInEmail({
  body: {
    email,
    password,
    rememberMe: true,
  },
  headers: event.req.headers,
});
```

В Nitro чаще sign in вызывают через Better Auth client, но server API полезен для server actions, custom flows или интеграций.

## `auth.api.signOut`

```ts
await auth.api.signOut({
  headers: event.req.headers,
});
```

Чаще client вызывает `authClient.signOut`, но server route тоже может завершить session.

## Server API vs client API

| Где код | Что использовать |
|---|---|
| Browser component | `authClient.*` |
| Vue/Nuxt composable на клиенте | `authClient.*` |
| Nitro server route | `auth.api.*` |
| Middleware/guard | `auth.api.getSession` |
| Better Auth catch-all route | `auth.handler(...)` |

Не вызывай browser client API как основной auth layer внутри server routes.

## `asResponse`

Некоторые server API calls могут вернуть `Response`, если нужно вручную прокинуть cookies/headers:

```ts
const response = await auth.api.signInEmail({
  body: {
    email,
    password,
  },
  asResponse: true,
});

return response;
```

В Nitro чаще проще пользоваться стандартным mounted handler, который сам управляет response.

## `headers`

Для session-based flow важно передавать headers:

```ts
headers: event.req.headers
```

Без cookies/session headers Better Auth не поймет, кто текущий пользователь.

## Custom server method wrapper

```ts
// server/utils/require-auth.ts
import { createError, type H3Event } from 'h3';
import { auth } from './auth';

export async function getAuthSession(event: H3Event) {
  return auth.api.getSession({
    headers: event.req.headers,
  });
}

export async function requireAuth(event: H3Event) {
  const session = await getAuthSession(event);

  if (!session) {
    throw createError({
      statusCode: 401,
      statusMessage: 'Unauthorized',
    });
  }

  return session;
}
```

## Мини-шпаргалка

- Server side: `auth.api.*`.
- Protected routes: `auth.api.getSession({ headers })`.
- `headers` нужны для cookies/session.
- Sign in/out обычно удобнее через mounted Better Auth endpoints/client.
- `asResponse` полезен, когда нужно вернуть готовый `Response`.
- Для Nitro routes сделай `requireAuth(event)` helper.
