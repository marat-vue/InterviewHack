# Что такое Error Boundary?

> [!summary]
> Error Boundary - это React-компонент, который ловит ошибки render в дочернем дереве, логирует их и показывает fallback UI вместо сломанной части интерфейса. В классическом React Error Boundary реализуется классовым компонентом через `getDerivedStateFromError` и `componentDidCatch`.

## Минимальная реализация

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false }

  static getDerivedStateFromError(error) {
    return { hasError: true }
  }

  componentDidCatch(error, info) {
    logError(error, info)
  }

  render() {
    if (this.state.hasError) {
      return <h2>Something went wrong</h2>
    }

    return this.props.children
  }
}
```

Использование:

```jsx
<ErrorBoundary>
  <UserWidget />
</ErrorBoundary>
```

## За что отвечают методы?

`static getDerivedStateFromError(error)`:

- вызывается после ошибки в дочернем дереве;
- возвращает новый state;
- нужен, чтобы показать fallback UI.

`componentDidCatch(error, info)`:

- вызывается после ошибки;
- подходит для логирования;
- получает `componentStack` внутри `info`.

## Что ловит Error Boundary?

Ловит ошибки:

- во время render;
- в constructor;
- в lifecycle methods дочерних class components;
- в render phase hooks.

Не ловит:

- event handlers;
- async callbacks;
- `setTimeout`;
- обычный `fetch`;
- ошибки внутри самой boundary;
- ошибки server-side rendering в классической модели.

## Где ставить boundaries?

```jsx
function App() {
  return (
    <>
      <Header />

      <ErrorBoundary>
        <MainRoutes />
      </ErrorBoundary>

      <ErrorBoundary>
        <SupportChat />
      </ErrorBoundary>
    </>
  )
}
```

Границы ставят вокруг смысловых независимых областей, чтобы падение одного виджета не заменяло весь продукт белым экраном.

## Функциональный компонент может быть Error Boundary?

Встроенного hook API для Error Boundary в React нет. На практике используют:

- class component;
- библиотеку `react-error-boundary`;
- route-level error boundaries во фреймворках/роутерах.

## Мини-шпаргалка

- Error Boundary ловит render errors ниже себя.
- Для fallback нужен `getDerivedStateFromError`.
- Для логирования нужен `componentDidCatch`.
- События и async-код нужно ловить отдельно.
- Boundaries лучше ставить вокруг независимых частей UI.
