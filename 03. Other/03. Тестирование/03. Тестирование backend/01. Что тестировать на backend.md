# Что тестировать на backend?

> [!summary]
> На backend тестируют бизнес-логику, HTTP endpoints, валидацию, авторизацию, работу с базой, транзакции, ошибки и интеграции с внешними сервисами. Главная цель - убедиться, что система правильно обрабатывает данные и защищает инварианты.

## Что важнее всего?

Backend часто отвечает за:

- сохранность данных;
- права доступа;
- бизнес-правила;
- транзакции;
- интеграции;
- безопасность;
- корректные HTTP responses.

Поэтому тесты должны проверять не только "вернулся статус 200", но и состояние системы после действия.

## Что покрывать тестами?

| Область | Пример проверки |
|---|---|
| services | расчет цены, создание заказа |
| controllers/routes | статус, body, headers |
| validation | неверный email дает `400` |
| auth | без токена нельзя получить данные |
| permissions | обычный user не может удалить чужой ресурс |
| database | запись создана, rollback сработал |
| external services | платеж не прошел, email не отправился |

## Пример backend-сценария

Сценарий: пользователь создает заказ.

Проверки:

- пользователь существует;
- товары существуют;
- итоговая цена рассчитана правильно;
- заказ сохранен;
- items сохранены;
- при ошибке оплаты заказ не считается оплаченным;
- endpoint возвращает правильный status code.

## Unit или integration?

Для чистой бизнес-логики подойдет unit test:

```ts
expect(order.calculateTotal()).toBe(2500);
```

Для проверки связи endpoint + validation + database лучше integration test:

```ts
await request(app.getHttpServer())
  .post('/orders')
  .send({ items: [{ productId: 1, quantity: 2 }] })
  .expect(201);
```

## Мини-шпаргалка

- Backend-тесты защищают данные, правила и безопасность.
- Services удобно проверять unit-тестами.
- Endpoints часто проверяют integration-тестами.
- Auth, permissions и validation обязательно покрывать.
- Важен не только response, но и состояние базы.
