# Какие задачи лучше решать клиентскими компонентами?

> [!summary]
> Клиентские компоненты нужны для всего, что требует браузера: состояние UI, эффекты, обработчики событий, формы, анимации, browser APIs, client-side state managers и интерактивные библиотеки. В Next.js их стоит держать маленькими, чтобы не увеличивать client bundle.

## Главный принцип

Если компоненту нужен браузер, ему нужен Client Component.

```tsx
'use client'

import { useState } from 'react'

export function LikeButton() {
  const [liked, setLiked] = useState(false)

  return (
    <button onClick={() => setLiked((value) => !value)}>
      {liked ? 'Liked' : 'Like'}
    </button>
  )
}
```

## Какие задачи решать на клиенте?

| Задача | Почему нужен клиент |
|---|---|
| `useState`, `useReducer` | состояние меняется в браузере |
| `useEffect` | эффект выполняется после mount |
| `onClick`, `onChange` | обработчики событий пользователя |
| `window`, `document` | browser APIs |
| localStorage/sessionStorage | доступны только в браузере |
| animations | часто завязаны на interaction |
| Zustand/Redux UI-state | client-side state |
| формы с мгновенной реакцией | input state, validation UX |

## Хороший паттерн: маленький client island

```tsx
export default async function ProductPage() {
  const product = await getProduct()

  return (
    <article>
      <h1>{product.title}</h1>
      <p>{product.description}</p>
      <AddToCartButton productId={product.id} />
    </article>
  )
}
```

`ProductPage` остается Server Component, а на клиент уезжает только кнопка.

## Когда не нужен Client Component?

Не ставь `'use client'`, если компонент:

- просто выводит текст;
- рендерит список;
- читает данные на сервере;
- строит SEO-контент;
- не имеет событий;
- не использует browser APIs.

## Что отвечать на собеседовании?

Client Components нужны для интерактивности и browser-only логики. Их используют для state, effects, event handlers, forms, animations и client libraries. Хорошая практика в Next.js - оставлять страницу и данные на сервере, а клиентскими делать только небольшие интерактивные части.

## Частые ошибки

- Делать всю страницу Client Component ради одной кнопки.
- Читать важный SEO-контент только в `useEffect`.
- Импортировать server-only код в Client Component.
- Передавать несериализуемые props.
- Ставить `'use client'` на root layout без необходимости.

## Мини-шпаргалка

- Нужен `useState` - нужен Client Component.
- Нужен `onClick` - нужен Client Component.
- Нужен `window` - нужен Client Component.
- Client boundary держи ниже.
- Данные и SEO-контент лучше держать на сервере.
