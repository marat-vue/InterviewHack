# Что такое Single Executable Applications в Node.js?

> [!NOTE]
> Single Executable Applications, или SEA, позволяют упаковать Node.js-приложение в один исполняемый файл. Это удобно для CLI и internal tools, но для backend-сервисов чаще используют Docker image.

## Зачем SEA?

SEA нужен, чтобы:

- распространять CLI без установки Node.js;
- отдавать один executable пользователю;
- упростить internal tooling;
- зафиксировать runtime;
- уменьшить setup для оператора.

## Базовая идея

```txt
app.js + node binary + sea config -> executable
```

Пример config:

```json
{
  "main": "./dist/cli.js",
  "output": "./dist/my-cli",
  "assets": {
    "help.txt": "./assets/help.txt"
  }
}
```

Сборка:

```bash
node --build-sea sea-config.json
```

Детальный процесс зависит от OS: на macOS/Windows может понадобиться подпись бинарника.

## Как читать assets?

```js
import { getAsset, getAssetKeys } from 'node:sea';

console.log(getAssetKeys());

const help = getAsset('help.txt', 'utf8');
console.log(help);
```

## Когда SEA хороший выбор?

- CLI;
- миграционный tool;
- internal admin utility;
- self-contained dev tool;
- agent/daemon для controlled environment.

## Когда лучше Docker?

Для server backend обычно лучше Docker:

- проще runtime config;
- проще networking;
- проще observability;
- привычнее orchestration;
- легче обновлять зависимости ОС;
- не нужно думать о binary signing.

## Мини-шпаргалка

- SEA упаковывает Node-приложение в executable.
- Хорошо для CLI/tools.
- `node:sea` читает bundled assets.
- Для web backend чаще Docker.
- API находится в active development, проверяй версию Node.js.
