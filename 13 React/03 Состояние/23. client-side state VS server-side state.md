# Чем client-side state отличается от server-side state?

> [!summary]
> Client-side state - состояние, которым владеет интерфейс в браузере. Server-side state - данные, источником истины для которых является сервер: пользователь, товары, заказы, статьи. Их лучше обрабатывать по-разному.

## Client-side state

Примеры:

- открыт modal;
- текущая вкладка;
- значение input;
- тема;
- фильтр в интерфейсе;
- выбранный элемент на странице.

Такое состояние обычно хранится через:

- `useState`;
- `useReducer`;
- Context;
- Zustand/Redux, если нужно глобально.

## Server-side state

Примеры:

- список товаров из API;
- профиль пользователя;
- заказы;
- комментарии;
- настройки из backend;
- результаты поиска.

Особенности server state:

- нужно загружать;
- нужно кешировать;
- может устареть;
- может обновиться на сервере без ведома клиента;
- есть loading/error состояния;
- нужна инвалидация кеша;
- возможны optimistic updates.

## Почему не стоит все хранить в useState?

```jsx
const [products, setProducts] = useState([])
const [isLoading, setIsLoading] = useState(false)
const [error, setError] = useState(null)
```

Для одного запроса это нормально. Но в большом приложении появляются:

- повторные запросы;
- кеш;
- stale data;
- refetch;
- синхронизация вкладок;
- pagination;
- optimistic updates.

Для server state часто используют TanStack Query, SWR или возможности фреймворка.

## Как отличить?

Задай вопрос:

```text
Кто владеет истинным значением: браузерный UI или сервер?
```

Если сервер - это server state. Если интерфейс - client state.

## Мини-шпаргалка

- Client state принадлежит UI.
- Server state принадлежит backend.
- Server state нужно кешировать, обновлять и инвалидировать.
- Не смешивай UI-флаги и данные API без причины.
- Для server state часто лучше использовать отдельную библиотеку.
