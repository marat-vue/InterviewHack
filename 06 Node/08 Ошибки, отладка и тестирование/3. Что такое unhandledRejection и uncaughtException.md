# Что такое unhandledRejection и uncaughtException?

> [!summary]
> `unhandledRejection` возникает, когда Promise отклонен и ошибка не обработана. `uncaughtException` возникает, когда исключение дошло до верхнего уровня и не было поймано.

## unhandledRejection

```js
Promise.reject(new Error('Промис упал'));

process.on('unhandledRejection', (reason) => {
  console.error('Необработанный Promise rejection:', reason);
});
```

Такое часто случается, если забыть `await` или `.catch()`.

```js
async function save() {
  throw new Error('DB error');
}

save(); // нет await и нет catch
```

## uncaughtException

```js
setTimeout(() => {
  throw new Error('Не поймано');
}, 0);

process.on('uncaughtException', (error) => {
  console.error('Необработанное исключение:', error);
});
```

## Важный production-подход

Эти события не должны быть способом "продолжить как ни в чем не бывало". После необработанной ошибки состояние приложения может быть повреждено.

Обычно делают так:

1. Логируют ошибку.
2. Останавливают прием новых запросов.
3. Закрывают соединения.
4. Завершают процесс.
5. Позволяют process manager перезапустить приложение.

## Мини-шпаргалка

- `unhandledRejection` - Promise-ошибка без обработки.
- `uncaughtException` - исключение без `try/catch`.
- Не используй их как обычную бизнес-логику.
- В production после таких ошибок часто нужен graceful shutdown.
- Лучше предотвращать их через `await`, `.catch()` и централизованную обработку ошибок.
