# Что такое hydration в контексте SSR?

> [!summary]
> Hydration - это процесс, при котором React подключается к HTML, уже сгенерированному на сервере, сопоставляет его с деревом компонентов и добавляет интерактивность: обработчики событий, state и effects.

## Зачем нужна hydration?

После SSR браузер уже видит HTML:

```html
<button>Like</button>
```

Но кнопка еще не работает как React-компонент. JavaScript должен загрузиться, и React должен подключить логику.

```jsx
import { hydrateRoot } from 'react-dom/client'

hydrateRoot(document.getElementById('root'), <App />)
```

## Что делает React?

```text
1. Берет существующий server HTML
2. Строит React tree на клиенте
3. Сопоставляет tree с DOM
4. Подключает event handlers
5. Запускает effects после commit
6. Делает UI интерактивным
```

## hydrateRoot vs createRoot

CSR:

```jsx
createRoot(document.getElementById('root')).render(<App />)
```

React создает DOM с нуля.

SSR:

```jsx
hydrateRoot(document.getElementById('root'), <App />)
```

React ожидает, что DOM уже содержит HTML, который совпадает с первым render.

## Hydration mismatch

Проблема:

```jsx
function Clock() {
  return <p>{new Date().toLocaleTimeString()}</p>
}
```

Сервер и клиент могут отрендерить разный текст. React выдаст warning или ошибку hydration.

## Пока hydration не закончилась

Пользователь может видеть страницу, но интерактивность еще не готова:

```text
HTML visible != React interactive
```

Поэтому важны:

- размер client bundle;
- разделение client components;
- lazy loading;
- streaming;
- selective hydration во фреймворках;
- избегание тяжелого JS на первом экране.

## Мини-шпаргалка

- SSR показывает HTML.
- Hydration делает HTML интерактивным.
- Для hydration используют `hydrateRoot`.
- Первый клиентский render должен совпасть с серверным HTML.
- Hydration cost влияет на интерактивность.
