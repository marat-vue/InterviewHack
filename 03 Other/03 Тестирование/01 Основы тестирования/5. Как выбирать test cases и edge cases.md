# Как выбирать test cases и edge cases?

> [!summary]
> Test case - это конкретный сценарий проверки. Хороший набор тестов покрывает обычный путь, важные альтернативы, ошибки, границы и регрессии, которые уже случались или могут дорого стоить.

## Что такое test case?

Test case отвечает на вопрос: "При таких входных данных и таком действии что должно произойти?"

Пример:

```ts
test('returns free shipping for order from 5000', () => {
  expect(getShippingPrice({ total: 5000 })).toBe(0);
});
```

## Какие сценарии выбирать?

Обычно полезно покрывать:

- happy path;
- empty state;
- invalid input;
- boundary values;
- permissions;
- network errors;
- loading state;
- race conditions;
- регрессии после найденных багов.

## Что такое edge case?

Edge case - это граничная или необычная ситуация, где код часто ломается.

Примеры:

```ts
expect(calculateDiscount(0)).toBe(0);
expect(calculateDiscount(-100)).toThrow();
expect(calculateDiscount(10_000_000)).toBeLessThanOrEqual(10_000_000);
```

Для frontend:

- пустой список;
- длинный текст;
- disabled button;
- двойной клик;
- медленный API;
- ошибка сервера.

Для backend:

- пользователь не найден;
- нет прав;
- duplicate key;
- истекший токен;
- transaction rollback;
- внешний сервис недоступен.

## Как не переборщить?

Не надо писать тест на каждую строку. Лучше спросить:

- что сломает пользователя?
- что сломает деньги, безопасность или данные?
- где много условий?
- где код часто меняется?
- какие баги уже были?

## Мини-шпаргалка

- Happy path проверяет основной успешный сценарий.
- Edge cases проверяют границы и редкие ситуации.
- Ошибки и permissions почти всегда стоит тестировать.
- Регрессионный тест пишут после найденного бага.
- Тесты должны покрывать риск, а не просто строки кода.
