# Как работают Lists в Redis?

> [!NOTE]
> List - упорядоченная последовательность строк. Lists хорошо подходят для простых очередей, recent activity, bounded logs и stack/queue операций.

## Когда использовать List?

List подходит для:

- простой queue;
- recent events;
- activity feed limited size;
- background jobs без сложной надежности;
- stack/LIFO;
- FIFO buffer.

## Основные команды

```redis
LPUSH queue:emails job-1
RPUSH queue:emails job-2
LPOP queue:emails
RPOP queue:emails
```

FIFO очередь:

```redis
LPUSH queue:emails job-1
RPOP queue:emails
```

или:

```redis
RPUSH queue:emails job-1
LPOP queue:emails
```

## Blocking pop

```redis
BLPOP queue:emails 0
```

`BLPOP` ждет, пока появится элемент. Это полезно для worker-а.

Node.js:

```ts
while (true) {
  const item = await redis.blPop('queue:emails', 0);

  if (!item) {
    continue;
  }

  await processEmailJob(item.element);
}
```

## Recent activity с ограничением длины

```redis
LPUSH user:1:activity login
LTRIM user:1:activity 0 99
LRANGE user:1:activity 0 19
```

`LTRIM` оставляет только последние 100 элементов.

## Чем Lists хуже Streams для очередей?

Lists простые, но:

- нет consumer groups;
- нет встроенного pending list;
- сложнее retry;
- сложно посмотреть историю;
- нужно вручную проектировать ack/requeue.

Для надежной очереди чаще лучше Redis Streams или отдельная очередь.

## Мини-шпаргалка

- `LPUSH`/`RPUSH` - добавить.
- `LPOP`/`RPOP` - забрать.
- `BLPOP`/`BRPOP` - ждать элемент.
- `LRANGE` - range, не весь список без лимита.
- `LTRIM` - ограничить размер.
- Для надежных событий лучше Streams.
