# Какие production настройки безопасности важны для Better Auth?

> [!NOTE]
> Production auth ломается не только из-за кода, но и из-за настроек: secret, URL, cookies, CORS, trusted origins, HTTPS, rate limits, database schema, session lifetime, social callbacks и logs.

## Secret

Обязательно задай:

```bash
BETTER_AUTH_SECRET="long-random-secret"
```

Сгенерировать:

```bash
npx auth@latest secret
```

Secret нельзя:

- коммитить;
- показывать в logs;
- класть в public runtime config;
- менять без понимания влияния на sessions/tokens.

## URL

```bash
BETTER_AUTH_URL="https://app.example.com"
```

Неверный URL вызывает проблемы с:

- OAuth callback;
- cookies;
- redirects;
- session validation.

## HTTPS

Production auth должен работать через HTTPS. Cookies с `Secure` не будут корректно работать по plain HTTP.

## Cookies

Проверь:

- `HttpOnly`;
- `Secure`;
- `SameSite`;
- domain;
- path;
- max age;
- cross-subdomain behavior.

Если frontend/backend cross-origin:

- CORS `credentials: true`;
- frontend fetch credentials;
- trusted origins;
- `SameSite=None` + `Secure=true`, если нужно third-party/cross-site cookies.

## Rate limits

Rate limit нужен на:

- sign in;
- sign up;
- password reset;
- email verification resend;
- OTP send;
- magic link;
- social callback abuse;
- admin endpoints.

Nitro routeRules не заменяют полноценный rate limiter. Используй Redis/storage-aware limiter, если несколько инстансов.

## Database schema

После изменения Better Auth config/plugins:

```bash
npx auth@latest generate --config server/utils/auth.ts
npx prisma migrate dev --name update_auth
```

Production:

```bash
npx prisma migrate deploy
```

Не запускай `db push` в production без осознанной причины.

## Error handling

Не раскрывай:

- существует ли email;
- stack traces;
- OAuth provider secrets;
- raw database errors;
- token contents.

Пользователю:

```txt
Invalid email or password
```

В logs:

```txt
requestId, endpoint, status, auth error code
```

без секретов.

## Session settings

Проверь:

- session expiration;
- refresh behavior;
- revoke on password change;
- revoke all sessions;
- session list для пользователя;
- cookie cache, если включаешь;
- secondary storage/stateless sessions, если используешь.

## Social providers

Проверь:

- redirect/callback URLs;
- production client id/secret;
- allowed origins;
- scopes;
- account linking behavior;
- email verified trust;
- provider-specific risks.

## Мини-шпаргалка

- `BETTER_AUTH_SECRET` обязателен.
- `BETTER_AUTH_URL` должен быть production URL.
- HTTPS обязателен.
- Cookies, CORS и trusted origins настраиваются вместе.
- Auth endpoints требуют rate limit.
- Prisma schema обновляется через `auth generate` + Prisma migrations.
- Не раскрывай raw auth errors пользователю.
- Social provider callbacks должны совпадать с production domain.
