# Как валидировать body, query и params через H3 и Zod?

> [!NOTE]
> H3 дает validated utilities: `readValidatedBody`, `getValidatedQuery`, `getValidatedRouterParams`. Их можно использовать с функцией-валидатором или со schema library вроде Zod, Valibot и других Standard Schema-compatible библиотек.

## Зачем нужна validation?

Request всегда приходит снаружи, поэтому TypeScript не защищает runtime.

Плохой вариант:

```ts
const body = await readBody(event);
await prisma.user.create({
  data: {
    email: body.email,
  },
});
```

Проблемы:

- `email` может быть не строкой;
- поле может отсутствовать;
- body может быть массивом;
- лишние поля могут попасть в бизнес-логику;
- ошибки БД станут validation errors для пользователя.

## `readValidatedBody`

```ts
import { readValidatedBody } from 'h3';
import { z } from 'zod';

const createUserSchema = z.object({
  email: z.string().email(),
  name: z.string().min(1).max(100),
});

export default defineHandler(async (event) => {
  const body = await readValidatedBody(event, createUserSchema);

  return userService.create(body);
});
```

`body` после validation получает нормальный тип из Zod schema.

## `getValidatedQuery`

```ts
import { getValidatedQuery } from 'h3';
import { z } from 'zod';

const listUsersQuerySchema = z.object({
  page: z.coerce.number().int().positive().default(1),
  limit: z.coerce.number().int().min(1).max(100).default(20),
  search: z.string().trim().optional(),
});

export default defineHandler(async (event) => {
  const query = await getValidatedQuery(event, listUsersQuerySchema);

  return userService.findMany(query);
});
```

`z.coerce.number()` полезен, потому что query params приходят строками.

## `getValidatedRouterParams`

```ts
import { getValidatedRouterParams } from 'h3';
import { z } from 'zod';

const paramsSchema = z.object({
  id: z.string().uuid(),
});

export default defineHandler(async (event) => {
  const { id } = await getValidatedRouterParams(event, paramsSchema);

  return userService.findById(id);
});
```

## Валидация без Zod

Можно передать функцию:

```ts
const query = await getValidatedQuery(event, (data) => {
  return typeof data === 'object' && data !== null && 'page' in data;
});
```

Но для реального проекта schema library обычно лучше:

- типы выводятся автоматически;
- ошибки понятнее;
- проще переиспользовать schema;
- можно делать transform/coerce/default.

## Где хранить schemas?

Для небольшого endpoint:

```txt
server/routes/api/users.post.ts
```

можно держать schema рядом с handler.

Для повторного использования:

```txt
server/
  schemas/
    user.ts
  routes/
    api/
      users.post.ts
```

```ts
// server/schemas/user.ts
export const createUserSchema = z.object({
  email: z.string().email(),
  name: z.string().min(1),
});
```

## Что валидировать?

В public API валидируй:

- route params;
- query params;
- request body;
- uploaded files metadata;
- enum values;
- pagination;
- sorting fields;
- filter fields;
- callback URLs;
- redirect targets.

## Мини-шпаргалка

- TypeScript не валидирует runtime input.
- `readValidatedBody` - body + validation.
- `getValidatedQuery` - query + validation.
- `getValidatedRouterParams` - params + validation.
- `z.coerce` полезен для query и form data.
- Validation лучше делать на краю системы, до service/Prisma.
