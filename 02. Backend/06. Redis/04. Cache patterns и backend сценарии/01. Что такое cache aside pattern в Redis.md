# Что такое cache-aside pattern в Redis?

> [!NOTE]
> Cache-aside - самый частый Redis cache pattern в backend. Приложение сначала ищет данные в Redis, при miss читает source of truth, кладет результат в Redis с TTL и возвращает клиенту.

## Как работает cache-aside?

```txt
Request
  -> Redis GET
  -> cache hit: return cached value
  -> cache miss: read DB/API
  -> Redis SET EX
  -> return fresh value
```

## Пример на Node.js

```ts
export async function getProduct(productId: string) {
  const key = `cache:product:${productId}`;
  const cached = await redis.get(key);

  if (cached) {
    return JSON.parse(cached);
  }

  const product = await db.product.findUnique({
    where: {
      id: productId,
    },
  });

  await redis.set(key, JSON.stringify(product), {
    EX: 60 * 5,
  });

  return product;
}
```

## Зачем TTL?

TTL нужен, чтобы:

- cache сам очищался;
- stale data не жила бесконечно;
- Redis memory не росла бесконечно;
- ошибка invalidation не превращалась в вечный баг.

## Как инвалидировать при update?

```ts
export async function updateProduct(productId: string, data: UpdateProductDto) {
  const product = await db.product.update({
    where: {
      id: productId,
    },
    data,
  });

  await redis.del(`cache:product:${productId}`);

  return product;
}
```

Можно удалять cache после успешной записи в БД. Если удалить до записи, а БД update упадет, cache уже исчезнет без причины.

## Что такое cache miss и cache hit?

| Термин | Значение |
|---|---|
| Cache hit | данные найдены в Redis |
| Cache miss | данных нет, нужно читать source of truth |
| Hit ratio | доля успешных cache hits |

Высокий hit ratio обычно снижает нагрузку на БД.

## Какие риски?

- stale data;
- cache stampede;
- serialization bugs;
- отсутствие TTL;
- cache key не учитывает tenant/user/locale;
- Redis outage ломает endpoint вместо graceful fallback.

## Мини-шпаргалка

- Cache-aside: приложение само управляет Redis.
- Read path: `GET`, miss, DB, `SET EX`.
- Write path: DB update, `DEL cache`.
- TTL обязателен.
- Cache key должен учитывать все факторы результата.
