# Когда локальное состояние лучше глобального?

> [!NOTE]
> Локальное состояние лучше, когда данные нужны одному компоненту или небольшой связанной группе компонентов. Чем ближе state к месту использования, тем проще код.

## Вопрос

Когда локальное состояние лучше глобального?

## Типичные случаи

- Открыта ли конкретная модалка.
- Текст в поле формы.
- Активная вкладка внутри одного виджета.
- Локальная ошибка валидации.
- Hover/focus/expanded состояние.

```vue
<script setup>
import { ref } from "vue";

const activeTab = ref("profile");
const isModalOpen = ref(false);
</script>
```

## Почему не store

Если вынести локальные UI-детали в глобальный store, приложение становится шумнее: любое место теоретически может менять эти данные.

## Поднятие состояния

Если state нужен нескольким близким дочерним компонентам, можно поднять его к ближайшему общему родителю.

```text
UserPage
  -> UserFilters
  -> UserTable
```

Фильтры могут жить в `UserPage`, а не в глобальном store.

## Когда пора вынести

Если state начинают использовать независимые страницы или очень далекие ветки дерева, локальное хранение может превратиться в prop drilling.

## Мини-шпаргалка

- Держи state как можно ближе к месту использования.
- Локальный state проще тестировать.
- Поднимай state к ближайшему общему родителю.
- В store выноси только действительно общие данные.
