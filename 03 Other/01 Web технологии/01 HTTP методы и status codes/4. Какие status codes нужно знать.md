# Какие status codes нужно знать?

> [!summary]
> HTTP status code показывает результат обработки запроса. Коды делятся на классы: `1xx` informational, `2xx` success, `3xx` redirects, `4xx` client errors, `5xx` server errors.

## Классы status codes

| Класс | Смысл | Пример |
|---|---|---|
| `1xx` | промежуточная информация | `100 Continue` |
| `2xx` | успех | `200 OK` |
| `3xx` | redirect/cache navigation | `301`, `302`, `304` |
| `4xx` | ошибка клиента | `400`, `401`, `404` |
| `5xx` | ошибка сервера | `500`, `503` |

## Самые частые 2xx

| Код | Когда использовать |
|---|---|
| `200 OK` | запрос успешно выполнен, есть body |
| `201 Created` | ресурс создан |
| `202 Accepted` | запрос принят, обработка будет позже |
| `204 No Content` | успешно, но body нет |

## Самые частые 3xx

| Код | Когда встречается |
|---|---|
| `301 Moved Permanently` | постоянный redirect |
| `302 Found` | временный redirect |
| `304 Not Modified` | browser может использовать cache |

`304` часто появляется при cache validation через `ETag` или `Last-Modified`.

## Самые частые 4xx

| Код | Смысл |
|---|---|
| `400 Bad Request` | запрос некорректный |
| `401 Unauthorized` | пользователь не authenticated |
| `403 Forbidden` | authenticated, но нет прав |
| `404 Not Found` | ресурс не найден |
| `409 Conflict` | конфликт состояния |
| `422 Unprocessable Content` | данные синтаксически ок, но не проходят бизнес-валидацию |
| `429 Too Many Requests` | rate limit |

## Самые частые 5xx

| Код | Смысл |
|---|---|
| `500 Internal Server Error` | непредвиденная ошибка сервера |
| `502 Bad Gateway` | proxy/gateway получил плохой ответ |
| `503 Service Unavailable` | сервис временно недоступен |
| `504 Gateway Timeout` | upstream не ответил вовремя |

## Как frontend должен реагировать?

```ts
const response = await fetch('/api/users/1');

if (response.status === 401) {
  redirectToLogin();
}

if (response.status === 403) {
  showForbiddenMessage();
}

if (!response.ok) {
  showError();
}
```

`fetch` не бросает exception на `404` или `500`. Он бросает exception на сетевые ошибки, CORS-блокировку или отмену запроса.

## Мини-шпаргалка

- `2xx` - успех.
- `3xx` - redirect или cache validation.
- `4xx` - проблема в request/client state.
- `5xx` - проблема на server/upstream.
- `401` - не вошел в систему.
- `403` - вошел, но нельзя.
- `fetch` требует ручной проверки `response.ok`.
