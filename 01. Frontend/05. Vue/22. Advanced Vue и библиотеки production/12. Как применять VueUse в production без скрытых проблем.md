# Как применять VueUse в production без скрытых проблем?

> [!NOTE]
> VueUse - набор composables для Vue. Он экономит время, но его нужно использовать осознанно: учитывать SSR, cleanup, shared state, размер bundle, browser API и границы ответственности.

## Вопрос

Как применять VueUse в production и не получить скрытые проблемы?

## Подключение

```bash
npm i @vueuse/core
```

Использование:

```vue
<script setup lang="ts">
import { useWindowSize } from "@vueuse/core";

const { width, height } = useWindowSize();
</script>

<template>
  <p>{{ width }} x {{ height }}</p>
</template>
```

## Зачем нужен VueUse

VueUse закрывает типовые задачи:

- browser APIs;
- storage;
- events;
- media queries;
- clipboard;
- fetch;
- debounce/throttle;
- observers;
- dark mode;
- shared state;
- lifecycle helpers;
- utility composables для refs/watch.

Без VueUse команда часто пишет десятки похожих `useEventListener`, `useLocalStorage`, `useDebounce`, `useMediaQuery`, и каждый вариант немного отличается.

## `useStorage`

```vue
<script setup lang="ts">
import { useStorage } from "@vueuse/core";

const settings = useStorage("settings", {
  compact: false,
  pageSize: 20,
});
</script>
```

Теперь `settings.value` синхронизируется с storage.

Где применять:

- UI settings;
- draft filters;
- non-sensitive preferences;
- selected theme;
- layout state.

Не хранить:

- access tokens;
- private user data;
- большие server responses;
- данные, требующие миграций без версии.

## `useFetch`

```typescript
import { useFetch } from "@vueuse/core";

const { data, error, isFetching, execute, abort } = useFetch("/api/users", {
  immediate: false,
}).json<User[]>();

await execute();
```

Полезно для простых клиентских запросов.

Для сложного server state лучше рассмотреть TanStack Query/Vue Query или Nuxt data fetching, если проект на Nuxt.

## `useEventListener`

```typescript
import { useEventListener } from "@vueuse/core";

useEventListener(window, "keydown", (event) => {
  if (event.key === "Escape") {
    close();
  }
});
```

Плюс VueUse: cleanup произойдет автоматически при unmount/scope dispose.

## Debounce и throttle

```typescript
import { ref } from "vue";
import { useDebounceFn, watchDebounced } from "@vueuse/core";

const query = ref("");

const search = useDebounceFn(async () => {
  await api.search(query.value);
}, 300);

watchDebounced(
  query,
  async (value) => {
    await api.search(value);
  },
  { debounce: 300 },
);
```

Где применять:

- search input;
- resize handlers;
- scroll handlers;
- autosave;
- analytics events.

## Observers

```typescript
import { useIntersectionObserver } from "@vueuse/core";
import { useTemplateRef } from "vue";

const target = useTemplateRef<HTMLElement>("target");

const { stop } = useIntersectionObserver(target, ([entry]) => {
  if (entry?.isIntersecting) {
    loadMore();
  }
});
```

`stop()` можно вызвать вручную, если наблюдение больше не нужно.

## Shared state

`createGlobalState`:

```typescript
import { createGlobalState } from "@vueuse/core";
import { ref } from "vue";

export const useGlobalSearchState = createGlobalState(() => {
  const query = ref("");

  return {
    query,
  };
});
```

`createSharedComposable`:

```typescript
import { createSharedComposable, useWindowSize } from "@vueuse/core";

export const useSharedWindowSize = createSharedComposable(useWindowSize);
```

Когда использовать:

- легкое shared UI-state;
- singleton browser subscriptions;
- shared observers.

Когда лучше Pinia:

- бизнес-состояние;
- actions;
- permissions;
- complex persistence;
- SSR state;
- devtools/debugging.

## SSR

Многие VueUse composables проверяют client environment, но разработчик все равно должен думать о SSR.

Правила:

- не обращаться к `window`/`document` напрямую в module scope;
- использовать `isClient`, если нужен явный guard;
- проверять hydration differences;
- задавать initial value, который одинаково выглядит на server/client;
- не читать localStorage для critical SSR markup.

```typescript
import { isClient } from "@vueuse/core";

if (isClient) {
  console.log(window.location.href);
}
```

## Bundle size

Импортируйте конкретные функции:

```typescript
import { useStorage } from "@vueuse/core";
```

Не делайте barrel-import всего namespace без необходимости:

```typescript
import * as VueUse from "@vueuse/core";
```

Обычно bundler справится с tree-shaking, но точечные импорты проще читать и анализировать.

## Частые ошибки

- Использовать `useStorage` для sensitive data.
- Делать shared state через VueUse там, где нужен Pinia.
- Не учитывать SSR и hydration.
- Создать debounce, но не отменять/не учитывать pending request.
- Использовать `useFetch` как полноценную замену server-state library в сложном приложении.
- Импортировать composables в module scope и ожидать component lifecycle.
- Слепо добавлять VueUse, не понимая, какую browser API он оборачивает.

## Что отвечать на собеседовании

VueUse - это библиотека composables для Vue, которая дает готовые wrappers над browser API, storage, events, observers, debounce/throttle, fetch и shared state. В production важно проверять SSR-совместимость, не хранить чувствительные данные в storage, отличать shared UI-state от Pinia store, использовать cleanup-aware composables и не превращать `useFetch` в универсальную data layer для сложного server state.

## Мини-шпаргалка

- `useStorage` - storage как ref.
- `useEventListener` - listener с cleanup.
- `useDebounceFn`/`watchDebounced` - debounce.
- `useIntersectionObserver` - lazy loading/visibility.
- `createGlobalState` - singleton state.
- `createSharedComposable` - shared composable instance.
- `isClient` - SSR guard.
- Для сложного server state смотри TanStack Query/Nuxt data fetching.
