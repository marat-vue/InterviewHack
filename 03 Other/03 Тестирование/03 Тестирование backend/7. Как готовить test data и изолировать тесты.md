# Как готовить test data и изолировать тесты?

> [!summary]
> Каждый тест должен получать понятные данные и не зависеть от результатов других тестов. Для этого используют factories, builders, fixtures, очистку базы, уникальные значения и независимый setup.

## Почему изоляция важна?

Плохой тест:

```ts
test('uses existing user from previous test', async () => {
  const order = await createOrderForUser(1);

  expect(order.userId).toBe(1);
});
```

Если предыдущий тест не создал user `1`, тест упадет. Или наоборот пройдет случайно.

## Factory

Factory создает валидный объект с дефолтами:

```ts
function makeUser(overrides: Partial<User> = {}): User {
  return {
    id: 1,
    email: 'ann@example.com',
    role: 'user',
    ...overrides,
  };
}
```

Использование:

```ts
const admin = makeUser({ role: 'admin' });
```

## Database seed helper

```ts
async function createTestUser(data = {}) {
  return prisma.user.create({
    data: {
      email: `user-${crypto.randomUUID()}@example.com`,
      passwordHash: 'hash',
      ...data,
    },
  });
}
```

Уникальные значения помогают избежать конфликтов.

## Как очищать базу?

Варианты:

- удалять записи после каждого теста;
- оборачивать тест в transaction и откатывать;
- пересоздавать schema/database;
- запускать контейнер БД заново для набора тестов.

## Мини-шпаргалка

- Тест не должен зависеть от порядка запуска.
- Factories создают понятные данные.
- Уникальные email/id уменьшают flaky tests.
- Базу нужно очищать или откатывать.
- Test data должна показывать смысл сценария.
