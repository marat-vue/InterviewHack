# Что тестировать во frontend?

> [!summary]
> Во frontend тестируют не только функции, но и пользовательское поведение: что отображается, какие события происходят, как работает форма, как обрабатываются загрузка, ошибки, роутинг, состояние и доступность интерфейса.

## Главный вопрос frontend-теста

Frontend-тест должен отвечать: "Пользователь сможет выполнить нужное действие и увидеть правильный результат?"

Например:

- товар отображается в каталоге;
- кнопка disabled, пока форма невалидна;
- ошибка API показывается человеку понятным текстом;
- после login пользователь попадает на нужную страницу;
- modal закрывается по кнопке.

## Что точно стоит тестировать?

| Область | Пример |
|---|---|
| rendering | компонент показывает данные из props |
| user events | click, input, submit |
| forms | validation, errors, disabled states |
| async UI | loading, success, error |
| state | Pinia store, composables |
| routing | redirects, guards, links |
| accessibility | labels, focus, keyboard |
| edge cases | empty list, long text, no permissions |

## Пример компонента

```vue
<template>
  <button :disabled="loading" @click="$emit('save')">
    {{ loading ? 'Сохраняем...' : 'Сохранить' }}
  </button>
</template>
```

Что проверять:

```ts
const wrapper = mount(SaveButton, {
  props: { loading: true },
});

expect(wrapper.get('button').attributes('disabled')).toBeDefined();
expect(wrapper.text()).toContain('Сохраняем...');
```

## Что не стоит тестировать?

Обычно не стоит тестировать:

- что Vue сам правильно обновляет DOM;
- внутренние private-переменные;
- каждую CSS-декларацию;
- реализацию чужих библиотек;
- простые getters без логики.

## Мини-шпаргалка

- Frontend-тесты проверяют пользовательское поведение.
- Важны rendering, events, forms, async states, router, store.
- Не тестируй Vue, браузер и чужие библиотеки вместо своего кода.
- Edge cases в UI часто важнее красивого happy path.
- Хороший тест похож на маленький пользовательский сценарий.
