# Методы массива vs циклы

> [!summary] Коротко
> Методы массива удобнее и выразительнее, но в горячих местах обычные циклы иногда быстрее и создают меньше промежуточных массивов.

## Вопрос

Почему методы массивов могут быть медленнее циклов?

## Основная идея

`map`, `filter`, `reduce` и другие методы вызывают callback для каждого элемента. Это удобно и читаемо, но может иметь накладные расходы на больших данных или в очень частых вычислениях.

## Читаемый вариант

```javascript
const result = users
  .filter((user) => user.isActive)
  .map((user) => user.name);
```

Для большинства UI-задач такой код хорош: он понятен и достаточно быстр.

## Возможный минус

Цепочка выше создает промежуточный массив после `filter`.

## Один цикл

```javascript
const result = [];

for (const user of users) {
  if (user.isActive) {
    result.push(user.name);
  }
}
```

Один проход и без промежуточного массива.

## Когда выбирать циклы

- огромные массивы;
- код выполняется много раз в секунду;
- участок подтвержден профилировщиком как bottleneck;
- важно уменьшить аллокации памяти.

## Практическое правило

Сначала выбирай читаемость. Оптимизируй на циклы только там, где измерения показали проблему.

## Мини-шпаргалка

```javascript
// readable
arr.filter(fn).map(fn);

// hot path
for (const item of arr) {}
```
