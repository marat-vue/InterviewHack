# useEffect и асинхронный код

> [!summary]
> `useEffect` используют для async-кода, когда компоненту нужно синхронизироваться с внешней системой после render: API, таймером, подпиской, DOM API. Сам callback эффекта не должен быть `async`, потому что React ожидает от него cleanup-функцию или `undefined`, а не Promise.

## Почему нельзя написать async прямо в useEffect?

Плохо:

```jsx
useEffect(async () => {
  const data = await fetchUser()
  setUser(data)
}, [])
```

`async` функция всегда возвращает Promise. React ожидает, что effect callback вернет:

- ничего;
- cleanup-функцию.

Поэтому async-функцию объявляют внутри.

## Правильный шаблон

```jsx
useEffect(() => {
  async function loadUser() {
    const data = await fetchUser()
    setUser(data)
  }

  loadUser()
}, [])
```

## Шаблон с loading/error

```jsx
function UserPage({ userId }) {
  const [user, setUser] = useState(null)
  const [status, setStatus] = useState('idle')
  const [error, setError] = useState(null)

  useEffect(() => {
    let ignore = false

    async function loadUser() {
      try {
        setStatus('loading')
        setError(null)

        const data = await fetchUser(userId)

        if (!ignore) {
          setUser(data)
          setStatus('success')
        }
      } catch (error) {
        if (!ignore) {
          setError(error)
          setStatus('error')
        }
      }
    }

    loadUser()

    return () => {
      ignore = true
    }
  }, [userId])
}
```

Флаг `ignore` защищает от установки устаревшего результата.

## AbortController

Если используется `fetch`, запрос можно отменять:

```jsx
useEffect(() => {
  const controller = new AbortController()

  async function loadUser() {
    try {
      const response = await fetch(`/api/users/${userId}`, {
        signal: controller.signal,
      })
      const data = await response.json()
      setUser(data)
    } catch (error) {
      if (error.name !== 'AbortError') {
        setError(error)
      }
    }
  }

  loadUser()

  return () => controller.abort()
}, [userId])
```

## Зависимости эффекта

Если внутри эффекта используется `userId`, он должен быть в dependencies:

```jsx
useEffect(() => {
  fetchUser(userId)
}, [userId])
```

Не надо "обманывать" массив зависимостей, иначе эффект начнет работать со старыми значениями.

## Мини-шпаргалка

- Effect callback не делают `async`.
- Async-функцию объявляют внутри эффекта.
- Все значения из render scope указывают в dependencies.
- Cleanup нужен для отмены, отписки или игнорирования результата.
- Для сложного data fetching лучше query-библиотека или loader.
