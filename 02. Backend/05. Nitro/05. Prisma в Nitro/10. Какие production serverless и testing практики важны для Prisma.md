# Какие production, serverless и testing практики важны для Prisma?

> [!NOTE]
> Prisma в Nitro требует внимания к connection lifecycle, migrations, pooling, error mapping, query performance и тестовой базе. Особенно аккуратно нужно работать в serverless и edge окружениях.

## Connection management

Не создавай `PrismaClient` на каждый request:

```ts
// плохо
export default defineHandler(() => {
  const prisma = new PrismaClient();
  return prisma.user.findMany();
});
```

Используй singleton:

```ts
export const prisma = globalForPrisma.prisma ?? new PrismaClient();
```

## Pooling

Для PostgreSQL в serverless могут быстро закончиться connections. Решения:

- managed connection pooler;
- PgBouncer;
- Prisma Accelerate/Data Proxy, если подходит;
- ограничение concurrency;
- правильный database URL;
- отдельный pool для migrations и runtime.

## Query performance

Проверяй:

- `include` на больших relations;
- отсутствие индексов;
- offset pagination на больших таблицах;
- `contains` без full-text/index strategy;
- N+1;
- слишком широкие `select`;
- transaction duration.

## Error mapping

Prisma errors не должны уходить пользователю как internal stack trace.

```ts
import { Prisma } from '@prisma/client';

export function mapPrismaError(error: unknown): never {
  if (error instanceof Prisma.PrismaClientKnownRequestError) {
    if (error.code === 'P2002') {
      throw createError({
        statusCode: 409,
        statusMessage: 'Unique constraint failed',
      });
    }

    if (error.code === 'P2025') {
      throw createError({
        statusCode: 404,
        statusMessage: 'Record not found',
      });
    }
  }

  throw error;
}
```

## Testing database

Варианты:

- отдельная test database;
- SQLite для простых unit/integration tests;
- Testcontainers для PostgreSQL/MySQL;
- transaction rollback per test;
- truncation/reset between tests;
- seed fixtures.

## Vitest setup

```ts
// tests/setup.ts
import { beforeAll, afterAll } from 'vitest';
import { prisma } from '../server/utils/prisma';

beforeAll(async () => {
  await prisma.$connect();
});

afterAll(async () => {
  await prisma.$disconnect();
});
```

## Test isolation

Плохой тест:

```ts
it('creates user', async () => {
  await prisma.user.create({ data: { email: 'a@example.com' } });
});
```

Если тесты запускаются повторно, unique email может конфликтовать. Лучше:

```ts
const email = `user-${crypto.randomUUID()}@example.com`;
```

Или чистить таблицы:

```ts
afterEach(async () => {
  await prisma.user.deleteMany();
});
```

## Raw SQL safety

Хорошо:

```ts
await prisma.$queryRaw`
  SELECT *
  FROM "User"
  WHERE email = ${email}
`;
```

Плохо:

```ts
await prisma.$queryRawUnsafe(`SELECT * FROM "User" WHERE email = '${email}'`);
```

`Unsafe` методы используй только если полностью контролируешь SQL и умеешь безопасно параметризовать.

## Мини-шпаргалка

- Singleton PrismaClient обязателен.
- В serverless думай о pooling.
- Production migrations - `migrate deploy`.
- Не возвращай Prisma stack/errors напрямую.
- Для тестов нужна изолированная database strategy.
- `select` лучше, чем отдавать всю модель.
- Raw SQL только параметризованно.
