# Почему не стоит блокировать event loop?

> [!NOTE]
> Если заблокировать Event Loop, браузер не сможет обрабатывать клики, таймеры, промисы, сетевые callbacks и обновление интерфейса.

## Вопрос

Почему блокировка Event Loop так опасна для производительности?

## Определение

JavaScript в браузере выполняется в основном потоке. Пока этот поток занят тяжелой синхронной задачей, Event Loop не может передать на выполнение другие задачи.

Для пользователя это выглядит как зависший интерфейс.

## Пример блокировки

```javascript
console.log('start');

const start = Date.now();

while (Date.now() - start < 3000) {
  // тяжелая синхронная работа
}

console.log('end');
```

Пока цикл работает, страница не реагирует.

## Что задерживается

- обработчики кликов и ввода;
- `setTimeout` и `setInterval`;
- продолжения промисов;
- рендер и анимации;
- сетевые callbacks;
- работа UI-фреймворков.

## Как избежать

- оптимизировать алгоритм;
- разбивать работу на чанки;
- использовать `requestIdleCallback`;
- переносить CPU-heavy задачи в Web Worker;
- не выполнять большие синхронные операции в обработчиках событий.

## Мини-шпаргалка

```text
long sync task -> blocked main thread -> frozen UI
```
