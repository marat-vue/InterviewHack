# Можно ли делать await fetch прямо в компоненте?

> [!summary]
> Да, в App Router можно делать `await fetch` прямо в Server Component, потому что серверные компоненты могут быть async. В Client Component так делать нельзя в render; там используют effects, event handlers или data libraries.

## Server Component

```tsx
export default async function PostsPage() {
  const posts = await fetch('https://api.example.com/posts').then((res) =>
    res.json(),
  )

  return <PostList posts={posts} />
}
```

Запрос выполняется на сервере.

## С обработкой ошибок

```tsx
async function getPosts() {
  const response = await fetch('https://api.example.com/posts')

  if (!response.ok) {
    throw new Error('Failed to load posts')
  }

  return response.json()
}
```

Лучше вынести data access в отдельную функцию.

## С cache options

```tsx
await fetch('https://api.example.com/posts', {
  next: { revalidate: 3600 },
})
```

```tsx
await fetch('https://api.example.com/live', {
  cache: 'no-store',
})
```

## Client Component

Плохо:

```tsx
'use client'

export function Posts() {
  const posts = await fetch('/api/posts')
  return <div>{posts}</div>
}
```

В Client Component используют:

- `useEffect`;
- TanStack Query;
- SWR;
- event handler;
- Suspense-enabled client library.

## Что отвечать на собеседовании?

`await fetch` прямо в компоненте разрешен в async Server Components App Router. Это один из главных паттернов Next.js. В Client Components нельзя делать async render таким образом; там нужны client-side data fetching инструменты.

## Частые ошибки

- Делать async Client Component.
- Не проверять `response.ok`.
- Забывать cache/revalidate стратегию.
- Делать лишний Route Handler для внутреннего server fetch.
- Загружать sensitive data и передавать лишнее клиенту.

## Мини-шпаргалка

- Server Component может быть `async`.
- Client Component не должен `await fetch` в render.
- Проверяй `response.ok`.
- Управляй cache через `fetch` options.
- Data access лучше выносить в функцию.
