# Где хранится состояние компонента?

> [!summary]
> Состояние React-компонента хранится не в локальной переменной функции, а внутри React, привязанное к месту компонента в UI-дереве. При каждом render React возвращает компоненту актуальное значение state для этой позиции.

## Почему state не хранится в переменной?

Компонент - это функция:

```jsx
function Counter() {
  const [count, setCount] = useState(0)
  return <button>{count}</button>
}
```

React может вызывать эту функцию много раз. Локальные переменные создаются заново при каждом вызове, поэтому React хранит state отдельно.

Упрощенно:

```text
React хранит state для конкретного компонента в конкретной позиции дерева.
```

## State привязан к позиции

```jsx
function App({ showSecond }) {
  return (
    <>
      <Counter />
      {showSecond && <Counter />}
    </>
  )
}
```

У первого и второго `Counter` разные состояния, потому что это разные позиции в дереве.

## Когда state сохраняется?

State сохраняется, если React видит тот же тип компонента на той же позиции:

```jsx
{isVisible && <Counter />}
```

Если `Counter` временно исчезает из дерева, его state обычно сбрасывается при повторном монтировании.

## Как key влияет на state?

`key` может заставить React считать компонент новым:

```jsx
<ProfileForm key={userId} userId={userId} />
```

Когда `userId` меняется, React размонтирует старую форму и создаст новую, сбросив локальный state.

Это полезно, если форма должна очищаться при смене пользователя.

## Где смотреть state?

State можно увидеть:

- в коде через hooks;
- в React DevTools;
- через поведение UI;
- в тестах компонента.

Но нельзя напрямую "достать весь state React" как обычный глобальный объект.

## Мини-шпаргалка

- State хранится внутри React, а не в обычной переменной.
- State привязан к позиции компонента в дереве.
- Один и тот же компонент в двух местах имеет два state.
- `key` может сбрасывать state.
- При размонтировании локальный state теряется.
