# Почему JOIN может создавать дубли?

> [!summary]
> `JOIN` не создает "дубли" случайно: он возвращает все комбинации строк, которые подходят под условие. Если слева одна строка, а справа три совпадения, в результате будет три строки.

## Пример one-to-many

```sql
SELECT u.id, u.email, o.id AS order_id
FROM users u
JOIN orders o ON o.user_id = u.id;
```

Если у пользователя три заказа, пользователь появится в результате три раза - по одному разу на каждый заказ.

## Когда это нормально?

Это нормально, если нужен список заказов с данными пользователя.

```txt
order 1 -> user
order 2 -> user
order 3 -> user
```

Но если нужен список пользователей, у которых есть заказы, лучше использовать `EXISTS`.

```sql
SELECT u.*
FROM users u
WHERE EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.user_id = u.id
);
```

## Ошибка в условии

Дубли могут появиться из-за неполного `ON`.

```sql
-- Подозрительно, если связь должна учитывать еще tenant_id
ON orders.user_id = users.id
```

## Мини-шпаргалка

- JOIN возвращает все совпавшие комбинации.
- One-to-many естественно размножает строки.
- `DISTINCT` не всегда правильное решение.
- Для проверки существования часто лучше `EXISTS`.
- Проверяй полноту условия `ON`.
