# Что такое первичный и внешний ключ?

> [!summary]
> Первичный ключ уникально идентифицирует строку в таблице. Внешний ключ связывает строку одной таблицы со строкой другой таблицы и поддерживает ссылочную целостность.

## Primary key

```sql
CREATE TABLE users (
  id bigint PRIMARY KEY,
  email text NOT NULL
);
```

`PRIMARY KEY` гарантирует уникальность и отсутствие `NULL`.

## Foreign key

```sql
CREATE TABLE orders (
  id bigint PRIMARY KEY,
  user_id bigint NOT NULL REFERENCES users(id)
);
```

`orders.user_id` может ссылаться только на существующего пользователя.

## Зачем нужен внешний ключ?

Без foreign key можно получить "висячую" ссылку.

```sql
INSERT INTO orders (id, user_id)
VALUES (1, 999);
```

Если пользователя `999` нет, FK не даст сохранить некорректные данные.

## Поведение при удалении

```sql
user_id bigint REFERENCES users(id) ON DELETE CASCADE
```

`CASCADE` удалит дочерние записи вместе с родительской. Это удобно, но опасно, если использовать без понимания.

## Мини-шпаргалка

- `PRIMARY KEY` уникально идентифицирует строку.
- `FOREIGN KEY` связывает таблицы.
- FK поддерживает ссылочную целостность.
- `ON DELETE CASCADE` удаляет зависимые строки.
- На FK-колонки часто нужен индекс для производительности.
