# Suspense и Data fetching

> [!summary]
> Suspense может использоваться для data fetching, но только с источниками данных, которые интегрированы с Suspense: фреймворковые loaders, Server Components, Relay, TanStack Query Suspense API и другие кеширующие механизмы. Обычный `fetch` в `useEffect` не включает Suspense.

## Без Suspense

```jsx
function Profile({ userId }) {
  const [user, setUser] = useState(null)
  const [isLoading, setIsLoading] = useState(true)

  useEffect(() => {
    fetchUser(userId)
      .then(setUser)
      .finally(() => setIsLoading(false))
  }, [userId])

  if (isLoading) return <ProfileSkeleton />

  return <ProfileView user={user} />
}
```

Компонент сам управляет loading state.

## С Suspense-enabled API

```jsx
function Profile({ userId }) {
  const { data } = useSuspenseQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
  })

  return <ProfileView user={data} />
}
```

Обертка:

```jsx
<ErrorBoundary fallback={<ProfileError />}>
  <Suspense fallback={<ProfileSkeleton />}>
    <Profile userId={userId} />
  </Suspense>
</ErrorBoundary>
```

`Suspense` показывает loading, Error Boundary показывает error.

## Как это работает концептуально?

```text
1. Компонент пытается прочитать данные
2. Данных нет -> источник данных suspend-ит render
3. React показывает fallback ближайшего Suspense
4. Данные готовы -> React повторяет render
5. Компонент получает данные и возвращает UI
```

## Suspense в Server Components

В RSC/фреймворках data fetching может быть ближе к серверу:

```tsx
async function Posts() {
  const posts = await getPosts()

  return <PostsList posts={posts} />
}

export default function Page() {
  return (
    <Suspense fallback={<PostsSkeleton />}>
      <Posts />
    </Suspense>
  )
}
```

Фреймворк может стримить fallback и позже дослать готовую часть.

## Когда не использовать Suspense для данных?

- простая форма с local loading;
- старое приложение на `useEffect`;
- библиотека data fetching не поддерживает Suspense;
- нужно очень явно управлять каждым loading state;
- команда пока не готова к Error Boundary/Suspense архитектуре.

## Мини-шпаргалка

- Suspense для данных требует специальной интеграции.
- `useEffect + fetch` не suspend-ит.
- Error Boundary обязателен для ошибок.
- Server Components и streaming SSR хорошо сочетаются с Suspense.
- Для обычного CRUD часто проще TanStack Query без Suspense mode.
