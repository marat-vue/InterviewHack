# Как валидировать structured data?

> [!summary]
> Валидация structured data нужна, чтобы убедиться: JSON-LD синтаксически корректен, использует подходящие типы, содержит нужные поля и может быть обработан поисковыми системами.

## Чем проверять?

Основные инструменты:

- Rich Results Test;
- Schema Markup Validator;
- Search Console;
- проверка HTML после рендера;
- автоматические тесты для шаблонов страниц.

## Что проверять вручную?

- JSON валиден.
- `@context` и `@type` указаны.
- Обязательные поля заполнены.
- URL абсолютные.
- Даты в корректном формате.
- Разметка соответствует видимому контенту.
- На странице нет конфликтующих сущностей.

## Как проверять в frontend-приложении?

Важно проверять итоговый HTML, а не только исходный компонент.

Пример идеи для теста:

```ts
expect(document.querySelector('script[type="application/ld+json"]')).toBeTruthy()
```

Для SSR/SSG можно проверять HTML ответа:

```bash
curl https://example.com/article | grep 'application/ld+json'
```

## Что делать с warnings?

Warnings не всегда блокируют rich results, но их нельзя игнорировать автоматически.

Оцени:

- поле действительно применимо?
- данные есть на странице?
- можно ли заполнить их честно?
- влияет ли warning на конкретный тип rich result?

## Мини-шпаргалка

- Проверяй и синтаксис, и соответствие контенту.
- В SPA проверяй состояние после рендера маршрута.
- Search Console показывает проблемы на реальном сайте.
- Warning - повод подумать, а не всегда срочно править.
- Structured data должны тестироваться как часть шаблона.
