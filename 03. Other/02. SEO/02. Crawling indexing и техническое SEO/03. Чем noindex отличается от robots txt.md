# Чем noindex отличается от robots.txt?

> [!summary]
> robots.txt отвечает на вопрос "можно ли роботу обходить URL", а noindex отвечает на вопрос "можно ли показывать страницу в индексе". Это разные механизмы, и их часто путают.

## Что делает robots.txt?

robots.txt может запретить роботу скачивать страницу:

```txt
User-agent: *
Disallow: /private/
```

Это снижает crawling, но не всегда удаляет URL из результатов поиска.

## Что делает noindex?

`noindex` просит поисковик не индексировать страницу:

```html
<meta name="robots" content="noindex, follow">
```

Или через HTTP header:

```http
X-Robots-Tag: noindex
```

Вариант с header удобен для PDF, изображений и файлов без HTML.

## Почему нельзя закрывать noindex-страницу в robots.txt?

Если страница закрыта от обхода, робот может не увидеть `noindex`.

Плохой сценарий:

```txt
Disallow: /old-page
```

```html
<meta name="robots" content="noindex">
```

Робот не заходит на `/old-page`, поэтому тег может не обработаться.

## Когда что использовать?

| Задача | Инструмент |
|---|---|
| Не тратить crawling на технические URL | robots.txt |
| Убрать страницу из индекса | `noindex` |
| Удалить несуществующую страницу | `404` или `410` |
| Склеить дубликаты | `rel="canonical"` |
| Перенести страницу навсегда | `301` redirect |

## Что такое follow и nofollow?

```html
<meta name="robots" content="noindex, follow">
```

`follow` разрешает поисковику переходить по ссылкам на странице.

```html
<meta name="robots" content="noindex, nofollow">
```

`nofollow` говорит не учитывать ссылки на странице. Использовать его нужно осторожно.

## Мини-шпаргалка

- robots.txt - про обход.
- noindex - про индекс.
- Для noindex робот должен увидеть страницу.
- Для удаления мусорных URL часто лучше `noindex`, `404`, `410` или canonical.
- Нельзя механически закрывать все "неважное" в robots.txt.
