# Что делает shouldComponentUpdate?

> [!summary]
> `shouldComponentUpdate` - lifecycle method классового компонента, который позволяет вернуть `false` и пропустить render при некоторых изменениях props или state. В современном React похожие задачи чаще решают через `React.memo`, правильную структуру state и профилирование.

## Базовый пример

```jsx
class UserCard extends Component {
  shouldComponentUpdate(nextProps) {
    return nextProps.user.id !== this.props.user.id
  }

  render() {
    return <h2>{this.props.user.name}</h2>
  }
}
```

Если метод вернет `false`, React может пропустить render компонента.

## Зачем он был нужен?

Для оптимизации:

- дорогих компонентов;
- больших списков;
- компонентов с частыми parent renders;
- ситуаций, где props фактически не изменились.

## Почему нужно осторожно?

Ошибка в `shouldComponentUpdate` может привести к stale UI:

```jsx
shouldComponentUpdate(nextProps) {
  return nextProps.user.id !== this.props.user.id
}
```

Если `user.name` изменился, а `id` тот же, компонент не обновится.

## Современные аналоги

Функциональный компонент:

```jsx
const UserCard = memo(function UserCard({ user }) {
  return <h2>{user.name}</h2>
})
```

Но `memo` тоже нужно использовать осознанно. Нестабильные object/function props могут свести пользу к нулю.

## Мини-шпаргалка

- `shouldComponentUpdate` может пропустить update класса.
- Возвращает `true` или `false`.
- Неправильная проверка может заморозить UI.
- Современный аналог - `React.memo`.
- Оптимизируй после измерения в Profiler.
