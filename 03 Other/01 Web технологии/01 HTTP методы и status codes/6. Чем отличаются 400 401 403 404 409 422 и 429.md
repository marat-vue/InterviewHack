# Чем отличаются 400, 401, 403, 404, 409, 422 и 429?

> [!summary]
> Эти status codes описывают разные ошибки клиента: плохой запрос, отсутствие authentication, запрет доступа, отсутствие ресурса, конфликт состояния, ошибку бизнес-валидации и rate limit.

## Быстрая таблица

| Код | Значение | Пример |
|---|---|---|
| `400` | request невозможно корректно разобрать | битый JSON |
| `401` | нет authentication | нет token/session |
| `403` | нет прав | user не admin |
| `404` | ресурс не найден | нет `/users/999` |
| `409` | конфликт текущего состояния | email уже занят |
| `422` | данные понятны, но невалидны по правилам | password слишком слабый |
| `429` | слишком много запросов | rate limit |

## 400 Bad Request

```http
POST /api/users
Content-Type: application/json

{ bad json
```

`400` подходит, когда request синтаксически или структурно некорректен.

## 401 Unauthorized

```json
{
  "message": "Authentication required"
}
```

Название немного сбивает с толку: `401 Unauthorized` на практике означает "не authenticated". Клиенту нужно войти, обновить token или отправить credentials.

## 403 Forbidden

```json
{
  "message": "You do not have permission to access this resource"
}
```

`403` означает: сервер понял, кто пользователь, но действие запрещено.

## 404 Not Found

`404` используют, когда ресурса нет или сервер не хочет раскрывать его существование.

Для приватных ресурсов иногда возвращают `404` вместо `403`, чтобы не подсказывать атакующему, что объект существует.

## 409 Conflict

```http
POST /api/users

{
  "email": "taken@example.com"
}
```

Если email уже занят, это конфликт с текущим состоянием системы. `409` хорошо подходит для unique constraint conflicts, optimistic locking, duplicate idempotency keys.

## 422 Unprocessable Content

`422` подходит, когда JSON корректный, но значения не проходят domain validation.

```json
{
  "email": "not-an-email",
  "password": "123"
}
```

Некоторые API вместо `422` используют `400` для всей validation. Главное - быть последовательным.

## 429 Too Many Requests

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 60
```

`429` означает rate limit. Frontend может показать сообщение и повторить запрос позже.

## Мини-шпаргалка

- `400` - request плохой.
- `401` - нужно войти.
- `403` - вошел, но нельзя.
- `404` - не найдено.
- `409` - конфликт состояния.
- `422` - validation/domain errors.
- `429` - rate limit.
