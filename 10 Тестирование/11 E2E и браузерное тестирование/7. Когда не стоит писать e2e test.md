# Когда не стоит писать e2e test?

> [!summary]
> E2E-тест не нужен для каждого маленького условия. Если сценарий быстрее, надежнее и понятнее проверить unit, integration или component test, лучше выбрать более низкий уровень пирамиды.

## Плохой кандидат для e2e

```text
Функция форматирует цену 1200 как "1 200 ₽".
```

Это unit test:

```ts
expect(formatPrice(1200)).toBe('1 200 ₽');
```

## Еще плохие кандидаты

- каждый вариант цвета кнопки;
- все ветки валидатора;
- каждый helper;
- каждый текст ошибки формы;
- все варианты props компонента;
- все edge cases сортировки.

Их дешевле покрывать unit/component tests.

## Хороший кандидат для e2e

```text
Пользователь входит -> добавляет товар -> оформляет заказ -> видит страницу успеха.
```

Такой сценарий проверяет связь многих частей системы.

## Вопрос для выбора уровня

Спроси:

```text
Мне нужно проверить всю систему или только конкретную логику/компонент?
```

Если вся система не нужна, e2e может быть избыточным.

## Мини-шпаргалка

- E2E дорогие, не трать их на мелкую логику.
- Форматтеры и validators - unit tests.
- UI states - component tests.
- Связи модулей - integration tests.
- Критичные пользовательские flows - e2e tests.
