# Польза статической и строгой типизации

> [!summary] Коротко
> Статическая и строгая типизация помогают находить ошибки раньше, лучше понимать код и безопаснее менять приложение.

## Вопрос

Какая практическая польза от статической и строгой типизации?

## Раннее обнаружение ошибок

```typescript
function getUserName(user: { name: string }) {
  return user.name.toUpperCase();
}

getUserName({ title: 'Ann' }); // ошибка TypeScript
```

TypeScript замечает, что у объекта нет нужного свойства `name`.

## Автодополнение

Когда типы известны, редактор может подсказывать свойства, методы и сигнатуры функций.

```typescript
const user = { name: 'Ann', age: 25 };

user. // редактор подскажет name и age
```

## Безопасный рефакторинг

Если изменить форму данных, TypeScript подсветит места, где код больше не соответствует новым типам.

```typescript
type User = {
  fullName: string;
};
```

Если раньше код ожидал `name`, TS покажет ошибки.

## Документация в коде

```typescript
type CreateUserDto = {
  email: string;
  password: string;
};
```

Тип сразу показывает, какие данные нужны функции или API.

## Что важно помнить

Типизация не отменяет тесты, runtime-валидацию и внимательность к бизнес-логике. TypeScript помогает с формой данных, но не гарантирует, что логика верна.

## Мини-шпаргалка

```text
types -> earlier errors + better IDE + safer refactoring
```
