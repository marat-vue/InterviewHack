# Как делать cache invalidation, versioning, tags и namespaces?

> [!NOTE]
> Cache invalidation - самая сложная часть cache. Redis делает удаление ключей простым, но проектировать нужно так, чтобы случайно не отдавать stale/private данные и не устраивать дорогие массовые очистки.

## Простая invalidation по key

```ts
await db.product.update({
  where: {
    id,
  },
  data,
});

await redis.del(`cache:product:${id}`);
```

Это default для entity cache.

## Versioned keys

```txt
cache:v1:catalog:phones:page:1
cache:v2:catalog:phones:page:1
```

Чтобы сбросить весь catalog cache, увеличь версию:

```ts
const version = await redis.incr('cache-version:catalog');
const key = `cache:v${version}:catalog:${category}:page:${page}`;
```

Старые ключи исчезнут по TTL.

## Tag-based invalidation через sets

Идея: хранить связи tag -> cache keys.

```redis
SADD cache-tag:product:42 cache:catalog:phones:page:1
SADD cache-tag:product:42 cache:product:42
```

При update:

```ts
const keys = await redis.sMembers('cache-tag:product:42');

if (keys.length > 0) {
  await redis.del(keys);
}

await redis.del('cache-tag:product:42');
```

На больших объемах нужно batch-ить deletion и использовать `UNLINK`.

## Namespaces

Пример:

```txt
prod:api:cache:user:1
prod:api:cache:tenant:2:dashboard
```

Namespace защищает от:

- смешивания env;
- конфликтов приложений;
- случайной очистки чужих ключей;
- tenant leakage.

## Что учитывать в cache key?

Cache key должен включать все, что влияет на результат:

- user/tenant;
- locale;
- permissions;
- query params;
- feature flags;
- API version;
- currency/region;
- pagination.

Плохой ключ:

```txt
cache:dashboard
```

Хороший ключ:

```txt
cache:tenant:42:user:1:dashboard:v3:locale:ru
```

## Мини-шпаргалка

- Entity update -> `DEL entity cache`.
- Массовый reset -> versioned keys.
- Related cache -> tags через sets.
- Private data -> user/tenant в key.
- Старые версии должны иметь TTL.
- Для больших deletes используй `UNLINK` batch-ами.
