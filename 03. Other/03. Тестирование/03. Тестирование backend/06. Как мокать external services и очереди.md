# Как мокать external services и очереди?

> [!summary]
> Внешние сервисы в тестах обычно заменяют mocks, fakes или локальными тестовыми адаптерами. Так можно проверить поведение при успехе, ошибке, timeout и retry, не отправляя настоящие письма, платежи и сообщения в очередь.

## Какие зависимости обычно мокают?

- email provider;
- payment gateway;
- SMS provider;
- object storage;
- message broker;
- сторонний REST API;
- analytics;
- webhooks.

## Пример payment mock

```ts
const paymentGateway = {
  charge: vi.fn().mockResolvedValue({
    id: 'pay_123',
    status: 'succeeded',
  }),
};

await checkoutService.pay(orderId);

expect(paymentGateway.charge).toHaveBeenCalledWith({
  amount: 3000,
  currency: 'RUB',
});
```

## Как тестировать ошибку внешнего сервиса?

```ts
paymentGateway.charge.mockRejectedValue(new Error('Payment unavailable'));

await expect(checkoutService.pay(orderId)).rejects.toThrow('Payment unavailable');

const order = await ordersRepository.findById(orderId);
expect(order.status).toBe('payment_failed');
```

## Как тестировать очередь?

Можно проверить, что job поставлена:

```ts
await usersService.register(input);

expect(queue.add).toHaveBeenCalledWith('sendWelcomeEmail', {
  userId: expect.any(Number),
});
```

А handler job лучше тестировать отдельно:

```ts
await sendWelcomeEmailProcessor.handle({ data: { userId: 1 } });

expect(emailService.send).toHaveBeenCalled();
```

## Мини-шпаргалка

- Настоящие внешние сервисы не нужны в unit tests.
- Проверяй success, error, timeout и retry.
- Для очередей отдельно тестируй постановку job и обработчик.
- В integration/e2e можно использовать sandbox-окружения.
- Не отправляй реальные платежи и письма из тестов.
