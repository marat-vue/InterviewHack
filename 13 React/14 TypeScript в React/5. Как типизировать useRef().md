# Как типизировать useRef()?

> [!summary]
> `useRef` типизируют по тому, что будет лежать в `.current`: DOM-элемент, timer id, mutable value или instance сторонней библиотеки. Для DOM почти всегда используют `useRef<HTML...Element>(null)`.

## Ref на DOM-элемент

```tsx
import { useRef } from 'react'

function SearchInput() {
  const inputRef = useRef<HTMLInputElement>(null)

  function focusInput() {
    inputRef.current?.focus()
  }

  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </>
  )
}
```

Почему `null`? До mount DOM-элемента еще нет, поэтому `current` сначала равен `null`.

## Частые DOM-типы

| Элемент | Тип |
|---|---|
| `<input>` | `HTMLInputElement` |
| `<textarea>` | `HTMLTextAreaElement` |
| `<button>` | `HTMLButtonElement` |
| `<div>` | `HTMLDivElement` |
| `<form>` | `HTMLFormElement` |
| `<a>` | `HTMLAnchorElement` |
| `<canvas>` | `HTMLCanvasElement` |

## Ref для хранения значения без rerender

`useRef` можно использовать не только для DOM:

```tsx
function Timer() {
  const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null)

  function start() {
    intervalRef.current = setInterval(() => {
      console.log('tick')
    }, 1000)
  }

  function stop() {
    if (intervalRef.current !== null) {
      clearInterval(intervalRef.current)
      intervalRef.current = null
    }
  }

  return (
    <>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
    </>
  )
}
```

`ReturnType<typeof setInterval>` безопаснее, чем `number`, потому что тип timer id отличается между browser и Node окружением.

## Ref для сторонней библиотеки

```tsx
type ChartInstance = {
  destroy: () => void
  update: (data: number[]) => void
}

const chartRef = useRef<ChartInstance | null>(null)
```

Так удобно хранить объект, изменение которого не должно вызывать rerender.

## forwardRef

Если компонент должен принимать ref от родителя:

```tsx
import { forwardRef } from 'react'

type TextInputProps = React.ComponentProps<'input'> & {
  label: string
}

const TextInput = forwardRef<HTMLInputElement, TextInputProps>(
  ({ label, ...props }, ref) => {
    return (
      <label>
        {label}
        <input ref={ref} {...props} />
      </label>
    )
  },
)
```

Первый generic - тип ref, второй - тип props.

## currentTarget иногда лучше ref

Для событий ref не всегда нужен:

```tsx
function Form() {
  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault()
    const formData = new FormData(event.currentTarget)
  }

  return <form onSubmit={handleSubmit} />
}
```

Если элемент нужен только внутри события, `event.currentTarget` проще.

## Что отвечать на собеседовании?

`useRef` типизируется типом значения в `.current`. Для DOM используют `useRef<HTMLInputElement>(null)`, для таймеров - `useRef<ReturnType<typeof setInterval> | null>(null)`, для mutable objects - конкретный тип объекта. Ref не вызывает rerender при изменении.

## Частые ошибки

- Использовать `any` для ref.
- Забывать, что DOM ref сначала `null`.
- Использовать `ref.current!` без проверки.
- Хранить в ref данные, от которых должен зависеть render.
- Типизировать browser timer как `number` в универсальном окружении.

## Мини-шпаргалка

- DOM: `useRef<HTMLInputElement>(null)`.
- Div: `useRef<HTMLDivElement>(null)`.
- Timer: `useRef<ReturnType<typeof setInterval> | null>(null)`.
- `.current` меняется без rerender.
- Для передачи ref используй `forwardRef`.
