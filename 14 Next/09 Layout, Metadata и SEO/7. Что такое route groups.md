# Что такое route groups?

> [!summary]
> Route groups - это папки в скобках, например `(marketing)` или `(dashboard)`, которые помогают группировать маршруты в App Router без добавления сегмента в URL. Они нужны для организации проекта, разных layout и нескольких root layouts.

## Как выглядит route group?

Обычная папка влияет на URL:

```text
app/
  dashboard/
    page.tsx
```

Маршрут будет:

```text
/dashboard
```

Папка в скобках не влияет на URL:

```text
app/
  (marketing)/
    about/
      page.tsx
```

Маршрут будет:

```text
/about
```

`(marketing)` нужен только для организации кода.

## Зачем нужны route groups?

### 1. Организация проекта

```text
app/
  (marketing)/
    page.tsx
    pricing/
      page.tsx
  (app)/
    dashboard/
      page.tsx
    settings/
      page.tsx
```

URL остается чистым:

```text
/
/pricing
/dashboard
/settings
```

Но внутри проекта видно, где публичные страницы, а где приложение.

### 2. Разные layout для разных групп

```text
app/
  (marketing)/
    layout.tsx
    page.tsx
    pricing/
      page.tsx
  (dashboard)/
    layout.tsx
    dashboard/
      page.tsx
```

`(marketing)/layout.tsx` может содержать публичную шапку и футер, а `(dashboard)/layout.tsx` - сайдбар кабинета и проверку авторизации.

## Пример

```tsx
// app/(marketing)/layout.tsx
export default function MarketingLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <>
      <Header />
      {children}
      <Footer />
    </>
  )
}
```

```tsx
// app/(dashboard)/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <DashboardShell>
      {children}
    </DashboardShell>
  )
}
```

## Несколько Root Layout

Через route groups можно создать несколько независимых root layouts:

```text
app/
  (shop)/
    layout.tsx
    page.tsx
  (admin)/
    layout.tsx
    admin/
      page.tsx
```

В таком случае у групп может быть разная HTML-оболочка. Это полезно, если части приложения сильно отличаются: например, публичный сайт и embedded admin-интерфейс.

Важно: навигация между разными root layouts может приводить к полной загрузке страницы, потому что меняется корневая оболочка документа.

## Ограничение: нельзя создавать одинаковые URL

Такой пример конфликтует:

```text
app/
  (marketing)/
    about/
      page.tsx
  (company)/
    about/
      page.tsx
```

Обе страницы дают один и тот же URL:

```text
/about
```

Next.js не сможет выбрать, какую страницу рендерить.

## Что отвечать на собеседовании?

Route groups - это папки в круглых скобках в App Router. Они не добавляются в URL, но помогают группировать маршруты, применять разные layout к разным частям приложения и создавать несколько root layouts. Их используют для архитектуры проекта, а не для изменения адресов страниц.

## Частые ошибки

- Думать, что `(dashboard)` появится в URL.
- Создавать одинаковые маршруты в разных route groups.
- Использовать route groups только ради красоты, когда структура и так понятна.
- Забывать, что layout внутри group применяется к маршрутам этой group.
- Не учитывать full page load при переходе между разными root layouts.

## Мини-шпаргалка

- `(group)` не попадает в URL.
- Route groups помогают организовать проект.
- Group может иметь свой `layout.tsx`.
- Через groups можно разделить публичную часть и приложение.
- Одинаковые URL в разных groups запрещены.
- Несколько root layouts возможны, но это архитектурное решение.
