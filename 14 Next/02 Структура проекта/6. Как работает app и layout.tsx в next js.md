# Как работает app и layout.tsx в next js?

> [!summary]
> Папка `app` задает App Router, а `layout.tsx` создает устойчивую оболочку route segment. Root layout обязателен для документа и должен возвращать `<html>` и `<body>`, а вложенные layouts сохраняют состояние между переходами внутри сегмента.

## Root layout

```tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  )
}
```

Root layout находится в `app/layout.tsx`.

Он отвечает за:

- HTML-документ;
- глобальные providers;
- шрифты;
- общую структуру;
- базовую metadata-настройку.

## Nested layout

```text
app/
  dashboard/
    layout.tsx
    page.tsx
    settings/
      page.tsx
```

`app/dashboard/layout.tsx` применится к:

- `/dashboard`;
- `/dashboard/settings`;
- всем вложенным routes внутри dashboard.

## Layout сохраняется

При переходе между дочерними страницами layout обычно не перемонтируется. Это полезно для:

- sidebar;
- tabs;
- player;
- scroll position внутри shell;
- открытого состояния навигации.

```tsx
export default function DashboardLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="dashboard">
      <Sidebar />
      <main>{children}</main>
    </div>
  )
}
```

## Layout получает children

`children` - место, куда Next.js вставляет текущий дочерний segment.

```tsx
export default function Layout({ children }: { children: React.ReactNode }) {
  return <section>{children}</section>
}
```

## Layout и Server Components

Layouts в App Router по умолчанию Server Components. Если layout должен использовать `useState`, `useEffect` или event handlers, придется сделать Client Component, но лучше не превращать root layout в client без необходимости.

## Что отвечать на собеседовании?

`app` управляет App Router, а `layout.tsx` задает persistent UI для route segment. Root layout должен содержать `<html>` и `<body>`. Вложенные layouts позволяют строить разные оболочки для разделов и сохраняют состояние между переходами.

## Частые ошибки

- Забывать `children`.
- Делать root layout Client Component без необходимости.
- Использовать layout там, где нужен `template.tsx`.
- Ожидать, что layout будет сбрасывать state при каждой навигации.
- Класть route-specific providers слишком высоко.

## Мини-шпаргалка

- `app/layout.tsx` - root layout.
- Root layout возвращает `<html>` и `<body>`.
- Nested layout применится к дочерним routes.
- Layout сохраняется между переходами.
- `children` - текущая страница/сегмент.
- Для reset при навигации есть `template.tsx`.
