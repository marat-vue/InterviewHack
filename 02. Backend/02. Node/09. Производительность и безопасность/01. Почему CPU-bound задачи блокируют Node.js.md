# Почему CPU-bound задачи блокируют Node.js?

> [!NOTE]
> Node.js хорошо работает с I/O-bound задачами, но тяжелые CPU-bound вычисления выполняются в основном JavaScript-потоке и могут блокировать event loop, задерживая обработку запросов, таймеров и callback-функций.

## I/O-bound vs CPU-bound

| Тип задачи | Пример | Node.js справляется? |
|---|---|---|
| I/O-bound | HTTP, БД, файлы, сеть | Да, это сильная сторона Node.js |
| CPU-bound | Сжатие, шифрование, парсинг огромного JSON, сложные вычисления | Может блокировать event loop |

## Пример блокировки

```js
import http from 'node:http';

function blockCpu(ms) {
  const end = Date.now() + ms;

  while (Date.now() < end) {
    // занятый цикл
  }
}

http.createServer((req, res) => {
  blockCpu(5000);
  res.end('done');
}).listen(3000);
```

Пока один запрос выполняет `blockCpu`, остальные ждут.

## Как решать?

Варианты:

- вынести вычисление в `worker_threads`;
- использовать отдельный сервис;
- использовать очередь задач;
- разбить работу на части;
- применять нативные или потоковые API, если они подходят.

## Собеседовательный ответ

Node.js не "однопоточный целиком". У него есть libuv, thread pool и возможности ОС. Но JavaScript-код в одном процессе обычно выполняется в одном основном потоке, поэтому тяжелая синхронная CPU-работа блокирует event loop.

## Мини-шпаргалка

- I/O-bound задачи - сильная сторона Node.js.
- CPU-bound задачи могут блокировать event loop.
- Блокировка event loop ухудшает latency всех запросов.
- Для вычислений используй workers, очереди или отдельные сервисы.
- Не запускай тяжелые циклы в HTTP-handler.
