# Что такое transparent reactivity?

> [!summary]
> Transparent reactivity - это идея, что компонент автоматически обновляется, когда меняется используемая им часть состояния. В Zustand это достигается через подписку selector: компонент не вызывает вручную render, а просто читает slice store.

## Простое объяснение

Компонент:

```jsx
const count = useCounterStore((state) => state.count)
```

Store:

```jsx
increment: () => set((state) => ({ count: state.count + 1 }))
```

Когда `count` меняется, компонент обновляется сам. Разработчик не вызывает:

```jsx
forceUpdate()
```

и не синхронизирует DOM вручную.

## Почему это transparent?

Потому что связь выглядит естественно:

```text
компонент читает значение -> значение изменилось -> компонент получил новый render
```

Компоненту не нужно знать детали подписки на store.

## В чем отличие от магии?

Это не магия: под капотом store хранит подписчиков и уведомляет их при изменении state. Selector выбирает значение, а Zustand решает, нужно ли обновлять компонент.

## Где могут быть проблемы?

- Компонент читает слишком большой slice.
- Selector возвращает новый объект каждый раз.
- Store содержит слишком много несвязанных данных.
- Derived values создают новые ссылки.
- Неправильная иммутабельность ломает ожидаемые обновления.

## Как сделать реактивность предсказуемой?

- Используй точные selectors.
- Разделяй stores по feature.
- Обновляй state иммутабельно.
- Не храни server state без стратегии кеша.
- Проверяй ререндеры в React DevTools.

## Мини-шпаргалка

- Transparent reactivity = UI обновляется при изменении используемого state.
- В Zustand это работает через selectors и подписки.
- Компонент не вызывает render вручную.
- Точность selector определяет точность обновлений.
- "Прозрачность" требует дисциплины в структуре store.
