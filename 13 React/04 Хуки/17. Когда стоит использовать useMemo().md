# Когда стоит использовать useMemo?

> [!summary]
> `useMemo` стоит использовать, когда есть реальная причина кешировать вычисление: оно дорогое, часто повторяется, мешает `memo`-оптимизации или создает нестабильную dependency для другого hook. Без измеримой пользы `useMemo` часто только усложняет код.

## Хороший сценарий: дорогое вычисление

```jsx
const visibleProducts = useMemo(() => {
  return products
    .filter(matchesQuery)
    .sort(compareByPrice)
}, [products, matchesQuery, compareByPrice])
```

Если список большой, фильтрация и сортировка могут быть заметными.

## Хороший сценарий: memo-компонент

```jsx
const chartData = useMemo(() => {
  return buildChartData(report)
}, [report])

return <Chart data={chartData} />
```

Если `Chart` обернут в `memo`, стабильный `data` может помочь не рендерить его лишний раз.

## Хороший сценарий: dependency другого hook

```jsx
const options = useMemo(() => ({
  serverUrl,
  roomId,
}), [serverUrl, roomId])

useEffect(() => {
  const connection = createConnection(options)
  connection.connect()
  return () => connection.disconnect()
}, [options])
```

Иногда лучше перенести объект прямо внутрь effect, но если объект нужен снаружи, `useMemo` может стабилизировать dependency.

## Плохой сценарий

```jsx
const sum = useMemo(() => a + b, [a, b])
```

Простое сложение не нуждается в мемоизации.

## Как принять решение?

Задай вопросы:

- Вычисление действительно дорогое?
- Компонент рендерится часто?
- Есть ли проблема в Profiler?
- Без стабильной ссылки ломается `memo`?
- Можно ли упростить структуру вместо мемоизации?

## Мини-шпаргалка

- `useMemo` нужен для дорогих вычислений и стабильных ссылок.
- Простые вычисления не мемоизируют.
- `useMemo` не должен исправлять баги.
- Для object dependencies часто лучше пересмотреть код effect.
- React Compiler снижает потребность в ручной мемоизации, но не отменяет понимания.
