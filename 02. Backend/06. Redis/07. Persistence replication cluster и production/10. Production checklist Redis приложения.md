# Production checklist Redis приложения

> [!NOTE]
> Redis production readiness - это не только `REDIS_URL`. Нужно проверить память, TTL, eviction, persistence, security, monitoring, backups, client lifecycle и failure behavior.

## Configuration

- `maxmemory` задан;
- `maxmemory-policy` соответствует роли Redis;
- persistence включена или осознанно выключена;
- `appendfsync` выбран осознанно;
- protected mode/network настроены;
- Redis не доступен публично из интернета.

## Keys and data model

- есть namespace;
- keys включают env/app/tenant, где нужно;
- временные keys имеют TTL;
- нет бесконечно растущих lists/streams/sets;
- есть trimming для Streams;
- нет big keys на hot path;
- Cluster hash tags используются только там, где нужны.

## Client

- singleton connection;
- отдельные Pub/Sub connections;
- error listener;
- reconnect/backoff strategy;
- timeouts;
- graceful shutdown;
- no client per request;
- metrics по errors/timeouts.

## Cache

- cache keys учитывают user/tenant/locale/permissions;
- TTL есть;
- jitter для hot keys;
- invalidation описана;
- Redis outage не ломает disposable cache;
- hit ratio мониторится.

## Reliability

- backups есть, если Redis хранит важные данные;
- restore проверен;
- replication/failover настроены;
- Sentinel/Cluster/managed HA выбран осознанно;
- Streams pending мониторится;
- workers idempotent;
- DLQ strategy есть.

## Security

- AUTH/ACL;
- TLS или private network;
- secrets в env/platform secrets;
- command/key permissions ограничены;
- logs не содержат secrets;
- Redis port не открыт публично.

## Observability

- `INFO memory`;
- `INFO clients`;
- `SLOWLOG`;
- latency;
- evictions;
- expired keys;
- hit/miss;
- stream lag;
- Pub/Sub reconnects.

## Мини-шпаргалка

- Memory limits до релиза.
- TTL для временных данных.
- No `KEYS *` в production.
- Backups только если проверен restore.
- Redis outage behavior должен быть явным.
- Security и monitoring обязательны.
