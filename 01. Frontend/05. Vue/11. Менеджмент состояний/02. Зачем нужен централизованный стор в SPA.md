# Зачем нужен централизованный стор в SPA?

> [!NOTE]
> Централизованный стор нужен, когда общее состояние должно быть доступно разным страницам и компонентам без длинного prop drilling.

## Вопрос

Зачем нужен централизованный стор в SPA?

## Проблема

В большом SPA одни и те же данные могут понадобиться в разных частях интерфейса.

```text
Header -> UserMenu
ProductPage -> AddToCartButton
CartSidebar -> CartTotal
CheckoutPage -> OrderSummary
```

Если передавать такие данные только props, появляются длинные цепочки и много промежуточного кода.

## Решение

Store хранит общее состояние отдельно от дерева компонентов.

```typescript
const cart = useCartStore();

cart.addItem(product);
```

Любой компонент, которому нужна корзина, может подключить store напрямую.

## Дополнительные плюсы

- Единый источник правды.
- Предсказуемые actions для изменения данных.
- Удобнее debug через devtools.
- Проще переиспользовать состояние между страницами.

## Риск

Центральный store не должен превращаться в свалку. Локальные UI-флаги, временные input values и состояние одного компонента лучше держать локально.

## Мини-шпаргалка

- Store нужен для общего состояния.
- Уменьшает prop drilling.
- Дает единый источник правды.
- Хорош для пользователя, корзины, прав, настроек.
- Локальные детали лучше не выносить.
