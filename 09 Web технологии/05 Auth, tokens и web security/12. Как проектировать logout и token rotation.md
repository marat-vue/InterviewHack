# Как проектировать logout и token rotation?

> [!summary]
> Logout должен не только удалить данные на клиенте, но и инвалидировать session или refresh token на сервере. Token rotation уменьшает риск повторного использования украденного refresh token.

## Плохой logout

```ts
localStorage.removeItem('accessToken');
```

Это очищает только browser storage. Если refresh token или session на сервере все еще валидны, пользователь или атакующий может получить новый access token.

## Хороший logout для session

```txt
POST /auth/logout
```

Server:

1. находит session по cookie;
2. удаляет session из store;
3. очищает cookie.

```http
Set-Cookie: sid=; Max-Age=0; Path=/; HttpOnly; Secure; SameSite=Lax
```

## Хороший logout для token pair

Server:

1. принимает refresh token;
2. инвалидирует refresh token или token family;
3. frontend очищает access token из memory/storage;
4. refresh endpoint больше не выдает новую пару.

## Refresh token rotation

```txt
refresh_1 -> выдать access_2 + refresh_2
refresh_1 -> становится недействительным
```

Если старый `refresh_1` используют повторно, это сигнал возможной кражи. Server может отозвать всю token family.

## Logout from all devices

Для "выйти на всех устройствах" нужно удалить все sessions или refresh tokens пользователя.

```txt
DELETE FROM sessions WHERE user_id = 42
```

или пометить все token families revoked.

## Мини-шпаргалка

- Logout должен затрагивать server-side state.
- Просто удалить token из frontend недостаточно.
- Session logout удаляет session и cookie.
- Refresh token нужно отзывать.
- Rotation помогает обнаружить replay украденного refresh token.
- Logout from all devices требует удаления всех sessions/tokens пользователя.
