# Vite в production и вопросы на собеседовании

> [!summary]
> Для production важно понимать `vite build`, code splitting, env modes, base path, sourcemaps, static hosting, preview, bundle analysis и отличие dev server от production server.

## Production build

```bash
npm run build
```

Обычно результат попадает в `dist/`.

```text
dist/
  index.html
  assets/
    index-abc123.js
    index-def456.css
```

Файлы получают hash для долгого кеширования.

## Preview

```bash
npm run preview
```

`preview` показывает production build локально. Это полезно для проверки, но не является полноценным production server для реального деплоя.

## base path

Если приложение деплоится не в корень домена:

```ts
export default defineConfig({
  base: '/frontend-app/',
})
```

Иначе assets могут грузиться с неправильных URL.

## Code splitting

Dynamic import помогает разделить bundle:

```tsx
const SettingsPage = lazy(() => import('./pages/SettingsPage'))
```

Vite/Rollup вынесет chunk отдельно.

## Sourcemap

```ts
export default defineConfig({
  build: {
    sourcemap: true,
  },
})
```

Sourcemaps помогают дебажить production ошибки, но их публикация должна соответствовать политике безопасности проекта.

## Частые вопросы

### Чем Vite dev отличается от build?

Dev использует native ESM и быстрый HMR. Build создает оптимизированные static assets для production.

### Что такое HMR?

Hot Module Replacement обновляет модуль в браузере без полной перезагрузки страницы и потери состояния, если это возможно.

### Что такое `VITE_` prefix?

Защитный механизм: в клиентский bundle попадают только env variables с prefix `VITE_`. Секреты нельзя хранить в frontend env.

### Можно ли деплоить Vite SPA на статический hosting?

Да, если backend не нужен для server rendering. Для client-side routes нужно настроить fallback на `index.html`.

## Частые ошибки

- Использовать dev server как production server.
- Хранить секреты в `VITE_*`.
- Не настроить fallback для SPA routes.
- Забыть `base` при деплое в подпапку.
- Не проверить production build через preview.
- Не синхронизировать aliases с TypeScript.

## Что отвечать на собеседовании?

Vite в production делает оптимизированную сборку static assets. Нужно понимать разницу между dev server и production build, работу env variables, static hosting fallback, code splitting через dynamic import, настройку `base`, sourcemaps и preview.

## Мини-шпаргалка

- `vite build` - production сборка.
- `vite preview` - локальная проверка build.
- `dist` - результат сборки.
- `base` - путь деплоя.
- Dynamic import - code splitting.
- Секреты не кладут в `VITE_*`.
