# Как отменить запрос внутри useEffect()?

> [!summary]
> Запрос внутри `useEffect` отменяют через cleanup-функцию. Для `fetch` стандартный способ - `AbortController`: создаем controller, передаем `signal` в `fetch`, а в cleanup вызываем `controller.abort()`.

## Базовый пример

```jsx
function UserPage({ userId }) {
  const [user, setUser] = useState(null)
  const [error, setError] = useState(null)

  useEffect(() => {
    const controller = new AbortController()

    async function loadUser() {
      try {
        const response = await fetch(`/api/users/${userId}`, {
          signal: controller.signal,
        })

        if (!response.ok) {
          throw new Error('Failed to load user')
        }

        const data = await response.json()
        setUser(data)
      } catch (error) {
        if (error.name === 'AbortError') {
          return
        }

        setError(error)
      }
    }

    loadUser()

    return () => {
      controller.abort()
    }
  }, [userId])
}
```

Когда `userId` изменится или компонент размонтируется, старый запрос будет отменен.

## Зачем отменять запрос?

Основные причины:

- пользователь ушел со страницы;
- пришел новый `userId`, старый ответ уже не нужен;
- нужно избежать race condition;
- не хочется тратить сеть на бесполезный запрос;
- cleanup должен корректно работать в Strict Mode.

## AbortController и AbortSignal

```js
const controller = new AbortController()

fetch('/api/data', {
  signal: controller.signal,
})

controller.abort()
```

`AbortSignal` можно использовать один раз. Если controller уже aborted, новый `fetch` с тем же signal сразу завершится ошибкой.

## Что делать с ошибкой AbortError?

Отмена запроса - не пользовательская ошибка.

```jsx
catch (error) {
  if (error.name === 'AbortError') {
    return
  }

  setError(error)
}
```

Не показывай пользователю "Произошла ошибка", если он просто перешел на другую страницу.

## Если API не поддерживает abort

Можно игнорировать устаревший результат:

```jsx
useEffect(() => {
  let ignore = false

  fetchUser(userId).then((user) => {
    if (!ignore) {
      setUser(user)
    }
  })

  return () => {
    ignore = true
  }
}, [userId])
```

Это не отменяет сеть, но защищает UI от старого ответа.

## Мини-шпаргалка

- Для `fetch` используй `AbortController`.
- `signal` передается в параметры `fetch`.
- В cleanup вызывай `controller.abort()`.
- `AbortError` обычно игнорируют.
- Для неподдерживаемых операций можно использовать флаг `ignore`.
