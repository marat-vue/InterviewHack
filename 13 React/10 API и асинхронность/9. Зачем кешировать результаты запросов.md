# Зачем кешировать результаты запросов?

> [!summary]
> Кеширование запросов позволяет переиспользовать уже полученные server data: быстрее показывать UI, уменьшать число запросов, избегать дублей и обновлять данные в фоне. Главная сложность кеша - не сохранить данные, а вовремя понять, когда они устарели.

## Что такое кеш запроса?

```text
queryKey -> cached data
```

Пример:

```text
['user', 42] -> { id: 42, name: 'Ada' }
['products', { page: 1 }] -> [...]
```

Когда другой компонент просит те же данные, библиотека может вернуть кеш мгновенно.

## Зачем это нужно?

Кеш помогает:

- ускорить повторный вход на страницу;
- убрать мигающие loaders;
- дедуплицировать одинаковые запросы;
- снизить нагрузку на API;
- показывать старые данные во время фонового refetch;
- поддерживать offline-like UX;
- синхронизировать несколько компонентов.

## Ручной кеш

```js
const cache = new Map()

async function fetchWithCache(key, request) {
  if (cache.has(key)) {
    return cache.get(key)
  }

  const data = await request()
  cache.set(key, data)
  return data
}
```

Так можно понять идею, но в реальном приложении быстро появляются вопросы:

- когда кеш устаревает;
- что делать после мутаций;
- как избежать race conditions;
- как повторять запросы;
- как обновлять при focus/reconnect;
- как чистить память.

## TanStack Query

```jsx
const { data, isLoading, isFetching } = useQuery({
  queryKey: ['user', userId],
  queryFn: () => fetchUser(userId),
  staleTime: 60_000,
})
```

`staleTime` говорит, сколько времени данные считаются свежими. Пока данные fresh, библиотека может не refetch-ить их без причины.

## SWR

SWR использует идею stale-while-revalidate:

```text
показать кеш -> запустить revalidation -> обновить UI свежими данными
```

```jsx
const { data, isLoading } = useSWR(`/api/users/${userId}`, fetcher)
```

## Мини-шпаргалка

- Кеш ускоряет повторное отображение данных.
- Query key должен точно описывать данные.
- Stale data не обязательно плохие данные.
- После мутаций кеш нужно инвалидировать или обновлять.
- Для server state лучше использовать специализированную библиотеку.
