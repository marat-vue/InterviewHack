# Как robots.txt влияет на crawling?

> [!summary]
> robots.txt - это файл с правилами обхода сайта для поисковых роботов. Он помогает управлять crawling, но не является надежным способом скрыть страницу из поиска и не удаляет URL из индекса.

## Где находится robots.txt?

Файл должен лежать в корне сайта:

```text
https://example.com/robots.txt
```

Для поддомена нужен свой файл:

```text
https://blog.example.com/robots.txt
```

## Как выглядит простой robots.txt?

```txt
User-agent: *
Disallow: /admin/
Disallow: /cart/
Allow: /

Sitemap: https://example.com/sitemap.xml
```

Здесь всем роботам запрещен обход `/admin/` и `/cart/`, а sitemap явно указан.

## Что важно понимать?

`Disallow` запрещает crawling, но не гарантирует отсутствие URL в выдаче.

Если на запрещенную страницу ведут внешние ссылки, поисковик может знать URL и показать его без нормального сниппета.

Для запрета индексации лучше использовать:

```html
<meta name="robots" content="noindex">
```

Но робот должен иметь возможность зайти на страницу и увидеть этот тег. Если страница закрыта в robots.txt, он может не увидеть `noindex`.

## Частые директивы

| Директива | Зачем нужна |
|---|---|
| `User-agent` | к какому роботу относится правило |
| `Disallow` | какой путь не обходить |
| `Allow` | какой путь разрешить внутри закрытой зоны |
| `Sitemap` | где лежит sitemap.xml |

## Пример с закрытием фильтров

```txt
User-agent: *
Disallow: /*?sort=
Disallow: /*?sessionId=
Allow: /

Sitemap: https://shop.example.com/sitemap.xml
```

Так можно уменьшить обход мусорных URL, но решение нужно проверять: иногда фильтры создают полезные посадочные страницы.

## Мини-шпаргалка

- robots.txt управляет обходом, а не индексацией.
- Не закрывай важные CSS, JS и изображения, если они нужны для рендера.
- Для удаления из индекса нужен `noindex`, удаление URL или корректный статус.
- robots.txt должен быть доступен по корню домена.
- После изменения проверяй файл в Search Console.
