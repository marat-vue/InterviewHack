# Что такое плоское состояние (flat state)?

> [!summary]
> Плоское состояние - это структура state без лишней глубокой вложенности и дублирования. Чем проще форма state, тем легче обновлять данные, избегать рассинхронизации и поддерживать компоненты.

## Пример слишком вложенного state

```jsx
const [project, setProject] = useState({
  id: 1,
  settings: {
    permissions: {
      users: {
        anna: {
          canEdit: true,
        },
      },
    },
  },
})
```

Обновление `canEdit` потребует копировать много уровней.

## Более плоский вариант

```jsx
const [permissionsByUserId, setPermissionsByUserId] = useState({
  anna: { canEdit: true },
})
```

Теперь обновление проще:

```jsx
setPermissionsByUserId((permissions) => ({
  ...permissions,
  anna: {
    ...permissions.anna,
    canEdit: false,
  },
}))
```

## Что значит нормализовать state?

Нормализация - это хранение сущностей по id:

```jsx
const [state, setState] = useState({
  usersById: {
    1: { id: 1, name: 'Анна' },
    2: { id: 2, name: 'Борис' },
  },
  userIds: [1, 2],
})
```

Так удобнее обновлять конкретную сущность и не дублировать ее в разных местах.

## Почему дублирование опасно?

Плохо:

```jsx
const [selectedUser, setSelectedUser] = useState(user)
const [users, setUsers] = useState([user])
```

Если пользователь обновится в `users`, `selectedUser` может остаться старым.

Лучше хранить id:

```jsx
const [selectedUserId, setSelectedUserId] = useState(user.id)
const selectedUser = users.find((user) => user.id === selectedUserId)
```

## Мини-шпаргалка

- Flat state легче обновлять.
- Избегай лишней глубокой вложенности.
- Не дублируй одни и те же данные в нескольких state.
- Часто лучше хранить `selectedId`, а не весь объект.
- Нормализация полезна для списков сущностей.
