# Почему proxy быстрее defineProperty?

> [!NOTE]
> `Proxy` в Vue 3 часто эффективнее подхода на `Object.defineProperty`, потому что он перехватывает операции с объектом целиком и позволяет Vue ленивее и точнее строить реактивность. Но это не значит, что `Proxy` быстрее в любой отдельной операции JavaScript.

## Контекст

Vue 2 строил реактивность через `Object.defineProperty`. Для каждого свойства объекта Vue создавал getter и setter.

```js
Object.defineProperty(user, "name", {
  get() {
    track();
    return value;
  },
  set(nextValue) {
    value = nextValue;
    trigger();
  },
});
```

Vue 3 использует `Proxy`, который оборачивает объект целиком.

```js
const reactiveUser = new Proxy(user, {
  get(target, key) {
    track(target, key);
    return target[key];
  },
  set(target, key, value) {
    target[key] = value;
    trigger(target, key);
    return true;
  },
});
```

## Главное отличие

`defineProperty` работает на уровне конкретного свойства. `Proxy` работает на уровне операций с объектом.

| Возможность | `Object.defineProperty` | `Proxy` |
| --- | --- | --- |
| Перехват чтения свойства | Да | Да |
| Перехват записи свойства | Да | Да |
| Перехват добавления нового свойства | Ограниченно | Да |
| Перехват удаления свойства | Ограниченно | Да |
| Перехват `in`, `ownKeys`, итераций | Нет или неудобно | Да |
| Работа с массивами | Нужны обходные пути | Естественнее |

## Почему Vue 3 получает преимущество

### Ленивое создание реактивности

Vue 2 должен был заранее пройтись по свойствам объекта и превратить их в getter/setter.

```js
const state = {
  user: {
    profile: {
      name: "Анна",
    },
  },
};
```

В подходе с `Proxy` вложенные объекты можно оборачивать лениво: только когда код реально к ним обращается.

### Новые свойства отслеживаются естественно

В Vue 2 добавление нового свойства было проблемным сценарием.

```js
user.age = 28;
```

С `Proxy` операция `set` перехватывается даже для нового ключа, поэтому реактивная система видит изменение.

### Массивы требуют меньше специальных обходов

Операции вроде `push`, изменения `length` и обращения по индексу проще отслеживать через прокси-ловушки.

```js
items.push(newItem);
items.length = 0;
```

## Важная оговорка

`Proxy` не является магически быстрее во всех микробенчмарках. Его преимущество для Vue в архитектуре реактивности: меньше предварительной работы, лучшее покрытие операций и меньше специальных API для крайних случаев.

## Практический вывод

Во Vue 3 можно писать естественный JavaScript и ожидать, что реактивность увидит добавление, удаление и изменение свойств.

```js
const user = reactive({
  name: "Анна",
});

user.age = 28;
delete user.name;
```

Такие операции хорошо ложатся на модель `Proxy`.

## Мини-шпаргалка

- `defineProperty` перехватывает доступ к отдельным свойствам.
- `Proxy` перехватывает операции с объектом целиком.
- Vue 3 может лениво оборачивать вложенные объекты.
- Добавление и удаление свойств отслеживаются естественнее.
- Главное преимущество `Proxy` - не чистая скорость каждой операции, а более гибкая и полная модель реактивности.
