# Как работает Redis replication?

> [!NOTE]
> Redis replication копирует данные с primary на replicas. Это нужно для high availability, read scaling и failover-сценариев, но replication обычно asynchronous, поэтому возможна потеря последних writes при падении primary.

## Что такое primary и replica?

```txt
primary -> replica 1
        -> replica 2
```

Primary принимает writes. Replicas получают копии данных.

## Зачем replication?

- failover;
- read replicas;
- backup без нагрузки на primary;
- географическое приближение reads;
- maintenance.

## Как настроить replica?

В `redis.conf`:

```txt
replicaof 127.0.0.1 6379
```

Или командой:

```redis
REPLICAOF 127.0.0.1 6379
```

## Как проверить replication?

```redis
INFO replication
```

Смотри:

- `role`;
- `connected_slaves` / replicas;
- replication offset;
- replication lag;
- link status.

## Что значит async replication?

Primary может подтвердить write клиенту до того, как replica получила это write. Если primary упадет сразу после подтверждения, promoted replica может не иметь последних данных.

Для cache это обычно ок. Для critical data нужно понимать риск.

## Read from replicas

Replicas могут разгружать reads, но:

- данные могут отставать;
- read-after-write consistency не гарантирована;
- не все клиенты прозрачно маршрутизируют reads.

## Мини-шпаргалка

- Replication копирует primary на replicas.
- Обычно replication async.
- Возможен replication lag.
- Failover требует Sentinel/Cluster/managed provider.
- Read replicas могут отдавать stale data.
