# Что такое layout в Next.js?

> [!summary]
> `layout.tsx` в App Router - это специальный файл маршрутизации, который задает общую оболочку для страницы или группы страниц. Он принимает `children`, оборачивает вложенный контент и сохраняется между переходами внутри своего сегмента маршрута.

## Зачем нужен layout?

В обычном React-приложении общую шапку, меню или сайдбар часто подключают вручную:

```tsx
export default function DashboardPage() {
  return (
    <>
      <Header />
      <Sidebar />
      <main>Dashboard</main>
    </>
  )
}
```

В Next.js App Router эту задачу берет на себя файл `layout.tsx`:

```tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <section>
      <aside>Навигация кабинета</aside>
      <main>{children}</main>
    </section>
  )
}
```

Все страницы внутри `app/dashboard` автоматически попадут в `children`.

## Как layout связан со структурой папок?

```text
app/
  layout.tsx
  page.tsx
  dashboard/
    layout.tsx
    page.tsx
    settings/
      page.tsx
```

Для страницы `/dashboard/settings` Next.js соберет цепочку так:

```tsx
<RootLayout>
  <DashboardLayout>
    <SettingsPage />
  </DashboardLayout>
</RootLayout>
```

То есть layout не импортируется в страницу вручную. Он подключается по файловой структуре.

## Какие свойства есть у layout?

- Он является Server Component по умолчанию.
- Он должен возвращать React-элементы и обязательно рендерить `children`.
- Он сохраняется при навигации между вложенными страницами.
- Он может быть вложенным: каждый сегмент маршрута может иметь свой `layout.tsx`.
- Root Layout в `app/layout.tsx` обязан содержать теги `<html>` и `<body>`.
- Layout может экспортировать `metadata` или `generateMetadata`.

## Пример Root Layout

```tsx
// app/layout.tsx
import type { Metadata } from 'next'
import './globals.css'

export const metadata: Metadata = {
  title: 'Frontend Notes',
  description: 'База знаний по frontend-разработке',
}

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  )
}
```

## Важный нюанс

Layout не должен быть местом для всего подряд. Чем выше layout расположен в дереве, тем больше страниц он оборачивает. Поэтому в `app/layout.tsx` обычно кладут только глобальные вещи: шрифты, базовые стили, провайдеры, общую HTML-структуру и глобальные метаданные.

Разделы вроде админки, кабинета пользователя или блога лучше оформлять отдельными вложенными layout.

## Что отвечать на собеседовании?

Layout в Next.js - это файловая конвенция App Router для создания общей оболочки маршрутов. Он автоматически оборачивает страницы своего сегмента, получает `children`, сохраняется между переходами и позволяет строить вложенную структуру интерфейса без ручного импорта общей разметки в каждую страницу.

## Частые ошибки

- Пытаться импортировать `layout.tsx` вручную в `page.tsx`.
- Забывать отрендерить `children`.
- Делать Root Layout без `<html>` и `<body>`.
- Помещать всю логику приложения в корневой layout.
- Делать layout клиентским компонентом без необходимости.
- Ожидать, что layout будет заново монтироваться при каждом переходе внутри сегмента.

## Мини-шпаргалка

- `layout.tsx` - общая оболочка маршрута.
- `children` - вложенная страница или следующий layout.
- Layout подключается по папкам, а не через import.
- Root Layout находится в `app/layout.tsx`.
- Layout по умолчанию является Server Component.
- Вложенные layout позволяют строить разные оболочки для разных разделов.
