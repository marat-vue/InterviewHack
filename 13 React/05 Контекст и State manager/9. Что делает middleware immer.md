# Что делает middleware immer в Zustand?

> [!summary]
> Middleware `immer` позволяет писать обновления Zustand state так, будто ты мутируешь объект, но на выходе создается новое иммутабельное состояние. Это особенно удобно для вложенных структур, но не отменяет понимания иммутабельности.

## Проблема без Immer

```jsx
const useStore = create((set) => ({
  user: {
    profile: {
      name: 'Анна',
    },
  },
  rename: (name) =>
    set((state) => ({
      user: {
        ...state.user,
        profile: {
          ...state.user.profile,
          name,
        },
      },
    })),
}))
```

Чем глубже объект, тем больше копирования.

## Пример с immer middleware

```jsx
import { create } from 'zustand'
import { immer } from 'zustand/middleware/immer'

const useStore = create(
  immer((set) => ({
    user: {
      profile: {
        name: 'Анна',
      },
    },
    rename: (name) =>
      set((state) => {
        state.user.profile.name = name
      }),
  }))
)
```

Код выглядит как мутация, но Immer создает новое состояние.

## Что важно понимать?

Внутри `immer` ты работаешь с draft:

```text
draft выглядит изменяемым, но результат остается иммутабельным
```

Это удобно, но может скрыть стоимость сложных обновлений. Не стоит делать state глубже только потому, что Immer позволяет писать короче.

## Когда middleware immer полезен?

- Сложные вложенные объекты.
- Большие формы.
- Редактирование nested settings.
- Reducer-like store.
- Команда уже использует Immer в проекте.

## Когда можно без него?

- Простые stores.
- Плоское состояние.
- Несколько boolean/string/number полей.
- Обновления легко пишутся через spread/map/filter.

## Мини-шпаргалка

- `immer` позволяет писать draft-мутации.
- На выходе получается новое иммутабельное состояние.
- Полезен для вложенных структур.
- Не нужен для простых stores.
- Immer не заменяет понимание иммутабельности.
