# Как поднимать pgAdmin, RedisInsight, Mailpit, MinIO и другие сервисы?

> [!NOTE]
> В реальном Nuxt/Nitro backend-е кроме Postgres и Redis часто нужны инструменты вокруг: UI для базы, UI для Redis, SMTP sandbox, S3-compatible storage, search engine. Их удобно держать в Compose profiles, чтобы они не стартовали всегда.

## Зачем profiles?

Без profiles каждый `docker compose up` будет поднимать все:

- приложение;
- Postgres;
- Redis;
- pgAdmin;
- RedisInsight;
- Mailpit;
- MinIO;
- Meilisearch;
- лишние debug tools.

С profiles можно запускать optional tools только когда они нужны:

```bash
docker compose --profile tools up
docker compose --profile mail up mailpit
docker compose --profile storage up minio
```

## pgAdmin для PostgreSQL

```yaml
services:
  pgadmin:
    image: dpage/pgadmin4
    environment:
      PGADMIN_DEFAULT_EMAIL: admin@example.com
      PGADMIN_DEFAULT_PASSWORD: admin
    ports:
      - "5050:80"
    depends_on:
      db:
        condition: service_healthy
    profiles:
      - tools
```

Подключение внутри pgAdmin:

```text
Host: db
Port: 5432
Database: app
User: app
Password: secret
```

Не `localhost`, потому что pgAdmin тоже container.

## RedisInsight

```yaml
services:
  redisinsight:
    image: redis/redisinsight:latest
    ports:
      - "5540:5540"
    depends_on:
      redis:
        condition: service_healthy
    profiles:
      - tools
```

Подключение:

```text
Host: redis
Port: 6379
```

## Mailpit для email в dev

```yaml
services:
  mailpit:
    image: axllent/mailpit
    ports:
      - "8025:8025"
      - "1025:1025"
    profiles:
      - mail
```

Env для Nuxt/Nitro:

```env
SMTP_HOST=mailpit
SMTP_PORT=1025
```

UI:

```text
http://localhost:8025
```

## MinIO для S3-compatible storage

```yaml
services:
  minio:
    image: minio/minio
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minio
      MINIO_ROOT_PASSWORD: miniosecret
    volumes:
      - miniodata:/data
    ports:
      - "9000:9000"
      - "9001:9001"
    profiles:
      - storage

volumes:
  miniodata:
```

Env для приложения:

```env
S3_ENDPOINT=http://minio:9000
S3_ACCESS_KEY_ID=minio
S3_SECRET_ACCESS_KEY=miniosecret
S3_BUCKET=uploads
S3_FORCE_PATH_STYLE=true
```

Для AWS SDK внутри container endpoint будет `http://minio:9000`, а с host - `http://localhost:9000`.

## Meilisearch для поиска

```yaml
services:
  meilisearch:
    image: getmeili/meilisearch:v1.16
    environment:
      MEILI_MASTER_KEY: dev-master-key
    volumes:
      - meili_data:/meili_data
    ports:
      - "7700:7700"
    profiles:
      - search

volumes:
  meili_data:
```

Env:

```env
MEILISEARCH_HOST=http://meilisearch:7700
MEILISEARCH_API_KEY=dev-master-key
```

## Как это связать с Nuxt service?

```yaml
services:
  app:
    environment:
      SMTP_HOST: mailpit
      SMTP_PORT: 1025
      S3_ENDPOINT: http://minio:9000
      MEILISEARCH_HOST: http://meilisearch:7700
```

Если optional service не запущен, app не должен падать при старте, если функция optional. Для обязательной зависимости добавляй `depends_on`.

## Что нельзя делать в production?

- Оставлять pgAdmin/RedisInsight открытыми в интернет.
- Использовать dev passwords.
- Публиковать admin tools без VPN/auth.
- Держать MinIO dev credentials.
- Поднимать debug tools в том же production Compose без профилей и access control.

## Что отвечать на собеседовании?

Дополнительные сервисы в Docker Compose лучше включать через profiles. Например, Postgres и Redis нужны почти всегда, а pgAdmin, RedisInsight, Mailpit, MinIO и search engine можно запускать только для dev/debug сценариев. Между контейнерами используются service names: `db`, `redis`, `mailpit`, `minio`, `meilisearch`.

## Частые ошибки

- Подключаться из pgAdmin к `localhost` вместо `db`.
- Всегда стартовать heavy tools.
- Открывать admin UI наружу в production.
- Хранить dev credentials в production `.env`.
- Делать optional dependency обязательной без fallback.
- Забывать volumes для stateful tools.

## Мини-шпаргалка

- pgAdmin -> `db:5432`.
- RedisInsight -> `redis:6379`.
- Mailpit SMTP -> `mailpit:1025`.
- MinIO internal -> `minio:9000`.
- Profiles -> optional startup.
- Production admin UI -> только с защитой.
