# Что делает useLocation()?

> [!summary]
> `useLocation` возвращает объект текущего location из React Router. Через него можно узнать `pathname`, `search`, `hash`, `state` и реагировать на смену маршрута внутри компонента.

## Что возвращает location?

```jsx
const location = useLocation()
```

Типичные поля:

```text
pathname -> "/products"
search   -> "?page=2&sort=price"
hash     -> "#reviews"
state    -> данные, переданные при navigate/link
key      -> уникальный ключ записи history
```

## Пример: показать текущий путь

```jsx
import { useLocation } from 'react-router-dom'

function CurrentPath() {
  const location = useLocation()

  return <p>Current path: {location.pathname}</p>
}
```

Компонент обновится при изменении location.

## Пример: аналитика

```jsx
function AnalyticsTracker() {
  const location = useLocation()

  useEffect(() => {
    analytics.pageView(location.pathname + location.search)
  }, [location.pathname, location.search])

  return null
}
```

Такой компонент можно положить рядом с routes.

## Пример: location.state

Переход:

```jsx
navigate('/profile', {
  state: { fromLogin: true },
})
```

Чтение:

```jsx
function ProfilePage() {
  const location = useLocation()

  return location.state?.fromLogin
    ? <p>Welcome back</p>
    : <p>Profile</p>
}
```

`location.state` не стоит использовать для важных данных, которые должны переживать reload или шариться ссылкой. Для этого лучше URL params, query params или store/server.

## useLocation vs window.location

`window.location` показывает адрес браузера, но не является React-aware источником. `useLocation` связан с Router и вызывает обновление компонента при навигации.

## Мини-шпаргалка

- `useLocation` читает текущий route.
- Для изменения route нужен `useNavigate`.
- Query string лежит в `location.search`.
- Временные данные лежат в `location.state`.
- Для query чаще удобнее `useSearchParams`.
