# Как изучать Zustand

> [!summary]
> Zustand стоит изучать как небольшой, но очень практичный state manager для client-side state. Главная цель - понять store, selector, action, middleware, persist и правила оптимизации подписок.

## Что такое Zustand?

Zustand - легковесная библиотека управления состоянием для React. Она позволяет создать store вне компонентов и читать из него только нужные поля.

```tsx
import { create } from 'zustand'

type CounterStore = {
  count: number
  increment: () => void
}

export const useCounterStore = create<CounterStore>()((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
}))
```

Использование:

```tsx
function Counter() {
  const count = useCounterStore((state) => state.count)
  const increment = useCounterStore((state) => state.increment)

  return <button onClick={increment}>{count}</button>
}
```

## Что нужно знать по порядку?

1. Что такое client-side state.
2. Как создать store через `create`.
3. Как читать данные через selector.
4. Как описывать actions.
5. Почему не стоит подписываться на весь store.
6. Как работает `persist`.
7. Как использовать `devtools`, `immer`, `subscribeWithSelector`.
8. Как типизировать store.
9. Когда Zustand лучше Context, а когда нет.

## Где Zustand особенно полезен?

- UI-state: sidebar, modal, filters, selected tab.
- Cross-page state в SPA.
- Простые глобальные настройки.
- Состояние редакторов, конструкторов, dashboards.
- Локальные client-only кэши, не являющиеся server state.

## Где Zustand не нужен?

Zustand не должен заменять TanStack Query для server state:

```tsx
// Не лучший вариант: руками хранить server cache в Zustand
const useUsersStore = create((set) => ({
  users: [],
  loadUsers: async () => {
    const users = await fetch('/api/users').then((r) => r.json())
    set({ users })
  },
}))
```

Для данных сервера обычно лучше `useQuery`, потому что там уже есть кеш, stale time, retries, refetch, invalidation и mutation lifecycle.

## Что отвечать на собеседовании?

Zustand - минималистичный state manager, где store создается через `create`, состояние читается через hook, а ререндеры контролируются selectors. Он хорош для client-side state, но server state лучше хранить в TanStack Query или похожем инструменте.

## Мини-шпаргалка

- `create` создает store.
- `set` обновляет состояние.
- `get` читает текущее состояние внутри actions.
- selector выбирает часть store.
- `persist` сохраняет state в storage.
- Zustand не заменяет server-state cache.
