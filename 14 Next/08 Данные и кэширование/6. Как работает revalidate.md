# Как работает revalidate?

> [!summary]
> `revalidate` задает, когда кешированные данные или route могут обновляться. В Next.js есть time-based revalidation через число секунд и on-demand revalidation через `revalidatePath` или `revalidateTag`.

## Time-based revalidate

```tsx
export const revalidate = 60
```

Это означает: route может обновляться не чаще, чем раз в 60 секунд.

Для конкретного `fetch`:

```tsx
await fetch('https://api.example.com/posts', {
  next: { revalidate: 60 },
})
```

## Как это выглядит для пользователя?

Упрощенно:

1. Данные попали в cache.
2. Пока 60 секунд не прошло, пользователи получают кеш.
3. После истечения времени следующий запрос может инициировать обновление.
4. Новые пользователи получают обновленную версию после regeneration.

Важно: revalidation не всегда означает, что уже открытая вкладка сама мгновенно изменится.

## On-demand revalidation

```ts
'use server'

import { revalidatePath } from 'next/cache'

export async function createPost(formData: FormData) {
  await savePost(formData)
  revalidatePath('/blog')
}
```

По тегу:

```tsx
await fetch('https://api.example.com/posts', {
  next: { tags: ['posts'] },
})
```

```ts
revalidateTag('posts')
```

## Что отвечать на собеседовании?

`revalidate` управляет свежестью кеша. Time-based revalidation обновляет данные по времени, а `revalidatePath` и `revalidateTag` позволяют инвалидировать кеш после события, например после Server Action.

## Частые ошибки

- Путать revalidation с polling.
- Ожидать мгновенного обновления всех открытых вкладок.
- Не тегировать fetch, который потом нужно обновить.
- Использовать `no-store` вместо разумного revalidate.
- Не обновлять кеш после mutation.

## Мини-шпаргалка

- `revalidate = 60` - route-level.
- `next.revalidate` - fetch-level.
- `revalidatePath` - обновить path.
- `revalidateTag` - обновить tagged data.
- `no-store` - без кеширования.
- Revalidation не равна real-time.
