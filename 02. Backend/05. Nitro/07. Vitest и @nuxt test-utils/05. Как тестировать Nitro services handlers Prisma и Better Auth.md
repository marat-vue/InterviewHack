# Как тестировать Nitro services, handlers, Prisma и Better Auth?

> [!NOTE]
> Nitro backend лучше тестировать слоями: чистые services unit-тестами, Prisma repositories integration-тестами с test database, handlers через runtime/e2e, Better Auth через mounted endpoints и session checks.

## Слои тестирования

```txt
unit
  -> pure functions
  -> permissions
  -> validation
  -> services with mocks

integration
  -> Prisma repositories
  -> Nitro handlers
  -> Better Auth endpoints

e2e
  -> real Nuxt/Nitro app
  -> browser/session/cookies
```

## Service test

```ts
it('creates user', async () => {
  const repo = {
    create: vi.fn().mockResolvedValue({
      id: 'u1',
      email: 'a@example.com',
    }),
  };

  const service = createUserService({ repo });

  const user = await service.create({
    email: 'a@example.com',
  });

  expect(repo.create).toHaveBeenCalledWith({
    email: 'a@example.com',
  });
  expect(user.id).toBe('u1');
});
```

## Prisma integration test

```ts
import { afterEach, expect, it } from 'vitest';
import { prisma } from '../server/utils/prisma';

afterEach(async () => {
  await prisma.user.deleteMany();
});

it('stores user', async () => {
  const user = await prisma.user.create({
    data: {
      email: `u-${crypto.randomUUID()}@example.com`,
    },
  });

  expect(user.id).toBeTruthy();
});
```

Для production-like confidence лучше использовать PostgreSQL test database, если production тоже PostgreSQL.

## Handler test strategy

Handler можно тестировать несколькими способами:

- вынести бизнес-логику в service и unit-test service;
- поднять Nuxt/Nitro через `@nuxt/test-utils/e2e` и дернуть `$fetch`;
- использовать runtime utilities в Nuxt component/server tests;
- создать H3 app вручную для standalone integration tests.

Чем ближе к HTTP/cookies/routeRules, тем полезнее integration/e2e test.

## Better Auth test strategy

Better Auth лучше тестировать как integration:

```txt
setup test app
  -> signUp/signIn через auth endpoint/client
  -> проверить Set-Cookie/session
  -> вызвать protected route
  -> signOut
```

Unit-тестировать внутренности Better Auth не нужно. Тестируй свою конфигурацию и свои guards.

## Guard test с mock session

```ts
vi.mock('../server/utils/auth', () => ({
  auth: {
    api: {
      getSession: vi.fn(),
    },
  },
}));
```

Затем проверяй:

- без session -> `401`;
- user без role -> `403`;
- admin -> success;
- owner -> success.

## Что обязательно тестировать?

- validation schemas;
- permission logic;
- Prisma unique conflicts;
- `404` mapping;
- protected routes;
- auth session check;
- pagination params;
- dangerous filters/sorting allowlist;
- webhook signature checks.

## Мини-шпаргалка

- Services тестируются быстро с mocks.
- Prisma тестируется с test database.
- Handlers лучше тестировать через runtime/e2e, если важны HTTP details.
- Better Auth тестируй через mounted endpoints и свои guards.
- Не тестируй чужую библиотеку, тестируй свою интеграцию.
