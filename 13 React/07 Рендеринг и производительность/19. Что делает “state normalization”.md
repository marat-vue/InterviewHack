# Что делает “state normalization”?

> [!summary]
> State normalization - это хранение связанных сущностей в плоском виде: отдельно по типам и по `id`. Такой подход уменьшает дублирование, упрощает обновления и помогает точнее перерисовывать UI.

## Проблема вложенного state

```jsx
const state = {
  posts: [
    {
      id: 1,
      title: 'React',
      author: { id: 10, name: 'Ada' },
      comments: [
        { id: 100, text: 'Great', author: { id: 11, name: 'Lin' } },
      ],
    },
  ],
}
```

Проблемы:

- автор может дублироваться в нескольких местах;
- сложно обновить одно поле глубоко внутри;
- легко случайно мутировать state;
- трудно понять, какие компоненты должны обновиться;
- тяжелее делать memoized selectors.

## Нормализованный state

```jsx
const state = {
  posts: {
    byId: {
      1: { id: 1, title: 'React', authorId: 10, commentIds: [100] },
    },
    allIds: [1],
  },
  users: {
    byId: {
      10: { id: 10, name: 'Ada' },
      11: { id: 11, name: 'Lin' },
    },
    allIds: [10, 11],
  },
  comments: {
    byId: {
      100: { id: 100, text: 'Great', authorId: 11 },
    },
    allIds: [100],
  },
}
```

Теперь каждая сущность хранится один раз, а связи выражаются через id.

## Как читать нормализованные данные?

Через selector:

```jsx
function selectPostViewModel(state, postId) {
  const post = state.posts.byId[postId]
  const author = state.users.byId[post.authorId]
  const comments = post.commentIds.map((id) => {
    const comment = state.comments.byId[id]

    return {
      ...comment,
      author: state.users.byId[comment.authorId],
    }
  })

  return { ...post, author, comments }
}
```

UI получает удобную структуру, а store остается плоским.

## Почему это помогает производительности?

Если изменился `comments.byId[100]`, не нужно пересоздавать весь `posts` массив и все вложенные объекты.

Компоненты можно подписывать точнее:

```jsx
const comment = useStore((state) => state.comments.byId[commentId])
```

Так обновится конкретный комментарий, а не вся лента.

## Когда normalization нужна?

Используй, если:

- данные имеют связи;
- есть дублирование;
- сущности часто обновляются;
- есть большие списки;
- важно точное кеширование и инвалидация.

Не усложняй, если данные маленькие, одноразовые и не имеют отношений.

## Мини-шпаргалка

- Нормализация похожа на таблицы в базе данных.
- Сущности хранятся по `id`.
- Связи хранятся как `authorId`, `commentIds`.
- Selector собирает данные в удобный view model.
- Подход полезен для больших и связанных данных.
