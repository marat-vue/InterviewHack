# Как Vite обрабатывает assets и public?

> [!summary]
> Vite различает assets внутри `src` и файлы в `public`. Assets из `src` проходят через bundler, могут получить hash и оптимизированный URL. Файлы из `public` копируются как есть и доступны от корня сайта.

## Assets внутри src

```vue
<template>
  <img src="@/assets/logo.svg" alt="Logo" />
</template>
```

или:

```typescript
import logoUrl from "@/assets/logo.svg";
```

Vite обработает import и в production может выдать URL с hash:

```txt
/assets/logo-91ab2.svg
```

## public

```txt
public/
  robots.txt
  favicon.svg
  images/og-image.png
```

Доступ:

```html
<img src="/images/og-image.png" alt="" />
```

Файлы из `public` не проходят через module graph и не получают hash от Vite.

## Когда использовать src/assets?

- images внутри компонентов;
- icons;
- fonts, которые импортируются из CSS;
- assets, которые должны получить hash;
- assets, связанные с кодом.

## Когда использовать public?

- `robots.txt`;
- favicon;
- static files с фиксированным URL;
- files, на которые ссылается внешний сервис;
- assets, которые не нужно импортировать из JS/CSS.

## CSS url

```css
.logo {
  background-image: url("@/assets/logo.svg");
}
```

Vite также умеет обрабатывать asset references из CSS.

## Мини-шпаргалка

- `src/assets` проходит через Vite processing.
- `public` копируется как есть.
- Assets из `src` могут получить hash.
- Public files доступны от root path.
- Для component images обычно лучше `src/assets`.
- Для fixed URLs лучше `public`.
