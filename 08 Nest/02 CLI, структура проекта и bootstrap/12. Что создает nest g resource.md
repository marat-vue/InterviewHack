# Что создает nest g resource?

> [!summary]
> `nest g resource` генерирует стартовый набор файлов для фичи: module, controller, service, DTO, entity и тестовые файлы. Это хороший учебный способ увидеть, как NestJS ожидает раскладывать CRUD-фичу.

## Команда

```bash
nest g resource users
```

CLI обычно спросит transport layer и нужен ли CRUD entry points.

## Пример результата

```txt
src/users/
  dto/
    create-user.dto.ts
    update-user.dto.ts
  entities/
    user.entity.ts
  users.controller.ts
  users.controller.spec.ts
  users.module.ts
  users.service.ts
  users.service.spec.ts
```

## Как читать сгенерированное?

- `users.module.ts` показывает регистрацию фичи;
- `users.controller.ts` показывает routes;
- `users.service.ts` показывает методы use case;
- `dto` показывает input contract;
- `entities` показывает модель;
- `*.spec.ts` показывает тестовый каркас.

## Важно

Generated resource - стартовая точка, а не идеальная архитектура для любого проекта. По мере роста фичи можно выделить repository, mapper, policies, use cases.

## Мини-шпаргалка

- `nest g resource` удобен для обучения.
- Он показывает стандартную связку module/controller/service/DTO.
- CRUD skeleton нужно адаптировать под бизнес-логику.
- Не все фичи обязаны быть CRUD.
- Generated code стоит читать, а не просто принимать как магию.
