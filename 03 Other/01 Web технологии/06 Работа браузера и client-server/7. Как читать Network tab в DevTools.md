# Как читать Network tab в DevTools?

> [!summary]
> Network tab - главный инструмент для диагностики client-server проблем. В нем видно, ушел ли request, какие headers отправлены, какие cookies приложились, был ли preflight, откуда взялся response и сколько времени занял каждый этап.

## Базовый чеклист

1. Найди нужный request.
2. Проверь method и URL.
3. Проверь status code.
4. Проверь request headers.
5. Проверь payload.
6. Проверь response headers.
7. Проверь response body.
8. Проверь cookies.
9. Проверь timing и cache source.

## Что значит status `(blocked:cors)`?

Browser заблокировал response из-за CORS. Нужно смотреть:

- `Origin`;
- `Access-Control-Allow-Origin`;
- `Access-Control-Allow-Credentials`;
- preflight `OPTIONS`;
- allowed methods;
- allowed headers.

## Что значит `from memory cache`?

Response взят из browser memory cache. Server мог вообще не получить request.

Если нужно проверить реальный request, включи `Disable cache` в DevTools при открытой панели.

## Как понять, отправилась ли cookie?

Открой request -> Headers -> Request Headers:

```http
Cookie: sid=abc
```

Если cookie нет, смотри вкладку Cookies и attributes:

- `Domain`;
- `Path`;
- `SameSite`;
- `Secure`;
- expiration;
- credentials mode.

## Как понять, что ошибка на backend?

Если request ушел, response пришел, status `500`, а CORS не блокирует чтение, вероятно ошибка на server side.

Но frontend все равно должен корректно обработать `500`, показать fallback и не падать всем приложением.

## Мини-шпаргалка

- Network tab показывает факты.
- CORS ищи через preflight и `Access-Control-*`.
- Cookies проверяй в request headers и cookie details.
- Cache source может объяснить "почему данные старые".
- Timing помогает найти DNS/TLS/server/download bottleneck.
