# Что такое состояние (State)?

> [!summary]
> State - это внутренняя память компонента, которая хранит данные, меняющиеся со временем и влияющие на UI. Когда state обновляется, React запускает новый render компонента и показывает интерфейс для нового состояния.

## Простое определение

State нужен для данных, которые могут измениться после первого render:

- значение input;
- открыт ли modal;
- текущая вкладка;
- счетчик;
- выбранный элемент;
- результат пользовательского действия;
- локальные UI-настройки.

Пример:

```jsx
import { useState } from 'react'

function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      Счет: {count}
    </button>
  )
}
```

## Почему обычной переменной недостаточно?

```jsx
function Counter() {
  let count = 0

  return (
    <button onClick={() => count++}>
      Счет: {count}
    </button>
  )
}
```

Такой код не обновит UI. React не знает, что обычная переменная изменилась, и не запускает render.

State нужен, чтобы:

```text
изменить данные -> сообщить React -> получить новый render
```

## Когда данные должны быть state?

Данные стоит хранить в state, если:

- они меняются со временем;
- изменение должно обновлять UI;
- значение нельзя полностью вычислить из props или другого state;
- значение принадлежит конкретному компоненту или его детям.

Не нужно хранить в state то, что можно вычислить:

```jsx
const fullName = `${firstName} ${lastName}`
```

Если `firstName` и `lastName` уже есть в state, отдельный `fullName` может стать лишним derived state.

## State локален

State принадлежит конкретному экземпляру компонента:

```jsx
<Counter />
<Counter />
```

У каждого `Counter` будет свой независимый `count`.

## Мини-шпаргалка

- State - данные, изменение которых влияет на UI.
- State обновляют через setter, например `setCount`.
- Обычная переменная не запускает render.
- State локален для экземпляра компонента.
- Не храни в state данные, которые можно безопасно вычислить.
