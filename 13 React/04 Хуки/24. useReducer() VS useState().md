# useReducer vs useState

> [!summary]
> `useState` лучше подходит для простого локального состояния, а `useReducer` - для сложных обновлений, связанных полей и явных actions. Выбор зависит не от "крутости" хука, а от читаемости модели состояния.

## Короткое сравнение

| Критерий | useState | useReducer |
|---|---|---|
| Простота | проще | сложнее |
| Логика обновлений | в handlers | в reducer |
| Несколько связанных полей | может стать шумно | обычно удобнее |
| Тестирование логики | сложнее отдельно | reducer легко тестировать |
| Actions | нет | есть |
| Boilerplate | меньше | больше |

## Когда выбрать useState?

```jsx
const [isOpen, setIsOpen] = useState(false)
const [query, setQuery] = useState('')
```

Подходит для:

- boolean-флагов;
- input;
- простых счетчиков;
- локальных UI-состояний;
- независимых значений.

## Когда выбрать useReducer?

```jsx
const [state, dispatch] = useReducer(formReducer, initialState)
```

Подходит для:

- сложных форм;
- нескольких связанных полей;
- validation flow;
- undo/redo;
- состояний загрузки;
- сценариев с явными событиями.

## Пример, где useReducer читабельнее

```jsx
dispatch({ type: 'submitStarted' })
dispatch({ type: 'submitSucceeded', user })
dispatch({ type: 'submitFailed', error })
```

Actions описывают события предметной области. Это проще поддерживать, чем набор разрозненных `setIsLoading`, `setError`, `setUser`.

## Когда useReducer будет лишним?

```jsx
const [isOpen, setIsOpen] = useState(false)
```

Для такого state reducer только добавит ceremony:

```jsx
dispatch({ type: 'toggle' })
```

Иногда это нормально, но чаще избыточно.

## Мини-шпаргалка

- `useState` - проще и короче.
- `useReducer` - явнее для сложных переходов.
- Reducer удобен для тестирования.
- Не выбирай `useReducer` ради "архитектурности".
- Если handlers стали читать сложно, подумай о reducer.
