# Что такое Redis и зачем он нужен?

> [!NOTE]
> Redis - in-memory data store, который используют как cache, key-value database, message broker и streaming engine. Его сила в высокой скорости, богатых структурах данных, атомарных командах и TTL.

## Что такое Redis простыми словами?

Redis - это сервер, который хранит данные по ключам:

```txt
user:1:name -> "Marat"
cart:42 -> {"items":[...]}
rate:ip:127.0.0.1 -> 17
```

Но Redis не ограничивается простыми строками. Значения могут быть:

- strings;
- hashes;
- lists;
- sets;
- sorted sets;
- streams;
- bitmaps;
- HyperLogLog;
- geospatial indexes;
- JSON/Search/TimeSeries/Bloom/Vector sets в Redis Stack/Redis 8 ecosystem.

## Зачем Redis backend-разработчику?

Redis нужен, когда операция должна быть быстрой, атомарной или разделенной между несколькими инстансами приложения.

Типичные задачи:

- кешировать дорогие SQL/API-запросы;
- хранить session data;
- считать rate limits;
- хранить одноразовые коды и reset tokens;
- делать distributed locks;
- собирать leaderboard;
- строить queue;
- рассылать WebSocket-события между процессами;
- хранить события в Streams;
- ограничивать повторную обработку idempotency keys.

## Почему Redis быстрый?

Redis быстрый потому что:

- основные данные находятся в RAM;
- команды часто выполняются как простые операции над структурами данных;
- многие операции атомарны;
- network protocol легкий;
- event loop обрабатывает команды последовательно;
- клиент может использовать pipelining, уменьшая round trips.

Скорость Redis не значит, что можно бездумно выполнять `KEYS *`, хранить огромные значения или делать большие `LRANGE` на горячем пути.

## Redis - это cache или database?

И то, и другое, но с разным уровнем ответственности.

Redis как cache:

- данные можно потерять;
- источник истины находится в SQL/API;
- TTL обязателен;
- eviction допустим.

Redis как database:

- нужны persistence, backups, replication;
- потеря данных недопустима или дорого стоит;
- нужно тщательно проектировать ключи и модель;
- нужно понимать ограничения транзакций и durability.

На собеседовании хороший ответ: Redis может быть database, но чаще в web backend он используется как infrastructure store рядом с основной БД.

## Пример: cache-aside рядом с PostgreSQL

```ts
import { createClient } from 'redis';

const redis = createClient({
  url: process.env.REDIS_URL,
});

await redis.connect();

export async function getUserProfile(userId: string) {
  const key = `profile:${userId}`;
  const cached = await redis.get(key);

  if (cached) {
    return JSON.parse(cached);
  }

  const profile = await db.user.findUnique({
    where: {
      id: userId,
    },
  });

  await redis.set(key, JSON.stringify(profile), {
    EX: 60 * 5,
  });

  return profile;
}
```

## Когда Redis не нужен?

Redis не нужен, если:

- данные редко читаются повторно;
- нет bottleneck-а;
- один процесс и достаточно обычного in-memory `Map`;
- нужна сложная relational модель;
- команда не готова обслуживать отдельную инфраструктуру;
- потеря cache не ускоряет, а ломает продукт.

## Мини-шпаргалка

- Redis - быстрый in-memory data store.
- Главные use cases: cache, sessions, rate limits, locks, queues, streams, Pub/Sub.
- Redis не отменяет SQL.
- Большинство production-ключей должны иметь namespace и TTL.
- Для Node.js используй `redis` (`node-redis`) или `ioredis`, если проект уже на нем.
