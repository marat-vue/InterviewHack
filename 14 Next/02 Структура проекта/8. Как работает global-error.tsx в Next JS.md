# Как работает global-error.tsx в Next JS?

> [!summary]
> `global-error.tsx` - глобальная error boundary для App Router. Она ловит ошибки верхнего уровня, включая ошибки root layout, должна быть Client Component и обязана возвращать собственные `<html>` и `<body>`.

## Где находится?

```text
app/
  global-error.tsx
  layout.tsx
  page.tsx
```

`global-error.tsx` работает на уровне всего приложения.

## Минимальный пример

```tsx
'use client'

export default function GlobalError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <html>
      <body>
        <h1>Something went wrong</h1>
        <button onClick={() => reset()}>Try again</button>
      </body>
    </html>
  )
}
```

Почему нужен `'use client'`? Error boundary должна уметь обработать ошибку и вызвать `reset` на клиенте.

## Чем отличается от error.tsx?

| Файл | Где работает |
|---|---|
| `error.tsx` | ловит ошибки конкретного route segment |
| `global-error.tsx` | ловит глобальные ошибки, включая root layout |

Обычно сначала используют локальные `error.tsx`, а `global-error.tsx` оставляют как последнюю линию защиты.

## Что global-error не ловит?

Как и React Error Boundary, он не является универсальным try/catch.

Не стоит ожидать, что он поймает:

- ошибки в event handlers;
- ошибки в `setTimeout`;
- ошибки в промисах без обработки;
- ошибки вне React render flow.

## Что отвечать на собеседовании?

`global-error.tsx` - глобальный error UI App Router. Он должен быть Client Component, принимает `error` и `reset`, возвращает `<html>` и `<body>`, потому что заменяет весь документ при ошибке верхнего уровня. Для локальных сегментов лучше использовать `error.tsx`.

## Частые ошибки

- Забывать `'use client'`.
- Не возвращать `<html>` и `<body>`.
- Использовать global error вместо локальных boundaries.
- Показывать пользователю сырой stack trace.
- Не логировать ошибку во внешний monitoring.

## Мини-шпаргалка

- Файл: `app/global-error.tsx`.
- Обязателен `'use client'`.
- Возвращает `<html>` и `<body>`.
- Принимает `error` и `reset`.
- Ловит ошибки root layout.
- Локальные ошибки лучше ловить `error.tsx`.
