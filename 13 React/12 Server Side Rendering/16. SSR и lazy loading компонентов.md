# SSR и lazy loading компонентов

> [!summary]
> Lazy loading уменьшает клиентский JavaScript, а SSR дает готовый HTML. В React 18+ эти подходы лучше всего работают вместе через `Suspense` и streaming SSR: сервер может показать fallback, а код и HTML медленного блока догружаются позже.

## Что такое lazy loading в React?

```jsx
import { lazy, Suspense } from 'react'

const Chart = lazy(() => import('./Chart'))

function Dashboard() {
  return (
    <Suspense fallback={<ChartSkeleton />}>
      <Chart />
    </Suspense>
  )
}
```

`Chart` попадает в отдельный JavaScript chunk и загружается не сразу.

## Где возникает сложность при SSR?

SSR хочет отрендерить HTML на сервере.

Lazy loading говорит: "код компонента будет загружен асинхронно".

Без Suspense и streaming это конфликт: сервер не может просто синхронно получить компонент, если он еще грузится.

## Современный подход

React 18 streaming SSR понимает Suspense.

```jsx
function Page() {
  return (
    <main>
      <Hero />

      <Suspense fallback={<ChartSkeleton />}>
        <Chart />
      </Suspense>
    </main>
  )
}
```

Сервер может:

- отправить `Hero` сразу;
- отправить fallback для `Chart`;
- дослать содержимое `Chart`, когда оно готово;
- подключить client bundle для hydration.

## Client-only компоненты

Иногда компонент вообще не должен рендериться на сервере:

- зависит от `window`;
- использует DOM-библиотеку;
- тяжелая карта;
- редактор;
- график, которому нужны browser APIs.

В фреймворках для этого часто есть client-only dynamic import.

```jsx
// Идея API фреймворка:
const Map = dynamic(() => import('./Map'), {
  ssr: false,
})
```

Это уменьшает риск SSR-ошибок, но ухудшает первый HTML для этого блока.

## Что важно для hydration?

Сервер и клиент должны договориться о chunks и HTML.

Нужны:

- корректный manifest assets;
- одинаковое дерево компонентов;
- Suspense fallback, который не ломает layout;
- Error Boundary для chunk load errors;
- аккуратное разделение server-safe и client-only кода.

## Мини-шпаргалка

- `React.lazy` требует `Suspense`.
- В SSR lazy лучше раскрывается через streaming.
- Client-only lazy ухудшает HTML, но спасает browser-only компоненты.
- Lazy loading уменьшает стартовый JS.
- Error Boundary нужен для ошибок загрузки chunk.
