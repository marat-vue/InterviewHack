# Как делать backup, restore, PITR и проверять восстановление?

> [!NOTE]
> Backup имеет смысл только если restore проверен. Для PostgreSQL важно понимать logical backups, physical backups, WAL и PITR: point-in-time recovery.

## Logical backup

`pg_dump`:

```bash
pg_dump "$DATABASE_URL" > backup.sql
```

Восстановление:

```bash
psql "$DATABASE_URL" < backup.sql
```

Хорошо для:

- small/medium DB;
- переносов;
- выборочного restore;
- schema/data export.

## Custom format

```bash
pg_dump -Fc "$DATABASE_URL" -f backup.dump
pg_restore -d "$DATABASE_URL" backup.dump
```

Custom format удобен для `pg_restore` options.

## Physical backup

Physical backup копирует data directory и WAL. Его используют для больших production БД и PITR.

## WAL и PITR

WAL - write-ahead log. Если хранить base backup + WAL archive, можно восстановиться на момент времени:

```txt
restore base backup -> replay WAL до 2026-08-06 12:00
```

PITR спасает от:

- случайного `DELETE`;
- плохой миграции;
- corruption;
- human error.

## Restore drill

Минимальный процесс:

1. Взять свежий backup.
2. Поднять отдельную БД.
3. Восстановить backup.
4. Прогнать smoke queries.
5. Проверить количество ключевых строк.
6. Зафиксировать время восстановления.

## Что мониторить?

- backup freshness;
- backup size;
- WAL archiving lag;
- restore success in staging;
- RPO/RTO;
- encryption;
- access to backups.

## Мини-шпаргалка

- `pg_dump` - logical backup.
- Physical backup + WAL - база для PITR.
- RPO - сколько данных можно потерять.
- RTO - как долго можно восстанавливаться.
- Backup без restore drill - надежда, а не гарантия.
