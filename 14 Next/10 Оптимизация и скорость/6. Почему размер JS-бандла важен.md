# Почему размер JS-бандла важен?

> [!summary]
> JavaScript - один из самых дорогих ресурсов в вебе: его нужно скачать, распарсить, скомпилировать и выполнить. Большой JS-бандл ухудшает LCP, INP, TTI и особенно больно бьет по мобильным устройствам.

## Почему JS дороже, чем картинка или CSS?

Картинку браузер в основном скачивает и декодирует. JavaScript проходит больше этапов:

```text
download -> parse -> compile -> execute -> hydrate -> handle updates
```

Каждый этап стоит времени и CPU.

На слабом телефоне лишние 300-500 КБ JavaScript могут быть гораздо заметнее, чем кажется на рабочем ноутбуке.

## Как большой bundle влияет на метрики?

| Метрика | Как JS ухудшает |
| --- | --- |
| LCP | Главный контент позже появляется из-за блокирующей работы |
| INP | Main thread занят, клики обрабатываются медленнее |
| TBT | Длинные JS-задачи блокируют поток |
| TTI | Страница позже становится интерактивной |
| FCP | В CSR контент может ждать выполнения JS |

## Почему это особенно важно в Next.js?

В App Router есть разделение:

```text
Server Components -> не отправляют свой код в браузер
Client Components -> отправляют код в браузер
```

Если слишком рано поставить `'use client'`, можно случайно отправить в bundle большой кусок дерева компонентов.

Плохо:

```tsx
// app/dashboard/page.tsx
'use client'

import Chart from 'heavy-chart-library'
import BigTable from '@/components/big-table'

export default function DashboardPage() {
  return <Chart />
}
```

Лучше:

```tsx
// app/dashboard/page.tsx
import { DashboardChart } from './dashboard-chart'

export default async function DashboardPage() {
  const data = await getDashboardData()
  return <DashboardChart data={data} />
}
```

```tsx
// app/dashboard/dashboard-chart.tsx
'use client'

export function DashboardChart({ data }: { data: ChartData }) {
  return <Chart data={data} />
}
```

Клиентским остается только интерактивный график, а загрузка данных и оболочка остаются на сервере.

## Как уменьшать bundle?

### 1. Держать компоненты серверными по умолчанию

Не добавляй `'use client'`, если компоненту не нужны:

- `useState`;
- `useEffect`;
- обработчики событий;
- browser APIs;
- Zustand/Redux на клиенте;
- DOM-измерения;
- анимации.

### 2. Lazy load тяжелые компоненты

```tsx
import dynamic from 'next/dynamic'

const Chart = dynamic(() => import('./chart'), {
  loading: () => <ChartSkeleton />,
})
```

Так график не попадет в initial bundle, если он не нужен сразу.

### 3. Не импортировать огромные библиотеки целиком

Плохо:

```ts
import _ from 'lodash'
```

Лучше:

```ts
import debounce from 'lodash/debounce'
```

Или заменить зависимость маленькой функцией, если используется один метод.

### 4. Следить за UI-kit

Material UI, chart libraries, rich text editors и date libraries могут резко увеличить bundle.

Хорошая практика:

- lazy load редкие модалки;
- lazy load редакторы;
- не грузить графики на главной;
- проверять bundle analyzer;
- выносить тяжелые вычисления на сервер.

## Как анализировать bundle?

Часто используют:

```bash
npm install @next/bundle-analyzer
```

И подключают analyzer в `next.config.ts`. После этого видно, какие зависимости попали в client bundle и какие chunks стали слишком большими.

## Что отвечать на собеседовании?

Размер JS-бандла важен, потому что JavaScript нужно не только скачать, но и выполнить. Он блокирует main thread, ухудшает INP, TBT и TTI, а в CSR может задерживать появление контента. В Next.js особенно важно держать компоненты серверными по умолчанию, ограничивать `'use client'`, делать code splitting и lazy load тяжелых клиентских зависимостей.

## Частые ошибки

- Измерять только gzip-size и забывать execution cost.
- Ставить `'use client'` на весь page или layout.
- Импортировать тяжелые библиотеки в компоненты первого экрана.
- Не проверять bundle analyzer.
- Грузить chart/editor/map libraries сразу.
- Игнорировать мобильные CPU.

## Мини-шпаргалка

- JS нужно скачать, распарсить и выполнить.
- Большой bundle ухудшает INP и TTI.
- Server Components уменьшают client JS.
- `'use client'` расширяет клиентский module graph.
- Тяжелые виджеты лучше lazy load.
- Bundle analyzer помогает найти виновников.
