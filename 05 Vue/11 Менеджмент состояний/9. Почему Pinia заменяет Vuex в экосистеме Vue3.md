# Почему Pinia заменяет Vuex в экосистеме Vue3

> [!summary] Коротко
> Pinia стала основным выбором для Vue 3, потому что она проще Vuex, лучше типизируется, не требует mutations и естественно работает с Composition API.

## Вопрос

Почему Pinia заменяет Vuex в экосистеме Vue 3?

## Меньше концепций

Vuex строился вокруг `state`, `getters`, `mutations`, `actions`. Pinia оставляет `state`, `getters`, `actions`, а изменения state можно делать прямо в actions.

```typescript
actions: {
  increment() {
    this.count++;
  },
}
```

## Лучшая TypeScript-эргономика

Pinia хорошо выводит типы state, getters и actions без большого количества ручной типизации.

```typescript
const cart = useCartStore();

cart.items;
cart.addItem(product);
```

## Composition API

Pinia выглядит как набор composables: stores подключаются через функции `use...Store`.

```typescript
const userStore = useUserStore();
```

## Devtools и модульность

Pinia поддерживает Vue Devtools, hot module replacement и удобную модульность stores без строгой вложенной структуры Vuex modules.

## Когда Vuex все еще встречается

В legacy-проектах, особенно Vue 2, Vuex может оставаться нормальным рабочим решением. Но для нового Vue 3 проекта чаще выбирают Pinia.

## Мини-шпаргалка

- Pinia проще Vuex.
- В Pinia нет обязательных mutations.
- TypeScript работает приятнее.
- Stores выглядят как composables.
- Vuex чаще встречается в старых проектах.
