# Какие метрики производительности вы знаете?

> [!NOTE]
> Метрики производительности помогают понять, как быстро приложение загружается, когда становится интерактивным и насколько стабильно ведет себя интерфейс для пользователя.

## Core Web Vitals

| Метрика | Что измеряет | Почему важна |
| --- | --- | --- |
| `LCP` | Время появления самого крупного видимого элемента | Показывает, как быстро пользователь увидел основной контент |
| `INP` | Задержку реакции интерфейса на пользовательские действия | Показывает, насколько приложение отзывчивое |
| `CLS` | Суммарные сдвиги layout во время загрузки | Показывает, прыгает ли интерфейс |

## Дополнительные метрики загрузки

| Метрика | Расшифровка | Смысл |
| --- | --- | --- |
| `TTFB` | Time To First Byte | Как быстро сервер начал отвечать |
| `FCP` | First Contentful Paint | Когда появился первый видимый контент |
| `TBT` | Total Blocking Time | Насколько долго главный поток был заблокирован тяжелыми задачами |
| `Speed Index` | Индекс визуальной загрузки | Как быстро страница визуально наполнялась |

## Метрики, важные для SPA

Во Vue-приложениях важно смотреть не только на первую загрузку, но и на поведение после нее.

- **Bundle size**: сколько JavaScript нужно скачать и выполнить.
- **Hydration time**: сколько времени занимает "оживление" SSR-разметки.
- **Route transition time**: как быстро приложение переключается между страницами.
- **Component render time**: сколько времени занимает рендер тяжелых компонентов.
- **Memory usage**: не накапливаются ли лишние объекты, подписки и DOM-узлы.
- **FPS**: насколько плавны анимации, скролл и drag-and-drop.

## Пример: как мыслить по метрикам

```text
Пользователь открыл страницу
  -> TTFB показывает скорость ответа сервера
  -> FCP показывает первый контент
  -> LCP показывает основной контент
  -> TBT/INP показывают, не мешает ли тяжелый JavaScript
  -> CLS показывает, не прыгает ли интерфейс
```

## Пример проблем во Vue

```vue
<template>
  <ProductCard
    v-for="product in products"
    :key="product.id"
    :product="product"
  />
</template>
```

Если `products` содержит тысячи элементов, могут пострадать:

- `TBT`, потому что JavaScript долго создает VNode и компоненты.
- `INP`, потому что главный поток занят рендером.
- `Memory usage`, потому что в памяти слишком много экземпляров компонентов.

Обычно помогают пагинация, виртуализация списка, lazy loading и разбиение тяжелых компонентов.

## Чем измерять

- Lighthouse и PageSpeed Insights: общая диагностика страницы.
- Chrome DevTools Performance: профилирование главного потока.
- Chrome DevTools Network: размер и порядок загрузки ресурсов.
- Vue Devtools: дерево компонентов, события, состояние, время обновлений.
- Web Vitals library: сбор метрик у реальных пользователей.

## Мини-шпаргалка

- `LCP` - скорость появления основного контента.
- `INP` - отзывчивость интерфейса.
- `CLS` - визуальная стабильность.
- `TBT` часто показывает, что JavaScript слишком тяжелый.
- Для Vue особенно важны bundle size, время рендера компонентов и гидратация.
