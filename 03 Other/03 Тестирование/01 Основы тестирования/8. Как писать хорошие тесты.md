# Как писать хорошие тесты?

> [!summary]
> Хороший тест понятен, стабилен, проверяет одно важное поведение и падает по понятной причине. Он не повторяет реализацию и не привязывается к деталям, которые пользователь или внешний потребитель системы не замечает.

## Признаки хорошего теста

Хороший тест:

- имеет понятное имя;
- проверяет один сценарий;
- содержит конкретный assertion;
- не зависит от порядка запуска других тестов;
- не ходит во внешний интернет;
- не повторяет код реализации;
- легко объясняет, что сломалось.

## Плохой пример

```ts
test('works', async () => {
  const wrapper = mount(ProfileCard);

  expect(wrapper.vm.isOpen).toBe(false);
  await wrapper.vm.toggle();
  expect(wrapper.vm.isOpen).toBe(true);
});
```

Проблема: тест проверяет внутреннее состояние и внутренний метод. Пользователю важно не `isOpen`, а видимый результат.

## Хороший пример

```ts
test('shows profile details after clicking expand button', async () => {
  const wrapper = mount(ProfileCard, {
    props: { user: { name: 'Ann', email: 'ann@example.com' } },
  });

  await wrapper.get('[data-testid="expand-profile"]').trigger('click');

  expect(wrapper.text()).toContain('ann@example.com');
});
```

Здесь тест проверяет поведение: пользователь нажал кнопку и увидел детали.

## Когда использовать `data-testid`?

`data-testid` полезен, когда:

- нет устойчивой роли или label;
- текст может меняться из-за переводов;
- нужно найти технический элемент.

Но если можно найти элемент как пользователь, лучше так:

```ts
screen.getByRole('button', { name: 'Сохранить' });
```

В Vue Test Utils чаще используют `find`, `get`, CSS selectors и `data-testid`.

## Как делать тесты стабильнее?

- Изолируй состояние между тестами.
- Очищай mocks после тестов.
- Не используй реальные таймеры, если можно fake timers.
- Не завязывайся на случайные даты.
- Не проверяй полный HTML без необходимости.
- Не делай snapshot вместо смысловой проверки.

## Мини-шпаргалка

- Тестируй поведение, а не реализацию.
- Один тест - один важный сценарий.
- Имя теста должно объяснять expected behavior.
- Моки очищай между тестами.
- Snapshot не заменяет нормальные assertions.
