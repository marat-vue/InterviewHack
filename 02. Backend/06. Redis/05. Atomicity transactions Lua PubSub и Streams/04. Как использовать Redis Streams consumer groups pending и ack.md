# Как использовать Redis Streams, consumer groups, pending и ACK?

> [!NOTE]
> Streams дают более надежную модель обработки сообщений, чем Pub/Sub: события сохраняются, consumer group распределяет сообщения между workers, а `XACK` подтверждает успешную обработку.

## Как создать stream и group?

```redis
XGROUP CREATE emails email-workers $ MKSTREAM
```

`MKSTREAM` создаст stream, если его еще нет.

## Как добавить job?

```redis
XADD emails * type welcome userId 1 email admin@example.com
```

## Как worker читает job?

```redis
XREADGROUP GROUP email-workers worker-1 COUNT 10 BLOCK 5000 STREAMS emails >
```

`>` означает “новые сообщения, которые еще не доставлялись этой group”.

## Как подтвердить обработку?

```redis
XACK emails email-workers 1786000000000-0
```

Без `XACK` сообщение остается в pending entries list.

## Как посмотреть pending?

```redis
XPENDING emails email-workers
```

Подробно:

```redis
XPENDING emails email-workers - + 10
```

## Как забрать зависшие сообщения?

```redis
XAUTOCLAIM emails email-workers worker-2 60000 0-0 COUNT 10
```

Это помогает, если `worker-1` упал после чтения, но до `XACK`.

## Как сделать worker idempotent?

Streams могут привести к повторной обработке, особенно после retry. Поэтому обработчик должен быть idempotent:

```ts
const processedKey = `processed:email:${message.id}`;
const firstTime = await redis.set(processedKey, '1', {
  NX: true,
  EX: 60 * 60 * 24,
});

if (!firstTime) {
  await redis.xAck('emails', 'email-workers', message.id);
  return;
}

await sendEmail(message.message);
await redis.xAck('emails', 'email-workers', message.id);
```

## Мини-шпаргалка

- `XADD` - добавить событие.
- `XGROUP CREATE` - создать group.
- `XREADGROUP` - читать через group.
- `XACK` - подтвердить.
- `XPENDING` - что зависло.
- `XAUTOCLAIM` - забрать у упавшего consumer.
- Worker должен быть idempotent.
