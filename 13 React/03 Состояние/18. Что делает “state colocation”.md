# Что делает state colocation?

> [!summary]
> State colocation - это принцип "держи состояние как можно ближе к месту, где оно используется". Он помогает уменьшить лишние render, упростить компоненты и избежать преждевременного глобального состояния.

## Простое определение

State должен жить там, где он действительно нужен.

Если состояние нужно только одному компоненту:

```jsx
function Dropdown() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <div>
      <button onClick={() => setIsOpen(!isOpen)}>Меню</button>
      {isOpen && <Menu />}
    </div>
  )
}
```

Не нужно поднимать `isOpen` в `App`, если другие компоненты его не используют.

## Плохой пример

```jsx
function App() {
  const [isTooltipOpen, setIsTooltipOpen] = useState(false)

  return (
    <Page
      isTooltipOpen={isTooltipOpen}
      setIsTooltipOpen={setIsTooltipOpen}
    />
  )
}
```

Если tooltip нужен только внутри маленькой кнопки, state слишком высоко.

## Почему это важно для производительности?

Когда state находится слишком высоко:

- рендерится большой кусок дерева;
- props приходится передавать через промежуточные компоненты;
- сложнее понять, кто меняет данные;
- локальная UI-логика загрязняет верхний уровень.

State colocation уменьшает радиус обновления.

## Когда state нужно поднимать?

State стоит поднять, если:

- значение нужно нескольким sibling-компонентам;
- родитель должен принимать решение на основе состояния;
- состояние нужно синхронизировать с URL;
- данные должны пережить размонтирование локального компонента;
- это часть бизнес-сценария, а не локальный UI-флаг.

## Мини-шпаргалка

- State colocation = держать state ближе к месту использования.
- Не поднимай state без причины.
- Локальный UI-флаг обычно должен быть локальным.
- Если state нужен нескольким компонентам, его можно поднять.
- Правильное место state часто важнее мемоизации.
