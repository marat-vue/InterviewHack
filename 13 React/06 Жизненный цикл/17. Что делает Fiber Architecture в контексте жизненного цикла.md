# Что делает Fiber Architecture в контексте жизненного цикла?

> [!summary]
> Fiber Architecture - внутренняя архитектура React, которая представляет работу над UI как дерево fiber-узлов. Она помогает React разбивать render-работу на части, расставлять приоритеты, прерывать менее срочную работу и поддерживать concurrent rendering.

## Зачем Fiber нужен lifecycle?

Без Fiber обновление большого дерева было бы проще представить как одну длинную синхронную работу:

```text
начали render -> дошли до конца -> применили результат
```

Fiber позволяет React гибче работать с render phase:

- разбивать работу на единицы;
- приостанавливать render;
- продолжать render позже;
- выбрасывать устаревшую работу;
- отдавать приоритет пользовательскому вводу.

## Render phase и Fiber

Render phase может быть прервана:

```text
React начал считать тяжелый список
пользователь печатает в input
React обрабатывает более срочное обновление
потом возвращается к менее срочной работе
```

Именно поэтому render должен быть чистым. Если render имеет side effects, повторные или прерванные вызовы создадут баги.

## Commit phase

Commit phase применяет уже готовый результат:

- меняет DOM;
- обновляет refs;
- запускает layout effects;
- планирует passive effects.

Commit не должен быть "полуготовым": пользователь должен увидеть согласованный UI.

## Что разработчику важно знать?

Не нужно работать с fiber напрямую. Важно понимать последствия:

- компонент может рендериться больше одного раза;
- render может быть прерван;
- side effects в render опасны;
- transitions делают часть работы менее срочной;
- Strict Mode помогает найти нечистый render.

## Мини-шпаргалка

- Fiber - внутренняя архитектура React.
- Она помогает планировать и прерывать render-работу.
- Render phase может быть interruptible.
- Commit phase применяет готовые изменения.
- Fiber лежит в основе concurrent возможностей.
