# В чем преимущества компонентного подхода?

> [!NOTE]
> Компонентный подход разбивает интерфейс на независимые части. Это улучшает переиспользование, читаемость, тестируемость и управление сложностью приложения.

## Вопрос

В чем преимущества компонентного подхода?

## Переиспользование

Один компонент можно использовать в разных местах.

```vue
<template>
  <BaseButton variant="primary">Сохранить</BaseButton>
  <BaseButton variant="secondary">Отмена</BaseButton>
</template>
```

Вместо копирования HTML и логики создается общий компонент.

## Разделение ответственности

Каждый компонент отвечает за свой кусок интерфейса.

```text
App
  -> AppLayout
  -> UserList
    -> UserCard
```

Так проще понимать, где находится конкретная логика.

## Изоляция изменений

Если меняется внешний вид `UserCard`, не нужно переписывать все страницы, где карточка используется.

## Тестируемость

Компонент можно тестировать отдельно: передать props, вызвать события, проверить отрисовку.

## Композиция

Сложный интерфейс собирается из маленьких компонентов, как из функций.

```vue
<UserPage>
  <UserHeader />
  <UserStats />
  <UserOrders />
</UserPage>
```

## Мини-шпаргалка

- Компоненты уменьшают дублирование.
- Упрощают чтение и поддержку.
- Помогают разделить ответственность.
- Дают естественную границу для тестов.
- Делают UI композиционным.
