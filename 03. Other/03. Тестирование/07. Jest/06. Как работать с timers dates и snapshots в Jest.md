# Как работать с timers, dates и snapshots в Jest?

> [!summary]
> Jest умеет подменять timers, управлять системным временем и создавать snapshots. Это полезно для debounce, retry, expiration logic и стабильного сравнения результата, но требует аккуратности.

## Fake timers

```ts
beforeEach(() => {
  jest.useFakeTimers();
});

afterEach(() => {
  jest.useRealTimers();
});

test('runs callback after timeout', () => {
  const callback = jest.fn();

  setTimeout(callback, 1000);
  jest.advanceTimersByTime(1000);

  expect(callback).toHaveBeenCalledTimes(1);
});
```

## Current date

```ts
jest.useFakeTimers().setSystemTime(new Date('2026-01-01T00:00:00Z'));

expect(isTokenExpired(expiredToken)).toBe(true);

jest.useRealTimers();
```

Так тесты не зависят от текущей даты.

## Snapshot testing

```ts
expect(formatUser(user)).toMatchSnapshot();
```

Или для UI:

```ts
expect(wrapper.html()).toMatchSnapshot();
```

Snapshot сохраняет эталонный результат. При изменении результата тест падает.

## Когда snapshots опасны?

Snapshots становятся бесполезными, если:

- они огромные;
- их обновляют без просмотра diff;
- они проверяют нестабильную разметку;
- вместо смысла проверяют случайный шум.

Лучше сочетать snapshots с осмысленными assertions.

## Мини-шпаргалка

- Fake timers тестируют `setTimeout`, debounce, retry.
- `advanceTimersByTime` двигает виртуальное время.
- `setSystemTime` фиксирует текущую дату.
- Snapshot фиксирует снимок результата.
- Большие snapshots часто плохо читаются.
