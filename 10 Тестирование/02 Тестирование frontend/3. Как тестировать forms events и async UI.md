# Как тестировать forms, events и async UI?

> [!summary]
> Формы и асинхронный UI тестируют через действия пользователя: ввод, submit, ожидание обновления DOM, проверку loading, success и error states. Важно учитывать, что Vue обновляет DOM асинхронно.

## Как тестировать форму?

Пример формы:

```vue
<template>
  <form @submit.prevent="submit">
    <input v-model="email" aria-label="Email" />
    <button :disabled="!email">Войти</button>
  </form>
</template>
```

Тест:

```ts
const wrapper = mount(LoginForm);

await wrapper.get('input').setValue('ann@example.com');
await wrapper.get('form').trigger('submit');

expect(wrapper.emitted('submit')).toEqual([
  [{ email: 'ann@example.com' }],
]);
```

## Почему нужен `await`?

Vue обновляет DOM не мгновенно, а на следующем tick. Методы Vue Test Utils вроде `trigger` и `setValue` возвращают promise, поэтому их обычно await-ят.

```ts
await wrapper.get('button').trigger('click');

expect(wrapper.text()).toContain('Готово');
```

## Как тестировать loading и error?

```ts
api.loadUser.mockRejectedValue(new Error('Network error'));

const wrapper = mount(UserProfile);

await wrapper.get('[data-testid="reload"]').trigger('click');
await flushPromises();

expect(wrapper.text()).toContain('Не удалось загрузить профиль');
```

`flushPromises` помогает дождаться завершения pending promises.

## Что проверять в формах?

- начальные значения;
- validation errors;
- disabled submit;
- successful submit;
- server error;
- очистку формы;
- double submit protection.

## Мини-шпаргалка

- Формы тестируют через `setValue` и `trigger`.
- После событий часто нужен `await`.
- Для promises используй `flushPromises`.
- Проверяй loading, success и error.
- Submit должен проверять payload, а не внутренние refs.
