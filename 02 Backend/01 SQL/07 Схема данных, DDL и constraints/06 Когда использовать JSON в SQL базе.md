# Когда использовать JSON в SQL базе?

> [!NOTE]
> JSON-колонки полезны для гибких, редко фильтруемых или слабо структурированных данных. Но JSON не должен заменять нормальную модель там, где нужны связи, constraints, индексы и частые запросы по полям.

## Когда JSON подходит?

- настройки пользователя;
- внешний payload;
- редко используемые metadata;
- экспериментальные поля;
- интеграционные данные;
- лог событий.

```sql
CREATE TABLE events (
  id bigint PRIMARY KEY,
  type text NOT NULL,
  payload jsonb NOT NULL
);
```

## Когда JSON плохая идея?

Если по полю нужно часто фильтровать, джойнить, валидировать и поддерживать ссылочную целостность, лучше обычная колонка или отдельная таблица.

```sql
-- Подозрительно
payload->>'user_id'
```

Если `user_id` важен, его стоит хранить отдельной колонкой с FK.

## PostgreSQL jsonb

В PostgreSQL часто используют `jsonb`: он хранит JSON в бинарном формате и поддерживает индексацию через GIN.

## Мини-шпаргалка

- JSON полезен для гибких metadata.
- Не прячь важные связи внутри JSON.
- Часто фильтруемые поля лучше выносить в колонки.
- В PostgreSQL для JSON часто используют `jsonb`.
- JSON удобен, но снижает строгость схемы.
