# Redis шпаргалка для backend-разработчика

> [!NOTE]
> Короткая шпаргалка по Redis для повторения перед собеседованием или перед проектированием backend-фичи.

## Что такое Redis?

Redis - in-memory data store для cache, key-value, counters, sessions, Pub/Sub, Streams и структур данных.

## Главные структуры

| Структура | Кейс |
|---|---|
| String | cache, token, counter |
| Hash | object fields |
| List | simple queue |
| Set | unique membership |
| Sorted Set | leaderboard, priority |
| Stream | durable events |
| Bitmap | boolean analytics |
| HyperLogLog | approximate unique count |
| Geo | nearby search |

## Главные команды

```redis
GET key
SET key value EX 300
INCR counter
HSET user:1 email a@b.com
SADD online user:1
ZADD leaderboard 100 user:1
XADD events * type login userId 1
PUBLISH channel message
SCAN 0 MATCH cache:* COUNT 100
```

## Cache rules

- TTL обязателен.
- Key должен учитывать user/tenant/locale/params.
- Update source of truth -> invalidate cache.
- Hot keys защищай jitter/lock/SWR.
- Redis outage для cache не должен ломать весь backend.

## Production rules

- `maxmemory`;
- eviction policy;
- no public Redis;
- AUTH/ACL/TLS;
- backups, если Redis state важен;
- monitoring;
- no `KEYS *`;
- no big keys;
- singleton client.

## Pub/Sub vs Streams

| Вопрос | Pub/Sub | Streams |
|---|---|---|
| Хранит сообщения | Нет | Да |
| Offline consumer получит | Нет | Может |
| Retry | Нет | Да |
| Realtime broadcast | Отлично | Можно, но тяжелее |
| Jobs/events | Слабо | Хорошо |

## Собеседовательный ответ в 30 секунд

Redis нужен, когда требуется быстрый общий state: cache, sessions, rate limits, counters, locks, queues, Pub/Sub, Streams и leaderboards. Я выбираю data type под операцию, ставлю TTL, избегаю `KEYS` и big keys, использую singleton client, а в production настраиваю memory, eviction, persistence, replication, security и monitoring.
