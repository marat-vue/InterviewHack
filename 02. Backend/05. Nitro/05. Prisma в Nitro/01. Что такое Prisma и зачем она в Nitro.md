# Что такое Prisma и зачем она в Nitro?

> [!NOTE]
> Prisma - TypeScript ORM и typed query client для работы с базой данных. В Nitro Prisma обычно используют как database layer: route handler принимает HTTP request, service описывает бизнес-логику, а Prisma Client выполняет запросы к PostgreSQL, MySQL, SQLite, SQL Server, MongoDB или другой поддерживаемой БД.

## Где Prisma находится в Nitro-архитектуре?

```txt
HTTP request
  -> Nitro route handler
    -> validation/auth
    -> service
      -> repository или Prisma Client
        -> database
```

Handler не должен превращаться в огромную смесь HTTP, validation, SQL и бизнес-логики. Prisma лучше вызывать из service/repository слоя.

## Что дает Prisma?

- `schema.prisma` как описание моделей;
- generator для Prisma Client;
- типизированные CRUD methods;
- relation queries;
- nested writes;
- transactions;
- migrations;
- seed workflow;
- raw SQL для сложных случаев;
- автодополнение TypeScript;
- типы для `where`, `select`, `include`, `orderBy`.

## Пример route с Prisma

```ts
// server/routes/api/users.get.ts
export default defineHandler(async () => {
  return prisma.user.findMany({
    select: {
      id: true,
      email: true,
      name: true,
    },
    orderBy: {
      createdAt: 'desc',
    },
  });
});
```

Лучше через service:

```ts
// server/routes/api/users.get.ts
export default defineHandler(() => {
  return userService.findMany();
});
```

```ts
// server/services/userService.ts
export const userService = {
  findMany() {
    return prisma.user.findMany({
      select: {
        id: true,
        email: true,
        name: true,
      },
    });
  },
};
```

## Prisma не заменяет SQL-мышление

Даже с ORM нужно понимать:

- индексы;
- foreign keys;
- транзакции;
- isolation levels;
- N+1;
- pagination strategies;
- constraints;
- migrations;
- connection pooling;
- raw SQL risks.

Prisma помогает писать типизированные запросы, но не делает плохую схему хорошей автоматически.

## Когда Prisma особенно удобна в Nitro?

Prisma хорошо подходит, если:

- backend на TypeScript;
- нужна строгая типизация models;
- есть CRUD API;
- используются relations;
- нужна Better Auth Prisma adapter;
- есть production migrations;
- команда хочет единый DB workflow.

## Когда Prisma может быть не лучшим выбором?

Подумай о другом инструменте, если:

- нужна максимальная SQL-ручная оптимизация;
- проект heavily database-specific;
- query builder удобнее ORM;
- edge runtime не поддерживает выбранный Prisma engine/adapter;
- БД очень простая и достаточно `useDatabase`/SQL client.

## Мини-шпаргалка

- Prisma - ORM и typed query client.
- В Nitro Prisma живет в `server/utils`, `server/services` или `server/repositories`.
- `schema.prisma` - source of truth моделей.
- `PrismaClient` генерируется из schema.
- Для auth с Better Auth удобно использовать Prisma adapter.
- Prisma не отменяет понимание SQL, индексов и транзакций.
