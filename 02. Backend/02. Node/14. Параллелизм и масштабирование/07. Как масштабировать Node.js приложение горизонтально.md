# Как масштабировать Node.js приложение горизонтально?

> [!NOTE]
> Горизонтальное масштабирование означает запуск нескольких экземпляров приложения и распределение трафика между ними. Для Node.js это часто важнее, чем попытка сделать один процесс бесконечно мощным.

## Вертикальное vs горизонтальное

| Подход | Что делаем |
|---|---|
| Вертикальное | даем одной машине больше CPU/RAM |
| Горизонтальное | запускаем больше инстансов |

## Stateless-приложение

Горизонтально проще масштабировать приложение, которое не хранит пользовательское состояние в памяти процесса.

Плохо:

```js
const sessions = new Map();
```

Лучше:

```txt
app instances -> Redis/Postgres/session store
```

## Что нужно вынести наружу?

- sessions;
- кэши, если они должны быть общими;
- загруженные файлы;
- очереди задач;
- scheduled jobs;
- WebSocket broadcast.

## Load balancer

```txt
users -> load balancer -> app-1
                       -> app-2
                       -> app-3
```

Load balancer распределяет запросы и убирает нездоровые инстансы из ротации.

## Мини-шпаргалка

- Горизонтальное масштабирование - больше инстансов.
- Stateless API масштабируется проще.
- State нужно хранить во внешних системах.
- Load balancer распределяет трафик.
- WebSocket требует отдельного внимания к sticky sessions и broadcast.
