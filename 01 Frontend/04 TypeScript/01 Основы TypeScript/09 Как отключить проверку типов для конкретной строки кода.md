# Как отключить проверку типов для конкретной строки кода?

> [!NOTE] Коротко
> Для отключения проверки на следующей строке используют `// @ts-ignore` или более безопасный `// @ts-expect-error`.

## Вопрос

Как временно отключить ошибку TypeScript для конкретной строки?

## @ts-ignore

`@ts-ignore` заставляет TypeScript проигнорировать ошибку на следующей строке.

```typescript
// @ts-ignore
const value: number = 'not a number';
```

Такой комментарий лучше использовать редко: он скрывает любую ошибку на строке.

## @ts-expect-error

`@ts-expect-error` тоже ожидает ошибку на следующей строке, но если ошибки нет, TypeScript сам сообщит об этом.

```typescript
// @ts-expect-error: проверяем некорректный тип в тесте
formatPrice('100');
```

Это безопаснее, потому что комментарий не останется незаметным после исправления кода.

## Когда допустимо

- тесты типов;
- временная несовместимость сторонней библиотеки;
- миграция большого JS-проекта в TS;
- точечный workaround с понятным комментарием.

## Чего избегать

Не стоит использовать такие комментарии как способ "победить TypeScript". Обычно лучше уточнить тип, исправить модель данных или добавить runtime-проверку.

## Сравнение

| Комментарий | Поведение |
| --- | --- |
| `@ts-ignore` | всегда игнорирует следующую строку |
| `@ts-expect-error` | ожидает ошибку и ругается, если ее нет |

## Мини-шпаргалка

```typescript
// @ts-expect-error: reason
brokenCall();

// @ts-ignore
legacyCode();
```
