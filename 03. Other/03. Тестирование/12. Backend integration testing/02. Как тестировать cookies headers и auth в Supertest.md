# Как тестировать cookies, headers и auth в Supertest?

> [!summary]
> Supertest позволяет задавать headers, cookies и authorization, а также проверять `Set-Cookie`, redirects, status codes и protected endpoints. Это важно для тестирования login, sessions, CSRF, refresh tokens и role-based access.

## Headers

```ts
await request(app.getHttpServer())
  .get('/profile')
  .set('Authorization', `Bearer ${accessToken}`)
  .set('Accept', 'application/json')
  .expect(200);
```

## Cookies

```ts
await request(app.getHttpServer())
  .get('/session')
  .set('Cookie', ['sid=session-id'])
  .expect(200);
```

## Проверка `Set-Cookie`

```ts
await request(app.getHttpServer())
  .post('/auth/login')
  .send({ email: 'ann@example.com', password: 'secret123' })
  .expect(200)
  .expect('set-cookie', /refreshToken/);
```

## Agent для сохранения cookies

```ts
const agent = request.agent(app.getHttpServer());

await agent
  .post('/auth/login')
  .send({ email: 'ann@example.com', password: 'secret123' })
  .expect(200);

await agent
  .get('/profile')
  .expect(200);
```

`agent` хранит cookies между запросами.

## Auth cases

Покрывай:

- нет токена -> `401`;
- неверный токен -> `401`;
- недостаточно роли -> `403`;
- токен есть, user удален -> `401` или `404`;
- refresh token истек -> `401`;
- cookie с правильными flags.

## Мини-шпаргалка

- `.set()` задает headers.
- `.set('Cookie', [...])` передает cookies.
- `request.agent()` хранит cookies между запросами.
- `Set-Cookie` нужно проверять для auth endpoints.
- Auth tests должны покрывать `401`, `403` и happy path.
