# Local VS Global state

> [!NOTE] Коротко
> Local state принадлежит одному компоненту или небольшой ветке компонентов. Global state нужен, когда одни и те же данные используют разные части приложения.

## Вопрос

Чем отличается локальное состояние от глобального?

## Local state

Локальное состояние живет рядом с компонентом.

```vue
<script setup>
import { ref } from "vue";

const isModalOpen = ref(false);
</script>
```

Если флаг нужен только этой модалке или странице, не стоит выносить его в глобальный store.

## Global state

Глобальное состояние доступно разным компонентам без длинного проброса props.

```typescript
// stores/user.ts
export const useUserStore = defineStore("user", {
  state: () => ({
    currentUser: null as User | null,
  }),
});
```

Такой state полезен для текущего пользователя, корзины, прав доступа, темы приложения.

## Как выбрать

Спроси: "Кому нужны эти данные?" Если одному компоненту - local. Если многим независимым частям - global.

## Частая ошибка

Выносить все в глобальный store "на всякий случай". Это делает приложение более связанным и усложняет тестирование.

## Мини-шпаргалка

- Local state проще и ближе к месту использования.
- Global state нужен для общих данных приложения.
- Не выноси временные UI-флаги в store без причины.
- Если props пробрасываются через много уровней, подумай о store или provide/inject.
