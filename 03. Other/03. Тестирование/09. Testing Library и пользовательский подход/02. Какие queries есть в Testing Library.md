# Какие queries есть в Testing Library?

> [!summary]
> Queries - это способы найти элементы в DOM. Testing Library рекомендует выбирать queries по тому, как пользователь воспринимает интерфейс: role, label, placeholder, text, display value, alt text, title и только потом test id.

## Приоритет queries

Обычно лучший порядок такой:

1. `getByRole`
2. `getByLabelText`
3. `getByPlaceholderText`
4. `getByText`
5. `getByDisplayValue`
6. `getByAltText`
7. `getByTitle`
8. `getByTestId`

Идея простая: если элемент можно найти через роль и имя, интерфейс обычно лучше с точки зрения доступности.

## `getByRole`

```ts
screen.getByRole('button', { name: 'Сохранить' });
screen.getByRole('textbox', { name: 'Email' });
screen.getByRole('heading', { name: 'Профиль' });
```

`role` отражает семантику элемента, а `name` - accessible name.

## `getByLabelText`

```ts
screen.getByLabelText('Email');
```

Полезно для form controls:

```html
<label for="email">Email</label>
<input id="email" />
```

## `getByText`

```ts
screen.getByText('Заказ оформлен');
```

Подходит для обычного текста, но для кнопок и полей лучше использовать role/label.

## `queryBy`, `findBy`, `getBy`

| Query | Когда использовать |
|---|---|
| `getBy...` | элемент должен быть сразу |
| `queryBy...` | элемент может отсутствовать |
| `findBy...` | элемент появится асинхронно |

Пример:

```ts
expect(screen.queryByText('Ошибка')).not.toBeInTheDocument();

expect(await screen.findByText('Данные загружены')).toBeInTheDocument();
```

## Мини-шпаргалка

- `getByRole` - главный query для интерактивных элементов.
- `getByLabelText` - хороший выбор для inputs.
- `queryBy` - когда элемента может не быть.
- `findBy` - когда элемент появляется после async action.
- `getByTestId` оставляй на крайний случай.
