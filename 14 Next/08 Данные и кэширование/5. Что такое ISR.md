# Что такое ISR?

> [!summary]
> ISR, или Incremental Static Regeneration, позволяет отдавать страницу как статическую, но обновлять ее после build по времени или по событию. Это компромисс между скоростью SSG и свежестью SSR.

## Формула

```text
ISR = static rendering + revalidation
```

Страница может быстро отдаваться из кеша, но периодически обновляться.

## App Router пример

```tsx
export const revalidate = 3600

export default async function ProductsPage() {
  const products = await getProducts()

  return <ProductList products={products} />
}
```

Route обновляется не чаще, чем раз в час.

## Fetch-level ISR

```tsx
const products = await fetch('https://api.example.com/products', {
  next: { revalidate: 3600 },
}).then((res) => res.json())
```

## On-demand ISR

```ts
'use server'

import { revalidatePath } from 'next/cache'

export async function updateProduct(formData: FormData) {
  await saveProduct(formData)
  revalidatePath('/products')
}
```

## Когда использовать?

- каталог товаров;
- статьи из CMS;
- документация;
- публичные профили;
- страницы категорий;
- контент, где допустима небольшая задержка обновления.

## Что отвечать на собеседовании?

ISR позволяет обновлять статически отрендеренные страницы или данные без полной пересборки сайта. В App Router это делается через `revalidate`, `next.revalidate`, `revalidatePath` и `revalidateTag`.

## Частые ошибки

- Думать, что ISR подходит для real-time.
- Считать, что каждый пользователь всегда видит свежие данные.
- Не инвалидировать страницу после CMS update.
- Использовать SSR там, где достаточно ISR.
- Путать ISR с client-side refetch.

## Мини-шпаргалка

- ISR обновляет статику.
- `export const revalidate = 3600`.
- `next: { revalidate: 3600 }`.
- `revalidatePath('/path')`.
- `revalidateTag('tag')`.
- Не для real-time данных.
