# Гарантия выполнения таймера

> [!NOTE] Коротко
> Таймер гарантирует минимальную задержку перед постановкой callback в очередь, но не точное время выполнения.

## Вопрос

Гарантирует ли `setTimeout(callback, 1000)`, что callback выполнится ровно через одну секунду?

## Определение

`setTimeout()` задает минимальную задержку. После ее истечения callback становится готовым к выполнению, но все еще должен дождаться свободного Call Stack и своей очереди в Event Loop.

Поэтому фактическое выполнение может произойти позже указанного времени.

## Пример задержки

```javascript
console.log('start');

setTimeout(() => {
  console.log('timer');
}, 1000);

const start = Date.now();

while (Date.now() - start < 3000) {
  // блокируем поток на 3 секунды
}

console.log('end');

// start
// end
// timer
```

Таймер должен был быть готов через 1 секунду, но callback выполнился только после освобождения стека.

## Что может задержать таймер

- тяжелый синхронный код;
- длинная очередь микротасок;
- активная вкладка или фоновый режим браузера;
- ограничения браузера на вложенные таймеры;
- нагрузка на процессор.

## Формулировка для собеседования

`setTimeout(fn, delay)` означает: "выполнить `fn` не раньше чем через `delay` миллисекунд, когда основной поток будет свободен".

## Мини-шпаргалка

```javascript
setTimeout(fn, 1000); // не раньше 1000 мс
```
