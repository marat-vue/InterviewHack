# Как читать HTTP request и response в DevTools?

> [!summary]
> Network tab в DevTools показывает реальный HTTP-обмен: method, URL, status, request headers, response headers, cookies, payload, response body, timing, cache и CORS-проблемы.

## Где смотреть?

Открой DevTools -> Network -> выбери запрос.

Обычно полезны вкладки:

- `Headers`;
- `Payload`;
- `Response`;
- `Preview`;
- `Cookies`;
- `Timing`;
- `Initiator`.

## Что смотреть в Headers?

```txt
Request URL: https://api.example.com/users
Request Method: POST
Status Code: 201 Created
Remote Address: 203.0.113.10:443
Referrer Policy: strict-origin-when-cross-origin
```

Ниже обычно есть:

- request headers;
- response headers;
- query string params;
- form data или request payload.

## Что проверять при ошибке?

| Симптом | Что смотреть |
|---|---|
| `401` | отправился ли `Authorization` или cookie |
| `403` | есть ли роль/permission |
| CORS error | `Origin`, preflight `OPTIONS`, `Access-Control-Allow-*` |
| Не обновились данные | method, payload, status, response body |
| Cache мешает | `Cache-Control`, `ETag`, `304`, size `(memory cache)` |
| Cookie не ставится | `Set-Cookie`, `SameSite`, `Secure`, `Domain`, `Path` |

## Почему request может не появиться?

Если ошибка произошла до сети, запроса может не быть:

- JavaScript exception до `fetch`;
- browser заблокировал mixed content;
- URL собран неправильно;
- request отменен `AbortController`;
- service worker перехватил запрос.

## Fetch и ошибки

```ts
const response = await fetch('/api/users');

if (!response.ok) {
  const error = await response.json();
  throw new Error(error.message);
}
```

`fetch` не бросает ошибку на `404` или `500`. В Network status будет красным, но в коде нужно проверить `response.ok`.

## Мини-шпаргалка

- Network tab показывает фактический HTTP.
- Всегда смотри method, URL, status, headers, payload и response.
- Для cookies проверяй `Set-Cookie` и вкладку Cookies.
- Для CORS ищи preflight `OPTIONS`.
- Для cache смотри `Cache-Control`, `ETag`, `304` и source.
