# Что делает useCallback()?

> [!summary]
> `useCallback` кэширует ссылку на функцию между рендерами. Он нужен не для того, чтобы "не создавать функцию", а для того, чтобы передавать стабильный callback туда, где важна ссылочная идентичность: в `memo`-компоненты, зависимости эффектов и кастомные хуки.

## Короткое определение

```jsx
const cachedFn = useCallback(fn, dependencies)
```

React вернет ту же функцию между рендерами, пока зависимости не изменились.

```jsx
function SearchPage({ onSearch }) {
  const [query, setQuery] = useState('')

  const handleSubmit = useCallback(() => {
    onSearch(query)
  }, [onSearch, query])

  return <SearchForm query={query} onSubmit={handleSubmit} onChange={setQuery} />
}
```

Если `query` или `onSearch` изменятся, React создаст новую версию `handleSubmit`. Если нет - вернет прежнюю ссылку.

## Почему ссылки на функции важны?

В JavaScript каждая новая функция - новая ссылка:

```jsx
function Parent() {
  const handleClick = () => {}

  return <Child onClick={handleClick} />
}
```

При каждом render `Parent` создается новый `handleClick`. Для обычного ребенка это часто не проблема. Но если ребенок обернут в `memo`, новая функция ломает поверхностное сравнение props.

```jsx
const Child = memo(function Child({ onClick }) {
  console.log('Child render')
  return <button onClick={onClick}>Save</button>
})
```

`memo` сравнит старый `onClick` и новый `onClick`, увидит разные ссылки и разрешит повторный render.

## Когда useCallback действительно полезен?

`useCallback` имеет смысл, когда:

- callback передается в компонент, обернутый в `memo`;
- callback передается в глубоко оптимизированный список;
- callback используется в зависимостях `useEffect`, `useMemo` или другого `useCallback`;
- кастомный хук возвращает функцию наружу, и потребители ожидают стабильную ссылку;
- profiler показал, что нестабильные callback-функции создают лишние render.

Пример с `memo`:

```jsx
const ProductRow = memo(function ProductRow({ product, onAdd }) {
  return <button onClick={() => onAdd(product.id)}>{product.title}</button>
})

function ProductList({ products }) {
  const addToCart = useCallback((productId) => {
    cartStore.add(productId)
  }, [])

  return products.map((product) => (
    <ProductRow key={product.id} product={product} onAdd={addToCart} />
  ))
}
```

## Важная ловушка: устаревшие замыкания

Если забыть зависимость, функция будет видеть старое значение.

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  const logCount = useCallback(() => {
    console.log(count)
  }, []) // плохо: count всегда из первого render
}
```

Правильно:

```jsx
const logCount = useCallback(() => {
  console.log(count)
}, [count])
```

Если нужно обновить state на основе предыдущего значения, часто можно убрать зависимость через functional update:

```jsx
const increment = useCallback(() => {
  setCount((count) => count + 1)
}, [])
```

## useCallback и useMemo

Эти варианты эквивалентны:

```jsx
const handleClick = useCallback(() => {
  save()
}, [save])

const handleClick = useMemo(() => {
  return () => save()
}, [save])
```

`useCallback` просто удобнее для функций.

## Мини-шпаргалка

- `useCallback` кэширует функцию, а не результат функции.
- Он полезен, когда важна стабильная ссылка.
- Сам по себе `useCallback` не ускоряет render.
- Неверные зависимости приводят к stale closure.
- Не стоит оборачивать все обработчики подряд.
