# Какие request utilities H3 нужно знать?

> [!NOTE]
> Request utilities H3 помогают читать и проверять входящий запрос: body, query, params, method, URL, host, IP, protocol, cache headers и content type. В Nitro это основной набор функций для работы с request внутри handler.

## Body utilities

| Метод | Зачем нужен |
|---|---|
| `assertBodySize(event, limit)` | ограничить размер body и выбросить `413`, если body слишком большой |
| `readBody(event, options?)` | прочитать body и распарсить JSON, URL-encoded или явно выбранный тип |
| `readValidatedBody(event, validate)` | прочитать body и валидировать через функцию или schema library |

Пример:

```ts
import { assertBodySize, readValidatedBody } from 'h3';
import { z } from 'zod';

const schema = z.object({
  title: z.string().min(1),
});

export default defineHandler(async (event) => {
  assertBodySize(event, 1024 * 1024);
  const body = await readValidatedBody(event, schema);

  return postService.create(body);
});
```

## Query method utilities

HTTP `QUERY` - это отдельный метод для безопасных, идемпотентных и cacheable read-запросов с body.

| Метод | Зачем нужен |
|---|---|
| `appendAcceptQuery(event, mediaTypes)` | добавить `Accept-Query` header и объявить поддерживаемые форматы QUERY body |
| `requireContentType(event, acceptedTypes)` | проверить `Content-Type` для request body и выбросить HTTP error при ошибке |

В обычном REST API эти helpers встречаются редко, но их полезно знать для сложных read endpoints.

## Cache header utility

| Метод | Зачем нужен |
|---|---|
| `handleCacheHeaders(event, opts)` | обработать conditional request headers и выставить `ETag`, `Last-Modified`, `Cache-Control` |

Используется, когда endpoint сам управляет HTTP caching.

## Method utilities

| Метод | Зачем нужен |
|---|---|
| `isMethod(event, expected, allowHead?)` | проверить request method |
| `assertMethod(event, expected, allowHead?)` | проверить method и выбросить `405 Method Not Allowed`, если он не подходит |

Пример:

```ts
import { assertMethod } from 'h3';

export default defineHandler((event) => {
  assertMethod(event, 'POST');

  return {
    ok: true,
  };
});
```

Если route уже называется `.post.ts`, `assertMethod` обычно не нужен.

## Query utilities

| Метод | Зачем нужен |
|---|---|
| `getQuery(event)` | получить parsed query object |
| `getValidatedQuery(event, validate)` | получить и валидировать query |

Пример:

```ts
const query = await getValidatedQuery(event, z.object({
  page: z.coerce.number().int().positive().default(1),
}));
```

## Route params utilities

| Метод | Зачем нужен |
|---|---|
| `getRouterParam(event, name, opts?)` | получить один route param |
| `getRouterParams(event, opts?)` | получить все route params |
| `getValidatedRouterParams(event, validate)` | получить и валидировать params |

Пример:

```ts
const { id } = await getValidatedRouterParams(event, z.object({
  id: z.string().uuid(),
}));
```

## URL, host, IP и protocol utilities

| Метод | Зачем нужен |
|---|---|
| `getRequestHost(event, opts?)` | получить host |
| `getRequestIP(event, opts?)` | получить IP клиента |
| `getRequestProtocol(event, opts?)` | получить `http`/`https` |
| `getRequestURL(event, opts?)` | получить полный URL |
| `getRequestFingerprint(event, opts)` | получить fingerprint запроса |

Важно: host и forwarded headers могут быть подделаны, если proxy/CDN не нормализует их.

## Request conversion utilities

| Метод | Зачем нужен |
|---|---|
| `toRequest(input, options?)` | привести input к Web `Request` |
| `requestWithBaseURL(req, base)` | создать lightweight request proxy с удаленным base path |
| `requestWithURL(req, url)` | создать lightweight request proxy с другим URL |

Обычно эти helpers нужны для adapters, proxy и integration-level кода.

## Мини-шпаргалка

- Body: `assertBodySize`, `readBody`, `readValidatedBody`.
- Query: `getQuery`, `getValidatedQuery`.
- Params: `getRouterParam`, `getRouterParams`, `getValidatedRouterParams`.
- Method: `isMethod`, `assertMethod`.
- URL: `getRequestURL`, `getRequestHost`, `getRequestIP`, `getRequestProtocol`.
- Для public API используй validated helpers, а не plain parsing.
