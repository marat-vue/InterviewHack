# Как работает TypeScript в Nuxt, auto imports и generated types?

> [!NOTE]
> Nuxt генерирует типы в `.nuxt`, настраивает project references, auto-import declarations и aliases. Поэтому Nuxt-проект не стоит типизировать как обычный Vue/Vite проект без учета generated files.

## Что генерирует Nuxt?

При `nuxt dev`, `nuxt build` или `nuxt prepare` Nuxt создает:

```text
.nuxt/
  tsconfig.app.json
  tsconfig.server.json
  tsconfig.shared.json
  imports.d.ts
  components.d.ts
  types/
```

Это нужно для:

- auto-import composables;
- auto-import components;
- aliases `#imports`, `#app`, `#build`;
- server route types;
- module-provided types;
- correct app/server/shared TypeScript contexts.

## `nuxt prepare`

Если IDE не видит Nuxt types после clone:

```bash
npx nuxi prepare
```

или:

```bash
pnpm nuxt prepare
```

Эта команда генерирует `.nuxt` без запуска dev server.

## Typecheck

Установка:

```bash
pnpm add -D typescript vue-tsc
```

Команда:

```bash
pnpm nuxt typecheck
```

Можно включить typecheck в build/dev:

```ts
export default defineNuxtConfig({
  typescript: {
    typeCheck: true
  }
})
```

Для больших проектов лучше запускать typecheck отдельной CI-командой, чтобы dev/build не стали слишком медленными.

## Почему не редактировать `.nuxt/tsconfig.*`?

`.nuxt` - generated directory. Любые ручные изменения будут потеряны.

Правильно расширять root `tsconfig.json`:

```json
{
  "extends": "./.nuxt/tsconfig.json"
}
```

или настраивать через `nuxt.config.ts`, если option относится к Nuxt.

## Auto imports

Nuxt auto-imports:

- Vue composables: `ref`, `computed`, `watch`;
- Nuxt composables: `useFetch`, `useRuntimeConfig`, `useRoute`;
- composables из `app/composables`;
- utils из `app/utils`;
- components из `app/components`.

Пример:

```ts
// app/composables/useMoney.ts
export function useMoney(value: number) {
  return new Intl.NumberFormat('ru-RU', {
    style: 'currency',
    currency: 'RUB'
  }).format(value)
}
```

Использование без import:

```vue
<script setup lang="ts">
const price = useMoney(1000)
</script>
```

## Когда лучше явный import?

Auto imports удобны, но явный import может быть лучше:

- в shared libraries;
- в plain TypeScript files вне Nuxt context;
- когда функция имеет конфликтующее имя;
- когда важна читаемость dependency;
- в tests без Nuxt environment.

## Типизация provided values

Plugin:

```ts
export default defineNuxtPlugin(() => {
  const api = $fetch.create({
    baseURL: '/api'
  })

  return {
    provide: {
      api
    }
  }
})
```

Типы:

```ts
declare module '#app' {
  interface NuxtApp {
    $api: typeof $fetch
  }
}

declare module 'vue' {
  interface ComponentCustomProperties {
    $api: typeof $fetch
  }
}

export {}
```

## Server/shared типы

Nuxt разделяет contexts:

```text
app/     -> browser + SSR Vue app
server/  -> Nitro server
shared/  -> общий код без browser/server-specific API
```

Не импортируй server-only код в component:

```ts
// плохо
import { prisma } from '~/server/utils/prisma'
```

В component ходи через API route:

```ts
const { data } = await useFetch('/api/products')
```

## Typed API responses

Простой подход:

```ts
type Product = {
  id: string
  title: string
  price: number
}

const { data } = await useFetch<Product[]>('/api/products')
```

Для больших проектов лучше выносить contracts:

```text
shared/types/product.ts
```

и использовать один тип на server и client.

## Что отвечать на собеседовании?

Nuxt генерирует TypeScript types в `.nuxt`: auto imports, components, aliases, app/server/shared tsconfig и module types. После clone полезно запускать `nuxt prepare`, а для проверки типов - `nuxt typecheck`. Важно не редактировать generated `.nuxt` файлы и не импортировать server-only код в client components.

## Частые ошибки

- Редактировать `.nuxt/tsconfig`.
- Не запускать `nuxt prepare` в CI/IDE setup.
- Думать, что `nuxt build` всегда делает полноценный typecheck.
- Импортировать Prisma/server utils в Vue component.
- Не типизировать `$api` из plugin.
- Создавать auto-import функции с конфликтующими именами.

## Мини-шпаргалка

- Generated types: `.nuxt`.
- Prepare: `nuxi prepare`.
- Typecheck: `nuxt typecheck`.
- Root tsconfig extends `.nuxt/tsconfig.json`.
- `app` != `server` != `shared`.
- Contracts удобно хранить в `shared/types`.
