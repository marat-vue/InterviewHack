# Чем useReducer отличается от useState?

> [!summary]
> `useState` удобен для простого состояния, а `useReducer` - для сложной логики обновлений, нескольких связанных полей и действий, которые лучше описывать явно. Оба хука хранят state, но обновляют его по-разному.

## useState

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

`useState` хорош, когда обновления простые и понятные.

## useReducer

```jsx
function reducer(state, action) {
  switch (action.type) {
    case 'increment':
      return { count: state.count + 1 }
    case 'decrement':
      return { count: state.count - 1 }
    default:
      return state
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 })

  return (
    <>
      <button onClick={() => dispatch({ type: 'decrement' })}>-</button>
      <span>{state.count}</span>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
    </>
  )
}
```

`dispatch` отправляет action, а reducer решает, каким будет следующий state.

## Когда выбрать useState?

- Одно-два простых значения.
- Простые boolean-флаги.
- Простая форма.
- Локальное UI-состояние.
- Логика обновления находится рядом и читается легко.

## Когда выбрать useReducer?

- Много связанных полей.
- Сложные переходы состояний.
- Несколько типов действий.
- Обновления трудно читать в handlers.
- Нужно вынести логику из компонента.
- Удобно тестировать reducer отдельно.

## Важное правило reducer

Reducer должен быть чистой функцией:

```text
nextState = reducer(previousState, action)
```

Внутри reducer не нужно делать запросы, мутировать state или вызывать случайные side effects.

## Мини-шпаргалка

- `useState` проще для простого state.
- `useReducer` лучше для сложной логики обновления.
- Reducer принимает `state` и `action`, возвращает новый state.
- `dispatch` описывает событие, а не напрямую меняет значение.
- Reducer должен быть чистым.
