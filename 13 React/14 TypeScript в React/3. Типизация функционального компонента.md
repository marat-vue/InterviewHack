# Типизация функционального компонента

> [!summary]
> Функциональный компонент в React обычно типизируют через отдельный `type Props` и обычную функцию. TypeScript сам выводит возвращаемый тип, а props, children, events, refs и нативные HTML-атрибуты описываются явно.

## Базовый паттерн

```tsx
type CardProps = {
  title: string
  children?: React.ReactNode
}

function Card({ title, children }: CardProps) {
  return (
    <article>
      <h2>{title}</h2>
      {children}
    </article>
  )
}
```

Это самый читаемый и распространенный вариант.

## Нужно ли указывать возвращаемый тип?

Обычно нет:

```tsx
function Badge({ label }: { label: string }) {
  return <span>{label}</span>
}
```

TypeScript сам понимает, что компонент возвращает React-элемент.

Иногда можно указать явно:

```tsx
function EmptyState(): React.ReactElement {
  return <p>No data</p>
}
```

Если компонент может ничего не рендерить:

```tsx
function ErrorMessage({ error }: { error?: string }): React.ReactElement | null {
  if (!error) {
    return null
  }

  return <p>{error}</p>
}
```

Но в большинстве случаев явный return type не нужен.

## Props с union

Union-типы помогают описывать варианты компонента:

```tsx
type AlertProps =
  | { status: 'success'; message: string }
  | { status: 'error'; message: string; retry: () => void }

function Alert(props: AlertProps) {
  if (props.status === 'error') {
    return (
      <div>
        {props.message}
        <button onClick={props.retry}>Retry</button>
      </div>
    )
  }

  return <div>{props.message}</div>
}
```

TypeScript понимает, что `retry` есть только у `error`.

## Нативные props элемента

Если компонент оборачивает `<button>`, не нужно вручную перечислять `onClick`, `disabled`, `type` и другие HTML-props:

```tsx
type ButtonProps = React.ComponentProps<'button'> & {
  variant?: 'primary' | 'secondary'
}

function Button({ variant = 'primary', ...props }: ButtonProps) {
  return <button data-variant={variant} {...props} />
}
```

Так компонент принимает все стандартные props кнопки.

## Исключение конфликтующего prop

Если нужно переопределить prop:

```tsx
type LinkButtonProps = Omit<React.ComponentProps<'a'>, 'href'> & {
  to: string
}

function LinkButton({ to, ...props }: LinkButtonProps) {
  return <a href={to} {...props} />
}
```

`Omit` убирает `href`, чтобы вместо него использовать `to`.

## Компонент с generic

```tsx
type ListProps<T> = {
  items: T[]
  getKey: (item: T) => string
  renderItem: (item: T) => React.ReactNode
}

function List<T>({ items, getKey, renderItem }: ListProps<T>) {
  return (
    <ul>
      {items.map((item) => (
        <li key={getKey(item)}>{renderItem(item)}</li>
      ))}
    </ul>
  )
}
```

Использование:

```tsx
<List
  items={[{ id: '1', name: 'Ada' }]}
  getKey={(user) => user.id}
  renderItem={(user) => user.name}
/>
```

TypeScript сам выведет тип `user`.

## React.FC использовать или нет?

Можно встретить такой стиль:

```tsx
const Card: React.FC<CardProps> = ({ title }) => {
  return <article>{title}</article>
}
```

Но в современных проектах часто предпочитают обычную функцию:

```tsx
function Card({ title }: CardProps) {
  return <article>{title}</article>
}
```

Причины:

- меньше шума;
- проще generic-компоненты;
- проще читать props;
- возвращаемый тип обычно выводится автоматически.

`React.FC` не запрещен, но не нужен по умолчанию.

## Что отвечать на собеседовании?

Функциональный компонент обычно типизируют через `type Props` и обычную функцию. `children` явно добавляют как `React.ReactNode`, HTML-атрибуты наследуют через `React.ComponentProps<'button'>`, а сложные варианты props удобно описывать union-типами.

## Частые ошибки

- Типизировать props как `any`.
- Использовать `React.FC` везде без необходимости.
- Забывать явно добавить `children`.
- Вручную перечислять все нативные props вместо `ComponentProps`.
- Делать props слишком широкими.

## Мини-шпаргалка

- База: `type Props = {...}; function Component(props: Props)`.
- Return type чаще всего выводится сам.
- `children?: React.ReactNode`.
- HTML props: `React.ComponentProps<'button'>`.
- Конфликты props решает `Omit`.
