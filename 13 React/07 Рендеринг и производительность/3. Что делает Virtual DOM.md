# Что делает Virtual DOM?

> [!summary]
> Virtual DOM - популярное название модели, где React работает с легковесным описанием UI, а не напрямую с DOM на каждом шаге. Компоненты возвращают React-элементы, React сравнивает старое и новое дерево и затем применяет нужные изменения к настоящему DOM.

## Что возвращает компонент?

```jsx
function Title() {
  return <h1>React</h1>
}
```

React получает не DOM-узел, а описание UI:

```js
{
  type: 'h1',
  props: {
    children: 'React'
  }
}
```

## Как это помогает?

Virtual DOM помогает:

- писать декларативный UI;
- не управлять DOM вручную;
- сравнивать старое и новое дерево;
- применять только нужные DOM-изменения;
- строить UI из компонентов.

## Упрощенная схема обновления

```text
state changed
component render
new React element tree
diff/reconciliation
commit DOM updates
```

## Важный нюанс про производительность

Фраза "Virtual DOM всегда быстрее DOM" некорректна.

Правильнее:

```text
Virtual DOM дает удобную модель обновления UI. Производительность зависит от размера дерева, reconciliation, keys, state placement, memoization и стоимости настоящего DOM.
```

Иногда ручной DOM-код может быть быстрее, но React выигрывает в предсказуемости и архитектуре.

## Мини-шпаргалка

- Virtual DOM - описание UI в памяти.
- Компоненты возвращают React-элементы.
- React сравнивает старое и новое дерево.
- DOM обновляется на commit-этапе.
- Virtual DOM не заменяет понимание performance.
