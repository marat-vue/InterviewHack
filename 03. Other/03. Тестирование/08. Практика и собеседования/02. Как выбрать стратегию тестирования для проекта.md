# Как выбрать стратегию тестирования для проекта?

> [!summary]
> Стратегия тестирования зависит от рисков проекта, архитектуры, команды и стоимости ошибки. Хорошая стратегия распределяет проверки между unit, integration, component, e2e, visual и accessibility tests.

## С чего начать?

Сначала опиши риски:

- где деньги?
- где персональные данные?
- где сложная бизнес-логика?
- где много условий?
- где часто бывают баги?
- какие flows критичны для продукта?

Потом выбери уровень теста.

## Пример для frontend app

Для интернет-магазина:

- unit: price formatting, discounts, validators;
- component: product card, cart item, checkout form;
- integration: cart store + components;
- e2e: login, add to cart, checkout;
- visual: UI-kit components;
- accessibility: forms, modals, navigation.

## Пример для backend API

Для API заказов:

- unit: order total, permissions rules;
- integration: service + repository;
- endpoint tests: status codes, validation, auth;
- database tests: transactions, constraints;
- contract tests: API response shape;
- e2e: full order creation with test database.

## Как понять, что тестов достаточно?

Нет универсального числа. Хороший признак:

- критичные flows покрыты;
- бизнес-правила покрыты;
- ошибки и permissions покрыты;
- команда доверяет тестам;
- тесты не слишком часто flaky;
- тесты помогают менять код быстрее.

## Что запускать в CI?

Обычно:

```bash
npm run lint
npm run typecheck
npm run test:run
npm run build
```

Для больших проектов:

- быстрые тесты на каждый push;
- e2e/visual tests на pull request или nightly;
- coverage report;
- Storybook build.

## Мини-шпаргалка

- Стратегия начинается с рисков.
- Unit tests покрывают логику.
- Component tests покрывают UI states.
- Integration tests покрывают связи.
- E2E tests покрывают критичные flows.
- CI должен быть быстрым и надежным.
