# Как искать memory leak в Node.js?

> [!summary]
> Memory leak - это ситуация, когда приложение продолжает удерживать память, которая больше не нужна. В Node.js утечки часто возникают из-за глобальных коллекций, кэшей без лимита, забытых listeners, таймеров и удержания больших объектов замыканиями.

## Частые причины

| Причина | Пример |
|---|---|
| Глобальный массив | В него постоянно добавляют данные запросов |
| Кэш без TTL | Объекты никогда не удаляются |
| EventEmitter listeners | Подписки создаются, но не снимаются |
| Таймеры | `setInterval` продолжает держать ссылки |
| Замыкания | Функция удерживает большой объект |

## Пример утечки

```js
const requests = [];

function handleRequest(req, res) {
  requests.push({
    url: req.url,
    headers: req.headers,
  });

  res.end('ok');
}
```

Массив растет бесконечно.

## Что смотреть?

```js
console.log(process.memoryUsage());
```

Полезные поля:

| Поле | Значение |
|---|---|
| `rss` | Вся память процесса |
| `heapUsed` | Использованная JS heap |
| `heapTotal` | Выделенная JS heap |
| `external` | Память вне V8 heap, например Buffers |

## Практический план поиска

1. Воспроизвести рост памяти под нагрузкой.
2. Снять heap snapshot.
3. Сравнить snapshots во времени.
4. Найти объекты, которые должны были быть удалены.
5. Проверить, кто удерживает ссылки.

## Мини-шпаргалка

- Утечка - память больше не нужна, но ссылка на нее осталась.
- Проверяй кэши, массивы, listeners и таймеры.
- `process.memoryUsage()` дает быстрый обзор.
- Heap snapshot помогает найти удерживающие ссылки.
- У кэшей должны быть лимиты, TTL или стратегия очистки.
