# Что такое React Server Components (RSC)?

> [!summary]
> React Server Components - это компоненты, которые выполняются на сервере и не отправляют свой JavaScript-код в браузер. Они отличаются от SSR: SSR производит HTML, а RSC передают описание React-дерева, которое может объединяться с Client Components.

## Server Component

Server Component может:

- быть `async`;
- читать данные рядом с компонентом;
- обращаться к БД и файловой системе;
- использовать server-only зависимости;
- не попадать в client bundle.

```tsx
// app/products/page.tsx
import { db } from '@/db'
import { LikeButton } from './LikeButton'

export default async function ProductsPage() {
  const products = await db.product.findMany()

  return (
    <main>
      {products.map((product) => (
        <article key={product.id}>
          <h2>{product.title}</h2>
          <LikeButton productId={product.id} />
        </article>
      ))}
    </main>
  )
}
```

## Client Component

Client Component нужен для интерактивности.

```tsx
'use client'

import { useState } from 'react'

export function LikeButton({ productId }: { productId: string }) {
  const [liked, setLiked] = useState(false)

  return (
    <button onClick={() => setLiked((value) => !value)}>
      {liked ? 'Liked' : 'Like'} {productId}
    </button>
  )
}
```

## Что нельзя в Server Component?

Нельзя использовать:

- `useState`;
- `useEffect`;
- event handlers;
- `window`;
- `document`;
- browser-only libraries;
- обычные функции как props в Client Component.

Props через server-client boundary должны быть сериализуемыми.

## RSC vs SSR

| Вопрос | SSR | RSC |
|---|---|---|
| Что генерирует сервер | HTML | React Server Component payload |
| Нужна hydration | Для клиентского React tree | Только для Client Components |
| JS серверных частей в браузере | Обычно да, если это client app | Нет |
| Где data fetching | Обычно loaders/server code | Прямо в Server Components |

RSC и SSR могут использоваться вместе. Например, фреймворк может сначала отдать HTML через SSR, а Server Components уменьшат клиентский JavaScript.

## Зачем это нужно?

- меньше client bundle;
- меньше hydration;
- проще data fetching;
- server secrets остаются на сервере;
- тяжелые зависимости не едут в браузер;
- проще разделять интерактивное и неинтерактивное.

## Мини-шпаргалка

- RSC выполняются на сервере.
- Server Components не отправляют JS в браузер.
- `'use client'` задает client boundary.
- Client Components нужны для интерактива.
- SSR и RSC - разные, но совместимые технологии.
