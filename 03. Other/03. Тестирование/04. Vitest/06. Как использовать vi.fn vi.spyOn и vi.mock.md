# Как использовать vi.fn, vi.spyOn и vi.mock?

> [!summary]
> `vi.fn` создает mock-функцию, `vi.spyOn` следит за существующим методом, `vi.mock` подменяет модуль. Эти инструменты помогают изолировать код от зависимостей и проверять взаимодействия.

## `vi.fn`

`vi.fn` создает функцию-заглушку:

```ts
const onSubmit = vi.fn();

await wrapper.get('form').trigger('submit');

expect(onSubmit).toHaveBeenCalled();
```

Можно задать результат:

```ts
const loadUser = vi.fn().mockResolvedValue({ id: 1, name: 'Ann' });
```

## `vi.spyOn`

`vi.spyOn` следит за методом существующего объекта:

```ts
const spy = vi.spyOn(console, 'warn').mockImplementation(() => {});

logger.warnInvalidToken();

expect(spy).toHaveBeenCalledWith('Invalid token');

spy.mockRestore();
```

Spy полезен, когда объект настоящий, но нужно проверить конкретный вызов.

## `vi.mock`

`vi.mock` подменяет весь модуль:

```ts
vi.mock('@/api/users', () => ({
  getUser: vi.fn(),
}));
```

Использование:

```ts
import { getUser } from '@/api/users';

vi.mocked(getUser).mockResolvedValue({ id: 1, name: 'Ann' });
```

Важно: `vi.mock` поднимается наверх файла. Поэтому не стоит строить фабрику mock на переменных, объявленных ниже, если не понимаешь hoisting.

## Очистка mocks

```ts
afterEach(() => {
  vi.clearAllMocks();
});
```

Если spy менял оригинальную реализацию:

```ts
afterEach(() => {
  vi.restoreAllMocks();
});
```

## Мини-шпаргалка

- `vi.fn` - создать mock-функцию.
- `vi.spyOn` - следить за существующим методом.
- `vi.mock` - подменить модуль.
- `mockResolvedValue` - успешный async result.
- `mockRejectedValue` - async error.
- Очищай mocks между тестами.
