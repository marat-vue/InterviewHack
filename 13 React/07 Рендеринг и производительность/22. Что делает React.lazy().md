# Что делает React.lazy()?

> [!summary]
> `React.lazy` позволяет объявить компонент, код которого будет загружен позже через dynamic `import()`. Когда React впервые пытается отрендерить такой компонент, он приостанавливает render ближайшей Suspense-границей и показывает `fallback`.

## Базовый пример

```jsx
import { lazy, Suspense } from 'react'

const SettingsPage = lazy(() => import('./SettingsPage'))

export function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <SettingsPage />
    </Suspense>
  )
}
```

Модуль `SettingsPage` должен иметь `default export`:

```jsx
export default function SettingsPage() {
  return <h1>Settings</h1>
}
```

## Что возвращает lazy?

`lazy` возвращает React-компонент. Это не Promise и не результат импорта.

```jsx
const SettingsPage = lazy(() => import('./SettingsPage'))

// SettingsPage можно использовать как обычный компонент
<SettingsPage />
```

React сам:

- вызовет функцию загрузки при первом render;
- дождется Promise;
- возьмет `default` export;
- закеширует Promise и загруженный компонент;
- повторно не будет загружать тот же модуль без причины.

## Пример с роутингом

```jsx
const HomePage = lazy(() => import('./pages/HomePage'))
const ProfilePage = lazy(() => import('./pages/ProfilePage'))
const ReportsPage = lazy(() => import('./pages/ReportsPage'))

function AppRoutes() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Routes>
        <Route path="/" element={<HomePage />} />
        <Route path="/profile" element={<ProfilePage />} />
        <Route path="/reports" element={<ReportsPage />} />
      </Routes>
    </Suspense>
  )
}
```

Так каждая крупная страница может попасть в отдельный chunk.

## Что делать с named export?

`lazy` ожидает `default`. Если компонент экспортируется именованно:

```jsx
export function SettingsPage() {}
```

Можно сделать промежуточный модуль:

```jsx
// SettingsPage.lazy.js
export { SettingsPage as default } from './SettingsPage'
```

И импортировать его:

```jsx
const SettingsPage = lazy(() => import('./SettingsPage.lazy'))
```

## Lazy loading и ошибки

Если chunk не загрузился, ошибка должна попасть в ближайший Error Boundary.

```jsx
<ErrorBoundary fallback={<p>Failed to load page</p>}>
  <Suspense fallback={<PageSkeleton />}>
    <SettingsPage />
  </Suspense>
</ErrorBoundary>
```

Это важно для плохой сети, устаревшего deploy и проблем CDN.

## Мини-шпаргалка

- `lazy` работает через dynamic `import()`.
- Нужен default export.
- Нужен `<Suspense fallback={...}>`.
- Ошибки загрузки стоит ловить Error Boundary.
- Лучше лениво грузить крупные страницы и тяжелые виджеты.
