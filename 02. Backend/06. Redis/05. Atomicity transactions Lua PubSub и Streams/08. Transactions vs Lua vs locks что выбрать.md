# Transactions vs Lua vs locks: что выбрать?

> [!NOTE]
> Redis дает несколько способов управлять конкурентностью: atomic commands, transactions, Lua scripts и locks. Выбор зависит от того, нужна ли атомарность одной команды, нескольких команд или coordination между процессами.

## Сначала ищи готовую команду

Если есть готовая команда, используй ее:

```redis
INCR counter
SADD users user:1
ZINCRBY leaderboard 10 user:1
SET lock:job:42 token NX PX 30000
```

Это проще и надежнее, чем писать свою логику.

## Когда выбрать MULTI/EXEC?

Выбирай transaction, если:

- нужно выполнить несколько команд подряд;
- нет сложных условий;
- optimistic locking через `WATCH` достаточно;
- rollback не нужен.

```redis
MULTI
SET a 1
SET b 2
EXEC
```

## Когда выбрать Lua?

Выбирай Lua, если:

- нужно read-check-write атомарно;
- нужна conditional logic;
- нужно безопасно удалить lock;
- нужен token bucket;
- нужно claim jobs из sorted set;
- нужно сохранить TTL вместе с update.

Lua работает на сервере и блокирует Redis на время выполнения, поэтому script должен быть коротким.

## Когда выбрать lock?

Lock нужен для coordination:

- один worker прогревает cache;
- один instance запускает scheduled job;
- один процесс выполняет migration-like task.

Но lock не должен быть единственной защитой critical domain invariants.

## Когда выбрать SQL transaction?

Если операция меняет деньги, заказы, inventory или права доступа, лучше source of truth transaction:

```txt
PostgreSQL transaction + unique constraints + idempotency key
```

Redis можно использовать рядом, но не вместо доменной консистентности.

## Мини-шпаргалка

- Atomic command - первый выбор.
- MULTI/EXEC - несколько команд без сложной логики.
- Lua - сложная атомарная логика.
- Lock - coordination между workers.
- SQL transaction - доменная целостность.
