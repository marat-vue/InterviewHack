# Почему Client Components дороже?

> [!summary]
> Client Components дороже Server Components, потому что их код отправляется в браузер, участвует в гидратации, выполняется на устройстве пользователя и может увеличивать JS-бандл, нагрузку на main thread и задержку интерактивности.

## Что значит "дороже"?

Дороже - не значит "плохо". Это значит, что компонент требует больше ресурсов:

- сетевых;
- CPU;
- памяти;
- времени гидратации;
- клиентского JavaScript;
- архитектурной поддержки состояния.

Client Components нужны для интерактивности, но их стоит использовать осознанно.

## Server Component vs Client Component

```tsx
// Server Component
export default async function ProductPage() {
  const product = await getProduct()
  return <ProductDetails product={product} />
}
```

Такой компонент может выполниться на сервере, получить данные и не отправить свой код в браузер.

Client Component:

```tsx
'use client'

export function AddToCartButton({ id }: { id: string }) {
  const [isPending, setIsPending] = useState(false)

  return (
    <button onClick={() => addToCart(id)}>
      Добавить в корзину
    </button>
  )
}
```

Этот код нужен браузеру, потому что есть состояние и обработчик клика.

## 1. Client Components попадают в JS bundle

Все, что импортируется из Client Component, становится частью клиентского module graph.

```tsx
'use client'

import HeavyChart from 'heavy-chart-library'
import { formatReport } from '@/lib/report-format'
```

Если `formatReport` тянет тяжелые зависимости, они тоже могут попасть на клиент.

## 2. Нужна hydration

Если сервер отдал HTML, React должен подключить к нему клиентскую логику:

```text
HTML visible -> JS loaded -> React hydrates -> events work
```

Пока гидратация не завершилась, интерфейс может выглядеть готовым, но еще не быть полностью интерактивным.

## 3. Работа выполняется на устройстве пользователя

Client Component выполняется в браузере:

- форматирует данные;
- обрабатывает события;
- пересчитывает state;
- ререндерит UI;
- работает с DOM;
- запускает эффекты.

На слабых устройствах это может ухудшить INP.

## 4. Client Components не могут напрямую читать серверные ресурсы

В них нельзя напрямую:

- обращаться к базе;
- читать файлы сервера;
- использовать секретные env-переменные;
- вызывать Node.js-only API.

Поэтому часто нужен дополнительный слой:

```text
Client Component -> API / Server Action -> database
```

Если спроектировать плохо, появляются лишние запросы и waterfall.

## Как правильно выбирать Client Component?

Client Component нужен, если есть:

- `useState`;
- `useEffect`;
- `onClick`, `onChange`, `onSubmit`;
- browser APIs: `window`, `document`, `localStorage`;
- анимации;
- drag and drop;
- форма с интерактивным состоянием;
- клиентский store;
- realtime UI.

Все остальное лучше сначала пробовать как Server Component.

## Хороший паттерн: серверная оболочка, клиентский остров

```tsx
// app/products/[id]/page.tsx
export default async function ProductPage({ params }: Props) {
  const { id } = await params
  const product = await getProduct(id)

  return (
    <>
      <ProductInfo product={product} />
      <AddToCartButton productId={product.id} />
    </>
  )
}
```

```tsx
// app/products/[id]/add-to-cart-button.tsx
'use client'

export function AddToCartButton({ productId }: { productId: string }) {
  return <button onClick={() => addToCart(productId)}>В корзину</button>
}
```

Большая часть страницы остается серверной, клиентским становится только интерактивный элемент.

## Что отвечать на собеседовании?

Client Components дороже, потому что их код отправляется в браузер, требует гидратации и выполняется на устройстве пользователя. Они увеличивают JS-бандл, могут блокировать main thread и ухудшать INP. В Next.js рекомендуемый подход - использовать Server Components по умолчанию, а Client Components выделять только для интерактивных частей интерфейса.

## Частые ошибки

- Ставить `'use client'` на весь layout.
- Делать страницу Client Component только ради одной кнопки.
- Импортировать server-only код в Client Component.
- Передавать в Client Component несериализуемые props.
- Грузить тяжелый UI-kit в первом экране.
- Забывать, что все imports клиентского компонента могут попасть в browser bundle.

## Мини-шпаргалка

- Client Component нужен для интерактивности.
- Его код попадает в браузер.
- Он требует hydration.
- Он увеличивает JS cost.
- Он не читает базу напрямую.
- Лучший паттерн - server page + small client islands.
