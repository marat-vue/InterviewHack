# Как выбрать Redis, SQL, PostgreSQL, MongoDB или in-memory cache?

> [!NOTE]
> Redis часто выбирают из-за скорости, но скорость не должна быть единственным критерием. Выбор хранилища зависит от модели данных, durability, queries, relations, latency, масштаба и операционных требований.

## Когда выбрать Redis?

Redis подходит, если нужны:

- быстрые key-value операции;
- TTL;
- атомарные counters;
- sessions;
- cache;
- Pub/Sub;
- Streams;
- leaderboard;
- rate limiting;
- distributed coordination.

Пример:

```redis
INCR rate:user:42
EXPIRE rate:user:42 60
```

## Когда выбрать PostgreSQL?

PostgreSQL подходит, если нужны:

- relations;
- foreign keys;
- transactions ACID;
- сложные фильтры;
- JOIN;
- reporting;
- migrations;
- constraints;
- долгоживущие доменные данные.

Пример: пользователи, заказы, платежи, права доступа, аудит.

## Когда выбрать MongoDB?

MongoDB может быть удобен, если:

- данные документные;
- структура гибкая;
- документы читаются целиком;
- нужны nested documents;
- команда уже умеет MongoDB;
- relations ограничены.

Но MongoDB не заменяет Redis для low-latency counters/TTL/cache, и Redis не заменяет MongoDB для больших документных коллекций с query language.

## Когда хватит in-memory cache в Node.js?

Обычный `Map` подходит, если:

- приложение запущено в одном процессе;
- данные disposable;
- не нужно делить состояние между инстансами;
- restart очищает cache без проблемы;
- нет горизонтального масштабирования.

```ts
const cache = new Map<string, unknown>();
```

Как только процессов несколько, каждый `Map` станет отдельным cache, и данные начнут расходиться.

## Таблица выбора

| Требование | Лучше выбрать |
|---|---|
| Relations и JOIN | PostgreSQL |
| Cache с TTL | Redis |
| Session store для нескольких инстансов | Redis |
| Сложные аналитические запросы | PostgreSQL |
| Документная модель | MongoDB |
| Leaderboard | Redis sorted set |
| Очередь с retry/replay | Redis Streams или queue system |
| Локальный cache одного процесса | `Map` / LRU cache |
| Strong consistency доменной транзакции | SQL |

## Как часто Redis работает рядом с SQL?

Очень часто:

```txt
PostgreSQL -> source of truth
Redis -> cache, rate limit, sessions, events
Node.js -> business logic
```

Это нормальная архитектура. Redis берет на себя быстрые инфраструктурные операции, SQL хранит доменную правду.

## Что сказать на собеседовании?

Хороший ответ:

> Я не выбираю Redis только потому, что он быстрый. Если данные доменные, relational и требуют строгой целостности, беру SQL. Если нужны TTL, counters, cache, Pub/Sub, Streams или leaderboard, Redis хорошо подходит. Часто Redis идет рядом с PostgreSQL, а не вместо него.

## Мини-шпаргалка

- Redis - скорость, TTL, атомарность, realtime.
- SQL - отношения, constraints, ACID, аналитика.
- MongoDB - document model.
- `Map` - только локальный disposable cache.
- Хороший backend часто использует несколько хранилищ под разные задачи.
