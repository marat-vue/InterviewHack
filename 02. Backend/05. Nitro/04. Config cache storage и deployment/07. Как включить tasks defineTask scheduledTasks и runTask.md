# Как включить tasks, defineTask, scheduledTasks и runTask?

> [!NOTE]
> Nitro tasks - экспериментальный API для одноразовых runtime operations: миграции, seed, очистка, синхронизация CMS, прогрев cache. Tasks можно описывать файлами, регистрировать в config, запускать по расписанию или программно через `runTask`.

## Как включить tasks?

```ts
export default defineConfig({
  experimental: {
    tasks: true,
  },
});
```

## Как создать task?

```ts
// server/tasks/db/seed.ts
export default defineTask({
  meta: {
    name: 'db:seed',
    description: 'Seed database',
  },
  async run({ payload, context }) {
    await seedDatabase(payload);

    return {
      result: 'ok',
    };
  },
});
```

Nested directories превращаются в task name:

```txt
tasks/db/migrate.ts -> db:migrate
tasks/cms/update.ts -> cms:update
```

## Task interface

```ts
interface Task<RT = unknown> {
  meta?: {
    name?: string;
    description?: string;
  };
  run(event: TaskEvent): { result?: RT } | Promise<{ result?: RT }>;
}
```

`TaskEvent` содержит:

| Поле | Что значит |
|---|---|
| `name` | имя task |
| `payload` | данные, переданные в task |
| `context` | runtime context, может содержать `waitUntil` |

## Регистрация через config

```ts
export default defineConfig({
  experimental: {
    tasks: true,
  },
  tasks: {
    'db:migrate': {
      handler: './tasks/custom-migrate.ts',
      description: 'Run database migrations',
    },
  },
});
```

Если task есть и в `tasks/`, и в config, config-defined handler имеет приоритет.

## Scheduled tasks

```ts
export default defineConfig({
  scheduledTasks: {
    '* * * * *': ['cms:update'],
    '0 * * * *': 'db:cleanup',
  },
});
```

Cron expression мапится на одну task или массив tasks. Несколько tasks в одном cron могут выполняться параллельно.

## Programmatic runTask

```ts
import { runTask } from 'nitro/task';

export default defineHandler(async (event) => {
  await requireAdmin(event);

  const { result } = await runTask('db:migrate', {
    payload: {
      dryRun: true,
    },
  });

  return {
    result,
  };
});
```

Важно: endpoint, который запускает task, должен быть защищен auth/authorization и validation.

## Ошибки runTask

`runTask` бросает HTTP error, если:

- task не существует - `404`;
- у task нет handler implementation - `501`;
- внутри `run` произошла ошибка - она пробрасывается вызывающему коду.

## Когда использовать tasks?

Подходящие задачи:

- `db:seed`;
- `db:migrate` для internal workflows;
- `cache:warm`;
- `cms:update`;
- `sessions:cleanup`;
- `emails:retry`;
- `reports:generate`.

Не стоит использовать tasks вместо:

- очереди задач для high-volume jobs;
- надежного background worker;
- transactional business logic;
- payment processing.

## Мини-шпаргалка

- Tasks experimental.
- Включаются через `experimental.tasks`.
- `defineTask` описывает task.
- `scheduledTasks` задает cron.
- `runTask` запускает task из кода.
- Админские task endpoints обязательно защищай.
