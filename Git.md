
| Команда                                            | Пояснение                                                                                                                                                                                                                                                                            |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| git config --global user.name "marat"              | Представься Git-у. Эта команда устанавливает твое имя, которое будет подписыно под всеми твоими коммитами (сохранениями). Флаг `--global` значит, что это имя будет использоваться для всех проектов на компьютере.                                                                  |
| git config --global user.email "example@gmail.com" | То же самое, что и выше, только для твоей электронной почты. Обычно используется почта, привязанная к аккаунту на GitHub или GitLab.                                                                                                                                                 |
| git config –list                                   | Показать все настройки Git. Полезно, чтобы проверить, правильно ли ввел имя и почту.                                                                                                                                                                                                 |
| git init                                           | Сделать из обычной папки репозиторий. Git создает в папке скрытую папку `.git`, куда будет складывать всю историю изменений. Команда выполняется один раз для нового проекта.                                                                                                        |
| git add "имя файла или ."                          | Подготовить файлы к сохранению (добавить в _staging area_). Ты как бы говоришь: «Следи за этим файлом и приготовь его к коммиту». Если поставить точку (`.`), то добавятся **все** новые и измененные файлы в текущей папке.                                                         |
| git add -A                                         | Добавить **все** изменения в проекте (новые, измененные, удаленные файлы) для следующего коммита. Работает во всем репозитории, а не только в текущей папке.                                                                                                                         |
| git add -u                                         | Добавить только те файлы, которые уже отслеживались Git-ом ранее, но были изменены или удалены. Новые файлы эта команда не добавляет.                                                                                                                                                |
| git commit -m "Комментарий к коммиту"              | Сделать снимок (сохранение) проекта. Это как нажать «Сохранить» в игре. Флаг `-m` позволяет сразу написать короткое пояснение, что было сделано в этом коммите.                                                                                                                      |
| git log                                            | Показать историю коммитов. Ты увидишь список всех сохранений, кто их сделал, когда и с каким комментарием.                                                                                                                                                                           |
| git checkout -b "имя ветки"                        | Создать новую ветку и сразу переключиться на нее. Ветки нужны, чтобы разрабатывать новую функцию отдельно от основного кода, не боясь всё сломать.                                                                                                                                   |
| git branch                                         | Показать список всех веток. Звездочкой (`*`) будет отмечена та ветка, в которой ты сейчас находишься.                                                                                                                                                                                |
| git branch -d "имя ветки"                          | Удалить ветку (обычно делают после того, как влили её изменения в основную ветку). Флаг `-d` удаляет ветку безопасно, только если её изменения уже влиты в другую.                                                                                                                   |
| git merge "имя ветки"                              | Влить изменения из другой ветки в текущую. Например, ты закончил писать новую функцию в ветке `feature` и хочешь перенести её код в основную ветку `main`. Для этого нужно переключиться на `main` и выполнить `git merge feature`.                                                  |
| git rebase main                                    | Альтернатива `merge`. Эта команда переставляет твои коммиты из текущей ветки на конец ветки `main`. Нужна для поддержания чистой и линейной истории.                                                                                                                                 |
| git push                                           | Отправить (загрузить) твои локальные коммиты в удаленный репозиторий (например, на GitHub). Только после этой команды твои изменения увидят другие.                                                                                                                                  |
| git pull                                           | Забрать (скачать) изменения из удаленного репозитория к себе на компьютер. Это нужно делать перед началом работы, чтобы получить свежий код, который могли добавить коллеги.                                                                                                         |
| git push -u origin "имя ветки"                     | Отправить новую ветку на удаленный репозиторий. Флаг `-u` (--set-upstream) нужен при первом пуше новой ветки, чтобы связать локальную ветку с веткой на сервере. В следующий раз можно будет писать просто `git push`. `origin` — это стандартное имя твоего удаленного репозитория. |
