# Что будет, если использовать v-for без ключа (key)?

> [!NOTE]
> Без `key` Vue может переиспользовать DOM-элементы по позиции. Это быстрее в простых случаях, но опасно для списков с локальным состоянием, формами, анимациями и перестановками.

## Вопрос

Что будет, если использовать `v-for` без ключа (`key`)?

## Проблема

```vue
<li v-for="user in users">
  <input :value="user.name" />
</li>
```

Если список изменится, Vue может переиспользовать DOM-узел для другого пользователя. В формах это иногда приводит к визуально "перепутанному" состоянию.

## Правильный вариант

```vue
<li v-for="user in users" :key="user.id">
  <input :value="user.name" />
</li>
```

`key` говорит Vue, какой DOM-узел соответствует какой сущности.

## Почему индекс не всегда подходит

```vue
<li v-for="(user, index) in users" :key="index">
  {{ user.name }}
</li>
```

Если элементы можно удалять, сортировать или вставлять в середину, индекс меняется вместе с позицией, а не с самой сущностью.

## Когда key особенно важен

- Списки с input-ами.
- Списки компонентов с локальным состоянием.
- Анимации переходов.
- Сортировка, фильтрация, удаление и вставка элементов.

## Мини-шпаргалка

- `key` должен быть уникальным и стабильным.
- Лучший key - id сущности.
- Индекс допустим только для статичных списков.
- Без key Vue ориентируется на порядок элементов.
