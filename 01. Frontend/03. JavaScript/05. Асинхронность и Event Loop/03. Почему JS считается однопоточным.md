# Почему JS считается однопоточным?

> [!NOTE]
> JavaScript считается однопоточным, потому что основной JS-код выполняется в одном Call Stack: одна операция за раз.

## Вопрос

Почему JavaScript называют однопоточным, если в нем есть асинхронные операции?

## Определение

Однопоточность JavaScript означает, что ваш код выполняется последовательно в одном стеке вызовов. В один конкретный момент движок исполняет один участок JS-кода.

Асинхронность не делает сам JS-код многопоточным. Долгие операции выполняет среда: браузер, Node.js, Web API, libuv. Затем результат возвращается в основной поток через очередь задач.

## Пример

```javascript
console.log(1);

setTimeout(() => {
  console.log(2);
}, 0);

console.log(3);

// 1
// 3
// 2
```

Даже с задержкой `0` таймер выполнится только после синхронного кода.

## Что делает среда выполнения

Браузер или Node.js могут иметь дополнительные потоки и системные механизмы для таймеров, сети, файлов и других задач. Но callback, который вы написали на JavaScript, вернется в основной поток и выполнится там.

## Почему это важно

Если запустить тяжелый синхронный код, он займет Call Stack и заблокирует:

- обработку кликов;
- перерисовку интерфейса;
- таймеры;
- выполнение других callback-функций.

## Исключение: настоящая параллельность

Для вычислений в отдельном потоке существуют:

- Web Workers в браузере;
- Worker Threads в Node.js.

Они работают отдельно и общаются с основным потоком через сообщения.

## Мини-шпаргалка

```javascript
// JS-код:
// один Call Stack -> одна операция за раз

// Асинхронность:
// среда выполняет долгую работу -> callback возвращается через очередь
```
