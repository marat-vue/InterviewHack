# Как использовать advanced routing, validate, route groups, named views и prefetch?

> [!NOTE]
> Nuxt file-based routing умеет больше, чем `pages/index.vue` и `[id].vue`: optional params, catch-all routes, nested routes, route groups, named views, route validation, custom navigation и prefetch.

## Dynamic route

```text
app/pages/products/[id].vue
```

URL:

```text
/products/123
```

```vue
<script setup lang="ts">
const route = useRoute()
const id = route.params.id
</script>
```

## Optional param

```text
app/pages/[[slug]].vue
```

Совпадает с:

```text
/
/about
```

Вложенный вариант:

```text
app/pages/blog/[[slug]].vue
```

Совпадает с:

```text
/blog
/blog/post-1
```

## Catch-all route

```text
app/pages/[...slug].vue
```

Совпадает с:

```text
/any/path/here
```

Пример:

```vue
<script setup lang="ts">
const route = useRoute()
const slug = route.params.slug
</script>

<template>
  <pre>{{ slug }}</pre>
</template>
```

Catch-all используют для CMS pages, docs, fallback pages. Важно валидировать slug.

## Nested routes

```text
app/pages/account.vue
app/pages/account/profile.vue
app/pages/account/security.vue
```

`account.vue`:

```vue
<template>
  <section>
    <AccountNav />
    <NuxtPage />
  </section>
</template>
```

Child pages отрисуются внутри `<NuxtPage />`.

## Route groups

```text
app/pages/
  (marketing)/
    about.vue
    pricing.vue
  (app)/
    dashboard.vue
```

URL не содержит group name:

```text
/about
/pricing
/dashboard
```

Groups нужны для организации файлов без изменения URL.

## Named views

Named views позволяют отрисовать несколько `<NuxtPage>` outlets:

```text
app/pages/parent.vue
app/pages/parent/child.vue
app/pages/parent/child@sidebar.vue
```

`parent.vue`:

```vue
<template>
  <main>
    <NuxtPage />
    <aside>
      <NuxtPage name="sidebar" />
    </aside>
  </main>
</template>
```

Это advanced-сценарий. В большинстве интерфейсов проще layout + components.

## Route validation

```vue
<script setup lang="ts">
definePageMeta({
  validate(route) {
    return typeof route.params.id === 'string' &&
      /^\d+$/.test(route.params.id)
  }
})
</script>
```

Если `validate` вернет `false`, Nuxt покажет 404.

Можно вернуть object:

```ts
definePageMeta({
  validate(route) {
    if (route.params.slug === 'old') {
      return {
        statusCode: 410,
        statusMessage: 'Page removed'
      }
    }

    return true
  }
})
```

## `<NuxtLink>` и prefetch

```vue
<template>
  <NuxtLink to="/products/123">
    Открыть товар
  </NuxtLink>
</template>
```

Nuxt может prefetch linked page code/payload, когда ссылка попадает во viewport. Это ускоряет навигацию.

Отключить:

```vue
<template>
  <NuxtLink to="/heavy-report" no-prefetch>
    Тяжелый отчет
  </NuxtLink>
</template>
```

## Programmatic navigation

```ts
await navigateTo('/dashboard')
```

External URL:

```ts
await navigateTo('https://example.com', {
  external: true
})
```

Replace:

```ts
await navigateTo('/login', {
  replace: true
})
```

## Custom routing

Если нужно расширить routes не файловой структурой:

```ts
export default defineNuxtConfig({
  hooks: {
    'pages:extend'(pages) {
      pages.push({
        name: 'legacy-product',
        path: '/p/:id',
        file: '~/pages/products/[id].vue'
      })
    }
  }
})
```

Это полезно для legacy URL, но не должно заменять нормальную file-based структуру без причины.

## Что отвечать на собеседовании?

Nuxt routing основан на file-based router: `[id]` для dynamic params, `[[slug]]` для optional params, `[...slug]` для catch-all, nested routes через вложенные pages и `<NuxtPage>`. Route groups позволяют группировать файлы без влияния на URL, named views дают несколько outlets, а `validate` в `definePageMeta` может вернуть 404 или custom error status.

## Частые ошибки

- Использовать catch-all без валидации.
- Ожидать, что route group появится в URL.
- Забыть `<NuxtPage>` в parent route.
- Делать named views там, где хватит layout.
- Prefetch-ить очень тяжелые страницы без необходимости.
- Делать custom routes hooks вместо понятной структуры pages.

## Мини-шпаргалка

- `[id]` - dynamic.
- `[[slug]]` - optional.
- `[...slug]` - catch-all.
- `(group)` - не влияет на URL.
- `validate` - page-level route validation.
- `<NuxtLink>` - navigation + prefetch.
