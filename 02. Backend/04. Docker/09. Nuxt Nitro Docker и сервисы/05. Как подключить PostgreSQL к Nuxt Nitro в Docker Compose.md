# Как подключить PostgreSQL к Nuxt Nitro в Docker Compose?

> [!NOTE]
> PostgreSQL в Compose поднимают отдельным service, данные сохраняют в named volume, readiness проверяют через `pg_isready`, а Nuxt/Nitro подключается к базе по host `db`.

## PostgreSQL service

```yaml
services:
  db:
    image: postgres:18
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  pgdata:
```

В dev `ports` удобны для подключения из DBeaver/DataGrip/TablePlus. В production порт базы обычно не публикуют наружу.

## Connection string для Nuxt/Nitro

Внутри Docker Compose:

```env
DATABASE_URL=postgresql://app:secret@db:5432/app
```

С host-машины:

```env
DATABASE_URL=postgresql://app:secret@localhost:5432/app
```

Разница в host:

```text
inside Compose -> db
from host      -> localhost
```

## Подключение через Prisma

`prisma/schema.prisma`:

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

Nuxt/Nitro helper:

```ts
import { PrismaClient } from '@prisma/client'

const globalForPrisma = globalThis as unknown as {
  prisma?: PrismaClient
}

export const prisma =
  globalForPrisma.prisma ?? new PrismaClient()

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma
}
```

Route:

```ts
export default defineEventHandler(async () => {
  const users = await prisma.user.findMany({
    take: 20,
    orderBy: { createdAt: 'desc' }
  })

  return { users }
})
```

## Init scripts

Postgres official image выполняет SQL/shell-файлы из `/docker-entrypoint-initdb.d` только при первой инициализации пустого data directory.

```yaml
services:
  db:
    image: postgres:18
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./docker/postgres/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```

`docker/postgres/init.sql`:

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

Если volume уже создан, init script повторно не выполнится. Для повторного старта с чистой базой в dev:

```bash
docker compose down -v
docker compose up -d db
```

## Backup и restore в dev

Dump:

```bash
docker compose exec db pg_dump -U app app > dump.sql
```

Restore:

```bash
docker compose exec -T db psql -U app app < dump.sql
```

## Что добавить к Nuxt service?

```yaml
services:
  app:
    build: .
    environment:
      DATABASE_URL: postgresql://app:secret@db:5432/app
      NUXT_DATABASE_URL: postgresql://app:secret@db:5432/app
    depends_on:
      db:
        condition: service_healthy
```

`depends_on.condition: service_healthy` помогает не стартовать приложение раньше, чем Postgres начнет принимать подключения.

## Что отвечать на собеседовании?

PostgreSQL в Docker Compose поднимается отдельным service из official image. Данные лежат в named volume, readiness проверяется через `pg_isready`, а приложение внутри Compose подключается не к `localhost`, а к service name `db`. Для Prisma connection string обычно передается через `DATABASE_URL`, migrations запускаются отдельным шагом.

## Частые ошибки

- Использовать `localhost` внутри Nuxt container.
- Не добавлять volume для `/var/lib/postgresql/data`.
- Думать, что init scripts выполняются при каждом запуске.
- Публиковать `5432` в production без необходимости.
- Не делать healthcheck и получать race condition на старте.
- Использовать `POSTGRES_PASSWORD=secret` в production.

## Мини-шпаргалка

- Service: `db`.
- Internal URL: `postgresql://app:secret@db:5432/app`.
- Host URL: `postgresql://app:secret@localhost:5432/app`.
- Data: `/var/lib/postgresql/data`.
- Readiness: `pg_isready`.
- Init scripts: только при пустом volume.
