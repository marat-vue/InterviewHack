# Как смонтировать Better Auth handler в Nitro route?

> [!NOTE]
> Better Auth в Nitro монтируется через catch-all route, который передает Web Request в `auth.handler`. Обычно это файл `server/routes/api/auth/[...all].ts` или в Nuxt `server/api/auth/[...all].ts`.

## Catch-all route в standalone Nitro

```txt
server/
  routes/
    api/
      auth/
        [...all].ts
```

```ts
// server/routes/api/auth/[...all].ts
import { toWebRequest } from 'h3';
import { auth } from '../../../../utils/auth';

export default defineHandler((event) => {
  return auth.handler(toWebRequest(event));
});
```

URL prefix:

```txt
/api/auth/*
```

## Catch-all route в Nuxt

```txt
server/
  api/
    auth/
      [...all].ts
```

```ts
// server/api/auth/[...all].ts
import { toWebRequest } from 'h3';
import { auth } from '../../utils/auth';

export default defineEventHandler((event) => {
  return auth.handler(toWebRequest(event));
});
```

URL prefix:

```txt
/api/auth/*
```

## Почему нужен `toWebRequest`?

Better Auth handler ожидает Web-compatible `Request`. Nitro/H3 работает с `H3Event`. `toWebRequest(event)` преобразует event в подходящий request.

```ts
return auth.handler(toWebRequest(event));
```

## Какие endpoints появятся?

Better Auth сам обслуживает endpoints под выбранным base path, например:

- sign up;
- sign in;
- sign out;
- get session;
- social callback;
- plugin endpoints;
- verification/password reset endpoints.

Точный набор зависит от config и plugins.

## Как проверить?

Запусти dev server и дерни session endpoint через client или HTTP.

Client:

```ts
const session = await authClient.getSession();
```

Server:

```ts
const session = await auth.api.getSession({
  headers: event.req.headers,
});
```

## Частые ошибки

| Ошибка | Причина |
|---|---|
| 404 на `/api/auth/*` | catch-all route лежит не там |
| session не ставится | неправильный `BETTER_AUTH_URL`, cookies, CORS |
| Prisma table missing | не сгенерирована/не применена schema |
| social callback падает | неверный callback URL у provider |
| TypeScript ругается на import path | неверная глубина `../../utils/auth` |

## Мини-шпаргалка

- Better Auth handler монтируется как catch-all route.
- Standalone: `server/routes/api/auth/[...all].ts`.
- Nuxt: `server/api/auth/[...all].ts`.
- Используй `auth.handler(toWebRequest(event))`.
- Все `/api/auth/*` endpoints обслуживает Better Auth.
- После изменения plugins проверь schema и route.
