# Почему в React `className`, а не `class`?

> [!summary]
> В JSX для CSS-классов используют `className`, потому что JSX ближе к JavaScript и DOM-свойствам, чем к HTML-строке. В DOM API свойство элемента называется `className`, а слово `class` в JavaScript исторически связано с объявлением классов.

## Как правильно?

```jsx
function Button() {
  return <button className="button button-primary">Сохранить</button>
}
```

В HTML было бы:

```html
<button class="button button-primary">Сохранить</button>
```

Но в JSX используется `className`.

## Почему JSX отличается от HTML?

JSX превращается в JavaScript-объект:

```jsx
<button className="primary">Сохранить</button>
```

Можно представить так:

```js
{
  type: 'button',
  props: {
    className: 'primary',
    children: 'Сохранить'
  }
}
```

Поэтому названия многих props похожи на DOM-свойства.

## Другие отличия JSX-атрибутов

| HTML | JSX |
|---|---|
| `class` | `className` |
| `for` | `htmlFor` |
| `tabindex` | `tabIndex` |
| `onclick` | `onClick` |
| `readonly` | `readOnly` |

React props обычно пишутся в camelCase.

## Как задавать классы условно?

```jsx
function Alert({ type, children }) {
  return (
    <div className={`alert alert-${type}`}>
      {children}
    </div>
  )
}
```

Или аккуратнее через массив:

```jsx
const className = [
  'button',
  isActive ? 'button-active' : '',
  isDisabled ? 'button-disabled' : '',
].filter(Boolean).join(' ')
```

## Мини-шпаргалка

- В JSX нужно писать `className`.
- JSX - не HTML, а JavaScript-синтаксис.
- Большинство DOM props пишутся в camelCase.
- Для `label` используют `htmlFor`.
- Условные классы лучше собирать явно и читаемо.
