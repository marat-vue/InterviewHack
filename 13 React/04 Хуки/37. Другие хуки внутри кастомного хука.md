# Можно ли вызывать другие хуки внутри кастомного хука?

> [!summary]
> Да. Кастомный хук как раз и нужен для композиции других хуков. Внутри него можно вызывать `useState`, `useEffect`, `useRef`, `useMemo`, `useReducer`, `useContext` и другие хуки, если соблюдаются правила хуков.

## Пример с несколькими хуками

```jsx
function useDebouncedValue(value, delay) {
  const [debouncedValue, setDebouncedValue] = useState(value)

  useEffect(() => {
    const timerId = setTimeout(() => {
      setDebouncedValue(value)
    }, delay)

    return () => clearTimeout(timerId)
  }, [value, delay])

  return debouncedValue
}
```

Внутри используются `useState` и `useEffect`.

## Пример с useRef

```jsx
function usePrevious(value) {
  const ref = useRef()

  useEffect(() => {
    ref.current = value
  }, [value])

  return ref.current
}
```

Так можно получить значение из предыдущего render.

## Главное правило

Внутри custom hook тоже нельзя вызывать хуки условно:

```jsx
function useFeature(enabled) {
  if (enabled) {
    useEffect(() => {
      connect()
    }, [])
  }
}
```

Правильно:

```jsx
function useFeature(enabled) {
  useEffect(() => {
    if (!enabled) {
      return
    }

    return connect()
  }, [enabled])
}
```

## Custom hook как слой абстракции

Хук может скрыть детали:

- API-запроса;
- подписки;
- debounce;
- работы с localStorage;
- контекста;
- внешнего store.

Но он не должен становиться непрозрачной коробкой, где смешаны несвязанные задачи.

## Мини-шпаргалка

- В custom hook можно вызывать другие хуки.
- Правила хуков действуют внутри custom hook.
- Условие помещают внутрь hook logic, а не вокруг вызова hook.
- Custom hook должен решать связную задачу.
- Если хук слишком большой, раздели его.
