# Как работает Redis Cluster, hash slots и sharding?

> [!NOTE]
> Redis Cluster распределяет ключи по нескольким primary nodes через 16384 hash slots. Это нужно, когда dataset или write throughput не помещается в один Redis primary.

## Что такое hash slot?

Каждый ключ попадает в один из 16384 slots.

```txt
CRC16(key) % 16384 -> slot
```

Cluster распределяет slots между nodes:

```txt
node A: slots 0-5000
node B: slots 5001-10000
node C: slots 10001-16383
```

## Что происходит при GET?

Client вычисляет slot ключа и отправляет команду на нужный node.

Если client ошибся, Redis вернет redirect:

```txt
MOVED 1234 10.0.0.2:6379
```

Cluster-aware client обновит slot map.

## Multi-key ограничения

Команды вроде `MGET a b` работают только если ключи в одном slot.

Hash tags:

```txt
cart:{user:1}:items
cart:{user:1}:total
```

Redis считает hash только по содержимому `{...}`, поэтому оба ключа будут в одном slot.

## Когда нужен Cluster?

Cluster нужен, если:

- dataset больше одного node;
- write throughput слишком большой;
- нужно horizontal scaling;
- нужна managed Redis cluster topology;
- single primary стал bottleneck.

## Когда Cluster не нужен?

Cluster может быть лишним, если:

- Redis только cache и помещается в один node;
- team не готова к cluster constraints;
- много multi-key операций;
- нужен простой Sentinel HA;
- workload небольшой.

## Что учитывать в key design?

Для связанных ключей:

```txt
user:{42}:profile
user:{42}:settings
user:{42}:sessions
```

Для равномерного распределения:

```txt
cache:product:1
cache:product:2
cache:product:3
```

Не ставь один и тот же hash tag на все ключи, иначе весь dataset попадет в один slot.

## Мини-шпаргалка

- Cluster = sharding + HA.
- Всего 16384 hash slots.
- Multi-key операции требуют один slot.
- Hash tags: `{...}`.
- Cluster-aware client обязателен.
- Cluster усложняет key design.
