# setTimeout(fn, 0)

> [!NOTE]
> `setTimeout(fn, 0)` не выполняет функцию сразу, а ставит ее в очередь макротасок после текущего синхронного кода.

## Вопрос

Что означает задержка `0` в `setTimeout(fn, 0)`?

## Определение

`setTimeout(fn, 0)` просит среду выполнения запланировать callback с минимальной задержкой. Но callback не попадет в Call Stack мгновенно: сначала должен завершиться текущий синхронный код, затем должны выполниться микротаски.

## Пример

```javascript
console.log('A');

setTimeout(() => {
  console.log('B');
}, 0);

console.log('C');

// A
// C
// B
```

`B` выводится последним, потому что callback таймера выполняется как макротаска.

## Сравнение с Promise

```javascript
console.log(1);

setTimeout(() => console.log(2), 0);

Promise.resolve().then(() => console.log(3));

console.log(4);

// 1
// 4
// 3
// 2
```

Микротаска промиса выполняется раньше макротаски таймера.

## Зачем так делают

- отложить работу до завершения текущего кода;
- дать браузеру возможность обработать другие задачи;
- разбить тяжелую работу на части;
- избежать немедленного синхронного выполнения.

## Мини-шпаргалка

```javascript
setTimeout(fn, 0); // выполнить позже, не прямо сейчас
```
