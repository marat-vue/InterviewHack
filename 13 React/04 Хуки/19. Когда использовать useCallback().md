# Когда использовать useCallback?

> [!summary]
> `useCallback` стоит использовать, когда стабильная ссылка на функцию действительно важна: функция передается в `memo`-компонент, используется как dependency effect или возвращается из custom hook. В остальных случаях он часто добавляет шум без выигрыша.

## Сценарий 1: memo-компонент

```jsx
const SlowList = memo(function SlowList({ items, onSelect }) {
  return items.map((item) => (
    <button key={item.id} onClick={() => onSelect(item.id)}>
      {item.title}
    </button>
  ))
})

function Page({ items }) {
  const handleSelect = useCallback((id) => {
    console.log(id)
  }, [])

  return <SlowList items={items} onSelect={handleSelect} />
}
```

Если `SlowList` дорогой и props стабильные, `useCallback` может помочь.

## Сценарий 2: dependency effect

```jsx
const loadUser = useCallback(() => {
  return api.getUser(userId)
}, [userId])

useEffect(() => {
  loadUser()
}, [loadUser])
```

Но если функция нужна только effect, часто лучше объявить ее внутри effect:

```jsx
useEffect(() => {
  function loadUser() {
    return api.getUser(userId)
  }

  loadUser()
}, [userId])
```

## Сценарий 3: custom hook API

```jsx
function useModal() {
  const [isOpen, setIsOpen] = useState(false)

  const open = useCallback(() => setIsOpen(true), [])
  const close = useCallback(() => setIsOpen(false), [])

  return { isOpen, open, close }
}
```

Стабильные функции удобны для потребителей custom hook.

## Когда не использовать?

Не нужно:

```jsx
const handleClick = useCallback(() => {
  setCount(count + 1)
}, [count])
```

если функция передается только в обычный `<button>` и нет проблемы производительности.

## Мини-шпаргалка

- Используй `useCallback`, когда важна стабильная ссылка.
- Самый частый сценарий - callback в `memo`-компонент.
- Для effect часто проще объявить функцию внутри effect.
- Не добавляй `useCallback` везде автоматически.
- Проверяй пользу через Profiler и структуру props.
