# Как использовать Nuxt layers в проектах и монорепозиториях?

> [!NOTE]
> Nuxt layers позволяют переиспользовать часть Nuxt-приложения: компоненты, layouts, composables, middleware, server routes и config. Это удобно для monorepo, white-label проектов, shared design system и нескольких сайтов на одной базе.

## Что такое layer?

Layer - это почти обычный Nuxt-проект, который другой Nuxt-проект может расширить.

Минимальный layer:

```text
base-layer/
  nuxt.config.ts
  app/
    components/
      AppButton.vue
    composables/
      useFormatPrice.ts
```

`base-layer/nuxt.config.ts`:

```ts
export default defineNuxtConfig({})
```

Главный проект:

```ts
export default defineNuxtConfig({
  extends: ['./base-layer']
})
```

## Что можно выносить в layer?

- components;
- composables;
- utils;
- layouts;
- middleware;
- plugins;
- pages;
- `app.config.ts`;
- `server/api`;
- `server/middleware`;
- часть `nuxt.config.ts`;
- modules.

## Monorepo пример

```text
apps/
  shop/
    nuxt.config.ts
  docs/
    nuxt.config.ts
layers/
  ui/
    nuxt.config.ts
    app/components/
  seo/
    nuxt.config.ts
  auth/
    nuxt.config.ts
    app/middleware/
    server/api/
```

`apps/shop/nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  extends: [
    '../../layers/ui',
    '../../layers/seo',
    '../../layers/auth'
  ]
})
```

## Priority и override

Если один и тот же файл есть в проекте и layer, приоритет выше у проекта.

Общая идея:

```text
project files > local layers > extends layers
```

В `extends` более ранний layer имеет более высокий приоритет, чем следующий:

```ts
export default defineNuxtConfig({
  extends: [
    './premium-theme',
    './base-theme'
  ]
})
```

`premium-theme` может перекрыть `base-theme`.

## Auto-scanned layers

Nuxt может читать layers из директории:

```text
layers/
  01.base/
  02.theme/
```

Префиксы помогают явно контролировать порядок.

## Remote layer

```ts
export default defineNuxtConfig({
  extends: [
    'github:company/nuxt-layer#v1.2.0'
  ]
})
```

Для private repository нужны tokens/env. В production чаще стабильнее использовать npm package, чтобы lockfile фиксировал версию.

## Named layer aliases

Layer может объявить имя:

```ts
export default defineNuxtConfig({
  $meta: {
    name: 'ui'
  }
})
```

После этого внутри layer проще строить imports через alias, а не случайные relative paths.

## Как отключить module из layer?

Если layer подключает module, а проекту он не нужен:

```ts
export default defineNuxtConfig({
  extends: ['./base-layer'],
  image: false,
  pinia: false
})
```

Конкретный ключ зависит от module. Например, `image` для `@nuxt/image`, `pinia` для `@pinia/nuxt`.

## Когда layer не нужен?

Layer не нужен, если:

- проект один и переиспользования нет;
- shared code проще вынести в обычный package;
- layer начинает скрывать слишком много магии;
- команда не понимает priority/override rules.

## Что отвечать на собеседовании?

Nuxt layers позволяют расширять приложение другим Nuxt-проектом. Это удобно для монорепозиториев, white-label сайтов и shared UI/config. Layer может содержать `app/components`, `app/composables`, layouts, middleware, pages, server routes и config. Важно понимать приоритет: файлы проекта перекрывают layer, а порядок в `extends` влияет на merge.

## Частые ошибки

- Класть в layer слишком много project-specific logic.
- Не фиксировать версию remote layer.
- Использовать aliases так, что они резолвятся относительно потребителя неожиданно.
- Не документировать priority.
- Делать layer зависимым от devDependencies, которых нет у потребителя.
- Использовать layer там, где достаточно npm package.

## Мини-шпаргалка

- `extends` подключает layer.
- Project files имеют highest priority.
- Layer похож на Nuxt app.
- Хорош для UI/config/middleware/server routes reuse.
- Remote layer лучше версионировать.
- Не превращай layer в черный ящик.
