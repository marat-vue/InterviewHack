# Как работают layers и cache?

> [!summary]
> Docker image состоит из слоев. Инструкции Dockerfile создают layers, а Docker Build может переиспользовать неизменившиеся layers из cache. Поэтому порядок `COPY`, `RUN` и установка зависимостей сильно влияют на скорость сборки.

## Что такое layer?

Layer - это набор изменений файловой системы.

Например:

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
```

Упрощенно:

```text
base node layer
workdir metadata
package files layer
node_modules layer
source code layer
```

## Почему cache важен?

Если инструкция и ее входные данные не изменились, Docker может не выполнять ее заново.

Хорошо:

```dockerfile
COPY package*.json ./
RUN npm ci
COPY . .
```

Изменение `src/index.ts` не сломает cache для `npm ci`.

Плохо:

```dockerfile
COPY . .
RUN npm ci
```

Любое изменение файла в проекте заставит заново устанавливать зависимости.

## Cache инвалидируется сверху вниз

Если слой изменился, все последующие слои тоже нужно пересчитать.

```text
Layer 1 ok
Layer 2 changed
Layer 3 rebuild
Layer 4 rebuild
```

Поэтому редко меняющиеся операции лучше ставить выше, а часто меняющийся код - ниже.

## Как смотреть layers?

```bash
docker image history my-api
```

Полезно увидеть, какие инструкции создают большие слои.

## BuildKit cache mounts

Для package manager можно использовать cache mount:

```dockerfile
# syntax=docker/dockerfile:1

FROM node:22-alpine
WORKDIR /app

COPY package*.json ./
RUN --mount=type=cache,target=/root/.npm npm ci

COPY . .
CMD ["npm", "start"]
```

Это ускоряет повторные сборки, не добавляя cache директорию в final image как обычный слой.

## Что отвечать на собеседовании?

Docker image состоит из layers. Каждая важная инструкция Dockerfile создает слой, а Docker переиспользует слои из build cache, если инструкция и входные файлы не изменились. Чтобы сборка была быстрой, сначала копируют lock-файлы и устанавливают зависимости, а исходный код копируют позже. Изменение раннего слоя инвалидирует все последующие.

## Частые ошибки

- Делать `COPY . .` перед `npm ci`.
- Не использовать lock-файлы.
- Не смотреть размер layers.
- Думать, что каждый `RUN` бесплатен.
- Класть временные файлы в image.
- Не использовать `.dockerignore`.

## Мини-шпаргалка

- Image состоит из layers.
- Cache зависит от инструкции и входных файлов.
- Изменение слоя ломает cache ниже.
- Dependencies копируют до source code.
- `docker image history` показывает layers.
- BuildKit cache mounts ускоряют сборку.
