# Как работает constructor injection?

> [!summary]
> Constructor injection - основной способ внедрять зависимости в NestJS. Класс объявляет зависимости в constructor, а DI container создает и передает нужные providers.

## Пример

```ts
@Injectable()
export class OrdersService {
  constructor(private readonly usersService: UsersService) {}
}
```

`OrdersService` не создает `UsersService` сам. Он получает его от NestJS.

## Почему это удобно?

- зависимости видны явно;
- класс проще тестировать;
- можно подменять реализации;
- меньше ручного создания объектов;
- легче контролировать lifetime.

## Тестирование

```ts
const service = new OrdersService(mockUsersService);
```

Если логика не зависит от Nest runtime, сервис можно тестировать проще.

## Частая ошибка

Создавать зависимость через `new` внутри service.

```ts
private client = new ExternalClient();
```

Лучше вынести client в provider и внедрить через constructor.

## Мини-шпаргалка

- Constructor injection делает зависимости явными.
- NestJS сам создает provider graph.
- Не создавай services через `new` вручную.
- Для тестов можно передать mock.
- Сложные зависимости лучше скрывать за interface/token.
