# Что делает “Function as Child” паттерн?

> [!summary]
> Function as Child - это разновидность render props, где `children` передается не как готовый JSX, а как функция. Компонент вызывает эту функцию и передает наружу данные или методы.

## Обычный children

```jsx
function Card({ children }) {
  return <section>{children}</section>
}

<Card>
  <h2>Hello</h2>
</Card>
```

`children` здесь - React node.

## Function as Child

```jsx
function WindowSize({ children }) {
  const size = useWindowSize()

  return children(size)
}
```

Использование:

```jsx
<WindowSize>
  {({ width, height }) => (
    <p>
      {width} x {height}
    </p>
  )}
</WindowSize>
```

`children` здесь - функция.

## Зачем это нужно?

Компонент может владеть логикой:

- подписка на событие;
- получение данных;
- состояние формы;
- hover/focus state;
- позиция мыши;
- доступ к API компонента.

А родитель решает, как отрисовать результат.

## Пример с toggle

```jsx
function Toggle({ children }) {
  const [on, setOn] = useState(false)

  return children({
    on,
    toggle: () => setOn((value) => !value),
  })
}
```

Использование:

```jsx
<Toggle>
  {({ on, toggle }) => (
    <button onClick={toggle}>
      {on ? 'Enabled' : 'Disabled'}
    </button>
  )}
</Toggle>
```

## Минусы

- JSX становится более вложенным;
- сложнее читать, если таких компонентов много;
- новые функции создаются при render;
- TypeScript-типизация может быть длиннее;
- custom hooks часто дают более простой API.

## Мини-шпаргалка

- Function as Child = `children` является функцией.
- Компонент вызывает `children(data)`.
- Это частный случай render props.
- Паттерн отделяет поведение от отображения.
- В новом коде его часто заменяют custom hooks.
