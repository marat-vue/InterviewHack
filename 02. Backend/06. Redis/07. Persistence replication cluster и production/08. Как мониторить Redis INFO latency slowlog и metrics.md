# Как мониторить Redis: INFO, latency, slowlog и metrics?

> [!NOTE]
> Redis часто становится скрытым bottleneck-ом: приложение “просто тормозит”, а причина в big keys, memory pressure, slow commands или connection storm. Monitoring нужен до incident-а.

## Что смотреть в INFO?

```redis
INFO memory
INFO stats
INFO clients
INFO commandstats
INFO persistence
INFO replication
```

Ключевые signals:

- `used_memory`;
- `used_memory_peak`;
- `mem_fragmentation_ratio`;
- `connected_clients`;
- `blocked_clients`;
- `evicted_keys`;
- `expired_keys`;
- `keyspace_hits`;
- `keyspace_misses`;
- replication lag;
- latest fork status.

## Hit ratio

```txt
hit ratio = keyspace_hits / (keyspace_hits + keyspace_misses)
```

Низкий hit ratio может означать:

- плохие keys;
- слишком маленький TTL;
- cache pollution;
- недостаточно memory;
- endpoint не повторяет запросы.

## Slowlog

```redis
SLOWLOG GET 20
```

Ищи:

- `KEYS`;
- `HGETALL`;
- `SMEMBERS`;
- Lua scripts;
- большие `ZRANGE`;
- медленные deletes.

## Big keys

CLI:

```bash
redis-cli --bigkeys
```

Или выборочно:

```redis
MEMORY USAGE key
```

Big keys лучше разбивать, trim-ить или удалять через `UNLINK`.

## Latency

Смотри:

- p50/p95/p99 latency команд;
- network latency app -> Redis;
- timeout rate;
- reconnect count;
- blocked clients;
- CPU;
- fork time для persistence.

## Application metrics

Логируй:

- cache hit/miss per endpoint;
- Redis command errors;
- timeout count;
- fallback count;
- stream pending length;
- queue lag;
- Pub/Sub reconnects.

## Мини-шпаргалка

- `INFO` - общая картина.
- `SLOWLOG` - тяжелые команды.
- `MEMORY USAGE`/`--bigkeys` - big keys.
- Hit ratio важен для cache.
- Pending length важен для Streams.
- Monitoring должен быть на уровне Redis и приложения.
