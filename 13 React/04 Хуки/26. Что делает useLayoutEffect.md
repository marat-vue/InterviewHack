# Что делает useLayoutEffect?

> [!summary]
> `useLayoutEffect` - версия `useEffect`, которая выполняется после изменения DOM, но до того, как браузер перерисует экран. Он нужен для измерения layout и синхронной корректировки UI до paint, но может ухудшить производительность.

## Чем отличается от useEffect?

`useEffect`:

```text
commit -> browser paint -> effect
```

`useLayoutEffect`:

```text
commit -> layout effect -> browser paint
```

Это значит, что `useLayoutEffect` может заблокировать отрисовку кадра.

## Пример измерения элемента

```jsx
function Tooltip() {
  const ref = useRef(null)
  const [height, setHeight] = useState(0)

  useLayoutEffect(() => {
    const rect = ref.current.getBoundingClientRect()
    setHeight(rect.height)
  }, [])

  return (
    <div ref={ref} style={{ transform: `translateY(${-height}px)` }}>
      Подсказка
    </div>
  )
}
```

Здесь нужно измерить DOM до того, как пользователь увидит неправильное положение.

## Когда useLayoutEffect нужен?

- измерить размер элемента;
- вычислить позицию tooltip/popover;
- синхронно скорректировать scroll;
- интегрироваться с библиотекой, которая требует layout до paint;
- избежать визуального "мигания" при первом кадре.

## Почему его нельзя использовать везде?

Код внутри `useLayoutEffect` блокирует browser paint. Если делать тяжелую работу, страница станет менее отзывчивой.

Официальная рекомендация простая:

```text
По возможности предпочитай useEffect.
```

## SSR-нюанс

Effects не выполняются на сервере. `useLayoutEffect` может вызывать предупреждения в SSR-сценариях, потому что layout существует только в браузере.

## Мини-шпаргалка

- `useLayoutEffect` выполняется до browser paint.
- Он нужен для layout measurements.
- Он блокирует отрисовку, поэтому может вредить performance.
- Большинство effects должны быть обычными `useEffect`.
- В SSR нужно быть осторожным.
