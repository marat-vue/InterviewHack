# Как сделать единый формат ошибок?

> [!summary]
> Единый формат ошибок помогает frontend и API-клиентам стабильно обрабатывать failures. В NestJS его обычно делают через exception filter и аккуратное использование HTTP exceptions.

## Пример формата

```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "error": "Bad Request",
  "path": "/api/users",
  "timestamp": "2026-08-03T10:00:00.000Z"
}
```

## Filter

```ts
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse<Response>();
    const req = ctx.getRequest<Request>();

    const status =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;

    res.status(status).json({
      statusCode: status,
      path: req.url,
      timestamp: new Date().toISOString(),
    });
  }
}
```

## Что не отдавать клиенту?

- stack trace;
- SQL queries;
- secrets;
- internal service names;
- raw database errors.

## Мини-шпаргалка

- Единый формат упрощает frontend.
- Filter может добавить path и timestamp.
- Internal details нужно логировать, но не отдавать клиенту.
- Validation errors стоит приводить к понятному виду.
- Production error response должен быть безопасным.
