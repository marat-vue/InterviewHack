# Как использовать event context, request hooks и waitUntil?

> [!NOTE]
> `event.context` - место для данных текущего запроса. Через него middleware, handlers и utilities передают request-scoped информацию: user, session, requestId, tenant, feature flags. Для фоновых операций в совместимых runtimes используют `waitUntil`.

## Что такое `event.context`?

`event.context` - объект, привязанный к одному request.

```ts
export default defineEventHandler((event) => {
  event.context.requestId = crypto.randomUUID();
});
```

Другой handler/middleware в рамках этого же request может прочитать:

```ts
export default defineHandler((event) => {
  return {
    requestId: event.context.requestId,
  };
});
```

## Что можно хранить в context?

Хорошо хранить:

- `requestId`;
- `user`;
- `session`;
- `tenantId`;
- `logger`;
- `startedAt`;
- `permissions`;
- `featureFlags`;
- `matchedRoute` metadata.

Плохо хранить:

- глобальное состояние приложения;
- кеш между пользователями;
- PrismaClient на каждый request без необходимости;
- secrets, которые потом случайно вернутся в response;
- огромные объекты.

## Типичный middleware context

```ts
// server/middleware/01.context.ts
export default defineEventHandler((event) => {
  event.context.requestId = crypto.randomUUID();
  event.context.startedAt = Date.now();
});
```

```ts
// server/middleware/02.logger.ts
export default defineEventHandler((event) => {
  console.log(`[${event.context.requestId}] ${event.method} ${event.path}`);
});
```

## Как типизировать context?

В проекте можно расширить типы H3:

```ts
// server/types/h3.d.ts
declare module 'h3' {
  interface H3EventContext {
    requestId?: string;
    user?: {
      id: string;
      email: string;
    };
  }
}

export {};
```

После этого `event.context.user` будет типизирован.

## Request hooks

Nitro plugins могут подписываться на hooks:

```ts
export default definePlugin((nitroApp) => {
  nitroApp.hooks.hook('request', (event) => {
    event.context.requestId = crypto.randomUUID();
  });
});
```

Hooks полезны для cross-cutting concerns:

- metrics;
- tracing;
- logging;
- request context;
- error reporting.

## `waitUntil`

В edge/serverless-compatible средах `waitUntil` позволяет запланировать promise, который может продолжить работу после отправки response.

```ts
export default defineHandler((event) => {
  event.waitUntil?.(
    analytics.track({
      path: event.path,
    }),
  );

  return {
    ok: true,
  };
});
```

Используй для:

- analytics;
- logs shipping;
- cache refresh;
- non-critical notifications.

Не используй для:

- обязательной записи в БД;
- платежей;
- критичных side effects;
- операций, от которых зависит ответ.

## `onDispose`

`onDispose` вызывается после завершения event:

```ts
import { onDispose } from 'h3';

export default defineHandler((event) => {
  const startedAt = Date.now();

  onDispose(event, () => {
    console.log('duration', Date.now() - startedAt);
  });

  return {
    ok: true,
  };
});
```

## Мини-шпаргалка

- `event.context` - request-scoped данные.
- Context не должен быть глобальным кешем.
- Типы context можно расширить через module augmentation.
- Nitro hooks подходят для tracing/logging/metrics.
- `waitUntil` - только для non-critical background work.
- `onDispose` - cleanup и измерение завершения request.
