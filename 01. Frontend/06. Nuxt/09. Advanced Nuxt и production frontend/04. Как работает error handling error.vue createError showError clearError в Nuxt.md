# Как работает error handling, error.vue, createError, showError и clearError в Nuxt?

> [!NOTE]
> В Nuxt ошибки могут возникнуть в page rendering, server routes, plugins, middleware и data fetching. Нужно понимать разницу между локальной ошибкой компонента, server error и глобальной error page.

## Какие уровни ошибок есть?

| Уровень | Где возникает | Чем обрабатывать |
| --- | --- | --- |
| Component error | Vue component | `<NuxtErrorBoundary>`, локальный fallback. |
| Page error | `pages/*.vue`, `useFetch`, middleware | `createError`, `showError`, `error.vue`. |
| Server route error | `server/api/*.ts` | `throw createError(...)`. |
| Fatal app error | plugin, SSR render, startup | `error.vue`, logs, monitoring. |
| Client navigation error | route middleware, async data | `showError`, redirect, retry. |

## `createError`

В page:

```vue
<script setup lang="ts">
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.id}`)

if (!product.value) {
  throw createError({
    statusCode: 404,
    statusMessage: 'Product not found',
    fatal: true
  })
}
</script>
```

В server route:

```ts
export default defineEventHandler(async (event) => {
  const id = getRouterParam(event, 'id')
  const product = await findProduct(id)

  if (!product) {
    throw createError({
      statusCode: 404,
      statusMessage: 'Product not found'
    })
  }

  return product
})
```

## `error.vue`

Файл:

```text
app/error.vue
```

Пример:

```vue
<script setup lang="ts">
import type { NuxtError } from '#app'

defineProps<{
  error: NuxtError
}>()

const handleError = () => clearError({ redirect: '/' })
</script>

<template>
  <main>
    <h1>{{ error.statusCode }}</h1>
    <p>{{ error.statusMessage || 'Что-то пошло не так' }}</p>
    <button @click="handleError">
      На главную
    </button>
  </main>
</template>
```

`error.vue` - полноценная страница ошибки. Она должна быть простой и надежной: не делай внутри сложных запросов, которые тоже могут упасть.

## `showError`

`showError` удобно вызвать, когда нужно программно перевести приложение в error state:

```ts
export default defineNuxtRouteMiddleware((to) => {
  if (to.path.startsWith('/legacy')) {
    return showError({
      statusCode: 410,
      statusMessage: 'Page removed'
    })
  }
})
```

## `clearError`

`clearError` очищает текущую ошибку и может сделать redirect:

```ts
await clearError({
  redirect: '/'
})
```

Частый сценарий - кнопка “вернуться на главную” на `error.vue`.

## `<NuxtErrorBoundary>`

Если ошибка не должна валить всю страницу:

```vue
<template>
  <NuxtErrorBoundary>
    <ProductRecommendations />

    <template #error="{ error, clearError }">
      <section>
        <p>Рекомендации временно недоступны</p>
        <button @click="clearError">
          Попробовать снова
        </button>
      </section>
    </template>
  </NuxtErrorBoundary>
</template>
```

Это полезно для optional widgets: рекомендации, reviews, analytics block.

## Ошибки в data fetching

```vue
<script setup lang="ts">
const { data, error, status, refresh } = await useFetch('/api/orders')
</script>

<template>
  <p v-if="status === 'pending'">Загрузка</p>
  <section v-else-if="error">
    <p>Не удалось загрузить заказы</p>
    <button @click="refresh">Повторить</button>
  </section>
  <OrderList v-else :orders="data" />
</template>
```

Не каждая ошибка API должна становиться глобальной страницей ошибки.

## Что логировать?

На сервере:

- status code;
- route;
- user/session id без персональных данных;
- request id;
- stack trace для unexpected errors;
- payload only if safe.

На клиенте:

- route;
- component name;
- user action;
- browser metadata;
- correlation/request id.

## Что отвечать на собеседовании?

В Nuxt для HTTP-like ошибок используют `createError`, для глобального error state - `showError`, а для восстановления - `clearError`. Глобальная страница лежит в `app/error.vue`. Для локальных виджетов лучше использовать `<NuxtErrorBoundary>`, чтобы ошибка одного блока не ломала всю страницу. В server routes ошибки тоже бросают через `createError`.

## Частые ошибки

- Делать `error.vue` зависимой от API, которое может упасть.
- Показывать глобальную error page для любой маленькой ошибки виджета.
- Возвращать `200 OK` с `{ error: ... }` для настоящей server error.
- Раскрывать stack trace пользователю.
- Не очищать ошибку перед redirect.
- Не различать 404, 401, 403 и 500.

## Мини-шпаргалка

- `createError` - создать HTTP-like error.
- `showError` - показать глобальную ошибку.
- `clearError` - выйти из error state.
- `app/error.vue` - глобальная error page.
- `<NuxtErrorBoundary>` - локальный fallback.
- Server route errors тоже через `createError`.
