# Как не дать Swagger документации разъехаться с кодом?

> [!summary]
> Swagger становится опасным, если документация не совпадает с реальным validation и behavior. Чтобы избежать расхождения, нужно держать DTO, validation, response decorators и e2e tests согласованными.

## Где возникает drift?

- DTO изменили, `@ApiProperty` забыли обновить;
- Zod schema отличается от Swagger schema;
- error filter возвращает другой формат;
- controller status code изменился;
- auth guard добавили, `@ApiBearerAuth` забыли.

## Практики

- использовать DTO как единый contract;
- добавлять e2e tests на важные endpoints;
- экспортировать OpenAPI JSON в CI;
- сравнивать schema diff;
- документировать error response DTO;
- не писать raw schema без необходимости.

## С Zod

Если validation в Zod, а Swagger в class DTO, следи за синхронизацией. Для важных API лучше добавить тест, который проверяет реальные 400 errors и documented schema.

## Мини-шпаргалка

- Swagger должен быть контрактом, а не декором.
- Validation и docs должны совпадать.
- Error format документируй отдельно.
- Protected routes помечай security decorators.
- Для external API полезен OpenAPI schema diff в CI.
