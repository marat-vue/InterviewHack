# Что такое streaming SSR и как он работает?

> [!summary]
> Streaming SSR отправляет HTML клиенту частями, по мере готовности. Вместо ожидания всей страницы сервер может отправить shell сразу, показать fallback для медленных частей и позже дослать HTML для Suspense-boundaries.

## Обычный SSR

```text
render entire page -> send full HTML
```

Если часть страницы долго грузит данные, весь HTML может ждать.

## Streaming SSR

```text
render shell -> stream shell -> stream more content as it becomes ready
```

Пользователь раньше видит каркас и готовые части страницы.

## React API для Node.js

```jsx
import { renderToPipeableStream } from 'react-dom/server'

app.get('/', (request, response) => {
  const { pipe, abort } = renderToPipeableStream(<App />, {
    bootstrapScripts: ['/client.js'],

    onShellReady() {
      response.setHeader('content-type', 'text/html')
      pipe(response)
    },

    onError(error) {
      console.error(error)
    },
  })

  setTimeout(() => abort(), 10_000)
})
```

Для Web Streams окружений используют `renderToReadableStream`.

## Suspense в streaming SSR

```jsx
function ProductPage() {
  return (
    <ProductLayout>
      <ProductInfo />

      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />
      </Suspense>
    </ProductLayout>
  )
}
```

`ProductInfo` и layout могут уйти в HTML раньше. `Reviews` появятся позже, когда данные будут готовы.

## onShellReady и onAllReady

`onShellReady`:

- shell готов;
- можно начинать streaming;
- хорошо для пользователей.

`onAllReady`:

- готово все содержимое;
- можно отправить полный HTML без progressive streaming;
- полезно для crawlers или static generation.

## Плюсы

- раньше появляется shell;
- меньше ожидание медленных частей;
- лучше perceived performance;
- хорошо сочетается с Suspense;
- можно отдавать частичный HTML постепенно.

## Сложности

- сложнее обработка ошибок после начала stream;
- сложнее status codes, если ошибка произошла поздно;
- сложнее кеширование;
- нужно аккуратно проектировать Suspense boundaries;
- нужно контролировать abort и timeouts.

## Мини-шпаргалка

- Streaming SSR отправляет HTML частями.
- `renderToPipeableStream` - Node.js stream API.
- `renderToReadableStream` - Web Streams API.
- `Suspense` задает границы медленных частей.
- `onShellReady` начинает stream, `onAllReady` ждет все.
