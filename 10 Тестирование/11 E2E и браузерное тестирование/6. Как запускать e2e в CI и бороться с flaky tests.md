# Как запускать e2e в CI и бороться с flaky tests?

> [!summary]
> E2E в CI требуют стабильного окружения: предсказуемые данные, правильный webServer, retries, trace на retry, parallelization и отсутствие ручных sleep. Flaky tests нужно чинить, а не просто бесконечно перезапускать.

## Базовый CI script

```bash
npm ci
npm run build
npx playwright install --with-deps
npx playwright test
```

Для frontend-проекта часто запускают preview server:

```ts
webServer: {
  command: 'npm run preview',
  url: 'http://localhost:4173',
  reuseExistingServer: !process.env.CI,
}
```

## Retries

```ts
retries: process.env.CI ? 2 : 0,
```

Retries помогают пережить редкие инфраструктурные сбои, но не должны маскировать плохие тесты.

## Parallelization

Playwright умеет запускать тесты параллельно. Но параллельные тесты должны иметь независимые данные.

Плохо:

```text
Все тесты используют user@example.com и одну корзину.
```

Лучше:

```text
Каждый тест создает пользователя user-${uuid}@example.com.
```

## Не используй `waitForTimeout`

Плохо:

```ts
await page.waitForTimeout(3000);
```

Лучше:

```ts
await expect(page.getByText('Заказ оформлен')).toBeVisible();
```

## Мини-шпаргалка

- В CI e2e должны запускаться в предсказуемом окружении.
- `retries` полезны, но не лечат flaky tests.
- Trace на retry помогает debug.
- Параллельные тесты требуют изоляции данных.
- Жди состояние, а не время.
